# File Watch Debounce

一个带事件去抖动的文件系统监听器，解决文件监听中的各种坑。

## 特性

- **事件去抖动**：在指定时间窗口内合并同一文件的多次事件，默认500ms
- **最大等待时间**：防止持续编辑导致回调永远不触发，默认5秒
- **智能事件合并**：
  - 删除+创建 = 替换（Replace）
  - 创建+写入 = 创建（Create）
  - 多次写入 = 修改（Modify）
- **重命名事件识别**：关联源文件和目标文件
- **符号链接处理**：只监听链接本身，不跟踪目标文件变化

## 快速开始

### 编译

```bash
go build ./...
```

### 启动服务端

```bash
go run ./cmd/server
# 或指定端口
go run ./cmd/server -port 8080
```

### 使用客户端

```bash
# 添加监听目录
go run ./cmd/client add /path/to/watch

# 添加监听并自定义参数
go run ./cmd/client add /path/to/watch --debounce 500ms --max-wait 5s

# 列出所有监听
go run ./cmd/client list

# 查看最近事件
go run ./cmd/client events

# 移除监听
go run ./cmd/client remove <watch-id>
```

## 事件类型

| 类型 | 说明 |
|------|------|
| `create` | 新建文件 |
| `modify` | 修改文件内容或属性 |
| `delete` | 删除文件 |
| `rename` | 重命名文件 |
| `replace` | 删除后重新创建（替换） |

## 事件去抖动机制

### 工作原理

1. 收到文件事件后，启动一个去抖动定时器（默认500ms）
2. 如果在定时器到期前收到同一文件的新事件，重置定时器
3. 定时器到期后才真正触发回调
4. 同时设置最大等待时间（默认5秒），确保不会无限等待

### 为什么需要去抖动？

用户用编辑器保存文件时，底层可能产生一系列事件：
- 创建临时文件
- 写入内容
- 重命名覆盖原文件

如果每次事件都触发回调，一个保存操作可能触发多次回调。去抖动机制会将这些事件合并为一次。

### 事件合并规则

- **同一文件**的多次事件在去抖动窗口内合并
- 记录所有原始事件类型
- 根据原始事件类型推断最终事件类型

### 事件类型推断

```
原始事件           →  最终事件
────────────────────────────────
CREATE + WRITE    →  create（新建文件）
WRITE + WRITE     →  modify（修改文件）
REMOVE            →  delete（删除文件）
REMOVE + CREATE   →  replace（替换文件）
RENAME            →  rename（重命名）
```

## 符号链接行为

**重要说明**：本监听器**不跟踪符号链接指向的目标文件**。

### 具体行为

| 操作 | 是否触发事件 |
|------|-------------|
| 创建符号链接 | ✅ 触发 create |
| 删除符号链接 | ✅ 触发 delete |
| 修改符号链接指向 | ✅ 触发 modify |
| 修改目标文件内容 | ❌ 不触发事件 |
| 目标文件被删除 | ❌ 不触发事件 |

### 为什么这样设计？

1. **性能考虑**：跟踪所有符号链接目标会导致递归监听，性能开销大
2. **预期一致性**：用户监听目录A中的符号链接，通常期望的是链接本身的变化
3. **避免循环**：符号链接可能形成循环引用，导致无限递归

### 如果需要监听目标文件

如果你需要监听符号链接指向的目标文件，请直接监听目标文件所在的目录，而不是通过符号链接间接监听。

## 常见问题

### Q: 为什么我保存文件后收到了多次事件？

A: 可能的原因：
1. 你的操作间隔超过了去抖动时间（默认500ms）
2. 某些编辑器会产生多个独立的写入操作

可以尝试增加去抖动时间：
```bash
go run ./cmd/client add /path --debounce 1s
```

### Q: 新建文件显示为modify而不是create？

A: 这通常是因为文件系统对新建文件同时触发了CREATE和WRITE事件。本项目的实现会正确识别为create事件。

如果确实遇到这个问题，请检查：
1. 文件是否真的之前不存在
2. 是否有其他进程在操作这个文件

### Q: 删除后创建同名文件产生了两个事件？

A: 确保删除和创建操作在去抖动窗口内完成。如果两个操作的时间间隔超过去抖动时间，会产生两个独立事件。

### Q: 为什么符号链接目标文件变化没有触发事件？

A: 这是预期行为。请参考上面的"符号链接行为"章节。
