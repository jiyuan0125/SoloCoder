要实现一套CRDT（Conflict-free Replicated Data Types）库，支持三种基本数据类型：G-Counter（增长计数器）、PN-Counter（正负计数器）和G-Set（仅增长集合）。这些数据类型的设计目标是：多个副本可以独立更新，之后通过merge操作合并，最终所有副本会收敛到一致的状态，不需要中心化协调。

G-Counter的原理是为每个节点维护一个独立的计数器，全局值是所有节点计数值的总和。节点的增量和merge操作都是取对应位置的最大值，所以增量只会增长不会减少。一个容易搞错的地方是：merge时不能简单地把两个G-Counter的值相加，而是要对每个节点的分量取max，否则多次merge会导致数值膨胀。PN-Counter在G-Counter的基础上增加了一个递减能力，内部用两个G-Counter分别记录增量和减量，全局值等于增量总和减去减量总和。G-Set只支持添加元素，不支持删除，merge操作取并集。重复添加同一个元素不应该产生副作用。

merge操作必须满足交换律和结合律，即merge(A, B) == merge(B, A)，merge(merge(A, B), C) == merge(A, merge(B, C))。这一点需要在测试中严格验证。节点ID要支持字符串类型，不限于整数。当两个不同节点的计数器merge时，结果要包含所有出现过的节点ID。G-Set判断元素是否存在要用精确匹配，不能有类型转换或隐式比较。

服务端提供创建CRDT实例、执行操作（increment/decrement/add）、merge两个实例三个接口。客户端命令行支持创建多个模拟节点，各自独立操作后执行merge并查看结果。

核心功能实现为一个独立package。在此基础上写两个程序：服务端引用核心库对外提供HTTP接口，客户端是命令行工具通过HTTP调用服务端。服务端和客户端各自独立main包，请求响应格式定义放在公共包。核心库、服务端、客户端各按职责分文件。先go mod init再开发，go build ./...能编译通过。

本项目属于跨系统多模块架构。
