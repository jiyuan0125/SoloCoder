| User Prompt | 帮我用 C 写一个缓存集群的请求分发模块。后端有 N 个缓存节点（比如 Memcached 实例），每个节点有一个标识字符串。客户端要缓存数据时，根据数据的键来决定存到哪个节点，这样同样的键永远映射到同一个节点。 直接取模有个问题：如果增加或减少一个节点，几乎所有键的映射都会变，导致大面积缓存失效。所以需要一种方案让节点变动时只影响一小部分键的映射。 具体方案：把每个节点的标识通过某种映射规则放到一个 0 到 2^32-1 的环上，每个节点映射多个点（比如每个节点 150 个虚拟点，用节点标识加编号作为输入）。数据键也映射到同一个环上，顺时针找到的第一个节点就是目标节点。 要支持动态增删节点：加入新节点后，只有新节点和下一个节点之间的那部分键会重新映射。删除节点后，它负责的键会转移给顺时针方向的下一个节点。增删操作后要能立即生效，不需要重建整个映射。 查询功能：给定一个键，返回它应该映射到哪个节点。给定一个键，返回它的备份应该存到哪个节点（顺时针方向的下 N-1 个节点，N 是副本数，默认 1）。 有个容易忽略的点：当节点数量很少（比如只有 1 个或 2 个）时，虚拟点数量不变的话分布会很不均匀，需要确保在这种情况下也能比较均匀地分配。 用纯 C 写，gcc 在 Linux 上编译通过。写个 main 演示：创建 5 个节点，映射 10000 个键，展示每个节点分配到的键数量，然后增删节点看变化。 代码要分模块组织——一致性哈希环管理模块、节点映射与查找模块各自的头文件和实现文件分开，加一个 main 做演示。至少 3 个 .c 文件加对应的 .h 文件。gcc 编译能过。 |
