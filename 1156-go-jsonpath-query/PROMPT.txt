数据分析平台需要一种灵活的方式从JSON文档中提取数据，XPath在XML领域很成功，JSON对应的就是JSONPath。我要用Go实现一个JSONPath查询引擎，支持常见的查询语法。

JSONPath的基础语法用$表示文档根，.表示子节点访问，[]表示数组下标或对象属性访问。比如$.store.book[0].title取第一个book的title。支持递归下降..，比如$.store..price会找到store下面所有层级的price字段，不论price嵌套在多深。数组支持切片[start:end]，这是左闭右开区间，和Go的slice一致但和某些语言的substring不同。还支持通配符*，匹配任意字段名或数组下标。

过滤器的实现比较复杂。语法是[?(@.price < 10)]，@表示当前节点。支持的比较运算符有==、!=、<、<=、>、>=，逻辑运算符有&&和||。比较值可以是数字、字符串（用单引号包裹）和布尔值。过滤器中要正确区分数值比较和字符串比较，比如@.age > 18是数值比较，@.name == 'Alice'是字符串比较。如果字段值是字符串但比较值是数字（或反过来），应该怎么处理需要明确规则，我建议做类型兼容转换而不是直接报错。

服务端提供查询接口，输入JSON数据和JSONPath表达式，返回匹配的所有结果。结果可能是一个值也可能是一个数组（路径匹配到多个节点时）。这里有个细节：如果查询路径只匹配一个节点，返回这个节点的值；如果匹配多个节点，返回数组。但用户可能需要区分"结果是数组"和"匹配了多个节点"，所以响应中要带上匹配数量和路径列表。

命令行客户端支持从文件读取JSON或直接传入JSON字符串。用法类似 `client query --json data.json --path '$.store.book[*].author'`。结果输出默认用缩进的JSON格式，可以加--compact参数输出单行。如果查询没有匹配到任何节点，输出"no matches"而不是空数组，避免混淆。

实现递归下降查询时要性能。对大型JSON文档，..操作符理论上需要遍历整棵树，如果schema很深或很宽，递归可能很慢。可以在实现时对简单路径（不包含..和过滤器）做优化，用精确的路径查找代替遍历。但这个优化不是必须的，先把正确性做好。

核心功能实现为一个独立package。在此基础上写两个程序：服务端引用核心库对外提供HTTP接口，客户端是命令行工具通过HTTP调用服务端。服务端和客户端各自独立main包，请求响应格式定义放在公共包。核心库、服务端、客户端各按职责分文件。先go mod init再开发，go build ./...能编译通过。
