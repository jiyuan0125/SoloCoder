| User Prompt | 帮我用 C 写一个日志文件自动轮转模块。后台服务持续写日志，日志文件会越来越大，需要自动切分和清理，否则磁盘会被撑爆。 按大小轮转：当前日志文件超过指定大小时（比如 100MB），自动把当前文件重命名为备份文件，然后创建一个新的空文件继续写。备份文件命名带序号：app.log.1、app.log.2、app.log.3...，序号越大越旧。每次轮转时，现有的备份文件序号全部加 1（app.log.1 变成 app.log.2，以此类推），当前日志变成 app.log.1。 保留数量限制：最多保留 N 个备份文件（比如 10 个），超出后最旧的自动删除。保留数量可以配置为 0，表示不保留任何备份（直接删除旧日志）。 按时间轮转（可选）：除了按大小，也支持按天轮转。每天零点切分一次，备份文件名带日期（app.log.2026-05-03）。如果当天日志已经超过大小限制，在零点之前也要切分。 压缩：轮转后的旧日志可以配置为自动压缩（gzip），节省磁盘空间。压缩是异步的，不能阻塞当前日志写入。压缩失败不能影响主流程。 并发安全：日志写入和轮转可能在不同线程中进行。轮转时要确保不会丢失正在写入的日志内容——先关闭当前文件让缓冲区刷新，再重命名，再打开新文件。 有个坑：轮转时如果目标备份文件名已经存在（比如上一次轮转失败了，旧的 .1 文件还在），应该覆盖而不是报错退出。否则日志服务会因为轮转失败而停掉。 用纯 C 写，gcc 在 Linux 上编译通过。写个 main 演示：持续写日志，触发轮转，验证文件命名和保留数量。 代码要拆成至少 4 个源文件，按功能模块分——文件轮转控制、备份文件管理、异步压缩、主程序。头文件和实现文件分开。gcc 编译能过。 |
