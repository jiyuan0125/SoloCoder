| User Prompt | 帮我用 C 写一个网址解析模块，用于短链接服务的后端。用户访问短链时，服务需要从 URL 中提取各种信息来做路由和统计。 解析内容：从完整的 URL 字符串中拆分出以下部分——协议（http/https）、用户名（可选）、密码（可选）、主机名、端口（可选，没写就用协议默认端口）、路径、查询参数（键值对列表）、片段标识（# 后面的部分）。 查询参数解析是重点：多个参数用 & 分隔，键和值用 = 分隔。值可能被 URL 编码过（%XX 格式），解析时要自动解码还原。参数值可能包含中文、特殊字符，都要正确处理。同一个键出现多次时（如 ?a=1&a=2），要把所有值都保留下来，不能只留最后一个。 路径处理：路径中的 /./ 和 /../ 要能正确归一化。比如 /a/b/../c 要归一化成 /a/c。但要防止路径穿越——如果归一化后路径跑到了根路径之外（比如 /a/../../etc/passwd），要标记为异常路径。 URL 编码/解码：提供独立的编码和解码方法。编码时只编码需要编码的字符（非 ASCII 字符、空格、特殊符号），字母数字和 -_.~ 不编码。解码时 %XX 要转回对应字符，% 后面如果不是两个合法的十六进制字符，保留原样不处理。 IPv6 地址：主机名部分可能是 IPv6 地址（用方括号包裹，如 [::1]:8080），要能正确识别。 有个坑：URL 中可能包含 @ 符号，要区分它是用户名密码分隔符还是路径/查询参数的一部分。判断依据是 @ 出现在第一个 / 之前才算用户名密码分隔符。 用纯 C 写，gcc 在 Linux 上编译通过。写个 main 演示：解析各种格式的 URL，打印拆分结果。 代码要拆成至少 4 个源文件，按功能模块分——URL 拆分解析、查询参数处理、编解码、主程序。头文件和实现文件分开。gcc 编译能过。 |
