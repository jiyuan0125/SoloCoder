帮我用 C 写一个高性能的请求计数器模块，用于网关层的限流。网关要对每个 IP 地址（或每个API 路径）的请求频率做限制，超过阈值的请求直接拒绝。

基本计数：每个 key（比如 IP 地址字符串）维护一个计数器，支持原子加 1 和读取当前值。多个线程同时更新同一个 key 的计数器时要保证不会丢失更新（两个线程同时加 1，结果必须是加了 2 而不是 1）。

滑动窗口限流：支持两种限流模式。第一种是固定窗口——每分钟的前 N 个请求通过，后面的拒绝。第二种是滑动窗口——把 1 分钟分成 6 个 10 秒的小窗口，每个小窗口独立计数，限流判断时综合最近 6 个小窗口的总计数。滑动窗口的边界更平滑，不会出现窗口切换瞬间请求量翻倍的问题。

key 的自动清理：不可能无限保存所有 key 的计数器——有些 IP 可能只发了一次请求就再也没来。需要定期清理长时间没有新请求的 key，释放内存。清理策略：超过 5 分钟没有任何操作的 key自动移除。

统计查询：当前有多少个活跃 key、总请求量、被拒绝的请求量。某个 key 在最近 1 分钟内的请求次数和被拒绝次数。

性能要求：计数操作要尽量快，不能每次加 1 都去拿锁。可以考虑用 CPU 原子指令（如 GCC 的__sync_fetch_and_add）来实现无锁计数。

有个隐藏坑：滑动窗口模式下，小窗口的切换时间点要精确对齐（每个 10 秒窗口从 xx:x0 秒开始），不能从第一个请求到达时开始计时，否则不同 key 的窗口边界不一致会导致限流不均匀。

用纯 C 写，gcc 在 Linux 上编译通过。写个 main 演示：模拟多线程并发请求计数，展示限流效果。

代码要拆成至少 4 个源文件，按功能模块分——计数器管理、滑动窗口限流、过期清理、主程序。头文件和实现文件分开。gcc 编译能过。
