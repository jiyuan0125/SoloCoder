帮我用 C 写一个定时任务调度引擎。我们的运维平台需要执行各种定时任务——每隔 5 秒采集一次服务器指标、每天凌晨 2 点做数据库备份、每月 1 号生成月度报表。这些任务的执行时间各不相同，需要统一的调度器来管理。

一次性定时任务：指定一个绝对时间点（或相对延迟），到时间后执行一次。执行完后自动移除。比如「10 秒后执行清理操作」。

周期性任务：指定一个间隔时间，反复执行。比如「每 30 秒采集一次 CPU 使用率」。支持设置最大执行次数——执行 N 次后自动停止。

取消任务：每个任务创建后获得一个 ID，通过 ID 可以取消还没执行的任务。如果任务正在执行中，取消操作等它执行完后才生效（下次不再执行）。

任务执行时不能阻塞调度器——任务在独立的工作线程中执行，调度器继续管理其他任务的调度。如果工作线程池满了（所有工作线程都在忙），新触发的任务排队等待。

时间精度：调度器每隔一段时间检查一次是否有任务到期，检查间隔越小精度越高但 CPU 开销越大。要设计成动态调整——没有任务即将到期时降低检查频率，有任务快到期时提高频率。

有个关键的设计考量：当有大量定时任务时（比如上万个），每次检查是否到期都要遍历所有任务的话性能很差。需要设计一种高效的数据组织方式，让检查到期任务的操作尽量快——理想情况下只需要看第一个元素就能知道最近什么时候有任务要执行。

用纯 C 写，gcc 在 Linux 上编译通过。写个 main 演示：注册几个一次性任务和周期任务，观察执行顺序和时间精度。

代码要拆成至少 4 个源文件，按功能模块分——定时任务优先队列、任务调度与触发、工作线程管理、主程序。头文件和实现文件分开。gcc -lpthread 编译能过。
