帮我用 C 写一个文件完整性校验模块。我们有一个文件传输系统，文件在传输前后需要计算摘要值来验证文件是否完整、是否被篡改。这个模块负责计算文件的 MD5 摘要值。

支持两种使用方式：一次性计算整个文件（传入文件路径，返回 32 位十六进制摘要字符串）、流式计算（分多次传入数据块，最后获取最终摘要）。流式模式用于大文件——不用把整个文件读入内存，每次读一块处理一块。

除了文件，也要能直接计算内存中数据的摘要（传入字节指针和长度）。

输出格式：返回 32 个字符的十六进制字符串（小写），加上末尾的空字符。也可以选择返回 16 字节的原始二进制摘要（用于内部比较，不需要转成字符串）。

MD5 算法本身要自己实现，不能调用系统的 md5sum 命令或者 OpenSSL 库。算法步骤包括：填充消息（补位到 512 位的倍数）、附加原始长度、分块处理（每块 512 位）、轮处理步骤。具体的轮常量和移位量需要查表。

性能要求：对于 1GB 的文件，计算时间不超过 5 秒。可以考虑用查表法加速核心计算。

验证功能：给定一个文件和一个预期的摘要字符串，判断文件的实际摘要是否匹配。这个功能用于校验下载的文件是否完整。

有个容易踩的坑：大文件（超过 4GB）的文件大小在 32 位系统上用普通 int 存不下，需要用64 位整数来记录消息长度。MD5 的原始设计中消息长度字段是 64 位的，实现时要确保正确处理。

用纯 C 写，不依赖第三方库，gcc 在 Linux 上编译通过。写个 main 演示：计算几个已知文件的MD5，跟系统 md5sum 命令的结果对比验证正确性。

代码要拆成至少 4 个源文件，按功能模块分——MD5 算法核心计算、流式数据处理、文件读写与验证、主程序。头文件和实现文件分开。gcc 编译能过。
