| User Prompt | 帮我用 C 写一个事件分发系统，用于桌面窗口程序的消息处理。窗口程序里有很多事件来源——鼠标点击、键盘输入、定时器到期、网络数据到达、窗口大小变化等，这些事件需要统一收集、按优先级排队、然后分发给对应的处理模块。 事件类型：每种事件有一个类型编号和优先级。优先级高的先处理——比如系统关机事件比普通鼠标移动优先级高。同一优先级内按到达顺序处理（先进先出）。 事件投递：任何线程都可以往事件通道投递事件。投递时指定事件类型、附加数据（一个 void 指针和大小）、优先级。投递操作不能阻塞——即使通道满了也要能立即返回（丢弃或报错）。 事件消费：只有一个消费线程（通常是主线程）从通道中取事件处理。取事件时总是取优先级最高的。如果通道为空，消费线程阻塞等待直到有新事件到来。 事件处理器注册：不同的事件类型可以注册不同的处理回调。投递事件时不需要指定由谁处理，消费线程取到事件后根据类型自动找到对应的回调来执行。 定时事件：支持投递一个延迟事件——不是立即放入通道，而是等指定时间后才放入。比如投递一个5 秒后到期的定时器事件。定时事件到期后按其优先级插入通道。 取消事件：通过事件 ID 可以取消还没被消费的事件。如果事件已经被消费了，取消操作无效。定时事件也可以在到期前取消。 有个坑：事件处理回调里可能会投递新事件（比如处理鼠标点击事件时弹出一个对话框，这会投递绘制事件）。这种情况不能导致死锁——消费线程在处理回调时，投递操作不应该被阻塞。 用纯 C 写，gcc 在 Linux 上编译通过。写个 main 演示：注册几个事件处理器，投递各种事件，观察处理顺序。 代码要拆成至少 4 个源文件，按功能模块分——事件通道与优先队列、事件分发与处理器注册、定时事件管理、主程序。头文件和实现文件分开。gcc -lpthread 编译能过。 |
