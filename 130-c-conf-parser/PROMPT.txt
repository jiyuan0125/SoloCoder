帮我用 C 写一个通用配置文件解析模块。我们的各种 C 服务都需要读配置文件，格式类似 INI——用分节和键值对组织。这个模块要能解析这种格式并把配置值存起来供其他模块查询。

配置文件格式：
- 用 [section_name] 定义分节
- 每行一个 key = value 键值对
- # 或 ; 开头的是注释行
- 空行忽略
- key 不区分大小写，value 区分大小写
- value 可以用三引号包裹来包含换行（多行值）

value 的类型自动推断：纯数字（整数或浮点数）存为数值类型，true/false 存为布尔类型，其他存为字符串。查询时可以按类型获取——get_int、get_float、get_bool、get_string，类型不匹配时给默认值而不是崩溃。

变量引用：value 中可以用 ${section.key} 或 ${key} 引用其他配置项的值。引用在查询时动态展开——如果被引用的值后续被修改了，引用它的地方也会跟着变。要检测循环引用（A 引用 B、B 引用 A），发现循环时停止展开并报错。

默认值：每个查询都可以指定默认值，配置文件中没有对应的 key 时返回默认值。有分节的查询格式是 section.key，没有分节的直接用 key。如果 key 在全局和某个分节中都存在，分节里的优先。

文件监控（可选）：如果配置文件被外部修改了，模块能自动重新加载。通过比较文件的修改时间来判断是否需要重载。

有个坑：Windows 和 Linux 的换行符不同，配置文件可能用 \r\n 也可能用 \n。解析时要兼容两种。另外配置文件编码假设是 UTF-8，但实际可能是带 BOM 的 UTF-8，开头三个字节 \xEF\xBB\xBF要能跳过。

用纯 C 写，gcc 在 Linux 上编译通过。写个 main 演示：解析一个配置文件，查询各种类型的值。

代码要拆成至少 4 个源文件，按功能模块分——配置文件解析、变量引用展开、类型推断与查询、主程序。头文件和实现文件分开。gcc 编译能过。
