帮我用 C 写一个考试成绩排名系统。期末考试后，教务系统需要把几千名学生的成绩进行排名。排名规则比简单的按总分排序复杂得多。

每个学生有多科成绩（语文、数学、英语、物理、化学），还有总分。排名按以下优先级：
第一优先级是总分（从高到低），第二优先级是数学成绩（总分相同时数学高的排前面），第三优先级是语文成绩，第四优先级是英语成绩。如果所有科目成绩都相同，按学号升序排列。

排名的坑在于并列处理：如果两个学生总分和各科成绩完全一样，他们应该是并列第 N 名，下一个学生的名次是 N+2 而不是 N+1。比如第 1 名有 2 个人，那下一个是第 3 名。

分段排名：除了总排名，还需要按班级排名、按文理科排名（文科生和理科生分开排）。一个学生可能同时在年级排名、班级排名、文理科排名中出现。

百分位排名：除了名次，还要能计算百分位——比如一个学生排第 150 名，总共 1000 人，他的百分位是 85%（超过了 85% 的学生）。百分位用公式计算，注意边界情况。

成绩分布统计：各科的平均分、最高分、最低分、中位数、标准差。分数段分布（90-100 多少人、80-89 多少人等）。

数据量可能从几百到几十万不等，排序性能要能应对。内存有限制——不能为了排序就把数据复制好几份。

有个容易忽略的点：如果成绩数据中有缺失值（某个学生缺考某科），该科成绩记为 0 参与排名计算，但在统计平均分等指标时要标记出来，不能让缺考拉低平均分的统计意义。需要分别统计"参考人数"和"缺考人数"。

用纯 C 写，gcc 在 Linux 上编译通过。写个 main 演示：加载一批学生成绩数据，执行排名和统计。

代码要拆成至少 4 个源文件，按功能模块分——学生成绩数据管理、多维排名排序、统计分析、主程序。头文件和实现文件分开。gcc 编译能过。
