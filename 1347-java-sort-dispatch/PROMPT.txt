我们物流公司在做一套配送分拣系统，需要处理多仓发货、路由规划和中转节点管理。

先说仓库和网点。公司在几个城市有仓库（比如北京仓、上海仓、广州仓、成都仓），每个仓库覆盖周边区域的配送。客户下单后，系统根据收货地址自动选择最近的仓库发货。如果最近仓库库存不足，才从次近的仓库调货。这里"最近"不是简单的直线距离，而是有一个预设的路由表，记录各仓库到各区域的配送距离和时效。

中转站是中间节点，有些偏远区域的包裹需要经过中转站分拣后再派送。每个中转站服务的区域是固定的，包裹到达中转站后需要"卸货分拣"操作，把不同目的地的包裹分到不同的配送线路。中转站有一个处理能力上限（每小时能处理的包裹数），超过上限的包裹需要排队等待。

订单流程是这样的：客户下单（包含商品、数量、收货地址）→ 系统分配仓库 → 仓库拣货出库 → 运输到中转站（如果需要）→ 中转站分拣 → 配送员派送 → 签收。每个环节都有状态更新和时间记录。如果某个环节超时（比如中转站积压超过4小时），需要标记异常。

包裹在运输途中有体积和重量的限制：单包裹不超过50公斤、长宽高之和不超过1.5米。下单时如果超出限制，要拆分成多个包裹，每个包裹单独追踪。拆分后的包裹可以走不同的线路，但最终都要送达同一个收货地址。

查询接口：按订单查物流轨迹（显示每个节点的时间和状态）、按仓库查当前库存和待发货量、按中转站查积压情况、统计各仓库的发货量和平均配送时效。

初始化数据：4个仓库、3个中转站、一些区域和路由配置、若干商品（有库存）。预设一些处于不同流转状态的订单。

注意一个情况：如果一个订单拆分成了多个包裹，其中某个包裹签收了但其他包裹还在途中，订单状态应该是"部分签收"而不是"已签收"。只有所有包裹都签收后，订单才算完成。还有，如果某个包裹丢失了（超过预计送达时间7天未签收且无物流更新），要标记为异常并通知客服。
