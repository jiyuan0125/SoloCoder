| User Prompt | 帮我用 C 写一个父子进程间的数据管道通信模块。我们的服务采用 master-worker 架构——主进程负责管理和分发任务，工作进程负责实际执行。主进程和工作进程之间需要通过管道交换数据。 基本通信模式：主进程创建工作进程时同时建立管道，每个工作进程有两条管道——一条用于主进程向工作进程发指令，一条用于工作进程向主进程报告结果。 消息格式：每条消息有 4 字节长度头 + 消息体。长度头用网络字节序（大端），消息体是二进制数据，内容对管道透明。发送端把长度和内容连续写入管道，接收端先读 4 字节长度再读对应长度的内容。 消息分片问题：管道的写入不保证原子性——如果一次写入的数据超过 PIPE_BUF（通常 4096 或65536 字节），数据可能和其他进程的写入交错。所以接收端必须处理消息分片的情况：可能一次read 只读到部分消息，需要把数据暂存起来等凑齐一整条消息再处理。 非阻塞读写：管道的读写要支持非阻塞模式。主进程向多个工作进程发消息时，如果某个工作进程的管道写满了，不能阻塞住其他工作进程的消息发送。非阻塞模式下写满返回错误，主进程可以选择稍后重试。 进程生命周期管理：工作进程正常退出或异常崩溃时，主进程要能检测到（通过管道读取返回 0 或 SIGCHLD 信号），然后清理对应的管道和资源。不能因为工作进程崩溃导致主进程也挂在管道读写上。 有个坑：管道的读端和写端都要正确管理。如果工作进程退出但主进程没有关闭对应的写端，工作进程的读端永远不会收到 EOF，可能导致残留的工作进程子线程无法正常退出。需要在工作进程退出时确保主进程关闭对应的管道端。 用纯 C 写，gcc 在 Linux 上编译通过。写个 main 演示：主进程 fork 3 个子进程，通过管道通信。 代码要拆成至少 4 个源文件，按功能模块分——消息帧封装与解析、管道读写管理、进程生命周期监控、主程序。头文件和实现文件分开。gcc 编译能过。 |
