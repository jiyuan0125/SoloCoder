帮我用 C 写一个数据完整性校验计算模块。网络传输中数据包可能损坏（比特翻转），需要在发送前计算校验值附加在数据包末尾，接收方重新计算并比对。我们用 CRC32 作为校验算法。

核心功能：给一段数据（字节指针和长度），计算 32 位的 CRC32 校验值。返回 uint32_t 类型。也可以选择返回 8 位十六进制字符串格式。

流式计算：支持分多次传入数据块，最终得到和一次性传入相同的校验值。这样处理大文件或网络流时不需要缓存全部数据。

CRC32 算法实现：基于查表法。初始化时生成 256 项的查找表，计算时每读一个字节查表一次并更新中间值。查找表的生成要正确——多项式用 0xEDB88320（反向表示法），这是以太网和 ZIP 等广泛使用的标准 CRC32 多项式。

验证功能：给定数据和预期校验值，判断是否匹配。返回布尔结果。

合并计算：如果两段数据各自的 CRC32 已知，能快速计算合并后的 CRC32，而不需要重新处理两段数据的全部内容。这个功能用于分段传输的场景——每个数据段有自己的校验值，接收方收到所有段后合并校验。合并公式涉及两个 CRC32 值和中间数据的长度。

性能：查表法计算 CRC32 应该非常快——现代 CPU 上处理速度应该能达到每秒几个 GB。确保编译器没有过度优化导致查表计算不正确（volatile 或者 barrier 可能需要）。

有个容易忽略的点：CRC32 的初始值通常是 0xFFFFFFFF，最终结果要异或 0xFFFFFFFF。如果初始值不同（比如用 0），计算出来的结果和标准工具（如 crc32 命令）不一致。需要确保和标准实现兼容。

用纯 C 写，不依赖第三方库，gcc 在 Linux 上编译通过。写个 main 演示：计算已知数据的 CRC32，跟系统工具结果对比。

代码要分几个模块：查找表生成模块、校验值计算模块、流式与合并计算模块，各自有头文件和实现文件。加一个 main 做演示。至少 3 个 .c 文件加对应的 .h 文件。gcc 编译能过。
