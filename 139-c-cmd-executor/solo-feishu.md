| User Prompt | 帮我用 C 写一个命令批量执行模块，用于运维自动化。运维人员需要在一批服务器上执行相同的命令（比如更新配置、重启服务、检查状态），这个模块负责并发执行命令并收集结果。 基本执行：给一个命令字符串（如 "ls -la /tmp"），创建子进程执行，等待执行完毕后收集退出码、标准输出、标准错误。超时时间可配置——如果命令执行超过指定时间就强制杀掉子进程。 并发执行：同时执行多个命令（在不同子进程中）。每个命令在独立子进程中运行，互不影响。可以设置最大并发数——如果同时要执行 100 个命令但最大并发数是 10，就分批执行，每批 10 个，前一批有完成的就补上新的。 输出收集：每个命令的标准输出和标准错误分别收集。如果输出太大（比如某个命令输出了 100MB），要能限制缓冲区大小——超过限制后丢弃后续输出但继续等待命令完成。不能因为输出太大就爆内存。 环境变量和工作目录：每个命令可以指定不同的环境变量和工作目录。环境变量是追加到继承的环境变量之上的，不会覆盖已有的（除非显式指定覆盖）。 管道支持：命令的输出可以重定向到文件，也可以通过管道传递给另一个命令（类似 shell 的 | ）。不过管道的完整支持比较复杂，先支持输出重定向到文件就行。 结果汇总：所有命令执行完毕后，输出汇总报告——成功数、失败数、超时数，每个命令的退出码、输出摘要（前几行和后几行）。失败的命令重点标红显示。 有个隐藏坑：子进程可能产生孙子进程（命令本身又启动了其他进程）。杀掉子进程时，孙子进程不会自动被杀，变成孤儿进程。需要通过进程组来确保杀掉子进程的同时也杀掉它的所有后代进程。 用纯 C 写，gcc 在 Linux 上编译通过。写个 main 演示：并发执行几个命令，收集和展示结果。 代码要拆成至少 4 个源文件，按功能模块分——子进程创建与执行、并发调度与限流、结果收集与汇总、主程序。头文件和实现文件分开。gcc 编译能过。 |
