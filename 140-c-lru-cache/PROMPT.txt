帮我用 C 写一个查询结果缓存模块。我们的数据库查询服务每次查询都要走网络，延迟几十毫秒。很多查询是重复的——同样的查询条件短时间内被多次执行。需要一个内存缓存来避免重复查询。

基本操作：给定一个键（查询条件的字符串表示）和值（查询结果的二进制数据），存入缓存。下次用同样的键查询时直接从缓存取，不用走网络。键的最大长度 256 字节，值的最大长度 1MB。

容量限制：缓存有一个总容量（比如 100MB），当存储的数据总量超过容量时，需要淘汰一部分旧数据。淘汰策略是「最近最少使用」——最近被访问过的数据保留，最久没被访问的优先淘汰。

过期机制：每个缓存项可以设置过期时间。查询时如果发现数据已过期，删除并返回未命中。过期数据的清理不应该影响正常查询的性能——不能每次查询都扫描所有缓存项来清理过期的。

并发安全：多个线程同时读写缓存。读操作之间不互斥（可以同时读），写操作和读操作之间需要同步。目标是读多写少的场景下读操作尽量不阻塞。

缓存命中率统计：记录总查询次数、命中次数、未命中次数、淘汰次数。命中率 = 命中次数 / 总查询次数。提供一个重置统计的方法。

批量操作：一次查询多个键，返回所有命中的结果和所有未命中的键列表。批量查询的效率要比逐个查询高——一次加锁取所有结果，而不是每个键加一次锁。

有个关键的设计挑战：淘汰操作需要找到最久没被访问的数据。如果每次淘汰都遍历所有数据找最久没访问的，性能会很差。需要设计一种数据组织方式，让淘汰操作尽量快——理想情况下是常数时间就能找到应该淘汰的数据。

用纯 C 写，gcc -lpthread 在 Linux 上编译通过。写个 main 演示：存入大量数据，查询、观察淘汰行为和命中率。

代码要拆成至少 4 个源文件，按功能模块分——缓存数据存储与淘汰、并发读写控制、过期清理与统计、主程序。头文件和实现文件分开。gcc -lpthread 编译能过。
