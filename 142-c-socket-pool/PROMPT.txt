帮我用 C 写一个网络连接池模块。我们的服务需要频繁连接后端数据库（通过 TCP 长连接），每次查询都新建连接太慢了（TCP 三次握手 + 数据库认证要好几十毫秒）。需要维护一个连接池，复用已有的连接。

基本操作：从池中获取一个可用连接，使用完毕后归还到池中。获取时如果池中有空闲连接就直接给，没有就创建一个新连接（但不能超过最大连接数限制）。

连接健康检查：获取连接时要验证连接是否还活着——可能后端数据库已经断开了这个连接（超时、重启等），但客户端不知道。验证方式是发一个简单的探测包（比如数据库的 ping 命令），如果探测失败就把这个连接丢弃，从池中取下一个或创建新的。

最大连接数：池中同时存在的连接数有上限。达到上限后，新的获取请求阻塞等待，直到有连接被归还。等待超时后返回错误。最大连接数和等待超时在创建池时配置。

空闲连接回收：长时间没有使用的连接应该被关闭回收，释放后端资源。每个连接记录最后一次被使用的时间，后台定期扫描，超过空闲时间上限（比如 5 分钟）的连接自动关闭。

最小连接数：也可以配置一个最小连接数——池中始终保持至少 N 个连接。空闲回收时如果连接数已经降到最小值，就不再继续回收。

并发安全：多个线程同时获取和归还连接，不能出现同一个连接被分给两个线程的情况。

有个隐藏坑：归还的连接可能处于不干净的状态——上一个使用者可能遗留了未读完的数据或者连接处于半关闭状态。归还时最好做一些清理操作（比如读取并丢弃残留数据），确保下一个使用者拿到的是干净的连接。

用纯 C 写，gcc 在 Linux 上编译通过。写个 main 演示：创建连接池，模拟并发获取和归还。

代码要拆成至少 4 个源文件，按功能模块分——连接获取与归还、健康检查与回收、并发安全控制、主程序。头文件和实现文件分开。gcc -lpthread 编译能过。

服务端的监听端口应该支持通过命令行参数或环境变量来指定，不要硬编码。
