帮我用 C 写一个高性能的异步日志写入模块。我们的服务每秒产生大量日志，直接写磁盘文件太慢（磁盘 I/O 会阻塞业务线程），需要一个缓冲层把日志先存到内存，然后由专门的写入线程异步刷到磁盘。

设计模式：单个写入线程 + 多个业务线程。业务线程调用日志写入方法时，把日志消息拷贝到一个共享的环形缓冲区就立即返回，不等待磁盘写入完成。写入线程不断从缓冲区取消息写入文件。

环形缓冲区：固定大小（比如 64MB），写入位置和读取位置各有一个索引。写入时数据追加到写入位置后面，读取时从读取位置取数据。缓冲区满时，新消息覆盖最旧的消息（丢弃策略），或者阻塞等待（可配置）。

无锁设计：理想情况下业务线程写入时不加锁，只用原子操作更新写入索引。写入线程读取时也只用原子操作更新读取索引。这样在多核 CPU 上业务线程之间完全不会互相阻塞。

消息格式：每条消息包含时间戳（微秒级精度）、日志级别（DEBUG/INFO/WARN/ERROR）、线程 ID、源文件名、行号、日志内容。写入时把这些信息格式化成一个字符串存入缓冲区。

刷盘策略：缓冲区中的数据不一定要立即写入磁盘。可以配置两种策略：每条日志立即刷盘（最安全但最慢）、缓冲区使用量超过阈值时刷盘（折中方案）。应用退出时必须把缓冲区中剩余数据全部刷完。

性能指标：业务线程的日志写入延迟应该不超过 1 微秒（不含格式化时间）。在 8 核机器上，多线程并发写日志的吞吐量应该随线程数线性增长。

有个关键挑战：单个写入线程是瓶颈——如果写入速度跟不上产生速度，缓冲区会被填满。需要在缓冲区快满时让写入线程优先工作（比如提高它的调度优先级），同时业务线程可以临时降低日志级别来减少数据量。

用纯 C 写，gcc 在 Linux 上编译通过。写个 main 演示：多线程并发写日志，验证不丢不乱。

代码要拆成至少 4 个源文件，按功能模块分——无锁环形缓冲区、日志格式化、异步刷盘控制、主程序。头文件和实现文件分开。gcc 编译能过。
