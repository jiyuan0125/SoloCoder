帮我用 Go 写一个投诉处理系统，核心是工单管理、派发和回访。核心功能做成一个独立的 package，服务端引用核心库对外提供 HTTP 接口，客户端是命令行工具通过 HTTP 调用服务端。

投诉工单创建有两种入口，客服手动录入填投诉人姓名、联系电话、投诉内容、投诉渠道（电话、微信、APP、现场），或者外部系统通过 API 推送。工单创建后自动生成工单号，格式是 TS 加年月日加四位流水号。工单按投诉类型分类（服务质量、产品质量、物流问题、售后问题、其他），不同类型的处理时限不同，服务质量类24小时内响应，物流问题12小时内响应。超过时限未响应的工单自动升级为超时状态。

派发逻辑是工单创建后进入待派发池，派发专员根据投诉类型和地区分配给对应的责任部门。派发时选择紧急程度（普通、紧急、特急），特急工单同时发通知给责任部门负责人。责任部门处理完后填写处理结果，状态变为待回访。

回访模块，工单处理完成后24到72小时内由回访人员对投诉人进行回访，记录回访结果（满意、基本满意、不满意）和备注。不满意则工单重新打回给责任部门重新处理，最多打回两次，第三次仍不满意升级到部门经理处理。

指标聚合统计今日新增工单数、处理中工单数、已关闭工单数、平均处理时长（从创建到处理完成的小时数）、回访满意率（满意加基本满意除以总回访数）。平均处理时长排除超时升级的工单。满意率按最近30天滚动计算。同一工单被多个客服同时操作要保证数据一致性。

核心功能实现为一个独立 package。在此基础上写两个程序：服务端引用核心库对外提供 HTTP 接口，客户端是命令行工具通过 HTTP 调用服务端。服务端和客户端各自独立 main 包，请求响应格式定义放在公共包。核心库、服务端、客户端各按职责分文件。先 go mod init 再开发，go build ./... 能编译通过。服务端的监听端口应该支持通过命令行参数或环境变量来指定。
