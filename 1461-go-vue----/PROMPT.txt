帮我用 Go 写一个质量追溯系统，制造业工厂用来管理生产批次、工序和检验记录。核心功能做成一个独立的 package，服务端引用核心库对外提供 HTTP 接口，客户端是命令行工具通过 HTTP 调用服务端。

批次管理是起点，每批产品生产时创建一个生产批次记录，包含批次号（格式为工厂代码加年月日加三位流水号）、产品名称、计划生产数量、实际生产数量、生产开始和结束时间。批次号在同一个工厂同一天内不能重复。实际生产数量和计划数量偏差率超过10%要标记为异常批次。批次创建后不允许修改批次号和产品名称。

工序管理记录每个批次经过的生产工序。每个产品类型有不同的工序流程。每道工序完成后操作工登记，记录实际操作人、开始时间、完成时间、工序结果（合格、不合格）。工序按定义的顺序执行，不能跳过。某道工序结果为不合格，该批次暂停进入下一道工序等待品质部门判定是返工还是报废。返工的批次重新从出问题的那道工序开始，返工次数超过2次自动标记为报废。

检验模块分来料检验、过程检验和成品检验三种。检验指标有上下限值，检验结果在上下限之间为合格。所有检验记录都关联到批次号。数据导出方面批次列表、工序记录和检验记录都支持导出 CSV。

指标聚合展示最近30天的批次一次合格率（没有经过返工直接全部合格的批次比例）、各工序的不良率。如果某批次还在生产中没有完工检验结果，不应该纳入一次合格率的计算。同一批次的多道工序如果同时有数据上报，服务端要正确处理并发。

核心功能实现为一个独立 package。在此基础上写两个程序：服务端引用核心库对外提供 HTTP 接口，客户端是命令行工具通过 HTTP 调用服务端。服务端和客户端各自独立 main 包，请求响应格式定义放在公共包。核心库、服务端、客户端各按职责分文件。先 go mod init 再开发，go build ./... 能编译通过。服务端的监听端口应该支持通过命令行参数或环境变量来指定。
