帮我用 Go 写一个实验室管理系统，检测机构或工厂实验室用的，管样品、检测和报告。核心功能做成一个独立的 package，服务端引用核心库对外提供 HTTP 接口，客户端是命令行工具通过 HTTP 调用服务端。

样品管理是流程的起点，客户送样时录入样品信息，包括样品编号（自动生成，格式LB加年月日加三位流水号）、样品名称、样品数量、送样客户、送样日期、检测要求。样品入库后分配到一个存储位置（实验室有若干样品柜，每个柜子有编号和容量）。样品数量超过5个或者单个样品体积超过规定标准的要标记为大样并安排特殊存储。样品状态分为待检测、检测中、已检毕、已退回、已销毁，状态流转要记录日志。

检测模块是核心，每个检测项目有标准方法编号、检测步骤描述、判定标准。检测人员领取样品后开始检测，逐项录入检测数据。检测数据根据项目类型有不同格式，数值型录入数值和单位，判定型录入合格或不合格。检测完成后所有项目都合格则样品判定为合格，有任一项目不合格则判定为不合格。某些检测项目有复检规则，第一次不合格可以申请复检一次，复检结果作为最终结果。复检申请需要实验室主管审批。

报告模块在检测完成后自动生成检测报告草稿，包含样品信息、检测项目、检测结果、判定结论。报告有唯一编号，格式为RPT加年月加四位流水号。主管审核报告后签发，签发后的报告不可修改，发现错误只能作废原报告重新生成。超期未检测的样品（送样超过7天未开始检测）要自动提醒。

同一个样品柜不能分配给超出容量的样品。多个检测人员同时领取不同的样品，服务端要正确处理并发状态变更。

核心功能实现为一个独立 package。在此基础上写两个程序：服务端引用核心库对外提供 HTTP 接口，客户端是命令行工具通过 HTTP 调用服务端。服务端和客户端各自独立 main 包，请求响应格式定义放在公共包。核心库、服务端、客户端各按职责分文件。先 go mod init 再开发，go build ./... 能编译通过。服务端的监听端口应该支持通过命令行参数或环境变量来指定。
