帮我用 Go 写一个竣工结算系统，工程项目完工后用的，管工程量核算、签证和审计。核心功能做成一个独立的 package，服务端引用核心库对外提供 HTTP 接口，客户端是命令行工具通过 HTTP 调用服务端。

工程量管理维护项目各分部分项的工程量清单，每条清单包含项目编码、项目名称、计量单位、合同工程量（投标时的数量）、实际工程量（完工后核实的数量）。偏差率等于实际减合同除以合同乘以100。偏差率超过正负5%的需要标记为异常工程量重点审核。工程量的单位各不相同有平方米、立方米、米、个、吨等，输入时要校验数值不能为负数且合同工程量不能为零。项目编码在同一项目内不能重复。

签证管理记录施工过程中的工程变更签证。每条签证有签证编号（自动生成）、签证原因、变更内容描述、增加的工程量、减少的工程量、签证金额。签证金额的计算涉及综合单价，金额计算要精确到分。签证需要监理单位和建设单位双方确认才能生效，确认后的签证金额计入结算总额。签证编号按项目维度连续编号每个项目从001开始。驳回的签证可以修改后重新提交。

审计模块对整个项目的结算数据进行审计。结算金额等于合同金额加上签证增加金额减去签证减少金额，再加上工程量偏差的调价金额。调价金额的计算规则是偏差率在正负5%以内的不调价，超过5%的部分按超出比例乘以该分项的合同金额计算。所有金额精确到分。审计人员可以添加审计意见，审核通过后结算数据锁定不可再修改。

审计日志记录结算过程中所有的修改操作不可删除不可修改。多个审计人员同时操作同一个项目的结算数据，服务端要保证数据一致性。

核心功能实现为一个独立 package。在此基础上写两个程序：服务端引用核心库对外提供 HTTP 接口，客户端是命令行工具通过 HTTP 调用服务端。服务端和客户端各自独立 main 包，请求响应格式定义放在公共包。核心库、服务端、客户端各按职责分文件。先 go mod init 再开发，go build ./... 能编译通过。服务端的监听端口应该支持通过命令行参数或环境变量来指定。
