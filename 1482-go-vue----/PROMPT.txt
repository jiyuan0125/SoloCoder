帮我用 Go 写一个汽车维修管理系统，给汽修店用，管工单、配件和工时。核心功能做成一个独立的 package，服务端引用核心库对外提供 HTTP 接口，客户端是命令行工具通过 HTTP 调用服务端。

客户开车来店里，前台创建一个维修工单。工单记录车牌号、客户姓名、联系电话、车辆问题描述和故障类型（保养、发动机、变速箱、底盘、电气、空调、钣金喷漆）。维修技师接单后可以添加维修项目，每个项目包含项目名称、所需配件列表、预估工时和实际工时。配件管理是独立的模块，每个配件有编码、名称、规格、单价（精确到分）、库存数量。

工时计费方面，维修工按级别分学徒工、中级工、高级工三个等级，不同等级的工时费不同：学徒工每小时60元，中级工每小时100元，高级工每小时150元。每个维修项目指定负责的技师等级和工时数。实际完工后按实际工时计费。实际工时超过预估工时的50%以上的需要技师填写超时原因，系统标记为异常工时。

配件出库要严格管理。配件从仓库领用到工单时扣减库存，工单取消或配件退回时要加回库存。库存数量降到预警值以下时生成补货待办。配件的价格可能会调整，但已出库到工单上的配件按出库时的单价计算，不受后续调价影响。

工单费用合计等于所有维修项目的工时费总和加上所有配件费用总和。工时费精确到角向下取整。比如某个高级工做了2.35小时，费用是2.35乘150等于352.5元取整为352元。

多个技师同时从仓库领用同一个配件，服务端要正确处理并发确保库存不为负数。

核心功能实现为一个独立 package。在此基础上写两个程序：服务端引用核心库对外提供 HTTP 接口，客户端是命令行工具通过 HTTP 调用服务端。服务端和客户端各自独立 main 包，请求响应格式定义放在公共包。核心库、服务端、客户端各按职责分文件。先 go mod init 再开发，go build ./... 能编译通过。服务端的监听端口应该支持通过命令行参数或环境变量来指定。
