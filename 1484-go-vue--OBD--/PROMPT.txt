帮我用 Go 写一个车联网数据分析平台，数据来自车载 OBD 设备上传的驾驶行为和油耗信息。核心功能做成一个独立的 package，服务端引用核心库对外提供 HTTP 接口，客户端是命令行工具通过 HTTP 调用服务端。

每辆车有一个设备ID，设备定期上传数据包，包含时间戳、GPS经纬度、瞬时速度、发动机转速、油耗率（每百公里升数）、急加速次数、急刹车次数和急转弯次数。数据上传频率是每30秒一次。设备偶尔会断线重连，重连后补传离线期间的数据，数据可能存在时间戳重复的情况，系统需要做去重处理。

指标聚合是核心功能。按车辆维度聚合可以得到单车的日均行驶里程、平均油耗、百公里安全评分。按时间维度聚合可以得到每日全车队的总行驶里程、平均油耗、异常驾驶事件总数。安全评分的计算方式是基础100分，每次急加速扣3分，急刹车扣5分，急转弯扣2分。日安全评分等于100减去当天所有扣分之和，最低为0分。

油耗分析要处理数据导出。按月导出每辆车的油耗明细 CSV 文件，字段包括日期、行驶里程、总油耗、平均油耗、安全评分。导出时某辆车某天没有数据记录的（设备离线），该天在 CSV 中仍然要有一行，里程和油耗填0，安全评分不填。CSV 使用 UTF-8 BOM 编码确保 Excel 直接打开不乱码。

驾驶行为告警方面，单次急刹车速度下降超过30km/h标记为严重急刹车，日急刹车次数超过10次触发安全告警，连续3天安全评分低于60分触发驾驶习惯告警。告警生成后进入待处理队列。告警不能重复生成，同一辆车同一天只生成一次同类型告警。

核心功能实现为一个独立 package。在此基础上写两个程序：服务端引用核心库对外提供 HTTP 接口，客户端是命令行工具通过 HTTP 调用服务端。服务端和客户端各自独立 main 包，请求响应格式定义放在公共包。核心库、服务端、客户端各按职责分文件。先 go mod init 再开发，go build ./... 能编译通过。服务端的监听端口应该支持通过命令行参数或环境变量来指定。
