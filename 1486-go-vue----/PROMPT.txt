帮我用 Go 写一个智能快递柜的管理系统，管存件、取件和格口管理。核心功能做成一个独立的 package，服务端引用核心库对外提供 HTTP 接口，客户端是命令行工具通过 HTTP 调用服务端。

每个快递柜有一个编号和安装地址，柜子分成大中小三种格口。大格口50乘40乘30厘米，中格口40乘30乘25厘米，小格口30乘25乘20厘米。每个格口有唯一编号和当前状态：空闲、已存件、超时未取。快递员存件时选择合适的格口，输入收件人手机号后四位，系统生成一个6位数字取件码。

取件流程是收件人输入取件码，系统验证后打开对应格口。取件码在存件后24小时内有效。超时未取的包裹状态变为超时，快递员可以将其取出重新投递或退回发件方。每天早上8点系统自动扫描所有超时包裹生成超时处理待办清单。

营业时间的规则需要处理。管理员为每个快递柜配置营业时间，比如每天7:00到22:00。非营业时间内快递员可以存件但用户不能取件，取件码的有效期从营业开始时间起算。比如凌晨3点存的件，营业时间从7点开始，那取件码有效期到第二天7点。

计费方面，快递员每次使用格口收费：小格口0.3元，中格口0.5元，大格口0.8元。费用从快递员的预存账户余额中扣除，余额不足时无法存件。

同一个格口不能连续被同一个快递员使用超过3次。系统在分配格口时优先选择空闲格口中编号最小的，但如果该快递员最近3次都用了同一个格口则跳过选下一个。多个快递员同时向同一个快递柜存件，服务端要正确处理并发确保格口不被重复分配。

核心功能实现为一个独立 package。在此基础上写两个程序：服务端引用核心库对外提供 HTTP 接口，客户端是命令行工具通过 HTTP 调用服务端。服务端和客户端各自独立 main 包，请求响应格式定义放在公共包。核心库、服务端、客户端各按职责分文件。先 go mod init 再开发，go build ./... 能编译通过。服务端的监听端口应该支持通过命令行参数或环境变量来指定。
