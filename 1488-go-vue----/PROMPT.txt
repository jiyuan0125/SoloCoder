帮我用 Go 写一个家政服务预约平台，管阿姨档案、客户下单预约和评价打分。核心功能做成一个独立的 package，服务端引用核心库对外提供 HTTP 接口，客户端是命令行工具通过 HTTP 调用服务端。

阿姨入驻平台时提交个人信息：姓名、年龄、手机号、服务类别（日常保洁、深度清洁、月嫂、育婴师、老人陪护）、从业年限、服务区域。每个阿姨有一个综合评分，初始5.0分，每次客户评价后重新计算。评分算法是取最近20条评价的加权平均分，最近5条评价权重1.2更早的权重1.0。评价不足20条的取全部评价计算。评分精确到一位小数四舍五入。

客户下单时选择服务类别、服务日期、预计服务时长（2小时起每半小时一个档位最长8小时）、服务地址。系统根据条件匹配合适的阿姨。阿姨每天最多接3单，每单之间至少预留30分钟交通时间。某个时段没有阿姨可用的订单进入待匹配状态，有阿姨空闲后系统自动分配。

阿姨开始服务后点击开始，结束服务后点击完成并填写实际服务时长。实际时长超出预估时长30分钟以内按预估时长计费，超出30分钟以上的部分按半小时一档加收费用。比如预估3小时实际3小时40分钟，计费3.5小时。

费用计算是基础单价乘以服务时长。日常保洁每小时45元，深度清洁每小时65元，月嫂每天200元，育婴师每天180元，老人陪护每天150元。日结服务按天算小时服务按小时算。所有费用精确到元。

管理后台统计每个阿姨的月度接单数、总服务时长、平均评分、客户复购率（下过单的客户中再次下单的比例）。多个客户同时预约同一个阿姨的同一时段，服务端要正确处理并发确保不冲突。

核心功能实现为一个独立 package。在此基础上写两个程序：服务端引用核心库对外提供 HTTP 接口，客户端是命令行工具通过 HTTP 调用服务端。服务端和客户端各自独立 main 包，请求响应格式定义放在公共包。核心库、服务端、客户端各按职责分文件。先 go mod init 再开发，go build ./... 能编译通过。服务端的监听端口应该支持通过命令行参数或环境变量来指定。
