帮我用 Go 写一个管道疏通报修管理系统，居民报修管道堵塞，系统自动派单给维修师傅，师傅上门处理完成后客户验收确认。核心功能做成一个独立的 package，服务端引用核心库对外提供 HTTP 接口，客户端是命令行工具通过 HTTP 调用服务端。

报修流程从用户提交报修单开始。用户填写地址、联系方式、堵塞类型（厨房下水道、卫生间下水道、马桶、地漏、主管道）、堵塞程度（轻微流水慢、严重完全堵塞）、是否反复堵塞。系统根据报修地址自动匹配负责该片区的维修站点，然后从站点中筛选空闲的师傅进行派单。

派单有调度逻辑。每个维修站点有若干师傅，每个师傅有技能标签（普通疏通、高压清洗、管道检测、管道更换）。厨房和卫生间堵塞派普通疏通技能的师傅，主管道堵塞需要高压清洗技能的师傅，反复堵塞需要管道检测技能的师傅。当前站点没有合适技能的空闲师傅向邻近站点借调。师傅每天最多接5单，同时只能处理一个工单。

师傅接单后前往现场，疏通完成后填写维修记录：使用的疏通方式（手工疏通、管道疏通机、高压清洗）、疏通时长、是否更换了管道配件、配件名称和费用。维修费用分人工费和材料费两部分。人工费按疏通方式不同：手工疏通80元，管道疏通机120元，高压清洗200元。材料费按实际使用的配件计算。

验收环节由客户完成。师傅提交完工后客户查看费用明细确认验收。客户对疏通效果不满意可以拒绝验收系统重新派单。同一报修单最多重新派单2次，第3次仍不满意则升级为投诉工单由主管介入处理。

多个报修单同时到达，服务端要正确处理并发派单确保同一个师傅不会被分配多个同时进行的工单。

核心功能实现为一个独立 package。在此基础上写两个程序：服务端引用核心库对外提供 HTTP 接口，客户端是命令行工具通过 HTTP 调用服务端。服务端和客户端各自独立 main 包，请求响应格式定义放在公共包。核心库、服务端、客户端各按职责分文件。先 go mod init 再开发，go build ./... 能编译通过。服务端的监听端口应该支持通过命令行参数或环境变量来指定。
