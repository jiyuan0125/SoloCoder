帮我用 Go 写一个家电维修上门服务平台，用户报修家电故障，系统做故障诊断引导，师傅带备件上门维修。核心功能做成一个独立的 package，服务端引用核心库对外提供 HTTP 接口，客户端是命令行工具通过 HTTP 调用服务端。

用户提交维修请求时选择家电品类（空调、冰箱、洗衣机、电视、热水器、油烟机、燃气灶），填写品牌和型号，描述故障现象。系统根据品类和故障描述做初步的故障诊断引导，给出可能的原因列表和预估维修费用范围。比如空调不制冷可能是缺氟、压缩机故障、滤网堵塞，对应预估费用分别是150到300元、800到1500元、50到100元。

备件管理维护常用备件的库存信息，每个备件有编码、名称、适用品类和品牌、单价和库存数量。师傅接单后根据故障诊断结果申请备件，系统扣减库存。库存不足的生成采购待办。维修完成后未使用的备件要退回仓库加回库存。备件价格调整后已出库的按原价计算。

师傅派单逻辑根据品类和区域匹配。每个师傅标注自己擅长的品类和服务区域。系统优先派给擅长该品类且在用户附近的师傅。师傅每天最多接6单，每单之间预留1小时交通和维修时间。当前没有合适师傅的订单进入等待队列按下单时间顺序自动分配。

维修完成后师傅填写维修报告：故障原因、更换的备件列表、维修费用明细。费用包含上门费50元加备件费加人工费（按品类固定：空调100元、冰箱80元、洗衣机80元、电视60元、热水器100元、油烟机60元、燃气灶60元）。

多个师傅同时申请同一个备件，服务端要正确处理并发确保库存不为负数。

核心功能实现为一个独立 package。在此基础上写两个程序：服务端引用核心库对外提供 HTTP 接口，客户端是命令行工具通过 HTTP 调用服务端。服务端和客户端各自独立 main 包，请求响应格式定义放在公共包。核心库、服务端、客户端各按职责分文件。先 go mod init 再开发，go build ./... 能编译通过。服务端的监听端口应该支持通过命令行参数或环境变量来指定。
