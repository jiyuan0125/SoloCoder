帮我用 Go 写一个装修设计管理平台，管设计方案、报价和施工进度跟踪。核心功能做成一个独立的 package，服务端引用核心库对外提供 HTTP 接口，客户端是命令行工具通过 HTTP 调用服务端。

客户联系后设计师先记录房屋基本信息：面积（精确到0.1平方米）、户型（几室几厅）、楼层、朝向。然后设计师出设计方案，方案包含多个空间的设计说明，每个空间标注设计风格和主要材料。一个方案可以有多个版本，客户选择确认后才进入报价环节。

报价按施工项目和材料两个维度来组织。施工项目包括拆除、水电改造、防水、瓦工、木工、油漆、安装等大类，每个大类下有具体的子项目。每个子项目有单位、工程量和单价。材料清单独立管理，每种材料有名称、规格、品牌、单价、用量。报价总金额等于所有施工项目费用之和加上所有材料费用之和，精确到元，用整数分存储。

工程量变更方面，施工过程中客户可能要求增减项目，每次变更生成一份变更单记录变更内容、原因和费用差额。变更单需要客户确认后生效。最终结算金额等于原始报价加上所有已确认变更单的费用差额。某个子项目的实际工程量跟报价时不一样且差额超过10%的，需要重新确认。

施工进度管理按待办事项的方式。每个施工大类作为一个阶段按顺序执行。每个阶段有预计开始和结束日期，实际进度由项目经理更新。某个阶段延期超过3天的系统生成延期告警。

多个施工队同时更新不同阶段的进度，服务端要正确处理并发。金额计算全部用整数分存储。

核心功能实现为一个独立 package。在此基础上写两个程序：服务端引用核心库对外提供 HTTP 接口，客户端是命令行工具通过 HTTP 调用服务端。服务端和客户端各自独立 main 包，请求响应格式定义放在公共包。核心库、服务端、客户端各按职责分文件。先 go mod init 再开发，go build ./... 能编译通过。服务端的监听端口应该支持通过命令行参数或环境变量来指定。
