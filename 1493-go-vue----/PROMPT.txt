帮我用 Go 写一个保洁服务调度管理系统，管服务区域、保洁员排班和任务分配、还有服务质量检查。核心功能做成一个独立的 package，服务端引用核心库对外提供 HTTP 接口，客户端是命令行工具通过 HTTP 调用服务端。

服务区域是按客户合同来划分的。每个客户有固定的保洁服务合同，包含服务地址、服务面积、清洁频次（每天一次、每周三次、每周两次、每周一次）和特殊要求。每个合同关联一个或多个服务区域。

保洁员管理包括人员信息和技能标签。保洁员有基础保洁和深度保洁两种技能等级。每个保洁员被分配到一个固定的班组，班组有负责的片区。排班按周来做，管理员为每个班组设置每周的排班表。保洁员请假或调班需要提前一天申请，审批通过后排班表自动更新。

任务调度是系统的核心。系统根据所有客户的合同和服务频次自动生成每周的保洁任务清单。每天的任务包含任务编号、客户名称、服务地址、服务区域、清洁类型（基础或深度）、预计工时、分配的保洁员。每个保洁员每天的总工时不超过8小时，同一片区的任务优先分配给该片区的保洁员。当天任务量超过可用人员工时的，多出来的任务标记为待分配状态。

质检是待办驱动的工作流。每次保洁完成后质检员在24小时内到现场检查，填写质检表。质检项包括地面清洁度、桌面整洁度、垃圾清理情况等每项打1到5分。总分低于15分的任务生成整改待办分配给原保洁员返工。返工后需要二次质检。同一任务三次质检都不合格的升级为班组管理问题。

多个任务同时生成和分配，服务端要正确处理并发确保每个保洁员的工时不超过8小时上限。

核心功能实现为一个独立 package。在此基础上写两个程序：服务端引用核心库对外提供 HTTP 接口，客户端是命令行工具通过 HTTP 调用服务端。服务端和客户端各自独立 main 包，请求响应格式定义放在公共包。核心库、服务端、客户端各按职责分文件。先 go mod init 再开发，go build ./... 能编译通过。服务端的监听端口应该支持通过命令行参数或环境变量来指定。
