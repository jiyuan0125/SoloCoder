帮我用 Go 写一个绿化养护管理系统，管植物信息、浇水修剪等养护工作和养护人员调度。核心功能做成一个独立的 package，服务端引用核心库对外提供 HTTP 接口，客户端是命令行工具通过 HTTP 调用服务端。

植物档案管理是基础模块。每个养护区域下有多棵植物或植物群落，记录植物名称、品种、种植日期、位置描述、健康状态（良好、一般、较差、枯萎）。植物按类型分为乔木、灌木、草坪、花卉四类，不同类型的养护要求不同。

养护任务分常规任务和临时任务。常规任务是按养护计划自动生成的，比如草坪每周浇水两次、每月修剪一次，乔木每季度修剪一次。管理员为每个区域配置养护计划，系统根据计划自动创建任务并分配给养护人员。临时任务是巡检时发现植物有问题手动创建的，比如发现病虫害需要消杀处理。

养护人员调度方面，每个养护人员有工号、姓名、技能等级（初级、中级、高级）和负责区域。调度时根据任务类型匹配技能等级：修剪乔木需要高级人员，草坪浇水初级人员即可。每个人每天工作8小时，系统根据每项任务的预估工时来分配确保不超过8小时上限。某个区域当天任务量过大的可以从其他区域临时调人。

任务执行和验收走待办流程。养护人员接到任务后执行，完成后上传记录。主管验收后确认通过或打回。打回的任务注明原因重新进入待办。同一个任务最多打回两次，第三次自动升级为紧急工单由主管亲自处理。

养护成本统计方面，每项任务记录使用的材料和人工工时，月底按区域汇总生成成本报告。材料费用精确到分，人工费用按人员等级小时费率乘以工时计算（初级每小时30元、中级每小时45元、高级每小时60元）。

核心功能实现为一个独立 package。在此基础上写两个程序：服务端引用核心库对外提供 HTTP 接口，客户端是命令行工具通过 HTTP 调用服务端。服务端和客户端各自独立 main 包，请求响应格式定义放在公共包。核心库、服务端、客户端各按职责分文件。先 go mod init 再开发，go build ./... 能编译通过。服务端的监听端口应该支持通过命令行参数或环境变量来指定。
