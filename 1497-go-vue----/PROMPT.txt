帮我用 Go 写一个二手闲置交易平台，用户发布闲置物品、其他用户浏览和议价、达成交易后确认成交。核心功能做成一个独立的 package，服务端引用核心库对外提供 HTTP 接口，客户端是命令行工具通过 HTTP 调用服务端。

用户发布商品时填写标题、描述、分类（数码电子、家居用品、图书文具、服饰鞋包、运动户外、其他）、新旧程度（全新未拆、几乎全新、轻微使用痕迹、明显使用痕迹）、原价和售价。售价是卖家的期望价格精确到元。商品发布后进入审核状态管理员审核通过后上架。每个用户同时最多发布20件在售商品。

浏览和议价是核心交互。买家可以按分类、价格区间和新旧程度筛选，也可以按关键词搜索标题和描述。买家对感兴趣的商品可以出价，出价要等于或高于卖家标价的50%。卖家收到出价通知后可以选择接受、拒绝或还价。买卖双方最多来回议价3轮，3轮内未达成一致则交易关闭。每一轮议价都有时间限制24小时超时未回应视为放弃。还价金额必须低于上一轮价格且不能低于自己标价的50%。

交易确认流程是待办驱动的。买家出价被接受后生成交易订单状态为待付款。买家确认付款后（模拟）状态变为待发货。卖家发货后填写物流单号状态变为待收货。买家确认收货后状态变为已完成。待付款状态超过48小时买家未付款的订单自动取消。待收货状态超过7天买家未确认的系统自动确认收货。

商品下架处理方面，卖家在商品有人出价但还没成交的状态下不能直接下架商品。商品已售出的系统自动标记为已售并从列表中移除。

平台对每笔成交收取卖家2%的服务费精确到角四舍五入。成交金额不足10元的免收服务费。金额用整数分存储。多个买家同时出价同一个商品，服务端要正确处理并发。

核心功能实现为一个独立 package。在此基础上写两个程序：服务端引用核心库对外提供 HTTP 接口，客户端是命令行工具通过 HTTP 调用服务端。服务端和客户端各自独立 main 包，请求响应格式定义放在公共包。核心库、服务端、客户端各按职责分文件。先 go mod init 再开发，go build ./... 能编译通过。服务端的监听端口应该支持通过命令行参数或环境变量来指定。
