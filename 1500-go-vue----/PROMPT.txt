帮我用 Go 写一个小区业主委员会管理系统，管业委会选举、业主提案和公告公示。核心功能做成一个独立的 package，服务端引用核心库对外提供 HTTP 接口，客户端是命令行工具通过 HTTP 调用服务端。

业主信息管理是基础。系统录入小区所有业主的信息：姓名、手机号、房号、建筑面积、入住状态（已入住、空置、出租）。每个业主根据其房屋建筑面积拥有投票权份额，比如100平方米的房屋有100份投票权。业主可以委托其他业主代为投票，委托关系需要双方确认后生效。

选举管理是核心模块。业委会换届选举时管理员发布选举公告，公示候选人名单和选举规则。候选人由业主自荐或推荐产生，每个候选人需要获得至少20名业主联名推荐。选举采用线上投票方式投票期为7天。每个业主（含受托投票的）投出的票权等于其建筑面积对应的份额。计票时候选人按总得票份额从高到低排序，取前N名当选（N为业委会委员人数由上届业委会在选举前确定）。

投票系统有几个规则。投票是不可撤销的一旦提交不能更改。可以投弃权票，弃权票不参与任何候选人的得票计算。同一业主被多人委托投票的，只有第一个确认的委托关系有效，后续委托自动失效并通知委托人。投票截止后如果某候选人得票份额相同由上届业委会抽签决定排名。

提案管理让业主提交关于小区管理的事项。提案包含标题、内容描述、提案人、附议人列表。提案需要至少10名业主附议才能进入审议流程。业委会审议后给出处理意见：采纳、部分采纳、暂缓、驳回。采纳的提案生成执行待办指定负责部门和完成期限。

公告公示模块用于发布小区重要通知。公告有标题、内容、发布日期和有效期。过期公告自动归档但仍可查阅。

多个业主同时投票，服务端要正确处理并发确保投票权份额的准确计算。投票份额用整数存储。

核心功能实现为一个独立 package。在此基础上写两个程序：服务端引用核心库对外提供 HTTP 接口，客户端是命令行工具通过 HTTP 调用服务端。服务端和客户端各自独立 main 包，请求响应格式定义放在公共包。核心库、服务端、客户端各按职责分文件。先 go mod init 再开发，go build ./... 能编译通过。服务端的监听端口应该支持通过命令行参数或环境变量来指定。
