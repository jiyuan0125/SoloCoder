生鲜电商平台的后端支撑系统要我们来建，这是一个从产地到餐桌的全链路管理系统。技术栈是 Go 后端加 Vue 前端。数据全部放内存。

系统管理多个产地信息，每个产地有名称、地址、主要产品类别（水果、蔬菜、肉禽、水产）。冷链物流是重点，平台有一批冷藏车，每辆车有编号、当前温度、载重量上限（吨）、当前载重量。配送任务由调度器统一管理，每个配送任务关联一个订单，包含起始地点（产地或仓库）、目的地、商品名称、重量、要求温度范围。调度器根据距离和温度要求分配给合适的冷藏车。车辆出发后定时上报GPS位置和车厢温度，前端地图页面实时展示所有在途车辆的位置和温度状态。

数据导出功能提供给运营团队。可以选择日期范围，导出该时段内的所有配送任务记录，包括任务编号、商品、重量、起始地、目的地、实际送达时间、是否超时。导出格式为纯文本表格，前端直接展示可复制。运营用这些数据做月度分析。

业务规则上有几个容易出错的地方。调度器分配冷藏车时，如果该车的当前载重量加上新任务重量超过载重上限，不能分配给这辆车，跳过找下一辆。车厢温度如果超出任务要求的温度范围，系统标记为温度异常并记录，但不自动中断配送，由调度中心人工决定是否需要处理。同一辆车不能同时被分配两个温度要求冲突的任务，比如一个要求0到4度另一个要求常温15到25度。导出数据时如果选择的日期范围内没有记录，返回一条提示信息而不是空内容。配送任务如果24小时内没有任何温度上报记录，标记为通讯中断，不标记为超时。冷藏车载重量不能为负数。前端任务列表页面支持按状态筛选，包括待分配、配送中、已完成、温度异常、通讯中断等多种状态。配送完成后自动释放冷藏车载重量。产地管理页面展示各产地的产品信息和最近的配送记录，方便运营团队了解产地出货情况。车辆管理页面展示每辆冷藏车的当前状态、位置和温度。

Go 用 net/http 搭建 API 服务，数据存内存用 map 和 slice。Vue 前端用 CDN 引入，组件化组织，fetch 调后端。
