| User Prompt | 帮我用 C 写一个共享资源的管理模块。场景是这样的：我们正在开发一个图片处理服务，系统里有一些大对象（比如加载好的图片数据、编译好的模板文件），创建成本很高，多个地方需要用到同一个对象。管理模块负责跟踪每个对象被多少地方引用着——有新的地方开始用就引用计数加一，某个地方用完了不再需要就减一。当引用数减到零的时候，说明没人用了，就把这个对象占用的内存释放掉。要求：同一个对象在内存里只能有一份拷贝，多个使用者共享同一份内存，不能每个使用者各持一份。如果一个对象已经被释放了，还有人试图引用它，应该安全地拒绝（或者自动重新创建）而不是让程序崩溃。支持通过一个字符串标识来查找和获取对象，找不到就创建新的并加入管理。对象被引用期间不能被意外释放——即使只有一个地方还在用，也不能被其他人释放。要考虑多线程安全——不同的线程可能同时获取和释放对象，引用计数的增减必须是原子操作，不能出现计数错误。支持查看当前被管理的所有对象列表以及各自的引用计数。还要考虑循环引用的情况——如果对象 A 引用了对象 B，对象 B 又引用了对象 A，怎么避免内存永远不被释放。用纯 C 写，gcc 编译通过，不依赖第三方库。模块对外暴露的操作要简洁明了，使用起来不能太复杂。可以参考引用计数智能指针的设计思路，但用纯 C 实现。 代码拆成至少 4 个源文件：引用计数管理、对象存储查找、生命周期管理、主程序，各自有头文件和实现文件。gcc 编译能过。 |
