帮我用 C 写一个大日志文件的内容搜索工具。问题是这样的：线上服务器有一个好几 GB 的 access log 文件，运维人员经常需要在里面搜索某个关键词出现在哪些行，以及上下各 3 行的内容。如果每次都用普通的读文件方式（从头到尾扫描），每次搜索都要把整个文件读一遍，几 GB 的文件太慢了，可能要等好几分钟。要求实现一个加速机制：第一次搜索某个关键词时，扫描整个文件并建一个索引，记录每个关键词出现的行号和在文件中的偏移位置。索引存到磁盘上，下次程序启动时可以直接加载，不用重新扫描。后续再搜同一个词的时候，直接用索引跳到对应位置读取，速度要快得多。日志文件是持续写入的——服务还在运行，日志在不断追加新内容。索引要能增量更新：每次搜索时只扫描上次索引之后新增的部分，不用从头重建整个索引。还要支持同时搜索多个关键词，显示每个关键词的匹配行数和匹配内容。如果搜索的关键词包含正则表达式的特殊字符，要能正确处理或者提供转义选项。日志文件很大，不能全部读进内存，必须分块处理。用纯 C 写，gcc 编译通过，不依赖第三方库。工具的输出要清晰易读——显示匹配行的行号、文件偏移位置、以及匹配行周围上下文的内容。搜索耗时也要显示出来。
代码拆成至少 4 个源文件：索引管理、文件搜索、查询接口、主程序，各自有头文件和实现文件。gcc 编译能过。
