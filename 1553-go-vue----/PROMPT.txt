最近在搞航道管理，需要一个航道综合管理系统，FastAPI 实现。航道区段实测水深低于设计水深减0.5米标记为限航状态。航标管理，一个区段两个以上航标故障或缺失标为航标异常。疏浚计划深度必须大于实测且不超过设计加1米，同区段不能同时两个施工中的计划。

船舶吃水申报自动校验——限航状态申报吃水不能超实测减安全裕度，有施工中疏浚的不超目标深度减安全裕度。区段水深数据更新后关联的已申报船舶吃水校验结果也要重新计算，已经通过校验并完成通行的不再重新计算。

水深监测连续三天持续下降生成预警。每个区段的航标状态、水深记录、疏浚计划和吃水申报都要能通过 /sections/{id}/beacons、/sections/{id}/depth、/sections/{id}/dredging、/sections/{id}/draft-declarations 这些路径分别查询。待办按优先级排，紧急任务处理期限不超24小时。

FastAPI + SQLite，端口环境变量指定，pip install -r requirements.txt 后 python -m server 能启动服务端。
