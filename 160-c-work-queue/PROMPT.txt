帮我用 C 写一个后台任务处理模块。场景是：一个 Web 服务器收到用户请求后，有些操作不适合在请求线程里同步做——比如生成图片缩略图可能要好几秒、发送通知邮件可能要等对方服务器响应、写入大量日志记录需要磁盘IO。这些耗时操作需要放到一个后台处理区里，由专门的几个工作线程异步执行，让请求线程快速返回响应给用户。具体要求：提交到后台的任务有优先级区分——高优先级的（比如支付相关的操作）要先执行，中优先级的（比如发邮件）次之，低优先级的（比如写日志）最后。同优先级的任务按提交的先后顺序执行。工作线程的数量可以在启动时配置。后台处理区有容量上限，如果积压的任务太多（比如超过1000个），新提交的任务直接丢弃并记录一条警告日志。系统关闭时要优雅退出——等所有正在执行的任务完成后再退出，还没开始的任务要清空并通知提交者。支持查询当前积压了多少任务、每个工作线程正在处理什么任务、已经完成了多少任务。提交任务后要能拿到一个任务编号，后续可以用这个编号查询任务的状态（等待中/执行中/已完成/已失败）。用纯 C 写，gcc 编译通过，不依赖第三方库。如果任务执行失败了，要记录失败原因（错误信息或错误码），方便后续排查。支持查询某个任务的详细执行状态和结果。
代码拆成至少 4 个源文件：任务队列管理、优先级调度、工作线程管理、主程序，各自有头文件和实现文件。gcc 编译能过。
