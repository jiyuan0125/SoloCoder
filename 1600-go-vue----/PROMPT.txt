我们天文台最近需要一套观测任务和公众科普预约系统，用 TypeScript 做。

观测任务这块，每月排观测计划，每个任务有目标天体、观测时段、使用设备和负责人。同一台设备同一时段不能重复预约，冲突校验在服务端做。天气原因取消的标记为"天气取消"不计入完成率，设备故障取消的单独标记并记录故障原因。任务流程是待排期→已排期→观测中→已完成→已归档，天气取消和设备故障可以从已排期直接跳到取消，其他状态按顺序走。排期后管理员可以调整任务顺序或更换设备，调整时原设备时段释放新设备时段被占用，调整结果要同步更新到观测日历里，如果新设备正好被另一个任务占了日历上要能看到冲突提示。

公众科普每周六晚开放参观，每场限50人需预约，一个手机号最多约4个名额。参观前24小时可以取消，取消后名额释放给候补列表里的人，候补按先到先得分配。如果某场预约不足10人自动取消该场次并通知已预约的人。遇到特殊天象可以临时加场，不受周六限制但仍需预约和限流。观测数据和活动记录支持按月份和设备维度导出报表。

Express + TypeScript + SQLite，npm run build 能跑起来就行，端口环境变量指定。
