租户管理太乱了，每个客户的配额和告警都靠人工盯，想做一个多租户管理平台，TypeScript 后端。

租户创建时填写企业名称、联系人、联系电话和套餐类型，企业名称不能重复，重复创建返回 409。套餐决定资源配额：用户数上限、存储空间上限和每月 API 调用量上限。系统需要提供套餐的创建、查询、更新、删除接口，也要提供租户的完整 CRUD。某项资源使用量达到配额 80% 时记录告警，达到 100% 时阻止新操作并返回错误码和具体哪个资源超限。管理员给单个租户临时提升配额时记录原因和有效天数，有效期用创建时间加有效天数算，过期后自动恢复原配额。临时配额提升时如果新的配额值小于等于原配额返回 400 拒绝。租户删除时如果还有活跃订阅或未处理告警返回错误提示不能删，错误消息里列出具体哪些资源阻断了删除。配额检查在每个涉及资源消耗的操作之前执行，同一个租户同时只能有一个配额变更操作在执行，并发提交返回 409。

Express + TypeScript + SQLite，npm run build 能编译通过，node dist/server.js 能启动，端口环境变量指定。
