最近在搞UGC内容治理，需要一个内容审核系统，TypeScript + Express 实现。

文本审核维护一套敏感词库，分三个等级：一级违禁词直接拒绝，二级违规词标记待人工审核，三级关注词只记录日志。敏感词匹配要支持模糊匹配，比如"加 微 信"中间有空格也要能识别。图片审核根据URL的hash值决定结果，30%概率待审核，5%概率违规。

规则引擎是核心：每条规则包含条件组合（AND/OR逻辑）、匹配字段和操作。规则按优先级从高到低执行，命中第一条后停止。AND和OR混合嵌套时求值顺序严格按优先级处理。内容有提交审核、自动审核完成、人工复审、最终判定这几个环节，每个环节都有独立的接口，内容详情页也能查看完整审核历史。审核日志在内存中最多保留最近1万条，超出后最早的被淘汰，淘汰时不能影响正在查询的请求。规则执行后如果命中了需要人工复审的条件，系统自动把内容推送到复审队列，推送的时候如果复审队列服务暂时不可用，这条内容就跳过推送留在自动审核完成状态等下次触发。

npm run build 能编译通过，端口环境变量指定。
