最近在搞 UGC 内容治理，需要一个内容审核系统，TypeScript + Express 实现。

文本审核维护一套敏感词库，分三个等级：一级违禁词直接拒绝，二级违规词标记待人工审核，三级关注词只记录日志。敏感词匹配支持模糊匹配，比如"加 微 信"中间有空格也能识别。系统需要提供敏感词的创建、查询、更新、删除接口，也要提供审核规则的 CRUD。图片审核根据 URL 的 hash 值决定结果，30% 概率待审核，5% 概率违规。规则引擎是核心：每条规则包含条件组合（AND/OR 逻辑）、匹配字段和操作，规则按优先级从高到低执行，命中第一条后停止。条件为空或操作为空的规则跳过不执行。

内容状态流转：提交审核→自动审核完成→人工复审→最终判定，只能按顺序走，非法跳转返回 400 和当前状态。每个状态变更都有独立接口：POST /api/contents/{id}/auto-review、POST /api/contents/{id}/manual-review、POST /api/contents/{id}/finalize。命中人工复审条件时系统自动把内容推送到复审队列，推送失败（队列不可用）时内容留在自动审核完成状态，返回 503 和"复审队列暂不可用"的提示，不静默丢弃。审核日志在内存中保留最近 1 万条，超出后最早的被淘汰。删除敏感词时如果它被某条审核规则引用返回错误拒绝删除。查询内容列表时没有匹配结果返回空数组。

npm run build 能编译通过，端口环境变量指定。
