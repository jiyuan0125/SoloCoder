推荐结果不准，运营天天投诉，所以想做一个推荐引擎后台管理服务，TypeScript 后端。电商场景，基于协同过滤做商品推荐。

系统需要提供用户评分的录入、查询、更新、删除接口，以及商品的管理接口。每个用户对购买过的商品打 1 到 5 分，分数超出范围返回 400。基于用户-商品评分矩阵做两种推荐：基于用户的协同过滤（找口味相似的用户推荐他们买过但目标用户没买过的商品）和基于物品的协同过滤（找和目标用户购买过的商品相似的商品推荐），两种结果合并后去重。相似度用余弦相似度，共同评分商品少于 2 个时相似度设为 0。用户对同一商品重复打分以最新一次为准，不产生重复评分记录。

冷启动策略：新用户评分少于 3 条时推荐全站评分最高的 Top 20 商品。新商品至少有 5 个用户评分后才进入推荐候选集，不够时查询该商品推荐返回空数组。推荐覆盖率、准确率（推荐列表中被用户实际点击或购买的比例，分母是总推荐曝光次数）和多样性按天统计。用户修改评分后该商品相关推荐在下一次查询时重新计算，已展示给用户的历史推荐不追溯更新。删除商品时如果还有用户评分关联返回错误拒绝删除。查询推荐时如果用户 ID 不存在返回 404。

Express + TypeScript + SQLite，npm run build 能编译通过。
