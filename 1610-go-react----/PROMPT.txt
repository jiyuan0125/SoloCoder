通知渠道太散了经常漏发重复发的管理平台，TypeScript + Express 后端。

通知模板支持邮件、短信、站内信和钉钉四种类型，提供模板的创建、查询、修改、删除接口。模板内容中用双花括号包裹变量名，变量替换时校验参数完整性，缺失变量时接口返回400错误和缺失的变量名列表。渠道支持配置主备两个实例，主渠道发送失败自动切换到备用，主备切换操作和渠道状态更新在同一次请求内完成，不会出现切换了状态但配置没更新的情况。频率控制：同一用户同一渠道类型最多每分钟1条、每小时5条、每天20条，用滑动窗口实现，超限的通知返回429状态码并在响应体里包含剩余等待秒数。

频率检查和延迟队列投递共用同一套频率校验逻辑，延迟队列中的通知投递时如果又触发频率限制则继续延迟。当某个渠道发送失败率连续10分钟超过10%时触发告警，告警触发后自动切换到备用渠道，告警状态更新和渠道配置变更作为原子操作，要么同时成功要么同时不生效。渠道配置和频率参数支持通过 PUT /channels/{id}/config 接口动态修改并立即生效，频率参数传0或负数时返回400错误。删除渠道时如果还有待发送的通知则返回409拒绝删除。

npm run build 能编译通过，node dist/server.js 能启动，端口环境变量指定。
