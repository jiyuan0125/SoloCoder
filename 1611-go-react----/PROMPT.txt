客服那边提了个需求，要一个产品反馈管理系统，TypeScript + Express 后端。

提供反馈分类的增删改查接口，分类包含功能建议、Bug报告、体验投诉、其他四种。用户提交反馈时填写标题（5到100字符，超出范围返回400）和详细描述（20到2000字符），可以上传附件，单个附件超过10MB返回413。优先级自动判定：Bug报告且标题加描述中包含"崩溃""闪退""白屏""数据丢失"的标记为紧急，功能建议标记为低优先级，其余为普通。管理员也可以通过接口手动调整优先级。

反馈状态流转只有四条合法路径：新建→待处理、待处理→处理中、处理中→已解决、已解决→已关闭，其他任何跳转返回400并在响应体里说明当前允许的操作。状态变更记录操作人和时间。反馈从已解决到已关闭需要用户确认，用户7天没确认自动关闭并给用户发通知，用户账号已注销时通知接口返回404并改为在内部记一条日志。反馈创建到关闭超过7天未解决自动标记为超时。删除反馈时如果还有未处理的内部备注则返回409。同一用户10分钟内提交相同标题的反馈返回409拒绝重复。

反馈列表按优先级排序（紧急>普通>低），支持批量领取（POST /feedbacks/batch-claim）和批量标记已解决（POST /feedbacks/batch-resolve），批量操作中单个失败不影响其他记录。查询反馈列表结果为空时返回空数组而不是404。

Express + TypeScript + SQLite，npm run build 通过就行。
