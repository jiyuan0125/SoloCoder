帮我用 TypeScript 写一个灰度发布系统的后端服务，管理发布计划、灰度控制和回滚。

创建发布计划时填写计划名称、旧版本号、新版本号和灰度策略。灰度策略支持三种：按比例灰度（哈希计算用发布计划ID加用户ID一起做哈希，不能只用用户ID）、按白名单灰度、按规则灰度（根据用户属性配置条件）。

发布过程分四个阶段：待开始→灰度中→全量发布→已完成。灰度中阶段可以随时暂停，暂停后所有用户回退到旧版本。全量发布后如果发现严重问题可以一键回滚，所有用户切回旧版本。回滚后如果又创建新的灰度发布计划，新计划要正常工作不受之前回滚影响。限流保护：新版本错误率用最近5分钟的滑动窗口计算，超过阈值自动暂停灰度。错误率监控基于日志中的错误计数。

核心功能实现为独立模块。服务端用 Express 框架提供 HTTP 接口，客户端是命令行工具通过 HTTP 调用服务端。项目用 TypeScript 写，tsconfig 开启 strict 模式。npm install 后 npm run build 能编译通过，node dist/server.js 能启动服务端。服务端监听端口通过环境变量指定。
