我们运维团队最近需要一套灰度发布系统，TypeScript + Express 做。

创建发布计划时填写计划名称、旧版本号、新版本号和灰度策略。灰度策略三种：按比例灰度（哈希计算用发布计划ID加用户ID一起做哈希，只用用户ID不行）、按白名单灰度、按规则灰度（根据用户属性配条件）。提供发布计划的创建、查询、更新、删除接口。发布过程四个阶段，合法流转路径只有：待开始→灰度中、灰度中→全量发布、全量发布→已完成、灰度中→暂停（暂停后回退旧版本）、暂停→灰度中（恢复），其他跳转返回400和当前允许的操作列表。

错误率监控用最近5分钟滑动窗口计算，错误率查询和发布计划状态判断在同一步完成，错误率超过阈值时自动暂停灰度，暂停操作和错误率记录作为原子操作同时生效。全量发布后可以一键回滚（POST /plans/{id}/rollback），所有用户切回旧版本，回滚后创建新的灰度发布计划正常工作不受之前回滚影响。删除发布计划时如果处于灰度中或全量发布阶段则返回409拒绝删除。灰度比例传负数或超过100时返回400。同一个App同时只能有一个处于灰度中状态的计划，第二个创建时返回409。

Express + TypeScript + SQLite，npm run build 能跑起来就行。
