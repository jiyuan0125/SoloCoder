我们运维团队最近需要一套灰度发布系统，用 TypeScript 做。

创建发布计划时填写计划名称、旧版本号、新版本号和灰度策略。灰度策略支持三种：按比例灰度（哈希计算用发布计划ID加用户ID一起做哈希，不能只用用户ID）、按白名单灰度、按规则灰度（根据用户属性配置条件）。发布过程分四个阶段：待开始→灰度中→全量发布→已完成。

灰度中阶段可以随时暂停，暂停后所有用户回退到旧版本。全量发布后如果发现严重问题可以一键回滚，所有用户切回旧版本，回滚后如果又创建新的灰度发布计划要正常工作不受之前回滚影响。限流保护：新版本错误率用最近5分钟的滑动窗口计算，错误率检查时需要同步查询发布计划的状态来决定是否自动暂停，超过阈值自动暂停灰度。错误率监控基于日志中的错误计数。发布计划每个阶段都有独立的操作接口，通过计划ID和阶段名称来触发状态变更。

Express + TypeScript + SQLite，npm run build 能跑起来就行。
