功能开关全靠改代码重新部署太慢了，所以想做一个功能开关管理系统，TypeScript + Express 后端。

每个开关有唯一的key、名称、描述和开启状态，提供开关的创建、查询（单个和批量）、修改、删除接口（GET/POST/PUT/DELETE /switches）。开关可以设置生效条件：按用户ID白名单、按用户百分比（同一用户多次请求返回一致结果）、按用户属性、按时间窗口，多个条件之间AND关系。开关值支持布尔和JSON两种类型，JSON值编辑时格式不合法返回400和解析错误信息。批量查询接口 POST /switches/batch 接受key数组，一次返回对应的值。

配置加载：业务服务启动时拉取所有开关缓存到本地，之后每隔60秒轮询增量更新，连续3次轮询失败不清空本地缓存，用上次成功拉取的数据继续服务，并在响应头里加 X-Config-Stale: true 标记。开关变更记录操作人和时间。同一个开关短时间内多次修改，查询时返回最后一次修改的值。开关被删除后，业务方通过key查询时返回该开关最后一次生效的值和 deleted: true 标记，不返回404。白名单中添加重复用户ID返回409。百分比设置为负数或超过100返回400。删除开关时如果还有活跃的业务方引用记录则返回409提示有关联引用。

Express + TypeScript + SQLite，npm run build 通过。
