帮我做一套统一API文档平台，TypeScript 后端。微服务太多Swagger文件散落各处需要统一管理和在线调试。

管理员上传微服务的Swagger JSON文件（支持OpenAPI 3.0），后端解析提取所有API路径、方法、请求参数和响应格式。Swagger文件解析要容错，很多团队的文件不规范，解析失败时跳过有问题的API并记录警告，不能导致整个服务崩溃。每个微服务有独立的API列表，每个API有独立的调试接口，调试结果也能单独查看。

在线调试功能：后端提供代理接口转发请求到目标服务。代理转发设置默认30秒超时，支持自定义。目标服务不可达时返回明确的错误信息。代码分析功能：解析Swagger时统计每个API的标签分组、必填参数的类型分布和响应状态码覆盖情况。配置如代理超时、最大请求体等支持通过配置文件加载，修改后热生效不需要重启。每个微服务下每个API的操作路径设计成 /services/{serviceId}/apis/{apiId}/debug 这种多层级的。

Express + TypeScript + SQLite，npm run build 能跑起来。
