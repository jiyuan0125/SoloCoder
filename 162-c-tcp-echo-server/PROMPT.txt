帮我用 C 写一个网络协议测试工具，用来测试 TCP 连接的连通性和延迟。工具启动后监听一个指定端口，等待客户端连接。客户端连上来之后，工具把客户端发过来的所有数据原封不动地回传回去（这就是所谓的「回声」效果）。这个工具主要用来测试网络质量——客户端发一段数据过去，看看能不能完整地收回来、延迟是多少。功能要求：同时支持多个客户端连接，每个客户端的数据独立回传，A 发的数据只能 A 收到，不能跑到 B 那里去。如果某个客户端突然断开了（比如网络中断、进程崩溃），不影响其他客户端的正常通信。如果某个客户端连接上之后一直不发数据也不断开（比如网络中间设备出了问题导致连接僵死），服务器这边要设置一个超时时间（比如60秒），超时后自动关闭这个连接释放资源。要能实时显示当前连接的客户端数量、每个客户端连接的时长、以及收发的字节数。还要支持一种测试模式：服务器收到数据后不是立即回传，而是等一段指定的时间再回传，这样可以测量延迟。支持通过命令行参数指定监听端口和超时时间。用纯 C 写，gcc 编译通过，不依赖第三方库。支持一种测试模式：收到数据后延迟指定毫秒数再回传，这样客户端可以精确测量网络往返延迟。
代码拆成至少 4 个源文件：连接管理、数据回传、超时检测、主程序，各自有头文件和实现文件。gcc 编译能过。
