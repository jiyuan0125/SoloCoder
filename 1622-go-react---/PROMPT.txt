应用日志散在各处查问题太慢了，所以想做一个日志采集分析服务，TypeScript 后端。

应用通过接口上报日志，每条日志包含时间戳、日志级别（DEBUG/INFO/WARN/ERROR）、服务名称、traceId、消息内容和标签。日志级别传入非法值时返回400和合法值列表。查询支持按时间范围、级别、服务名和关键词筛选，时间范围为空返回400提示必填。每个服务有独立的日志查询接口 /logs/{serviceName}，聚合统计有独立入口 /logs/stats。

日志聚合：统计指定时间范围内各级别数量、每个服务的错误率（ERROR数/总日志数）、最频繁错误消息Top10。聚合粒度根据时间范围自动选：1小时内按分钟，1天内按小时，更长按天。如果某个服务在指定时间范围完全没有日志，跳过不参与错误率计算，返回结果中不包含该服务。traceId查询接口 /logs/trace/{traceId} 串联完整请求链路，按时间排序，没有找到返回404。查询大量日志用分页，不传分页参数时默认每页50条，page参数超出范围返回空列表而不是错误。

Express + TypeScript + SQLite，npm run build 通过。
