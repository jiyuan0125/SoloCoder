应用日志散在各处查问题太慢了，所以想做一个日志采集分析服务，TypeScript 后端。

应用通过接口上报日志，每条日志包含时间戳、日志级别（DEBUG/INFO/WARN/ERROR）、服务名称、traceId、消息内容和额外标签。日志按服务名和时间分区存储在内存中。查询支持按时间范围、日志级别、服务名称和关键词筛选。每个服务有独立的日志查询接口，聚合统计也有独立的查询入口。

日志聚合功能：统计指定时间范围内各级别的日志数量、每个服务的错误率（ERROR级别数量占总日志数量的比例）、最频繁出现的错误消息Top10。聚合粒度根据时间范围自动选择：1小时内按分钟，1天内按小时，更长按天。查询大量日志时要用分页避免内存溢出。traceId查询可以串联出一条完整的请求链路，展示日志按时间排序的完整调用链，同一个traceId的日志可能来自不同服务。聚合查询时如果某个服务在指定时间范围内完全没有日志，直接跳过不参与错误率计算。

Express + TypeScript + SQLite，npm run build 通过。
