我们微服务配置全靠本地文件管理太混乱了，需要一个配置中心，TypeScript + Express 后端。

配置按应用和环境（开发/测试/生产）隔离，提供应用的增删改查接口 /apps、配置项的增删改查接口 /apps/{app}/configs。每个配置项有key、value、值类型（字符串/数字/布尔/JSON）、描述和修改历史。配置修改时记录操作人、修改时间和修改前后值，历史不可删除。配置项的key在同一个应用和环境组合下不能重复，重复创建返回409。JSON类型值保存时校验格式，不合法返回400和解析错误位置。

批量发布：管理员一次修改多个配置项，事务中完成全部生效或全部不生效，任何一个配置项校验失败整个批次回滚并返回失败项列表。客户端拉取支持全量和长轮询增量，长轮询时客户端带版本号，有新版本才返回否则保持连接到超时（30秒）。配置被删除后，正在长轮询的客户端连接要立即断开并返回410表示配置已不存在。应用删除时级联清理该应用所有配置和环境，但如果有客户端正在长轮询这些配置，先断开所有连接再清理。配置回滚接口 /apps/{app}/configs/{key}/rollback/{version}，回滚操作本身也记入修改历史。

Express + TypeScript + SQLite，npm run build 能跑起来就行。
