我们微服务配置全靠本地文件管理太混乱了，需要一个配置中心，TypeScript + Express 后端。

配置按应用和环境（开发/测试/生产）隔离。每个配置项有key、value、值类型（字符串/数字/布尔/JSON）、描述和修改历史。配置修改时记录操作人、修改时间和修改前后的值，历史不可删除。配置支持版本管理，可以回滚到任意历史版本。

客户端拉取配置时支持两种模式：全量拉取和长轮询增量更新。长轮询时客户端带上上次拉取的版本号，服务端在有新版本时才返回，否则保持连接直到超时（默认30秒），长轮询过程中如果配置被删除了要返回合适的响应。批量发布功能：管理员可以一次修改多个配置项，修改在事务中完成，要么全部生效要么全部不生效。配置项的key在同一个应用和环境组合下不能重复。JSON类型配置值要校验格式合法性。应用删除后该应用的所有配置和环境一起清理，但如果还有客户端正在长轮询该应用的配置，清理后长轮询连接要能优雅断开。

Express + TypeScript + SQLite，npm run build 能跑起来就行。
