运维那边提了个需求，要一套分布式任务调度服务，TypeScript + Express。cron散落在各台机器上管不过来。

任务创建时指定任务名称、cron表达式、超时时间、重试次数和执行参数。cron表达式保存前校验合法性。任务执行时系统记录开始时间、结束时间、执行状态（成功/失败/超时）和执行结果，超时的任务自动标记为超时状态。任务有已创建→待调度→执行中→已完成/已超时/已失败几个状态，已完成的任务不能再重新触发执行。

并发控制：同一个任务前一次还没执行完时下一次触发时间到了的处理策略可选——跳过本次执行、等待上次执行完再执行或强制终止上次执行。任务执行失败后按配置的重试次数进行重试，重试间隔递增（1分钟、5分钟、30分钟）。任务支持手动触发执行，手动触发不影响定时调度的正常运行，同一个任务短时间内多次手动触发不会产生重复执行记录。任务从待调度到执行中的转换需要先检查上次执行是否完成，如果上次还没完成就按并发策略处理。

npm run build 能编译通过，端口环境变量指定。
