运维那边提了个需求，要一套分布式任务调度服务，TypeScript + Express。cron散落在各台机器上管不过来。

任务创建时指定名称、cron表达式、超时时间、重试次数和执行参数。cron表达式不合法返回400和具体错误位置。任务状态有「已创建→待调度→执行中→已完成/已超时/已失败」，已完成的不能再触发返回400，只有已创建和待调度能转执行中。任务管理接口路径 /tasks、/tasks/{id}、/tasks/{id}/executions。

并发控制：同一个任务前一次没执行完下一次触发到了，策略可选跳过本次、等上次完成再执行、强制终止上次执行。任务执行失败按重试次数重试，间隔递增（1分钟、5分钟、30分钟），重试耗尽标记为已失败，返回结果中包含最后一次失败的原因。手动触发接口 /tasks/{id}/trigger，手动触发不影响定时调度，短时间内多次手动触发不产生重复执行记录，如果任务正在执行中返回409说明当前状态。超时的任务自动标记为已超时，超时后如果任务实际执行完了不覆盖状态。任务从待调度转执行中时先检查上次执行是否完成，没完成按并发策略处理。

npm run build 能编译通过，端口环境变量指定。
