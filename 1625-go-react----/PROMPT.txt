帮我做一套服务注册与发现系统，TypeScript 后端。微服务越来越多需要统一管理服务实例。

服务实例注册时提供服务名称、实例地址、端口号、权重和元数据，注册成功返回唯一ID。同一个地址重复注册不创建新记录而是更新原有实例信息，更新时保持原有的ID和注册时间不变。实例需要定期发心跳（默认10秒一次），连续3次心跳超时标记为不健康并从可用列表移除。实例状态有「健康→不健康→已注销」，不健康实例恢复正常心跳后自动回到健康状态。管理接口路径 /services、/services/{name}/instances、/services/{name}/instances/{id}。

服务发现接口 /services/{name}/discover 返回所有健康实例，加权轮询时权重为0的不参与分配但仍然在列表中展示。服务下线主动注销，注销后不再被发现但历史心跳记录保留。实例从健康变不健康后正在进行的请求不受影响，新的发现请求才排除该实例。服务下线时有实例还在健康状态的，一并标记为已注销。实例地址或端口格式不对时注册返回400。权重传入负数返回400，默认值为1。

Express + TypeScript + SQLite，npm run build 能编译通过就行。
