帮我做一套服务注册与发现系统，TypeScript 后端。微服务越来越多需要统一管理服务实例。

服务实例启动时向注册中心注册，提供服务名称、实例地址、端口号、权重和元数据。注册成功后实例获得一个唯一ID。服务实例需要定期发送心跳（默认10秒一次），连续3次心跳超时则标记为不健康并从可用列表中移除。

服务发现接口：客户端查询某个服务的可用实例列表，返回所有健康实例的地址和权重。支持多种负载均衡策略：轮询、加权轮询和随机，加权轮询时权重为0的实例不参与分配。服务下线时主动注销，注销后的实例不再被发现但历史记录保留。同一个服务实例地址重复注册时不会创建多条记录而是更新原有实例信息。实例从健康变为不健康后，正在进行中的请求不受影响，新的服务发现请求才不返回该实例。

Express + TypeScript + SQLite，npm run build 能编译通过就行。
