ETL数据管道管理服务，TypeScript + Express 后端。数据工程团队日常运维各种同步管道需要统一管理。

管道由多个步骤组成，每步定义数据源、转换规则和目标。数据源支持HTTP接口和内存数据。转换规则支持字段映射、类型转换、过滤和聚合。管道按顺序执行各步骤，每步只处理上一步的输出，已消费的数据不能被后续步骤重复消费，重复消费时返回错误。管道管理接口 /pipelines、/pipelines/{id}、/pipelines/{id}/steps、/pipelines/{id}/executions。

管道执行失败时记录失败步骤和错误原因，已执行步骤结果保留不回滚。重新执行接口 /pipelines/{id}/executions/{execId}/retry 支持从失败步骤开始而不是从头，如果指定了一个不存在的步骤序号返回400。管道执行记录包含每步的开始时间、结束时间、处理条数和状态。数据量大的管道分批处理每批1000条串行执行。管道设为定时执行时，上次还在执行中新的触发直接返回409拒绝不排队。步骤引用的数据源被删除后，管道执行到该步时返回错误说明数据源不可用，而不是静默跳过。步骤的转换规则引用了不存在的字段时返回400。

Express + TypeScript + SQLite，npm run build 能跑起来就行。
