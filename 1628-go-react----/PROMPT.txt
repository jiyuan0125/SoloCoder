网关层没有统一管理太乱了，所以想做一个API网关服务，TypeScript 后端。请求路由、限流和认证一起搞定。

网关管理多个上游服务，每个服务有名称、上游地址和路由前缀。管理接口 /gateway/services、/gateway/services/{id}。客户端请求根据路径前缀匹配上游，精确匹配优先于前缀匹配，多个前缀匹配选最长那个。限流支持按IP、按用户ID和按接口路径三个维度，每维度配每秒、每分钟、每小时的请求上限，滑动窗口实现，超限返回429和剩余等待时间。

认证模块支持API Key，请求在header中携带key。key可以设过期时间和调用权限（允许访问的路由列表），路由权限要和网关注册的路由前缀匹配才能访问，不匹配返回403。key过期返回401。调用方管理接口 /gateway/clients、/gateway/clients/{clientId}/keys、/gateway/clients/{clientId}/keys/{keyId}/stats。网关转发超时默认10秒，超时返回504不是502。上游不可达返回502。请求日志记录方法、路径、状态码、响应时间和匹配的上游。同一个路由前缀重复注册返回409。key创建时权限列表为空表示允许所有路由。

Express + TypeScript + SQLite，npm run build 能跑起来就行。
