用 TypeScript 写一个服务降级和熔断管理系统。保护后端服务不被突发流量压垮。

管理员为每个接口配置降级规则，包含触发条件（错误率超阈值或响应时间超阈值）、降级动作（返回默认值、返回缓存或拒绝）和时间窗口（默认1分钟）。接口管理路径 /circuit-breakers、/circuit-breakers/{id}。熔断器状态有「关闭→打开→半开→关闭」，关闭状态正常转发，打开状态直接拒绝返回503和熔断原因。只有关闭能转到打开、打开转到半开、半开转到关闭或打开，非法跳转返回500。熔断器状态切换记录时间和原因到日志。

打开持续30秒后进入半开，允许少量请求通过。半开请求成功则关闭熔断器，失败则重新打开。半开到关闭过程中如果有新错误立刻重新打开，不等半开测试结束。同一个接口1分钟内多次触发降级条件，熔断器只打开一次不反复切换，重复触发记录日志但不改变状态。接口调用统计按分钟聚合，记录成功数、失败数和平均响应时间，统计接口 /circuit-breakers/{id}/stats。降级规则的时间窗口和阈值都传入非法值时返回400。查询不存在的熔断器返回404。

Express + TypeScript + SQLite，npm run build 通过就行。
