我们运维团队需要一套服务监控告警系统，用 TypeScript 做。采集服务指标，异常时自动触发告警。

每个服务定期上报指标数据（CPU使用率、内存使用率、QPS、错误率、平均响应时间），按服务名和时间戳存储。查询支持按服务名和时间范围筛选。需要这些接口：POST /services 创建服务、POST /services/{name}/metrics 上报指标、GET /metrics 按服务名和时间范围查询、POST /rules 创建告警规则、GET /rules 列出规则、DELETE /rules/{id} 删除规则。

告警规则包含指标名称、比较运算符（gt/lt/eq）、阈值、持续时间（持续超阈值多久才告警）和级别（warning/critical/emergency）。告警触发后生成告警记录，记录包含时间、规则ID、当前值和级别。告警状态只能是 pending→processing→recovered 这个顺序，跳步的请求返回 400 和错误消息 "invalid state transition from {from} to {to}"。同一个规则对同一个服务在 pending 或 processing 状态下不重复触发，恢复后再次超阈值算新告警。

指标名称在某个服务从未上报过的，对应规则对该服务跳过不触发，不报错。指标数据保留最近7天，超出的自动清理。重复上报同一服务同一指标的请求返回 409 和 "duplicate metric report"。删除规则时如果该规则有 pending 状态的告警记录返回 400 和 "rule has active alerts"。

Express + TypeScript + SQLite，npm run build 能跑起来就行。
