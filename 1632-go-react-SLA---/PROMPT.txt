帮我做一套 SLA 管理系统，TypeScript 后端。服务等级协议定义和监控。

每个服务可以定义一个 SLA，包含可用性目标（如 99.9%）、响应时间目标（如 P99 低于 200ms）和错误率目标（如低于 0.1%）。SLA 按月度评估，系统根据采集的指标数据自动计算实际达成情况。可用性计算：(总分钟数 - 故障分钟数) / 总分钟数，故障由管理员手动记录或根据连续错误率超标自动触发。响应时间取 P99 值。需要这些接口：POST /services 创建服务、POST /services/{id}/sla 创建 SLA 定义、GET /services/{id}/sla 查询 SLA、POST /incidents 记录故障、GET /reports/{year}/{month} 查月度报告、PUT /reports/{year}/{month}/recalc 重新计算报告。

月度 SLA 报告包含各项指标达成情况、故障记录和达标率（达标项数 / 总 SLA 项数）。SLA 违约时自动生成违约记录，同一故障 ID 不能重复计入多次违约，重复提交返回 409 和 "duplicate incident in SLA breach"。月度报告生成后如果管理员补充了故障记录，调用 recalc 接口重新计算：已确认达标的指标项结果不变，只更新受新增故障影响的部分。

故障记录中影响时长为 0 或负数的不计入故障分钟数，返回 400 和 "incident duration must be positive"。P99 计算时如果数据点不足 100 个，用实际数据点数计算百分位。

Express + TypeScript + SQLite，npm run build 能编译通过就行。
