容量规划全靠拍脑袋太不靠谱了，想做一个容量管理服务，TypeScript + Express 后端。监控服务器资源并做预测。

管理多台服务器的资源数据，每台记录 CPU、内存、磁盘和网络带宽使用率，按分钟采集存最近 30 天。查询时根据时间范围自动聚合：1 小时内原始粒度，1 天内按 5 分钟聚合，7 天内按小时聚合，更长按天聚合。需要这些接口：POST /servers 注册服务器、POST /servers/{id}/metrics 上报资源数据、GET /servers/{id}/metrics 查询（参数 timeRange 和 resourceType）、GET /servers/{id}/alerts 查预警列表、GET /servers/{id}/prediction 查容量预测。

任何一项资源使用率超过阈值（默认 80%）且持续超过配置时长（默认 5 分钟）生成预警。同一台服务器同一项资源在预警未解除前不重复生成，重复触发返回 409 和 "alert already active for this resource"。容量预测基于最近 7 天聚合数据用线性回归预测未来 7 天趋势，如果预测某项资源 7 天内达到 90% 提前生成容量告警。预测数据缺失的天数用前一天数据填充，但如果连续缺失超过 3 天则不填充，返回提示 "insufficient data for prediction, {n} consecutive days missing"。

服务器不存在时上报指标返回 404 和 "server not found"。指标数据中使用率为负数或超过 100 返回 400 和 "usage must be between 0 and 100"。

npm run build 能编译通过就行。
