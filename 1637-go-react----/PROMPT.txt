制品管理的后端服务，TypeScript + Express。构建产物的存储和版本管理太散了需要统一。

制品按项目组织，每个制品有名称、类型（docker/jar/npm/static）、版本号和存储路径。需要这些接口：POST /projects 创建项目、POST /projects/{id}/artifacts 上传制品、GET /projects/{id}/artifacts 列表查询（支持按类型和名称筛选）、GET /artifacts/{id} 查详情、DELETE /artifacts/{id} 删除制品、POST /artifacts/{id}/tag-latest 标记为 latest、GET /artifacts/{id}/download 下载、GET /projects/{id}/storage 查存储用量。

制品上传时自动计算 SHA256，和客户端提供的校验和不一致返回 400 和 "checksum mismatch, expected {expected} got {actual}"。同一名称加版本号组合不能重复上传，返回 409 和 "artifact version already exists"。快照版本（版本号含 SNAPSHOT）可覆盖更新，发布版本不可覆盖（返回 403 和 "release version cannot be overwritten"）。

标记 latest 时自动解除之前同类型同名称的 latest 标记。下载时记录下载次数。项目存储超配额时禁止上传，返回 403 和 "project storage quota exceeded, limit {limit} bytes"。制品保留策略：只保留最近 N 个快照版本，超出的自动清理。删除制品时如果该制品是 latest 标记返回 400 和 "cannot delete latest artifact, remove tag first"。

Express + TypeScript + SQLite，npm run build 能跑起来就行。
