制品管理的后端服务，TypeScript + Express。构建产物的存储和版本管理太散了需要统一。

制品按项目组织，每个制品有名称、类型（Docker镜像/JAR包/NPM包/静态文件）、版本号和存储路径。制品上传时自动计算SHA256校验和，上传完成后和客户端提供的校验和比对不一致则拒绝。同一个制品名称加版本号的组合不能重复上传。

制品仓库支持快照版本和发布版本两种类型，快照版本可以被覆盖更新，发布版本不可覆盖。制品可以被标记为latest，标记latest时自动解除之前同类型同名称的latest标记，但被引用的旧latest如果正在被下载流程使用则不能立即移除。制品下载时记录下载次数和下载者。存储空间管理：统计每个项目的制品总大小超过配额时禁止上传新制品。制品可以设置保留策略比如只保留最近10个快照版本，超出的自动清理，清理时正在被下载的版本跳过。

Express + TypeScript + SQLite，npm run build 能跑起来就行。
