环境太多全靠文档记录早就过时了，想做一个环境管理服务，TypeScript + Express 后端。

环境分为 dev、test、staging 和 prod 四种类型。每个环境有名称、类型、所属项目和状态（creating→initializing→running→maintenance→destroyed）。环境资源包括服务实例数量、数据库连接信息和中间件配置，配置以键值对形式存储支持版本历史。需要这些接口：POST /environments 创建环境、GET /environments 列表查询（按项目和类型筛选）、GET /environments/{id} 查详情、PUT /environments/{id} 更新环境配置、DELETE /environments/{id} 销毁环境、POST /environments/{id}/status 更新状态、POST /environments/{id}/clone 克隆环境、GET /environments/{id}/config-history 配置变更历史、POST /environments/{id}/rollback 回滚到指定配置版本。

状态只允许 creating→initializing→running→maintenance→destroyed 顺序流转，非法跳转返回 400 和 "invalid state transition from {from} to {to}"。已销毁的环境不能恢复，对 destroyed 状态的任何修改请求返回 400 和 "destroyed environment cannot be modified"。克隆时复制配置和资源定义但不复制数据，克隆完成后新环境状态为 maintenance。环境配额：每个项目每种类型有数量上限，超配额创建返回 403 和 "environment quota exceeded for project {id} type {type}"。

同一环境同时只能有一个变更操作进行中，并发变更返回 409 和 "another change is in progress for environment {id}"。配置回滚时正在运行的服务实例不能直接停掉，返回提示 "active instances detected, manual restart required"。

npm run build 能编译通过，端口环境变量指定。
