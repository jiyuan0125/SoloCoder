帮我用 C 写一个 HTTP 请求解析器。场景是：我们在写一个轻量级的 Web 服务器，收到了客户端发来的原始字节数据（就是 TCP 连接上收到的那些字节），需要把这些原始数据解析成结构化的信息才能进一步处理。要能解析出以下内容：请求方法（GET、POST、PUT、DELETE 等）、请求路径（比如 /v1/users/123）、查询参数（路径后面 ?key=value&key2=value2 的部分，要拆成键值对）、HTTP 版本号（HTTP/1.0 还是 HTTP/1.1）、所有请求头（每一行的 HeaderName: HeaderValue）、以及请求体（POST 和 PUT 请求带的 body 数据）。要处理各种常见的异常情况：请求行格式完全不对（不是有效的 HTTP 请求）、Header 行缺少冒号分隔符、请求体实际长度和 Content-Length 头声明的不一致、请求体使用了分块传输编码（Transfer-Encoding: chunked）、一个 TCP 连接上连续收到多个 HTTP 请求（keep-alive 场景下需要能区分请求边界）。解析出来的查询参数要做 URL 解码处理（%20 转空格，+ 转空格等特殊编码）。如果请求内容不完整（比如只收到了一半），要能缓存已收到的部分，等剩余数据到达后继续解析。用纯 C 写，gcc 编译通过。解析器的内存管理——不能无限制地分配内存来缓冲请求数据，要设置一个最大请求大小的上限。
代码拆成至少 4 个源文件：请求行解析、请求头解析、请求体处理、主程序，各自有头文件和实现文件。gcc 编译能过。
