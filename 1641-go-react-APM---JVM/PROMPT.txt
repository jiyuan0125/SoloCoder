最近在搞APM，需要一个应用性能监控服务，TypeScript + Express 后端。应用太多手动盯指标盯不过来。

应用通过 POST /applications 注册，注册时指定名称和描述，名称不能重复重复注册返回409。注册后通过 POST /applications/{appId}/metrics 定期上报指标数据，包括HTTP请求统计（总请求数、各状态码计数、平均响应时间）、数据库查询统计（查询次数、慢查询数量、平均耗时）、JVM/运行时指标（内存使用量、GC次数、线程数）和自定义指标（键值对），指标按分钟粒度聚合存储。appId不存在时返回404。

异常检测：对比最近5分钟和前1小时的指标均值，偏差超过2倍标准差标记为异常，每次新数据写入后异步执行。应用超过10分钟未上报数据时异常检测跳过该应用不做空数据对比。报警规则接口 POST /alerts/rules，管理员配置指标阈值和通知方式，触发后生成告警记录。同一个报警规则对同一个应用在告警未恢复前不重复触发，重复触发返回409说明告警已存在。告警查询接口 GET /applications/{appId}/alerts。应用拓扑图接口 GET /topology 根据上报的调用链数据生成应用间调用关系，每个节点展示名称和健康状态。

npm run build 能编译通过，端口环境变量指定。
