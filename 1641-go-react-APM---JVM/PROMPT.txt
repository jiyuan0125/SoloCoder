最近在搞APM，需要一个应用性能监控服务，TypeScript + Express 后端。应用太多手动盯指标盯不过来。

应用注册后定期上报指标数据，包括：HTTP请求统计（总请求数、各状态码计数、平均响应时间）、数据库查询统计（查询次数、慢查询数量、平均耗时）、JVM/运行时指标（内存使用量、GC次数、线程数）和自定义指标（用户自定义的键值对数值），指标数据按分钟粒度聚合存储。

异常检测：对比最近5分钟和前1小时的指标均值，如果偏差超过2倍标准差则标记为异常，异常检测在每次新数据写入后异步执行。应用拓扑图：根据上报的调用链数据自动生成应用间的调用关系，每个节点展示应用名称和当前健康状态。报警规则：管理员配置指标阈值和通知方式，触发后生成告警记录，同一个报警规则对同一个应用在告警未恢复前不重复触发。应用如果长时间不上报数据，异常检测不应该用空数据做对比而是跳过检测。

npm run build 能编译通过，端口环境变量指定。
