性能热点排查全靠猜太低效了，所以想做一个性能剖析服务，TypeScript 后端。采集和分析应用的性能瓶颈。

性能剖析数据按应用分组。开始采集接口 POST /profiling/{appId}/start 指定采集类型（CPU剖析或内存剖析），同一应用同一时间只允许一次采集，已有进行中的返回409提示采集正在进行。每次剖析记录包含开始时间、持续时间和一组采样数据，每个采样有函数名、文件名、行号、采样次数和自身耗时。结束采集接口 POST /profiling/{appId}/stop。

火焰图数据接口 GET /profiling/{appId}/records/{recordId}/flamegraph 将采样按调用栈聚合，计算每个函数的总耗时和自身耗时（不含子调用），总耗时占比超过10%的标记为热点。对比接口 POST /profiling/compare 传入两次剖析ID，展示耗时变化最大的函数列表——函数名和文件路径都相同才是同一函数，函数名相同但路径不同视为不同函数分别列出。剖析记录列表 GET /profiling/{appId}/records，每个应用保留最近100次剖析，新增时如果已满自动删除最早的记录及其采样数据。查询已清理的recordId返回404。

Express + TypeScript + SQLite，npm run build 通过就行。
