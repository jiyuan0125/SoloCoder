我们运维最近需要一套告警通知中心，用 TypeScript 做。统一管理多种告警渠道的通知发送。

告警源通过 POST /alerts 推送告警事件，包含告警名称、级别（信息/警告/严重/紧急）、来源系统、描述和关联指标数据。名称、级别和来源系统为必填缺失返回400。通知渠道配置接口 PUT /channels/{type}/config，支持邮件、短信和Webhook三种（模拟发送），每种可配是否启用和每分钟发送频率上限，超限的通知排队到下一分钟发送。

告警聚合：同一来源系统、相同级别和名称的告警在5分钟窗口内合并，出现次数累加。窗口内又来了相同特征的告警窗口从最新告警时间重新计时5分钟。合并后的告警只在窗口关闭后发送一次通知内容包含累计次数。告警升级：严重级别告警在创建后15分钟内未被确认自动升级为紧急，升级时发更高优先级通知，升级判断用创建时间加15分钟。告警确认接口 PUT /alerts/{id}/acknowledge，解决接口 PUT /alerts/{id}/resolve，已确认的不触发升级，已解决的如果相同特征告警再出现算新告警。已确认和已解决状态不能回退，重复操作返回200但状态不变。告警查询 GET /alerts 支持按级别和状态筛选。

Express + TypeScript + SQLite，npm run build 能跑起来就行。
