帮我做一套事件总线服务，TypeScript 后端。微服务之间的事件通知全靠点对点调用太脆弱了。

事件发布接口 POST /events，每个事件有主题、事件类型、payload（JSON格式）、发布时间和事件ID。主题和事件ID为必填缺失返回400。事件ID由发布者指定，相同ID的事件不重复存储直接返回208表示已存在。订阅者注册接口 POST /subscriptions 指定主题和回调URL，回调URL格式不合法返回400。

系统收到事件后根据主题匹配找到所有订阅者逐个发送HTTP POST到回调URL。订阅者暂停接口 PUT /subscriptions/{id}/pause，恢复接口 PUT /subscriptions/{id}/resume，暂停期间的事件不投递也不堆积。同一主题多个订阅者独立投递一个失败不影响其他。投递保证至少一次，回调返回非2xx则重试，重试间隔30秒、1分钟、5分钟，三次都失败后标记投递失败不再重试。投递记录接口 GET /events/{eventId}/deliveries 返回该事件对所有订阅者的投递状态和重试次数。事件保留策略：投递成功的保留7天，投递失败的保留30天，清理后查询返回404。订阅者删除接口 DELETE /subscriptions/{id}，删除后不再接收该主题事件。

Express + TypeScript，npm run build 能编译通过，端口环境变量指定。
