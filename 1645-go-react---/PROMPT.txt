帮我做一套事件总线服务，TypeScript 后端。微服务之间的事件通知全靠点对点调用太脆弱了。

事件发布者通过接口发布事件，每个事件有主题、事件类型、payload（JSON格式）、发布时间和事件ID，事件ID由发布者指定相同ID的事件不会重复存储。订阅者注册时指定感兴趣的主题和回调URL，系统收到事件后根据主题匹配找到所有订阅者逐个发送HTTP POST通知。

事件投递保证至少一次，如果回调返回非2xx则重试。重试间隔递增：30秒、1分钟、5分钟，重试用上次投递时间加间隔来计算下次时间。投递时需要检查订阅者的暂停状态并更新投递记录，暂停的订阅者不投递。投递记录包含事件ID、订阅者、投递时间、响应状态码和重试次数。事件保留策略：已投递成功的事件保留7天，未投递完成的保留30天。订阅者可以暂停和恢复订阅，暂停期间的事件不投递也不堆积。同一个主题的多个订阅者之间独立投递，一个订阅者失败不影响其他订阅者。

Express + TypeScript，npm run build 能编译通过，端口环境变量指定。
