我们安全团队最近需要一套审计日志服务，用 TypeScript 做。所有敏感操作都要留痕可追溯。

审计日志记录每次敏感操作的完整上下文：操作人ID、操作类型（创建/读取/更新/删除）、资源类型、资源ID、时间戳、操作前后的数据快照和来源IP。日志写入后只能追加不能改也不能删。

查询支持按操作人、类型、资源类型和时间范围组合筛选，结果按时间倒序分页。还要能对比同一条资源的任意两条日志，展示字段级差异——只列出变化的字段。日志量大的时候查询要控制返回条数。保留策略默认永久也可配置保留天数，过期数据后台定时清理。

审计日志写入时如果遇到写日志本身还要记一条日志的场景（比如管理员修改了保留策略），直接写入不能形成循环等待。同一个操作短时间内重复提交（比如双击）只记一次，用操作人ID加操作类型加资源ID加时间窗口（5秒内）做去重。

Express + TypeScript + SQLite，npm run build 能跑就行。
