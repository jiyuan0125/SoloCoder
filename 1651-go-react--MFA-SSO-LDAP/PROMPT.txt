认证中心系统，TypeScript 后端。要支持多因素认证和单点登录。

用户先用用户名密码登录，密码用bcrypt哈希存在内存里。用户名不存在返回 401 和"用户名或密码错误"，不能透露具体是用户名不存在还是密码错误。登录成功后颁发JWT格式的token，包含用户ID、签发时间和过期时间，有个接口专门验证token的签名和有效期，token过期返回 401，签名不合法返回 401，格式错误返回 400。

多因素认证这块，用户可以在设置里开启，开启时生成Base32编码的TOTP密钥，用户拿认证器App扫码绑定。之后每次登录除了密码还要输TOTP验证码，验证码允许前后1个时间窗口的偏差。TOTP验证码错误返回 401 和"验证码错误"，连续输错5次冻结TOTP验证10分钟防止暴力破解。单点登录做一个简化版的SAML流程：第三方应用把用户重定向过来登录，成功后回调到第三方并携带用HMAC签名的认证凭证，回调URL不在已注册的回调列表中返回 400 拒绝回调。同一个用户在多个应用同时登录时，注销认证中心后所有应用的会话都失效，注销操作和各应用会话清理要尽量完成，某个应用的回调失败不影响其他应用的会话清理。

登录成功后颁发token的同时要自动记录一条认证日志，日志写入不需要再走一遍鉴权。登录失败连续5次冻结账号15分钟，冻结期间尝试登录返回 403 和"账号已冻结"加剩余冻结时间，冻结计数器在冻结解除后清零重新计算。冻结状态的读取和登录计数的更新要处理并发场景，不能两个请求同时读到4次失败然后都放行。

Express + TypeScript + SQLite，npm run build 能编译，node dist/server.js 能启动。
