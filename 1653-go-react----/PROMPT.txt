用 TypeScript 写一个统一的密码策略校验服务。不同系统对密码的要求五花八门需要集中管理。

后端暴露一个校验接口，输入密码字符串返回通过或失败加具体原因，密码为空或超128位返回 400。策略可配置：最小长度（默认8位最大128位）、是否必须包含大写字母、小写字母、数字和特殊字符、是否禁止包含用户名（不区分大小写的正向包含检查）、是否禁止使用最近N次历史密码（默认3次）。

密码历史按用户存储，改密码时检查新密码是否在历史里，用户ID不存在返回 404。历史记录满了N条后最早的淘汰。密码强度评分0到100：包含大写加20、包含数字加20、包含特殊字符加20、长度超12加20、长度超16加20。规则变更后已通过旧规则的密码不强制改，但下次改密码时按新规则来，策略ID不存在返回 404。

校验接口本身修改密码的时候也要调自己来做校验，但调用链不能形成死循环——校验接口只做校验不会触发密码修改，调用深度超过2层直接返回 500 和"调用链异常"。同一个用户短时间多次请求校验要限流，10秒内超过20次返回 429。密码修改成功后历史记录的追加和密码本身的更新要原子性完成，不能出现历史记了但密码没改的情况。

Express + TypeScript + SQLite，npm install 后 npm run build 能编译通过。
