最近在搞API安全，需要一个API访问安全网关，TypeScript 实现。做IP白名单和频率限制。

所有API请求先过这个网关，按顺序检查：协议解析（从请求头提取真实IP，处理X-Forwarded-For和X-Real-IP）、IP白名单校验、频率限制和风险打分，全部通过才放行。白名单命中直接放行返回 200，黑名单命中返回 403，不在名单里的走频率限制和风险打分。

IP白名单支持单IP和CIDR格式的IP段，变更后立即生效，CIDR格式不合法返回 400，规则ID不存在返回 404。频率限制按IP维度，每分钟最多60次请求，用滑动窗口实现，超限返回 429 和"请求频率超限"。风险打分根据多个因素：请求频率正常0分、接近限制加30、触发限制加100；IP在黑名单加50；请求路径含admin或config关键字加20。总分超80直接拒绝返回 403 和风险分数。黑名单IP可以指定过期时间，过期用添加时间加有效时长算。

网关本身的管理接口路径有好几级，像 /gateway/rules/{ruleId}/conditions/{conditionId} 这种，要确保路径解析不踩坑，ruleId不存在返回 404，conditionId不存在返回 404。规则的新增和更新要校验规则之间不能有冲突（同一个IP同时在白名单和黑名单返回 409），规则的生效和请求的检查之间可以有毫秒级延迟但不能丢请求。

Express + TypeScript + SQLite，npm run build 能编译通过。
