用 TypeScript 写一个内容安全审核服务。UGC内容越来越多需要自动审核。

文本审核维护一个敏感词库，用Trie树结构支持前缀匹配，对提交的文本做扫描。匹配到敏感词时记录命中位置和词内容。用户可能通过插入特殊字符绕过（比如"色[]情"），所以扫描前要做文本标准化：去掉所有非汉字非字母非数字的字符，全角转半角，连续空格合并为一个。标准化后的文本做匹配，返回结果时映射回原始文本的位置。

图片审核暂时用模拟：根据图片URL的hash值决定结果，30%概率待审核，5%违规，其余通过。审核队列管理：自动通过的直接放行，待审核和违规的进人工审核队列。审核员逐条审核做决定（通过/删除/警告）。批量提交的内容如果其中一条违规不影响其他内容的审核结果。

审核接口路径设计成 /content/{contentId}/audit/{auditId}/action 这种多层级的，路径解析别出问题。

Express + TypeScript + SQLite，npm run build 能编译通过就行。
