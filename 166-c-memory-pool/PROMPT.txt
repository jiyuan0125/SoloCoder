帮我用 C 写一个高频场景下的内存管理模块。场景是：我们正在开发一个金融交易系统，每秒要处理几万笔交易，每笔交易都要创建一个交易记录对象，交易完成后又要销毁。如果每次都用标准的内存分配和释放方式，会有两个严重问题：第一是速度太慢——标准的内存分配器要维护复杂的元数据，高频调用时开销很大；第二是内存碎片——频繁分配和释放不同大小的内存块，会导致可用内存被切得七零八落，即使总空闲内存够用也分配不出连续的大块。需要实现一个内存池来解决这个问题：启动时一次性向操作系统申请一块大内存（比如 64MB），之后所有的对象分配都从这块内存里切出一块来用。对象大小可以配置，但同一个池子在同一时刻只管理一种大小的对象（不同大小的对象用不同的池子）。释放对象时不归还给操作系统，而是标记为空闲，下次分配时直接复用这块空间。当整块内存都被占满没有空闲块时，新的分配请求直接失败返回空指针。提供查询功能可以看到内存池的使用率、已用块数、空闲块数。还要支持在程序退出时自动释放整块内存。用纯 C 写，gcc 编译通过。内存池本身不管理对象的内容，只管理内存块的分配和释放。调用者负责在内存块上初始化对象。用纯 C 写，gcc 编译通过。内存池的实现要避免碎片化——相同大小的内存块连续分配，释放后能立即被复用。
代码拆成至少 4 个源文件：内存块管理、分配回收、使用统计、主程序，各自有头文件和实现文件。gcc 编译能过。
