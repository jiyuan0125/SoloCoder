支付团队那边提了个需求，要一套支付网关服务，TypeScript 后端。对接三个渠道统一管理路由和对账。

每个渠道费率不同而且是阶梯式的，比如微信1000元以内0.38%，超过0.32%。网关对外暴露统一API，内部根据策略路由。路由策略三种：按费率优先（选最便宜的）、按成功率优先（选历史成功率最高的）、按指定渠道，指定的渠道不存在返回 404。费率优先时按实际金额算每个渠道手续费再比较，金额用整数分运算，金额为零或负数返回 400。

支付记录有商户订单号、金额、渠道、渠道流水号、状态和创建时间，商户订单号重复返回 409。状态有待支付、已支付、已关闭和已退款，退款不能超过支付金额超了返回 400，已退款的不能再退款返回 409，状态只能按待支付→已支付→已关闭/已退款流转。渠道健康度监控记录请求次数、成功次数和平均响应时间，按小时聚合。连续10分钟成功率低于95%的渠道自动降级不再路由新支付，降级后已有支付不受影响。

渠道降级后所有新支付要路由到其他渠道。如果所有渠道都降级了暂时停止接受新支付返回 503 和"所有渠道不可用"，等至少一个渠道恢复后再接受。支付创建和渠道扣款要保证一致性——渠道扣款成功但本地记录创建失败时要做反向退款不能让用户钱扣了但订单没创建。

Express + TypeScript + SQLite，npm run build 能编译通过。
