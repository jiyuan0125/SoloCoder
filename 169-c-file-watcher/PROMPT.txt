帮我用 C 写一个自动构建触发器，用在开发团队的日常工作中。场景是：开发人员在本地改代码，改完保存后，希望系统能自动检测到文件变化，然后自动跑编译和测试，不用手动执行命令。程序启动后持续监控指定的代码目录，当发现文件被修改、新增或删除时，不立即触发构建，而是等一小段时间（默认2秒，可配置）——因为编辑器保存文件时可能触发多次文件系统事件（先写入临时文件再重命名等），需要等变化稳定后再执行。确认变化稳定后，执行一个外部命令（比如 make && make test，命令可以通过配置文件指定），把命令的标准输出和标准错误都记录到日志文件里。如果上一次构建还在跑（比如测试跑了很久还没结束），新的文件变化先记下来，等当前构建完成后立即触发下一次构建，不丢失任何一次变更。支持同时监控多个目录。如果某个目录被意外删除或者权限变了不可访问，要能检测到并跳过，不能让整个程序崩溃。还要支持配置忽略规则——.git 目录、node_modules 目录、*.tmp 临时文件等的变化不触发构建。构建命令执行超时（比如超过10分钟）要能强制终止。用纯 C 写，gcc 编译通过。构建日志要按日期保存——每天的日志存到不同的文件里，方便回溯历史构建记录。
代码拆成至少 4 个源文件：文件变化监控、构建任务调度、日志记录、主程序，各自有头文件和实现文件。gcc 编译能过。
