帮我用 TypeScript 写一个慢病管理系统的后端，覆盖高血压、糖尿病等慢性病患者的随访和健康监测。

患者建档包含基本信息、慢病类型（可多个）、确诊日期和病史。记录初始指标：血压（收缩压和舒张压）、空腹血糖、糖化血红蛋白、体重和身高。风险等级：低风险每3月随访、中风险每月、高风险每两周。随访记录包含日期、症状、用药、指标值和生活习惯评估。

指标异常判断：收缩压持续超140或舒张压持续超90判定血压控制不佳，空腹血糖持续超7.0判定血糖控制不佳。"持续"定义为连续两次随访都超出标准。控制不佳自动升级风险等级并增加随访频次。用药管理记录当前用药清单，新药品加入时检查配伍禁忌。药物到期前7天生成续药提醒。连续两次随访未按时服药标记"依从性差"并通知家庭医生。指标控制率指最近一次随访达标患者数占总患者数的百分比。随访完成率按时完成次数占应随访次数的百分比。

患者建档时慢病类型为空返回 400，确诊日期晚于当前日期返回 400。随访记录的指标值如果收缩压低于60或高于250返回 400，空腹血糖为负数返回 400。风险等级只能从低→中→高方向升级，人工可以降级但降级后随访频次要同步调整。同一患者同一天不能重复随访返回 409。药品配伍禁忌检查依赖内置禁忌表，禁忌表数据更新不影响已开具的处方。用药续药提醒的生成和发送要在同一个调度周期完成，提醒发送失败不影响下次提醒的生成。

核心功能实现为独立模块。服务端用 Express 框架提供 HTTP 接口，客户端是命令行工具通过 HTTP 调用服务端。项目用 TypeScript 写，tsconfig 开启 strict 模式。npm install 后 npm run build 能编译通过，node dist/server.js 能启动服务端。服务端监听端口通过环境变量指定。
接口：基础操作在 /api/r，子资源在 /api/r/{id}/items，动作在 /api/r/{id}/actions/approve|reject|cancel。
预算调整后各项目按比例重新分配。已结算的不变只调整未结算的。调整后总额要对得上。
系统管理两类实体。操作时一类依赖另一类的配置。
服务端端口通过命令行参数或环境变量指定。
