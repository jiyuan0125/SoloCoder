我们研究院需要一个学术论文全生命周期管理系统，用 Go 做 REST 后端，React 做前端单页应用。系统要覆盖论文从投稿到发表的完整流程。

先说论文管理模块。作者提交论文时填写标题、摘要、关键词（逗号分隔）、作者列表（姓名和单位）、学科分类和投稿期刊。论文有状态流转：草稿、待审稿、审稿中、修改中、已录用、已发表。每次状态变更都要记录变更时间和操作人，形成完整的版本历史，前端能按时间倒序查看每次变更。

审稿模块是这样的：编辑部收到论文后分配审稿专家，每个专家独立评审给出意见（通过、修改后重审、拒稿）和评审分数（1到10分）。当所有专家都提交评审后，系统自动计算平均分，如果平均分低于5分则论文状态自动变为拒稿，如果有一个专家给拒稿且平均分低于6分也自动拒稿。但这里有个容易出错的地方：如果论文被分配了3个审稿人，只有2人提交了评审，这时候不能自动判定，要等所有人评完或者超过30天未评审视为放弃。发表模块记录发表信息：期刊名、卷号、期号、页码范围和DOI。

前端界面分三个主页面。论文列表页支持按状态筛选和按提交时间排序，支持关键词搜索。论文详情页展示基本信息和完整的审稿意见列表，每个审稿意见卡片显示专家姓名、评审时间、意见和分数。版本历史页用时间线形式展示每次状态变更。

后端用 Gin 框架，数据存内存 map。关键 API 包括提交论文、分配审稿人、提交评审意见、更新论文状态。论文的版本历史通过一个待办机制实现：每次状态变更生成一条待办记录关联到论文ID，审稿人提交意见也生成待办标记为已完成。

第一，论文标题不能和已有论文重复，但修改标题时要检查修改后的标题是否和其他论文冲突。第二，作者列表排序有讲究，第一作者和通讯作者有特殊标记，通讯作者可以和第一作者不同也可以是同一个人。第三，审稿人不能评审自己参与的论文，系统要校验审稿人的姓名不在作者列表中。第四，论文从"已录用"到"已发表"只能由管理员操作，普通作者只能看到发表信息不能自行填写。
