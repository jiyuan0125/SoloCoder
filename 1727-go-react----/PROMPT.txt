我们学校的科研经费管理系统需要重构，之前是 Excel 管理的，现在要做成 Go 后端加 React 前端的 Web 系统。

核心业务围绕科研项目的经费流转。每个科研项目有一个经费总额，经费分预算、报销和决算三个阶段。项目负责人创建项目时填写项目名称、负责人、起止日期、经费总额和预算分配。预算分配是把总额拆分到不同支出类别：设备费、材料费、差旅费、劳务费、专家咨询费和其他费用，各类别金额之和必须精确等于经费总额，分毫不差。这里有个容易踩的坑：金额计算必须用精确到分的整数运算，不能有浮点误差。比如经费总额1000000元分到6个类别，每个类别的金额加起来必须是1000000.00元，不允许出现999999.99这种差一分钱的情况。

报销模块中，科研人员提交报销单填写报销类别、金额、报销事由和日期。报销时系统要做两个校验：一是该类别的累计报销金额不能超过预算金额，二是报销单金额不能为负数或零。报销单有三种状态：待审批、已批准、已驳回。项目负责人的待办列表中会显示所有待审批的报销单，批准后该类别的已用预算实时更新。驳回时负责人需要填写驳回理由，报销人可以看到驳回理由后重新提交。

决算模块在项目结题时使用。系统自动汇总各类别的实际报销金额，和预算做对比，计算执行率和结余金额。执行率等于实际报销金额除以预算金额乘以100，精确到小数点后两位，四舍五入。如果某个类别的执行率低于30%，系统要标记为"预算执行异常"。

前端用 React 做，页面包括项目列表、项目详情（含预算分配饼图）、报销单列表和提交表单、决算报告页面。报销单列表支持按状态和日期筛选。

后端用 Gin 框架，内存存储。金额统一用"分"作为整数单位存储和计算，API 返回给前端时转换为元并保留两位小数。项目经费总额录入时可以精确到小数点后两位，比如500000.50元，转换为分就是50000050分，所有运算都在分的基础上做。
