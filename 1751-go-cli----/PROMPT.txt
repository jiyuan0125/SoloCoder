我们团队整理资料时经常需要批量重命名文件，手动改太累了。你帮我写一个 Go 命令行工具，用 cobra 做子命令架构，主命令叫 frename，下面有三个子命令：preview、apply、undo。

preview 子命令接收一个目录路径和一组重命名规则，扫描目录下的文件但不实际改名，只列出每个文件的原名和将要改成的新名，用表格形式打印到终端。支持的重命名规则有：前缀替换（把文件名开头的旧前缀换成新的）、后缀替换（文件名末尾的旧后缀换成新的）、正则替换（用正则表达式匹配文件名中的部分并替换）、序号填充（给文件名加数字编号，支持设置起始值和步长，数字部分自动补零到指定位数）。规则可以组合使用，按传入顺序依次应用。重命名规则只作用于文件名的主干部分。如果某条正则规则语法错误，打印具体错误信息和规则编号，跳过该条规则继续处理其余规则。目标文件名包含非法字符（/、\、:、*、?、<、>、|）时提示不合法并跳过。多条规则应用后如果两个不同文件重命名后同名，preview 阶段就要检测出冲突并报告涉及的文件对。

apply 子命令接收同样的参数，但实际执行重命名操作。apply 执行前先跑一遍 preview 的逻辑检查冲突，有冲突直接报错退出码 1 不执行任何重命名。执行时要保证操作可追溯和可逆。日志文件用 JSON Lines 格式存储，每行一个 JSON 对象，包含时间戳、原文件名、新文件名和操作状态（成功或失败及原因）。重命名过程中如果某个文件失败（比如目标路径所在磁盘只读），跳过该文件继续处理其余文件，失败的记录到日志中状态标记为 failed，最后输出失败数量，退出码为 2。同名文件的 rename 操作如果在短时间内被连续执行两次，第二次不应该产生新的日志条目，退出码为 0 并提示无变更。apply 过程中对每个文件加文件锁防止外部进程同时修改同一个文件导致数据损坏。

undo 子命令读取日志文件，把文件名改回原来的样子。undo 的结果等价于撤销最近一次 apply 的所有改动，文件名应完全恢复到 apply 之前的状态。如果日志文件不存在或格式损坏，输出错误信息退出码 1。undo 过程中如果某个文件已经被手动改名导致找不到对应的新文件名，跳过该条目并在最后汇总报告跳过数量。undo 完成后验证所有文件名是否与日志中记录的原文件名一致，不一致的列出具体差异。

工具需要正确处理目录扫描中可能遇到的各种文件类型和异常情况。目录不存在时退出码 1 并打印提示。
