我们团队整理资料时经常需要批量重命名文件，手动改太累了。你帮我写一个 Go 命令行工具，用 cobra 做子命令架构，主命令叫 frename，下面有三个子命令：preview、apply、undo。

preview 子命令接收一个目录路径和一组重命名规则，扫描目录下的文件但不实际改名，只列出每个文件的原名和将要改成的新名，用表格形式打印到终端。支持的重命名规则有：前缀替换（把文件名开头的旧前缀换成新的）、后缀替换（文件名末尾的旧后缀换成新的）、正则替换（用正则表达式匹配文件名中的部分并替换）、序号填充（给文件名加数字编号，支持设置起始值和步长，数字部分自动补零到指定位数）。规则可以组合使用，按传入顺序依次应用。重命名规则只作用于文件名的主干部分。

apply 子命令接收同样的参数，但实际执行重命名操作。apply 执行时要保证操作可追溯和可逆。日志文件用 JSON Lines 格式存储，每行一个 JSON 对象，包含时间戳、原文件名、新文件名和操作状态。

undo 子命令读取日志文件，把文件名改回原来的样子。undo 的结果等价于撤销最近一次 apply 的所有改动，文件名应完全恢复到 apply 之前的状态。

工具需要正确处理目录扫描中可能遇到的各种文件类型和异常情况。
同名文件的 rename 操作如果在短时间内被连续执行两次，第二次不应该产生新的日志条目。
流程：验证-备份-部署-验证部署-完成。部署失败自动回滚。回滚后也要验证。
多级路径：tool process --input ./data --output ./result。相对绝对路径都支持。
服务端端口通过命令行参数或环境变量指定。
