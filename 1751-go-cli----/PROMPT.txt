我们团队整理资料时经常需要批量重命名文件，手动改太累了。你帮我写一个 Go 命令行工具，用 cobra 做子命令架构，主命令叫 frename，下面有三个子命令：preview、apply、undo。

preview 子命令接收一个目录路径和一组重命名规则，扫描目录下的文件但不实际改名，只列出每个文件的原名和将要改成的新名，用表格形式打印到终端。支持的重命名规则有：前缀替换（把文件名开头的旧前缀换成新的）、后缀替换（文件名末尾的旧后缀换成新的）、正则替换（用正则表达式匹配文件名中的部分并替换）、序号填充（给文件名加数字编号，支持设置起始值和步长，数字部分自动补零到指定位数）。

apply 子命令接收同样的参数，但实际执行重命名操作。执行前先做一遍预览检查，如果发现任何两个文件会重名（比如规则冲突导致不同文件改成同一个名字），就拒绝执行并报错。每次 apply 执行时要把原始文件名和新文件名的对应关系记录到一个隐藏的日志文件里（.frename.log），存在操作目录下。

undo 子命令读取日志文件，把文件名改回原来的样子。如果日志文件不存在就提示没有可撤销的操作。

有几个细节要注意。第一，规则是可以组合的，比如同时指定前缀替换和正则替换，规则按传入顺序依次应用。第二，文件名中的扩展名应该单独保留，规则只作用于扩展名前面的部分。第三，如果目标文件名已经存在（不是本次操作产生的），要跳过并给出警告。第四，日志文件用 JSON Lines 格式存储，每行一个 JSON 对象，包含时间戳、原文件名、新文件名和操作状态。第五，符号链接文件不要跟随，直接跳过不处理。
