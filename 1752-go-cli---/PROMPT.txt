我们公司有个公共文件服务器，上面积累了大量重复文件，浪费了很多磁盘空间。需要你写一个 Go 命令行工具来查找和清理重复文件。

工具名叫 dedup，用标准库 flag 包做参数解析，不用 cobra。支持以下参数：目录路径（必填）、最小文件大小（字节，默认跳过小于 1KB 的文件）、是否自动替换（默认只报告不操作）、操作日志输出文件路径。目录路径不存在或不是目录时退出码 1 并打印提示。

工具的工作流程是这样的。第一步递归扫描指定目录下所有普通文件，跳过符号链接和特殊文件，权限不足无法读取的文件要记录错误但不要中断整个扫描。第二步对每个文件计算内容的 SHA-256 哈希值，相同哈希的文件归为一组。为了加速大文件的处理，先用文件大小做一次预分组，大小不同的文件肯定不重复，只对大小相同的文件计算哈希。两个文件大小相同但哈希不同说明内容不同，不应当作重复。扫描期间如果目录中有文件被外部进程修改导致大小变化，以最终哈希值为准，大小预分组和哈希计算要对同一个文件的最终状态保持一致。第三步对于每组重复文件，保留修改时间最早的那个，其余的用硬链接替换为保留文件。这样所有副本指向同一个 inode，删除任何一个都不会丢数据，而且节省磁盘空间。硬链接替换前先验证目标文件和源文件的哈希确实一致，如果不一致说明文件在扫描期间被修改了，跳过该组不执行替换。

输出方面，先用表格列出所有找到的重复文件组，每组显示文件数量、单个文件大小、总共节省的空间。然后如果开了自动替换，再输出每一步硬链接替换的操作记录。正在被其他进程打开的文件（比如日志文件）不能做硬链接替换，要跳过并在日志中记录。扫描目录如果跨越多个挂载点，要按挂载点分别处理，因为跨文件系统的硬链接是不支持的，跨挂载点的重复文件在报告中单独列出不执行替换。空文件（大小为0）全部算作重复的，因为内容一样，但空文件做硬链接没有意义，只在报告中列出不执行替换。

每次替换操作写入日志，日志格式 JSON Lines，每行包含时间戳、原文件路径、硬链接目标路径、操作结果（成功或跳过及原因）。自动替换模式下如果执行过程中遇到磁盘 IO 错误，停止后续替换操作并汇总已完成的和失败的，退出码为 2。只报告模式下所有结果输出到 stdout，退出码 0 表示找到重复文件，退出码 0 且无输出表示没有重复文件。
