帮我用 Go 写一个配置中心命令行管理工具。我们不用 etcd 或 consul 这种重量级方案，就用本地 JSON 文件当配置中心，但需要支持多环境和敏感字段加密。工具的核心是管理一套配置数据，支持以下子命令。init 子命令在指定目录下初始化配置仓库，创建基础目录结构和示例配置文件。目录结构分 environments 子目录存放各环境的配置（dev.json、staging.json、prod.json），templates 子目录存放配置模板，templates 里的文件用 Go template 语法，渲染时从环境配置中取值填充。render 子命令根据指定环境名渲染模板，比如 render --env prod --template app.yaml.tmpl --output app.yaml，从 prod.json 读取数据填充模板输出到指定文件。set 子命令直接修改某个环境的某个配置项，路径支持点号分隔的嵌套路径。encrypt 子命令对配置中的敏感字段加密，使用 AES-256-GCM 算法，加密密钥从环境变量 CONFIG_KEY 读取。加密后的值以 ENC(密文) 的格式存储在 JSON 中，读取时自动解密。decrypt 子命令批量解密指定环境配置中所有加密字段并输出明文 JSON。switch 子命令切换当前激活的环境，会在项目根目录创建一个 .current-env 软链接指向对应环境的配置文件。validate 子命令检查配置完整性，对照模板中用到的所有变量，看当前环境配置是否都提供了对应的值，缺少的变量名列出来。模板语法除了基本的变量替换，还要支持 if 条件判断和 range 循环。所有子命令的错误信息要包含具体的字段路径和原因，不要只抛一个笼统的错误。
render 子命令模板中引用的变量在环境配置中不存在时输出空字符串不报错中断。validate 检查配置完整性，缺少变量时退出码 1 并列出缺失的变量名，全部满足退出码 0。set 子命令修改配置时先写临时文件再 rename，避免中途断电导致配置文件损坏。encrypt 加密密钥从环境变量 CONFIG_KEY 读取，环境变量未设置时退出码 2 不用空密钥加密。switch 切换环境时如果目标环境的配置文件不存在，报错退出码 1 不创建空链接。
