缓存服务上线第一周踩了好几个边界条件的坑，key 为空、TTL 乱传、缓存满了怎么淘汰，每个都导致了线上问题。这次用 Rust axum 重写，把这些情况全部处理到位。

key 的校验要严格：空字符串直接拒绝返回 400，超过 256 字节的也拒绝——key 太长影响内部索引性能。value 为空是允许的，有些场景就是标记一个状态，比如"这个用户已经发过券了"只需要 key 存在就行。TTL 为 0 表示永不过期，这是合法值。TTL 为负数返回 400，带上"过期时间不能为负"的提示。

批量操作最容易出事。批量写入时部分 key 已存在，已存在的直接覆盖，不报错。批量读取时部分 key 不存在，返回结果里把存在的和不存在的分开列出来——调用方拿到结果一眼就能看出哪些命中哪些 miss，不用自己比对。

缓存空间满的时候写入新数据触发淘汰。淘汰策略用 LRU，淘汰最久没被访问的 key。淘汰过程中如果内部状态异常导致淘汰失败，新数据照样写入，淘汰失败的记录写到诊断日志里。诊断日志不能无限增长，后台定期清理超过 7 天的记录。清理时统计删除条数，方便监控日志增长趋势。

端口通过 PORT 环境变量配置，cargo build 能过。
