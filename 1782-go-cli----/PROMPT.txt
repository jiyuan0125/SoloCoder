有个老系统是 Java 写的密码策略模块，维护不动了，用 Go 重写一个密码生成和强度评估工具。安全团队要求所有系统账号密码必须满足强度要求。

gen 子命令生成随机密码。--length 指定长度默认 16，--lower/--upper/--digit/--symbol 控制包含哪些类型（默认都包含），--exclude 排除指定字符（比如排除 0Oo1lI）。生成的密码要保证每种启用类型至少出现一个字符，长度不够就报错。batch 批量生成，每行一个带序号。entropy 计算密码信息熵：统计字符类型算出字符空间，log2(空间^长度)，同时给强度评级（<40 弱，40-60 中，60-80 强，>80 非常强）。

estimate 估算暴力破解时间，假设每秒 10 亿次尝试，输出人类可读格式。policy 定义密码策略并验证：最小长度、各类字符要求、禁止连续重复、禁止常见弱密码（内置几百个）。策略从 JSON 文件加载。validate 验证密码是否符合策略，输出详细的通过/未通过检查结果。

密码通过命令行参数传入不要走标准输入，避免 shell 历史泄漏。生成用 crypto/rand 不用 math/rand。
gen 启用类型数大于长度时报错退出码 1。entropy 空字符串退出码 0 输出熵值 0。policy JSON 格式错退出码 2。validate 不符合退出码 1，符合退出码 0。生成全用 crypto/rand。batch 密码间不重复。
