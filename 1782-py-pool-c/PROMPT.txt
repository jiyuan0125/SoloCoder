连接池异常没处理，线上出了两回事故了。头一回是下游服务挂了，连接创建一直失败，连接池没降级把调用方全卡死了。第二回是连接泄漏，借出去的连接没还回来，池子耗尽之后所有请求超时。Python aiohttp 重写，这次全处理好。

连接创建失败的情况：目标不可达时重试 N 次（N 可配），全部失败后把整个池子标记为降级状态。降级状态下所有获取连接的请求直接返回 503，附上"后端不可达"的提示，调用方可以走降级逻辑。降级状态有定时恢复机制——每隔一段时间尝试重建连接，成功了就恢复。

连接泄漏检测不能少。借出超过 60 秒没归还的连接视为泄漏，自动回收并创建新连接补充池子。泄漏检测日志要记清楚：连接的借用时间、超时时长，以及调用来源（记录调用栈或者请求 ID）。这些信息对排查泄漏问题很关键。

连接池配置也有边界情况——最大连接数配成 0 或负数的直接拒绝创建，返回 400。等待超时设为 0 表示不等待，池子满了立即返回错误。

管理接口两个：/api/pools/{name}/stats 查单个池子的状态（活跃连接数、空闲连接数、降级状态），/api/pools 查所有池子的概览。

端口用 PORT 环境变量。
