配置中心这东西，边界条件不处理好线上迟早出事。你想想，配置值 64KB 的往里塞、key 带空格带换行的、删除一个配置但客户端还在订阅它——哪个处理不好都是故障。Spring Boot 搞，这次把这些场景全部覆盖。

配置值超大（超过 64KB）的允许写入，但返回一条提示，告诉调用方这个值偏大可能影响下发效率。配置 key 包含空格、换行这些非法字符的，直接拒绝返回 400 附带校验规则说明。重复创建同一个 key 的，覆盖旧值并生成新版本号，旧版本保留在历史记录里可以回溯。

删除配置时要照顾订阅者。删了一个正在被客户端订阅的 key，推送删除通知给所有订阅者，通知内容包含被删除的 key 和版本号。通知发送失败只记日志，不影响删除操作本身——不能因为一个客户端网络不好就卡住配置的删除流程。

批量导入是另一个容易出事的地方。一批配置里部分格式错误，错误的跳过不导入，正确的正常写入。返回导入结果汇总：成功了几条、失败了几条、每条失败的原因是什么。批量上限 100 条，超过返回 400。

配置历史版本查询支持按时间范围过滤，默认返回最近 50 条。时间格式传错了返回 400 加上"期望格式 yyyy-MM-dd HH:mm:ss"的提示。

Maven 构建，JDK 17，端口写在配置文件里。
