微服务一多，手工维护服务地址就不可行了。上次迁移服务忘记改地址表，用户反馈了才发现。用 Spring Boot 写个注册中心，把这些事情自动化掉。

服务注册时带上 IP、端口、标签和权重。心跳间隔支持配置——不同服务的心跳频率不一样，有些实时性要求高的每 5 秒一次，有些离线任务型的 30 秒一次就行。注册时 IP 格式不合法或者端口超出范围（1-65535）返回 400。心跳超时的服务自动从发现列表里移除，不需要人工干预。

订阅者通过内存列表管理。服务上下线时推送通知给订阅者，通知失败只记日志不做重试。生产环境里通知丢了的影响比服务挂了小得多，订阅者下次查询时自然会拿到最新列表，不需要为了通知的可靠性把注册中心搞复杂。

接口方面：全量服务列表 GET /services 返回所有注册的服务和实例，支持按标签过滤；单个服务实例详情 GET /services/{name}/{instanceId} 返回该实例的完整信息（IP、端口、标签、权重、注册时间、最后心跳时间）。服务发现接口 GET /discover/{serviceName} 返回该服务所有健康实例，权重为 0 的不返回。

Maven 构建，端口用 server.port 配置。
