我们团队代码审查用的是系统自带的 diff，输出格式太难看了，配置管理也跟着遭殃。Go 写个文本差异比较合并工具。

diff 子命令对比两个文件，输出 unified diff 格式（就是 git diff 那种）。--- 标旧文件，+++ 标新文件，@@ 包行号范围，空格/加号/减号标记 unchanged/added/removed。--color 用 ANSI 颜色高亮（删除红色、新增绿色）。word 做单词级差异比较，变化单词用方括号标记，对比配置值变化时特别有用。merge 三路合并：输入基础版本、版本 A、版本 B。不同部分自动合并，同一部分冲突用 <<<<<<< ======= >>>>>>> 标记。stat 输出差异统计：新增/删除/修改行数，支持目录递归对比。

patch 应用 unified diff 补丁文件到目标文件。先检查补丁能否干净应用，目标已修改导致补丁无法应用就报错。reverse 反转补丁（新增变删除），可以撤销一个补丁。ignore 指定比较时忽略的内容：空白变化、大小写、空行增减、正则匹配的行。

所有操作在内存中完成不修改原文件，除非 --apply。
diff 文件不存在退出码 1，完全一致退出码 0，有差异退出码 1。merge 冲突区域用标准标记，自动合并部分不引入额外空行。patch 无法干净应用退出码 2 不修改目标。reverse 反转补丁应用一次应恢复原状态。diff 目录不存在退出码 1。
