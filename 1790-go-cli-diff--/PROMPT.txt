帮我用 Go 写一个文本差异比较和合并命令行工具。代码审查和配置管理经常需要对比两个版本的文件，目前用的是 diff 命令但输出格式不够友好。diff 子命令对比两个文件或两段文本的差异，输出格式类似 unified diff（就是 git diff 的那种格式）。以 --- 开头标记旧文件，+++ 开头标记新文件，@@ 包裹行号范围，行首用空格、加号、减号标记 unchanged、added、removed。支持加 --color 参数用 ANSI 颜色高亮差异，删除的行用红色，新增的行用绿色。word 子命令做单词级别的差异比较，不是按行比较而是在行内找出具体哪些单词发生了变化。输出时变化的单词用方括号标记出来。这个功能在对比配置值变化时特别有用。merge 子命令尝试自动合并两个修改版本。输入三个文件：基础版本（共同祖先）、版本 A（一个分支的修改）、版本 B（另一个分支的修改）。如果 A 和 B 修改的是不同的部分就自动合并，如果修改了同一部分就标记为冲突。冲突区域的格式是 <<<<<<< A 的内容，======= B 的内容，>>>>>>> 结束标记。stat 子命令输出差异统计信息：新增了多少行、删除了多少行、修改了多少行。如果对比的是两个目录，递归对比目录下所有文件，输出每个文件的差异统计和汇总。patch 子命令应用补丁文件。读取 unified diff 格式的补丁文件，应用到目标文件上。应用前先检查补丁是否能干净地应用，如果目标文件已经被修改过导致补丁无法应用就报错。reverse 子命令反转补丁，把新增变成删除、删除变成新增，可以用来撤销一个补丁。ignore 子命令指定比较时忽略的内容：--ignore-space 忽略空白变化，--ignore-case 忽略大小写，--ignore-blank-lines 忽略空行的增减，--ignore-pattern 用正则指定要忽略的行。所有操作都在内存中完成，不修改原始文件，除非显式指定 --apply 参数。
差异对比时要能识别出整行被移动到新位置的情况，而不是同时报告删除一行和新增一行。
分析完成后自动生成摘要，摘要生成也要读中间数据。中间数据和结果存在同一个文件里。
同步完成自动清理临时文件。已被手动删就跳过，同步结果不受影响。
子命令：tool cmd subcmd [flags]。cmd有add/list/show/export，export有csv/json/pdf子格式。
服务端端口通过命令行参数或环境变量指定。
