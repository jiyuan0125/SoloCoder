用 tokio 做个异步消息队列，发布订阅模式，把这些问题都想清楚。

消息用 broadcast channel 分发。每个 channel 有独立的缓冲区大小配置，默认 256 条。慢消费者如果积压超过缓冲区容量，丢掉最旧的消息——宁可丢旧消息也不能让生产者阻塞。丢消息时记一条 WARN 日志，包含 channel 名称和丢弃的消息数。

HTTP 接口三个。创建 channel：POST /channels，指定名称和缓冲区大小，名称重复返回 409。发布消息：POST /channels/{name}/messages，body 就是消息内容，channel 不存在返回 404。订阅：GET /channels/{name}/subscribe，返回 SSE 流，先推最近 100 条历史消息再推新消息。订阅断开后服务端清理资源。

channel 列表查询接口返回所有 channel 的元数据：名称、缓冲区大小、当前订阅者数量、累计发布消息数。可以按名称模糊搜索。

消息体大小限制在 1MB 以内，超过返回 413。空消息体返回 400。消息发布成功返回消息 ID 和时间戳。

端口通过 PORT 环境变量配置，Cargo build 能过。
