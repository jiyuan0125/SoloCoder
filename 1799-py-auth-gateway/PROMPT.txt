FastAPI 认证网关。两种认证方式并存：JWT 和 API Key。为什么两种？浏览器端用 JWT 方便，前端带着 Token 就行。服务间调用用 API Key 简单，不用管 Token 过期刷新。用户信息存内存字典，启动时加载默认用户。

JWT 过期时间可配置，默认 2 小时。刷新 Token 时旧 Token 加入黑名单（内存 set），防止 Token 被盗后还能刷新。黑名单定期清理过期的 Token——每分钟扫一次，移除已过期的条目。同一个 Token 1 分钟内只能刷新一次，防止短时间内大量刷新把服务打满。

API Key 创建时随机生成一个 32 字符的字符串，返回给调用方。这个值只显示一次，之后通过管理接口只能查看 Key 的元数据（创建时间、最后使用时间、绑定的权限范围），不能查看 Key 本身。Key 可以吊销，吊销后使用该 Key 的请求返回 401。

接口清单：登录（POST /auth/login，用户名+密码换 Token，失败返回 401 不提示具体是哪个字段错误）、刷新 Token（POST /auth/refresh）、管理 API Key（增删查）。查 API Key 列表时支持分页和按状态过滤（活跃/已吊销）。

权限方面，每个 API Key 绑定一组允许的路径前缀。请求路径不在允许范围内的返回 403。

端口用 PORT 环境变量。
