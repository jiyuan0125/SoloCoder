Read-Through 缓存和普通缓存不同——miss 时自动从数据源加载，调用方不用关心缓存是否存在，拿到的永远是要么是缓存值要么是从数据源实时加载的值。Rust/tokio 实现。

数据源是 HTTP 接口。URL 支持模板替换，比如 http://backend/api/data/{key}，请求时 {key} 自动替换成实际值。模板里可以有多个占位符，比如 http://backend/api/{category}/{id}。加载成功的结果写入缓存再返回给调用方；加载失败不缓存，直接透传错误（包含 HTTP 状态码和错误信息）。

缓存同时支持手动和自动模式。手动模式下 get 只查缓存，miss 返回空不触发加载。自动模式（Read-Through）下 get 在 miss 时自动加载。两个模式用不同的接口路径区分。

TTL 在 set 时指定，不指定默认 300 秒。后台 tokio 定时任务每 60 秒扫描过期 key 并清理。容量上限触发 LRU 淘汰。

接口：手动 set/get/delete、Read-Through get、管理数据源配置（增删改查）、查看缓存统计（命中率、当前 key 数、数据源调用次数）。

PORT 环境变量配端口，Cargo build 能编译通过。
