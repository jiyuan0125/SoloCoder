用Go写一个多仓库状态巡检命令行工具，用 cobra 做子命令架构。我们运维团队管理着20多个Git仓库，每个仓库部署在不同服务器上，每天要检查各个仓库的状态是不是正常。

工具叫gitpolice，配置文件（YAML格式）中定义所有需要监控的仓库列表。配置文件路径默认为 ./gitpolice.yaml，可通过 -c 参数指定，文件不存在时退出码 1 并提示。配置文件语法错误时退出码 1 并打印错误行号。每个仓库配置包括：名称、本地路径或远程URL、分支名称、告警阈值。

巡检内容包括：检查仓库是否有未提交的修改（git status不干净）。检查当前分支是否落后于远程分支（git fetch后比较本地和远程的差异）。检查是否有过期的分支（超过N天没有新提交的分支），N可以配置。检查仓库的磁盘占用大小，如果超过阈值就告警。检查是否有大文件被提交（超过10MB的单文件），这在Git历史中是不推荐的。本地路径不存在或不是 Git 仓库时该条目标记为"不可达"继续检查其余仓库。

巡检结果输出一个汇总报告。正常的项目显示绿色OK，有问题的显示红色告警和具体问题描述。报告末尾有一个统计摘要：总共检查了多少个仓库，多少个正常，多少个有问题，按问题类型分类计数。有问题的仓库数大于 0 时退出码为 3，全部正常退出码 0。

加--watch参数可以进入持续监控模式，每隔指定时间（默认5分钟，可通过--interval配置）自动巡检一次。在持续模式下，只有状态发生变化时才输出告警，避免重复报告相同的问题。状态变化指的是之前正常的仓库变异常、或者之前异常的仓库恢复正常。

加--notify参数支持告警通知。目前支持输出到文件，每条告警一行JSON，后续可以对接其他通知渠道。告警消息包含时间戳、仓库名称、问题类型和详细描述。通知文件写入失败时打印到 stderr 但不中断巡检。

并发检查多个仓库时，20多个仓库如果串行检查会很慢，特别是需要git fetch的远程仓库。需要用goroutine并发执行，但每个仓库的检查结果是独立的，用sync.WaitGroup等待所有仓库检查完成后汇总。并发数量要可配置，默认10个并发，超出部分排队等待。某个仓库检查超时（默认30秒可配置）不阻塞其他仓库，超时的仓库标记为"检查超时"。

有些仓库可能是bare仓库（没有工作目录），git status命令不适用。要能自动检测仓库类型，bare仓库跳过工作目录检查。如果仓库配置了SSH远程地址，检查时需要SSH密钥认证。工具不应该处理认证问题，如果连接失败就直接报告"无法连接"，不阻塞其他仓库的检查。
