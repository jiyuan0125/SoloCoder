数据管道里任务之间有先后依赖，手工编排容易出错——上次 B 任务在 A 任务完成前就跑了，读了不完整的数据产出了一堆脏数据。Go/Fiber 做一个任务调度器，支持声明式依赖。

任务 B 声明依赖任务 A，A 完成后 B 自动触发。依赖链支持多层嵌套（A→B→C→D）。创建任务时做环检测——如果新增的依赖会形成环路，直接拒绝返回 409 附带"检测到循环依赖"和环路路径（比如"A→B→C→A"）。

执行失败会级联传播。一个任务挂了，所有直接和间接依赖它的任务全部标记为 FAILED，附带原因"上游任务 {id} 执行失败"。级联传播是递归的，一次失败可能影响整条依赖链。中间任务失败不会阻止不相关的其他分支执行。

任务状态有：PENDING（等待依赖）、READY（依赖满足等待执行）、RUNNING（执行中）、SUCCESS、FAILED。状态变更记录时间戳，查询时可以看到每个任务的完整生命周期。任务执行超时（默认 60 秒）自动标记为 FAILED。

接口可以创建带依赖的任务（指定依赖的任务 ID 列表）、查看依赖关系图（返回所有任务和依赖边，前端可以画 DAG）、查询单个任务状态。任务执行用 goroutine 模拟，执行时长随机 1-5 秒。

PORT 环境变量指定端口，go build 能过就行。
