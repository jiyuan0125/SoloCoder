HTTP 连接建立开销大，尤其是 TLS 握手那一下能占到首次请求耗时的 40%。Spring Boot 写个连接池管理服务，多个后端各自独立池，互不影响。某个后端的池子出问题不会拖累其他后端的请求。

获取连接有超时控制。设定等待超时（默认 5 秒），超时返回 503 附带"获取连接超时，池名 {name}"而不是让调用方干等。连接泄漏检测：借出超过 N 秒（可配置，默认 60）没还的记 WARN 日志，包含连接 ID、借用时间、当前持有者信息。日志要详细到能定位是哪段代码没关连接。

池满时的策略很关键。请求排队等连接释放，等待队列也设上限（默认 50 个）。队列满了直接拒绝返回 503——宁可拒绝也不能把整个服务拖垮。拒绝时附带提示"连接池 {name} 已满，当前队列长度 {n}"。队列中的请求按 FIFO 排队，先进先出。

接口动态调参：修改最大连接数、等待超时、泄漏检测阈值。调最大连接数时，缩容只缩空闲连接，借出去的等归还后再缩。扩容时按需创建，不提前预热。

管理接口查每个后端的池子状态：活跃数、空闲数、等待队列长度、累计借用次数、累计超时拒绝次数、累计泄漏检测次数。server.port 配端口，Maven 构建。
