给朋友的小团队写个代理测试工具，Go 写服务端跑在本地就行。他们经常要验证 HTTP 代理和 SOCKS5 代理能不能正常工作，手动测太麻烦。

http 子命令测试 HTTP/HTTPS 代理。用户指定代理地址（如 http://proxy:8080），工具通过代理访问一个测试 URL，记录连接时间、首字节时间（TTFB）和总耗时。测试 URL 默认用 httpbin.org/ip，可以通过 --url 参数自定义。验证代理返回的 IP 是否和预期一致（--expect-ip 参数）。代理地址格式不合法退出码返回 1。

socks 子命令测试 SOCKS5 代理。类似 HTTP 代理测试，但走 SOCKS5 协议。支持 SOCKS5 的用户名密码认证（--user 和 --pass 参数）。认证失败退出码返回 2。

benchmark 子命令对代理做性能测试。连续发 N 个请求（默认 10，通过 --count 调整），统计成功数、失败数、平均延迟、P95 延迟和 P99 延迟。并发数通过 --concurrency 控制，默认 5，超过 50 时退出码返回 1 防止把代理打挂。

chain 子命令测试代理链。指定多个代理（如 A → B → C），工具验证每一跳是否可达，最终出站 IP 是否符合预期。

proxy 子命令启动一个简单的本地代理服务器（HTTP 或 SOCKS5），方便在没有代理环境的开发机临时用。监听端口通过 --port 指定，默认 1080，端口被占用退出码返回 1。

代理连接超时默认 10 秒。代理服务器如果返回连接拒绝，退出码返回 2 并提示代理可能没启动。HTTPS 代理要正确处理 CONNECT 方法建立隧道。SOCKS5 握手阶段如果服务器返回的版本号不是 5，退出码返回 2。benchmark 并发测试时每个请求独立计时，不做平均化处理。chain 测试时中间某跳失败，输出到失败那一跳为止的结果，后续跳不测试。加 --json 参数输出结构化结果。加 --output 参数保存到文件。
