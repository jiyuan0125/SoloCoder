帮我用 C 写一个并行计算的任务调度框架。场景是：我们有一个需要对大量独立数据进行相同处理的需求——比如对服务器上的1000张图片做缩略图生成、对500个日志文件做关键词扫描、对一批 CSV 文件做数据清洗。这些任务之间没有任何依赖关系，可以完全并行处理。框架的使用方式：启动时指定工作线程的数量（一般设为 CPU 核心数），然后往框架里提交任务。框架自动把任务分配给空闲的工作线程执行。每个任务执行完后产生一个结果，提交者可以等待所有任务完成后统一收集所有结果。如果一个任务执行过程中出错了（比如某个图片文件损坏了），记录错误信息，但这个错误不影响其他任务的继续执行。支持在第一批任务还在执行的过程中继续提交新任务。框架关闭时要优雅退出——等所有已提交的任务执行完毕后再退出，不能有任务执行到一半被强制终止。提供一个监控功能：当前有多少任务在排队等待、多少任务正在执行、已经完成了多少任务。每个工作线程的分配要尽量均衡，不能出现一个线程忙死另一个线程闲着的情况。如果提交的任务数量远大于工作线程数量，要保证所有工作线程都能持续有活干。用纯 C 写，gcc 编译通过。如果工作线程在执行任务时崩溃了（比如遇到了段错误），框架要能检测到并把这个任务标记为失败，不影响其他工作线程。
代码拆成至少 4 个源文件：任务队列、线程管理、结果收集与监控、主程序，各自有头文件和实现文件。gcc 编译能过。
