Spring Boot 漏桶限流器。请求先进桶排队，以固定速率一个个放出去处理。桶满了——排队位置不够了——后来的直接拒绝，返回 429。

先说配置。每个 API 路径有独立的漏桶：桶容量（burst capacity）和出水速率（steady rate）两个参数。初始化时可以批量设，也可以运行时通过接口逐个改。改完新请求立即按新规则走，桶里已经在排队的按旧规则继续处理完。

再说运行。1. 请求进来查路径对应的桶配置，没有配置的路径不限流直接放行。2. 桶里还有位置就排队，返回 202 表示已接受等处理。3. 桶满了返回 429，响应头带 Retry-After 告诉客户端多久后再试。4. 桶以固定速率出水，每个出水的请求转发给后端业务逻辑。

然后是管理接口。GET /limiter/stats 返回所有路径的桶状态——当前排队数量、最近一分钟溢出（被拒绝）的次数。PUT /limiter/config 批量更新多个路径的限流参数，body 是个 JSON 数组，每个元素带 path、capacity、rate。PATCH /limiter/config/{path} 单独改一个路径。删除配置 DELETE /limiter/config/{path}，删了就不再限流。

配置数据存内存。服务重启后配置清空需要重新设。端口用 server.port 配置，Maven 构建。
