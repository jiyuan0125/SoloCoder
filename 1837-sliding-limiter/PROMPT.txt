我们的 API 被刷了，需要一个独立的限流服务挡在前面。Go 标准库 net/http 做一个滑动窗口限流器。

两种维度限流：按客户端 IP、按 API Key（请求头 X-API-Key）。每个维度维护滑动窗口计数器，窗口大小和每窗口最大请求数都可以通过接口配置——比如"IP 维度，60 秒窗口，最多 100 次"。

限流检查逻辑：请求进来先看有没有全局冷却——如果某个 IP 同时触发了多条规则的限流，直接给它加全局冷却期。冷却期间所有请求一律返回 429，响应头带 Retry-After 秒数。没在冷却期的正常走滑动窗口检查，超了返回 429，没超放行并计数加一。

规则通过接口管理。POST /rules 创建限流规则，body 带 dimension（ip 或 apikey）、window_seconds、max_requests。DELETE /rules/{id} 删除规则。删除规则后，已有的冷却状态要同步清理——不能删了规则用户还被冷却卡着。

这个服务可能会吃大量并发，被攻击的时候更夸张。内存里的计数器数据要管理好——窗口过了的数据及时清理，不要无限制涨。按 API Key 限流的话，Key 管理要有注册和吊销接口，注册时返回 Key，吊销后该 Key 所有请求直接 429。

API Key 注册 POST /keys，返回 key 字符串。吊销 DELETE /keys/{key}。端口 PORT 环境变量，go build 能过。
