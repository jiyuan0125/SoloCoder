运维那边提了个需求，要在没装 top 或 htop 的精简环境里查和管理进程，还要能输出结构化数据方便写脚本。用 Go 写一个进程监控管理工具。

工具列出系统所有进程信息：PID、PPID、进程名、命令行参数、用户、CPU 占用率、内存占用、启动时间和进程状态。支持按 CPU 或内存排序，支持按进程名或用户过滤。指定用户不存在退出码 0 输出空列表不报错。

进程树功能：根据 PPID 关系构建进程树，用缩进展示父子关系。某个进程如果有多棵子树要完整展示。支持指定 PID 只展示它下面的子树，PID 不存在退出码 1。进程树构建时可能出现孤儿进程（PPID 指向的进程已不存在），这种进程挂在根节点下面。

信号管理：向指定进程或进程组发送信号，常用 SIGTERM 和 SIGKILL。PID 不存在退出码 1。支持交互模式，发 SIGTERM 后等待几秒检查进程是否退出，没退出再提示是否发 SIGKILL。非交互模式加 --force 参数直接发 SIGKILL。

监控模式：定期刷新进程列表，高亮新出现或消失的进程，以及 CPU 或内存突然飙升的进程。资源占用超过阈值时输出告警到 stderr，不干扰 stdout 的结构化输出。

读取进程信息通过读 Linux 的 /proc 文件系统。CPU 占用率需要采样两次计算差值。进程可能在读取瞬间退出，读 /proc 时处理文件消失的情况跳过该进程不报错。内存占用要区分 RSS（实际物理内存）和 VSZ（虚拟内存），不能混淆。监控刷新间隔默认 2 秒，间隔小于 0.5 秒退出码 1。JSON 输出中数值字段统一用数字类型。加 --json 输出 JSON 格式。
