给朋友的运维小团队写个 CPU 监控工具，Go 写的命令行程序。他们需要在服务器上实时监控 CPU 各核心负载、频率变化和温度，排查性能瓶颈和过热问题。

工具通过读取 /proc/stat 采集 CPU 总体和各核心使用率（user、system、idle、iowait、steal 等），通过 /sys 下文件采集各核心当前频率和温度。支持实时监控和单次采集两种模式，不在 Linux 上运行退出码 1。实时模式下每隔指定秒数刷新，用彩色字符在终端显示各核心使用率条形图，使用率高的核心用红色标注。采样间隔小于 0.5 秒退出码 1。

分析模式持续采集一段时间（比如 60 秒），然后输出统计：平均值、最大值、最小值、标准差。检测 CPU 使用率突增突降事件（一秒内变化超过 30%），记录事件时间和前后各核心详细数据。

告警功能：某个核心温度超过阈值或 iowait 占比过高时，输出告警到 stderr，不干扰 stdout 数据输出。告警阈值通过命令行参数配置，阈值为负数退出码 1。

/proc/stat 中 CPU 时间单位是 jiffies，两次采样间隔要固定才能准确计算。某些虚拟化环境 steal time 可能很高（宿主机超售 CPU），这个指标要单独展示。温度信息获取路径因硬件平台不同而不同，有些服务器可能没温度传感器或没加载对应内核模块，温度读取如果某个核心返回空或异常（比如负的极端值），标注为读取失败不影响其他数据。CPU 频率要区分当前频率和最大频率，有些核心可能休眠频率为 0。工具自身 CPU 开销要尽量低。加 --json 输出 JSON。加 --output 把数据保存到 CSV。
