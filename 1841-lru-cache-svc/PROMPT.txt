Redis 太重了，用 Go Gin 写一个轻量级 HTTP 缓存服务。核心就是 LRU 淘汰加 TTL 过期。

缓存条目有三个状态：活跃、过期、淘汰。活跃条目的 TTL 到期了就变过期。过期条目不会被立刻删除——等下次有请求访问到它或者淘汰扫描扫到它的时候才真正清掉。手动调用 delete 接口直接变淘汰。活跃条目每次被 get 访问都刷新 LRU 排序，确保热点数据不被误淘汰。

容量通过接口配置，单位是条目数。比如配 10000 就最多存 10000 条。每个条目可以单独设 TTL（秒数），不设就走全局默认 TTL。一个关键场景：如果把全局容量从 10000 改成 5000，而当前已经存了 8000 条，那改完立刻触发淘汰，把最久没访问的 3000 条干掉。

接口清单——set: POST /cache，body 带 key、value、ttl（可选）。get: GET /cache/{key}，命中返回 200 + value，未命中返回 404。delete: DELETE /cache/{key}。flush: DELETE /cache 清空所有。stats: GET /cache/stats 返回命中率、当前条目数、总查询次数。capacity: PUT /cache/config，body 带 capacity 和 default_ttl。

统计里的命中率 = 命中次数 / 总查询次数。服务重启后数据清空。端口 PORT 环境变量，go build 能过。
