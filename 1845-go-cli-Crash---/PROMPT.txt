测试团队那边每天产生大量应用崩溃日志，手动归类太痛苦了。用 Go 写一个崩溃日志解析和去重分析工具，能处理 Java 的 hs_err_pid、Go 的 panic 堆栈、C/C++ 的 coredump backtrace 等多种格式。

工具支持解析多种崩溃日志格式。Java 堆栈从 hs_err_pid 开头的日志提取 JVM 版本、线程信息和崩溃时的堆栈跟踪。Go panic 从包含 panic 和 goroutine 堆栈的日志提取 panic 消息和调用链。C/C++ 段错误从 gdb backtrace 输出提取崩溃地址和调用栈。无法识别格式的文件跳过并在汇总列出，退出码 0。

提取的关键信息包括崩溃类型、崩溃消息、崩溃时函数调用栈（取前 10 帧）、发生时间。对崩溃信息做去重：调用栈顶部 N 帧（可配置，默认 3 帧）相同的视为同一个崩溃。去重后统计每种崩溃出现次数，按次数从多到少排序。

时间维度分析：按天统计崩溃总数变化趋势，标记新出现的崩溃类型（之前没见过的调用栈模式）。支持把分析结果输出为 HTML 报告，包含崩溃类型饼图和趋势折线图（用内嵌 SVG 生成）。

不同语言堆栈格式差异很大，解析正则各自适配。去重关键是确定哪些帧是应用代码哪些是系统库代码，应用代码帧才是有区分度的部分。日志文件编码可能是 GBK（Windows Java 应用）或 UTF-8，要自动检测。有些崩溃日志不完整（进程被强杀导致截断），解析时要容错，提取到多少信息就输出多少。输入目录不存在退出码 1。加 --json 输出 JSON。批量处理文件数量为 0 退出码 0 输出"无崩溃日志"。HTML 报告中 SVG 图表在 Chrome 和 Firefox 都能正常显示。
