新规要求所有服务上线必须提交完整的 K8s YAML 部署文件，得赶紧搞个 YAML 生成工具。每次上线新服务都要写一堆 Deployment、Service、ConfigMap、Secret、Ingress，大部分是重复模板代码，手动复制粘贴很容易出错。

工具通过交互式问答或配置文件收集部署信息（应用名称、镜像地址、副本数、端口、环境变量、资源限制等），配置文件用 YAML 格式，文件不存在退出码 1，语法错误退出码 1 并打印行号。然后自动生成一套完整的 K8s YAML。

生成的 YAML 包含：Deployment（liveness/readiness 探针、资源请求和限制、滚动更新策略）、Service（根据端口配置自动生成 ClusterIP 或 NodePort）、ConfigMap（非敏感环境变量）、Secret（敏感信息 Base64 编码）、HPA（根据 CPU 使用率自动扩缩容）。Secret 的 Base64 编码解码后要和原始明文完全一致。

滚动更新：修改配置后重新生成 YAML，和当前 YAML 对比，只应用有变化的资源。还能生成 kubectl apply 命令脚本。

模板管理：维护几套通用部署模板（Java 应用、Go 应用、前端静态资源），生成时选择对应模板，模板名不存在退出码 1 并列出可用模板。不同模板默认值不同（Java 默认内存大、前端不需要健康检查端口等）。

批量部署：从一个配置文件读取多个服务部署信息，一次性生成所有 YAML，输出目录按服务名组织，目录不存在自动创建。

生成的 YAML 要符合最佳实践，比如给所有资源加统一标签（app 名称、环境、版本号）。ConfigMap 和 Secret 数据有 1MB 限制，环境变量太多时提示改用文件挂载。Ingress 配置因 Controller 不同而不同（Nginx、Traefik 等），通过 --ingress-type 支持多种模板，默认 Nginx。
