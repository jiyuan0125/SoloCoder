前端 HTTP 后端有些是 gRPC 的，中间需要一个转换层。Rust tokio 做协议网关，把 HTTP JSON 请求翻译成 gRPC protobuf 发给后端，响应再转回 JSON。

工作流程：1. 请求进来路径格式是 /v1/{service}/{method}，从路径里提取 service 名和 method 名。2. 查配置表找到这个 service+method 对应的 protobuf 映射规则。3. 把 JSON 请求体按规则转成 protobuf 消息，发给后端 gRPC 服务。4. 拿到 gRPC 响应后转回 JSON 返回给客户端。

配置表通过接口管理。POST /routes 注册转换规则，body 带 service、method、protobuf 定义（文件路径或者内联都行）。GET /routes 查看所有规则。没有注册过的 service+method 组合，请求进来返回 404。

后端 gRPC 服务不可用时返回 502。gRPC 状态码要映射成 HTTP 状态码——OK→200，INVALID_ARGUMENT→400，NOT_FOUND→404，UNAVAILABLE→503，DEADLINE_EXCEEDED→504，INTERNAL→500，其他→500。

还有一个特殊场景：客户端发过来的不是 JSON，而是纯文本。网关需要按约定的分隔符或格式解析纯文本内容，拼成 protobuf 字段再发。这种场景单独在路由配置里标注 content_type: text。

数据全内存。端口 PORT 环境变量。Cargo build。
