DBA 团队那边提了个需求，要一个 Go 命令行工具分析 MySQL 慢查询日志。开发人员反馈接口慢的时候，要从慢查询日志里找对应的 SQL 分析原因，文件太大手动翻很痛苦。

analyze 子命令读取一个慢查询日志文件（mysqldumpslow 能解析的那种格式），统计所有慢查询的平均执行时间、最大执行时间、总执行次数，按平均执行时间从慢到快排序输出前 20 条。每条输出包含 SQL 语句（太长截断到 200 字符）、执行次数、平均时间、最大时间、锁等待时间和扫描行数。

explain 子命令针对指定 SQL 生成分析建议。内置简单规则引擎，检测 SELECT * 建议只查需要的字段，检测没有 LIMIT 建议加限制条件，检测 WHERE 里用了函数（如 WHERE YEAR(create_time)=2024）建议改范围查询，检测扫描行数远大于返回行数提示可能缺索引。

export 子命令把分析结果导出为 CSV。

慢查询日志格式有时不完全标准，SQL 可能跨多行需要正确拼接，拼接时保留原始换行。时间单位可能是秒或毫秒，要自动识别——数值超过 1000 按毫秒处理否则按秒。如果日志里有非慢查询内容要能跳过不影响分析。时间范围过滤参数可以指定只分析某段时间内的，开始时间晚于结束时间退出码 1 提示。日志文件不存在或无法读取退出码 1，不是创建空结果。explain 的 SQL 为空字符串退出码 1 提示需要提供 SQL。同一条 SQL 有多处建议按严重程度排序，SELECT * 优先级最高。export 导出 CSV 时文件已存在先覆盖不追加。导出过程中磁盘空间不足删除不完整文件退出码 1。
