有个老系统用的是 Flyway 管迁移脚本，但 Go 微服务这边没有好用的迁移工具，自己写一个。核心功能是管理 SQL 迁移文件的执行顺序和版本追踪。

迁移文件放指定目录下，文件名格式"版本号_描述.sql"，版本号递增数字（如 001_create_users.sql）。工具维护本地版本记录文件（JSON 格式）记录当前执行到哪个版本。

init 子命令初始化迁移管理创建版本记录文件。create 子命令生成新迁移文件模板，自动计算下一个版本号。up 子命令从当前版本开始按顺序执行所有未执行迁移文件，执行前打印文件列表让用户确认，每个文件成功后更新版本记录。down 子命令回滚指定数量版本，逆序执行已执行迁移文件的回滚操作。status 子命令显示已执行和待执行的版本列表。

每个迁移文件可能包含 UP 部分（-- UP 标记）和 DOWN 部分（-- DOWN 标记）。只有 UP 没有 DOWN 的迁移不可回滚，status 里要标记出来。

版本号不连续（如 001、002、005）时给出警告但不阻止运行。某个迁移文件执行失败后版本记录里标记为"failed"，后续 up 不自动重试而是提示让用户手动处理或用 force 参数重试。正在执行 up 时不允许同时执行另一个 up（通过锁文件实现），第二个 up 检测到锁文件退出码 1。down 回滚时如果某个版本的 DOWN 执行失败，版本记录不能前移。init 在已有版本记录的目录再次执行退出码 1 提示已初始化。create 生成的文件如果写入一半断电，下次 init 或 status 要能检测到不完整文件并报告。迁移文件 SQL 有语法错误时捕获错误回滚当前文件已执行部分标记为失败，不让工具崩溃。
