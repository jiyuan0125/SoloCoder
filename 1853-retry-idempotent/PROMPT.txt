调第三方支付接口超时率 15%，不重试丢钱，重试了怕重复扣款。Go 标准库 net/http 做一个重试调度服务，把重试逻辑从业务代码里抽出来。

客户端提交重试任务时提供：目标 URL、HTTP 方法、请求体、最大重试次数、间隔策略（固定间隔或指数退避）。提交后不阻塞，返回一个任务 ID，后台慢慢重试。指数退避加随机抖动——公式 base * 2^attempt + rand(0, base)，避免一堆任务同时重试把下游打爆。

幂等性靠幂等键保证。客户端提交任务时带一个 idempotency_key，如果已有相同键的任务在执行中或已完成，直接返回之前的结果，不重复执行。这个键的作用域是全局的。

任务状态流转：待执行→执行中→成功→失败。每次执行不管成功失败都记到历史记录里。超过最大重试次数后标为失败，不再尝试。

任务执行结果变更后，订阅了该任务的下游方要收到通知——调用它们注册的回调 URL。通知失败不重试，记录失败原因就行。

整个服务分四块：scheduler 管任务队列和调度时机，executor 负责实际发 HTTP 请求，store 存任务数据和幂等键映射，query 提供查询接口（按任务 ID 查状态、按幂等键查结果）。数据全内存。端口 PORT 环境变量，go build 能过。
