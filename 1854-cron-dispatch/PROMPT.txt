定时任务散在各台机器上管理一团糟——谁跑了什么、哪个失败了、下次什么时候跑，全靠人肉查 crontab。Spring Boot 做集中的事件调度器，用 java.time 和 java.util.concurrent 的调度能力。

支持两种任务类型：Cron 表达式的周期任务和指定延迟的一次性任务。Cron 到时间后 POST 回调 URL 传任务参数（body 里带任务名和自定义参数）。一次性任务执行完自动移除。任务状态：待调度→执行中→成功→失败。执行失败按配置决定是否重试（最多 3 次，间隔递增）。

一个关键问题：同一个任务上一次没执行完，下一次调度时间又到了怎么办？两种策略可选——跳过（skipped，记录一次跳过事件）或排队（queued，最多排 5 个，超出的跳过）。配置在任务注册时指定。

调度器重启后，所有待调度的任务要恢复。实现思路：任务信息持久化到本地文件，启动时加载恢复调度。回调 URL 不可达时标记失败，记录原因（连接超时 / DNS 解析失败 / HTTP 非 2xx）。

历史记录保留最近 1000 条执行记录，超出的丢弃最旧的。GET /tasks 查任务列表，GET /tasks/{id}/history 查执行历史，GET /tasks/{id}/logs 查回调日志（请求和响应内容）。POST /tasks 注册任务，DELETE /tasks/{id} 删除。Maven 构建，端口配置文件。
