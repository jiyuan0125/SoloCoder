Go 的 os/exec 包调用 mysqldump 和 pg_dump 挺方便的，拿来写一个数据库备份管理工具。现在备份靠 shell 脚本做的，功能太简单想用 Go 重写。

工具支持 MySQL 和 PostgreSQL 两种数据库备份。流程是调用数据库导出命令（MySQL 用 mysqldump，PostgreSQL 用 pg_dump）导出 SQL 文件，然后压缩，压缩完可选加密。

backup 子命令执行一次备份，需提供数据库类型、连接参数（主机、端口、用户名、数据库名）、输出目录。文件名自动生成"数据库名_日期_时间.sql.gz"，精确到秒。压缩用 gzip，等级通过参数指定（1-9，默认 6）。指定 --encrypt 则压缩后用 AES-256 加密，密钥从环境变量 BACKUP_KEY 读取。

schedule 子命令设置定时备份，用户指定 cron 表达式和备份参数，工具后台进程运行到点自动执行，配置保存到本地文件。

list 子命令列出所有备份文件，显示文件名、大小、压缩前大小、创建时间和是否加密。clean 子命令清理过期备份文件，指定保留天数，超过的自动删除但至少保留最近 3 个。restore 子命令从备份恢复数据库，自动检测是否加密，加密了先解密再解压缩再执行 SQL。

备份过程中数据库连接失败重试 3 次（间隔 5 秒），3 次都失败退出码 1。文件可能几个 GB，压缩加密都用流式处理不能加载到内存。加密用密钥派生函数从用户密钥生成实际密钥和 IV，不能直接用原始密钥。备份到一半中断（比如磁盘满）清理不完整文件。清理本身也失败退出码 1 并列出残留路径。BACKUP_KEY 为空或长度不足 16 字节退出码 1。密钥派生用 PBKDF2 至少 10000 轮。restore 时校验和不匹配退出码 1 不允许跳过校验。schedule 的 cron 格式错误退出码 1 指出哪一段解析失败。clean 时如果所有文件都超过保留天数但只剩 3 个，保留这 3 个退出码 0 并打印警告。
