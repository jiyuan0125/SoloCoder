线上 Redis 实例好几套，有时候要快速看键分布和内存状况，运维操作也需要。写一个 Go 的 Redis 管理工具，cobra 做子命令。

info 子命令显示 Redis 基本信息：版本号、已用内存、最大内存配置、客户端数、键总数、数据库数量。这些从 INFO 命令输出解析。

keys 子命令分析指定前缀的键，统计数量和内存。--pattern 参数用通配符匹配键名（如 user:* 或 session:*）。对匹配到的键统计每种数据类型数量（string、hash、list、set、zset），估算各类型总内存占用。估算方法：string 按值字节长度，hash 按字段数乘平均大小，其他类似。

memory 子命令找占用内存最多的前 N 个键，通过 SCAN 遍历所有键用 MEMORY USAGE 获取每个键内存占用，按大小排序输出。操作可能慢要显示进度。

evict 子命令查看和修改 Redis 淘汰策略。显示 maxmemory 和当前策略，支持通过参数修改。delete 子命令批量删除匹配模式的键，删除前显示数量和预估释放内存，要求用户确认，删除过程显示进度。

Redis 设了密码的话通过 --password 或环境变量 REDIS_PASSWORD 获取，都没提供且 Redis 需要认证则退出码 1。支持 --tls 启用 TLS。键数量非常多（几百万）时 SCAN 遍历可能很慢，要处理超时和连接中断，支持断点续扫从上次 cursor 开始。MEMORY USAGE 在旧版 Redis 可能不支持，不支持时跳过内存统计只显示键数量和类型。delete 批量删除时如果中途连接断开，已删除的键不可恢复，工具在删除前把要删的键列表写入临时文件，断开后重连对比临时文件和实际键只删剩余的。memory 遍历中某个键被删了（返回 0 或 nil）跳过不计入，不因单个键中断。keys 的 pattern 为空退出码 1。evict 修改后要回读确认，不一致退出码 1。
