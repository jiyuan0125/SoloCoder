帮我用 C 写一个多线程环境下的日志记录模块。场景是：一个高性能服务程序有很多工作线程（可能几十个），每个线程在处理请求的过程中都可能需要写日志——记录请求参数、处理结果、异常信息等。如果每个线程都直接打开文件写日志，会有严重的性能问题：频繁的磁盘 IO 很慢，而且多个线程同时写同一个文件需要频繁加锁。需要一种更高效的方式：每个线程写日志的时候，先把日志内容放到一个线程本地的内存缓冲区里（不阻塞业务线程），然后由一个专门的日志写入线程定期把所有缓冲区里的日志收集起来，批量写入磁盘文件。缓冲区大小固定（比如每个线程 4KB），如果某个线程产生日志的速度太快导致缓冲区满了还没来得及被收集，新来的日志可以覆盖最旧的那条——宁可丢失少量日志，也不能让业务线程因为写日志而阻塞等待。每条日志要包含：时间戳（精确到毫秒）、产生日志的线程编号、日志级别（DEBUG、INFO、WARN、ERROR）、日志正文内容。日志文件有大小上限，超过后自动切换到新文件（按日期或大小轮转）。用纯 C 写，gcc 编译通过。日志级别要可以动态调整——不需要重启服务就能把日志级别从 INFO 改成 DEBUG 来排查问题。
代码拆成至少 4 个源文件：缓冲区管理、日志写入、文件轮转、主程序，各自有头文件和实现文件。gcc 编译能过。
