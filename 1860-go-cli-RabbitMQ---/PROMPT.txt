上个月 MQ 出了个事故，队列堆积没人发现，原因就是没有统一的管理工具。现在要上 RabbitMQ 管理工具，用 Go 通过 Management HTTP API 操作（默认 http://localhost:15672/api），需要用户名密码。

queue 子命令管理队列：列出所有队列显示名称、消息数量（ready 和 unacked）、消费者数、状态（running/idle）、声明方式和创建时间。--create 创建队列指定是否持久化、自动删除、TTL 和最大长度。--purge 清空所有消息不可逆需二次确认。--delete 删除队列。

exchange 子命令管理交换器：列出所有显示名称、类型（direct/fanout/topic/headers）、是否持久化、绑定队列数。支持创建和删除。

binding 子命令管理绑定：列出指定交换器或队列的所有绑定。创建新绑定指定交换器、队列和路由键。删除绑定。

message 子命令查看队列中消息但不消费，peek 前 N 条显示消息体、属性和投递时间。publish 子命令往交换器发测试消息指定路由键和内容。

Management API 返回 403 时识别权限不足退出码 1 提示检查权限。RabbitMQ 不可用重试 3 次后退出码 1。创建队列同名已存在参数不同时 RabbitMQ 返回 precondition_failed，工具解析后退出码 1 提示先删旧队列。同名已存在参数一致退出码 0 提示无需创建。purge 前要求输入队列名二次确认，不一致取消退出码 1。binding 创建时交换器或队列不存在退出码 1 提示哪个不存在。publish 交换器不存在退出码 1。message peek 队列为空打印"队列为空"退出码 0。
