数据库扛不住了怎么办？前面加一层缓存。Go 标准库 net/http 做缓存服务，不要 Redis 那么重。

缓存两种淘汰机制并存：LRU（最久没访问的先淘汰）和 TTL（过期时间到了自动失效）。容量通过接口配，单位是条目数。每个 key 可以单独设 TTL（秒），不设就走全局默认 TTL。

get 一个 key 的时候如果命中了但发现已经过期了，要删掉这条然后返回 miss（404）。set 的时候如果当前条目数已经到容量上限了，先淘汰最久没访问的再写入。flush 接口一键清空所有数据。

改容量有个坑——如果把容量从 10000 改成 5000，而当前已经存了 8000 条，改完立刻触发淘汰，干掉 3000 条最久没访问的。

统计接口 GET /stats 返回三组数据：命中率（命中次数 / 总查询次数）、当前条目数、总查询次数。这些统计从服务启动开始累计。

key 和 value 都是字符串，不限制长度但极端长的 value 要考虑内存。整个服务分四块——cache 管淘汰和过期，policy 管 TTL 策略，storage 可选做文件持久化（不做也行），api 暴露 HTTP 接口。数据默认全内存。端口 PORT 环境变量，go build 能过。
