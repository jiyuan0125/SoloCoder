三个后端节点权重配的一样，但其中一台磁盘 IO 慢三倍，拖累了整体响应时间——均匀分配对异构集群不公平。FastAPI 做负载均衡引擎，按权重分配流量，让强的多扛点活。

服务分四个部分。registry 管节点注册——POST /nodes，body 带 address 和 weight（权重，正整数）。checker 定时做健康检查，间隔和阈值可配，检查用 HTTP GET /health。balancer 按加权轮询分配请求，权重越高的节点分到的请求越多。stats 记录每个节点的累计请求量和平均响应时间。

节点有状态流转：新建→活跃→疑似故障→已摘除。新注册的节点需要一次健康检查通过才变活跃。活跃节点检查失败变疑似故障，疑似故障连续 3 次检查成功恢复活跃。已摘除的节点需要重新注册。状态变更时通知注册了回调 URL 的订阅方。

权重变更后 stats 模块的历史统计保留——改了权重不代表之前的数据就作废了。权重设为 0 的节点不参与分配但不断开注册（相当于暂停）。删除节点 DELETE /nodes/{id}，注册回调 POST /callbacks。

查询 GET /nodes 返回所有节点状态和权重。GET /nodes/{id}/stats 返回该节点的请求量和响应时间统计。GET /stats 总览所有节点的统计。端口 PORT 环境变量。
