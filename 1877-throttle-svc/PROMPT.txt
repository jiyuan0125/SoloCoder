上游对接方不按约定的 QPS 调用，高峰期直接把我们打满了，自己的正常请求反而进不来。Go 标准库 net/http 做限流服务，用 sync 包做并发控制，time 包做窗口计算。

两种限流模式：固定窗口和滑动窗口。固定窗口按整分钟切割计数，简单但有边界突发问题。滑动窗口更平滑，但实现稍复杂。两种都支持，按规则配。维度按客户端 IP 或 API Key，请求头 X-API-Key 传入。

规则通过接口配置——POST /rules，body 带 dimension（ip/apikey）、mode（fixed/sliding）、window_seconds、max_requests。限流触发返回 429，响应头带 Retry-After 秒数。规则要有创建入口——这是最基本的管理能力。

限流检查的时候内部有个交互要注意。检查逻辑要调用一个统计模块来获取当前窗口的计数。统计模块更新计数时也要检查是否超限——如果超限了要触发告警记录。这两个操作涉及同一份计数数据的读写，用 sync.RWMutex 或类似机制保证并发安全，不要互相卡住。

统计模块记录每个规则维度的触发次数。GET /stats 返回各维度的限流触发次数、最后触发时间。GET /rules 查所有规则。数据全内存。端口 PORT 环境变量，go build 能过。
