上个月代码审计发现好几个 SQL 注入隐患，用 Go 写个命令行工具来扫描项目里的 SQL 语句，给安全团队做快速审计。

从 SQL 文件或源代码文件（.go/.java/.py）提取 SQL 语句。源代码用正则从字符串字面量中提取，处理多行字符串和转义。检测项：字符串拼接（未用参数占位符直接拼变量）、是否用参数化占位符（?/:1 算安全）、危险函数（LOAD_FILE/INTO OUTFILE/EXEC）、多语句风险。评分规则：参数化无拼接 80 分，拼接扣 30，危险函数扣 20，多语句扣 15，最低 0 分。拼接的给出参数化改写建议。

存储过程内部语句降低检测灵敏度避免误报。ORM 表名列名拼接不扣分。输出表格含文件名、行号、SQL 摘要、评分、风险项。文件不存在退出码 1。二进制文件退出码 1。无 SQL 退出码 0。全安全退出码 0，有低于 60 分的退出码 1。存储过程不完整打印警告降灵敏度。多行字符串正确拼接。Base64 字符串先解码再检测。
