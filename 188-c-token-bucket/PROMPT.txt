帮我用 C 写一个访问频率控制模块。场景是：公司的开放平台对外提供一些服务，为了保证服务质量，需要对每个调用方（每个应用）的调用频率做限制。比如普通应用每分钟最多调用60次，付费应用每分钟最多200次。模块需要在服务器端精确地控制调用频率——每收到一个请求就检查这个应用在当前时间窗口内已经调用了多少次，如果没超限就放行并把计数加一，如果超限了就拒绝请求并告诉客户端「调用太频繁了，请 X 秒后再试」。关键要求：限流要精确——不能出现一分钟内实际通过了超过配额数量的请求。如果有多个工作线程同时处理不同应用的请求，限流计数必须准确，不能出现竞争条件导致计数偏差。每个应用的配额可以不同，启动时从配置文件加载。支持运行时查询某个应用当前剩余的可用次数。如果一个应用在某个时间窗口内完全没有请求，下一个窗口开始时配额完全恢复。有一个容易出错的边界情况：请求时间刚好卡在窗口切换的边界上（比如 59.999 秒发了一个请求），要确保这个请求被正确地计入当前窗口而不是下一窗口。用纯 C 写，gcc 编译通过。限流模块本身不能成为性能瓶颈——即使每秒有几万个请求要检查，检查操作也必须在微秒级完成。用纯 C 写，gcc 编译通过。限流模块的内存占用要可控——不能为每个应用都永久保存详细的请求时间记录。
代码拆成至少 4 个源文件：计数管理、时间窗口检查、配置加载、主程序，各自有头文件和实现文件。gcc 编译能过。
