MySQL 主库每秒扛 5000 查询，热点数据反复穿透磁盘 IO。Go Gin 写一个缓存代理挡在前面，先把读压力吃掉。

set 写缓存，get 读缓存，delete 删单个，flush 清全部，stats 看统计——这五个操作必须覆盖。全局有一个 default_ttl（秒），set 的时候不指定就走默认值，也可以 per-key 单独覆盖。淘汰策略是 LRU，容量通过 PUT /cache/config 动态改，单位是条目数。

缓存值被更新之后，之前 get 拿到旧值的客户端再读就是新的了——这里没有主动推失效通知，靠下次读取拿最新值。容量从大改小，多出来的条目立刻按 LRU 淘汰到新容量之内，不要等下次 set 才清。容量改大则不触发任何淘汰。

key 没有格式限制，URL 也好自定义字符串也好，原样存储。value 也是字符串，大小不做硬限制。get 一个不存在的 key 返回 null 不报错。

并发 set 同一个 key 的时候后来的覆盖前面的，不报错。stats 返回总条目数、命中次数、未命中次数、当前容量配置。端口 PORT 环境变量，go build 能过。
