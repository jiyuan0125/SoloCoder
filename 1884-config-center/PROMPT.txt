你说一个数据库连接串改了要重启七个服务，这合理吗？FastAPI 写配置中心，集中管所有服务的配置，改了就推，不用重启。

配置按 environment 和 project 两级分组。同一个 key 在 dev/staging/prod 可以有完全不同的值。每次 PUT /configs/{project}/{env}/{key} 修改配置都生成一个版本快照，版本号自增。GET /configs/{project}/{env}/{key}/history 能看完整变更链，回滚用 POST /configs/{project}/{env}/{key}/rollback?version=N，回滚操作本身也生成一条版本记录，版本历史不会断。

客户端通过 POST /watches 注册对某个 key 的关注，带上 callback_url。配置变更时中心往 callback_url POST 通知，失败重试 2 次、间隔 5 秒。连续 5 次推失败标记该 watch 为 inactive，不再推送。批量修改多个 key 时，每个 key 独立触发各自的 watch，一个推送失败不影响其他。

差异查询 GET /configs/{project}/{env}/diff?v1=5&v2=8 返回两个版本之间 key 级别的增删改。端口 PORT 环境变量。
