微服务网关用 Go Gin 搞。路由表存内存里，支持两种匹配——精确匹配和前缀匹配，同一个路径如果精确和前缀都有，精确优先。每个路由绑定一个认证策略：none（无认证）、apikey（API Key 校验）、jwt（JWT 验证）。

JWT 验证模块独立放一个文件，检查过期时间和签名，签名密钥通过配置传入。API Key 存内存 map，管理接口 POST /admin/keys 创建、DELETE /admin/keys/{kid} 吊销，吊销后立即生效。请求带了不存在的 Key 返回 401。

有个请求聚合功能比较特别——POST /api/aggregate，Body 里传一组后端 URL 列表，网关并发请求这些 URL，等全部回来后合并 JSON 结果返回。聚合请求有总超时（默认 10 秒），单个后端超时不影响其他，超时的那个在结果里填 null。Body 里的 URL 必须是已注册的后端地址，不认识的返回 400。

同一个 API Key 同时发大量聚合请求要控制并发——每个 Key 最多同时 5 个聚合请求在跑，超了直接 429。端口 PORT 环境变量，go build 能过。
