最近缓存数据出了两次事故——TTL 配置不合理导致脏数据读了好几个小时没人发现。需要一个可控的缓存服务，Rust axum 来做。

LRU 淘汰策略，容量按条目数配置，超容量淘汰最久未访问的条目。每个 Key 可以单独设 TTL，没设的走全局默认值（默认 300 秒）。过期数据惰性删除——访问时发现过期才清掉，不专门跑清理线程。清理的条目数计入淘汰统计。

统计接口返回命中率、当前条目数、总查询次数、淘汰次数、过期清理次数。修改全局容量后，如果当前条目超过新容量，立即触发淘汰到新容量以下。淘汰过程中新写入正常处理，只是淘汰和写入并发时淘汰优先。

支持按 Key 前缀批量删除，比如删掉 cache:user:* 下所有条目。批量删除返回实际删除的条目数，也要更新统计数据。Key 最长 256 字节，value 最大 1MB，超出拒绝写入返回 422。写入时 value 已经存在就覆盖，TTL 以新值为准。命名空间功能——Key 带 namespace: 前缀的归到一个命名空间，支持按命名空间批量清除和独立统计命中率。查询接口支持按前缀扫描，返回匹配的 key-value 列表。端口 PORT 环境变量，Cargo build 能过。
