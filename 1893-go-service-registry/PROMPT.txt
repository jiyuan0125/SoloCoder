微服务拆了十几个，每次部署不知道哪些实例还活着。Go 标准库写一个注册中心，先把服务发现这件事搞定。

第一步：服务注册时带上名称、IP、端口、一组标签（键值对）。同一个服务名可以有多个实例，每个实例有独立的 ID。注册成功返回实例 ID 和租约时长。实例 ID 自动生成，格式 servicename-timestamp-random。

第二步：心跳保活。默认 30 秒发一次，超时自动注销。注销后 5 秒内又发心跳算重新注册，不需要走注册流程。连续 3 次心跳超时才真正注销并通知所有订阅者。心跳接口要轻量，返回实例 ID 和下次心跳截止时间。

第三步：服务查询。按服务名查所有健康实例，支持按标签过滤。标签值可能是数字也可能是字符串，过滤时统一按字符串精确匹配。查询结果按实例 ID 排序返回。不健康的实例也能查到但标注状态。

注册和查询要并发安全，高频率的心跳不能阻塞查询。服务注销后如果有请求还在引用这个实例信息，不能导致服务崩溃——用读写锁或 copy-on-write 保护。管理接口列出所有注册的服务和实例数，包含健康和不健康的。端口 PORT 环境变量，go build 能过。
