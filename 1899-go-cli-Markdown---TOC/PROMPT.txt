帮我用Go写一个Markdown文档处理命令行工具，专门用于技术博客的管理。功能包括自动生成目录、检查文章中的链接是否有效、以及批量管理Markdown文件的元数据。

第一个功能是目录生成。接收一个Markdown文件，扫描其中的标题行（以一到六个井号开头的行），生成一份目录并插入到文档中指定位置。目录的格式是每个标题缩进对应层级的空格，后面跟标题文本和锚点链接。锚点的生成规则：把标题文本转小写，空格替换为连字符，去除标点符号，连续的连字符合并为一个。比如"## Go 语言入门教程"生成锚点"go-语言入门教程"。插入位置通过一个特殊标记识别，在Markdown文件中写一行"<!-- TOC -->"，工具找到这行后替换为生成的目录。如果文件中没有这个标记，就在第一个标题之前插入目录。每次重新生成时替换上一次生成的目录区域（通过<!-- TOC -->和<!-- /TOC -->标记包裹的区域）。

第二个功能是链接检查。扫描Markdown文件中所有的链接，包括行内链接、引用式链接和图片链接。行内链接格式是[text](url)，引用式链接是[text][ref]加文末的[ref]: url。对每个URL做有效性检查：如果是相对路径（以/或./开头），检查文件是否存在。如果是绝对URL（http或https开头），发送HEAD请求检查响应状态码，200到399算有效，404算失效，超时或网络错误标记为无法验证。检查结果输出一个报告，列出每个链接的状态。支持并行检查，默认10个并发，通过参数调整。

第三个功能是元数据管理。技术博客的Markdown文件通常在文件开头有YAML Front Matter（---开头和结尾的YAML块），包含标题、日期、标签、分类、摘要等元数据。工具可以读取、修改和批量更新这些元数据。比如批量给一批Markdown文件添加或修改标签、统一日期格式、检查必填的元数据字段是否齐全。元数据操作通过子命令实现：meta read显示文件的元数据，meta set key value修改某个字段，meta check检查必填字段，meta batch对目录下所有Markdown文件执行批量操作。

这个工具需要注意以下几点。Markdown中代码块内的内容不应该被扫描，代码块（用三个反引号包裹的区域）里可能包含井号开头的行（Shell注释）、链接格式的文本（代码示例），这些不应该被当成标题或链接处理，工具需要正确识别代码块的边界，跳过代码块内的内容。HTML注释内的内容也要跳过，因为TOC标记本身就在HTML注释里。链接检查时有些网站会拒绝HEAD请求（返回405），这种情况下需要回退到GET请求，但GET请求可能下载很大的文件，应该设置一个最大下载大小限制（比如1KB），只读取响应头判断状态码。锚点生成时中文字符的处理，GitHub和很多Markdown渲染器对中文锚点的处理方式是直接保留中文字符，不做转换，你的锚点生成规则要和目标平台的规则一致，或者提供选项切换。

代码架构把Markdown解析、目录生成、链接提取和检查、元数据操作分成独立模块。Markdown解析器用简单的状态机，识别标题、链接、代码块和HTML注释这几种关键元素，不需要完整的Markdown AST。链接检查用worker pool并发执行HTTP请求。
代码块内的井号开头行不应该被当成标题，工具需要正确识别代码块边界并跳过。
处理分三步：扫描-分析-输出。可指定从某步开始。如果从分析开始但扫描未执行，用空数据继续。
多级路径：tool process --input ./data --output ./result。相对绝对路径都支持。
服务端端口通过命令行参数或环境变量指定。
