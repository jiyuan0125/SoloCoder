各服务认证逻辑五花八门，有的用 token 有的用签名有的啥也不用。统一收到网关层，Rust axum 做认证网关。

支持两种认证方式：API Key（静态密钥）和 JWT（动态令牌）。路由表配置哪些路径需要认证、用哪种方式。同一个路径可以同时配两种，请求带哪个就用哪个验。都没带返回 401，响应头带 WWW-Authenticate 说明支持的方式。

API Key 存在内存里，可以通过管理接口增删。每个 Key 关联一组元数据（比如服务名、权限等级）。JWT 密钥支持轮换——新密钥签发的 token 优先验证，旧密钥保留一段时间（默认 1 小时）也能验。过期后旧 token 统一 401。

认证通过的请求转发到后端，转发时在 Header 里注入用户信息：从 JWT payload 提取或从 Key 关联的元数据取。后端服务地址通过配置指定。JWT 过期时间检查精确到秒，不能差一秒。API Key 的增删操作本身需要 JWT admin 角色认证保护。

未注册的路由路径返回 404 而不是 401——别让攻击者通过 401 猜到路径存在。认证失败记录日志但不记录 token 原文。Cargo build，PORT 环境变量。
