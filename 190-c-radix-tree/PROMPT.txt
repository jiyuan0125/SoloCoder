帮我用 C 写一个 URL 路径的快速匹配和分发模块。场景是：一个 Web 服务器需要根据请求的 URL 路径把请求交给不同的处理逻辑来处理。比如访问 /web/users 的请求交给用户管理模块，访问 /web/orders 的请求交给订单管理模块，访问 /assets/ 开头的路径交给静态文件服务。模块支持两种路径规则：精确匹配和前缀匹配。精确匹配就是路径必须完全一样才行（/web/users 只匹配 /web/users，不匹配 /web/users/123）。前缀匹配就是路径以某个前缀开头就行（/assets/ 匹配 /assets/css/style.css 和 /assets/js/app.js）。还支持路径参数——比如规则 /web/users/:id 可以匹配 /web/users/42 也可以匹配 /web/users/hello，其中 :id 部分是参数，实际值是 42 或 hello。一条路径规则里可以有多个参数（比如 /web/users/:userId/posts/:postId）。匹配优先级：精确匹配优先于前缀匹配，参数少的规则优先于参数多的规则。支持在运行中动态添加新的路径规则和删除已有的规则。匹配速度要快——每个 HTTP 请求都要做一次匹配，即使有几百条规则也不能线性扫描。用纯 C 写，gcc 编译通过。如果没有规则能匹配某个路径，要有一个默认的处理逻辑（比如返回404页面或者把请求交给默认处理器）。
代码拆成至少 4 个源文件：路径规则管理、前缀树匹配、参数提取、主程序，各自有头文件和实现文件。gcc 编译能过。
