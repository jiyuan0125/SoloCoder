排查一个问题跨五个服务翻日志，人都要疯了——Java Netty 写一个链路追踪收集器。

每个请求在入口网关生成一个 TraceID（UUID），后续所有调用通过 X-Trace-Id 这个 Header 传递。每次服务调用记一个 Span，包含：TraceID、SpanID（本跳 UUID）、ParentSpanID（上一跳的 SpanID）、服务名、操作名、起止时间戳、耗时（毫秒）、状态码（200/500/timeout 等）。Span 通过 HTTP POST /spans 异步推上来，Body 是 JSON。

推送失败不能丢——存本地一个内存队列，后台线程每 5 秒重试一次，队列上限 1000 条，超了丢弃最老的并打 WARN 日志记录丢弃的 TraceID。

查 TraceID 走 GET /traces/{tid}，返回完整的调用树，每层展示服务名、操作名、耗时和状态。支持按服务名 GET /traces?service=order-service 和时间范围 ?from=xxx&to=xxx 搜索，结果按时间倒序排列。

服务通过 POST /services 注册（Body 带 name 和 address），注册后才能推 Span 数据，未注册服务的 Span 直接丢弃并记日志。Maven 构建，PORT 环境变量。
