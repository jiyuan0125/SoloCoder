Rust axum 做限流——两种算法并存，固定窗口和滑动窗口，按客户端选。

固定窗口按分钟整点切割，比如 10:00:00 到 10:01:00 是一个窗口，下一个窗口 10:01:00 重新计数。滑动窗口按秒级精度，回溯最近 60 秒的请求数。两种算法的限额可以不同，比如固定窗口每分钟 100 次，滑动窗口每分钟 80 次。

限流规则按 API 路径配——PUT /rules/{path} 设置该路径用哪种算法和限额（Body 带 algorithm: fixed_window / sliding_window、limit: 数字），未配置的路径不限流直接放行。但有个全局总 QPS 上限，所有路径加起来不能超过这个数，全局满了就算某条路径还没到自己的限额也被拦，返回 429。

改限额的时候，已经在处理中的请求按旧限额计，新请求走新限额。实时统计走 GET /stats，返回每个路径的当前 QPS、被限流次数、算法类型。GET /rules 列出所有已配置的规则。全局上限通过 PUT /config/global-qps 修改。统计接口还返回当前活跃的规则数和最近 1 分钟的请求 QPS。Cargo build，PORT 环境变量。
