朋友公司那边邮件系统要加实时推送，说现在收邮件全靠手动刷，效率太低。用 Go 帮他写个 WebSocket 推送后端，不需要实现完整邮件协议，只做内部消息的实时通知和状态同步。

新邮件到了立刻推给收件人。发件人通过 HTTP 接口发邮件（指定收件人、主题、正文和附件列表），收件人在线就走 WebSocket 推通知，离线存离线队列。通知只含邮件 ID、发件人、主题和到达时间，正文要用户主动拉。邮件状态（已读、未读、星标、归档）通过 WebSocket 同步到用户所有在线设备，手机标记已读了电脑端立刻更新。服务端维护推送指针记录每个用户推到哪封邮件了，上线后从指针位置逐条推，推完更新指针。指针重启后会丢，重启后从头推但要去重。

邮件可归类到文件夹（收件箱、已发送、草稿箱、垃圾箱）和打标签。文件夹和标签变更走 HTTP 接口，结果通过 WebSocket 推给所有设备。附件信息在通知里带着，内容通过单独 HTTP 接口下载，大附件（超过 10MB）上传支持分片，上传完服务端合并，上传失败能断点续传。邮件删除先软删除移到垃圾箱，从垃圾箱再删才硬删除，硬删除后通知所有设备移除。多设备同时标记已读以最后到达服务端的为准。

gorilla/websocket 处理实时连接，JSON 消息格式，内存存储。邮件 ID 不存在返回 404，非收件人删除返回 403。服务端端口通过命令行参数或环境变量指定。
