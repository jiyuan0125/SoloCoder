下个月合规要求上线，短信发送必须有审核通过的模板，不能随便发自定义内容。赶紧搞一个短信网关后端管理服务，Go 开发，WebSocket 用于实时推送短信状态回调和接收上行短信。

短信发送流程是业务系统通过 HTTP 提交请求，指定手机号、模板 ID 和模板参数，服务端用模板填充参数生成最终文本再调外部服务商 API 发。模板支持变量占位符，比如"您的验证码是${code}，${time}分钟内有效"。管理员创建模板时填名称、内容和变量说明，模板有审核状态（待审核、已通过、已拒绝）。审核被拒后修改重新提交，审核状态要正确流转。

外部服务商把发送状态回调到我们的 HTTP 接口，服务端收到后更新短信状态（已发送、已送达、发送失败），同时通过 WebSocket 推给提交发送请求的业务系统。业务系统建 WebSocket 连接订阅关心的消息 ID，状态变更实时收到。状态回调可能重复到达，要做幂等处理。发送失败服务商返回临时错误时自动重试最多 3 次，间隔递增。

上行短信（用户回复）由服务商推到 HTTP 接口，服务端解析后通过 WebSocket 推给对应业务系统。解析时要容错处理特殊字符和编码问题。服务端还要统计每个业务系统的短信发送量（按天、按小时汇总），每个业务系统有每日发送上限，超过拒绝，限流按 API Key 维度。WebSocket 断线重连时，重连期间的状态变更要能补推。

gorilla/websocket，JSON 格式，内存存储。服务端端口通过命令行参数或环境变量指定。
