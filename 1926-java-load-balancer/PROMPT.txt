有状态服务做负载均衡不能随便分配——用户第一次请求落在节点 A，第二次打到节点 B，session 全废了。Spring Boot 用一致性哈希。

虚拟节点数可配，默认每个真实节点 150 个虚拟节点，通过 PUT /config 设置 vnodes_per_node。节点上下线只影响相邻虚拟节点的流量重分配，不会全局打乱。节点四种状态：注册中→活跃→draining→离线。注册中的还没完成初始化不接流量。活跃的正常服务。Draining 不接受新请求但把手里已有的处理完再下线——给运维一个优雅下线的窗口。离线的完全不参与哈希环计算。

切换到一致性哈希模式后，已有会话映射不立即全部打乱，而是逐步迁移——新请求按哈希分配，已经建立映射的会话在一段时间内（默认 60 秒，可配）保持原节点，过了窗口才按新哈希走。

注册时 POST /nodes 带 ip 和 port，同一个 ip:port 不能重复注册。GET /nodes 查看所有节点状态和当前权重。代码至少三个源文件：策略模块（哈希环计算和虚拟节点管理）、节点管理（状态机和健康检查）、API 层（HTTP 接口）。Maven 构建。
