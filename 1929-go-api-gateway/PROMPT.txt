前端一个页面要调五个后端接口，串行加载要 3 秒，用户等不了。Go Gin 做请求编排网关——客户端一个请求触发后端多个服务调用，结果按模板合并返回。

编排方案通过接口配置。POST /plans 创建方案，Body 里定义一组后端调用（每条带 url、method、并行或串行标记）和一个合并模板。模板里用 ${response.serviceA.field} 引用后端返回值——比如 ${response.user.name} 取 user 服务返回的 name 字段。嵌套字段用点号连接。

后端调用失败时按降级策略处理：return_default（模板里该字段填默认值）、ignore（该字段填 null）、fail_all（整个请求返回 500）。降级策略每个调用单独配。

方案里引用的后端 URL 必须已通过 POST /backends 注册。方案修改后新请求用新方案，正在处理中的请求继续用旧方案不受影响。GET /plans 列出所有方案，GET /plans/{id} 查看单个方案详情。方案里至少要有一个后端，空方案提交返回 400。端口 PORT 环境变量，go build 能过。
