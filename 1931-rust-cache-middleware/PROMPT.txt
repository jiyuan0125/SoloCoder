线上缓存就一层 LRU，热 key 命中率还行但长尾 key 频繁 miss，每次 miss 都要穿透到后端存储，RT 抖得厉害。想加一层远程缓存又怕架构搞太复杂，干脆 Rust axum 写个两级缓存中间件先把方案跑通。

L1 是进程内 LRU，容量小速度快，放热数据；L2 用 HashMap 加人工延迟模拟远程缓存（比如每次读写随机睡几毫秒），验证两级协作的逻辑。查询路径很直白：先查 L1，命中直接返回；miss 了查 L2，命中就回填 L1 再返回；都 miss 返回空。写入时同时写 L1 和 L2，保证两边数据一致。

有个并发细节——L2 写入有模拟网络延迟，如果同一个 Key 刚好在写入过程中，此时又来一个查询，不能让查询穿透到 L2 再读一次，应该直接等前一次写入完成再返回结果。L1 满了做淘汰时只淘汰 L1 自己的条目，L2 那边不动。L2 条目带 TTL，过期用惰性删除——访问时发现过期才清理，不主动扫。

两级容量独立配置，L1 比如 1000 条，L2 比如 10000 条，通过接口或配置文件传进去。统计接口要能看清每级缓存的命中率、当前条目数，还有个关键指标：L1 miss 但 L2 命中的次数，这个越高说明 L1 容量可能不够。

GET /stats 返回两级各自的 hits、misses、当前 size 和 L1-miss-L2-hit 计数。GET /cache/{key} 查询，PUT /cache/{key} 写入，DELETE /cache/{key} 删除（两级都删）。
