Go 标准库做一个支持灰度发布的注册中心。场景很简单——新版本上线不能一把全切，得先让少量流量试试水，没问题了再放量。

实例生命周期分五个状态，严格按顺序流转：
1. 待上线 → 服务刚注册，还没通过健康检查。注册时带健康检查配置（路径、间隔、超时），注册中心定时探测，连续通过 3 次自动变为「预发布」
2. 预发布 → 只接收带 X-Canary: true 请求头的灰度流量，普通流量不会路由到这里。灰度观察一段时间后，运维手动调接口确认
3. 正式 → 确认后变为正式实例，接收全量流量。这是常态，大部分时间实例都在这个状态
4. 下线中 → 触发下线操作后进入此状态，不再接受新请求，但已经进来的请求要等处理完。注册中心跟踪活跃连接数，降到 0 后自动变为「已下线」
5. 已下线 → 实例彻底不参与路由。保留 24 小时后注册中心自动清理记录，这段时间内还可以查看历史信息

预发布切正式必须手动调 POST /instances/{id}/promote，不能自动——这是安全卡点，防止灰度没验证完就全量铺开。

服务发现接口 GET /services/{name}/instances 支持 include_canary 参数，默认 false 只返回正式实例，传 true 则包含预发布实例。每个实例返回 ID、地址、权重、当前状态、最后心跳时间。

实例注册用 POST /services/{name}/instances，心跳用 PUT /instances/{id}/heartbeat，超时机制跟健康检查分开——心跳 30 秒不来就标记不健康，但不会自动注销，只有健康检查连续失败才触发下线流程。
