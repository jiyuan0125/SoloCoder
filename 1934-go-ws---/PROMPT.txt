我们公司要做一个众筹项目的实时进度推送服务，用 Go 开发。众筹发起人设定目标金额和截止日期，支持者可以随时出资。页面需要实时显示当前已筹金额、支持者人数、距离目标的百分比和剩余天数。当有新的出资时，所有正在浏览该项目的用户都能立刻看到数字跳动更新。

服务端维护每个众筹项目的状态。支持者通过 HTTP 接口提交出资请求，服务端处理后通过 WebSocket 广播给所有订阅了该项目的客户端。推送的数据包括最新总额、新增金额、出资者昵称（可以匿名）、留言内容和出资时间。

项目页面要显示一个出资流水，最新的在最上面。每个出资记录包含金额、时间和留言。这个流水在 WebSocket 连接建立时要推送最近二十条历史记录，之后只推送增量。

为了增加互动感，当金额达到某些里程碑时（比如目标的百分之二十五、百分之五十、百分之七十五、百分之百）要推送一个特别的庆祝消息，前端可以据此播放动画效果。众筹成功后要推送回报方案的领取指引。

出资金额的统计要用整数分来累加，避免浮点精度问题导致显示的总额和实际明细对不上。另外如果同一个人多次出资，总额要合并显示。WebSocket 推送要做合并，如果一百毫秒内有多笔出资，合并成一条推送而不是逐条发，避免消息过于频繁。出资留言要做长度限制和敏感词过滤，超长留言截断而不是报错。项目用 Go modules，internal 放众筹状态管理和推送模块，cmd 放 main.go。服务监听 8082 端口，同时提供 HTTP 接口用于提交出资和查询项目详情。内存维护所有数据，服务重启后清空。

出资金额不能为零或负数，提交时返回 400。众筹目标金额不能为零，创建项目时校验。同一个出资者多次出资时合并统计人数不变，但金额累加。里程碑庆祝消息只推送一次，不能因为重连等原因重复触发。出资记录按时间倒序推送最近二十条历史时，如果不足二十条就全部返回。项目查询 HTTP 接口返回项目详情时包含已筹金额、支持者人数和完成百分比，百分比保留一位小数。
服务端端口通过命令行参数或环境变量指定。
