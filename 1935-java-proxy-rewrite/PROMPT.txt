我们产品线最近接了个大客户，他们的后端服务有 v1 和 v2 两个版本同时跑，客户端请求头里带个 X-API-Version 字段标明要访问哪个版本，没有这个头就走默认版本。流量转发服务用 Spring Boot 来做。

路由规则是这样的——解析 X-API-Version 头，匹配到对应版本的后端地址列表，然后做负载均衡转发。如果请求头缺失或者版本号不在配置里，走默认版本的后端。后端地址列表支持配置多个，轮询或随机分配都行，这块不用太复杂。

GET 请求的响应可以做短期缓存，相同请求路径 + 查询参数在 5 秒内命中缓存就直接返回，不再转发到后端。缓存 key 要包含版本号，不同版本的相同路径不能串。POST、PUT、DELETE 这类写操作不缓存。

后端返回 5xx（500/502/503/504 都算）的时候触发自动重试——从同版本的其他后端实例中挑一个重发，最多重试 2 次，加上首次请求一共 3 次机会。3 次都失败返回最后一个错误的响应给客户端。重试的时候要记录日志，方便排查是哪个后端有问题。

转发时要保留原始请求的 Header 和 Body，同时注入 X-Forwarded-For 记录客户端真实 IP。超时设置默认 10 秒，可配。

Maven 构建，端口用配置文件指定。
