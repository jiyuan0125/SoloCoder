老系统是 PHP 写的，里面的限流逻辑散落在十几个文件里，改一处怕漏五处。拿 FastAPI 从头写一个滑动窗口限流器，把限流从业务代码里抽出来独立部署。

算法用滑动窗口，精度到秒——不是那种粗糙的固定窗口，不会出现在窗口边界处突发两倍流量的问题。窗口大小和每秒允许的阈值按 API 路径分组配置，比如 /api/login 可以配成 10 次/分钟，/api/query 配成 100 次/分钟。配置通过接口动态下发，改完立刻生效。

限流分三级串行判断——先查 IP 级别（单个 IP 地址的总量），再查用户级别（单个用户 ID 的总量，从 Header 里取 X-User-Id），最后查 API 级别（该接口的全局限量）。任何一级触发阈值直接拒绝，返回 429，响应体带上剩余等待时间和触发的具体规则描述。

被限流的请求要记事件日志，包含客户端 IP、用户 ID、请求路径、触发的规则层级、时间戳。日志写入内存，保留最近 5000 条，通过 GET /rate-limit-events 可以按时间范围和路径查询。

滑动窗口的实现建议用时间片数组——把一个窗口按秒拆成多个小格子，每秒滑动一格，统计时把窗口内所有格子的计数加起来。这样既能保证精度，又不用存每个请求的时间戳。

POST /rules 配置限流规则（路径、窗口大小、阈值、层级），DELETE /rules/{id} 删除，GET /rules 列出所有规则。GET /status/{path} 查看某个路径当前的限流状态和剩余配额。

端口用 PORT 环境变量。
