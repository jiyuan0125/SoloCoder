竞品那个开放 API 网关看起来挺能打的，协议转换那块做得挺顺手——客户发 XML 过来，内部服务只接 JSON，网关中间就把这事办了。Netty 写一个类似的协议网关试试。

路由表这块要支持路径参数提取。比如定义路由 /users/{userId}/orders，请求进来后把 userId 提出来，注入到转发请求的 Header 里面（X-Path-Param-userId: xxx）。后端服务拿到 Header 就知道要查谁的数据，不用自己再解析路径。路由规则用 Map 存就行，启动时加载，运行时也可以通过接口热更新。

限流用令牌桶算法，每个路由独立配桶——有的接口敏感限得严（比如 10 QPS），有的接口无所谓（比如 1000 QPS）。令牌桶参数包括桶容量和填充速率，通过接口配置。超限返回 429，响应体带上 Retry-After 头告诉客户端等多久。

协议转换是核心能力。请求进来先检测 Content-Type：application/xml 的自动转成 JSON 再转发，application/json 的直接过。响应也一样，后端返回 JSON 但客户端 Accept 是 application/xml 的话，转成 XML 再返回。转换失败返回 400，带具体错误信息（哪个字段格式不对、标签不闭合之类的）。GET 请求不需要 body 转换。

转发用 Netty 的 HttpClient 实现，异步非阻塞，超时默认 5 秒可配。Maven 构建，端口用配置文件指定。
