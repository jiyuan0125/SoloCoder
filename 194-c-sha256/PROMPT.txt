帮我用 C 写一个文件完整性校验工具。场景是：运维团队需要在文件传输前后验证文件有没有被篡改或者损坏。使用方式：对输入文件计算出一个固定长度的摘要值（一串字符），传输完成后再算一次，两次的摘要值一致就说明文件完整无损。要求：支持任意大小的文件——从几个字节的小配置文件到几十 GB 的数据库备份文件，都能处理。对于大文件，不能把整个文件读进内存，必须分块读取处理。相同内容的文件必须算出完全相同的摘要值。不同的文件内容（哪怕只有最后一个字节不同）算出的摘要值要几乎不可能相同——碰撞概率要极低。支持对整个目录递归计算——遍历目录下所有文件，分别计算每个文件的摘要，并输出一个汇总的摘要（把所有文件的摘要值拼接后再算一次摘要）。还要支持部分校验——只计算文件前 N 个字节的摘要（用于大文件的快速初步校验），和只计算文件最后 N 个字节的摘要。输出格式是十六进制字符串。如果输入是一个目录，遇到子目录要递归处理，遇到符号链接要跟踪实际文件还是跳过需要明确。用纯 C 写，gcc 编译通过，不依赖第三方库。计算大文件（几个 GB）的摘要时，要能显示进度——让用户知道正在处理中而不是以为程序卡死了。用纯 C 写，gcc 编译通过。整个工具做成一个命令行程序，通过参数指定文件路径和操作模式。
代码拆成至少 4 个源文件：哈希计算、文件分块读取、进度显示、主程序，各自有头文件和实现文件。gcc 编译能过。
