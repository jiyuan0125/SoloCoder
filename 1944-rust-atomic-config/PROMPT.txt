隔壁部门做了个基础服务，配置参数每次上线都得手动改好几个文件，改漏一个就跑不起来。我们这边自己对接的同时顺便把安全配置中心也做了——tokio 实现的配置管理服务。

原子更新是个硬需求——改配置经常是一组 key 要一起变，比如数据库地址改了、连接池大小也得跟着调，不能只生效一半。接口支持一次请求更新多个 key-value 对，要么全部写入成功，要么一个都不动，不出现中间状态。实现上可以用事务日志——先写意图日志，全部 key 写成功后标记提交，服务重启时如果有未提交的日志就回滚。

敏感配置的安全处理——key 可以标记为 secret，标记了的 key 存储时用 AES 之类的对称加密，读的时候自动解密。列表接口返回所有 key 的元信息（名称、是否 secret、更新时间），但 secret 的 key 不返回值。单独查询接口 GET /configs/{key} 返回解密后的值，但需要调用方有相应权限（简单起见，校验请求头里的 X-Auth-Token）。

审计日志每次变更都要记——谁改的（从 X-User-Id 头取）、什么时候改的、改了哪个 key、旧值是什么、新值是什么。secret 的 key 在审计日志里旧值和新值都显示 ***。日志保留最近 2000 条，GET /audit/logs 支持按操作人和时间范围查询。

POST /configs 批量写入配置，PUT /configs/{key} 单个更新，GET /configs 列表，DELETE /configs/{key} 删除。端口通过 PORT 环境变量配置，Cargo build 能过。
