新规下来了——生产环境必须有 Prometheus 采集业务指标，之前都只监控了系统层面的 CPU 内存，业务指标一个没有。Spring Boot 做一个指标采集服务，让业务方把关键指标灌进来。

三种指标类型对应不同的场景。Counter 是递增计数器，比如请求总量、错误总量，只能往上加不能减，重启后从 0 开始。Gauge 是可增可减的仪表盘，比如当前在线用户数、队列深度，随时上下浮动。Histogram 是分布直方图，比如请求响应时间，统计落在各个桶里的数量（<100ms、<500ms、<1s、<5s、>=5s），还能算 P50/P95/P99。

/metrics 接口输出标准 Prometheus 文本格式——每行一个指标，指标名后面可以带标签维度。比如 http_requests_total{method="GET",path="/api/users",status="200"} 12345。业务方通过 POST /metrics/{type} 接口上报数据，type 区分 counter/gauge/histogram。上报的时候指定指标名、标签 map 和值。

聚合查询能力——GET /metrics/query 按 metric name 和时间范围查询历史数据，计算 P99、P95、平均值。数据存储在内存中，按时间窗口滚动保留最近 1 小时的原始数据点，聚合结果持久保留。时间窗口粒度可选：1 分钟、5 分钟、1 小时。

标签维度不能太多——单个指标的标签组合不超过 100 种，防止维度爆炸把内存吃光。超过限制的上报返回 422。

Maven 构建，端口用配置文件指定。
