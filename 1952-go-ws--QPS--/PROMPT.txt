我们做了个 API 网关，需要实时监控每个下游服务的健康状态。具体来说，网关会把每个请求的 QPS、平均延迟、错误率这些指标通过 WebSocket 推给我们的监控面板。监控面板是一个前端页面，打开后连上 WebSocket 就能实时看到各个服务的状态变化。

用 Go 实现这个推送服务。网关侧也是 WebSocket 客户端，连上来后注册自己负责的服务名称，然后持续上报指标数据。监控面板连上来后订阅感兴趣的服务列表，只收到订阅的那些服务的指标推送。

指标数据需要做聚合。QPS 是每秒请求数，上报频率不一定固定，服务端要根据上报时间戳计算滑动窗口内的真实 QPS。延迟要分 P50、P95、P99 三个分位数。错误率按 HTTP 状态码大于等于 400 的比例算。

还有一个限流功能。如果某个服务的错误率连续 3 分钟超过 10%，自动给这个服务发一个降级通知，通过 WebSocket 推给所有订阅了该服务的客户端。降级通知发出去之后，如果错误率降回 5% 以下持续 1 分钟，再发一个恢复通知。

分位数计算不能用简单的排序取值，数据量上来之后排序太慢，要用近似算法。滑动窗口的边界要处理清楚，不能把窗口外的数据算进去。降级判断里的连续 3 分钟，是指最近 3 分钟内的每个 1 分钟窗口都超标，中间断了一下就不算连续了。客户端断线重连后，要重新订阅之前的列表，不能默认全量推送，因为有些面板只关心特定的几个服务。
