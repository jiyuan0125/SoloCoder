我们要做一个实时告警推送系统。各种监控系统（服务器监控、应用监控、网络监控等）检测到异常后，把告警通过 WebSocket 发到我们的告警中心。告警中心再把告警实时推给运维人员，运维人员在 Web 页面上能看到告警弹出来，可以点击确认，也可以升级给上级处理。

用 Go 写告警中心服务。监控系统的 agent 通过 WebSocket 接入告警中心，连接后注册自己属于哪个监控源（比如 server-monitor、app-monitor），然后持续推送告警事件。每个告警有严重级别（critical、warning、info）、标题、详情和关联的主机或服务名。

运维人员也通过 WebSocket 连接告警中心。连接后运维人员可以选择订阅哪些监控源、哪些严重级别的告警。告警进来后，系统先做一个待办匹配，看看这个告警关联的资源当前有没有未处理的待办工单。如果没有，就自动创建一个待办，并把告警推给所有匹配订阅条件的运维人员。如果已经有未处理的待办，就把告警追加到那个待办下面。

运维人员收到告警后可以确认，确认后告警状态变为已确认，所有订阅者都能实时看到状态变化。如果一个 critical 级别的告警超过 15 分钟没人确认，自动升级，把告警推给该监控源的备用联系人列表。升级后如果再过 30 分钟还没人处理，再升级一次，推给团队负责人。

指标聚合方面，需要统计每个监控源的告警数量趋势，每分钟统计一次最近一小时内每分钟的告警数，这些统计数据要能通过 WebSocket 查询返回。

几个的地方。告警去重很重要，同一个主机同一个告警标题在 5 分钟内重复上报只算一条，但要记录重复次数。运维人员断线重连后，要把他离开期间未确认的告警补发给他。升级通知要避免重复发，同一个告警同一级别只升一次。待办工单的状态变更也要实时推送。如果某个监控源的 agent 断线了，要检测到并生成一个 agent 离线的告警。
