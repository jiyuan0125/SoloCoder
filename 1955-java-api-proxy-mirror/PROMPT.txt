现在用的方案不支持流量录制，测试团队每次要造测试数据都得手动调接口，想复现一个线上 bug 更是费劲——得先猜当时的请求参数是什么。Spring Boot 做个 API 镜像代理，把经过的请求和响应都录下来，需要的时候回放。

代理模式很简单——正常转发请求到后端，同时在内存里存一份请求响应对。录制的每条记录包含：请求方法、路径、请求头、请求体、响应状态码、响应头、响应体、时间戳。录制开关可以按路径过滤，不是所有接口都需要录，比如 /health 这种就不用存。

回放模式——通过 GET /replay/{record_id} 可以重放某条录制的记录，直接返回当时录到的响应，跳过后端。这个功能特别适合做回归测试：先录一批正常流量，然后代码改完之后回放这些请求比对响应是否一致。GET /replay/latest 自动回放最近一条匹配的记录。

录制存储上限可配——比如默认保留最近 5000 条，超出后最老的记录自动覆盖。按路径和状态码筛选录制的记录：GET /records?path=/api/users&status=200。单条记录的详情通过 GET /records/{id} 查看。

转发本身要透明——原始请求的所有信息原样传到后端，额外加一个 X-Recorded: true 的头标记这是被录制的请求。转发超时默认 10 秒可配。

POST /mirror/start 开始录制（可指定路径过滤规则），POST /mirror/stop 停止录制。Maven 构建，端口用配置文件指定。
