海外用户访问国内机房延迟动辄 300ms，有些 API 调用甚至超时失败。北上广各部署了机房，但流量分配全靠 DNS 轮询，用户实际跑到哪个机房看运气。axum 做一个地理位置负载均衡，根据请求来源把流量路由到最近的机房。

核心逻辑——客户端请求进来后，取其 IP 地址，查地理位置（可以用内置的 IP 段映射表，按 CIDR 分区，比如亚洲 IP 段对应上海机房、欧洲 IP 段对应法兰克福机房）。找到最近的机房后，从该机房的后端列表里选一个做负载均衡转发。

就近机房不可用怎么办？如果最近机房的所有后端都标记为 unhealthy（健康检查连续失败），自动切换到第二近的机房，以此类推。所有机房都不可用时返回 503。切换逻辑要有日志记录，方便排查是不是有机房在频繁抖动。

机房健康状态定时探测——每个后端独立探测，探测间隔可配（默认 10 秒），探测方式为 HTTP GET 到后端的 /health 路径。连续 3 次探测失败标记为 unhealthy，探测恢复后自动标记 healthy。整体机房状态是：机房内所有后端 healthy 则机房 healthy，否则 degraded。

IP 段到机房的映射通过 POST /zones 配置——每个 zone 定义名称、CIDR 列表、后端地址列表。GET /zones 查看所有 zone 的配置和健康状态。GET /stats 查看每个机房处理的请求量和平均延迟。
