API 要升级到 v2，但还有一堆老客户端在用 v1，直接停掉 v1 客户端全挂，不改吧新功能又上不去。Netty 做一个版本网关，新旧版本的后端并存，客户端各走各的路。

路由按 URL 路径中的版本号匹配——/v1/users 路由到 v1 后端集群，/v2/users 路由到 v2 后端集群。版本号从路径第一段提取。如果路径没有版本前缀（比如 /users），走默认版本（可配，比如 v2）。版本和后端地址的映射关系通过配置文件或接口管理。

兼容层处理——v1 的请求格式和 v2 不一样的话（比如字段名改了、结构变了），网关在转发前自动做转换。v1 请求进来，通过兼容层转换成 v2 的格式再转发到 v2 后端，响应再反向转回 v1 格式。兼容规则可配置，字段映射 + 类型转换 + 默认值填充。不配兼容层的就直接透传，不做转换。

版本使用统计——每个版本独立统计调用量、平均响应时间、错误率（4xx 和 5xx 分别统计）。GET /stats/versions 返回各版本的统计数据。这些数据帮助判断什么时候可以安全下线 v1——当 v1 的调用量降到可忽略的时候。

路由规则通过 POST /routes 配置，包含版本号、后端地址列表、是否启用兼容层。GET /routes 列出所有路由规则。DELETE /routes/{version} 下线某个版本的路由。

构建用 Maven，端口走默认配置文件。
