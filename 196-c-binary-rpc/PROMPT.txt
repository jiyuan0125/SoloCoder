帮我用 C 写一个跨进程的服务调用通信模块。场景是：系统架构中有一个主进程负责接收外部请求和调度，多个工作进程负责执行具体的计算任务。主进程需要能调用工作进程里的处理逻辑——告诉工作进程「去做什么事」，工作进程做完后把结果报告给主进程。这就是跨进程的服务调用。模块要支持的功能：调用方构造一个请求（指定要调用的方法名称和若干参数），发送给目标进程。目标进程收到请求后执行对应的方法，把执行结果发回来。请求和响应都用紧凑的二进制格式编码，减少通信的数据量和解析时间。参数支持多种类型：整数（32位和64位）、浮点数、字符串、二进制数据块。每次调用有超时机制——如果目标进程在指定时间内没有响应，就取消这次调用并返回超时错误。支持异步调用模式——发出请求后不阻塞等待，目标进程处理完后通过回调来通知结果。多个调用可以同时进行，互相不干扰。如果目标进程崩溃了，正在进行的调用要能检测到并返回错误而不是永远等着。还要考虑通信通道本身的可靠性——如果消息在传输过程中丢失或损坏，要有检测机制。用纯 C 写，gcc 编译通过。同一个方法可以被多个调用方同时调用，模块要能区分不同的调用并正确返回各自的结果。用纯 C 写，gcc 编译通过。通信的底层可以基于管道或者 Unix 域套接字，根据具体场景选择。
代码拆成至少 4 个源文件：请求构造与编码、响应解析与解码、通信传输通道、主程序，各自有头文件和实现文件。gcc 编译能过。
