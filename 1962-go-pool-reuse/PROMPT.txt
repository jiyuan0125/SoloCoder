之前买的 SaaS 数据库连接服务到量了，续费太贵。Gin 自建分片连接池，把连接按 key 分散开，同一个 key 的请求复用同一个分片，既省连接数又避免热点。

分片逻辑是这样的——连接池分成 N 个分片（N 可配，比如 16），每个分片是独立的微型连接池，有自己的最大连接数和空闲超时。请求进来时根据 key 做一致性哈希，算出该落到哪个分片。同一个 key 永远路由到同一个分片，连接可以复用，不用每次新建。

一致性哈希的好处是扩缩容时迁移量小——分片数从 16 加到 32，只有大约 50% 的 key 需要重新映射，不像取模那样全盘打乱。虚拟节点也加上，每个物理分片映射 100 个虚拟节点，保证 key 分布均匀。

每个分片独立管理自己的连接——最大连接数、空闲超时、最大生命周期都是分片级别的参数。某个分片压力大不影响其他分片。分片状态可查询：GET /pool/shards 查看每个分片的活跃连接数、空闲连接数、等待数、总请求数。

连接获取接口 POST /pool/acquire（传 key，返回连接信息），POST /pool/release 归还连接（传 key 和连接 ID）。GET /pool/stats 查看整体统计——总分片数、总连接数、平均获取耗时、各分片的负载分布。

端口通过 PORT 环境变量配置。项目能 go build 通过，能正常启动就行。
