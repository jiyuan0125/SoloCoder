上次发版有个服务挂了，排查两小时才发现它拖垮了另外三个下游服务——A 挂了导致 B 超时，B 超时导致 C 线程池耗尽，C 耗尽导致 D 请求全失败。这种级联故障靠人脑根本记不住依赖关系。Spring Boot 做服务依赖分析，把这些关系自动理清楚。

服务注册时声明自己的上游依赖——POST /services 注册服务，body 里包含服务名和依赖列表（这个服务依赖哪些其他服务）。注册中心收到后自动构建全局依赖图：每个服务是一个节点，A 依赖 B 就画一条 A→B 的边。

自动检测循环依赖——每次注册或更新依赖关系后，跑一遍图的深度优先遍历。如果发现 A→B→C→A 这种环，立刻返回告警信息，列出环上所有服务。循环依赖是定时炸弹，上线前必须解决。

影响分析是关键功能——当某个服务要下线或维护时，调 GET /impact/{service_name}，系统从依赖图中算出所有直接和间接依赖这个服务的下游服务。比如 C 挂了，分析结果显示 B（直接依赖）、A（间接依赖，通过 B）都会受影响。每个受影响的服务列出依赖深度和影响路径。

依赖图可视化数据通过 GET /graph 获取——返回节点列表（服务名、状态）和边列表（from、to、调用次数）。前端拿这个数据画个有向图就行。定时刷新各服务的健康状态，不健康的标红。

Spring Boot 配置文件管理端口，Maven 构建。
