上个月线上出了个事故——GPU 计算集群资源有限，同时只能跑 3 个推理任务，但没有排队机制，所有任务一窝蜂抢资源，最后一个都没跑成。FastAPI 做一个分布式信号量，控制同时最多 N 个客户端持有资源。

信号量的语义很简单——初始化时指定 N（比如 3），表示最多 3 个客户端可以同时持有。客户端调 POST /semaphores/{name}/acquire 获取许可，成功返回 200 和一个 acquire_id。持有期间其他请求还能来，只要当前持有数没超过 N 就继续放。超过 N 的请求进入等待队列，不立刻拒绝。

等待队列用 FIFO——有人释放许可时（POST /semaphores/{name}/release，传 acquire_id），按先进先出的顺序唤醒队列头部的等待者。等待者被唤醒后自动获取许可，返回成功。等待超时可配（默认 30 秒），超时返回 408，不无限挂着。

信号量可以通过 POST /semaphores 创建，传名称和容量 N。运行时可以调 PUT /semaphores/{name}/config 修改容量——比如 GPU 扩容了，从 3 改成 5。容量增大后等待队列里排着的请求可以立刻被满足。容量缩小的话，已经持有的许可不受影响，但新请求要等到当前持有数降到新容量以下才能获取。

GET /semaphores/{name}/status 查看当前持有者列表（acquire_id 和持有时间）、等待队列长度、总容量。GET /semaphores 列出所有信号量。

端口用 PORT 环境变量。
