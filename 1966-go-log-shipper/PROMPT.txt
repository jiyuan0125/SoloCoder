生产环境的日志散落在十几个容器里，每次排查问题得挨个登录容器 grep，效率低得要命。Go 标准库 做一个日志搬运工，把分散的日志集中到一个地方。

架构是多源多目标——从多个源收集日志（每个源是一个 HTTP 端点或文件路径），输出到多个目标（文件、HTTP 接口、内存缓冲区）。日志通过 POST /ingest 接口写入，body 是 JSON 格式，包含 level、message、timestamp、source 和自定义字段。

每个目标独立配置——文件目标配置路径和轮转策略（按大小或按时间），HTTP 目标配置远程 URL 和批量大小（攒够 50 条或 5 秒发一次），内存目标配置最大条目数。目标之间完全独立，某个目标写入失败（比如远程 HTTP 接口超时）不影响其他目标的写入——文件该写写、内存该存存。

失败重试策略也是目标级别的——HTTP 目标默认重试 3 次，间隔递增（1 秒、2 秒、4 秒）。全部重试失败后该批日志暂存到本地待重试队列，后台定时重新尝试发送。文件目标写入失败（磁盘满）则记录一条告警到 stderr，不丢弃日志。

GET /targets 查看所有目标的状态——类型、配置、最近写入时间、累计成功/失败次数。POST /targets 添加目标，DELETE /targets/{id} 移除。GET /stats 查看整体吞吐量——每秒接收多少条、各目标的写入速率。

端口通过 PORT 环境变量配置。项目能 go build 通过，能正常启动就行。
