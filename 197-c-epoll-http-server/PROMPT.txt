帮我用 C 写一个高性能的 HTTP 服务框架。场景是：需要搭建一个能同时处理大量客户端连接的 Web 服务——比如同时有几千个客户端在请求，每个请求可能需要几十毫秒到几秒来处理。要求：使用高效的等待和通知机制来管理大量并发连接，绝对不能为每个连接创建一个独立的线程（几千个线程会让系统崩溃）。支持解析客户端发来的 HTTP 请求——提取请求方法（GET/POST 等）、请求路径、请求头、请求体。根据请求路径把请求分发给对应的处理逻辑——不同的路径由不同的处理模块来处理。支持构造 HTTP 响应——设置状态码（200、404、500 等）、响应头（Content-Type、Content-Length 等）、响应体。要内置一个静态文件服务——根据请求路径返回对应的文件内容，根据文件扩展名自动设置正确的内容类型（.html 返回 text/html，.css 返回 text/css 等）。支持 keep-alive——一个 TCP 连接上可以连续处理多个 HTTP 请求，不用每个请求都重新建连接。对于 POST 请求，请求体的最大长度要有上限（比如 1MB），超过就拒绝。用纯 C 写，gcc 编译通过，不依赖第三方库。框架要有一个简单的方式注册路由处理逻辑——使用者只需要写处理逻辑并指定路径，不需要关心底层细节。
代码拆成至少 4 个源文件：请求解析、路由分发、响应构造、主程序，各自有头文件和实现文件。gcc 编译能过。
