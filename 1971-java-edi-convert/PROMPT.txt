供应商发来的 EDI 格式各不相同——这个用 D97A 版本，那个用 D98B，字段分隔符、段结束符都不一样，每次对接新供应商都得写一套解析代码。Spring Boot 做一个 EDI 报文转换器，把解析和生成逻辑统一起来。

EDIFACT 报文解析——接收一段 EDI 文本，按 EDIFACT 语法规则拆分成段（以单引号分隔）、数据元（以 + 或 : 分隔），构建成内部结构化的树形格式（Map 或 POJO）。反向也能从内部格式生成 EDI 文本——段和数据元按规则拼接，加上正确的分隔符和终止符。

不同交易伙伴的映射规则——虽然都叫 EDIFACT，但各家用的段、数据元顺序、必填项可能不同。通过 POST /mappings 配置映射规则：源格式到目标格式的字段对应关系。比如供应商 A 的 BGM 段第 2 个数据元是订单号，供应商 B 的在同一位置但含义不同。映射规则按交易伙伴 ID 区分，转换时自动匹配。

转换前后都要校验必填字段——解析 EDI 时检查必填段和数据元是否存在，缺失的字段返回明确错误：哪个段、第几个数据元、期望什么值。生成 EDI 时也校验内部格式的完整性，避免生成不合规的报文。错误信息包含行号或段标识，方便定位。

POST /convert/parse 解析 EDI 文本为 JSON，POST /convert/generate 从 JSON 生成 EDI 文本。GET /mappings 列出所有映射配置。

Maven 构建，端口用配置文件指定。
