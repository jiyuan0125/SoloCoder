旧系统的 URL 路径规范是 /api/v1/getUser?id=123，新后端改成 /users/123 了。前端代码量太大改不动，两套路径规范得并行一段时间。Spring Boot 在中间做一层重写代理，前端继续调旧路径，代理自动转成新路径转发给后端。

重写规则用正则表达式——每条规则包含匹配模式（正则）、替换模板、优先级（数字越小越先匹配）。比如模式 ^/api/v1/getUser\?id=(\d+)$ 替换成 /users/$1。请求进来后按优先级依次匹配规则，命中第一条就执行替换并停止继续匹配（first-match-wins 策略）。替换后的路径作为新的请求路径转发到后端。

重写规则可以动态管理——POST /rewrite-rules 添加规则（正则、替换模板、优先级），PUT /rewrite-rules/{id} 修改，DELETE /rewrite-rules/{id} 删除。修改后立刻对新请求生效。GET /rewrite-rules 列出所有规则及各自的匹配次数。

重写过程要记录日志——每条被重写的请求记录原始路径、重写后的路径、命中的规则 ID。日志保留最近 5000 条，GET /rewrite-logs 可查询。没命中任何规则的请求直接透传到后端，不做任何修改。

转发时要保留原始请求的 method、headers 和 body，只改路径。查询参数也要正确处理——正则里可以捕获 query string 并重新拼接到新路径上。转发超时默认 10 秒可配。

端口在 application 配置文件中指定，mvn package 能打包就行。
