上周有个租户突然暴增请求量把共享 API 打挂了，全站受影响半小时才恢复。事后分析发现单层限流不够——租户级限了但全局没限，或者全局限了但单个租户没限，总有一层漏掉。FastAPI 做层级限流，从全局到租户到 API 逐级控制。

三级限流串行判断。第一级：全局总 QPS——整个系统的总请求量不能超过上限（比如 10000 QPS），超了直接拒绝，不管是谁的请求。第二级：租户级 QPS——每个租户（从 Header 取 X-Tenant-Id）有独立的 QPS 上限（比如租户 A 1000 QPS，租户 B 500 QPS）。第三级：单 API 级 QPS——每个 API 路径有全局限量（比如 /api/heavy-query 最多 100 QPS）。三级中任何一级超限就拒绝，返回 429 并带上触发的层级和剩余配额。

配额回收和借用——租户没用完的配额自动回收到共享池，其他租户可以临时借用。比如租户 A 配额 1000 但当前只用了 300，剩余 700 回收到共享池。租户 B 配额 500 用完了，可以从共享池借，但借用有上限（比如最多借 200），防止某个租户把共享池全占了。回收和借用的量实时统计。

GET /limiter/status 查看当前三级限流的状态——全局剩余配额、各租户的用量和配额、各 API 的用量。GET /limiter/stats/{tenant_id} 单个租户的详细数据。POST /limiter/config 配置各级别的限流阈值。

监听端口由 PORT 环境变量决定。
