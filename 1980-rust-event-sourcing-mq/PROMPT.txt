上次审计来查账，要求拉出三个月内每笔交易的状态流转，按时间线展示。翻数据库发现中间状态早覆盖了，根本还原不出来。这事儿之后拍板上事件溯源——谁也别想覆盖历史，每次变更都是一笔追加记录。

用 axum 做事件溯源队列。状态变更以事件形式持久化，回放事件能恢复到任意时刻的状态。事件结构包含 event_id、aggregate_id、event_type、payload（JSON）、timestamp、version。同一个 aggregate 下 version 严格递增，写入时做乐观并发校验——提交的 version 和当前最新不一致就返回 409，让客户端决定合并策略。

事件只能追加，修改和删除都不行，这就是溯源的基本规矩。查询接口按 aggregate_id 拉完整事件流，也支持按 event_type 和时间范围过滤。返回结果按 version 升序排，分页参数用 offset + limit。

定期做快照，把当前聚合状态序列化存下来。快照之后的事件回放从快照开始而不是从头跑。快照触发条件可配——按事件数量（每 1000 条）或时间间隔（每小时）。历史版本查询接口给定 aggregate_id 和 target version，服务端从最近的快照加增量事件回放到指定版本返回状态。

事件存储用内存，服务重启数据可以丢。但快照必须持久化到文件，启动时从最近快照恢复，再重放后续事件。cargo build 编译，PORT 环境变量控制监听端口。
