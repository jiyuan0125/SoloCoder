做一个远程桌面系统的后端，用 Go 写，通过 WebSocket 实现被控端和控制端之间的实时通信。被控端运行在用户的 Windows 或 Linux 电脑上，是一个轻量级的后台客户端程序。控制端是操作人员的浏览器页面。两端都通过 WebSocket 连接到我们的后端服务器，所有数据都经过后端中转。被控端每隔一秒截取一次屏幕画面，把图像用 JPEG 格式压缩后通过 WebSocket 发送给后端，后端转发给正在控制这台电脑的操作人员浏览器显示。被控端 ID 未注册返回 401，被控端已被其他控制端连接返回 409。操作人员在浏览器上看到远程桌面画面后可以发送鼠标点击、鼠标双击、鼠标移动、键盘按键和组合键（比如 Ctrl+C）等操作指令，后端转发给被控端执行。不支持的操作类型返回 400。除了远程控制外还支持文件传输功能：操作人员可以上传本地文件到被控端的指定目录，也可以从被控端下载文件到本地。文件传输走单独的 WebSocket 连接通道，不占用屏幕画面传输的带宽。后端要记录每次远程控制会话的完整操作日志，包括开始时间、结束时间、操作人员身份、被控端标识和所有操作指令的时间序列，支持导出为文本格式的审计日志。被控端和控制端之间的所有通信都经过后端中转，后端不存储传输的屏幕画面数据。

屏幕截图即使压缩后数据量也很大，后端要做帧率自适应控制，当网络质量差或服务器负载高时自动降低帧率（从每秒一帧降到每三秒一帧），不能因为一帧传输卡住就阻塞后面所有帧的发送。鼠标和键盘操作指令的传输延迟要尽可能低，键盘输入指令必须按顺序转发给被控端，不能因为网络优化把按键顺序打乱。被控端断线后后端要在三秒内检测到并通知控制端结束会话，不能让操作人员对着旧画面继续操作。文件传输过程中如果 WebSocket 断开，已传输的部分要保留在目标目录，重连后支持断点续传而不是从头开始。一台被控端同一时间只能被一个控制端控制，已有控制端连接时新连接返回 409。

服务端端口通过命令行参数或环境变量指定。
