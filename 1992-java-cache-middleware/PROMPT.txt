内部十几个服务各自管缓存，TTL 和淘汰策略五花八门，出了两次脏数据事故——一个服务 LRU 淘掉了还在用的 key，另一个服务 TTL 设太长读到过期数据。Spring Boot 2 做集中管理的单机内存缓存中间件，一个地方管所有缓存，策略统一。

缓存按 namespace 隔离，每个 namespace 独立配置 TTL、最大容量、淘汰策略（LRU 或 LFU）。key 不能重复，value 最大 1MB。容量满了按策略淘汰，过期 key 惰性删除——查询时顺带清掉，不专门跑清理线程。手动清除某个 namespace 或某个 key 的接口也提供。

批量操作一次写多个 key-value，要么全成功要么全失败，碰到 key 已存在或者 value 超限就整批回滚。缓存命中率按 namespace 分别统计，接口返回命中数、未命中数、淘汰数、当前容量。

客户端可以订阅 namespace 的 key 变更通知，注册时提供回调 URL，变更内容 POST 过去。回调失败重试 2 次，连续 3 次都失败的暂停该客户端通知 5 分钟，5 分钟后自动恢复尝试。

namespace 级别的配置（TTL、容量、策略）可以动态修改，修改后新写入按新规则，已有的 key 不受影响直到下次访问。Maven 构建，端口配置文件指定。
