新接了个项目，客户要求代码审查流程能多人实时协作看到彼此的评论。之前一直在用 GitHub PR Review 但客户想在自己的内网跑。Go 后端，审查者之间通过 WebSocket 实时推送评论。

开发者提交代码审查请求包含 diff 和描述，参数不完整返回 400。审查者逐行查看变更添加评论（行内批注或整体评论）。多个审查者同时看同一请求时新评论实时推送。审查请求不存在返回 404。审查者对代码行标记通过、需要修改或有疑问。开发者收到评论后可回复或修改代码重新提交新版本更新请求。

审查流程状态机：待审查、审查中、需要修改、已通过、已关闭。不能从待审查直接跳到已通过返回 400，已关闭不能改返回 409。后端维护完整状态转换历史。管理平台统计每个开发者平均审查等待时间、评论总数和通过率。审查请求超四十八小时没人处理自动升级通知团队负责人。

行号修改后会变，行内评论要按上下文内容匹配不是固定行号。评论要附带代码快照版本号，代码已改则标注基于旧版本。最终通过只有主审能设，非主审设通过返回 403。多审查者同时提交评论时推送互斥。

服务端端口通过命令行参数或环境变量指定。
