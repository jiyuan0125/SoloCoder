Rust axum 的 tower middleware 层做限流正合适，试一下。多策略限流器服务——三种算法混着来，按路径配。

固定窗口按分钟计数，简单粗暴。滑动窗口按秒级精度统计最近 60 秒，比固定窗口准但占内存。令牌桶有容量和填充速率，适合允许突发流量的场景。每条规则绑定一个资源路径，独立选算法和参数。同一路径可配多条规则，全部通过才放行。触发限流返回 429，响应头带上 X-RateLimit-Remaining 和 Retry-After。

统计每个路径的请求总数、被限流数、最近一次限流时间。同一个客户端 IP 在多个路径同时被限流也要能查——IP 粒度的聚合查询接口，返回该 IP 所有受限路径的状态。规则支持动态增删改，修改时已有计数不重置——别一改规则就把统计清零。删除后该路径不再限流，统计保留到内存回收。

限流规则配置包括：算法类型、路径模式（精确或前缀）、阈值参数、是否区分客户端 IP。不区分 IP 的是全局限流，区分 IP 的按 IP 独立计数。内存存不下的时候按 LRU 淘汰最早的计数器。

限流判断顺序按规则添加顺序执行，先匹配到的先算。路径模式用前缀匹配时，更长的前缀优先——/api/v2/ 比 /api/ 先匹配。删除规则后立即生效，后续请求不再经过该规则。Cargo build，PORT 环境变量。
