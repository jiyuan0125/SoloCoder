帮我用 C 写一个防刷保护的服务端模块。场景是：公司有一个公开的用户注册入口，被恶意爬虫频繁调用——爬虫每秒发送几十个注册请求，试图批量注册垃圾账号。需要在服务端做多层限流保护。限制规则：根据客户端的 IP 地址来限流。每个 IP 每分钟最多允许30次请求，每小时最多200次，每天最多1000次。三个维度的限制同时生效——任何一个维度超限都拒绝该 IP 的后续请求。被拒绝时返回 HTTP 状态码 429，并在响应头里带上信息告诉客户端是哪个维度超限了（minute/hour/day）以及大约还要等多久才能恢复。支持配置白名单——白名单里的 IP 地址不受任何限制（用于内网测试环境等）。支持管理员在运行时动态调整每个维度的限制阈值，不用重启服务就能生效。多线程环境下（多个请求处理线程同时检查和更新计数）限流计数必须准确。要记录每个 IP 的请求总次数和被拒绝次数，方便分析哪些 IP 是恶意的。内存使用要可控——不能为每个访问过的 IP 都永久保存计数数据。用纯 C 写，gcc 编译通过，不依赖第三方库。限流计数数据要定期清理——如果一个 IP 超过24小时没有再次访问，它的计数数据可以释放来节省内存。
代码拆成至少 4 个源文件：多维限流计数、白名单管理、计数清理与统计、主程序，各自有头文件和实现文件。gcc 编译能过。

服务端的监听端口应该支持通过命令行参数或环境变量来指定，不要硬编码。
