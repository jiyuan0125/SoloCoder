我们公司内部有几十个微服务，每个服务对外暴露的请求路径不一样，有 REST 风格的也有自定义格式的。现在要做一个统一的请求入口，收到请求后根据路径前缀和方法转发到对应的后端服务。比如 /api/user/* 转到用户服务，/api/order/* 转到订单服务，/api/order/{id}/detail 这种带路径参数的也要能正确匹配到目标。有时候两个服务的路径前缀会冲突，比如 /api/v1/user 和 /api/v2/user，这时候要按最长前缀匹配，请求 /api/v2/user/123 应该匹配到 v2 的服务。如果请求的路径没有任何服务匹配，返回 404 和一段 JSON 错误信息说明找不到对应的服务。每个后端服务可能有不同的超时时间，这个要能针对每个路径单独配置。还有个需求是有些路径需要校验请求头里有没有带 token，有些不需要，这个也要能按路径配置白名单。转发的时候要把客户端的原始 IP 放到 X-Forwarded-For 头里传给后端。帮我用 Go 实现这个请求分发服务，不用第三方框架，用标准库的 HTTP 包。路由匹配要支持通配符路径，比如 /api/files/* 可以匹配 /api/files/a/b/c 任意深度的子路径。后端服务的地址和端口可以通过配置文件修改，修改后热加载生效。

代码按功能模块分文件组织——路径前缀匹配、通配符路由解析、请求转发处理、配置管理各自独立文件。go build 能过。
