最近在搞这块业务，需要一个文件监控系统，Go 标准库 实现。
用 Gin 写一个文件变更监听 API
用户指定要监听的目录，当目录下的文件发生创建、修改、删除或重命名时，触发回调通知
每个操作有独立的接口路径：列表查询、详情查看、子项列表、子项操作。
支持监听子目录递归
短时间内一个文件可能被频繁修改（比如日志文件每秒都在追加），不能每改一个字节就触发一次通知，要有合理的聚合策略
系统同时管理主实体和明细记录。明细的每次变动都关联到对应的主实体。
被监听的文件可能被删除然后又重建
目录权限可能导致某些子目录无法访问
监听服务本身不能因为目标目录被删除或磁盘满而崩溃
流程按申请→初审→复审→批准→完成推进。每步有对应负责人。
支持通过 API 查看当前监听状态和最近的事件历史
数据存 SQLite，服务端口 8080。
