现在这块效率太低了，想做一个发布流程系统，Go 标准库。
用 Gin 写一个软件发布流程管理 API
发布单状态：开发中→提测→测试中→待发布→灰度中→全量发布→已完成
状态从新建→处理中→待确认→已完成变更。每步完成后进入下一步。
提测前代码冻结，不允许新的 commit 合入
测试中发现 bug 打回开发，修复后重新提测。测试通过后进入待发布状态
灰度发布可以选择灰度比例（1%、5%、10%、50%），灰度期间发现问题可以回滚
API 按层级设计：查看列表、查看单个详情、单个下的子资源列表、修改子资源。
回滚回到上一个已完成的发布版本。灰度指标正常后全量发布
全量发布后观察 24 小时，无问题则标记为已完成
数据存 SQLite，服务端口 8080。
