我们最近需要一套用户资料系统，用 Go 标准库做。

用户可以编辑自己的个人资料，包括昵称、个人简介、联系方式和自定义头像。每个用户有唯一的用户 ID，通过 URL 路径参数访问用户资料页（/profile/{id}），查询不存在的用户 ID 返回 404。用户可以查看其他用户的公开资料，但不能编辑别人的资料，越权编辑返回 403。昵称不能为空且不能超过 30 个字符，超限返回 400。个人简介上限 500 字。

资料修改历史保留，可以查看某个用户的所有修改记录，历史记录不可修改不可删除。管理员可以查看所有用户的资料和修改历史，普通用户只能看自己。支持批量查询多个用户的资料（传入一组用户 ID），ID 列表中有不存在的 ID 时，返回存在的用户资料并在响应中标注哪些 ID 未找到。

用户可以通过邮箱或手机号搜索其他用户，搜索格式不对返回 400，搜无结果返回空列表。操作完成后自动更新关联的统计汇总，统计更新时重新读取同一批数据核对总数。数据存 SQLite，服务端口 8080。
