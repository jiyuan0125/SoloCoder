我们公司的后端服务越来越多，目前已经有二十几个了，每个服务都需要一些公共的处理逻辑：请求日志记录（记录请求路径、耗时、状态码）、统一的错误响应格式（JSON 包含 code、message、data 三个字段）、跨域处理（允许前端域名访问）、请求耗时统计、请求 ID 自动生成。现在这些逻辑在每个服务里都写了一遍，代码大量重复，而且每个服务实现得还不一样——有的日志格式是这样有的那样，有的错误码定义不统一。帮我用 Go 写一套公共的请求处理组件，能像链条一样把多个处理步骤串起来。请求进来先经过日志记录，再经过跨域处理，再经过耗时统计，最后才到业务逻辑代码。每个处理步骤要能独立开关，有些服务需要日志但不需要跨域，有些全都需要，有些只要其中两三个。请求 ID 要自动生成（格式如 req-20260503120530-a3f8b2）并放到响应头 X-Request-ID 里返回给前端，这样前端遇到问题可以根据这个 ID 去后端查日志定位。耗时统计要区分不同的处理阶段分别记录时间，比如解析参数花了多少毫秒、业务逻辑花了多少毫秒。如果某个步骤出错了，后面的步骤还要不要继续要能配置。组件要提供简洁的 API 让业务代码能方便地使用。每个处理步骤都能读取到请求上下文信息（比如请求 ID、开始时间），方便在后续步骤中使用。处理步骤之间要能通过上下文传递自定义数据。

代码按功能模块分文件组织——请求日志记录、统一错误响应、跨域处理、耗时统计与请求 ID 各自独立文件。go build 能过。
