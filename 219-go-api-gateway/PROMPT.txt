我们公司有几十个后端服务分散在不同服务器上，前端直接调用这些服务有跨域问题，而且每个服务的身份验证方式不一样（有的用 token 有的用签名），前端要记住每个服务怎么调用太麻烦了。需要做一个统一的入口服务，前端只跟这个入口打交道。入口服务要做几件事：根据请求路径把请求转发到对应的后端服务；所有请求都要先统一验证用户身份 token；记录每个请求的调用日志（谁、什么时候、调了哪个后端、花了多长时间、结果如何）；如果某个后端服务响应太慢就自动切断请求，不要拖慢整个入口服务；支持动态配置转发规则，不用重启服务就能新增后端或修改转发路径。每个后端服务的地址、超时时间、是否需要身份验证都可以在配置文件里单独设置。如果前端请求的路径没有匹配到任何后端服务，要返回友好的 JSON 错误信息而不是一个空白的 500 页面。还要支持批量请求——前端一次请求里可以指定多个后端操作，入口服务并行调用所有后端然后把结果合并成一个 JSON 返回，总耗时取决于最慢的那个后端。帮我用 Go 实现这个入口服务。入口服务本身的健康状态要能查询，包括当前的请求数、每个后端服务的响应时间统计。配置文件的格式用 YAML，修改后自动热加载。所有请求和响应的日志要写入本地文件，按天切割保留最近 7 天。

代码按功能模块分文件组织——统一入口鉴权、后端路由与转发、批量请求聚合、配置热加载与日志各自独立文件。go build 能过。
