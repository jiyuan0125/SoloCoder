现在这块效率太低了，想做一个香料调配系统，Go 标准库。
用 Go 标准库写一个调料配方管理 API
每个配方由多种原料组成，每种原料有名称、重量（克）和单价（元/千克）
每个操作有独立的接口路径：列表查询、详情查看、子项列表、子项操作。
配方的总成本是所有原料的重量 × 单价之和
原料重量以 0.1 克为最小单位，不能出现 0.05 克这种精度
同一个配方的原料总量不能超过 1000 克
系统同时管理主实体和明细记录。明细的每次变动都关联到对应的主实体。
修改配方时保留历史版本，查看时默认显示最新版但可指定版本号
两个配方如果原料种类完全相同（不计重量）视为同类，同类配方不能超过 5 个
配方可以导出为 JSON 格式
流程按申请→初审→复审→批准→完成推进。每步有对应负责人。
HTTP API
数据存 SQLite，服务端口 8080。
