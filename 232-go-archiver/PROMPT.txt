我们公司每次发布新版本都要把编译好的程序文件和配置文件、前端静态资源、API 文档等打包成一个压缩包上传到文件服务器供运维部署。不同项目的打包规则不一样：有的项目需要排除某些目录（比如测试数据 fixtures/、源代码 src/，只保留编译产物）；有的需要在打包前执行预处理步骤（比如压缩图片、合并 CSS 文件、给 JavaScript 文件加 hash 后缀）；有的需要在压缩包里生成一个版本信息文件 version.json，内容包含构建时间、Git 提交哈希（短格式 8 位）、构建人的用户名、目标环境（dev/test/prod）。需要支持多种压缩格式：zip（Windows 兼容）、tar.gz（Linux 常用）、tar.xz（压缩率更高但速度慢）。打包过程中如果某个文件被占用（进程正在使用）或者权限不够读不了，不能让整个打包过程失败，要把这个文件记录到跳过列表里继续处理其他文件。打包完成后要自动计算整个压缩包的 MD5 和 SHA256 校验值，写入一个同名的 .checksum 文件，接收方下载后可以验证文件是否完整。如果上一次打包的产物还在且内容没变化（通过比对校验值），就跳过不重新打包，节省时间。帮我用 Go 实现这个项目打包工具。

代码按功能模块分文件组织——文件扫描与过滤、预处理流水线、压缩打包、校验值计算与缓存各自独立文件。go build 能过。
