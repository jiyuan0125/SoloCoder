我们团队要用 Go 开发好几个后端微服务，每个服务都需要处理 HTTP 请求、解析请求参数、返回 JSON 响应、统一错误处理这些基础工作。现在每个服务都是用标准库从头写的，重复代码很多。想写一个轻量的 HTTP 服务框架，把常用的模式封装起来减少重复劳动。具体需要这些能力：定义路由时能指定 HTTP 方法（GET/POST/PUT/DELETE）和路径参数（比如 /users/:id），请求进来时能自动把路径参数、查询字符串参数、JSON 请求体解析并填充到 Go 结构体字段上；请求进来时要能按顺序执行一系列处理步骤（类似洋葱模型——先执行外层再执行内层再回到外层）；响应统一用 JSON 格式，结构为 {"code": 0, "message": "ok", "data": ...}，出错时 code 非零、message 描述错误、data 为 null；错误处理要统一，不同类型的错误（参数校验失败、资源不存在、权限不足、服务器内部错误）自动对应不同的 HTTP 状态码；路由能分组管理，比如 /api/v1 下的路由共用一组处理步骤（身份验证、日志记录等）。框架要轻量，不引入大型第三方依赖。路由匹配要快，这是每个请求必经的路径。帮我用 Go 实现这个框架。

代码按功能模块分文件组织——路由注册与参数匹配、中间件链式执行、统一响应格式、错误分类与处理各自独立文件。go build 能过。
