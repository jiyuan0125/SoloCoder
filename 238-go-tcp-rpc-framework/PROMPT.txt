我们公司有几组服务之间需要频繁通信，之前用 HTTP + JSON 的方式但觉得太慢了——每次请求都要建立连接、序列化 JSON、反序列化 JSON，延迟高而且 CPU 开销大。想用 TCP 长连接 + 自定义二进制协议来提高通信效率。需要设计一套通信协议：每个消息有固定的消息头（16 字节，包含消息类型 2 字节、消息体长度 4 字节、请求 ID 8 字节、序列号 2 字节），后面跟着消息体。消息体用自定义的二进制格式编码，要支持常见的数据类型：整数（int8/int16/int32/int64）、浮点数（float32/float64）、字符串（带长度前缀）、字节数组（带长度前缀）、嵌套的键值对结构。每个请求要有唯一的请求 ID（客户端生成），服务端处理完后在响应里带上对应的请求 ID，这样异步处理的时候才能把响应和请求配对起来。如果某个请求 10 秒内没有收到响应，客户端要超时取消并释放相关资源。TCP 连接断开了要自动重连，重连期间发送的请求要排队，连接恢复后按顺序发出。如果发送方发得太快而接收方处理不过来，要有背压机制——接收方来不及处理时要通知发送方减慢速度，不能无限制地往连接上写数据导致内存撑爆。帮我用 Go 实现这个通信框架。

代码按功能模块分文件组织——二进制消息编解码、TCP 连接管理与重连、请求超时与配对、背压控制各自独立文件。go build 能过。
