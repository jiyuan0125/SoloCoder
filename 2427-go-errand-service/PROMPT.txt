业务那边提了个需求，要一套跑腿系统，Go 标准库。
用 Go 标准库写一个跑腿服务的 HTTP API
各操作走不同的 URL 路径区分：列表、详情、关联列表、关联操作。
用户发布跑腿需求（取件、送件、代购），跑腿员可以接单
费用根据距离和类型计算。不同类型起步价不同
距离越远加收越多，但加收规则没有统一标准
系统同时管理主实体和明细记录。明细的每次变动都关联到对应的主实体。
接单后跑腿员需要在规定时间内完成
完成后用户确认并支付。跑腿员有评分系统，评分影响接单优先级
流程走草稿→审批→执行→确认→关闭。中间可以退回上一步。
连续三个差评暂停接单资格，暂停多久取决于累计差评数量
数据存 SQLite，服务端口 8080。
