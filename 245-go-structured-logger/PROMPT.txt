我们公司的后端服务需要记录运行日志，但现在的日志都是直接 fmt.Println 打印到标准输出，格式不统一、没有结构化信息，线上排查问题的时候要在几 GB 的日志里 grep 关键字非常痛苦。需要一套结构化的日志方案：每条日志包含固定字段——时间戳（精确到毫秒）、日志级别（DEBUG/INFO/WARN/ERROR 四级）、所在的 Go 文件名和行号、日志消息正文；以及可以附加任意数量的自定义键值对字段，比如记录一个 HTTP 请求日志时可以带上 request_id=abc123、user_id=456、path=/api/orders、duration=128ms 这些上下文信息。日志要同时输出到两个地方：终端（带 ANSI 颜色，不同级别用不同颜色方便开发时阅读）和文件（纯文本不带颜色，方便用 grep 等工具搜索）。日志文件要按天自动切割，每天一个文件，文件名包含日期如 app-2026-05-03.log。保留最近 7 天的日志文件，超过 7 天的自动删除。单个日志文件如果超过 100MB 也要切割，避免单个文件太大不好打开。在高并发场景下（每秒产生几千条日志），写日志不能成为性能瓶颈，不能阻塞业务逻辑的执行。如果磁盘满了日志写不进去，要有降级策略（比如丢弃 DEBUG 和 INFO 级别只保留 WARN 和 ERROR），不能因为写日志失败导致整个服务崩溃。对于 DEBUG 级别的日志还要支持采样——每秒最多只记录 100 条，避免调试时日志量爆炸。帮我用 Go 实现这个日志库。

代码按功能模块分文件组织——结构化日志格式化、多输出目标（终端与文件）、日志切割与轮转、磁盘满降级与采样各自独立文件。go build 能过。
