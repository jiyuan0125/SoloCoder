我们公司运营了一个内容网站，上面有几千篇文章和产品页面，但搜索引擎一直收录不全，运营那边很头疼。他们希望我们能自动生成一个站点地图文件，告诉搜索引擎我们有哪些页面可以抓取。具体需求是这样的：我们有一个 JSON 文件记录了所有页面的信息，每条记录包含页面的访问地址、最后修改时间、更新频率（每天/每周/每月）和重要程度（0到1之间的小数）。需要根据这个文件生成标准的站点地图 XML。有几个要注意的地方：第一，如果页面总数超过5万个，要自动拆分成多个文件，然后再生成一个索引文件把它们串起来。第二，页面地址要做标准化处理——去掉 # 号后面的锚点部分，统一做 URL 编码，确保都以斜杠开头。第三，数据里可能有重复的地址，要去重只保留修改时间最新的那条。第四，支持增量模式，只输出上次生成之后新增或修改过的页面，这样文件不会越来越大。还有一个容易忽略的点：有些页面的更新频率和重要程度字段可能缺失，缺失的话更新频率默认用“每周”，重要程度默认用 0.5。输出的时间统一用 UTC 时区的 ISO 8601 格式。最后生成的 XML 文件如果超过 50MB 也要继续拆分，不能一个文件太大。生成的 XML 要符合搜索引擎能识别的标准格式，用 gzip 压缩后放到网站的根目录下，同时在 robots.txt 里指向这个文件。

代码按功能模块分文件组织——页面地址标准化与去重、站点地图 XML 生成与拆分、增量变更追踪、索引文件生成各自独立文件。go build 能过。
