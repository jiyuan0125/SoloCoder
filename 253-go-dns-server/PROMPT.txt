公司内网部署了不少服务，像代码仓库、内部文档、CI 构建平台、测试环境这些，但 IP 地址经常变，大家记不住也懒得记。我们想做一个内网名字解析服务，同事们只需要把电脑的网络设置指向这个服务，然后访问 git.company.internal 这种好记的地址就能跳转到对应的服务，不用再去翻文档查 IP 了。功能方面：运维同学通过命令行动态添加、修改、删除域名记录，操作完立刻生效不用重启服务。支持给一个域名配置多个 IP 地址，这样查到这个域名的时候轮流返回不同的 IP，实现简单的负载均衡。比如 git.company.internal 指向三台服务器 10.0.1.10、10.0.1.11、10.0.1.12，第一次查返回 10.0.1.10，第二次查返回 10.0.1.11，依次轮询。所有的查询操作要记录日志，包括谁查的、查什么域名、返回了什么结果、花了多少时间，方便排查网络问题。域名记录要支持设置过期时间，过期的记录自动失效不再响应查询。如果查一个不存在的域名，要返回“找不到”的结果而不是静默丢弃。配置数据要持久化到文件，服务重启后能恢复之前的所有记录。隐藏的坑：同一个域名如果短时间内收到大量查询（比如每秒超过 100 次），可能是有问题，要能检测到这种情况并在日志里告警，但不影响正常查询。

代码按功能模块分文件组织——域名记录管理、查询路由与负载均衡、访问日志与告警、主程序入口各自独立文件。go build 能过。
