DBA 团队需要一个 SQL 审计工具，开发人员提交的 SQL 语句在执行前先过一遍这个工具的检查，看有没有危险的写法。不是真的去执行 SQL，只是解析和检查。需要支持的检查项：第一，识别出 SQL 语句的类型（查询、插入、更新、删除、建表等）。第二，检查查询语句里有没有“全表扫描”的写法——就是查询条件里没有用到任何索引相关的字段（工具不需要真的知道哪些字段有索引，只需要检查 WHERE 子句里有没有条件就行，没有任何 WHERE 条件的查询就标记为可疑）。第三，检查有没有 SELECT * 的写法，建议改成明确的字段列表。第四，检查 UPDATE 和 DELETE 语句有没有 WHERE 条件，没有的话直接标记为高危——因为这意味着会修改或删除所有行。第五，检查有没有嵌套太深的子查询（超过 3 层就警告）。第六，支持批量检查——输入一个 SQL 文件，逐条解析和检查，最后输出一份报告。第七，SQL 语句可能跨多行，注释也有多种写法（单行注释 --、多行注释 /* */），解析时要能正确处理。容易出问题的地方：有些 SQL 语句的语法比较复杂，比如 WITH 子句、窗口函数、CASE WHEN 表达式，工具不需要完全理解语义，但至少不能因为这些语法就解析失败。另外，字符串字面量里可能包含看起来像 SQL 关键字的文本（比如用户表里存了 SELECT * FROM users 这段文字），要正确识别这是字符串而不是 SQL 语法。

代码按功能模块分文件组织——SQL 词法与语法解析、安全规则检查、批量处理与报告生成各自独立文件。go build 能过。
