帮我用 Gin 框架写一个多格式条码生成服务。支持一维码（Code 39、Code 128、EAN-13、UPC-A、Interleaved 2 of 5）和二维码（QR Code、Data Matrix、PDF417）。
用户通过 API 指定条码类型和内容数据，系统生成条码图片返回（PNG 或 SVG 格式）。不同条码类型对输入数据有不同约束：EAN-13 必须是 13 位数字，Code 39 只支持大写字母和数字等。不合法的输入要返回明确的错误信息。
QR Code 支持设置纠错等级（L/M/Q/H）和版本号（自动选择或手动指定）。支持在 QR Code 中编码日文 Shift-JIS 字符和 UTF-8 内容。
条码生成的图片尺寸可配置，默认 PNG 为 300 DPI。批量生成时如果某个条码数据格式不对，跳过并记录错误，不影响其他条码。
条码校验位的自动计算：EAN-13 的第 13 位是校验位，用户输入 12 位时系统自动补全校验位。
条码历史记录：生成的条码信息保存在数据库中，用户可以查看之前生成过的条码。支持重复生成已保存的条码。
提供批量生成接口：上传 CSV 文件，每行一个条码内容和类型，返回打包的 ZIP 文件。同时提供条码校验功能：上传一张条码图片，尝试识别其内容和格式。用 Go 实现。

SVG 格式的条码要支持自定义尺寸和颜色。QR Code 的 SVG 输出可以设置模块大小（每个黑白方块的像素尺寸）和留白边距。
条码校验功能上传图片后先做图像预处理（去噪、旋转校正），然后用识别算法解码。图片模糊或条码损坏的返回识别失败而不是错误。
批量生成的 ZIP 文件内每个条码图片的命名规则：类型_内容前16字符_序号.png，方便后续整理。
