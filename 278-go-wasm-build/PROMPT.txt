我们的产品有一个在线表格功能，用户可以在浏览器里编辑几十万行的数据表格。目前纯用 JavaScript 处理的话，当数据量超过 10 万行时就会明显卡顿——排序、筛选、计算公式这些操作都要好几秒。方案是把计算密集的部分编译成浏览器可以直接运行的格式（WebAssembly），利用更接近硬件的执行效率来加速。需要一个工具链，能把我们的计算逻辑编译成这种格式，然后在网页里加载和调用。具体需求：第一，把数据处理的核心逻辑（排序、筛选、公式计算）封装成可以在浏览器里运行的模块。第二，这个模块要能接收网页传过来的表格数据（二维数组），执行计算后把结果返回给网页。第三，数据在网页和模块之间传递要高效——大量数据传递时不能做不必要的拷贝。第四，要能处理各种数据类型——数字、文本、日期、布尔值、空值。第五，公式计算要支持常用的函数（求和、平均值、最大最小值、计数、条件判断等）。第六，提供性能指标——每次操作的耗时，方便对比优化前后的效果。隐藏的坑：内存管理是关键——处理几十万行数据时内存占用会很大，需要及时释放不再使用的数据。另外，不同浏览器对这种运行格式的支持程度不一样，要能检测浏览器是否支持，不支持的话降级到纯 JavaScript 实现。

代码按功能模块分文件组织——数据类型转换、公式与计算函数、内存管理、性能指标采集各自独立文件。go build 能过。
