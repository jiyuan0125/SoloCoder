我们的配置管理系统里，每个服务有一份 JSON 格式的配置文件。运维同事经常需要修改配置——有时候是改一个字段，有时候是加一个字段，有时候是删除一个字段。如果每次都传完整的配置文件，一来数据量大，二来容易出现并发冲突（两个人同时修改，后保存的会把先保存的覆盖掉）。需要一个“局部修改”的能力：只传需要修改的部分，服务端自动合并到完整配置上。功能需求：第一，支持添加一个字段——指定路径和值，如果路径不存在就自动创建中间层级。比如配置里没有 database 这个 key，可以一次性添加 database.host 和 database.port。第二，支持修改一个字段的值——指定路径和新值。第三，支持删除一个字段——指定路径，删除对应字段及其子字段。第四，支持数组操作——在数组的指定位置插入元素、删除指定位置的元素、替换指定位置的元素。第五，支持条件修改——只有当某个字段的当前值符合预期时才执行修改（类似乐观锁）。比如“只有当版本号为 3 时才把最大连接数改成 100”，如果版本号已经不是 3 了说明有人改过了，修改应该失败。第六，修改操作要记录审计日志——谁在什么时间做了什么修改、修改前的值是什么、修改后的值是什么。第七，修改前要验证路径的合法性——不能修改某些敏感字段。隐藏的坑：JSON 里的路径表示法可能有歧义——如果某个字段的 key 本身就包含点号（比如 app.version 是一个完整的 key 而不是 app 下面的 version），路径解析要能正确处理。需要支持转义或者提供替代的路径表示方式。

代码按功能模块分文件组织——路径解析与定位、补丁操作执行、条件修改与乐观锁、审计日志各自独立文件。go build 能过。
