我们的表单系统允许用户分步骤填写信息——第一步填基本信息，第二步填详细设置，第三步填附加选项。每一步提交的数据都是一段 JSON，最终需要把所有步骤的数据合并成一份完整的记录。功能需求：第一，合并两段 JSON 数据——相同路径的字段，后提交的值覆盖先提交的值。第二，对于嵌套的对象，合并是递归的——只覆盖有变化的字段，没变化的保留原值。比如第一步提交了 {"name": "张三", "settings": {"theme": "dark", "language": "zh"}}，第二步提交了 {"settings": {"theme": "light"}}，合并后应该是 {"name": "张三", "settings": {"theme": "light", "language": "zh"}}。第三，对于数组类型的字段，合并策略可配置——可以选择覆盖（用新值替换整个数组）或合并（去重后拼接两个数组）。第四，支持多份 JSON 数据一次性合并——不只是两份，可以传入任意数量的 JSON 片段按顺序合并。第五，合并时要能检测冲突——如果两个数据片段对同一个字段设置了不同的值（且不是简单的覆盖关系），可以记录冲突信息供后续人工审核。第六，支持“深度合并”和“浅合并”两种模式——浅合并只处理顶层字段，深度合并递归处理所有嵌套层级。第七，合并结果要能序列化回标准的 JSON 格式，保持键的顺序和格式整洁。隐藏的坑：如果某个字段在一份 JSON 里是字符串，在另一份里是数字，类型不一致怎么合并？需要定义明确的规则——比如后提交的覆盖先提交的，但要在合并日志里记录类型变化。另外，空值 null 的处理也要小心——提交了一个空值是代表“删除这个字段”还是“把值设为空”，需要在合并策略里明确。

代码按功能模块分文件组织——深度合并逻辑、冲突检测与记录、类型一致性处理各自独立文件。go build 能过。
