财务部门每个月会收到供应商发来的 XML 格式的报表文件，有些文件非常大（几百 MB 甚至上 GB）。如果用普通的 XML 解析方式把整个文件加载到内存里，程序直接就崩了。需要一个能流式处理大 XML 文件的工具——边读边处理，不需要把整个文件都放内存里。功能需求：第一，能够定位到 XML 文件中的特定元素开始处理——比如只关心 Transaction 元素，就只处理这个标签的内容，忽略其他部分。第二，处理过程中可以提取元素的属性和子元素的文本内容。第三，支持嵌套元素——比如 Transaction 下面有 Amount、Date、Description 等子元素，要能正确提取所有层级的数据。第四，处理过程中如果遇到格式错误（标签不匹配、属性格式不对等），不能让整个处理中断，记录错误信息后跳过当前元素继续处理下一个。第五，处理进度要可查询——当前处理到文件的第几个字节、第几个元素、预计还需要多久。第六，支持从网络流直接读取（比如从 HTTP 响应体直接解析），不一定非要从文件读取。第七，提取的数据可以输出为结构化的格式，方便后续处理。隐藏的坑：XML 文件可能声明了不同的编码（UTF-8、GBK、ISO-8859-1 等），要根据声明正确解码。另外，有些 XML 文件开头可能有 BOM 标记，或者文件中间有大段的空白和注释，解析时要能跳过这些不影响内容的部分。

代码按功能模块分文件组织——XML 流式解析与元素定位、编码声明检测、错误容错与进度报告各自独立文件。go build 能过。
