| User Prompt | 运营团队需要一套优惠券的发放和核销体系。后台创建优惠券批次时要填好面额（比如满50减10）、使用门槛金额、发放总量、有效期的起止日期、每个用户限领几张。用户调接口领券的时候要做并发控制——同一个人同时点两次不能领出两份来，超出限领数量的请求要被拒绝。下单时调核销接口，系统自动校验这张券有没有过期、是不是已经被用掉了、领券的人对不对。 核销成功后要返回核销时间，方便用户和运营对账。运营侧还要能查到某个批次的发放进度（已发多少、已核销多少、剩余多少），以及某个用户手里目前有哪些可用的券。 有效期校验要精确到秒——到期日当天23:59:59之前都算有效。满减类型的优惠券，订单金额刚好等于门槛金额时也算满足条件。如果一张券的发放总量已经全部领完了，运营不能再修改这个批次的参数。用户主动退订某个批次发出去的券时，已核销的不能退回，只有未使用的才能回收重新发放。优惠券名称不能为空且同一批次内名称唯一，面额必须大于零。 所有优惠券批次、领券记录和核销记录在服务重启之后必须还能完整查到，数据不能丢。 数据用 SQLite 存，服务启动时如果库文件不存在就自动建库建表。代码分至少三层——数据库访问层、业务逻辑层、HTTP 接口层，各层代码独立文件。先 go mod init 再开发，go build 能编译通过，能运行。 |
