| User Prompt | 电商退换货流程需要一个独立的后端服务。用户发起退货申请时要选择原因（质量问题、尺寸不合适、不想要了等），选择"质量问题"或"商品破损"时系统要求上传凭证照片（图片用base64放在请求体里）。换货申请要额外选择想换的新SKU和规格。 管理员审核通过后，退货的自动生成一个退款单号并记录退款金额，换货的创建一个新的发货单。退款金额按订单实际支付金额算，不能超过原单金额。换货如果新SKU价格跟原来的不一样，差价多退少补。用户端能查到退换货申请的当前状态（待审核、已同意、已拒绝、处理中、已完成）。 退货原因选择"不想要了"或"拍错"时，运费由买家承担；选择"质量问题""商品破损""与描述不符"时运费由平台承担，退款金额要加上运费。换货的差价如果新SKU便宜就退差额给用户，新SKU贵就用户补差价后再发货。凭证图片存储只存base64字符串，不做图片格式校验和尺寸限制。一个订单如果已经完成退货退款就不能再次提交申请。 所有退换货申请、凭证和退款记录在服务重启后不能丢失。 拆成服务端和客户端两个独立程序。服务端监听HTTP端口，处理退换货申请的提交、审核和退款流程，所有业务数据存在内存中。客户端是命令行工具，用户用它发起退换货和查看进度，管理员用它审核和处理退款。两个程序各自有独立的main包，共享的请求响应协议放在公共包里。各程序内部按职责分文件。先 go mod init 再开发，go build ./... 能编译通过。 |
