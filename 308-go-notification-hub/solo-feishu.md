| User Prompt | 系统需要一个多渠道通知中心。管理员创建通知时填写标题和内容，选择发送渠道（站内信、邮件、短信），选择目标用户——可以指定具体用户列表也可以选择发送给全部用户。创建后系统立即开始发送并记录每个渠道每条通知的送达状态。 群发全体用户时如果某个渠道出了问题（比如邮件服务挂了），不能影响其他渠道继续发送——站内信和短信该发还是要发。站内信因为不走外部服务直接标记为已送达，邮件和短信先标记为发送中，后续可以通过回调更新为已送达或发送失败。用户端能查到自己的通知列表并按已读未读筛选，标记某条通知为已读。管理员能查到某条群发通知在各渠道的成功数和失败数统计。 通知标题不能为空且不超过50个字符。发送给全部用户时系统要记录实际发送的总人数。如果管理员同时指定了具体用户列表又选了全部用户，以全部用户为准。已读标记只对站内信生效，邮件和短信渠道不跟踪已读状态。同一条通知对同一个用户只发送一次，不会因为重试而产生重复。 通知内容和所有送达状态记录在服务重启后不能丢。用 Go 标准库 net/http，邮件和短信渠道用打印日志模拟。 拆成服务端和客户端两个独立程序。服务端监听HTTP端口，负责通知的创建、分发和送达状态管理，数据存在内存中，多渠道发送互不阻塞。客户端是命令行工具，管理员用它创建通知和查看统计，用户用它查看通知列表和标记已读。两个程序各自有独立的main包，共享的消息格式放在公共包里。各程序内部按职责分文件。先 go mod init 再开发，go build ./... 能编译通过。 |
