| User Prompt | 产品侧要做一个用户反馈收集入口。用户提交反馈时选择类型（功能建议、Bug报告、体验投诉），给整体体验打1到5星评分，写一段详细描述。管理员登录后可以查看反馈列表，按类型和状态筛选，给某条反馈加内部备注（用户看不到），把处理状态从"待处理"改为"处理中"或"已关闭"。 评分字段要严格校验——前端可能传过来字符串"5"或者超出范围的数字"7"，后端都要拦住。评价文字不能超过500个字符。反馈列表一次不能返回太多，需要分页。管理员还需要能看到统计概览——各类型反馈各有多少条、平均评分是多少。 反馈提交时要记录提交者的用户标识，同一个用户一天内最多提交5条反馈，超出则拒绝。Bug报告类型的反馈管理员关闭时必须填写处理说明，不能空着就关。反馈描述中如果包含联系方式（手机号、邮箱），系统不做脱敏直接原样存储，但管理员端展示时可以按需过滤。分页参数需要做边界处理，页码不能为负数或零。反馈类型只能从预设的三种中选择，不允许自定义类型。管理员加的内部备注不超过500字。 所有反馈数据、备注和处理状态在服务重启后不能丢失。 拆成服务端和客户端两个独立程序。服务端监听HTTP端口，处理反馈的提交、审核和统计查询，数据存在内存中。客户端是命令行工具，用户用它提交反馈，管理员用它查看列表、加备注和关闭反馈。两个程序各自有独立的main包，共享的请求响应协议放在公共包里。各程序内部按职责分文件。先 go mod init 再开发，go build ./... 能编译通过。 |
