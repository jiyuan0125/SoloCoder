| User Prompt | 医院床位管理系统。每个科室下面有多个病区，每个病区有不同类型的床位——单人间、双人间、三人间，另外还有走廊加床（数量有上限但不受固定床位数约束）。患者入院时可以表达床位类型偏好，系统优先分配偏好类型，如果没有空余就降级分配（要单人间没有就给双人间）。 出院时床位立刻释放回可用状态。加床虽然灵活但每个病区最多只能加比如5张加床，不能无限加。工作人员能查到某科室当前各类型床位的可用数量、某患者当前住哪个床位。 分配降级时要记录实际分配的类型和原因，方便患者家属了解情况。患者转科时要先在原科室办理出院释放床位，再到新科室办理入院重新分配。加床编号用"科室-病区-加-X"格式区分，比如"内科-一区-加-1"。每个科室的床位布局（各类型数量、加床上限）由管理员配置，可以随时调整。患者办理入院时如果所有类型（包括加床）都没空余，放入候床队列按先来后到排序。科室和病区名称不能为空且不超过20个字符。 所有床位和患者数据在服务重启后不能丢失。 拆成服务端和客户端两个独立程序。服务端监听HTTP端口，处理床位分配、释放和候床队列管理，数据存在内存中。客户端是命令行工具，工作人员用它办理入院出院和查看床位状态，管理员用它配置科室床位布局。两个程序各自有独立的main包，共享的协议定义放在公共包里。各程序内部按职责分文件。先 go mod init 再开发，go build ./... 能编译通过。 |
