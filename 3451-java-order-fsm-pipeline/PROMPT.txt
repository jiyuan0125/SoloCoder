我们最近需要一套订单状态机，用Spring Boot做。
订单状态流转：创建→支付→发货→签收→完成，任何环节都可以取消。
支付超时30分钟自动取消订单。
订单状态机走创建→审核→执行→完成的流程，创建不通过退回修改后重新创建。
发货后7天未签收自动确认收货。
取消订单触发库存回滚和退款。
退款走独立的退款流程：申请→审核→打款。
创建成功后自动创建对应的关联单据，金额按比例算。
整个流程涉及订单模块、库存模块、支付模块、退款模块。
每个模块独立设计，通过事件驱动联动。用 H2 数据库。
需要维护客户的信息，订单录入时选择对应的客户。
记录编号唯一，重复提交返回409。操作的目标记录不存在时返回404。不能跳步，比如不能从创建直接到完成，非法跳转返回400和当前状态。多人同时操作同一资源时只有一个能成功，其余返回409。已完成的子记录不受影响，只更新未完成的。
项目能正常跑起来就行。
