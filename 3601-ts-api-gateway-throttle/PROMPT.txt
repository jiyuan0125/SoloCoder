技术组那边提了个需求，要一套API网关限流服务，用 Express + TypeScript。
支持按用户ID、IP地址、接口路径三个维度配置不同的请求频率上限。比如某个接口对普通用户限制每分钟60次，对VIP用户每分钟200次。同一个接口路径可以同时配置用户ID和IP两个维度的限流，请求需要两个维度都通过才能放行，任一维度超限就返回429。
超出限制返回429状态码，同时在响应头里告诉客户端还剩多少配额和触发限流的具体维度。配置的频率上限为0或负数时返回400。
限流规则通过配置文件管理，运行期间可以通过接口动态更新。每个维度的限流数据用内存存储。删除限流规则时传不存在的规则ID返回404。
限流规则变更后正在处理中的请求还是按旧规则判断，新进来的请求用新规则。旧的限流规则自动保存到历史记录里，历史记录查询支持按时间范围筛选，结果为空返回空数组不是404。
请求被限流的时候记录一条日志，包含被限流的维度信息和当前QPS。提供查询接口看最近一小时的限流事件统计。
SQLite 存数据，能正常编译启动就行。
