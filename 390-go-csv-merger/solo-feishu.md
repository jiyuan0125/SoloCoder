| User Prompt | 写一个 Go 命令行工具合并多个CSV文件。运营每个月导出一份销售数据CSV，年底需要把12个月的文件合并成一份年度汇总。 用法：./csv-merger -o yearly.csv jan.csv feb.csv mar.csv。所有CSV文件列结构必须相同（第一行表头），合并只保留一个表头。加 --dedup 参数按指定列去重（后出现的记录覆盖先出现的）。加 --sort 参数指定排序列和升降序。不同文件的编码可能不同（UTF-8、GBK）要自动检测并统一转为UTF-8输出。CSV中的数字列排序时按数值排而不是字符串排（100排在20后面）。去重时如果指定了多列作为去重依据则多列值完全相同的才视为重复。输入文件中有一个的列和其他文件不一致时报错并列出差异的具体列名。合并后的文件保持UTF-8编码不带BOM。加 --header 参数可以指定自定义表头替换原始表头。某个输入文件为空（只有表头没有数据行）时跳过不影响合并结果。所有输入文件都不存在时报错退出。合并后输出文件的换行符统一为\n不保留原始文件中的\r\n。 拆成两个独立程序：一个是后台常驻的服务进程，负责CSV文件读取、合并处理和编码转换；另一个是命令行客户端，用户通过它指定输入输出文件和去重排序参数。两个程序各自独立 main 包，通过 TCP 通信，共享协议定义放公共包。各程序内部按职责分文件。先 go mod init 再开发，go build ./... 能编译通过。 |

| 不满意原因 | 产物不满意：encoding.go 的 isGBK() 用字节范围判断编码，UTF-8 编码的中文字符（如"你好" = E4 BD A0 E5 A5 BD）恰好落在 GBK 有效字节范围内，导致 UTF-8 文件被错误当作 GBK 转换，中文变成乱码。实测合并 UTF-8 编码的 CSV 文件，"你好世界"变成了"浣犲ソ涓栫晫"。PROMPT 明确要求"不同文件的编码可能不同（UTF-8、GBK）要自动检测并统一转为UTF-8输出"，编码检测是核心功能。client/main.go 错误分支调了两次 cli.Parse()，第二次调用会重新解析 flag 导致 panic。使用了 Go 1.16+ 已 deprecated 的 ioutil 包。 |
