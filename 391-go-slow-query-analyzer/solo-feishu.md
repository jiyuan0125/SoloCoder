| User Prompt | 写一个 Go 命令行工具分析数据库慢查询日志。每行一条记录包含SQL语句、执行时间（毫秒）、扫描行数、锁等待时间。 功能：统计每条SQL模板（去除具体参数值后的SQL）的出现次数和平均执行时间，按平均执行时间或总执行时间排序。输出表格形式——排名、SQL模板、出现次数、平均执行时间、最大执行时间、总执行时间。SQL模板化时正确处理字符串参数——WHERE id=123和WHERE id=456归为同一个模板WHERE id=?，但不能误把表名或列名中的数字替换掉。IN子句中的多个值归并为单个占位符——IN (1,2,3)变为IN (?)。日志文件可能很大要逐行处理不能全部读入内存。加 --top 参数限制输出前N条默认20条。加 --min-time 参数过滤执行时间低于阈值的SQL。日志格式可以自定义通过 --format 参数指定字段分隔符和列顺序。无法解析的日志行记录警告并跳过不中断分析。统计时同时计算扫描行数的平均值，帮助判断慢查询是否因为全表扫描导致。 拆成两个独立程序：一个是后台常驻的服务进程，负责日志文件的逐行解析、SQL模板化和统计聚合；另一个是命令行客户端，用户通过它指定日志文件路径和查看分析结果。两个程序各自独立 main 包，通过 TCP 通信，共享协议定义放公共包。各程序内部按职责分文件。先 go mod init 再开发，go build ./... 能编译通过。 |
