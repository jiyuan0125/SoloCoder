流量翻了一倍，轮询已经不够用了——有些机器配置好应该多扛一些，有些节点暂时想隔离但不想注销。更头疼的是新加的节点上来就被打满，应该有个预热过程。Spring Boot 搞一个加权轮询负载均衡器，把节点生命周期和流量控制做得细一点。

1. 加权轮询：每个后端设权重（1-100），请求按权重比例分配。权重为 0 时不分配流量但保留注册信息，运行时通过 PUT `/backends/{id}/weight` 动态调整，立即生效。
2. 节点生命周期：状态流转为 新建→活跃→疑似故障→已摘除。新建节点先过一次健康检查才升级为活跃；活跃节点连续 3 次检查失败变疑似故障，疑似故障连续 3 次检查通过才恢复；已摘除的必须重新注册。每次健康检查都记日志，包含响应时间和检查结果。
3. 慢启动：新建节点升级为活跃后，5 分钟内权重从 0 线性增长到配置值，时间可按节点配。防止新节点一上来就吃满。
4. 查询与统计：GET `/backends` 返回所有节点实时状态、权重、活跃连接数。GET `/stats` 返回全局 QPS、平均响应时间和每个节点的请求计数。

健康检查定时自动跑，和负载分配逻辑分开。Maven 构建，`server.port` 配端口。节点状态变更触发回调通知，回调 URL 在注册时指定。
