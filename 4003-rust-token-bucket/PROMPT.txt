上周爬虫一夜刷了 200 万次 API，后端差点被打挂。限流必须安排上——Rust + actix-web 写令牌桶限流器，每个客户端 IP 独立一个桶，桶容量和填充速率通过 POST `/config` 接口配置，配置变更立刻生效。

核心机制——令牌按速率往桶里加，请求来了扣一个令牌。桶空了就拒绝，返回 429 状态码，响应头带 `Retry-After` 告诉客户端多久后重试。每个桶的容量（burst）和每秒填充速率（rate）独立配，没配过的 IP 用全局默认值。桶的数据全放内存，重启清零。

再叠一层 API Key 维度限流——同一个 Key 下的所有请求共享一个桶。检查顺序：先验 Key 是否合法（不合法返回 401），再检查 Key 维度限流，最后检查 IP 维度。两层都通过才放行。如果某个 IP 的所有桶（含不同 Key）都空了，给这个 IP 加全局冷却时间，冷却期间直接 429 不再逐桶判断。

查询接口 GET `/status` 返回所有活跃桶状态——剩余令牌数、最后填充时间、当前填充速率。GET `/cooldowns` 返回冷却中的 IP 列表和剩余冷却时间。桶超过 1 小时没活动自动回收内存。监听端口读 `PORT` 环境变量，`Cargo build` 通过就行。
