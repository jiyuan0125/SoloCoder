十几个微服务直接暴露在前端面前，这谁敢上线？路由、认证、聚合全缺。Go Gin 搭一个 API 网关，能不能把入口收口到一处？

路由表支持三种匹配——精确匹配（`/api/users`）、前缀匹配（`/api/orders/*`）、正则匹配（`/api/v[0-9]+/.*`），优先级精确>前缀>正则。路由通过接口增删改，热更新不重启。每个路由绑定一种认证策略：免认证、API Key 校验（Header 带 `X-API-Key`，内存里存白名单）或 JWT 校验（HS256 签名，密钥可配）。验证失败统一返回 401，Body 里的 reason 字段说明是 key 无效、签名错误还是 token 过期。

请求聚合入口 `POST /api/aggregate`，Body 里指定要调的后端服务列表和各自的路径参数。网关收到后并行调用多个后端，用 context 控制总超时（默认 10 秒），结果合并成一个 JSON 返回。某个后端超时或报错，对应字段填 null 加上 error 信息，不影响其他后端结果。

后端不可用时网关返回 502 并记录错误详情。所有请求经过网关时记访问日志：路径、认证结果、后端响应状态、耗时。代码按路由、认证、聚合、配置四个职责拆文件。`go build` 能编译通过，`PORT` 环境变量读监听端口。
