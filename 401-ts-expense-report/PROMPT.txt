团队报销一直靠纸质单据走审批，效率低还经常丢单据。做一个报销管理API服务，员工提交报销时填写日期、金额（精确到分）、费用类别（交通/餐饮/住宿/办公/其他）、事由和凭证文件名。提交后进入待审批状态，流转路径是待审批→已批准→已打款→已驳回。管理员可以批量审批多条待审批报销单，但批量中如果有一笔超过5000元的大额单，该笔自动跳过不参与批量操作必须单独走二级审批。单笔金额超过5000元不能直接批准，要先由部门经理审批再由财务总监审批才算完成。同一笔报销如果在二级审批过程中被部门经理驳回，审批流程直接回到待审批状态重新来，不保留中间意见。被驳回的报销修改后重新提交时审批记录全部清零重头开始。餐饮类报销单笔上限800元，住宿类每晚上限500元，超出部分自动标记需要补充说明否则直接驳回。查询支持按时间范围和状态筛选。金额计算全部以分为单位用整数运算，禁止浮点数参与金额计算。操作记录要可追溯，管理员能查看谁在什么时间做了什么操作。敏感操作（比如删除数据、修改金额）要单独记录审计日志，不能被普通用户删除或修改。所有函数的参数和返回值必须有明确的类型注解，不能用 any。
做成 TypeScript monorepo 项目。packages/shared 放公共的类型定义、API 请求响应的接口、消息格式和错误码。packages/server 用 Node.js 原生 http 模块监听端口提供 HTTP 接口（不使用 Express），处理所有业务请求，数据保存在内存中。packages/cli 是命令行工具，通过子命令和参数向服务端发请求，结果格式化输出到终端。根目录 package.json 用 workspaces 管理三个包，统一的 tsconfig.json 开启严格模式。各包内部按职责分文件。TypeScript strict 模式，禁止使用 any 和 @ts-ignore。npm install && npm run build 能编译通过。
