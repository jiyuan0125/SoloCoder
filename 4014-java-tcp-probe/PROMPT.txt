线上有 TCP 服务也有 HTTP 服务，健康检查策略不一样。用 Java Netty 做一个通用的健康检查服务。
检查目标可以配置为 HTTP 或 TCP 两种探针类型。HTTP 探针发 GET 请求，期望返回 200。TCP 探针尝试建立连接，连接成功就算健康。
每个检查目标有独立的检查间隔和超时时间。连续失败 N 次标记为不健康，连续成功 M 次标记为健康。N 和 M 按目标配置，默认都是 3。
检查目标按分组管理，可以查询某个分组下所有目标的健康状态。分组可以包含其他分组（嵌套），父分组的状态取决于子分组中不健康的比例——超过 50% 不健康则父分组标记为不健康。
目标的状态变更时触发通知，通知方式是调用一个回调 URL，和配置中心的 watch 类似。通知内容包含目标名称、旧状态、新状态、变更原因。
Maven 构建，端口通过命令行参数或环境变量配置。
