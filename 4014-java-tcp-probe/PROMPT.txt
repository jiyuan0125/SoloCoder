有些下游是 TCP 服务有些是 HTTP 的，甚至还有自定义协议的——健康检查不能一刀切。先用 Java Netty 搭一个通用的探针框架，再逐步接入各种后端。

第一步，定义检查目标。每个目标配置名称、检查类型（HTTP 或 TCP）、检查间隔、超时时间、不健康阈值 N 和健康阈值 M。HTTP 类型发 GET 请求期望 200，TCP 类型尝试建连成功即健康。连续失败 N 次标不健康，连续成功 M 次标健康，N 和 M 默认都是 3。目标按分组管理——POST `/groups` 创建分组，POST `/groups/{name}/targets` 添加目标到分组。

第二步，级联状态。分组可以嵌套，父分组的状态由子分组的不健康比例决定——超过 50% 不健康则父分组也不健康。级联深度不限，循环依赖要检测到并在创建时拒绝，返回 400 说明依赖链。

第三步，回调通知。状态变更时 POST 到目标配置的回调 URL，Body 包含目标名称、旧状态、新状态、变更原因（连续失败/连续成功/级联影响）和检查耗时。回调超时 5 秒，失败重试 2 次。所有回调投递记录可查。

Maven 构建，端口通过命令行参数或环境变量 `PORT` 指定。
