前端只认 HTTP JSON，后端有两三个老服务是 gRPC 的，改造成本太高。Go Gin 在中间搭一个协议网关：请求进来是 JSON，转成 protobuf 发给后端 gRPC 服务，响应再从 protobuf 转回 JSON。转换规则按 service 和 method 配置，路由格式 /v1/{service}/{method}，比如 /v1/userservice/CreateUser。

后端 gRPC 不可用时网关返回 502 并带错误详情，gRPC 状态码映射成 HTTP 状态码。支持 server streaming——网关把流式响应转成 chunked transfer encoding 给 HTTP 客户端。
编译 go build，监听端口环境变量 PORT。
