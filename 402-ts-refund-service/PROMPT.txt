电商后台需要处理退款申请。做一个退款服务API，记录每笔退款关联的订单号、退款原因和退款金额。下单超过30天的退款直接拒绝，这个天数要可配置方便后续调整。实物商品需要用户填退货物流单号，仓库确认收到后才退款；虚拟商品不需要退货直接退款。但虚拟商品如果用户已经消费了（比如在线课程已看完60%以上），只能退未消费部分按比例算退款金额。退款单提交后状态从待处理变成处理中，之后不能再重复提交。退款金额以原订单实付金额为准，用户自己填的不算数。如果一笔订单包含多个商品，用户可以选择只退其中几件，退款金额按各商品实际支付金额单独计算后汇总。整单退款时运费也一并退，部分退款则运费不退。提供退款列表查询和退款详情查看，支持按时间范围和退款状态筛选。服务重启后所有退款数据要还在。虚拟商品如果用户已经消费了（比如在线课程已看完60%以上），只能退未消费部分按比例算退款金额。如果一笔订单包含多个商品，用户可以选择只退其中几件，退款金额按各商品实际支付金额单独计算后汇总。整单退款时运费也一并退，部分退款则运费不退。退款进度支持查询，客服可以看到每个退款单当前处于哪个环节。售后期天数可由管理员在后台配置。金额一律以分为单位的整数存储和计算，避免浮点精度丢失。异步操作必须正确处理错误，不能吞掉异常。
用 TypeScript 写，采用 monorepo 结构。共享包（packages/shared）放公共的类型定义、请求响应接口和错误码。packages/server 使用 Node.js 内置的 http 模块监听端口，不引入第三方 Web 框架，所有业务逻辑在服务端完成，数据存内存。packages/cli 是命令行交互工具，通过 HTTP 调用服务端接口，将结果格式化展示。根目录通过 npm workspaces 统一管理三个子包，tsconfig.json 开启 strict 选项。各包按职责拆分文件组织。禁止使用 any 和 @ts-ignore。npm install && npm run build 必须能成功编译。
