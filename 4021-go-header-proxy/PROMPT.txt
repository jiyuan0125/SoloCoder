之前那个反向代理还不够用，现在要加一些 Header 操作能力。Go 标准库 net/http 做一个支持 Header 改写的反向代理。
每个路由规则可以配置一组 Header 操作：添加、删除、覆盖、传递（从请求复制到转发请求）。比如转发到用户服务时加上 X-Source: gateway，删掉 Cookie。
路由规则的匹配方式支持路径前缀匹配和正则匹配。同一个路径可能同时匹配多条规则，按规则注册顺序取第一条。
后端服务的响应 Header 也要能改写，比如去掉后端泄露的 X-Powered-By。请求和响应的改写规则分开配置。
如果配置了改写规则但后端不可用，代理返回 502，并且把已经解析好的 Header 操作记录到日志里方便调试。
配置通过接口热加载，不需要重启。路由规则和改写规则数量可能很大（上千条），匹配性能要注意。端口 PORT 环境变量，go build 能过。
