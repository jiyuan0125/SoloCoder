有状态服务用轮询会导致会话丢失——用户上次打到 A 节点、这次打到 B 节点，登录状态就没了。更烦的是缓存服务也是一样，请求换个节点就 miss。Spring Boot 实现一致性哈希负载均衡来解决。

1. 哈希环设计：每个后端节点在哈希环上占若干虚拟节点，虚拟节点数量由权重决定（权重 5 的节点占 50 个虚拟位，权重 1 的占 10 个）。请求根据某个可配的 key 做哈希映射到环上的节点——key 来源可选客户端 IP、指定 Header 值或 URL 参数，在路由级别配置。同一个 key 始终打到同一节点。

2. 节点变更：节点下线后虚拟节点移除，只影响被重新分配的那部分 key，其他 key 不动。新节点上线也只接管一部分 key。提供一个迁移报告接口 GET `/migration-report?event={event_id}`：列出哪些 key 从哪个节点迁到了哪个节点，结果按迁出节点分组。

3. 权重管理：权重为 0 时虚拟节点保留但不参与分配——和删除不同，后续恢复权重不用重新注册。PUT `/backends/{id}/weight` 动态调整。

Maven 构建，端口走配置文件。哈希函数用 MurmurHash3。
