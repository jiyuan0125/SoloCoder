之前做的请求聚合太简陋了——没有认证、串行调用不支持上下文传递，前端用了两版就不愿意再用了。Go Gin 重写一个带认证的请求聚合网关，这次把细节想清楚再动手。

路由支持路径参数（如 `/api/v1/users/:id/orders`），转发时把参数替换成实际值。聚合请求可配并行或串行调用多个后端——并行模式所有后端同时发请求，总耗时取决于最慢的那个；串行模式前一个响应能作为后一个请求的输入，用 `{{response0.data.userId}}` 这样的模板语法引用。聚合接口的响应格式支持自定义，用 JSON 模板配置，只返回客户端需要的字段。

认证走 API Key，Key 存内存。POST `/keys` 创建 Key，每个 Key 绑定一组允许访问的路由列表，不在列表里的返回 403。DELETE `/keys/{id}` 吊销。GET `/keys` 列出所有 Key 及其权限。

后端不可用时的容错——并行模式下某个后端超时或报错，对应字段填 null 并加 error 描述；串行模式下如果某一步失败，后续步骤跳过，返回已执行部分的结果。`go build` 编译，`PORT` 环境变量读端口。
