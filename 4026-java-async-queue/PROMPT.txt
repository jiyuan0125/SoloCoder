消息队列还需要支持异步投递确认。用 Java Netty 做一个高性能的异步消息队列。
生产者发送消息到 Topic，消费者从 Topic 拉取消息。投递后消费者需要在超时内确认（ACK），未确认的消息重新投递给其他消费者。
同一个 Consumer Group 内，一条消息同一时刻只能被一个消费者持有。消费者持有的消息如果超时未确认，自动变为可投递状态。
消息持久化用本地文件存储。写入时先写 WAL（Write-Ahead Log），确认后才标记为已消费。服务重启后从 WAL 恢复未确认的消息。
Topic 可以设置消息过期时间，过期的消息后台清理。消息体最大 1MB。超过限制的消息直接丢弃，但记录丢弃事件到审计日志。
Maven 构建，端口命令行参数或环境变量指定。
