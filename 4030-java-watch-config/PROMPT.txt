配置中心的推送不知道客户端到底收没收到——上次改了个数据库地址，三个服务拉到了两个没拉到，线上出了半小时故障。Spring Boot 加强版，把推送确认机制补上。

变更推送到客户端后，客户端必须回 ACK。超时（默认 10 秒）未 ACK 标记为推送失败，按策略重试——最多 3 次、间隔递增（5 秒、15 秒、30 秒）。推送历史保留，GET `/pushes/{configId}` 查某个配置推给了谁、什么时候推的、是否确认、重试了几次。推送状态有三种：待确认/已确认/失败。

回滚要加验证——如果要回滚到的版本里某个 key 在当前版本被其他项目引用了，回滚接口返回 409 列出冲突的 key 和引用项目，必须加 `force=true` 参数确认才能强制回滚。

配置导入功能——POST `/configs/import` 批量导入 key-value，支持 `dry-run` 模式（只预览不实际执行）。导入结果返回新增几个、修改几个、冲突几个（已有但值不同的 key）。GET `/configs/{env}/{project}/export` 批量导出。

Maven 构建，端口走配置文件。
