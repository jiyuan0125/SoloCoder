前端有个实时看板用了 WebSocket，后端全是 HTTP REST——两边协议不一样，前端团队说改不动后端也不愿动。Go Gin 做 WS↔HTTP 双向桥接，把两个世界连起来。

客户端通过 WebSocket 连到网关 `/ws`，发来的 JSON 消息必须包含 `request_id`、`path`、`method`（GET/POST/PUT/DELETE）、`body` 和可选的 `headers`。网关把 WS 消息转成 HTTP 请求发给后端，响应通过 WS 推回，用 `request_id` 匹配。同一连接上的多个请求并发处理，响应异步推送不阻塞。后端不可用时 WS 桥返回错误消息（JSON 里带 error 字段）而不是断开连接。

WS 连接异常断开时清理所有未完成请求——后端收到响应了但 WS 已经关了，这些响应直接丢弃。还支持广播模式——后端通过 POST `/broadcast` 接口主动推消息到网关，网关广播到所有已连接的 WS 客户端。每个 WS 连接分配唯一连接 ID。

GET `/stats` 返回当前连接数、总请求数、活跃请求数、广播次数。连接超过 5 分钟无消息自动断开保活资源。端口通过 `PORT` 环境变量传入，`go build` 能编译。
