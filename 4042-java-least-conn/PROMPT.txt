加权轮询对长连接场景效果差——某个节点接了一堆慢请求，活跃连接数已经很高了，轮询还在往那打，越打越慢。Spring Boot 用最少连接数算法，让负载更均衡。

选择后端时优先选活跃连接数最少的节点。计算公式：活跃比 = 当前活跃连接数 / 节点权重，活跃比最小的优先选。活跃连接数 = 已接受请求 - 已完成请求，每次请求开始加 1、响应完减 1。统计在内存里实时更新。

1. 慢启动：新节点不立即扛全部流量，5 分钟内权重从 0 线性增到配置值（时间可配）。增长期间按当前实际权重参与分配，避免新节点一上来被打满。

2. 排空模式：节点需要摘除时不立即断开——不接新连接、等现有连接自然结束，排空超时（默认 5 分钟）后强制下线。排空中的节点不参与负载分配但仍然出现在查询接口里，标记 `draining: true`。排空进度也可查——还有多少连接在用。

3. 统计与查询：GET `/backends` 返回每个节点的活跃连接数、总请求数、平均响应时间。GET `/stats` 返回全局 QPS 和平均响应时间。所有节点变更（注册、摘除、权重调整）记审计日志。

Maven 构建，端口走配置文件。
