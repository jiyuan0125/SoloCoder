API 网关缺限流和缓存——每个请求都打到后端去，后端扛不住不说，重复查询还浪费资源。Go Gin 把限流和缓存加上，网关层能扛的就不往后端丢。

请求限流按路由配独立 QPS 上限。维度支持 IP / API Key / 路由组合——比如 `/api/orders` 限每个 IP 每秒 10 次，`/api/search` 限每个 Key 每秒 50 次。超限返回 429，响应头带 `X-RateLimit-Limit` 和 `X-RateLimit-Remaining`。

响应缓存对 GET 请求生效。缓存 key 由路由 + 查询参数组成，TTL 和条目上限按路由配。超限用 LRU 淘汰。缓存命中时响应头加 `X-Cache: HIT`，未命中加 `X-Cache: MISS`。POST `/cache/flush` 手动清缓存。

路由匹配支持正则和路径参数（如 `/api/v{version:[0-9]+}/users/:id`），提取的参数传给后端。后端不可用时有降级策略——按路由配：返回缓存数据（即使过期也算）或返回配置的默认值，不直接 502。网关自己也有 `/health` 接口，返回路由数、缓存条目数、限流规则数。

`go build` 编译通过，`PORT` 环境变量配端口号。
