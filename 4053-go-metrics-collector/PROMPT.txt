凌晨两点线上挂了，翻日志才定位到是某个接口 QPS 突增。要是有实时指标看板根本不用排查这么久。Go 标准库 net/http 做一个指标收集和导出服务——不是给 Prometheus 用的那种通用方案，而是专门给中小团队开箱即用的轻量版。

三种指标类型：Counter 只增不减，用来统计请求总量；Gauge 可增可减，用来反映当前连接数这种瞬时值；Histogram 做分布统计，算 P50、P95、P99 延迟。每种类型创建时指定名称、标签集合和帮助文本。Counter 的 Inc 和 Add 操作要处理 uint64 溢出回绕——溢出后归零继续计数并记录一条警告日志。

指标按标签维度聚合，http_requests_total 按 method 和 path 分别统计就是两条独立的序列。查询时指定标签过滤条件，只返回匹配的序列，不传标签则返回全部。标签值支持精确匹配，不支持正则。

Prometheus 格式导出走 /metrics 端点，每个指标序列一行纯文本。Histogram 输出 _bucket、_sum、_count 三类数据，bucket 边界可配置，默认 10、50、100、500、1000 毫秒。指标数据存在内存里，重启后清零。服务自身暴露内部指标——注册的指标数、查询次数、导出耗时。端口 PORT 环境变量，go build 无错误通过，不依赖第三方 metrics 库。
