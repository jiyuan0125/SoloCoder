上个月 v2 版本全量发布后出了 P0 故障，全量回滚折腾了将近一小时。从那以后团队决定所有新版本必须走金丝雀发布，先灰度再放量。用 Python aiohttp 做一个流量染色和路由服务，精确控制哪些请求走新版本。

染色规则基于请求特征匹配——HTTP header 的某个字段值、cookie 里的标识、客户端 IP 段、指定的用户 ID 列表，四种匹配方式可以组合使用。匹配到的请求打上染色标签比如 x-canary: v2，然后路由到对应的版本实例。

流量百分比控制：新版本上线先把 5% 的流量导过去观察，没问题再逐步调到 10%、30%、50%、100%。比例按请求维度控制，不是按连接，同一用户的多次请求可能被分到不同版本——这样做的目的是尽快发现潜在问题。百分比的基数是所有请求，不是某个用户的请求。

染色的请求有回退机制——目标版本不可用时自动回退到稳定版本，响应 header 里加 x-canary-fallback: true 标记发生了回退。回退事件记录到 SQLite 方便事后排查。配置热更新，染色规则和路由表通过 API 修改后立即生效，已经在处理中的请求不受规则变更影响。规则存 SQLite 持久化，重启后规则不丢失。端口 PORT 环境变量。
