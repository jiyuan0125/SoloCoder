微服务调用链排查起来太痛苦了——一个请求经过七八个服务，哪个环节出了问题全靠猜。Java Netty 写一个轻量的链路追踪收集器，不是要替代 Jaeger，而是给中小项目一个开箱即用的方案。

每个请求进来时生成 TraceID，经过每个服务时创建 Span 并上报。Span 的字段：trace_id 关联整个调用链、span_id 标识当前节点、parent_span_id 指向调用方、service_name 和 operation_name 描述谁在做什么、start_time 和 duration 记录耗时。TraceID 通过 HTTP header X-Trace-Id 传播，SpanID 通过 X-Span-Id 传播，调用方负责传递这两个 header。

收集器接收 Span 后按 TraceID 归组，一棵 Trace 树由多个 Span 组成。查询时输入 TraceID 返回完整的调用树，按 parent_span_id 的父子关系构建树形结构展示。调用树里耗时最长的 Span 高亮标记，一眼看出瓶颈在哪。支持按服务名和操作名搜索，返回匹配的 TraceID 列表分页展示。

采样策略不是所有请求都收集——按比例采样比如 10%。采样比例运行时通过接口可调。被采样的请求所有 Span 都收集，不采样的直接丢弃不占资源。Trace 数据保留 7 天，过期数据后台每天凌晨清理。慢请求——整体耗时超过阈值——自动标记，支持按慢请求筛选查询。技术约束：Netty 实现 HTTP 服务，Maven 构建，端口配置文件，不依赖外部存储用内存。
