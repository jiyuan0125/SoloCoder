上个月机房割接，后端三台机器挂了两台，代理还在傻乎乎地往死掉的机器上转发请求。用 Go 标准库 net/http 做一个带健康检查的反向代理，后端挂了自动摘除，恢复了自动加回来。

路由规则按路径前缀匹配，每条规则对应一组后端实例。请求进来后先匹配路由，然后从后端列表里选一个转发——选择策略支持轮询和随机两种。轮询保证均匀分摊，随机适合无状态短连接场景。

健康检查定时对每个后端发 HTTP 探测。连续失败 N 次的后端标记为不可用，不再分配流量。后端恢复后需要连续成功 M 次才重新启用，避免网络抖动导致状态反复切换。探测的间隔和超时按后端组配置，不同业务可以用不同的检查策略。

转发超时按路由配置，超时后返回 504 同时记到审计日志。如果所有后端都不可用，返回 503 并带上降级响应——降级响应的内容在配置里预设。请求和响应的 header 可以配置改写规则，比如给请求加上 X-Forwarded-For，去掉响应里的 Server 头。配置通过接口修改，修改后即时生效。配置变更历史保留，支持回滚到之前的版本。后端的健康状态变更也记录日志。路由匹配、上游管理、健康检查、转发代理四个模块各司其职。端口 PORT 环境变量，go build 能过。
