缓存集群扩容缩容的时候，普通哈希会导致大量 key 重新分布，缓存命中率断崖式下降。Spring Boot 实现一个支持虚拟节点的一致性哈希负载均衡器，让扩缩容只影响最少的 key。

1. 节点注册与虚拟节点：后端节点注册时指定权重，权重越大的节点分配越多的虚拟节点。虚拟节点数量等于权重乘以倍数，倍数可配置默认 150。请求进来后对请求 key（如 IP 或 SessionID）做哈希，在环上顺时针找最近的虚拟节点，映射到实际节点。哈希函数用 MurmurHash3，分布均匀性比 CRC32 好。

2. 节点变更：节点下线时只影响分配到该节点的请求，其他请求不受影响。节点上线时新增虚拟节点，环上相邻节点的部分流量迁移到新节点。迁移量要均衡——不能出现某个节点突然吃掉大量流量的情况。

统计接口暴露每个节点的虚拟节点数、分配到的请求量、请求分布的标准差。标准差太大说明哈希不均匀，需要调整虚拟节点倍数或者检查 key 的分布特征。节点变更后主动推送最新的节点列表和哈希环状态给订阅方。推送失败记录下来不阻塞主流程，可以查询失败记录排查问题，后续可以查询失败记录手动重试。架构上分哈希环管理层、节点注册层、统计监控层、事件推送层。Maven 构建，端口配置文件。
