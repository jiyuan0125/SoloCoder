客户端要查用户资料，得分别调用户服务拿基本信息、调订单服务拿历史订单——三次网络来回，移动端体验能好吗？Go Gin 做一个带聚合能力的 API 网关，一次请求搞定。

路由匹配支持路径参数和查询参数，也支持通配符路径比如 /api/v2/* 匹配所有 v2 接口。匹配后可以把一个请求拆成多个后端调用，结果聚合成一个响应返回。客户端请求 /api/profile，网关同时并行调用用户服务和订单服务，把结果合并成一个 JSON。哪个后端先返回就先处理，不互相等待。

聚合调用的超时取所有后端超时的最大值，也可以按路由单独设一个聚合超时覆盖默认值。部分后端失败时策略按路由配置——要么返回部分结果并标记哪些字段缺失，要么整个请求返回 502。响应数据可以通过模板重新组织，支持字段提取、重命名和嵌套重组。转换规则存在配置文件里热加载。

限流和认证作为中间件链。限流按路由配置 QPS 上限，超限返回 429。认证支持 API Key 和 JWT 两种方式，不同路由可以选择不同的认证策略。未认证的请求返回 401，认证但权限不足返回 403。端口 PORT 环境变量，go build 能过。聚合层要不要加缓存？热点接口的结果缓存几分钟可以大幅减少后端压力。
