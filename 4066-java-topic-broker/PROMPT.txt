周二下午客服反馈一批用户的积分没到账，查下来是积分消费服务昨天处理消息出了 bug。想从昨天的 offset 重新消费，结果发现位移已经被新消息覆盖了。Spring Boot 做一个消息中间件，消费位移得能回溯，出了问题能重来。

Topic 里的消息按写入顺序分配 offset，从头开始单调递增。消费组记录每个分区的消费位移。位移提交支持自动和手动两种模式——自动模式下每消费 N 条提交一次，N 可配置；手动模式下消费者处理完主动提交。提交失败时回退到上一次提交的位移重新消费。

消费组重平衡：消费者加入或离开组时触发。重平衡策略支持轮询分配和按 key 范围分区。重平衡期间暂停消费，等分配完成后再继续，保证同一条消息不会被两个消费者同时处理。

消息回溯是核心能力：消费组可以把消费位移重置到更早的 offset，重新消费旧消息。回溯时不影响其他消费组。回溯的起点可以是具体的 offset 值，也可以指定时间戳——中间件找到该时间戳对应的最早 offset。消息保留时间可配置，过期消息后台异步清理，清理期间消费不受影响。消费组信息持久化到本地文件，重启后从文件恢复所有消费组的位移和状态。消息中间件自身也有监控接口，暴露 Topic 数、消费组数、消息吞吐量。Maven 构建，端口配置文件。
