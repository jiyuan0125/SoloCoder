线上缓存全用 LRU，偶尔来一波冷数据扫描就把热点 key 挤掉了，命中率腰斩。Rust axum 做一个多策略缓存服务——LRU 适合通用场景，LFU 保热点，FIFO 适合只管时效的数据，业务自己选。

1. 淘汰策略：每个缓存空间独立选择 LRU、LFU 或 FIFO。容量可以按条目数或字节大小限制。不同业务（用户会话、商品详情、排行榜）各自的缓存空间互不干扰，一个空间满了不影响另一个。

2. TTL 机制：固定时长和滑动时长两种模式。固定时长写入后 N 秒过期不管有没有被访问；滑动时长每次读取后延长 N 秒。两种模式按 key 前缀区分，比如 user: 前缀用滑动、cache: 前缀用固定。

缓存预热：启动时从数据源批量加载热点数据。加载任务有进度指示，加载期间查询未命中的 key 走正常 miss 逻辑不被阻塞。加载失败不影响已有数据。缓存穿透防护——查询不存在的 key 时缓存一个空值，短 TTL 比如 60 秒，防止反复穿透到数据源。空值和正常值在统计里分开计数。统计接口暴露命中率、淘汰数量、当前条目数、内存占用。每个缓存空间的统计独立，可以按空间名称过滤查看。架构分缓存管理层、淘汰策略层、存储引擎层、统计监控层。Cargo build，PORT 环境变量。
