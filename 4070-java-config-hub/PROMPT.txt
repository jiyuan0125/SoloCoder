配置推送点了全量发布之后发现有 bug，想回滚但不知道上一个版本的内容是什么。Spring Boot 做一个配置灰度发布系统，先给几台机器推，没问题再全量。

配置项按项目和环境隔离。每个配置项有版本号，每次修改版本号递增。修改配置时先创建新版本，不影响当前生效的版本。

灰度发布：发布新版本时先指定灰度范围（比如 IP 列表或实例标签）。灰度范围内的实例拉取到新版本，其他实例还是旧版本。灰度观察没问题后全量发布。

回滚：把当前版本回滚到指定版本。回滚也是一次发布操作，版本号继续递增。回滚后推送变更通知到所有客户端。

变更通知：客户端通过长轮询接收配置变更。长轮询超时后客户端重新发起。服务端在配置变更时立即响应等待中的长轮询请求。通知失败不重试，客户端下次轮询时拿到最新值。Maven 构建，端口配置文件。
