配置推送点了全量发布之后发现有 bug，想回滚但不知道上一个版本长什么样？Spring Boot 做一个配置灰度发布系统，先给几台机器推，确认没问题再全量。

配置项按项目和环境隔离，比如项目 shop 分 dev/staging/prod 三个环境。每个配置项有版本号，每次修改递增。修改配置时先创建新版本草稿，不影响当前生效的版本。草稿确认后才进入发布流程，发布前可以预览变更内容的 diff，确认无误后再发布。草稿也可以丢弃重新来过。配置的值类型支持字符串、数字、布尔和 JSON 对象。

灰度发布：发布新版本时指定灰度范围——IP 列表或实例标签。灰度范围内的实例拉取到新版本，其他实例还是旧版本。灰度期间新旧版本的配置值同时在线，可以在监控面板上对比两组实例的行为差异。灰度观察没问题后全量发布，所有实例切换到新版本。

回滚也是一次发布操作。把当前版本回滚到指定版本，版本号继续递增不回退。回滚后推送变更通知到所有客户端。变更通知走长轮询——客户端发起长轮询请求，服务端有配置变更时立即响应，没有变更则等到超时后客户端重新发起。通知失败不重试，客户端下次轮询时自然拿到最新值。Maven 构建，端口配置文件。配置中心本身的高可用怎么保证？要不要做集群部署？
