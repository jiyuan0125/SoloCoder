需要统一支付网关对接多渠道。做一个支付网关API，模拟微信支付和支付宝两个渠道各有不同签名和回调格式。创建订单时按金额自动选渠道：100以下走微信，100及以上走支付宝，订单金额必须大于0且不超过50万。回调必须幂等——同一订单多次回调只处理一次，用订单号加渠道作为去重key。支付发起30秒没收到回调订单自动变待确认，待确认的订单每天凌晨自动查一次状态尝试同步。退款根据原始渠道走对应流程，退款金额不能超过原支付金额。订单关闭后不能重新支付，要创建新订单。部分退款场景：一笔订单支持多次部分退款，但累计退款总额不能超过原支付金额，最后一次退款会把剩余金额全部退完。支持查询订单支付状态和退款进度。订单和支付订单金额必须大于0且不超过50万。支付发起30秒没收到回调订单自动变待确认，待确认的订单每天凌晨自动查一次状态尝试同步。部分退款场景：一笔订单支持多次部分退款，但累计退款总额不能超过原支付金额。订单关闭后不能重新支付要创建新订单。支付成功后生成唯一的交易流水号供财务对账。所有金额以整数分为单位计算，退款金额的加减必须用整数运算。null 和 undefined 语义不同，可选字段为空时用 null 表示，缺失用 undefined，严禁混用。
使用 TypeScript 实现，采用 monorepo 工程结构。packages/shared 管理共享的类型定义、API 接口、消息协议和错误码。packages/server 利用 Node.js 原生 http 模块启动 HTTP 监听（禁用 Express 等框架），承载完整业务逻辑，数据在内存中保存。packages/cli 提供命令行交互，用户通过子命令向服务端发送请求，服务端处理后客户端将结果格式化呈现。根 package.json 以 workspaces 组织三个包，全局 tsconfig.json 开启 strict 模式。各包内部按模块职责拆分文件。不允许 any 和 @ts-ignore。npm install && npm run build 编译无报错。
