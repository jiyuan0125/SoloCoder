限流 key 不一定是 IP 或路由——有些接口要从请求 body 里提取 tenant_id 做差异化限流，VIP 租户和普通租户的 QPS 上限差十倍。Rust actix-web 做一个内容感知限流器，限流维度灵活可配。

限流维度不限于 IP 和路由，还可以从请求 body 或 header 里提取字段作为限流 key。比如按请求里的 tenant_id 做限流。提取规则用 JSONPath 表达式——body 里 $.tenant.id 或者 header 里的 X-Tenant-Id 都行。提取失败时走默认限流规则兜底。

不同 key 的限流阈值可以不同。阈值按 key 前缀分组配置，比如 tenant:vip 前缀 QPS 上限 1000，tenant:normal 前缀 100。没有匹配到分组的用默认阈值。分组规则可以动态增删。

限流算法用令牌桶。桶容量和填充速率独立配置——桶容量决定能容忍的瞬时突发量，填充速率决定长期平均速率。桶的状态（当前令牌数、最后填充时间）存内存重启后清零。超限请求可以选择拒绝返回 429 或排队等待。排队等待的请求有超时，超时后也返回 429。等待队列有上限，满了直接拒绝。技术约束：Cargo build，PORT 环境变量，不依赖外部存储。
