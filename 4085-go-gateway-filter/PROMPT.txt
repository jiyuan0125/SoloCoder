请求校验放在后端做太晚了——不合法的请求已经消耗了网络带宽和服务资源。Go 标准库 net/http 做一个带校验能力的 API 网关，非法请求在入口就拦掉。

请求校验：对请求参数做校验——必填字段、类型、长度、格式。校验规则在配置文件里定义，支持 JSON Schema 格式。校验失败的请求直接返回 400 和详细的错误描述，不转发到后端。校验规则按路由配置，不同接口可以有不同的校验要求。

流量控制：请求速率限制和并发数限制。速率限制按路由和 IP 组合维度，比如 /api/query 每个 IP 最多 100 QPS。并发限制按路由维度，超出排队。多个限流规则可以叠加——先检查全局限流再检查路由限流。

请求转换：转发前可以对请求做简单转换——JSON 字段重命名、默认值填充、字段过滤。转换规则在配置里定义，比如把前端的 user_name 转成后端的 username。响应缓存：GET 请求的响应可以缓存。缓存 key 包含路由和查询参数，TTL 按路由配置。缓存条目上限可配置，满时 LRU 淘汰。缓存命中率和条目数通过 /cache/stats 接口可查。端口 PORT 环境变量，go build 能过。要不要给校验规则加个热更新机制？每次改校验规则不用重启网关。
