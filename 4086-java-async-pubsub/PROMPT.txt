下单后 30 分钟未支付自动取消——这种场景需要延迟消息，到期了再投递给消费者。Spring Boot 做一个消息中间件，支持延迟投递和消息过滤，让定时任务不再依赖外部调度器。

延迟消息：投递时指定延迟时间（单位秒），到期后才对消费者可见。延迟精度到秒。实现上用时间轮——消息先投到时间轮的对应槽位，到期后取出投递到目标 Topic。时间轮的精度和槽数可配置。延迟消息到期后自动投递，不需要消费者轮询。

消息过滤：消费者可以指定过滤表达式，只接收满足条件的消息。过滤基于消息的 header 属性（如 region、priority）。过滤在服务端执行，不匹配的消息不投递给该消费者，节省消费者的处理资源。

消息顺序保证：同一个 partition key 的消息保证顺序投递。不同 partition key 的消息不保证顺序。partition key 从消息属性里提取。消息确认机制：消费者处理完消息后发 ACK。超时未 ACK 的消息重新投递，重新投递的消息带原始投递时间和重试次数。超过最大重试次数进死信 Topic，死信 Topic 可以被专门的消费者消费处理异常。模块：delay（延迟调度）、filter（消息过滤）、partition（分区路由）、deadletter（死信处理）。Maven 构建，端口配置文件。
