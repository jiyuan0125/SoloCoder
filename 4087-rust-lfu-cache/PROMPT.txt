并发更新同一个 key，两个请求同时读到旧值各自修改先后写回——后写的覆盖了先写的，数据丢了。Rust axum 做一个支持批量操作和 CAS 的缓存服务，并发安全是第一优先级。

1. 批量操作：MGET/MSET 一次操作多个 key。批量操作是原子的——要么全部成功要么全部失败，不会出现一半写了一半没写的中间态。批量操作的 key 数量有上限，超出的拆成多个批次自动执行。MGET 不存在的 key 返回 null 不报错。

2. CAS 机制：更新时先比较版本号，版本号一致才更新。CAS 失败返回冲突信息——包含当前值和期望值。客户端可以据此重新读取最新值再重试。每个 key 每次写入版本号递增。CAS 是乐观锁的核心，比悲观锁性能好。

缓存事件通知：key 被更新或删除时推送通知给订阅者。订阅者按 key 前缀过滤，比如订阅 user: 前缀。通知是异步的推送失败不重试。通知消息包含 key、操作类型（update/delete）、新值。热点探测自动统计访问频率最高的 key，频率超过阈值标记为热点。热点的 TTL 自动延长淘汰优先级降低。热点列表通过接口可查。架构分缓存存储层、CAS 控制层、事件通知层、热点分析层。Cargo build，PORT 环境变量。
