先给服务实例注册标签。查服务实例只能按服务名查？不够——灰度发布时要查 version=v2 的实例，异地多活时要查 region=east 的实例。Go 标准库 net/http 做一个带标签路由的注册中心，查询维度随心配。

第一步，实例注册。除了 IP 和端口还可以打标签——version=v2、env=canary、region=east。查询时按标签过滤，比如查所有 version=v2 的实例。标签支持多值，一个实例可以有多个 version 标签。标签变更通过接口修改立即生效。

第二步，权重管理。实例的权重可以通过接口动态修改。权重影响查询结果的分布——权重越大的实例被选中概率越高。权重为 0 等于下线但保留注册信息。实例按标签自动分组，查询时可以指定分组也可以查所有分组。

第三步，状态流转和通知。实例状态：注册→健康→可疑→下线。可疑状态是心跳延迟但还没超时，提醒运维关注。从可疑恢复到健康需要连续 N 次正常心跳。实例分组变更（标签变化）时触发通知给订阅方。通知失败重试最多 3 次不阻塞。模块：registry（注册管理）、tag（标签路由）、weight（权重调度）、notify（变更推送）。端口 PORT 环境变量，go build 能过。
