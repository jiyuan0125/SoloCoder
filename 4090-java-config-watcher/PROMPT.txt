三个环境 dev/staging/prod 大部分配置一样，只有数据库地址不同——改一个公共配置得改三遍，改漏了就出事故。Spring Boot 做一个配置中心，子环境继承父环境的配置，改一处管全局。

配置按命名空间隔离，每个命名空间独立管理。命名空间可以有父子关系，子命名空间继承父的配置。子可以覆盖父的同名配置也可以新增。继承是单向的——子环境能看到父的配置，父环境看不到子的。

环境维度：每个命名空间下可以有多个环境（dev、staging、prod）。环境之间的配置独立但可以继承。比如 prod 继承 staging 的非覆盖项，staging 继承 dev 的非覆盖项。继承链的层级不要太深，三层以内比较清晰。

配置加密：敏感配置（数据库密码、API Key）存储时加密。加密算法用 AES-256。解密需要对应的密钥，密钥通过环境变量注入不落盘。查询时返回解密后的值（如果有权限），没权限的返回掩码。变更审计：每次配置修改记录操作人、时间、变更前后的内容。审计日志按命名空间查询。支持配置回滚到任意历史版本，回滚本身也产生一条审计记录。Maven 构建，端口配置文件。配置的权限管理要不要加？谁能改 prod 谁只能改 dev 这种。
