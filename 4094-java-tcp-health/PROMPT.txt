先注册服务并配置探针。告警太多运维看都不看了，真正挂掉的服务淹没在一堆无关紧要的告警里。Spring Boot 做一个带告警升级的健康检查系统，持续不恢复逐级升级通知，确保严重问题不被忽略。

第一步，配置探针。除了 HTTP 和 TCP 还支持执行自定义命令作为探针。命令的退出码决定健康状态——0 表示健康，非 0 表示不健康。命令超时可配置。比如用一个 curl 命令检查第三方 API 是否可用，用 ping 检查网络连通性。

第二步，配置告警升级链路。首次告警发给运维组，持续 N 分钟未恢复自动升级到研发组。持续 M 分钟再升级到管理层。升级链路和每级的通知方式（邮件、webhook）都可以配置。不同服务可以有不同的升级策略。

第三步，查看健康评分。每个服务有一个综合健康评分（0-100）。评分基于探测成功率、平均响应时间、依赖组件的健康度加权计算，权重可配置。评分低于阈值触发预警不算告警，但会在面板上标黄提醒运维关注。预警也可以配置通知方式。探测结果的历史数据保留 30 天，支持查询某个服务的历史健康趋势按天聚合。趋势数据用于容量规划和 SLA 报告。每种探针的探测结果也可以单独查询最近的 100 条记录。Maven 构建，端口配置文件。
