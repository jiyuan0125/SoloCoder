上周灰度发布翻车了，一个配置改了直接全量生效，影响了 30% 的用户。Spring Boot 重写配置中心，这次要支持灰度发布和分支管理。
配置项有环境维度（dev/staging/prod）和灰度维度。灰度维度可以指定哪些实例生效。同一个配置项在灰度环境和正式环境可以有不同的值，灰度确认后才合入正式。
配置变更历史完整保留，支持回滚到任意版本。回滚也算一次变更，记入历史。
客户端长轮询获取配置变更。客户端上报自己的环境标签和灰度标签，服务端根据标签返回对应的配置值。如果灰度配置存在且匹配客户端标签就返回灰度值，否则返回正式值。
配置项引用：一个配置项可以用 ${other.key} 引用另一个配置项的值。循环引用要能检测到。Maven 构建，端口配置文件。
