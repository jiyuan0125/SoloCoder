上周线上有个定时任务重复执行了三次，查了半天发现是分布式锁超时后没续期，另一个实例拿到锁又开始跑同一个任务。这种低级问题不该再出了。Rust axum 写一个分布式锁管理器，锁的获取、释放、续期全部走 HTTP 接口。

锁有超时时间，默认 30 秒，获取时可以指定。超时未续期自动释放，防止持有者宕机导致死锁。续期接口 PUT /lock/{name}/renew 延长超时时间，续期间隔建议设为超时时间的 1/3。同一个锁同一时间只有一个持有者，持有者通过一个随机 token 标识，释放时验证 token 防止误删别人的锁。POST /lock/{name}/acquire 获取锁，参数包含 timeout（超时秒数）和 wait（是否排队等待）。DELETE /lock/{name}/release 释放锁，需要传 token 做身份验证。

其他请求在获取锁时可以指定 wait=true，排队等锁释放后按先来先得获取。等待队列有上限，默认 100 个，超过上限直接返回 503 加上 queue_full 信息。

锁支持父子关系。获取子锁时自动获取父锁，释放父锁时所有子锁一起释放。子锁独立超时，子锁过期不影响父锁。父子关系通过 POST /lock/{child}/bind/{parent} 建立，绑定前检测是否形成循环——A 是 B 的父锁，B 不能再当 A 的父锁。循环绑定返回 422。

锁的状态流转：free → acquired → renewing（续期中）→ expired。管理接口 GET /locks 返回所有锁的当前状态、持有者 token、剩余超时秒数、等待队列长度。
