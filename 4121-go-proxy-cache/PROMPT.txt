后端接口响应慢得要死，老板说加一层缓存扛住高峰流量。Go Gin 写个带响应缓存的反向代理，GET 请求走缓存，POST/PUT/DELETE 直接透传到后端不做缓存。

缓存 key 怎么生成？请求路径 + query 参数按字母排序后拼接，做一次 MD5 得到固定长度 key。缓存项有 TTL，默认 60 秒。后端可以通过响应头 X-Cache-TTL 动态控制某个接口的缓存时间。同一个 key 并发请求时——这是重点——第一个去后端拿数据，后面的等第一个拿到结果后共享，不能让一波并发全打到后端。用 singleflight 模式实现，保证同一个 key 同一时刻只有一个飞行中的请求。

后端服务列表存在内存中，通过 POST /backends 添加新后端（参数 host 和 port），DELETE /backends/{addr} 移除。GET /backends 列出所有后端和当前状态。代理转发前做健康检查——每隔 10 秒 TCP dial 一次后端地址，连续 2 次失败的标记为 down，down 的后端不参与转发。恢复后自动重新加入。缓存项被后端新数据覆盖时，正在使用旧缓存数据的请求不受影响，各走各的。

缓存淘汰用 LRU，容量上限通过启动参数 --max-size 配置，默认 10000 条。缓存命中率、当前容量、后端存活数通过 GET /stats 端点暴露，返回 JSON 包含 hit_rate、total_keys、active_backends、total_requests。响应头 X-Cache 标记 HIT 或 MISS，方便排查问题。
