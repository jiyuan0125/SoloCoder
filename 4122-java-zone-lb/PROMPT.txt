双十一流量调度出了事故——跨机房流量全挤到一条线上，带宽打满，延迟飙到 5 秒。根本原因是负载均衡器不知道节点在哪个机房，瞎分配。Spring Boot 做一个分区负载均衡器，按区域调度流量。

后端节点划分到不同的区域。注册节点时 POST /nodes 指定 zone 参数，比如 east、west、north。请求也带区域标签，通过 X-Zone header 传入。优先把请求分配给同区域的节点。同区域没有可用节点时才跨区域，跨区域时选延迟最低的区域——每个区域的平均响应时间通过 GET /zones 统计。

1. 节点状态机：healthy → suspect（连续 2 次响应超时）→ unhealthy（连续 3 次失败）→ draining（管理员手动排水）→ removed。suspect 状态分配到的流量逐渐减少到 30%，给节点喘息恢复的机会。draining 状态不分配新流量，等已有请求处理完再移除。所有状态变更记录日志。

2. 区域切换。某个区域所有节点不可用时流量自动切到其他区域。区域恢复后流量自动切回，切回过程平滑——新请求切回，已有请求不动。切换事件记录到内存日志，GET /failover/history 查看最近的切换记录，包含切换时间、区域、原因和持续时间。

3. 权重。每个节点有 0-100 的权重值，影响同区域内的分配比例。权重为 0 的节点不分配流量但仍参与健康检查，方便临时摘流。手动设置权重通过 PUT /nodes/{id}/weight。GET /nodes 列出所有节点及其区域、状态、权重、当前连接数。
