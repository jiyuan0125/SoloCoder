客服工单系统有个 bug，VIP 客户的工单排在普通用户后面，等了两小时才被处理。Spring Boot 写一个支持优先级的消息队列，优先级高的先消费，失败的进死信。
消息有优先级（1-10，数字越大越优先）。同一个 topic 下的消息按优先级排序消费。高优先级消息插队到队列前面。相同优先级按发送时间排序。
消费失败的消息进入死信队列。死信队列中的消息可以查看和重新投递。重新投递的消息恢复原来的优先级。死信队列有容量上限，满了以后最早的消息被丢弃。
消息大小有上限（比如 1MB）。超大消息直接拒绝发送。消息体格式校验：必须是合法 JSON，字段符合 topic 定义的 schema。
生产者确认：消息发送后等待 broker 确认。确认超时视为发送失败。拆分 broker、consumer、deadletter、schema。Maven 构建，端口配置文件。
