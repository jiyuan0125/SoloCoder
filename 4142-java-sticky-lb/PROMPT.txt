WebSocket 长连接做的聊天室，用户每次刷新都分配到不同后端，消息丢了——WebSocket 连接断开重连到了新节点，之前的会话上下文全没了。Spring Boot 做一个支持会话保持和一致性哈希的负载均衡器。

会话保持。同一个客户端的请求始终路由到同一个后端。客户端标识从 Cookie 或 Header 中提取，通过配置指定取哪个字段。会话绑定表存在内存里，后端节点上下线时需要更新绑定表——受影响的客户端重新分配，重新分配时尽量少迁移（用一致性哈希选择新节点）。

1. 一致性哈希。用 Ketama 算法，虚拟节点数可配置默认 160。节点上下线时只影响相邻虚拟节点的数据迁移。哈希 key 从请求中提取，支持四种方式：Cookie 值、Header 值、客户端 IP、自定义字段的 JSON path。通过 POST /hashring/config 配置。

2. 权重支持。每个节点的权重影响虚拟节点数量——权重 2 的节点虚拟节点数是权重 1 的两倍。权重为 0 的节点不参与哈希环但保留在节点列表中方便恢复。PUT /nodes/{id}/weight 修改权重，修改后重建哈希环。

3. 会话超时。客户端超过 N 分钟没请求释放绑定（默认 30 分钟）。超时后下次请求重新走哈希分配。GET /sessions 查看当前所有活跃会话和绑定的后端。

4. 后端健康检查。每 10 秒一次，连续 3 次失败标记为 down 并从哈希环移除。恢复后自动加回。down 节点上的会话自动重新分配。
