项目整体架构合理，但存在以下必须修复的致命问题：

## 必须修复

1. 所有使用路径参数的 REST 接口全部返回 500 错误，错误信息为参数名无法通过反射获取，提示需要使用 '-parameters' 编译参数。涉及的接口包括：获取/更新/删除部门、获取/更新/删除员工、获取/更新/删除虚拟团队、查询操作日志等。只有不带路径参数的 GET 和使用 @RequestBody 的 POST 接口能正常工作。约 70% 的核心接口不可用。

2. 更新部门的父部门逻辑有误。当把部门 A 的父部门设为部门 B（不同的部门）时，系统报错"不能将自己设为父部门"。而当把部门 A 的父部门设为部门 A（设自己为父，应报错）时，反而没有报错。这个检查逻辑正好反了。

3. CLI client JAR 无法独立运行。`java -jar client/target/*.jar` 报 NoClassDefFoundError，缺少依赖。JAR 中没有包含 common 模块和第三方库。

4. CLI client 默认连接 http://localhost:8080，但 server 监听 8085 端口。client 无法连接到正确的 server 地址。

请修复以上所有问题后确保 `mvn clean package` 构建成功，server 和 client 都能正常运行。
