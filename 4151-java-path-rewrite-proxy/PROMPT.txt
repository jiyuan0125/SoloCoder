上个月运维老张凌晨被叫起来改 Nginx 的 rewrite 规则，改了三版还是没对，路径改写逻辑和业务耦合在一块儿根本理不清。我跟他合计了一下，决定用 Spring Boot 自己写一个路径改写代理，规则全部动态配置，不用再碰配置文件重启了。

请求进来先走 rewriter 模块，根据配置的规则表做路径变换和 Header 注入。比如前端发 /api/v1/orders/{id}，规则把它改写成后端实际的 /orders?id={id}，同时把 JWT 里的用户 ID 解出来塞到 X-User-Id 这个 Header 里。映射规则支持多级路径参数匹配和正则替换，规则本身通过 REST 接口动态增删改，不用重启服务。

upstream 模块管理后端服务列表，同一个接口路径可以配多个上游实例，请求按轮询策略分发。proxy 模块负责实际的转发和响应透传，上游返回什么状态码就透传什么状态码。

health 模块每 10 秒对所有上游做一次 TCP 探测，探测失败的实例标为不可用，请求自动绕过它。某个上游恢复后自动回到轮询列表里。如果全部上游都不可用，直接返回 503 并记录日志。Maven 构建，端口写在配置文件里。
