有没有遇到过这种情况——一个网关服务几十个业务方，结果某个租户突然狂发请求把其他人全拖垮了？Spring Boot 做一个多租户 API 网关，每个租户独立鉴权、独立限速、独立路由，谁也不影响谁。

租户模型是这样的：一个租户下面可以挂多个应用，每个应用有自己的密钥（API Secret）。请求过来时在 Header 里带密钥，filter 模块验签确认身份。密钥不对直接 401，验签通过后再看路径权限——每个应用绑定了一组允许访问的路径前缀，支持通配符匹配。不在白名单里的路径返回 403。tenant 模块管理租户、应用和密钥的增删改查。

限速按租户维度隔离。每个租户配一个 QPS 上限，router 模块在转发之前先检查这个租户当前的一分钟请求数。超了就返回 429，Header 里带上 Retry-After。不同租户之间计数器完全独立。

路由也是租户隔离的：同样一个 /api/orders 路径，租户 A 的请求转到订单服务集群 A，租户 B 的转到集群 B。转发时在 Header 里注入租户 ID 和应用 ID，后端服务拿来做业务隔离。gateway 模块协调整个请求生命周期。

所有请求日志记录原始路径、参数、目标上游和响应状态码。Maven 构建，端口写在配置文件里。
