上周排查了个线上问题：热点数据把 Redis 打满了，本地缓存又没有，请求全穿透到数据库。用 FastAPI 做一个多级缓存代理，L1 本地内存，L2 可以配多个远程节点。
读取时先查 L1，命中返回。未命中查 L2，命中后回填 L1 并返回。L2 也没命中则回调源函数获取数据，同时写入 L1 和 L2。
淘汰策略：L1 用 LRU，L2 用 LFU。L1 和 L2 各自独立配置容量上限和 TTL。L1 淘汰的数据如果 L2 里没有就同步过去。
容量管理比较模糊：L1 和 L2 的容量上限可以随时调整。调小的时候多余的怎么办没定，你们自己定策略就行。
缓存失效：支持按 key 单条失效和按前缀批量失效。失效操作要同步到所有级别。批量失效时 L2 可能要扫全量数据来匹配前缀。
代码拆成 cache、tier、eviction、handler 四个模块。端口 PORT 环境变量。
