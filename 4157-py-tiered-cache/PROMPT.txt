上周四晚上 Redis 集群内存打到 95%，本地缓存又没做，热点查询全穿透到数据库差点把主库打挂。这种事发生过不止一次了，干脆用 FastAPI 做个多级缓存代理：L1 是进程内内存缓存，L2 是可配置的远程缓存层。

读路径很清晰——先查 L1，命中直接回。L1 没有查 L2，命中后回填 L1 再返回。两级都没有就调源函数拿数据，拿到后同时写 L1 和 L2。tier 模块负责这个多级读写协调。

淘汰策略两级不同：L1 走 LRU 淘汰，因为本地内存有限，最近不用的优先清。L2 走 LFU，远程空间大一些，频次低的先淘汰。eviction 模块独立管理两个层级的淘汰逻辑。L1 淘汰数据时如果 L2 里没有对应 key，会同步一份过去，避免下次请求完全穿透。L1 和 L2 各自配容量上限和 TTL，参数可以运行时调整。调小容量时，多出来的数据按淘汰策略自然淘汰即可。

cache 模块暴露缓存操作接口——按 key 失效和按前缀批量失效。前缀匹配失效在 L2 上需要扫全量 key，性能上可以接受。失效操作要同步到所有级别。

handler 模块把以上能力包装成 HTTP 接口。端口 PORT 环境变量。
