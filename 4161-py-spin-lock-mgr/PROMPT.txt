前阵子线上出了个事故——一个服务拿到分布式锁之后进程卡死了，锁一直不释放，其他实例全在等，整个业务线卡了十分钟。Redis 的锁续期机制在那种场景下根本来不及。用 FastAPI 自己实现一套自旋锁管理器，续期由服务端主动推进，不依赖客户端续约。

获取锁时客户端指定 key 和 TTL。lock 模块先检查这个 key：不存在则创建锁并返回一个唯一 token；已存在但 TTL 已过则允许新客户端抢占，返回新 token；锁存在且未过期则返回失败，告知多久后重试。token 是获取锁的唯一凭证，后续所有操作都要带。

续期是 lease 模块的核心能力。客户端在 TTL 到期前发送续期请求，带上 token。token 匹配则延长 TTL，不匹配则拒绝——防止已经丢失锁的客户端误续别人的锁。多个客户端可能同时对同一个 key 发续期请求，manager 模块用内存锁保证串行处理。

释放锁也要带 token，token 不匹配拒绝释放。释放后 manager 检查等待队列，通知最早排队的请求。队列按请求时间 FIFO 排序。如果锁因 TTL 过期自动释放，不触发通知——过期意味着客户端可能已经不健康了，盲目通知没用。

handler 模块把锁操作包装成 REST 接口。端口 PORT 环境变量。
