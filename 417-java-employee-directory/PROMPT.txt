员工通讯录需要集中管理。做一个通讯录API，员工信息包含姓名、工号、部门、职位、手机号、邮箱、办公地点。按姓名、部门、职位模糊搜索，搜索结果按相关性排序（完全匹配优先于模糊匹配）。员工本人可以更新自己的手机号和邮箱，其他信息只有HR能改。离职员工记录保留但标记为离职，默认搜索不显示离职人员，管理员可以切换查看含离职人员的完整列表。同一个手机号不能同时绑定两个在职员工，新增或更新手机号时必须校验是否已被其他在职员工占用。邮箱域名必须是公司域名，不允许填个人邮箱。提供部门人数统计和组织架构树形视图数据。通讯录变更记录操作日志——谁在什么时间改了谁的什么字段。批量导入员工时遇到重复工号跳过并记录，最后返回成功数和失败列表。
搜索结果按相关性排序完全匹配优先于模糊匹配。邮箱域名必须是公司域名不允许填个人邮箱。管理员可以切换查看含离职人员的完整列表。通讯录变更记录操作日志谁在什么时间改了谁的什么字段。批量导入员工时遇到重复工号跳过并记录最后返回成功数和失败列表。员工工号一旦分配不可修改。字符串比较用 equals 不用 ==。DTO 类手写 getter/setter，不用 Lombok。

Java Maven 多模块架构。parent POM 管理依赖版本。common 模块包含 DTO 类定义、请求响应格式和错误码枚举。server 模块用 Spring Boot 搭建，监听端口提供 RESTful HTTP 接口，业务数据在内存中存储和维护。client 模块是纯 Java 的命令行客户端，不依赖 Spring 框架，通过 HTTP 调用 server 接口并格式化打印结果到终端。各模块内部按职责划分子包。不允许使用 Lombok。Java 17，mvn clean package 构建通过。

本项目属于跨系统多模块架构。
