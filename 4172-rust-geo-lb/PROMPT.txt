海外用户投诉说 API 响应慢，一查发现新加坡的请求全打到北京机房来了，延迟 200ms 起步。Rust actix-web 做一个基于地理位置的负载均衡器，把请求就近路由。

节点注册时上报所在区域（如 asia-east、us-west）和可用区。geo 模块维护一个区域层级树——同城 → 同区 → 跨区，层级越近距离权重越小。节点间的"距离"就按这个层级算，不做实际 GPS 计算。每个节点还可以配权重，同层级内多个节点时按权重随机选。

resolver 模块拿到客户端 IP 后做地理位置查询。内存维护一份 IP 段到区域的映射表，启动时加载、运行时可通过接口更新。查到区域后 balancer 模块按距离排序选最近的健康节点，权重为 0 的节点排除不参与路由。

tracker 模块追踪每个区域的节点健康状态，每 5 秒做一次 TCP connect 探测。区域里所有节点都不健康就标记区域不可用，请求自动跨区域路由到次近区域。区域恢复后自动切回本地，不需要人工干预。区域状态变更记日志。

节点下线后，之前一直路由到它的请求重新分配——重新走一遍距离排序逻辑。balancer、geo、resolver、tracker 四个模块。Cargo build，端口 PORT 环境变量。
