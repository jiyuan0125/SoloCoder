配额管理听着简单——不就是个计数器嘛——但真做起来"借用量""周期重置""超额处理"全是坑。FastAPI 做一个配额管理器，给不同用户不同资源类型的用量设上限。

quota 模块定义配额结构：用户 ID + 资源类型 → 总量 + 已用量 + 重置周期。资源类型比如 "api_calls"、"storage_gb"。周期支持每天和每月自动重置，重置时已用量归零、借出量归还。用户 ID 和资源类型不需要单独创建——在定义配额时自动生成。

请求到达时 manager 模块从路径提取资源类型、从 Header 提取用户 ID，查配额。充足则放行并扣减已用量。不足返回 429，Header 带 X-Quota-Remaining: 0 提示。meter 模块负责计数和扣减的原子性——并发请求不能超扣。

配额借用是个特殊能力：某个资源配额用完时，可以从同用户的其他资源临时借。借用规则配置化，比如 "api_calls 可以从 storage_gb 借 100 次"。借用的配额在原资源重置周期到期时自动归还，可能导致原资源已用量突然增加。

管理员可以调总量。调小时已用量可能超过新总量——超出部分不额外扣费，但下次请求会被拒绝直到用量自然回落。handler 模块包装所有 REST 接口。端口 PORT 环境变量。
