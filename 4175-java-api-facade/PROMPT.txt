有没有遇到过这种情况——前端要展示用户详情页，数据散落在用户服务、订单服务、积分服务三个地方，前端得发三个请求拼数据，还经常因为某个服务慢导致整个页面卡住。Spring Boot 做一个 API 聚合门面，后端帮你调多个服务、拼结果、转格式。

facade 模块定义虚拟接口路径，映射到后端。路径支持通配符和多级参数，比如 /api/v1/users/{userId}/profile 背后需要同时调用户服务拿基本信息、订单服务拿最近订单。aggregator 模块处理多后端调用——支持并行和串行两种模式。串行模式下前面接口的响应可以注入到后面请求的参数里，比如先拿 userId 对应的 region，再用 region 查库存。

transformer 模块做响应转换。后端返回的数据按配置的字段映射规则做过滤、重命名和格式转换。支持嵌套路径，比如 data.user.name 可以映射成前端要的 userName。转换规则配置变更后实时生效，不用重启。

错误处理按部分失败容忍：三个后端有两个成功了，聚合结果里正常返回那两个的数据，失败的标记 error 字段。全部失败才返回整体错误。router 模块管理后端地址和健康状态。Maven 构建，端口写在配置文件里。
