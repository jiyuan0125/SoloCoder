1. 去年双十一缓存大面积过期，数据库瞬间被打满，全线降级。FastAPI 做一个防穿透防雪崩的缓存中间件，专门处理缓存失效时的极端场景。

2. guard 模块处理两个核心问题。防穿透：某个 key 查不到数据，请求直接穿透到数据源，如果大量不存在的 key 同时打进来就是灾难。对策是——查询结果为空的 key 也缓存，TTL 设短一点（30 秒），同时用布隆过滤器记录"一定不存在"的 key 集合。下次查同样的 key 先过布隆过滤器，能拦住大部分无效请求。

3. 防雪崩：大量 key 集中在同一秒过期。对策是 TTL 加随机偏移量——配置 TTL 300 秒时，实际过期时间是 270 到 330 秒之间随机。另一个对策是回源排队——cache 模块保证同一个 key 同时只有一个回源请求在执行，后来的请求等第一个结果出来直接复用，不重复打数据源。

4. 数据源通过回调函数定义，guard 模块不关心数据源是什么。容量满了走 LRU 淘汰。淘汰时如果数据源不可用，被淘汰的 key 就暂时丢了，下次查询重新加载。queue 模块管理回源排队和等待通知。handler 模块包装 HTTP 接口。端口 PORT 环境变量。
