先搭建分片注册中心的基本框架——按服务名哈希把注册信息分到不同实例上，分散单点压力。Spring Boot 实现。

shard 模块管理分片逻辑。注册中心实例列表通过配置接口管理，支持动态扩缩。每个实例负责一部分服务名的分片——分片归属用一致性哈希确定，加删实例时只影响相邻的分片。新实例加入或旧实例下线时触发分片重新分配，重新分配是渐进式的不是一次性搬迁。

registry 模块处理服务注册。实例注册时按服务名算哈希找到负责的注册中心，把注册信息——IP、端口、元数据、心跳间隔——写进去。同一个 IP+端口重复注册做覆盖更新。心跳超时的实例自动注销，注销后 resolver 模块通知所有订阅该服务的客户端，通知通过回调地址异步推送。

syncer 模块处理分片迁移。分片重新分配后，原来负责的实例要把属于新实例的数据迁移过去。迁移过程中新的注册请求照常处理——写到新的负责实例上。查询可能暂时不完整，等迁移完就好了。客户端在迁移期间重试查询能拿到最终一致的结果。

resolver 模块提供查询接口——按服务名过滤、按健康状态过滤，查询请求自动路由到负责的分片实例。Maven 构建，端口写在配置文件里。
