传统的健康检查是中心化探活——一个探活服务盯着几百个节点，单点压力大还有延迟。心跳网格换个思路：节点之间互相检测，分散探测压力。Rust actix-web 实现。

节点注册到 mesh 模块后加入网格。注册信息包含地址、端口和检测间隔。节点列表通过接口管理，支持动态扩缩。节点下线后超过 3 个检测周期没响应自动移除。新加入的节点初始状态是 unknown，等第一轮检测完成后变 alive。

heartbeat 模块实现互相检测。每个节点按配置的间隔向其他节点发 HTTP GET 心跳。连续 3 次无响应标记为 suspect。suspect 状态持续 2 个检测周期后升级为 dead。suspect 期间如果收到该节点的心跳，立即恢复为 alive。detector 模块运行在每个节点上的检测逻辑是独立的——不存在全局调度器。

状态变更通过 gossip 协议在网格内传播。每个节点每秒随机挑一个邻居交换状态摘要，发现差异就更新本地视图。传播延迟控制在 2 秒以内。每个节点维护完整的全网格状态视图。

handler 模块提供查询接口——查单个节点状态或全网格视图。状态枚举：alive、suspect、dead、unknown。Cargo build，端口 PORT 环境变量。
