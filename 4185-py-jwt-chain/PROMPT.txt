JWT 验证从来不只是检查签名那么简单——过期了怎么办、被吊销了怎么办、这个角色有没有权限访问这个接口。FastAPI 做一个链式验证网关，把验证拆成独立环节串联起来。

chain 模块管理验证链。请求到达后按顺序经过多个验证步骤：签名验证 → 过期检查 → 权限检查 → 速率限制。每个步骤独立配置开关和参数。步骤之间共享上下文——比如 issuer 模块从 JWT 里解析出 user_id 和 roles，传给后续的权限检查步骤用。

签名验证支持 HS256 和 RS256 两种算法。密钥通过接口管理，支持轮换——新密钥签发的 token 用新密钥验，旧 token 在过渡期内用旧密钥也能验。过期检查要处理时钟偏移，允许 ±30 秒的容差。

validator 模块做权限检查。JWT 的 roles 字段决定权限，每个接口路径绑定需要的角色列表，满足任一即可。角色和路径的绑定关系通过接口管理，支持通配符。

revoke 模块维护令牌黑名单。被吊销的 JWT 用 jti 字段标识，加入内存黑名单。黑名单 TTL 和 JWT 的剩余有效期一致，过期自动清理。同一个 token 多个并发请求同时到达时，黑名单查询要做读写保护。端口 PORT 环境变量。
