分布式事务里最头疼的不是正向执行，而是执行到一半失败了怎么办。直接回滚？数据状态不确定。不管？脏数据留着更麻烦。FastAPI 做一个基于 Saga 模式的补偿事务管理器，每一步正向操作都有对应的补偿操作兜底。

saga 模块定义事务编排。一个长事务拆成多个步骤，每个步骤包含名称、正向调用地址、补偿调用地址和超时时间。步骤按顺序执行，前一个步骤的响应可以引用到后一个步骤的请求参数里——比如步骤 1 返回 orderId，步骤 2 的请求参数里用 ${orderId} 引用。

compensator 模块驱动状态机：pending → running → completed / compensating → compensated / failed。running 过程中某步正向执行失败，触发补偿——已经成功执行的步骤按反向顺序执行补偿操作。补偿操作本身也可能失败，失败的补偿记录到 journal 模块，标记为需要人工介入。

journal 模块记录每个步骤的执行和补偿细节：请求内容、响应内容、开始结束时间、状态。事务可以按 ID 查询完整执行链路。

handler 模块包装 REST 接口。步骤的调用地址响应格式不固定——JSON、纯文本、甚至 XML 都要能处理，compensator 不做格式校验只透传。端口 PORT 环境变量。
