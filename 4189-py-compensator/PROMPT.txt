重试要做好补偿，不然数据就乱了。FastAPI 做一个补偿事务管理器。
Saga 模式：一个长事务拆成多个步骤。每个步骤有正向操作和补偿操作。正向操作失败时，已经执行的步骤按反向顺序执行补偿。补偿操作也可能失败，失败的补偿记录下来人工处理。
步骤定义：步骤包含名称、正向调用地址、补偿调用地址、超时时间。步骤按顺序执行。前一个步骤的响应可以引用到后一个步骤的请求参数里。
事务状态：pending → running → completed / compensating → compensated / failed。running 过程中某步失败进入 compensating。compensating 完成进入 compensated。补偿也失败进入 failed。
事务日志：每个步骤的执行结果和补偿结果都记录。日志包含请求和响应内容。事务可以按 ID 查询完整执行链路。
执行步骤和补偿步骤的接口响应格式不确定，有的可能是 JSON 有的可能是纯文本，都得能处理。至少包含 compensator、saga、journal、handler 四个模块。端口 PORT 环境变量。
