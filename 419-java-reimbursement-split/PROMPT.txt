财务要求报销可以拆分到多个成本中心。做一个报销拆分API，一笔报销指定多个成本中心各分配百分比，所有百分比加起来必须正好100%，允许的最小分配单位是1%。比如差旅6000元，60%归属研发中心、40%归属市场中心。每个成本中心负责人都要审批通过。任一负责人驳回整笔回到待修改状态让员工重新调整，已经通过的审批全部清零重新走。审批过程中员工不能修改已提交的分配比例，必须等驳回后才能改。查询能看到每笔报销的分配明细和各中心审批状态。同一笔报销拆分的成本中心数量不超过5个，超过的话需要走特殊审批流程。已通过全部审批的报销单金额会自动汇总到各成本中心的月度支出报表中，用于后续预算对账。
审批过程中员工不能修改已提交的分配比例，必须等驳回后才能改。同一笔报销拆分的成本中心数量不超过5个，超过需要走特殊审批流程。已通过全部审批的报销单金额自动汇总到各成本中心的月度支出报表中用于后续预算对账。每个成本中心独立核算，拆分比例精确到1%不允许小数成本中心负责人审批通过后财务进行最终复核，复核通过才进入打款流程。每个成本中心每月的报销总额汇总后与预算系统对接做超支预警。金额用 BigDecimal 处理，不能用 double 或 float。DTO 类手写 getter/setter，不用 Lombok。

Maven 多模块项目结构。根目录 parent POM 负责依赖版本管理。公共模块（common）封装 DTO 类、请求响应格式及错误码定义。服务端模块（server）是 Spring Boot 应用，监听端口对外提供 REST 接口，所有业务逻辑在内存中处理。客户端模块（client）是纯 Java 命令行程序，不依赖 Spring，通过 HTTP 调用 server 的 REST 接口并将返回数据格式化展示在终端。各模块按职责分包。禁止使用 Lombok 注解处理器。Java 17，mvn clean package 一键构建成功。

本项目属于跨系统多模块架构。
