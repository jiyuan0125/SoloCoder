线上最怕的不是某个节点挂了——挂了自然有其他节点接——怕的是故障转移不干净，请求在坏节点上卡半天超时。Spring Boot 做一个带故障转移能力的负载均衡器。

balancer 模块管理节点池。每个服务有一组后端节点，节点有健康状态和权重。健康检查通过 HTTP GET 探活，每 10 秒一次。节点可以手动上下线——下线的节点不再参与分配但保留在列表里，上线后恢复。

failover 模块处理请求分配。默认启用会话保持——同一个客户端 IP 的请求优先发到同一节点。节点故障后，这个节点上的请求转移到负载最低的健康节点。负载计算综合考虑活跃连接数和节点权重。故障节点恢复后，之前转走的请求不自动切回——避免来回抖动。

detector 模块做故障检测。连续 3 次探活失败标记为故障，故障后降低探测频率改为每 10 秒一次。连续 2 次成功恢复。故障和恢复都触发通知。节点地址为空或格式不对的注册请求返回 400。

switchover 模块记录每次故障转移的详情——哪个节点的请求转到了哪个节点、转移原因、时间戳。权重为 0 的节点不参与分配但保留，负权重当 0 处理。Maven 构建，端口写在配置文件里。
