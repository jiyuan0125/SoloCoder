前端同事抱怨一个页面要调 5 个接口，首屏加载两秒起步。Go 标准库做一个 API 组合网关——前端发一个请求，后端聚合多个数据源一次性返回。

composer 模块定义虚拟接口。每个虚拟接口路径绑定多个后端调用，调用模式分并行和串行两种。并行模式下所有后端同时发起请求，任一超时不影响其他，结果按配置的顺序合并。合并策略支持三种：字段取值（取某个后端的指定字段作为最终结果的字段）、数组拼接（多个后端返回的列表拼成一个）、取第一个非空值。

串行模式由 reverse 模块处理。按顺序执行后端调用，前一个响应可以用 {{response.field}} 语法引用到后一个请求的参数里。引用路径支持嵌套和数组索引，比如 data.items[0].id。串行调用中如果前面某步失败，后续步骤跳过，最终结果中标记失败的部分。

aggregator 模块处理响应聚合逻辑和错误处理。cache 模块提供响应缓存——按虚拟接口路径 + 请求参数的 SHA256 做 key，TTL 可配。相同参数的请求直接返回缓存。后端数据更新时需要手动调失效接口清除缓存。端口 PORT 环境变量，go build 能过。
