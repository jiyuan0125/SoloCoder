普通缓存代理读到空就让调用者自己去回填——每个调用者都得写一遍"查缓存→miss→查后端→写缓存"的逻辑。Rust axum 做一个 Read-Through 缓存代理，回填内置，调用者只管读。

cache 模块管理 KV 存储，支持 TTL 和最大容量。容量满了用 LFU 淘汰——频次最低的先清。淘汰时如果后端不可用（探测失败），被淘汰的 key 就暂时丢了，下次读的时候重新加载。

loader 模块处理读路径。请求到达先查缓存，命中直接返回。未命中时从后端 HTTP 服务获取数据，写入缓存再返回。关键点是并发控制：同一个 key 同时只有一个回填请求在执行，后来的请求等第一个结果出来直接复用，不重复打后端。

写请求同时更新缓存和后端。后端写入失败时不更新缓存，保证一致性。后端成功但缓存更新失败时，标记该 key 为失效状态，下次读取时重新从后端加载。

invalidator 模块处理缓存失效——单 key 失效和按前缀批量失效。前缀失效需要扫描全量 key 做匹配。后端数据变更时需要主动调失效接口通知。handler 模块包装 REST 接口。Cargo build，端口 PORT 环境变量。
