普通的缓存代理读不到就让调用者自己处理回填逻辑。Read-Through 模式把回填内置到代理里。Rust axum 实现一个 Read-Through 缓存代理。
缓存存储：KV 结构，支持 TTL 和最大容量。容量满了用 LFU 淘汰。淘汰时如果后端不可用，被淘汰的数据就丢了。
读请求：请求到达后先查缓存。命中直接返回。未命中时从后端 HTTP 服务获取数据，然后写入缓存。回填时有并发控制：同一个 key 同时只有一个回填请求。其他请求等结果。
写请求：同时更新缓存和后端。后端写入失败时不更新缓存（保证一致性）。后端写入成功但缓存更新失败时标记缓存失效，下次读时重新加载。
缓存失效：支持单 key 失效和按前缀批量失效。前缀失效时扫描所有匹配的 key。失效后端存储的数据变更时需要主动通知缓存失效。
用户输入的 key 值直接用于缓存查找和后端请求。代码分 cache、loader、invalidator、handler 四个模块。Cargo build，PORT 环境变量。
