先是调研了一圈现有方案——Hystrix 停更了，Resilience4j 是 Java 的，Python 这边真没什么好用的。用 FastAPI 做一个自适应熔断器，核心思路是根据系统负载动态调整熔断阈值，不用人工盯着改参数。
先说熔断判定：熔断器跟踪最近N次调用的成功率和响应时间，成功率低于阈值或者慢调用比例超过阈值就触发熔断。再说自适应——阈值不是写死的，系统整体CPU和内存负载低的时候阈值放宽（允许更多失败），负载高的时候阈值收紧（更早触发熔断）。负载指标暴露一个 HTTP 端点，格式兼容 Prometheus，其他服务可以直接 scrape。
然后是降级逻辑：熔断打开后走降级，返回缓存数据或者默认值。降级策略按接口粒度配置，不同接口可以配不同的降级响应，支持返回固定JSON、返回最近一次成功的缓存值、或者直接返回错误三种模式。半开状态放少量请求探测（默认5个），全部成功就关闭熔断，有一个失败就回到打开状态。
熔断器状态变更要记日志，包括变更时间、旧状态、新状态、触发原因。自适应参数调整的时候也记日志，记录调整前后的阈值和当时的负载值。breaker 做熔断判定，policy 管自适应策略，fallback 处理降级，monitor 暴露指标端点。
