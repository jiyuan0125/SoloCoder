线上有个 Redis 缓存实例，但实际只用来存会话数据和配置信息，引入外部依赖增加了运维成本，每次 Redis 升级或者网络抖动都是事故。用 Rust actix-web 写一个嵌入式 LFU 缓存服务，把它替换掉。
1. 缓存淘汰策略用 LFU（最不经常使用），访问频率最低的先淘汰。频率相同的用 LRU（最近最少使用）打破平局。每个 Key 可以设置独立的 TTL。TTL 到期的 Key 自动清理，跟 LFU 淘汰互不影响——两种淘汰机制各自独立运行。
2. 缓存数据全在内存里，不持久化。服务重启后缓存是空的，上层应用需要自己处理缓存穿透（可以用预热接口）。缓存容量有上限（默认100万条），超过上限触发淘汰。
3. 缓存命中率、总Key数、淘汰次数、内存占用估算这些统计数据暴露一个查询端点，方便接入监控告警。
Key 的操作有：SET（创建或更新）、GET（读取，同时增加频率计数）、DELETE（删除）。GET 已过期的 Key 返回不存在，同时触发后台清理。新写入的 Key 如果超过容量上限，触发一次批量淘汰（淘汰到容量低于90%）。淘汰过程中读请求正常处理。cache（存储核心）、policy（淘汰策略引擎）、stats（统计聚合）、api（HTTP接口）四块代码。
