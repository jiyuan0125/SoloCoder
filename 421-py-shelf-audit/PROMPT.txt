仓库管理要精确到每个库位。做一个货架管理API，仓库划分区域（A区B区等），每个区域有多个货架，货架有多层多列库位。库位编码：区域字母+货架号+层号+列号，如A-03-02-05。商品入库自动分配空闲库位，分配策略优先选择同区域同商品已有库位的相邻位置。出库释放库位。同一个库位不能同时放不同种类商品，要放新种类必须先把原来的清空。同一种商品可以分散在多个库位，但单个库位有容量上限。出库时遵循先进先出原则——优先从入库时间最早的库位出货。库位盘点功能：发起盘点时锁定相关库位不允许出入库操作，盘点完成后自动比对系统记录和实际数量生成差异报告。双向查询：查库位放了什么商品，查商品存在哪些库位。库位容量上限可按商品体积动态计算库位状态有五种：空闲、已占用、已锁定、盘点中、维护中。维护中的库位不能进行出入库操作。库位容量超载时自动告警提示仓库管理员及时处理。金额计算使用 Decimal 类型，不能用 float。所有模型继承 Pydantic BaseModel，字段校验用 Field 约束。

分配策略优先选择同区域同商品已有库位的相邻位置减少拣货路径。出库时遵循先进先出原则优先从入库时间最早的库位出货。库位盘点功能：发起盘点时锁定相关库位不允许出入库操作，盘点完成后自动比对系统记录和实际数量生成差异报告。库位容量上限可按商品体积动态计算库位状态有五种：空闲、已占用、已锁定、盘点中、维护中。维护中的库位不能进行出入库操作。库位容量超载时自动告警提示仓库管理员及时处理。

用 Python 写，分三个包。共享包（shared/）定义 Pydantic 的数据模型、通信协议和错误码。服务端包用 FastAPI 框架监听端口提供 HTTP 接口，处理所有业务请求，数据保存在内存中。客户端是一个 CLI 程序，支持子命令和参数，通过 HTTP 请求调用服务端，结果格式化输出到终端。三个包各自有独立入口，根目录 pyproject.toml 统一管理依赖。各包内部按职责分模块。全量类型注解，函数参数和返回值都要标注类型，使用 mypy strict 模式检查。用 uv 管理依赖，uv sync 即可安装，uv run python -m server 能启动服务端。

本项目属于跨系统多模块架构。
