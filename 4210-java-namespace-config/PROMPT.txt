五十多个微服务的配置散落在各自的配置文件里，改一个配置要重启好几个服务，上了生产还经常漏改某个实例——这种痛谁懂？用 Spring Boot 搞一个配置中心把它统一管起来。
配置按命名空间隔离：dev、test、prod 三个环境各一套独立的KV。同一个Key在不同命名空间的值不同。命名空间之间支持继承关系——子空间没有的Key从父空间继承值，有的话覆盖父空间的值。比如 dev 继承 test 的配置，只需要覆盖数据库地址等少量差异项。
应用启动时从配置中心拉取自己需要的配置（通过应用名和命名空间定位）。拉取失败时使用本地缓存的上次配置，不能因为配置中心不可用导致应用起不来。应用可以订阅某个Key的变更通知，配置变更时推送给订阅者。推送失败的记录下来，后台定时重试，超过3次标记该实例为推送异常。
配置有全局递增版本号，每次变更版本号加一。可以查询某个Key的完整历史版本和变更人。可以回滚到指定版本，回滚操作也产生新版本。变更审计日志记录谁在什么时候改了什么，谁审批的。config（配置CRUD）、namespace（命名空间管理）、watch（变更推送）、audit（审计日志）。Maven 构建。
