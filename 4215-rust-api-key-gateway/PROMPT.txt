API 开放平台的认证怎么搞？JWT 不适合第三方调用场景，OAuth 又太重了。Rust tokio 写一个 API Key 认证网关，轻量够用。
每个 API Key 创建时指定名称、调用频率限制（比如每分钟100次）、IP白名单（可选）、过期时间。Key 的值自动生成（32位随机字符串，不可自定义）。白名单不在的请求直接返回403，不过限流逻辑。Key 过期后自动失效，不会自动续期。限流超限返回429，响应头带 Retry-After。
Key 的状态有四种：活跃（正常使用）、暂停（所有请求拒绝但Key还在，可以恢复）、过期（不可恢复，需要重新创建）、已吊销（不可恢复，用于安全事件应急）。暂停的Key可以恢复为活跃，过期和吊销都是终态。吊销操作有二次确认接口，防止误操作。
Key 使用统计按分钟聚合：调用次数、被限流次数、错误次数（4xx+5xx）。统计数据按Key查询，也支持按时间段筛选。统计保留最近24小时的数据，过期自动清理。
新Key创建时如果指定了已存在的Key名称，要拒绝创建（名称唯一）。Key的列表和详情通过管理端点查询，列表支持按状态过滤，支持分页。auth（认证和校验）、key（Key生命周期管理）、ratelimit（限流逻辑）、stats（统计聚合）各管一摊。
