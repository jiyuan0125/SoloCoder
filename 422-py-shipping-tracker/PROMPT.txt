物流追踪要给客户实时信息。做一个物流跟踪API，创建运单后通过添加节点更新状态。节点类型有已揽收、运输中、到达中转站、派送中、已签收，每个节点记录时间和地点。运单超过72小时没有新节点自动标记异常，异常运单每天生成一次告警直到有新节点更新。签收必须填签收人姓名，签收后不能再加新节点。新增节点时时间不能早于上一个节点的时间，地点信息不能为空。运单支持拆分——一个大运单拆成多个子运单分别派送，子运单各自独立跟踪但都关联主运单号。客户查询返回完整物流轨迹按时间正序排列。运单状态变更自动记录操作人（哪个快递员或系统操作）和变更时间。批量查询一次最多50个运单号。日期时间使用 datetime 模块，时区统一用 UTC。异常处理不能裸 except，必须指定具体异常类型。

异常运单每天生成一次告警直到有新节点更新。运单支持拆分——一个大运单拆成多个子运单分别派送，子运单各自独立跟踪但都关联主运单号。运单状态变更自动记录操作人和变更时间。批量查询一次最多50个运单号。签收时支持代签收，代签收需填写代签收人姓名和与收件人关系物流轨迹支持地图可视化数据输出——返回每个节点的经纬度坐标。运单创建时自动生成唯一运单号，编码规则为年月日加6位流水号。国际运单额外记录海关报关状态。

做成 Python 多包项目。shared/ 包放 Pydantic 的请求响应模型、协议定义和错误码常量。server/ 包基于 FastAPI 监听端口提供 HTTP 接口，处理所有业务请求，数据保存在内存中。cli/ 包是命令行工具，支持子命令和参数，通过 HTTP 请求调用服务端，结果格式化输出到终端。三个包各自有独立入口，根目录 pyproject.toml 统一管理依赖。各包内部按职责分模块。全量类型注解，函数参数和返回值都要标注类型，使用 mypy strict 模式检查。uv sync 能安装依赖，uv run python -m server 能启动服务端。

本项目属于跨系统多模块架构。
