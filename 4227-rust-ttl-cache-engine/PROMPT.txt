业务上需要个小缓存——存一些计算结果和配置信息，用 Redis 纯属杀鸡用牛刀，每次 Redis 网络抖动都是一次小事故。Rust tokio 的 async runtime 做缓存服务刚好，不需要外部依赖，也不需要额外运维。
1. TTL缓存服务，每个Key带过期时间。过期Key读的时候发现已过期就删除并返回不存在。TTL可以设置全局默认值（默认1小时），也可以每个Key单独设置。单独设置优先于全局默认。不设置TTL的Key永不过期（除非被LRU淘汰）。
2. 缓存容量有上限（默认100万条）。容量满时新写入触发LRU淘汰——淘汰最近最少访问的Key。淘汰的时候如果被淘汰的Key有TTL还没到期，也算淘汰（容量优先于TTL，容量满了就是满了）。淘汰是批量操作，一次淘汰到容量低于90%。
3. 缓存支持批量操作：批量获取（返回存在的Key和不存在的Key列表）、批量设置（所有KV对原子写入）、批量删除（返回实际删除的数量）。批量操作是原子的——要么全部成功要么全部失败，中间出错的整个批量回滚。
管理端点可以查看缓存容量使用率、命中率、淘汰次数、Key总数。cache（存储核心）、ttl（过期管理）、eviction（LRU淘汰策略）、batch（批量操作接口）四个模块。
