公司多仓库之间经常调拨库存。做一个库存调拨API，发起调拨单指定源仓库、目标仓库、商品和数量。调拨单状态：待确认→已确认→运输中→已到达→已入库。源仓库被调拨的库存要冻结，不能被其他出库单使用，冻结的库存在库存查询中要单独显示。到达目标仓库并完成入库后，正式扣减源仓、增加目标仓、解冻。中途取消只解冻源库存不影响目标仓。运输中可能有损耗，实际到达数量可能少于发出数量，允许修改实际入库数量，损耗部分记入损耗台账。一个调拨单可以包含多种商品，每种商品独立跟踪数量。调拨单审批：调拨金额超过1万元需要仓库主管审批，超过5万元需要物流总监审批。提供调拨单查询和各仓库库存总览。金额计算使用 Decimal 类型，不能用 float。默认参数不能使用可变对象（如列表、字典），必须用 None 代替。

一个调拨单可以包含多种商品，每种商品独立跟踪数量。调拨单审批：调拨金额超过1万元需要仓库主管审批，超过5万元需要物流总监审批。提供调拨单查询和各仓库库存总览。调拨完成后自动更新两个仓库的库存报表。损耗台账按月统计损耗率和损耗金额供管理层审批调拨单支持打印调拨出库单和调拨入库单供仓管人员签字确认。跨公司调拨需要额外审批流程。调拨完成后系统自动生成库存变动流水供对账使用。

用 Python 写，项目结构分成三个包。共享包（shared/）里放 Pydantic BaseModel 的数据结构、API 协议定义和错误码枚举。服务端包（server/）用 FastAPI 起一个 HTTP 服务，处理全部业务逻辑，数据存在内存中。命令行包（cli/）提供子命令式的交互工具，发 HTTP 请求到服务端，把结果格式化打印到终端。三个包各有独立入口，根目录 pyproject.toml 统一管依赖。各包内部按职责分模块。全量类型注解，函数参数和返回值都要标注类型，使用 mypy strict 模式检查。uv sync 安装依赖，uv run python -m server 启动服务端。

本项目属于跨系统多模块架构。
