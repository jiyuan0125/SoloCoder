| User Prompt | 采购流程中管供应商报价很繁琐。做一个报价管理API，采购需求发布后多个供应商提交报价（单价、承诺交货期、备注）。截止时间过后不能再提交，截止前可以多次修改覆盖最新一次为准。查询时同一供应商的修改历史要能看到，包括每次修改的时间和内容差异。采购方选择中标供应商后自动生成采购订单。未中标的供应商看到中标信息，但中标价格要脱敏——只显示比自己高还是低，不显示具体数字。报价有效期默认30天，过期后自动标记为失效。供应商资质等级（A/B/C三级）影响采购方选择时的权重，同条件下优先选高等级供应商。提供比价报表——按商品列出所有供应商报价的排名和价格分布。金额计算使用 Decimal 类型，不能用 float。所有模型继承 Pydantic BaseModel，字段校验用 Field 约束。 报价有效期默认30天，过期后自动标记为失效。供应商资质等级（A/B/C三级）影响采购方选择时的权重，同条件下优先选高等级供应商。比价报表按商品列出所有供应商报价的排名和价格分布。报价截止时间前最后一天提交的报价为迟到报价，系统标记但不拒绝采购方可自行决定是否纳入评选供应商基本信息管理——名称、联系人、电话、地址、资质等级。资质等级每年评审一次，评审结果影响后续采购权重。新供应商注册后需要审核通过才能参与报价。 整个系统用 Python 实现分成三个包。共享包 shared/ 存放 Pydantic 数据模型、请求响应协议和错误码常量。服务端包 server/ 用 FastAPI 框架监听 HTTP 端口处理所有业务，数据存内存。客户端包 cli/ 是一个命令行程序，通过子命令向服务端发请求并展示返回结果。三个包各自有独立入口，根目录 pyproject.toml 统一管理依赖。各包内部按职责分模块。全量类型注解，函数参数和返回值都要标注类型，使用 mypy strict 模式检查。用 uv 管理依赖，uv sync 即可安装，uv run python -m server 能启动服务端。 本项目属于跨系统多模块架构。 |
