试了三个现成消息队列都不满足我们的事件流需求，只能 Java Netty 自己写。
消息按事件流组织。每个流有一个名称。消息追加到流的末尾（只追加不修改）。消费者可以指定从哪个位置开始消费。消费进度独立维护，不同消费者互不影响。
消息有序号，严格递增。消费者可以按序号范围查询历史消息。流有保留策略：按时间保留（超过N天的删除）或按条数保留（超过N条的删除）。
多个消费者可以组成消费者组。组内消息只投递给一个消费者（点对点）。消费失败的消息组内重试。组内所有消费者都失败了才进死信队列。
流的创建通过接口完成。创建时指定保留策略。至少包含 stream、consumer、group、retention 四个模块。
