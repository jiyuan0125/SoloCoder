Nacos 那一套我们只用到了十分之一的功能——配置热加载和变更推送。剩下的服务发现、集群管理、权限控制全是摆设。Spring Boot 自建一个轻量的热加载配置中心，只做配置管理这一件事。
配置KV存储，Value支持四种类型：字符串、数字、布尔、JSON对象。应用启动时从配置中心拉取自己需要的配置（通过应用名和命名空间定位）。拉取失败时使用本地缓存的上次配置——不能因为配置中心不可用导致应用起不来。运行时通过长连接接收变更推送，推送时带上配置的版本号，应用可以判断是否需要更新。
配置变更有版本号（全局递增）。每次修改版本号加一。可以查询某个Key的完整历史值和版本号。可以回滚到指定版本——回滚操作产生新版本号（不是删除历史版本）。回滚也可以撤销，撤销也是一次新的变更。
应用可以订阅Key的变更——订阅信息记录应用名、实例IP、订阅的Key列表。推送失败时记入重试队列，重试间隔递增（1秒、2秒、4秒），超过3次标记该实例为推送异常，不再推送但保留订阅关系（实例恢复后可以重新订阅）。推送异常的实例在管理界面上标红显示。
配置项的增删改查通过REST接口。config（配置CRUD）、version（版本管理）、push（变更推送）、subscription（订阅管理）。Maven 构建。
