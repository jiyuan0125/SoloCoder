之前用过 Redis 做缓存——但敏感数据脱敏处理不够灵活，每次改脱敏规则得改业务代码。Spring Boot 自己写一个，脱敏规则跟着缓存配置走。KV 存储，可以设 TTL。值支持字符串、数字、JSON。Key 已存在时可以选覆盖或者跳过，用 PUT 强制覆盖，用 PUTIFABSENT 只在不存在时写入。写进来的如果是 JSON，自动把字段抽出来建二级索引——比如值是 {"name":"张三","age":30}，那通过 name 或 age 字段也能查到这条。
标了敏感的 Key，写入之前自动 AES 加密，密钥从配置文件读。查询时返回脱敏值——字符串中间打星号、数字只留首尾——有权限的请求（带 X-Decrypt header）才能拿原文。注意安全：用户提交的查询条件直接拼到缓存 Key 里去了，得做校验和转义，防止注入。
淘汰方面 LRU 和 TTL 过期都支持，LRU 淘汰时最久没访问的先走。容量满了按策略清，清的时候如果数据被标了持久化，就先写到后端存储再删，后端存储用 SQLite。缓存命中率、淘汰次数、当前容量这些指标接口可查。模块拆 cache、crypto、eviction、index。Maven 构建，端口写配置文件。
