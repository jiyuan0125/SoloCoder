业务上遇到个问题：多个服务实例同时抢同一个资源，结果同一个订单被处理了两次。打算用 Spring Boot 搞个分布式锁服务。两步搞定——第一步拿锁，第二步用完还回去。
1. 客户端来请求锁，同一个锁同时只能一个人拿着。拿的时候说好要持多久（租约，默认 30 秒），拿到后返回锁 ID 和过期时间。拿不到就排队等，队列按请求时间排序，先来先得。
2. 租约快到了可以续，续成功就延长，续期有次数上限（默认 10 次），到上限了强制释放。到期了自动释放，不用等客户端主动还。也可以主动放，但得验证是不是自己拿着的——拿锁时返回的 ID 放过来比对，不匹配就拒绝。
3. 万一出现死锁——锁持有时间超过最大租约的 3 倍——直接强制释放并告警，告警走 HTTP 回调。等待队列里等不及的可以取消，取消后通知下一个排队的。队列里的等待者有超时，超过 60 秒自动移除。
4. 锁的当前状态——谁拿着、什么时候过期、队列里有谁——都可以通过接口查。锁的获取和释放都记日志，包含锁名、持有者、操作类型和时间戳。系统里所有锁的概览也能查——当前有多少锁在使用、多少在等待、平均持有时长，方便运维巡检。模块拆 lock、lease、queue、detector。Maven 构建，端口写配置文件。
