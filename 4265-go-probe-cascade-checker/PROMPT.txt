服务挂了上游能感知到吗？光靠心跳不够，还得有级联检查。Go 标准库写一个级联健康检查器。探针分 HTTP 和 TCP 两种，每个探针配目标地址、检查间隔（默认 5 秒）、超时（默认 3 秒）、健康阈值和不健康阈值。探针状态有健康、不健康、未知三种，刚注册的算未知。
服务之间有依赖关系，比如网关依赖后端 A 和后端 B，后端 A 又依赖数据库。后端 A 挂了，网关也跟着标降级（degraded）。依赖关系通过接口配，配的时候要校验不能出环。查询可以按单个服务查，也可以按整棵依赖树查——返回树状结构，每个节点的状态一目了然。
状态流转规则：未知连续 N 次成功变健康，健康连续 N 次失败变不健康，反过来也一样，N 的值每个探针独立配。每次变更记下时间和原因，历史保留最近 200 条。级联检查是异步的——探针检测到状态变了，丢到队列里，级联检查器从队列消费后向上传播。
有个细节：根服务（没有上游依赖它的服务）挂了，不触发级联，只记录状态变更。叶子服务（没有下游依赖的服务）挂了，级联传播到所有上游。模块拆 probe、cascade、status、history。端口 PORT 环境变量，go build 能过。
