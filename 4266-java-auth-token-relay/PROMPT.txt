线上认证服务是多租户的，但 Token 签发都是同一套密钥，租户之间数据隔离出了问题。重写一个，Spring Boot 实现。用户登录后签发 JWT，里面放用户 ID、角色和租户 ID，三个字段缺一不可。签名用租户自己的密钥，密钥走接口管理——每个租户独立配 HS256 或 RS256 的密钥，各租户互不干扰。密钥轮换时新旧密钥共存一段时间，旧 Token 在共存期内还能验过。
请求来了验签名和过期时间，过了就把用户信息塞进请求上下文——后续的鉴权逻辑直接从上下文拿，不用再解析。Token 过期了可以用 Refresh Token 换新的，Refresh Token 管七天，一个 Refresh Token 只能换一次，用完旧的进黑名单。
还得把外部系统的 Token 转成内部的。转换规则按租户配——外部用户标识通过映射表对应到内部用户，映射表走接口维护。用户信息从外部系统接口拿，外部接口返回的字段映射到内部 JWT 的标准字段。转换后的 Token 不能带外部系统的敏感信息，只保留内部需要的字段。黑名单也按租户隔离，查黑名单时带租户 ID。模块拆 issuer、validator、converter、blacklist。Maven 构建，端口写配置文件。
