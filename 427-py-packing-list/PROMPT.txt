仓库出库要把一个订单的商品分装到多个包裹。做一个装箱管理API，出库订单可拆分成多个包裹，每个记录箱号、尺寸和重量。每个包裹总重不超过30公斤、总体积不超过0.1立方米。单品本身超过30公斤必须单独装一箱不能混装。装箱完成后如果订单被修改（减少某件商品数量），系统要重新校验所有已装包裹，不合规的自动标记需要重新装箱。易碎品和液体必须放在包裹最底层并用"易碎"标签标记。装箱时自动计算填充物体积，确保包裹内物品总体积不超过包裹容积的80%留出缓冲空间。提供按订单查询装箱明细和生成格式化装箱单文本——包含箱号、商品清单、尺寸重量和总箱数。已发出的包裹记录不可删除只可追加物流单号。默认参数不能使用可变对象（如列表、字典），必须用 None 代替。所有模型继承 Pydantic BaseModel，字段校验用 Field 约束。

易碎品和液体必须放在包裹最底层并用易碎标签标记。装箱时自动计算填充物体积，确保包裹内物品总体积不超过包裹容积的80%留出缓冲空间。已发出的包裹记录不可删除只可追加物流单号。装箱方案支持保存为模板，相似订单可以复用历史装箱方案减少重复操作装箱完成后生成唯一装箱单号供物流追踪使用。包装材料消耗统计——每种箱型使用数量和剩余库存。装箱方案优化建议——系统根据商品尺寸自动推荐最佳装箱组合。

项目用 Python 实现，结构为三个包。shared/ 是共享包，存放 Pydantic 的请求响应模型、通信协议定义和错误码常量。server/ 包用 FastAPI 框架监听端口提供 HTTP API，处理所有业务逻辑，数据存在内存中。cli/ 包是命令行工具，支持子命令和参数，通过 HTTP 调用服务端，结果格式化输出到终端。三个包各自有独立入口，根目录 pyproject.toml 统一管理依赖。各包内部按职责分模块。全量类型注解，函数参数和返回值都要标注类型，使用 mypy strict 模式检查。uv sync 安装依赖，uv run python -m server 启动服务。

本项目属于跨系统多模块架构。
