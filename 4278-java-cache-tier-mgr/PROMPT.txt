Redis 做缓存启动慢、运维成本高——我们只需要 KV 缓存，Spring Boot 写一个多级缓存管理器。两级缓存串联：L1 是本地内存（Guava Cache 风格），L2 是持久化缓存（文件或 SQLite）。查的时候先 L1，miss 了查 L2，再 miss 查数据源。数据源查到的回写到 L2 和 L1，回写是同步的，确保下次查能命中。
L1 用 LRU 淘汰，容量上限可配（默认 1 万条）。L2 用 TTL 过期，默认 24 小时。L1 满了清最久没用的，清的时候如果 L2 也没有，就标记为完全淘汰——下次查只能走数据源。
数据源更新时通过接口通知缓存失效，POST /cache/invalidate 传 key 或 key 前缀批量失效。也可以主动预热——POST /cache/warm 批量从数据源加载到 L1 和 L2，预热按队列顺序来，防止瞬间把数据源打爆。
L1 和 L2 的数据得一致——更新操作同时写两级，先写 L1 再写 L2。写 L2 失败了回滚 L1，别出现两级数据不一致的情况。缓存命中率（L1 单独命中率、L2 命中率、总命中率）每分钟统计一次，接口可查。模块拆 tier、l1、l2、loader。Maven 构建，端口写配置文件。
