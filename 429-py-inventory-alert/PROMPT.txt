仓库需要库存预警避免断货或积压。做一个库存监控API，为每个商品设安全库存最低值和最高值。低于最低值触发低库存预警，高于最高值触发积压预警。每次预警记录触发时间、当前库存量和建议补货或促销数量。同一个商品的同一类型预警24小时内只触发一次，冷却期过后仍低于才再触发。补货入库后如果库存恢复到安全范围内自动消除对应预警。系统每天自动生成库存健康报告列出所有商品的库存状态——正常、低库存、积压。季节性商品支持设置不同月份不同的安全库存值，比如羽绒服冬季安全库存高夏季低。按商品类别和预警级别筛选查询。预警记录永久保留供分析趋势。日期时间使用 datetime 模块，时区统一用 UTC。字典遍历时不能在循环中修改字典。

补货入库后如果库存恢复到安全范围内自动消除对应预警。季节性商品支持设置不同月份不同的安全库存值，比如羽绒服冬季安全库存高夏季低。预警记录永久保留供分析趋势。低库存预警同时生成建议补货单草稿，采购可以直接确认下单库存变动实时记录——每次入库、出库、调拨都生成变动流水。支持按商品类别批量设置安全库存值，不用逐个商品手动配置。库存周转率分析帮助优化备货策略。

用 Python 写，分三个包。共享包（shared/）定义 Pydantic 数据模型、协议和错误码。服务端包（server/）用 FastAPI 监听端口提供 HTTP 接口，处理所有业务请求，数据保存在内存中。命令行包（cli/）提供子命令式工具，通过 HTTP 请求调用服务端，结果格式化输出到终端。三个包各自有独立入口，根目录 pyproject.toml 统一管理依赖。各包内部按职责分模块。全量类型注解，函数参数和返回值都要标注类型，使用 mypy strict 模式检查。用 uv 管理依赖，uv sync 即可安装，uv run python -m server 能启动服务端。

本项目属于跨系统多模块架构。
