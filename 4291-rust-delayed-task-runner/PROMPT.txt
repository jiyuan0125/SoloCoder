Rust tokio 写一个延时任务执行器——下单后 30 分钟未支付自动取消，这种场景特别常见。提交延时任务时指定延迟多久（秒）、回调哪个 HTTP 地址（POST）。任务 ID 自增，返回给调用方。没执行的可以取消——取消了就不跑也不回调，状态标为 cancelled。
用时间轮管理延时任务，精度到秒，轮子大小可配（默认 3600 格，即一小时一圈）。时间到了取出来跑，跑的是异步 HTTP 请求——用 reqwest 异步发。回调响应码 2xx 算成功，其余算失败。
回调失败按策略重试：间隔递增（1s、2s、4s、8s...），到最大重试次数（默认 5 次）标彻底失败。结果都记着——任务 ID、回调地址、每次尝试的时间和响应码。
延时超过一圈的任务用溢出列表管——挂在当前格子上，每转一圈检查一次，时间没到的重新挂回去。大量任务同时到期时排队跑——用信号量控制并发上限（默认 100），不能丢任务。任务的状态（等待中、执行中、成功、失败、取消）都可以通过接口查，也可以按状态过滤列表。时间轮当前指针位置和溢出列表大小也接口可查，方便监控调度器运行状态。模块拆 wheel、task、callback、overflow。Cargo build，端口 PORT 环境变量。
