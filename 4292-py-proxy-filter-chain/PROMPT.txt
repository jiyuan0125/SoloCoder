做了一套请求过滤代理——不是普通的反代，是在转发前做一系列校验和改写。FastAPI 实现。请求进来后挨个过过滤器，哪个过滤器不满意直接中断，返回对应的 HTTP 状态码。过滤器有四种：IP 黑白名单（黑名单返回 403，白名单内的跳过后续 IP 检查）、Header 校验（必填的 Header 缺了返回 400）、请求体大小限制（超过上限返回 413）、路径白名单（不在白名单的返回 404）。
过了过滤链的请求转发给后端，后端可以配多个地址，轮询分发。转发时塞自定义 Header——X-Request-ID（UUID）、X-Forwarded-For、X-Real-IP 这些。后端超时可配，默认 10 秒。
后端返回后还得过一遍响应过滤器——去掉内部 Header（X-Internal- 开头的）、加 CORS 头、记日志（请求路径、后端地址、耗时、状态码）。过滤器配置走接口管，增删改即时生效。
过滤器顺序很关键。比如路径白名单放在 IP 黑名单前面，那白名单里的路径就不受 IP 限制了。顺序错了安全策略就形同虚设——所以配置变更时要校验顺序，有冲突的返回 400 提示。模块拆 filter、forwarder、responder、config。端口 PORT 环境变量。
