限流组件不支持滑动窗口——固定窗口在窗口边界会被刷两倍的请求，这是个经典问题。Spring Boot 写一个。每条规则有名称、窗口大小（比如 60 秒）、阈值（比如 100 次）和维度（IP、用户、接口路径，可以多选）。规则走接口管——CRUD 都有，改了立刻生效，不用重启。
窗口按秒分片——每个分片记录该秒内的请求数。每次请求取当前秒的分片计数加上前 N-1 秒的（N = 窗口大小），总和超阈值就拒，返回 429 带 Retry-After 头。当前秒的分片在请求结束后计数减 1——因为请求已经处理完了，不应该一直占着名额。不，等等，这取决于计数的是"并发中"还是"已完成"——按已完成算，不减；按并发中算，才减。这里按并发中算。
多实例共享计数数据——通过 HTTP 接口同步，间隔可配（默认 1 秒）。同步失败了就用本地计数兜底——可能稍微放多一点请求，但比直接拒绝好。同步的数据是各秒分片的增量，不是全量，减少传输量。
统计按规则名称记触发次数——每小时记一次限流触发总数，接口可查。还能查每条规则的当前窗口用量和剩余额度。模块拆 limiter、window、sync、stats。Maven 构建，端口写配置文件。
