越库作业是商品到仓库后不进存储区直接转到出库口发走。做一个越库管理API，越库单同时关联入库和出库操作：商品入库扫码确认后直接转到出库口扫码出库。中间停留不能超过4小时，超时自动标记告警并通知仓库主管。状态流转：待入库→已入库待出库→已出库→超时告警。入库扫码的商品和出库单要求的必须一致，不一致拒绝并提示差异明细（多了什么少了什么）。入库和出库必须由不同操作员完成防止舞弊。同一个越库单的入库和出库必须在同一天内完成，跨日的自动标记异常。支持批量越库——一个出库单对应多个入库单，全部入库完成后才能出库。越库效率统计：平均停留时长、超时率、日处理量。日期时间使用 datetime 模块，时区统一用 UTC。异常处理不能裸 except，必须指定具体异常类型。

超时自动标记告警并通知仓库主管。支持批量越库——一个出库单对应多个入库单，全部入库完成后才能出库。越库效率统计包含平均停留时长、超时率和日处理量。商品不一致时提供差异明细（多了什么少了什么）方便快速定位问题。每日生成越库作业汇总报告越库作业区域监控——实时显示当前越库单在各环节的数量分布。高峰期自动建议增加操作人员。越库异常处理流程标准化——超时、商品不一致、操作员不足都有对应预案。

做成 Python 多包项目。shared/ 包放 Pydantic 的请求响应模型、协议定义和错误码常量。server/ 包基于 FastAPI 监听端口提供 HTTP 接口，处理所有业务请求，数据保存在内存中。cli/ 包是命令行工具，支持子命令和参数，通过 HTTP 请求调用服务端，结果格式化输出到终端。三个包各自有独立入口，根目录 pyproject.toml 统一管理依赖。各包内部按职责分模块。全量类型注解，函数参数和返回值都要标注类型，使用 mypy strict 模式检查。uv sync 能安装依赖，uv run python -m server 能启动服务端。

本项目属于跨系统多模块架构。
