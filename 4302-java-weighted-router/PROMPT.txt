线上的负载均衡器不支持权重调节，新上线的服务不敢多给流量，只能一刀切，出了好几次问题。运维那边提了好几次了，这次用 Spring Boot 重写一个，把权重逻辑吃透。

1. 后端实例管理——每个实例存地址、权重、健康状态。权重是正整数，运行中随时能调。实例通过 POST /api/backends 添加、DELETE /api/backends/{id} 删除。健康状态靠定期探测更新，探测间隔可配。

2. 请求分发——按权重分配到后端，权重越大分得越多。某个后端不可用时跳过它。后端全部不可用返回 503。分发策略可以在加权轮询和加权随机之间切换，通过 PUT /api/strategy 切换。

3. 统计面板——记录每个后端的请求数、成功数、失败数、平均延迟，按分钟粒度保留。查询接口 GET /api/backends/{id}/stats。后端权重变更后已有统计不丢。

权重从 0 调到正数，该后端立即开始接收流量。从正数调到 0，已分配到该后端的请求正常处理完，新请求不再分配过去。这两种变更都要立即生效，不能有延迟。

整个拆成 balancer 负责分发逻辑、backend 负责实例管理、strategy 负责选择算法、stats 负责统计收集。Maven 构建，端口走配置文件。
