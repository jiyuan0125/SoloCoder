微服务越来越多，每个服务自己暴露端口，前端同事都快骂娘了——端口记不住，超时配置各不相同，认证逻辑到处写。用 Go 标准库做一个简易 API 网关把入口统一起来，能解决大部分问题。

路由规则通过接口注册，POST /api/routes 添加。规则包含路径模式（支持 {param} 路径参数）、目标服务地址、请求方法。路径匹配按最长前缀优先，相同前缀的规则按注册时间排。匹配到路由后转发请求，注入 X-Request-ID 和 X-Gateway-Timestamp 两个 Header。目标服务的响应原样返回给客户端。超时默认 5 秒，可以按路由覆盖。

一个路由可以配多个目标服务，这时候网关并发调用所有目标然后聚合响应。聚合策略支持两种——合并 JSON 数组和取第一个有效响应。哪种策略通过路由配置指定。

每个路由可以挂中间件：认证、限流、日志，按配置顺序执行。中间件可以中断请求链直接返回。路由变更后已有的中间件配置保留不动。

gateway 负责整体调度、router 负责路径匹配、proxy 负责转发和聚合、middleware 负责中间件链。端口 PORT 环境变量，go build 能过就行。后面如果还有精力，考虑加个 WebSocket 透传的支持。
