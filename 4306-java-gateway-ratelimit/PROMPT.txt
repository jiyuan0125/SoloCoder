消息队列 topic 不隔离老是串消息，隔壁组已经踩过两次坑了——订单消息跑到日志 topic 里，消费端解析直接炸。Spring Boot 做一个带 topic 的消息队列，topic 之间严格隔离。

创建 topic 时指定名称、最大分区数、消息保留时间。POST /api/topics 创建，GET /api/topics 列出。topic 不用了可以删除，删除时未消费的消息全部丢弃，不给确认机会。

向 topic 发消息走 POST /api/topics/{name}/publish，消息带时间戳和分区键。相同分区键的消息进同一个分区，保证局部顺序。分区满了按保留策略淘汰旧消息——要么按时间淘汰超期的，要么按数量淘汰最早的，策略创建 topic 时选定。发布成功返回消息 ID 和分区号。

消费者以组为单位订阅 topic，同组内每个分区只分配给一个消费者。消费者掉线后它的分区重新分配给组内其他成员。消费进度按组独立记录。消费者拉取消息后需要确认（POST /api/ack），超时未确认的消息重新入队，排在分区末尾，重新入队的消息带重试次数标记。

broker 负责消息存储和投递、topic 管理分区和保留策略、consumer 管理消费者组和分配、ack 管理确认和重入队。Maven 构建，端口走配置文件。
