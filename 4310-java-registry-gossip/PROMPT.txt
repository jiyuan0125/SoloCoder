配置中心我们之前用的那个，推配置要重启应用，出了两次线上事故。这次 Spring Boot 自己写一个，运行时热更新是刚需。

配置用 KV 格式存。Key 是层级路径，比如 /app/db/host、/app/db/port。Value 是字符串。支持按前缀批量查询，GET /api/config?prefix=/app/db。每次修改自动生成版本号，版本号单调递增。

客户端怎么感知变更？两种方式。一种是长连接监听——客户端连接后，服务端配置变更立刻推送。另一种是断连重连后的增量拉取——客户端记录自己的版本号，重连时拉取这个版本号之后的所有变更。推送失败不影响配置生效，配置在服务端已经改了。

配置要按环境隔离——dev、staging、prod 三个环境。通过 PUT /api/env/current 切换当前环境。不同环境的配置独立维护，互不影响。切环境是个危险操作，接口要记审计日志。

还有个灰度推送的功能——配置变更先推给指定 IP 列表的实例验证，验证通过后再全量推送。灰度期间的配置对非灰度实例不可见，避免影响线上。

store 管存储和版本、pusher 管推送和长连接、env 管环境隔离、release 管灰度发布流程。Maven 构建，端口走配置文件。
