消息处理失败不能就这么丢了——之前有个订单消息消费失败，直接没了，用户投诉才发现。Spring Boot 写一个带死信队列的消息代理，失败的消息有兜底。

生产者向 topic 发送消息，POST /api/topics/{name}/publish。消息带唯一 ID 和时间戳。消息路由到 topic 下的分区，分区策略支持按键哈希和轮询。投递成功返回消息 ID 和分区号。

消费者订阅 topic 拉取消息，GET /api/topics/{name}/consume。拉取时指定批量大小（默认 10 条）。消费成功发送确认，POST /api/ack/{messageId}。超时未确认（默认 30 秒）的消息重新投递。同一个分区同时只有一个消费者拉取。

消息重试超过 3 次进入死信队列。死信队列的消息不会自动重试，就那么放着。死信队列的内容可以通过 GET /api/deadletter 查询，支持按 topic 和时间范围过滤。管理员可以手动重新投递死信消息，POST /api/deadletter/{messageId}/redeliver——重新投递的消息重试计数清零。

所有投递、消费、重试、进入死信的操作都记审计日志。审计包含消息 ID、topic、分区、操作类型、时间戳。审计日志只追加不可删除。

broker 管消息存储和分区、consumer 管消费和确认、deadletter 管死信队列、audit 管审计日志。Maven 构建，端口走配置文件。
