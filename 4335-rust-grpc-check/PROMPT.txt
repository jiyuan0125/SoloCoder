你有没有遇到过这种事——认证网关放行了请求，转发到上游才发现上游挂了，白白浪费了一次认证开销？如果网关知道上游挂了就不该转发，直接返回 503 才对。Rust actix-web 做一个带 gRPC 健康检查的认证网关，把认证和上游健康绑定在一起。

JWT token 验证签名和过期。签名算法 RS256，公钥通过接口配置（POST /api/keys），支持轮换——新公钥加进来后旧的在过渡期（默认 5 分钟）内继续有效。过期 token 返回 401。请求完全不带 token 也返回 401，除非路径在白名单里。

token 里带角色信息（roles 数组字段）。不同路径要求不同角色，路径和角色的映射通过 POST /api/permissions 配置。角色不足返回 403。白名单通过 POST /api/whitelist 管理，新增立即生效。

定期检查上游 gRPC 健康状态。上游不健康时请求直接返回 503，不做认证也不转发。上游恢复后自动恢复转发。健康检查间隔可配。

每个请求的认证结果记下来：请求路径、token 用户信息、认证结果（通过/拒绝/过期/角色不足）、耗时毫秒。失败的认证日志单独标记。

auth 管认证、permission 管鉴权、probe 管 gRPC 健康检查、logger 管认证日志。Cargo build，PORT 环境变量。
