微服务架构下 token 验证散落在各个服务里，每个服务自己维护一套 JWT 解析逻辑，公钥更新要逐个服务改。FastAPI 做一个集中的 Token 内省服务，外部来的 token 统一到这里查有效性。

传入 token，返回是否有效、过期时间、scope 列表、关联的用户信息（用户 ID、角色）。支持两种 token 格式——JWT（本地解析验证）和 opaque token（查后端授权服务器）。token 类型通过 Header 指定：X-Token-Type: jwt 或 opaque。

内省结果缓存起来。缓存有 TTL（默认 5 分钟），缓存命中直接返回不查后端。缓存未命中时查后端授权服务器。后端不可用时返回缓存的旧结果，即使已过期——有旧数据总比没有强。降级策略通过配置控制。

token 可能被撤销——用户登出或改密码后 token 立即失效。撤销列表定期从授权服务器同步，同步间隔可配（默认 60 秒）。同步失败时继续用旧的撤销列表。在撤销列表里的 token 立即失效，不管缓存有没有。

每次内省操作记录审计日志——token 前 8 位、结果（有效/无效/过期/撤销）、数据来源（缓存/后端）。日志用于排查和统计。

introspector 管内省逻辑、cache 管结果缓存、revocation 管撤销列表、audit 管审计日志。端口 PORT 环境变量。
