延迟任务的场景不少——下单 30 分钟未支付自动取消、预约提前一天发提醒、数据备份凌晨 3 点执行。这些操作不需要立刻干，过一会儿再搞。Go 标准库做一个延迟任务调度器。

通过接口提交延迟任务，POST /api/tasks。指定执行时间（绝对时间戳）和回调地址。执行时间到了调回调（HTTP POST），请求体包含任务 ID 和自定义参数。任务提交后返回任务 ID。

任务持久化到本地文件（JSON 格式）。服务重启后从文件恢复未执行的任务。执行时间已过的恢复任务立即执行。任务状态流转：PENDING → RUNNING → DONE 或 FAILED。

后台定期扫描到期的任务（默认每秒扫一次），到期的加入执行队列。执行队列按时间排序。队列中的任务并发执行，并发数可配（默认 10）。回调超时默认 30 秒。

执行失败的任务重试，重试次数可配（默认 3 次）。重试间隔递增：1 秒、5 秒、15 秒。超过重试次数标记为 FAILED。FAILED 的任务保留记录不自动清理，可以手动查和重跑。

scheduler 管调度和扫描、store 管持久化和恢复、executor 管并发执行、retry 管重试策略。端口 PORT 环境变量，go build 能过。
