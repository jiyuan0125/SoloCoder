消息队列发的消息所有人都能收到，但我们有的业务需要按内容过滤——比如只有 type=order 的消息才需要投给订单服务。Spring Boot 做一个带主题过滤的消息发布订阅。

消费者订阅 topic 时可以指定过滤条件，POST /api/subscriptions。过滤条件是简单的字段匹配，比如 type=order、priority=high。不指定条件的订阅收该 topic 的所有消息。同一个 topic 可以有多个订阅者，每个订阅者独立过滤。

向 topic 发布消息，POST /api/topics/{name}/publish。消息是 JSON 格式。发布时自动添加时间戳和消息 ID。发布后遍历该 topic 的所有订阅者，消息的字段值匹配过滤条件就推送，不匹配就跳过。推送走 HTTP POST 回调。

消息至少投递一次。回调失败重试 3 次，重试间隔递增（5/15/45 秒）。3 次都失败的消息进入待重试队列，GET /api/retry 查询，管理员可以手动重发。

已发布的消息保留一段时间（默认 24 小时），保留期间可以通过 GET /api/topics/{name}/messages 查询。过期消息由后台定期清理。

订阅者如果 5 分钟没有活跃（没拉取消息也没回调成功），自动暂停推送。暂停的订阅在 GET /api/subscriptions 里标记为 inactive，可以手动恢复。

pubsub 管发布和订阅匹配、filter 管条件过滤、delivery 管投递和重试、retention 管消息保留和清理。Maven 构建，端口走配置文件。
