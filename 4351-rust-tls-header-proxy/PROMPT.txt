用 Rust tokio 自己写一个 TLS Header 代理，把路由和改写逻辑彻底掌控在自己手里。请求进来后，先解析 TLS SNI 字段和 HTTP Host Header，这两个组合决定转发目标。上游分主备两组。健康检查用 TCP 连接探测，每 5 秒一轮，连续 3 次连不上标为 down。探测超时设为 2 秒，超时也算失败。日志按分钟聚合成摘要：每分钟有多少次改写、路由到了哪里，聚合结果通过接口查。内部拆成 proxy 负责转发、rewriter 负责改写、upstream 管理上游和健康检查、logger 做日志聚合。Cargo build ，监听端口通过 PORT 环境变量指定。
