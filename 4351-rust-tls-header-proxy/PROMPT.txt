去年双十一那次 Nginx 反代改 Header 配置搞错了，线上全挂了半小时。痛定思痛，这次用 Rust tokio 自己写一个 TLS Header 代理，把路由和改写逻辑彻底掌控在自己手里。

请求进来后，先解析 TLS SNI 字段和 HTTP Host Header，这两个组合决定转发目标。SNI 是 TLS 握手阶段的信息，Host 是 HTTP 层的，两层都要看才能准确路由。转发之前改写 X-Forwarded-For——追加客户端真实 IP，X-Real-IP 直接设为客户端地址。改写逻辑按路由规则走，不同上游可以有不同的改写策略。

上游分主备两组。主组优先承载流量，主组全部不可用时自动切到备组。健康检查用 TCP 连接探测，每 5 秒一轮，连续 3 次连不上标为 down。主组恢复后自动切回，不需要人工介入。探测超时设为 2 秒，超时也算失败。

改写规则可以动态配置，增删改都不需要重启服务。每个请求记录改写前后的 Header 快照和最终目标地址，方便排查问题。日志按分钟聚合成摘要——每分钟有多少次改写、路由到了哪里，聚合结果通过接口查。上游地址和改写规则通过 HTTP 接口管理，系统启动时从 TOML 配置文件加载初始值。内部模块拆成 proxy 负责转发、rewriter 负责改写、upstream 管理上游和健康检查、logger 做日志聚合。Cargo build 能过，监听端口通过 PORT 环境变量指定。
