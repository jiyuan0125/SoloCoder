限流网关一挂，后端直接被流量打爆——这事我们经历过。这次用 Go 标准库 net/http 重写一个限流网关，同时支持滑动窗口和固定窗口两种模式，让业务方按场景选择。

客户端靠 API Key 识别身份。每个 Key 独立计数，互不影响。窗口大小和配额可以按 Key 单独配置——比如 VIP 客户给 1000 次/分钟，普通客户 100 次/分钟。没有单独配的 Key 走全局默认值。Key 通过接口创建和管理，支持启用禁用。

窗口内请求超过配额直接返回 429，响应 Header 带上 X-RateLimit-Remaining（剩余配额）和 X-RateLimit-Retry-After（重试等待秒数），方便客户端做退避。同一秒内可能涌入大量请求，计数器更新要用原子操作保证并发安全。滑动窗口的实现用时间桶——每秒一个桶，查询时聚合最近 N 秒的数据。

限流统计数据按 Key 聚合，可以查询每个 Key 当前窗口的已用配额、剩余配额、被拒绝次数。全局统计也能看——总请求数、总拒绝数、当前活跃 Key 数量。内部按 limiter（限流核心逻辑）、counter（计数存储）、keymgr（Key 管理）、stats（统计查询）拆模块。go build 能过，PORT 环境变量。
