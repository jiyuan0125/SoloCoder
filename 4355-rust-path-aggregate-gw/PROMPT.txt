你有没有遇到过这种情况——前端一个页面加载要发七八个请求，后端服务拆得越来越细，前端对接越来越痛苦？用 Rust axum 写一个 API 聚合网关，前端一次请求，网关在后面调多个后端服务，把结果拼成一个 JSON 返回。

路由匹配支持精确路径和前缀两种模式。匹配到的路由关联一组后端调用配置。调用可以设成并行——三个后端同时发请求，全部回来后合并响应；也可以设成串行——第一个调用的结果作为第二个调用的入参，适合有数据依赖的场景。并行调用的超时独立计算，一个超时不影响其他的。

后端调用失败时的策略由路由配置决定。可以设成严格模式——全部成功才返回 200，任一失败返回 502 并附带失败详情。也可以设成宽松模式——返回部分成功的结果，失败的那个字段标为 null 并附带错误信息。前端拿到响应后可以按字段判断。

路由配置通过 HTTP 接口管理，增删改即时生效不需要重启。每次配置变更记录变更日志和操作人。内部模块划分：router 管路由匹配、aggregator 管结果合并策略、caller 管后端调用和重试、config 管配置热更新。Cargo build 能过，PORT 环境变量。
