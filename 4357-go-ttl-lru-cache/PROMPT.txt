后端接口响应慢，加一层缓存是标准操作。但缓存要做对不容易——TTL 过期瞬间大量请求同时穿透到后端、缓存空间不够要淘汰谁、手动失效怎么批量清理。用 Go/Gin 写一个 HTTP 缓存代理，把这些坑都处理好。

请求进来先查缓存。缓存 key 是请求方法和路径的组合。命中且未过期直接返回，响应 Header 加上 X-Cache: HIT。未命中或过期的请求转发到后端，后端响应写入缓存后返回，Header 标记 X-Cache: MISS。

缓存淘汰用 LRU 策略，容量上限可配。每个缓存条目有 TTL，过期自动淘汰。后台每秒扫描一次过期条目。缓存空间不足时淘汰最久未被访问的条目。TTL 和容量都可以通过接口动态调整。

手动失效也是刚需。支持按完整 key 失效，也支持按 key 前缀批量失效——比如某个资源的所有缓存以 /api/users/ 开头，一次请求全部清掉。失效操作记录日志，包含失效的 key 数量和操作时间。

缓存命中率、当前条目数、总淘汰数、平均响应时间这些指标通过 /stats 接口查询，按分钟粒度统计。结构上分成 cache（缓存核心和 LRU）、proxy（请求代理）、evictor（过期扫描和失效）、stats（统计聚合）四个模块。go build 能过，PORT 环境变量。
