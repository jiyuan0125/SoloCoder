Spring Boot 项目里连接池的问题排查起来特别烦——不知道连接被谁借走了、不知道为什么池子里全是空闲连接占着资源。写一个带完整生命周期管理和自动缩容的连接池。

连接有明确的状态机：创建→空闲→借出→归还→销毁。每次状态变更记录时间戳。借出连接时做身份验证——从请求 Header 取 X-Caller-Id 作为调用方标识。每个调用方同时最多借 N 个连接（通过接口配置），超限的请求进入等待队列。等待超时（默认 5 秒，可配）返回 503 错误。

连接泄漏检测是重中之重。借出超过 leaseTimeout（默认 30 秒）未归还的连接视为泄漏。泄漏连接自动回收并销毁，同时创建新连接补充到池中。泄漏事件记录日志——谁的连接、借出时间、回收时间。

池缩容解决空闲连接占资源的问题。后台每分钟扫描一次，空闲连接超过 idleThreshold（默认 60 秒）的按最久未使用优先销毁。缩容不影响正在借出的连接。池内连接数低于 minIdle 时自动补充新连接。内部用 pool（连接池核心）、borrower（借还逻辑）、detector（泄漏检测）、shrinker（缩容扫描）拆分职责。Maven 构建，端口写在配置文件里。
