排查线上问题最头疼的就是翻日志——每个服务一台机器，十几个服务得登十几台机器 grep。Spring Boot 写一个日志聚合服务，把所有服务的日志收到一个地方，按 traceId 串起来看。

日志采集走 HTTP 接口，各服务通过 POST /logs/batch 批量上报结构化日志。每条日志的字段是固定的：timestamp（毫秒时间戳）、level（DEBUG/INFO/WARN/ERROR）、service（服务名）、traceId（链路追踪 ID）、message（日志内容）。批量上报减少网络开销，建议每 100 条或每 2 秒上报一次。采集端也要处理上报失败的情况，本地暂存后重试。

日志查询是日常最高频的操作。按时间范围（必填）、服务名、级别、traceId 过滤，支持对 message 字段做全文搜索——简单的关键词匹配就行，不需要分词引擎。查询结果按 timestamp 排序，分页返回，每页最多 100 条。返回格式保留原始字段，方便对接方解析。

日志告警防患于未然。配置告警规则：某服务的 ERROR 级别日志在 N 分钟内超过 M 条就触发。触发后通过 HTTP 回调 URL 通知，回调请求体包含服务名、时间窗口、错误数。告警规则支持启用禁用。内部四块：collector 管采集和写入、store 管存储和索引、query 管查询、alerter 管告警规则和触发。Maven 构建，端口写在配置文件里。
