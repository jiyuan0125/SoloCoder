线上有个 SSE 推流服务给前端推送实时行情数据，之前裸奔没有鉴权也没有限流，被人用脚本刷了几万个连接直接打挂了。在前面加一层 Rust actix-web 代理，专门做鉴权和限流。

流式转发要处理好几个细节。SSE 和 chunked 传输都不能缓冲完整响应体——代理必须边收边发，延迟越低越好。上游断开后客户端的连接也要立即断开，发一个 SSE event: error 的消息再关。反过来客户端断开后代理要主动清理上游连接和相关资源，不然连接泄漏会慢慢耗尽文件描述符。

鉴权层拦截所有请求。Token 从 URL 参数（?token=xxx）或 Authorization Header 取，优先用 Header。验证逻辑是查本地 token 列表（通过接口管理）。验证结果缓存 5 秒——同一 token 在 5 秒内的后续请求不重复验证。验证失败返回 401，响应体带上错误原因。

限流按 token 维度隔离。每个 token 每秒最多建立 N 个新连接（默认 10），超过的连接排队等待，排队超时（默认 3 秒）返回 429。当前活跃连接数也有限制（默认每个 token 100 个），防止一个 token 把资源全占了。proxy 管流式转发、auth 管鉴权、limiter 管限流、stream 管 SSE/chunked 协议处理。Cargo build，PORT 环境变量。
