分布式锁最怕的场景——客户端 A 拿到锁后 GC 停顿了 10 秒，锁超时释放，客户端 B 拿到锁开始操作。A 恢复后以为自己还有锁继续操作，两个客户端同时写数据。fencing token 就是解决这个问题的。Go/Gin 写一个带 fencing token 的分布式锁。

客户端请求获取锁时返回两个东西：锁的持有权和 fencing token。token 是全局递增的整数，每分配一次 +1。同一个锁同一时间只有一个持有者。获取失败可以设 wait=true 排队等待，锁释放后按 FIFO 顺序通知等待者。

锁释放有两种：正常释放和超时释放。客户端主动调 DELETE /lock/{name} 正常释放，释放后 token 不回收但标记为已释放。超时释放——持有者租约到期后自动释放，token 继续递增，下一个持有者拿到更大的 token。下游服务收到请求后比较 fencing token：token 小的请求是旧的，直接拒绝。这样即使旧持有者以为还有锁，下游也能识别出来。

监控接口查看锁的状态：当前持有者、当前 fencing token 值、等待队列中的客户端列表和各自的等待时间。代码分 lock（锁获取释放）、token（token 生成和校验）、queue（等待队列）、monitor（状态查询）四个模块。go build 能过，PORT 环境变量。
