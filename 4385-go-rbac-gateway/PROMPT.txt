网关做认证不难，难的是权限模型要灵活。不是所有路径都是 admin 才能访问，有的路径 user 就行，有的路径 readonly 角色也能看。用 Go 标准库 net/http 做一个 RBAC 认证网关，角色有继承关系。

请求进来先过认证。支持两种方式：API Key 从 X-API-Key Header 取，查本地 Key 列表（通过接口管理），Key 对应一个用户和角色列表。JWT 从 Authorization Header 的 Bearer 字段取，解析出用户信息和角色。认证失败返回 401，响应体带失败原因。

认证通过后检查权限。每个路径配置一个所需角色（比如 POST /admin/users 需要 admin 角色，GET /api/orders 需要 user 角色）。用户角色从 token 或本地存储查询。角色有继承关系——admin 继承 user 的所有权限，user 继承 readonly 的权限。检查时递归向上查找，不需要精确匹配。角色不匹配返回 403。

权限配置通过接口管理。路径-角色映射的 CRUD、角色定义（名称和继承关系）的 CRUD，都不需要重启网关。配置变更记录操作日志。模块化成 authn（认证）、authz（授权检查）、role（角色继承管理）、config（配置管理）。go build 能过，PORT 环境变量。
