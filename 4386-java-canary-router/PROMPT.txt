金丝雀发布最头疼的不是代码部署，而是流量控制——怎么让一小部分用户先试新版本，出了问题快速回滚不影响大盘。Spring Boot 写一个金丝雀流量染色网关，支持多维度染色策略。

染色策略可以叠加使用。按用户 ID 百分比染色——用户 ID 尾号 0-9 的请求走灰度版本，对应 10% 的流量。按地域染色——从 IP 库解析出省份，指定省份走灰度。按设备类型染色——从 User-Agent 判断移动端还是 PC 端。多个策略叠加时是 AND 关系——必须全部匹配才打灰度标签。

版本路由根据灰度标签决定后端目标。染色后的请求路由到灰度版本实例组，未染色的走稳定版。版本和实例的映射（哪个版本的实例列表是什么）通过接口管理。灰度版本实例不可用时自动 fallback 到稳定版，不能因为灰度实例挂了就拒绝请求。

效果观测是灰度发布能不能全量的决策依据。灰度版本的请求成功率、P50/P95 延迟、4xx/5xx 错误码分布独立统计，和稳定版对比展示。数据按分钟粒度聚合，保留 24 小时。tagger 负责染色、router 负责版本路由、strategy 负责匹配策略、observer 负责效果统计。Maven 构建，端口写在配置文件里。
