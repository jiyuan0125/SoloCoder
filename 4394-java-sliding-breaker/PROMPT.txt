先说固定窗口的问题——窗口边界那一秒可能涌进来两倍配额的请求（前一窗口末尾 + 后一窗口开头）。滑动窗口把时间切成小桶，统计时滑动着看最近 N 秒，没有边界问题。Spring Boot 写一个滑动窗口熔断器。

滑动窗口的实现：每秒一个计数桶，保留最近 60 个桶（对应 60 秒窗口）。每次请求进来更新当前秒的桶——成功请求 success+1，失败请求 failure+1。统计失败率时聚合最近 N 个桶的数据：失败率 = 总 failure / 总 requests。窗口内总请求数少于阈值（默认 10）时不判断失败率，避免样本太少误判。

熔断恢复流程。CLOSED→OPEN 比较直接，失败率超阈值就触发。OPEN 持续一段时间（默认 30 秒）后进入 HALF_OPEN。HALF_OPEN 状态放一个请求探测后端。探测成功恢复 CLOSED 并清空窗口数据重新计数，探测失败继续 OPEN 再等一轮。

每个下游服务独立统计和熔断。调用方通过请求 URL 或 Header 里的目标服务标识来区分。service-a 熔断了不影响 service-b 的调用。breaker 管状态机、window 管滑动窗口计数、recovery 管半开探测、monitor 管各服务状态查询。Maven 构建，端口写在配置文件里。
