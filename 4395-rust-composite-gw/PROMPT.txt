前端一个页面要展示用户信息、订单列表、推荐商品——三个接口三个后端服务。串行调太慢了，能不能并行调然后合并返回？Rust tokio 写一个组合网关，把请求拆分、并行执行、结果合并这三步做好。

请求分解按配置来。配置定义了每个路由对应哪些子请求。每个子请求有独立的目标地址（host:port）、路径、HTTP 方法和超时时间。子请求通过 tokio 的 join! 并行发出，不是串行等完一个再发下一个。

结果合并有两种策略。全成功才返回——任一子请求失败，整体返回 502，响应体包含失败的子请求名称和错误信息。部分成功也返回——成功的子请求结果正常放在对应字段，失败的子请求字段标为 null 并附带 error 对象。合并后的 JSON 响应格式：每个子请求的结果放在以子请求名称为 key 的字段里。

超时控制是分层的。整体超时（默认 5 秒）兜底，子请求独立超时（默认 3 秒）。子请求超时不影响其他子请求——超时的那个按失败策略处理，没超时的正常合并。gateway 管请求接收和路由、splitter 管请求分解、merger 管结果合并、timeout 管超时控制。Cargo build，PORT 环境变量。
