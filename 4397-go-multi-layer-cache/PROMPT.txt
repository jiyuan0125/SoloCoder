单层缓存要么命中快但容量小（内存），要么容量大但慢（磁盘/远程）。两层叠在一起——L1 内存 + L2 文件——大部分请求都能在 L1 命中，L1 没有查 L2，L2 也没有才请求后端。Go/Gin 做一个多层缓存代理。

L1 缓存用内存 map 实现，LRU 淘汰。容量上限可配（默认 10000 条）。每个条目有 TTL（默认 300 秒），过期后下次访问时惰性删除。命中 L1 直接返回，响应 Header 标记 X-Cache: L1-HIT。

L2 缓存用文件存储。按 key 的 MD5 哈希前两位分目录（00-ff 共 256 个目录），避免单目录文件过多。条目也有 TTL，过期文件在读取时检测并跳过。L1 未命中时从 L2 加载——读到内存后写入 L1 缓存，下次访问就能 L1 命中了。L2 命中时 Header 标记 X-Cache: L2-HIT。

回写策略先写 L1 再异步写 L2。后端响应回来后立即写入 L1（同步），然后丢给后台 goroutine 写入 L2 文件（异步）。异步写入失败不影响 L1 的数据——下次请求 L1 命中直接返回，L2 文件缺失下次访问时会重新从后端拉取。l1 管 L1 缓存、l2 管 L2 文件存储、proxy 管请求代理、writer 管异步回写。go build 能过，PORT 环境变量。
