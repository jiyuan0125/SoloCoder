同一用户的请求每次打到不同后端，session 全丢了，用户投诉说操作做到一半被踢出去。Spring Boot 做一个会话亲和负载均衡器解决这个问题。

后端实例通过接口注册，每个实例有地址和权重。负载均衡支持轮询和会话亲和两种策略，策略可以热切换。会话亲和的 key 从请求的某个 Header 取，Header 名可配。同一个 key 的请求固定到一个后端实例，亲和关系持久化到内存。如果那个后端挂了，重新分配到另一个，分配逻辑是找当前负载最低的实例。新注册的实例会自动参与分配，不需要手动激活。

1. 后端健康检查每 10 秒一次。不健康的实例不参与选择，但已有的会话亲和关系保留 30 秒。30 秒内后端恢复的话亲和关系不断。
2. 查询接口可以看所有实例的状态——地址、权重、健康状态、每个实例的活跃会话数。可以手动把某个实例标记为下线，下线前等现有会话结束。
3. 亲和关系的存储支持上限，超过上限时淘汰最久没活跃的会话绑定。

整体架构分成四块：registry 管实例注册和发现，balancer 做负载选择，session 维护亲和关系，health 做健康检查。Maven 构建，端口走配置文件。
