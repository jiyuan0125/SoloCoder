隔壁团队问能不能搞一套插件化网关——请求转发前经过一系列插件处理，插件还能随时加减？当然可以。Go 标准库 net/http 来做。

插件有名称、执行顺序、启用状态三个属性，全部通过接口增删改。插件按顺序依次执行，任何一个返回错误就终止链路并返回错误响应。内置三个开箱即用的插件：鉴权插件检查 Authorization 头，有效 token 需要预先注册；限流插件按 IP 做 QPS 限制，限额可配；日志插件记录请求路径和耗时，写入内存环形缓冲区。每个插件独立配置，通过接口读写配置。

那路由转发呢？请求匹配路径前缀后转发到配置的上游地址。路径支持多层参数比如 /api/{service}/{version}/{resource}，转发时把匹配到的参数写到 Header 里。上游地址变更后新请求走新地址，已在途的请求不受影响。

插件执行出错时要不要重试？默认不重试直接返回错误，但可以在插件配置里开启重试，重试次数和间隔可配。重试只针对可恢复的错误，比如超时。

代码组织成 plugin 管插件生命周期、chain 做执行链、router 管路由匹配、forward 做转发。端口 PORT 环境变量，go build 能过。
