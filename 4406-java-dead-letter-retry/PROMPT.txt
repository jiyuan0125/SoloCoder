凌晨三点被拉起来排查，发现是消息丢了——消费者处理失败后消息就消失了，没有任何兜底。Spring Boot 做一个带死信和重试的消息队列，再也不让消息无声无息地消失。

生产者通过接口发布消息到指定 topic，消息有 payload、优先级、重试次数，持久化到文件或嵌入式数据库。消费者通过接口拉取消息，拉取后必须在一定时间内确认（ack）。超时未确认的消息重新入队，重新入队时优先级不变。确认时可以选重新入队或进死信，进死信时记录原因和时间戳。

重试超过 3 次的消息自动进死信队列。死信队列的消息可以通过接口查询，支持按 topic 和时间范围过滤。也可以手动重投到原 topic，重投的消息重试计数归零。消息的投递顺序不保证严格有序，但同一个 key 的消息要保证投递到同一个消费者，key 通过消息头传入。

队列容量有上限，满了以后新消息按优先级淘汰最低的旧消息。淘汰的消息如果还没被消费会记录到事件日志。死信队列也有容量上限，满了拒绝新的死信入库并记录告警。消费进度有偏移量管理，重启后从上次偏移量继续。

模块划分：publisher 发消息，consumer 管消费，deadletter 处理死信，store 做持久化。Maven 构建，端口走配置文件。
