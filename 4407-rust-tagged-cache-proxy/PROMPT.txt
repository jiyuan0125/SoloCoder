缓存失效的噩梦——改了一个商品分类，要把该分类下所有商品的缓存都清掉，结果只能一个个 key 搜。Rust axum 搞一个带标签的缓存代理，按标签批量失效。

缓存条目有 key、value、TTL、标签列表。key 是请求 URL 的哈希，标签是字符串数组。存储上限可配，满了淘汰最久未访问的条目。标签信息跟着缓存条目一起存，不影响 TTL 计算。调用失效接口传入标签，所有带这个标签的缓存条目立即删除，失效操作返回实际删除的条目数。标签可以带版本号，相同标签不同版本不冲突——改了商品分类后新版本自动生效，旧版本条目保留到自然过期。

缓存未命中时向源站请求，源站地址可配。回源成功的响应写入缓存，标签从响应的 X-Cache-Tags 头提取。回源超时 3 秒，回源失败不缓存错误响应。空标签列表的条目只能按 key 单独失效。标签名允许特殊字符比如斜杠和冒号。

1. 标签索引和缓存条目分开存储，失效时先查索引再删条目，避免遍历全部缓存。
2. 回源请求并发时同一个 key 只发一次，其他请求等待结果。源站地址变更后已有的缓存条目自然过期，不做主动清理。

store 管存储、tag 管标签索引、proxy 做代理、upstream 通信源站。Cargo build，PORT 环境变量。
