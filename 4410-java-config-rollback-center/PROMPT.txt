上周有人把生产环境的数据库连接池大小改成了 5，整个服务差点瘫痪，恢复的时候翻了半天历史记录才找到之前的值。配置中心连个回滚功能都没有？Spring Boot 加上。

配置按 app + env + key 三级组织。每次修改生成一个递增版本号，所有历史版本都保留。配置值支持文本和 JSON 两种格式。回滚到指定版本不是删除新版本，而是创建一个新版本内容等于目标版本——这样回滚本身也有记录。回滚时推送变更通知给订阅的客户端，多个客户端同时订阅同一配置时变更要都能收到。

客户端通过长轮询监听配置变更，长轮询超时 30 秒。变更时立即返回新值，没变更等到超时返回空。推送失败时不阻塞其他客户端，记录推送失败的事件到日志。配置值的 JSON 格式在存储时要校验合法性，非法 JSON 不允许保存。

查询接口支持按 app 和 env 过滤配置列表，也支持查看某个 key 的完整版本历史。版本历史按时间倒序，包含操作人和操作时间。配置删除是软删除，删除后不再推送但历史版本保留。

store 负责存储和版本，rollback 处理回滚逻辑，pusher 管长轮询推送，validator 校验格式。Maven 构建，端口走配置文件。
