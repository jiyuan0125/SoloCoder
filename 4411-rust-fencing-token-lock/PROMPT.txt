去年出过一次数据覆盖事故——网络分区后旧锁 holder 还在写数据，新 holder 也在写，最后数据乱了。光靠锁不够，得有个单调递增的凭证来区分谁是新的。Rust tokio 做一个带 Fencing Token 的分布式锁。

客户端请求获取锁时传入资源名和超时时间。获取成功返回 fencing token（单调递增的数字）和锁 ID。同一个资源同时只能有一个持有者，获取失败返回当前持有者的信息。持有者在超时前要续期，续期时传入锁 ID。锁 ID 不匹配返回错误——说明锁可能已过期被别人拿走了。续期成功延长超时时间。续期失败不自动释放，等超时自然过期。

释放时传入锁 ID 和 fencing token。fencing token 小于当前资源的 token 说明是旧请求，直接忽略不执行释放。释放后通知等待队列中的下一个请求。

超时自动释放的锁也要更新 fencing token——这样下一个获取者拿到的 token 一定比上一个大。等待队列按 FIFO 排序，超时未等到的返回失败。资源名和客户端标识的长度不做限制但空值要拒绝。

代码分 lock 管锁状态、token 管 fencing token 生成、queue 管等待队列、lease 管租约。Cargo build，PORT 环境变量。
