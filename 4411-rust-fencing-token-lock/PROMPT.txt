Rust tokio 做一个带 Fencing Token 的分布式锁。光靠锁不够，还得防旧锁释放。
锁获取：客户端请求获取锁，传入资源名和超时时间。获取成功返回 fencing token（单调递增的数字）和锁 ID。同一个资源同时只能有一个持有者。获取失败返回当前持有者的信息。
锁续期：持有者在超时前要续期。续期时传入锁 ID。锁 ID 不匹配返回错误（锁可能已过期被别人拿走）。续期成功延长超时时间。续期失败不自动释放，等超时自然过期。
锁释放：释放时传入锁 ID 和 fencing token。fencing token 小于当前资源的 token 说明是旧请求，直接忽略。释放后通知等待队列中的下一个请求。
超时自动释放的锁也要更新 fencing token。资源名和客户端标识的长度不做限制但空值要拒绝。
至少包含 lock、token、queue、lease 四个模块。Cargo build，PORT 环境变量。
