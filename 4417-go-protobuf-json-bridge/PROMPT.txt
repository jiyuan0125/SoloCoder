内部服务用 Protobuf 通信效率高，但外部客户端只认 JSON，中间得有个桥。Go 标准库做一个 Protobuf-JSON 协议桥，两边都能对接。

接收 JSON 请求转换成 Protobuf 发到上游，接收 Protobuf 响应转换成 JSON 返回。上游地址可配，转换用的 .proto 定义通过接口上传。支持 Protobuf 3 语法，嵌套消息、repeated 字段、enum 都要处理。oneof 字段转 JSON 时只序列化设置的那个，map 字段转 JSON 用对象表示。

外部路径和内部 Protobuf service/method 的映射关系可配。比如 POST /api/users 对应 UserService.CreateUser。映射规则通过接口管理，支持路径参数提取——{id} 这种占位符映射到 Protobuf 请求的对应字段。

1. 转换失败时返回详细的错误信息，指出是哪个字段出了什么问题。空请求体和非法 JSON 要能正确处理，不能 panic。
2. 上游超时可配，默认 10 秒。上游不可用返回 502 并记录错误日志。
3. 同一个路径可以注册多个 proto 定义的不同 service，通过 Content-Type 区分。

codec 处理编解码，mapping 管路径映射，proxy 做转发，proto_store 存储 proto 定义。端口 PORT 环境变量，go build 能过。
