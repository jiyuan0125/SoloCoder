用 Java Spring Boot 写微服务调用链经常找不到是哪个环节慢：一个请求经过七八个服务，出了问题只能靠猜。服务通过接口上报 Span 数据：每个 Span 有 trace ID、span ID、父 span ID、服务名、操作名、开始时间、耗时。Baggage 的值有长度上限，超过 1KB 的截断。查询支持时间范围过滤。采样率可配，比如 10%，采样决策在根 Span 做出，采样后的请求所有 Span 都要采集。Span 的开始时间和耗时都用微秒精度。trace ID 和 span ID 的格式不做限制但空值拒绝。同一个 trace ID 的 Span 可以分多批上报，不影响聚合。Maven 构建，端口配置。
