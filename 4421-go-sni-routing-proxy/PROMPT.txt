TLS 握手阶段就能拿到 SNI 信息，不用解密流量也能做路由——这个能力在多层代理架构里太有用了。Go 标准库做一个基于 SNI 的路由代理，不终止 TLS 连接。

TLS 握手时提取 Server Name Indication，提取后根据域名做路由决策。提取失败的连接直接关闭并记录日志。域名到后端的映射关系可配，支持精确域名和通配符域名（*.example.com）。通配符优先级低于精确匹配——同时配置了 *.example.com 和 api.example.com 时后者优先。规则通过接口动态管理。

匹配到规则后把整个 TLS 连接透传到后端，不修改任何数据，纯粹做 TCP 层面的流量转发。后端不可用时尝试下一个规则，都没匹配时转发到默认后端。默认后端也可以不配，不配的话无匹配连接直接关闭。

每个域名统计连接数、流量（字节）、错误数，统计按分钟聚合保留最近 60 分钟。SNI 提取失败的连接也统计。统计接口支持按域名查和查全部。

连接建立后网关不干预数据传输，纯粹是四层转发——性能开销要低。后端连接池复用 TLS 连接，减少握手开销。

sni 提取模块、router 路由模块、forward 转发模块、metrics 统计模块。端口 PORT 环境变量，go build 能过。
