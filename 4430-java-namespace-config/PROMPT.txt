不同团队共用一个配置中心，key 经常冲突——"timeout"到底是支付团队的超时还是订单团队的？得用命名空间隔离开。Spring Boot 做一个带命名空间的配置中心。

命名空间是第一级隔离——通过接口创建命名空间，有名称和描述，名称全局唯一。命名空间有 ACTIVE 和 ARCHIVED 状态，ARCHIVED 的配置只读不能改也不能删。每个命名空间独立管理自己的配置——key、value、格式（text/json/yaml）、版本号。修改自动递增版本号，可以查看任意历史版本，支持回滚到指定版本。

命名空间有管理员列表。管理员可以增删改配置，非管理员只能读取。管理员通过接口添加和移除，列表持久化存储。配置变更后通知订阅者，订阅者通过长轮询监听，超时 30 秒。推送失败不影响配置保存，失败的事件记录下来可查。回滚操作也触发推送。

命名空间删除时检查是否有配置——有配置的命名空间不允许删除，需要先清空。配置 key 的格式允许字母数字下划线和点，长度不超过 128 字符。

namespace 管命名空间，config 管配置，permission 做权限，pusher 管推送。Maven 构建，端口走配置文件。
