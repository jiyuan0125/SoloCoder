服务之间的依赖关系复杂——先注册探针，再建依赖图，最后级联传播健康状态。不依赖 Spring，纯 Netty HTTP 做一个依赖健康聚合器。

通过接口注册健康探针，探针有名称、类型（HTTP/TCP）、目标地址、检查间隔、超时。探针状态 UNKNOWN → HEALTHY → UNHEALTHY，检查在后台定时执行。HTTP 探针发 GET 请求，TCP 探针尝试建连。通过接口配置服务之间的依赖关系形成有向图。图中的循环要在配置时检测并拒绝，返回构成环的服务列表。

某个服务 UNHEALTHY 时依赖它的服务状态变为 DEGRADED。DEGRADED 的服务如果还有其他依赖也 UNHEALTHY 状态保持 DEGRADED 不是变成 UNHEALTHY——降级和故障是两个级别。UNHEALTHY 的服务恢复后 DEGRADED 的服务自动恢复。

查询接口——查某个服务的状态和它所有依赖的状态、查整个依赖图的健康概况、查某个探针的检查历史（最近 100 次）。查询结果用 JSON 返回，包含每个探针的最近一次检查时间和状态。

探针检查间隔最小 5 秒，避免对目标造成压力。依赖关系变更后立即重新计算状态传播。

probe 管探针执行、graph 管依赖图、propagate 做状态传播、query 处理查询。Maven 构建，端口走配置文件。
