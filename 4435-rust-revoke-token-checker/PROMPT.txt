Token 泄露了但还没过期怎么办？光靠过期时间不够，得有个主动撤销的能力。Rust tokio 做一个 Token 撤销检查网关——即使没过期，被撤销了也不能用。

通过接口撤销 Token，撤销记录有 token ID、撤销时间、原因。撤销列表存在内存里，检查时直接查内存——速度是第一位的，每次请求都要过一遍。撤销列表支持批量导入，批量导入的撤销记录不检查是否重复——重复的幂等处理。

请求进来时从 Header 提取 Token ID。先查撤销列表——已撤销返回 401，响应带撤销原因。再查过期时间——过期也返回 401。都通过才转发到上游。Token ID 缺失返回 401。上游转发超时可配。

启动时从持久化存储加载撤销列表——持久化用文件即可。运行时通过接口新增的撤销立即生效。撤销列表定期全量同步到持久化存储，同步过程中已有的撤销记录不清除。

统计——已撤销的 Token 被使用的次数（命中撤销列表）、撤销列表的大小、检查耗时分布。统计按分钟聚合，查询接口返回最近 60 分钟的分钟级数据。

revoke_list 管撤销列表，checker 做检查，loader 加载初始数据，stats 收集统计。Cargo build，PORT 环境变量。
