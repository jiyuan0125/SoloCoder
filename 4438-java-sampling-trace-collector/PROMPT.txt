全量采集 Trace 太浪费资源——一个高峰期一小时就能产生几百万条 Span，存储和查询都扛不住。按比例采集才是正道。Spring Boot 做一个采样式 Trace 采集器。

全局采样率可配比如 10%。采样决策在请求入口做，被采样的请求在整个调用链中所有 Span 都要采集。没有被采样的不采集任何 Span。错误请求的采样率独立配置通常更高比如 100%。服务上报 Span 到采集器时，采集器过滤掉未被采样的 Span——过滤依据是 trace ID 对应的采样标记，标记存在内存中过期时间 5 分钟。采集到的 Span 持久化存储到文件。

按 trace ID 查完整调用链，按服务名查最近 N 条 trace，按耗时排序查慢请求。查询接口支持游标分页——不能用 offset 分页因为数据量大时性能差。

根据当前采集量动态调整采样率——超过上限时降低，低于下限时提高。自适应范围有最大最小值约束，不影响错误请求的采样率。调整的幅度和频率可配，避免采样率来回抖动。自适应调整的决策记录日志。

sampler 做采样，collector 采集 Span，query 处理查询，adaptive 管自适应调整。Maven 构建，端口走配置文件。
