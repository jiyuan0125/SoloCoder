后端实例又要预热又要熔断，两件事不能分开管——预热是控制流量导入的速度，熔断是控制故障隔离，两个维度得集成在一起。Spring Boot 做一个熔断和负载均衡的混合器。

1. 后端实例通过接口注册，有地址、权重、区域。实例状态 NEW → WARMING → READY → DOWN。WARMING 状态的实例权重从 0 逐渐增加到配置值，增长速度按预热时间线性。DOWN 的实例不参与负载均衡。
2. 每个实例独立的熔断器，CLOSED → OPEN → HALF_OPEN 三态。实例连续失败 5 次打开熔断，熔断打开后该实例从选择池中移除。熔断器半开时放一个请求探测。探测成功恢复，失败重新打开。
3. 选择策略是加权轮询加熔断感知，选择时跳过熔断打开的实例。所有实例都熔断时返回 503。

WARMING 实例的权重低但能被选中——预热的目的就是让它慢慢接收流量。实例从熔断恢复后权重从配置权重的一半开始慢慢恢复到满值。区域亲和——优先选同区域的实例，同区域全挂了再选其他区域。实例的权重变更后立即影响选择概率。

instance 管实例状态，breaker 做熔断，selector 做选择，warmer 管预热。Maven 构建，端口走配置文件。
