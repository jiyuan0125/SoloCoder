不同类型的消息发到不同的处理队列，路由错了业务就乱了——订单消息跑到库存队列里，库存扣了但订单没创建。Spring Boot 做一个 Topic 路由消息队列。

通过接口创建 topic，有名称、分区数、消息保留时间。名称全局唯一，分区数创建后不可修改——改分区数会影响路由一致性。消息超过保留时间自动清理，清理时如果消息还没被消费也照样删。生产者发消息时指定 topic 和路由 key，路由 key 决定消息进入哪个分区——用一致性哈希保证相同 key 进相同分区。分区内有序，不同分区并行处理。

消费者组订阅 topic。一个分区同一时间只给组内一个消费者。消费者通过接口拉取消息，拉取后必须确认。超时未确认的消息重新分配给组内其他消费者。消费者退出后它的分区立即重新分配。处理失败超过 3 次的消息进死信队列，死信可以查询和重新投递，重新投递的消息回到原 topic。

分区数不足时消息可以在同一分区内堆积，堆积超过容量限制时最旧的消息被丢弃并记录告警。topic 的消息量统计可以通过查询接口查看——总量、各分区分布、消费进度。

topic 管 topic 生命周期，router 做路由，consumer 管消费组，deadletter 处理死信。Maven 构建，端口走配置文件。
