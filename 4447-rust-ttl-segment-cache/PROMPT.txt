缓存按分片管理——每个分片独立过期和淘汰，一个分片的热点 key 不会影响其他分片的命中率。Rust tokio 做一个分片 TTL 缓存。

1. 通过接口创建分片，指定名称、容量上限、默认 TTL。分片之间数据隔离。每个分片独立的淘汰策略（LRU 或 FIFO），创建时选定。分片创建后可以修改 TTL 但不能改容量。
2. 通过接口往指定分片写入 key-value，可以指定单条 TTL 覆盖分片默认值。读取时检查 TTL，过期返回不存在。写入时如果分片已满触发淘汰。
3. 后台定期扫描每个分片的过期 key，扫描频率可配。扫描时记录清理数量。大量过期 key 集中在同一个时间段时要能快速清理——扫描时按批次删除不逐个处理。

支持批量写入和批量读取。批量写入中部分失败不影响其他——返回每个 key 的写入结果。批量读取返回存在的和不存在的分开。批量操作的数量上限 100 条，超过拒绝。

不存在的分片名称写入和读取都返回错误。TTL 为 0 表示立即过期——相当于删除。key 和 value 都支持任意字节序列不只是 UTF-8 字符串。

shard 管分片、store 做存储、cleaner 清理过期、batch 处理批量操作。Cargo build，PORT 环境变量。
