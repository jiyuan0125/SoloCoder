上个月有个项目后端拆成了用户、订单、库存七八个微服务，前端同事天天抱怨要记一堆地址，联调时经常搞混端口。网关层本来用 Nginx 凑合，但每次改路由规则都得提交配置变更等运维 reload，排期等不起。索性自己用 Rust actix-web 写一个路径前缀路由代理，不同服务挂到不同路径下，规则走接口动态管理。

每条路由规则配好路径前缀、上游地址列表和要注入的 Header。路径匹配分两种：精确前缀和通配符。通配符优先级低一些，不会意外抢精确规则的流量。规则走接口动态添加、删除、修改，改完立即生效。

匹配到规则后从上游地址列表里轮询选一个节点转发，走标准 HTTP 反向代理。请求 Body 和大部分 Header 原样透传到上游，转发时还能在上游地址后面追加路径后缀，比如把 /api/users/ 映射到上游的 /v2/internal/users/。上游每个节点定期发 HEAD 请求探测健康状态，连续失败 3 次就标记不健康、不再参与选择。不健康的节点 10 秒后自动重试，恢复了就回到可用列表。

有个细节容易忽略：路由规则热更新的时候已经建立的长连接不能断开，只有新请求才走新规则。先启动 HTTP 服务监听 PORT 环境变量指定的端口，router 模块管规则存储和匹配逻辑，proxy 模块处理转发和 Header 注入，upstream 模块管理上游列表，health 模块调度探测。Cargo build 通过即可。
