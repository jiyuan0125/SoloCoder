网关到底要干几件事？认证、路由、聚合，还是不是网关。用 Rust axum 把这几样串起来，做成一个能用的 API 网关。

路由规则支持路径前缀匹配和精确匹配两种。每条规则配上游地址列表和认证要求，走接口管理，变更实时生效。请求进来先匹配路由，再决定要不要认证。

标注需要认证的路由会从 Authorization Header 取 JWT Token，校验签名和过期时间。通过了把用户 ID 和角色塞进 Header 转给上游；没 Token 或 Token 无效直接 401，body 里带错误原因。

部分接口需要从多个上游拉数据拼在一起返回——聚合规则配好多个上游请求和合并策略。当前支持并行请求全部完成后拼接 JSON，任一上游超时或返回 5xx 则整个聚合请求报错，不会返回半成品数据。

模块上 gateway 管路由分发，auth 管 JWT 校验和用户信息注入，aggregator 管多上游并行请求和结果合并，transform 管请求响应的格式变换。Cargo build 能过，端口从 PORT 环境变量读。


聚合请求有超时控制——所有上游请求共享一个总超时，比如 3 秒内必须全部返回。超时的上游当失败处理，走降级逻辑。响应格式统一成 JSON，聚合后的结构按配置里的字段名组织，前端不需要关心数据来自几个上游。
