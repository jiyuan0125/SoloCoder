上游服务扛不住重复请求的压力——同一个查询一秒打过来几十次，数据库都快被压趴了。用 Go 标准库写一个 HTTP 缓存中间件挡在前面，命中缓存直接返回。

哪些路径需要缓存走接口配，每条规则包含路径模式、TTL、是否缓存空响应。路径模式用前缀匹配，比如 /api/users/ 匹配所有用户相关接口。没命中缓存的透传到上游，响应状态码 2xx 的自动存下来。缓存总量有上限，按条数算，超了按 LRU 淘汰最久没访问的，淘汰了下次请求重新回源。当前缓存使用情况、命中率有接口可查。

有个坑要注意：同一个 Key 短时间大量未命中叫缓存穿透，会压垮上游。防护手段是缓存空结果，但 TTL 设短一点比如 10 秒。上游恢复了空缓存自然过期，新请求正常回源填上真实数据。

缓存更新走异步写入，不能阻塞读请求。cache 管缓存存储和 TTL 过期，rule 管规则匹配，eviction 管 LRU 淘汰策略，shield 管穿透防护逻辑。端口 PORT 环境变量，go build 能过。


缓存命中率要统计——总请求数、命中数、未命中数、回源数，按分钟聚合。命中率低于阈值说明缓存策略有问题，可能是 TTL 太短或者缓存 Key 设计不合理。统计接口可以查当前规则和历史的命中率趋势。
