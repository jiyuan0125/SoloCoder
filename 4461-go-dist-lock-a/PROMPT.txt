多个服务实例抢同一把锁，不协调就乱了——库存扣多了、重复发券，出了好几次事故。用 Go Gin 做一个分布式锁服务把这事管起来。

加锁走接口，传入锁名、持有者标识、超时时间。成功了返回锁 ID，调用方拿着这个 ID 后续操作。释放也走接口，传锁 ID 和持有者标识，只能释放自己持有的锁，别人的锁不能动。锁超时自动释放，持有者崩溃了也不会死锁。

这把锁支持可重入：同一个持有者对同一把锁多次加锁，每次引用计数加 1，释放时减 1，减到 0 才真正释放。超时时间以最后一次加锁为准刷新，不用每次都重新算。

锁被占了怎么办？新请求进等待队列排队，锁一释放就唤醒队首等着的那位。等太久的自动取消并返回超时错误，不会永远卡在那里。lock 管加锁释放锁的原子操作，reentrant 管可重入的引用计数，queue 管等待队列的入队出队和超时，timeout 管锁超时和自动释放。端口 PORT 环境变量，go build 能过。


锁的等待队列有公平性保证——先来的先等，后来的排后面，不会出现某个请求永远等不到锁的情况。队列长度有上限，超过上限的请求直接返回错误不排队，防止大量等待把内存撑爆。
