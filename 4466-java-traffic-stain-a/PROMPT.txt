灰度发布的时候，怎么把一部分流量安全地导向新版本试试水？用 Spring Boot 做一个流量染色网关来搞定这件事。

1. 染色规则走接口配，匹配条件包括 Header 值匹配、Cookie 值匹配、IP 段匹配、百分比匹配四种。规则之间可以 AND/OR 组合——比如 "Header 里带 X-Beta=true AND IP 在 10.0.0.0/8 段内" 才命中。

2. 匹配到的请求打上 X-Gray-Tag Header 作为染色标记，值就是灰度版本号。有标记的请求路由到灰度环境，灰度地址也走接口配。同一服务可以有多个灰度版本，染色标记值决定走哪个版本。没标记的走正式环境，互不干扰。

3. 灰度流量有百分比控制，按分钟级窗口统计实际灰度比例。超百分比的请求降级到正式环境，不会让灰度版本扛不住。

4. 灰度版本的健康检查独立于正式环境——灰度挂了不影响正式流量。

dye 管染色规则匹配和标记注入，router 管灰度路由选择，rule 管规则的 CRUD，traffic 管流量百分比统计和降级。Maven 构建，端口走配置文件。


染色规则有优先级——多条规则都匹配时取优先级最高的那条的标记。比如按 IP 段匹配的优先级设为 10，按 Header 匹配的设为 20，Header 规则优先。优先级走接口配，改了立即生效。
