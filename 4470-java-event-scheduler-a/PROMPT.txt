定时任务散落在各个服务里，有的用 cron、有的自己写 timer，改一个调度时间要改代码重新部署，太不灵活了。Netty 实现一个集中式事件调度器，定时后台任务统一管理统一触发。

任务通过接口注册，包含名称、Cron 表达式（标准五段：分时日月周）、回调 URL、超时时间。任务有三种状态：ENABLED 正常调度、DISABLED 暂停不触发、DELETED 已删除不再执行。想暂停某个任务直接 DISABLED，不用删了再重建。

Cron 触发后走 HTTP POST 回调到指定 URL，回调超时时间可配，默认 10 秒。执行结果记录成功、失败或超时，失败的重试最多 3 次，每次间隔 1 分钟。重试也失败就标记为最终失败，不影响下一次 Cron 触发。

每次执行都留记录：任务名、触发时间、完成时间、结果状态和响应内容摘要。日志按天归档，可以按任务名和日期范围查历史执行情况。scheduler 管 Cron 解析和任务调度，executor 管 HTTP 回调和重试，logger 管执行日志的存储和查询，task 管任务的 CRUD 和状态。Maven 构建，端口走配置文件。


任务的 Cron 表达式解析要支持常见格式。每分钟执行一次（* * * * *）、每小时第 0 分执行（0 * * * *）、每天凌晨 2 点执行（0 2 * * *）这些都要正确解析。非法的 Cron 表达式在注册时就报错，不存进去。
