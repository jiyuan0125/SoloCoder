Go Gin 写一个多级限流器——全局、路径、用户三层过滤，层层收紧。

第一层是全局限流。设一个总 QPS 上限，比如 10000，超了直接返回 429，计数器按滑动窗口统计。全局是兜底措施，防止单个路径或用户把整个系统打满。

第二层是路径限流。每个路径模式可以独立配 QPS 上限，没配的不受路径级限流。路径支持前缀匹配，同一请求可能匹配多条规则，取最严的那个。比如 /api/ 配了 5000 QPS，/api/heavy/ 配了 1000 QPS，那 /api/heavy/export 请求按 1000 算。

第三层是用户限流。从 Token 里提取用户标识，每分钟请求数有上限。没登录的用 IP 做标识。超了返回 429 带 Retry-After Header。

每一级限流触发都记事件——哪个级别、什么 Key、什么时候触发的，方便排查是不是某个用户在刷接口。global 管全局限流，pathlimiter 管路径级限流规则匹配，userlimiter 管用户级限流，events 管限流事件记录和查询。端口 PORT 环境变量，go build 能过。


限流触发的事件走接口查询——哪个级别触发、什么 Key、什么时候触发的。事件保留最近 10000 条，用于分析和排查。比如发现某个 IP 频繁触发用户级限流，可能是爬虫或者攻击。
