能不能把认证、限流、日志这些横切关注点做成插件按需组合？Rust actix-web 实现一个插件化 API 网关，能力做成插件串成链跑，想加什么能力加个插件就行。

请求进来依次过请求链：认证插件检查 Token 是否合法，限流插件检查当前 QPS 有没有超，路由匹配插件确定上游地址。每个插件可以放行或拒绝，拒绝就直接返回对应错误码不再走后续插件。插件按优先级排序，通过接口管理增删改，比如临时关掉某个插件直接把优先级设为 0，不用卸载。

上游返回后进入响应链后处理：缓存插件对 GET 请求的响应做短期缓存、日志插件记录请求响应的摘要信息（URL、状态码、耗时）、Header 注入插件加一些固定的响应 Header 比如 X-Request-ID。响应插件出错不影响正常返回，记个警告日志就完了。

chain 管插件链的组装和执行顺序，interceptor 定义插件接口和生命周期，request 管请求侧插件调度，response 管响应侧插件调度。Cargo build，端口 PORT 环境变量。


插件接口设计要简洁——每个插件实现两个方法：process_request 和 process_response，返回放行或拒绝。插件之间通过 context 对象共享数据，比如认证插件把用户信息写进 context，后续插件可以读取。不用全局变量。
