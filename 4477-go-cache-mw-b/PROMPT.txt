纯内存缓存重启就没了，高峰期服务一重启缓存全空引发雪崩。纯文件缓存又太慢，每个请求都要读磁盘扛不住。用 Go 标准库写一个两级缓存中间件——内存做一级快但易丢，文件做二级慢但持久，两层配合取长补短。

请求先查 L1 内存缓存，命中直接返回。没命中查 L2 文件缓存，命中则返回并同时回填 L1。L2 也没有就回源请求上游，回源结果同时写 L1 和 L2。L1 有 TTL 过期机制，过期后查 L2 可能还有。L2 没有 TTL，靠主动删除淘汰过期内容。

有一个坑得防：同一个 Key 多个请求同时 miss 时不能全放去回源，只放一个去上游取，其他的等它的结果——这就是 singleflight。等太久的直接穿透回源，不能让后面的请求一直卡着。

预热接口可以提前回源一批路径，最多 50 个，后台异步执行不阻塞主流程。cache 管 L1 内存缓存的存取和 TTL，layer 管 L2 文件缓存的读写，singleflight 管并发回源控制，warmer 管预热任务调度。端口 PORT 环境变量，go build 能过。


L2 文件缓存的存储格式是 JSON——包含响应体、状态码、Header 和缓存时间。文件名用 URL 的哈希值，避免路径中的特殊字符导致文件系统问题。文件目录按哈希前两位分两级子目录，避免单目录文件过多。
