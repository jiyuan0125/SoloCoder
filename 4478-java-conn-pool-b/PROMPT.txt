Spring Boot 写一个 HTTP 连接池管理。后端调多个外部服务——支付、短信、物流，每个服务域名不同、超时要求也不同，连接得复用不能每次都新建 TCP 连接。

每个目标域名独立配池参数：最大连接数、连接超时、读超时、总超时，根据外部服务的 SLA 来定。比如支付接口给 5 秒总超时，日志上报给 2 秒就行。没配的域名走默认值。配置走接口管理，改了立即生效。

借连接从池里取空闲的，没有且没到上限就新建，到上限就等别的请求归还，等有超时时间。归还时检查连接是否存活——发一个小请求验证，死了就丢掉不放回池里。

连接借出超过一定时间没还就算泄漏。泄漏阈值可配，默认 30 秒。泄漏的连接强制关闭并记录日志，包含调用方信息和持有时长。某个目标域名泄漏次数超过阈值要告警，走接口推送通知。pool 管连接的借出归还和生命周期，config 管域名级参数配置，borrow 管借出逻辑和等待队列，leak 管泄漏检测和告警。Maven 构建，端口走配置文件。


连接池的状态要能查——每个域名当前有多少活跃连接、多少空闲、历史上创建了多少、关闭了多少。这些数据帮助判断池参数配得合不合理，需不需要调大或调小。
