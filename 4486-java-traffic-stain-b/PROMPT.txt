灰度发布不只是网关层的事——请求从网关进来，经过 A 服务、B 服务、C 服务，任何一环丢失染色标记，灰度流量就混到正式环境里了。Spring Boot 做一个全链路流量染色服务，保证标记从头传到尾。

请求在网关层打上染色标记（比如 X-Trace-Tag: gray-v2），标记通过 HTTP Header 传给下游服务。下游服务读到了必须在发出的请求里继续透传这个 Header，整条调用链标记不能丢。

每个服务可以配自己的染色规则，条件支持 Header 匹配和百分比。比如订单服务规定 Header 里带 X-VIP=true 的请求走灰度，库存服务规定 10% 的流量走灰度。网关层的规则优先级最高，网关打了标记的下游服务不能覆盖。

染色流量和正式流量在统计上隔离——各服务上报染色流量的 QPS、延迟、错误率，染色指标独立存储和查询，不会和正式流量混在一起看。marker 管染色标记的注入和解析，propagate 管标记在服务间的透传规则，rule 管染色规则的配置，isolate 管染色指标的隔离统计。Maven 构建，端口走配置文件。


染色标记的格式统一：X-Trace-Tag Header 的值是 tag:version 格式，比如 gray:v2。下游服务解析时按冒号分隔取 tag 和 version。这个格式保证标记值不会跟其他业务 Header 冲突。
