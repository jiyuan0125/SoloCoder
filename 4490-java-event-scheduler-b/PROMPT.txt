Spring Boot 实现一个延迟队列调度器，把消息队列里的延迟投递和定时任务两件事一起管了。

延迟消息这块，通过接口提交消息，带上 Topic、Body 和延迟时间。消息先存在延迟队列里，时间到了通过 HTTP 回调投递到对应 Topic 的消费者。投递失败重试 3 次，还是失败记到失败列表等人工处理。

定时任务这块，通过接口注册 Cron 表达式加回调 URL。调度器按 Cron 触发 HTTP POST 回调，执行结果记录下来。Cron 解析支持标准五段格式（分时日月周），非法表达式注册时就报错不让存。

每条延迟消息和每次任务执行都有状态跟踪：SCHEDULED 等待中、EXECUTING 执行中、SUCCESS 成功、FAILED 失败。可以按状态筛选查询，FAILED 的可以手动重新触发执行。scheduler 管 Cron 解析和整体调度，delay 管延迟消息的定时投递，timer 管定时任务的触发，tracker 管状态记录和查询。Maven 构建，端口走配置文件。


Cron 表达式支持秒级精度（六段）和分钟级精度（五段），自动识别不需要调用方指定。延迟消息的延迟精度是秒级——最小延迟 1 秒，最大延迟 7 天。超过 7 天的建议用定时任务。
