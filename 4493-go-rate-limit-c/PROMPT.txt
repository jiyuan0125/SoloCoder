Go Gin 写一个令牌桶限流集群——单机限流在多节点部署时不管用了，三个节点各限各的加起来超了总量。

标准令牌桶算法：桶容量和填充速率可配。请求消耗令牌，令牌不够就拒绝。每个限流 Key 一个桶，Key 可以是 API Key、用户 ID 或者客户端 IP。

多节点场景下通过中心服务同步。中心服务维护全局令牌桶状态，每节点定期从中心预分配一批令牌。比如每秒向中心申请 100 个令牌的配额，用完了再去申请。中心令牌不足时按比例分配给各节点——申请 100 个只给 50 个，大家按比例缩减。

预分配量基于节点历史消费速率动态调整——消费快的多分点，慢的少分点。新节点刚上线没有历史数据，给一个固定初始配额。没花完的预分配令牌定期还回去，不浪费。bucket 管本地令牌桶的实现，sync 管与中心服务的同步协议，allocator 管中心服务的令牌分配逻辑，center 管全局状态维护。端口 PORT 环境变量，go build 能过。


中心服务本身也要高可用——用主从模式，主节点处理令牌分配，从节点实时同步状态。主节点挂了从节点自动接管。节点间走心跳检测，5 秒没心跳触发选举。选主用简单的租约模式，最先拿到租约的成为主。
