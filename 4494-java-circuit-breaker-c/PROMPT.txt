多台机器各熔各的状态不一致——节点 A 说服务 X 熔断了，节点 B 还在往 X 发请求。用 Netty 做一个熔断器集群同步服务，让各节点的熔断状态保持一致。

每个被保护服务的熔断状态在集群内实时同步：状态变了就广播给所有节点，广播走 TCP 长连接。广播失败重试一次。节点间状态不一致时以多数派结果为准——超过半数节点说 OPEN 就是 OPEN。

OPEN 状态下的探测请求不能每个节点都发，那等于把探测流量放大了 N 倍。通过分布式选举决定谁来发探测——选出一个 leader 节点负责发探测请求，探测结果广播给所有节点。成功了大家一起切 HALF_OPEN，失败了全都保持 OPEN。

每个被保护服务独立维护状态，状态变更触发回调通知上层应用。提供查询接口看所有被保护服务在所有节点上的当前状态，状态变更历史有记录可追溯。cluster 管节点发现和通信，broadcast 管状态广播和多数派仲裁，probe 管选举和探测调度，state 管状态机和历史记录。Maven 构建，端口走配置文件。


选举算法用 Bully 算法——节点 ID 最大的成为 leader，简单直接。leader 挂了重新选举，选举过程中熔断状态冻结不变化。新 leader 选出后从本地状态恢复，不需要从其他节点同步。
