前端一个页面要调好几个后端接口——用户信息、订单列表、推荐商品，三个请求串行走 300ms 并行走 100ms，但前端不想管并行逻辑。Rust tokio 实现一个 API 聚合网关，帮忙合成一次返回。

每个聚合接口配多个后端请求模板，模板里写好 URL、Method 和参数映射规则。参数可以从原始请求的 Query、Header、Body 里提取，用 JSONPath 表达式指定。聚合配置走接口管理，增删改实时生效。

多个后端请求并行发出，全部完成后合并。合并策略有三种——直接拼接所有上游返回的 JSON 合成一个对象、按字段映射把上游响应的特定字段放到指定位置、自定义模板用模板引擎渲染最终结果。

部分后端失败时的降级策略也在配置里定：返回默认值跳过该字段、整个请求报错。只有全部后端都失败才返回整体错误。aggregator 管聚合配置和请求编排，executor 管并行请求和超时控制，merger 管结果合并的三种策略，fallback 管降级逻辑。Cargo build，端口 PORT 环境变量。


聚合请求有缓存——完全相同的聚合请求（相同参数、相同配置版本）短时间内直接返回缓存结果，不重复调用上游。缓存 TTL 很短，3 秒，避免返回过旧数据。写操作（POST/PUT/DELETE）不走缓存。
