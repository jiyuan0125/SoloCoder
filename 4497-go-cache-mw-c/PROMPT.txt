数据改了但缓存还显示旧的——商品价格调了，用户看到的还是原价，投诉电话都打爆了。用 Go 标准库写一个缓存失效管理器，保证缓存跟着数据走。

通过接口指定 Key 让缓存立刻失效，失效后下次请求重新回源拿最新数据。失效操作记日志，内容包括操作时间、失效的 Key 和调用方标识，方便排查是谁触发了失效。

也能指定 Key 模式批量失效——模式支持通配符，比如 user:* 匹配所有以 user: 开头的缓存 Key。匹配到的全部失效。Key 可能很多，异步执行不阻塞调用方，返回一个任务 ID 供查询进度。

缓存失效时通知订阅者，通知内容带失效的 Key 列表，订阅者收到后可以主动清理本地缓存。订阅者走接口注册回调地址。通知失败不重试，订阅者自己负责定期同步，不要完全依赖推送。invalidate 管单 Key 失效，pattern 管通配符匹配和批量失效，notify 管变更通知推送，log 管操作日志记录。端口 PORT 环境变量，go build 能过。


批量失效操作有进度查询——返回的 task_id 可以用来查失效了多少个 Key、还剩多少个、预计多久完成。批量失效完成时通知订阅者，一次性把所有失效的 Key 列表推过去。
