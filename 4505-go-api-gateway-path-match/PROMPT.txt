用 Gin 写一个 API 网关。后端有五六个微服务，前端请求都走网关转发。

路由匹配：支持精确路径和前缀匹配两种模式。路径里可以带参数，比如 /users/{id}/orders 里的 id 要提取出来传给后端。同一个路径支持 GET POST PUT DELETE 不同方法转发到不同后端。

认证注入：部分接口要求登录，请求头里带 Token，网关验证 Token 后把用户信息注入到转发请求的 header 里。没 Token 或 Token 过期的接口直接返回 401。白名单接口不需要认证。

请求聚合：有些页面的数据需要调多个后端接口，网关支持在一个请求里并行调用多个后端，把结果合并成一个 JSON 返回。聚合规则在配置里定义，哪个路径需要聚合哪几个后端接口。

至少包含 router、auth、aggregator、proxy 四个模块。编译通过，端口 PORT 环境变量。
