后端服务是 gRPC 协议，前端只能调 REST。用 Rust/tokio 写个协议转换层。

HTTP 请求进来后，根据路由表找到对应的 gRPC 方法。把 JSON body 转成 protobuf 消息，调用 gRPC 服务，再把响应转回 JSON。

路由表支持路径参数和查询参数映射。路径参数 /users/123 映射到 gRPC 请求的 user_id 字段。查询参数也一样映射。

转换错误要返回有意义的错误信息，不能直接暴露 gRPC 内部错误。gRPC 的 status code 映射到合适的 HTTP 状态码。

批量操作场景：一个 HTTP 请求可能触发多个 gRPC 调用，结果合并后返回。端口 PORT 环境变量，Cargo build 能过。
