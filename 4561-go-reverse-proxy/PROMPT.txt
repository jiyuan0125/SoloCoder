线上的微服务越来越多，每个服务都有自己的端口，前端调用太分散了。打算用 Go 标准库 net/http 做一个反向代理，把请求按路径前缀转发到后端服务。

代理维护一个上游服务列表，每个服务有名字、地址、健康状态。请求进来后根据 URL 前缀匹配到对应的服务组，在组内轮询选择一个健康的上游转发。转发时要改写 Host header 和 X-Forwarded-For，后端服务需要拿到真实客户端 IP。上游服务可以通过接口动态添加和移除。

代理每隔 10 秒对每个上游做一次健康检查（HTTP GET /health），连续 3 次失败标记为不健康，恢复需要连续 2 次成功。不健康的上游不参与转发。如果某个服务组所有上游都不健康，返回 503 并记录日志。

服务组定义和上游地址通过 JSON 配置文件加载，启动时读取，运行时可通过 API 热更新。端口通过环境变量 PORT 指定。go build 能编译通过就行。
