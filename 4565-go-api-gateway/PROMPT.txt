隔壁部门做了个用户中心和订单服务，我们需要统一入口，用 Go/Gin 做一个 API 网关把内部服务串起来。

网关的核心是路由表，每条规则定义：路径模式（支持通配符和路径参数）、目标服务地址、需要的认证级别（公开、需登录、需管理员）、请求转换规则。请求进来后先做路径匹配，匹配到了检查认证级别，需要认证的从 header 里取 token 验证，验证失败返回 401。

登录用户用 JWT token 标识，网关负责验证签名和过期时间。验证通过后把 user_id 注入到转发请求的 header 里。管理员权限也在 token 的 payload 里有标识。

有个聚合接口，一个请求可以并发调用多个后端服务，把结果合并成一个 JSON 返回。比如 /api/dashboard 同时调用户信息和最近订单，拼在一起返回。后端服务可以通过管理接口动态注册和注销。配置存在 JSON 文件里，启动时加载。端口环境变量 PORT 指定，go build 能过就行。
