我们有个高频查询的接口，数据库扛不住了。用 Rust + actix-web 做一个缓存中间件，挡在应用和数据库之间。

缓存用内存 HashMap 存储，每条缓存记录有 key、value（字节流）、创建时间、TTL。查询请求进来时先查缓存，命中且未过期直接返回。未命中或过期则转发到后端数据库接口，拿到结果后写入缓存再返回。TTL 默认 300 秒，可以在写入时指定。

缓存容量有上限（可配置，默认 10000 条），满了以后用 LRU 策略淘汰。key 支持前缀匹配批量删除，比如某个表的数据变更了，按表名前缀清掉所有相关缓存。缓存命中率、当前条目数、总查询次数这些指标通过 /metrics 接口暴露。

提供接口手动清除指定 key 或清空全部缓存。有个后台线程每隔 60 秒扫描一次过期的 key 并清理。端口通过环境变量 PORT 指定。cargo build 能编译通过。
