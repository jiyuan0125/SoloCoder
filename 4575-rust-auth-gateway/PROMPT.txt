现在各服务的认证逻辑都是各自实现的，token 格式也不统一。用 Rust + actix-web 写一个认证网关，所有请求先过网关验证身份再转发到后端。

支持两种认证方式：API Key（简单的 key-value 映射）和 JWT（HS256 签名）。每个后端服务可以配置需要的认证方式。API Key 存在内存 HashMap 里，可以通过接口增删。JWT 密钥在启动时配置，支持密钥轮换——新签发的用新密钥，旧的密钥仍然可以验证直到过期。

JWT payload 里包含 user_id、roles、exp。过期时间可配置，默认 2 小时。有 refresh token 机制，refresh token 有效期 7 天，可以用来换取新的 access token。refresh token 用完就作废。

用户可以自定义报表的名称和描述，这些内容会存到后端数据库里。网关在转发请求时把认证结果（user_id、roles）注入到 header 里传给后端。认证失败直接返回 401 或 403，不转发。所有认证日志记录下来，有接口可以查最近的认证记录。端口环境变量 PORT 指定。cargo build 能编译通过。
