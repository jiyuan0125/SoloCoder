线上的微服务调用链太长了，出了问题不知道卡在哪一步。用 Java Netty 写一个轻量级请求链路追踪服务。

每个请求进来时生成一个全局唯一的 TraceID（UUID），通过 X-Trace-Id header 传播。每经过一个服务节点，生成一个 SpanID，记录服务名、开始时间、结束时间、状态码。同一个 TraceID 下所有 Span 按调用顺序组成一棵调用树。客户端库用 Netty HTTP client 发 Span 数据到追踪服务，异步发送不阻塞业务。

追踪服务接收 Span 数据后存到内存里，按 TraceID 索引。查询接口可以按 TraceID 查完整的调用链，返回调用树结构（有父子关系），每层的耗时和状态。也支持按服务名和时间范围查询最近失败的 TraceID 列表。

有个接口返回耗时最长的 N 个 Trace，方便排查性能瓶颈。超过 24 小时的 Trace 数据自动清理。如果客户端发来的 Span 缺少必要字段（比如没有 TraceID），服务端自动生成一个并返回。端口环境变量 PORT 指定，能编译启动就行。
