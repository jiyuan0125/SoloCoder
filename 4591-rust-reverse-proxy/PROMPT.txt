线上的服务拆了十几个微服务，前端要对接一堆地址太乱了。用 Rust axum 写一个反向代理服务，把所有后端 API 统一到一个入口。

代理按路径前缀路由到上游，比如 /user/* 转到用户服务，/order/* 转到订单服务。路由规则支持精确匹配和前缀匹配，前缀匹配时要把匹配的部分从请求路径里去掉再转发。转发时保留原始请求的 Query String 和 Body。

上游地址从配置文件（TOML）加载，运行期间可以通过管理接口热更新。更新时新请求用新配置，正在处理的请求用旧配置。有个接口可以查看当前生效的所有路由规则和各上游的状态。

每个上游维护最近 100 次请求的响应时间（毫秒），查询接口能看到每个上游的平均延迟和 P99。转发超时 5 秒，超时返回 504。上游状态变更后，依赖该上游的统计面板数据要同步刷新。端口环境变量 PORT 指定，cargo build 能编过。
