打算给内部服务统一加一层网关，处理认证、限流、路由这些横切关注点。用 Rust tokio 写一个轻量 API 网关。

路由模块从配置文件加载路由表，支持路径参数（如 /api/users/:id）和精确匹配。路由匹配成功后经过中间件链：认证中间件检查请求头里的 Token，合法的注入用户信息到请求上下文；限流中间件按客户端 IP 维护计数器；最后转发到上游。任何中间件拒绝请求都直接返回错误。

中间件的注册顺序决定执行顺序。认证失败返回 401，限流触发返回 429。转发模块用 HTTP 客户端发请求到上游，超时 3 秒。

路由表、中间件配置、上游地址都从独立的 TOML 配置文件读取。有个管理接口可以查看当前路由表和中间件链的配置。端口环境变量 PORT 指定，cargo build 能编过。
