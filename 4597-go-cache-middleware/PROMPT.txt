后端数据库扛不住了，高峰期查询慢得要死。用 Go 标准库 net/http 写一个缓存中间件服务。

缓存以 key-value 形式存储，每个 key 可以设置独立的 TTL。写入时如果 key 已存在则覆盖，旧的 TTL 作废。读缓存时如果 key 不存在或已过期返回 miss。过期清理用惰性策略：读取时检查过期，过期的立即删除并返回 miss。

支持标签（tag）机制：写缓存时可以给 key 打上多个标签，之后可以按标签批量失效。同一个 key 可以属于多个标签。标签失效时，该标签下的所有 key 都标记为无效，即使没到期也一样。标签失效后，按标签查询的统计面板里相关计数也要清零。

缓存容量有上限（可配置，默认 10000 个 key）。超出时用 LRU 淘汰。有个统计接口看命中率、当前 key 数量、总请求数。统计可以重置。容量满了之后，多个请求同时写入可能争抢淘汰位置。端口环境变量 PORT 指定，go build 能编译通过。
