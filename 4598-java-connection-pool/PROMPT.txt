服务频繁创建销毁数据库连接太浪费资源了。用 Spring Boot 2.x（JDK 17，Maven）写一个通用连接池管理服务，管理模拟的后端连接。

连接池配置：最大连接数、最小空闲连接数、连接超时时间、空闲超时时间、最大存活时间。从池中获取连接时，有空闲连接就返回，没有且未达上限就创建新的，达到上限就等待，等待超时返回错误。

归还连接时检查连接是否还健康（模拟的 ping 操作），不健康的直接丢弃。后台定期扫描空闲连接，超时的关闭。连接超过最大存活时间也会被强制回收。

同一个连接获取后如果使用时间过长（超过配置的使用超时），强制回收并返回池中。有个管理接口可以看当前池状态：活跃数、空闲数、等待获取的请求数、累计创建数、累计销毁数。

可能同时有大量请求争抢获取连接。极端情况下所有连接都在使用中且都超时了。端口环境变量 PORT 指定，能编译启动。
