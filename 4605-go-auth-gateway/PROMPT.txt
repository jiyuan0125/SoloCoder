每个服务自己搞认证太乱了，token 验证逻辑到处重复。用 Go 标准库 net/http 写一个认证网关。

用户通过用户名密码登录，验证通过后签发 JWT token。token 里包含用户 ID、角色、过期时间。后续请求带 token 访问，网关验证 token 签名和有效期，合法的把用户信息注入请求头后转发到后端。

角色权限管理：管理员可以创建用户、分配角色、配置角色可访问的 API 路径列表。普通用户只能修改自己的密码。角色可以继承其他角色的权限。

有个 token 黑名单机制：用户可以主动注销 token，注销后该 token 即使没过期也不能用。黑名单定期清理过期的条目。

用户的角色变更后，已签发的 token 里的角色信息不会变。管理接口支持用户 CRUD、角色 CRUD、权限配置。后端服务地址从配置文件读取。端口环境变量 PORT 指定，go build 能编译通过。
