对外暴露的 API 需要统一鉴权、限流、路由，现在各服务自己实现导致策略不一致。用 Rust actix-web 写一个 API 网关。

路由配置支持精确路径、前缀路径和路径参数。路径参数在匹配时提取出来，转发时作为 Header 传给上游。路由优先级：精确 > 前缀（长的优先）。

请求处理管线：认证（JWT 校验）→ 权限检查（基于路由配置的角色要求）→ 限流检查（基于客户端 IP 或用户 ID）→ 转发。任何一步失败直接返回对应错误码。JWT 过期返回 401，权限不足返回 403，限流触发返回 429。

认证模块的公钥从配置加载，支持 RS256 算法验证。权限配置按路由粒度指定允许的角色列表。限流按固定窗口实现，窗口大小和限制数在路由配置中指定。

所有配置从 TOML 文件加载。可能同时收到大量非法请求（无效 token、超限请求）。转发超时 5 秒。端口环境变量 PORT 指定，cargo build 能编过。
