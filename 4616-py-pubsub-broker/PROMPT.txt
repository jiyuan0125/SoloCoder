系统之间的事件通知需要解耦，直接调用耦合太紧。用 Python aiohttp（async）写一个发布订阅消息代理。

Topic 由发送方创建，订阅方通过接口订阅 Topic。消息发布到 Topic 后推送给所有订阅者。推送方式是 HTTP POST 到订阅者提供的回调 URL。推送状态：待推送、推送中、成功、失败。

推送失败时自动重试，按指数退避：间隔 1s、2s、4s、8s、16s，最多重试 5 次。全部失败后标记为死信，存入死信队列。死信可以手动重新推送。

消息状态流转：已发布 → 待推送 → 推送中 → 成功/失败。每个订阅者对每条消息独立维护状态。消息的推送状态变更时记录时间戳。

管理接口：查看 Topic 列表、订阅者列表、消息统计（发布数、推送成功数、失败数、死信数）。Topic 可以暂停/恢复，暂停期间发布的消息缓存起来，恢复后开始推送。端口用环境变量 PORT。
