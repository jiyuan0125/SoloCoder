RPC 框架的连接管理太粗糙，连接泄漏经常发生。用 Java Netty 写一个连接池管理服务（HTTP 接口管理，连接模拟）。

池化资源模拟后端连接：创建时有初始化成本（模拟 100ms），使用时可以执行操作（模拟处理），用完后归还。连接有最大存活时间，超过后强制回收。

连接状态：空闲 → 使用中 → 空闲（归还后）→ 已关闭。空闲超时（默认 5 分钟）的连接自动关闭。获取连接时，有空闲的返回最久没用的，没有空闲且未达上限则创建新的，达上限则排队等待。

排队获取有超时机制（默认 3 秒），超时返回错误。等待队列中的请求按先进先出分配归还的连接。连接归还时如果等待队列非空，直接分配给队列头部的等待者，不经过空闲池。

连接使用超时：获取后超过一定时间（默认 30 秒）未归还的，标记为泄漏，强制回收并记录告警。管理接口可以看到当前连接状态分布、泄漏告警列表。连接泄漏后对应的等待者自动分配新连接。端口环境变量 PORT 指定，能编译启动。
