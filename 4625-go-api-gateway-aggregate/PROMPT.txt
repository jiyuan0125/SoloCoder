公司要搞统一API网关，用 Gin 框架。第一阶段先做请求聚合和鉴权。

网关收到一个请求后，可能需要同时调用多个后端服务，把结果聚合后返回给客户端。比如获取用户详情这个接口，需要同时调用户服务和订单服务。这些后端调用要并发执行。

每个请求进来先校验 JWT Token，从 Token 里解析出用户角色，注入到转发的 Header 里（X-User-Role）。如果 Token 过期或无效直接返回 401。

后端服务的地址配置在一个 JSON 文件里，包括服务名和对应的 URL 列表。服务地址变更后，已经在处理中的请求用旧地址，新请求用新地址。

路由设计要注意：/api/v1/users/{id}/profile 和 /api/v1/users/{id}/orders 是两个不同的聚合接口，路径解析要精确。端口 PORT 环境变量。
