定时任务和异步处理需要一个消息中间件，直接用数据库轮询太慢了。

有个场景需要进程内的消息队列，用 Spring Boot 2.x（JDK 17，Maven）实现。

支持 Topic 模式的发布订阅。

消费者消费失败的消息进入重试队列，最多重试3次，每次间隔递增（5秒、15秒、45秒）。3次都失败的消息进入死信队列，不再自动投递。

还有个场景：如果消息的 Topic 不存在，发布消息时应该自动创建 Topic 还是静默丢弃？

所有写操作要有操作日志记录，谁在什么时候做了什么要可追溯。

内存存储。

提供 Topic 管理、消息发送、消费者注册的 HTTP 接口。

包含 topic、queue、persist、store 模块。
