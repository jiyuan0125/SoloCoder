用 Go 的 Fiber 框架做一个插件化 API 网关。

网关的核心是一个中间件链，请求依次经过：认证插件 → 限流插件 → 日志插件 → 转发插件。每个插件独立实现一个接口（Process(ctx) error），插件的顺序通过配置文件指定。

插件可以热加载：通过接口上传新的插件 .so 文件，网关在不重启的情况下加载新插件替换旧插件。替换时已经在处理中的请求继续用旧插件。

认证插件校验 API Key，限流插件按 Key 限流，日志插件记录请求耗时和状态码，转发插件把请求发到上游。上游地址从配置读取。

配置文件里插件的顺序决定了执行顺序。如果配置了不存在的插件名称，启动时要报错。路径匹配方面，插件链要能区分 /api/v1/users 和 /api/v1/users/{id}。端口 PORT 环境变量。
