用 Rust 的 actix-web 做一个 Cache-Aside 模式的 HTTP 代理。

代理拦截 GET 请求，先查本地缓存（LRU + TTL）。命中就直接返回，没命中就转发到后端服务，拿到结果后写入缓存再返回。

后端数据变更时通过 HTTP 接口通知代理失效指定 key 的缓存。失效操作是即时的——收到失效通知后，该 key 的下一个请求会穿透到后端拿最新数据。

缓存击穿防护：当大量请求同时查同一个不存在的 key（或刚失效的 key），只有一个请求去后端拿数据，其他请求共享同一个结果。

缓存的状态有三种：有效、失效（已收到失效通知但还没重新获取）、不存在。失效状态下的请求行为和不存在不同——失效意味着肯定曾经有过数据，只是不确定现在还有没有。

后端服务变更地址后，代理转发的目标也要跟着变。端口 PORT 环境变量。
