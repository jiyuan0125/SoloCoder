用 Spring Boot 2.x（JDK 17，Maven）写一个日志收集和检索服务，集中管理多个服务的运行日志。

各服务通过接口推送日志，每条日志包含：来源服务名、级别（DEBUG/INFO/WARN/ERROR）、时间戳、消息内容、可选的标签（tags，字符串数组）。缺少服务名或时间戳的日志整批拒绝。时间戳格式要求 ISO 8601，不合法的单独跳过并在返回中说明。

日志存储按服务名和时间范围自动分文件，文件名格式 logs-{service}-{yyyy-MM-dd}.jsonl。每条日志一行 JSON。查询接口支持按服务名、级别、时间范围、关键字（匹配消息内容）筛选，结果分页返回。

聚合统计接口：统计指定时间范围内各服务的各级别日志数量，支持按小时或天分组。还有一个 Top N 接口：返回指定时间内日志量最多的前 N 个服务。

日志有保留策略，默认 7 天。后台定时任务每天凌晨清理过期文件。清理前记录一条汇总日志（清理了多少文件、释放了多少空间）。

告警规则：可以配置规则，当某个服务在指定时间窗口（如 5 分钟）内 ERROR 日志超过阈值（如 100 条），触发告警。告警记录到告警表，包含触发时间、服务名、实际数量。有个接口查询最近的告警记录。告警触发后进入冷却期（默认 10 分钟），冷却期内同一服务不再重复告警。端口环境变量 PORT 指定，能编译启动就行。
