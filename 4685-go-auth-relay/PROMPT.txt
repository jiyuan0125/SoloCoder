隔壁部门做了个统一用户中心，我们需要对接，顺便把 API 认证网关也做了，用 Go Fiber。

网关管理一组上游服务。每个上游服务有自己的路由前缀和认证要求。客户端请求先到网关，网关验证身份后把请求转发给上游。

认证方式支持两种：API Key 和 JWT Token。API Key 在网关侧配置，绑定到具体的客户端标识。JWT 的公钥通过配置文件加载，网关验证签名和过期时间，从 Token 的 payload 中提取用户 ID 和角色。角色信息用于后续的权限判断。

权限控制：每个上游服务可以配置允许访问的角色列表。用户请求某上游时，网关检查用户角色是否在允许列表中。上游服务还可以配置路径级别的权限，比如 /admin 路径只允许 admin 角色。没有配置权限规则的上游默认允许所有已认证用户访问。

转发时把用户 ID 和角色通过 Header 传给上游（X-User-Id, X-User-Role）。日志记录每个请求的认证结果、目标上游、响应状态。管理接口可以查看所有上游配置和请求统计。端口环境变量 PORT 指定，go build 能编译通过。
