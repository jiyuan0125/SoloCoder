用 Java Netty 写一个流量切片服务，把请求按规则分发到不同后端版本。

切片规则配置：每条规则有名称、匹配条件和目标后端列表。匹配条件支持：请求路径前缀、Header 中的值、请求体中的 JSON 字段（只支持第一层）。目标后端列表中每个后端有权重，权重决定流量分配比例。同一请求可能匹配多条规则，按优先级排序，只取第一条。

染色标记：请求被切片后，在转发 Header 中加上 X-Slice-Name 和 X-Slice-Target。同一个会话（通过 Cookie 中的 session_id 识别）的后续请求自动复用第一次的切片结果。会话绑定有过期时间，默认 30 分钟。

流量复制：把匹配某条规则的请求复制一份发到测试环境。复制请求的响应不返回给客户端，只记录到日志。复制超时 3 秒自动放弃。

统计接口：每条规则的命中数、各后端的分配数、会话绑定数、复制成功失败数。规则可以按流量比例调整：比如 v1 和 v2 最初 9:1，逐步调整到 5:5。调整时已有的会话绑定不受影响。端口环境变量 PORT 指定，能编译启动就行。
