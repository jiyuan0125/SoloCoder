之前用的 RabbitMQ 太重了，用 Java Netty 写一个轻量级消息队列，支持 Topic 发布订阅。

生产者往 Topic 发消息，消费者订阅 Topic 消费消息。每个消费者有一个消费组标识，同组内的消费者轮流收到消息（负载均衡），不同组的消费者各自收到全量消息。

消息需要持久化到本地文件，格式你自己定。消费者断连后重连，从上次消费的位置继续。如果消费者长时间没 ack，消息重新投递给同组其他消费者。

管理接口支持创建 Topic、查看消费者列表、查看各 Topic 的消息堆积量。消息堆积超过阈值时自动触发告警日志。

用 Netty 做 HTTP 接口，数据存本地文件或 SQLite 都行。端口通过启动参数或环境变量 PORT 指定。
