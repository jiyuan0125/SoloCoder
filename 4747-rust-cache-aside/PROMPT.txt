用 Rust tokio 做一个 Cache-Aside 模式的缓存代理服务。

这个服务挡在业务数据库前面，客户端发查询请求到缓存代理，代理先查内存缓存，命中就直接返回。未命中就查后端数据库（用 HTTP 调用模拟），把结果写入缓存再返回。

缓存支持 TTL，每个 key 有独立的过期时间。淘汰策略用 LRU，设置最大容量，满了就淘汰最久没访问的。有个缓存穿透防护：对查询结果为空的 key 也缓存一小段时间（30 秒），防止反复穿透到数据库。

缓存预热：服务启动时可以从一个 JSON 文件批量加载热数据。支持手动刷新指定 key。

写操作（新增/修改/删除）同时更新缓存和后端。如果后端写入失败，缓存中的旧数据保留不动。

管理接口查看缓存命中率、当前缓存大小、各 key 的剩余 TTL。项目能 cargo build && cargo run 跑起来，端口从 PORT 环境变量读取。
