连接池泄漏最头疼——借出不归还池子慢慢空了，上次忘关三天泄漏两千多连接差点耗光文件描述符。用 Rust tokio/axum 做 HTTP 连接池管理服务。

为多个上游分别维护连接池每个独立配置：最大连接数、连接超时、读写超时。有空闲直接返回没有未达上限新建达上限 FIFO 排队有连接归还通知队首，等超 10 秒返回 503。连接空闲超 60 秒关闭。

借出超时未还记告警日志更长超时强制回收后做健康检查通过才放回。上游地址配置更新旧连接全关重建。建连失败重试 2 次间隔递增。管理接口看各上游池状态、排队、历史统计（每分钟吞吐、平均延迟）。端口 PORT 环境变量，cargo build 编译通过。
