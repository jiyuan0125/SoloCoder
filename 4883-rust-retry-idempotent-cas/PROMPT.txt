用户点了两次提交订单后端收到两个一模一样请求——不做幂等就重复扣款。用 Rust tokio/axum 实现基于 CAS 的幂等性保障服务。

客户端发请求带 Idempotency-Key Header。服务端用 CAS（Compare-And-Swap）原子操作：key 不存在则执行业务并存储结果；key 存在且已完成直接返回缓存结果；key 存在但处理中则等待执行完成后返回结果。

去重记录有 TTL 过期自动清理。支持重试：请求失败（5xx）时 idempotency_key 保留，客户端可用同一 key 重试。4xx 不重试 key 标记为失败。

管理接口查看去重表统计（总条目、命中率、等待中数量）和重试统计。数据存内存。端口 PORT 环境变量，cargo build 编译通过。
