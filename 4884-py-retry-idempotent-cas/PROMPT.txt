前端重复提交、消息队列重投递——没有幂等层业务侧每个接口都写去重太蠢。用 Python aiohttp 实现 CAS 幂等性保障服务。

客户端发请求带 Idempotency-Key Header。服务端 CAS 原子操作：key 不存在则执行业务存结果；key 已完成返回缓存结果；key 处理中等待完成后返回。去重记录有 TTL 过期自动清理。

支持重试：请求失败（5xx）时 idempotency_key 保留客户端可用同一 key 重试。4xx 不重试 key 标记失败。指数退避控制重试节奏只有 5xx 才重试。

管理接口查看去重表统计（总条目、命中率、等待中数量）和重试统计。数据存 SQLite 持久化。端口 PORT 环境变量。
