服务间异步通信需要消息顺序保证——同一个订单的事件不能乱序处理。用 Rust actix-web/axum 做分区消息中间件相同 key 的消息路由到固定分区保证顺序。

Topic 创建时指定分区数（默认 4），消息按 key 哈希路由无 key 则轮询分配。每个分区独立存储文件按序号命名，消费者可指定消费特定分区或全部分区 offset 每 1000 条持久化一次。消息按写入顺序递增编号每个消费者独立维护消费进度。

消费必须 ACK 超时未确认重新投递。投递失败多次进死信队列可查可重新投递。管理接口看 Topic 列表、分区分布、消费者状态和各 Topic 堆积量。端口 PORT 环境变量，cargo build 编译通过。
