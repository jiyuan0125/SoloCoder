两台机器同时抢到同一把分布式锁导致重复扣款。光靠 Redis SETNX 不够，续期、解锁、防死锁每个环节都致命。加锁时生成唯一 token 标识持有者，同一锁名同一时间只允许一个。续期必须验 token，超时自动释放防死锁。等待队列 FIFO 排队，锁释放后按顺序通知等待者重新竞争。

用 axum 实现。三模块：锁管理器（维护锁状态和持有者）、等待队列（FIFO 唤醒）、过期扫描（定时检查超时锁）。过期扫描通过 channel 通知锁管理器释放。

获取支持阻塞和非阻塞模式，阻塞模式请求进等待队列。同一把锁等待队列上限 100，超限返回失败。Rust tokio/axum，cargo build 编译通过。端口 PORT 环境变量。
