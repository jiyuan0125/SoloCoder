排查支付接口慢请求要翻五个服务日志拼调用链对时间戳，花了两小时才定位到第三方余额查询慢。做分布式链路追踪，每个请求有全局唯一 TraceID 通过 HTTP Header 自动传播。每次调用产生 Span 记录起止时间，所有 Span 按 TraceID 聚合构建调用树展示耗时。超阈值自动标慢调用。查询按 TraceID、服务名、耗时排序。

追踪数据不能丢——服务崩溃时内存缓冲区的 Span 得尽量保留。用 Netty 做请求追踪。追踪数据先写内存缓冲区，每 100 条或每秒刷到本地文件。崩溃后重启从文件恢复已有数据。查询接口按 TraceID 返回整条链路所有 Span（含耗时和异常信息）。

Spring Boot 2.x（JDK 17，Maven）。端口 server.port。
