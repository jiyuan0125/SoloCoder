order-service 全线超时但根因是依赖的 Redis 先挂了。按依赖树逐层检查一眼看出根因。做健康检查编排，配置依赖关系形成依赖树，检查从叶子节点逐层往上汇总，底层不健康上层也标异常。探针支持 HTTP（GET 2xx）和 TCP（连接成功），超时可配。结果分 healthy、degraded、unhealthy。支持定时和手动触发。

服务间有依赖——A 挂了 B 也受影响。用 Spring Boot 做。注册时指定检查方式（HTTP/TCP）、间隔、超时、阈值。结果有缓存：间隔内多次查询返回缓存值。维护依赖图，某服务不健康标记依赖它的为"受影响"。服务可暂停检查暂停期间状态冻结。

Spring Boot 2.x（JDK 17，Maven）。端口 server.port。
