Gin 做一个 API 路由网关。后端有好几组服务，需要根据 URL 把请求分发到不同服务组。比如 /api/users 开头的去用户服务，/api/orders 开头的去订单服务。

路由规则支持精确匹配和前缀匹配，前缀匹配时长的优先（/api/users/profile 比 /api/users 优先）。每个路由规则可以配置是否需要认证，需要认证的接口要检查请求头里的 token。token 的校验逻辑是：从 Redis（先用内存 map 代替）查 token 是否存在且未过期。

接口要支持路径参数，比如 /api/users/123 这种。请求转发的超时时间全局配置，默认 10 秒。管理接口可以增删改路由规则，改了立即生效不用重启。网关本身也要有健康检查接口 /health。
