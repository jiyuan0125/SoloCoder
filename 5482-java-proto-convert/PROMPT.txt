Java/Netty 做 JSON↔Protobuf 编解码网关。场景是公司内部服务统一用 Protobuf 通信，但对外提供的 API 是 JSON 格式。

Schema 管理：通过管理接口上传 .proto 文件定义，网关解析后生成消息描述符。编解码接口：接收 JSON + 消息类型名称，转为二进制 Protobuf 格式；反向也支持。嵌套消息、repeated 字段、枚举都要正确处理。枚举在 JSON 里用字符串名表示，Protobuf 里用数字。

批量转换：一次请求可以提交多条消息一起转换。转换错误的要指出是哪个字段出了问题（字段路径 + 错误原因）。转换统计按消息类型统计成功/失败次数。端口通过配置指定。
