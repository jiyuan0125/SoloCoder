上个月接口联调又因为 JSON 字段对不上出了 bug——后端加了 `discount`，前端还在用旧的 `coupon`。这种事每个月来一次，得自动化。Go 命令行做 JSON 结构对比。

用法：`jsondiff --expected schema_v2.json --actual response.json --output diff.txt`。对比只看结构不看值。每行一个差异：`+ /path: added field "discount" (type: number)`、`- /path: removed field "coupon"`、`~ /path: type changed string→number`。三种标记：`+` 新增、`-` 缺失、`~` 类型变化。

数组长度不同标记：`~ /items: array length 5→8`。嵌套差异用斜杠路径：`/user/address/city`。`--ignore-fields` 排除不对比的字段（逗号分隔）。`--json-output` 时报告输出 JSON 数组：`[{"type": "added", "path": "/discount", "value_type": "number"}]`。

生成报告后尝试发邮件（读环境变量 `NOTIFY_EMAIL` 和 `SMTP_HOST`），没配跳过，stderr 输出 `email not configured, skipping notification`。文件不存在退出码 2，JSON 解析失败退出码 3，成功退出码 0。纯标准库，`go run .` 能跑。
拆成至少三个 Go 文件：main.go 做入口和参数解析，核心处理逻辑独立一个文件，工具函数单独放。
