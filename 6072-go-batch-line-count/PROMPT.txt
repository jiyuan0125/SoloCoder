wc -l 打出来的数字对我们来说太粗糙了——Go 文件、JS 文件、Markdown 全混一起，空行注释行也算进去了。我需要一个能按语言分类统计代码行数的工具，纯标准库实现。

命令行：`linecount <目录路径> --lang go,js,py --exclude vendor,node_modules --format table|json|csv`。按扩展名识别语言（.go→Go、.js/.ts→JS/TS、.py→Python、.java→Java、.rs→Rust），--lang 限定只统计哪些语言，不填统计全部。排除空行和单行注释行（Go 的 //、Python 的 #、Java 的 //），多行注释里的行按普通行算。

输出按语言分组，每组：文件数、总行数、代码行数、注释行数、空行数、代码占比百分比（保留一位小数如 72.3%）。最后输出汇总行，格式与分组一致。--format table 输出对齐文本表格（列用 | 分隔，第二行 ---|---|--- 分隔线），--format json 输出 JSON 数组（字段：language、files、total_lines、code_lines、comment_lines、blank_lines、code_ratio），--format csv 逗号分隔首行为表头。

目录不存在退出码 1，stderr 输出 "error: cannot access directory: <path>: <具体错误>"。无权限读取的文件跳过，stderr 输出 "warning: skip <文件>: permission denied"。正常退出码 0。go build 编译通过，不依赖第三方库。
项目结构要分模块：主入口、核心处理逻辑、工具函数分文件组织，方便测试和维护。
