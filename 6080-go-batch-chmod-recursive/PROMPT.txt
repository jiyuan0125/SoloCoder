线上出过一次事故——部署脚本把 Web 根目录权限全改成 777，安全扫描红了，CTO 在群里@所有人。Go 写个递归权限工具，文件和目录用不同规则，还能按扩展名精细控制，部署前跑一遍确保合规。

用法：`chmodr <目录> --dir-mode 0755 --file-mode 0644 --ext-rules ext_rules.json --dry-run`。--dir-mode 设目录权限，--file-mode 设默认文件权限，--ext-rules 是 JSON 文件定义例外如 {".sh": "0755", ".key": "0600"}。优先级：ext-rules > file-mode > dir-mode（目录只用 dir-mode）。

先遍历目录收集所有文件和子目录，按规则算目标权限。--dry-run 输出变更计划 `<路径> <当前权限如0777> → <目标权限如0644>`，不加则实际修改输出 `changed: <路径> <旧> → <新>`。符号链接跳过。权限已是目标的不输出。

stdout 输出 `summary: N files changed, M dirs changed, K skipped`。无权限修改的 stderr 输出 "permission denied: <路径>" 并跳过。退出码 0 全部成功，4 部分失败。子命令：chmodr apply、chmodr check（只检查不修改）、chmodr rollback（按日志恢复原权限）。纯标准库实现，go run . 能跑。
代码按模块拆分，不要把所有逻辑写在一个文件里。解析、转换、输出分开组织。
