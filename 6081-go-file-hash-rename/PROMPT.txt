上次部署脚本报错没发现——两个同名配置文件在复制时后者覆盖了前者，线上跑了两天才排查出来。做个哈希重命名工具，用文件内容哈希当文件名，彻底避免冲突。

用法：`hash-rename --dir ./configs --algo sha256 --dry-run`。遍历 `--dir` 下所有文件，`--flat` 只处理当前目录，`--recursive` 含子目录。计算内容哈希后重命名为哈希值.原始扩展名，比如 app.conf 变成 a1b2c3d4.conf。`--dry-run` 只打印计划不执行，输出格式为 "原名 -> 新名"。

哈希冲突时说明两个文件内容完全相同，不要覆盖——在文件名后追加序号，如 a1b2c3d4_2.conf，并在 stderr 输出 "duplicate content: file1, file2"。

文件处理阶段：待处理→处理中→校验中→已完成。校验阶段重新计算重命名后文件的哈希，与原始哈希比对。校验失败回退到处理中阶段重新执行。每个阶段的文件数量实时打印到 stderr，格式 "pending:5 processing:2 verifying:1 done:10"。

输入目录不存在退出码 1。文件无法读取跳过并在报告标记 skip，最终打印 "skipped N files"。`--algo` 支持 md5、sha1、sha256。不用第三方包，go build 通过就行。
