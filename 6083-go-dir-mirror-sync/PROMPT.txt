两台服务器之间的文件同步用 Python 脚本写的，依赖多环境一换就炸。而且上次有人误操作把目标目录清空了，同步脚本直接把源目录也同步没了——单向同步写成了双向同步。Go 重写目录镜像同步工具，必须是严格的单向镜像，安全第一。

核心思路——让目标目录完全镜像源目录的状态。比较逻辑：按相对路径逐个比对，用文件大小 + 修改时间判断是否相同（时间差 < 2 秒视为相同，兼容不同文件系统的精度差异）。目标多出的文件和目录需要删除，目标缺少的需要复制，内容不同的需要更新。

删除操作必须用户确认：列出待删除列表后提示 "delete N files/dirs? [y/N]: "，输入 y 才执行，否则跳过删除只做复制和更新。命令：`mirrorsync <源目录> <目标目录> --dry-run --exclude "*.tmp,.git" --delete-confirm`。--dry-run 只输出三类操作清单（ADD/UPDATE/DELETE），不实际执行。--exclude 逗号分隔排除模式，支持 * 通配符。

输出格式：每行一种操作，`ADD <相对路径>`、`UPDATE <相对路径>`、`DELETE <相对路径>`。最后汇总 `summary: N added, M updated, K deleted`。源目录不存在退出码 1，stderr 输出 "error: source directory not found: <路径>"。目标不存在自动创建（权限 0755）。单个文件复制失败 stderr 输出 "copy failed: <文件>: <错误>" 并跳过。退出码 0 全部成功，6 部分失败。纯标准库实现，go run . 能跑。
代码分文件组织，解析器、处理器、输出器分开，main.go 只做参数解析和流程串联。
