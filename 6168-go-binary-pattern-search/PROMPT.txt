安全审计要求在二进制固件中搜索已知恶意特征码和可疑文件头签名。strings 命令只能看可打印字符，十六进制模式匹配得自己写工具。

写个 Go CLI `binsearch` 做二进制模式搜索。`binsearch -f firmware.bin -p "FFD8FFE0"` 用十六进制模式搜索 JPEG 文件头。也支持 ASCII 模式：`binsearch -f data.bin -p "PK\x03\x04" --hex` 强制按十六进制解析。`-p` 可以多次指定，同时搜索多个模式。

匹配结果输出格式：`<filepath>:<offset>: <pattern> matched`。加 `--context 16` 输出匹配位置前后各 16 字节的十六进制 dump。`--count` 只输出各模式的匹配次数汇总。`--offset-range 0x1000-0x2000` 限制搜索范围。

目录递归搜索：`binsearch -d /firmware/ -p "4D5A"` 扫描目录下所有文件，跳过不可读文件并打印 `[SKIP] <file>: permission denied`。大文件（>1GB）用滑动窗口读取，内存占用不超过 64MB。模式长度超过文件大小时输出 `[SKIP] pattern longer than file: <file>`。

合并完成后默认删除源文件（`-f` 指定的临时文件），`--keep` 保留。不用第三方包，`go build` 通过就行。退出码 0 找到匹配，1 没找到，2 参数错误，3 文件读取失败。
至少拆成两个包或三个文件以上，不要单文件一把梭。
