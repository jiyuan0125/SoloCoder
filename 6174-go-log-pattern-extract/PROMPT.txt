现成方案功能太多太重，我们只需要按自定义模板从日志里提字段就行。用法 `logextract <logfile> --pattern '<timestamp> [<level>] <msg>' --fields timestamp,level,msg --output extracted.json --sort-by timestamp`。pattern 中的 `<name>` 是占位符，匹配到非空白字符序列，对应 fields 中指定的字段名。fields 用逗号分隔，顺序和 pattern 中的 `<name>` 一一对应，数量不匹配时 stderr 输出 "error: fields count mismatch: pattern has N, fields has M" 退出码 1。匹配失败的行跳过，stderr 输出 "warning: line N does not match pattern"。输出 JSON 是数组，每个元素是一个对象，key 是字段名，value 是提取的字符串。`--sort-by` 指定按哪个字段排序，字段值能解析为 time.RFC3339 时按时间排序，否则按字符串字典序。`--limit 100` 限制最多输出 N 条结果。输入文件为空时输出空数组 `[]` 并退出码 0。输入文件不存在退出码 1，stderr 输出 "error: file not found"。同步流程也实现：准备→扫描→传输→验证→完成五阶段，验证失败从传输阶段重试，最多 3 次。不用第三方包，go build 通过就行。
拆成至少三个 Go 文件：main.go 做入口和参数解析，核心处理逻辑独立一个文件，工具函数单独放。
