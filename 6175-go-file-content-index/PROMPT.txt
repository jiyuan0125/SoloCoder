几 GB 的代码库 grep 一遍要二十分钟，改了代码想确认有没有别的地方引用，等不起。建个倒排索引，第一次慢点后面秒出，中文编码也比现成搜索工具支持好。

建索引：`indexctl build --dir ./src/ --store .index/` 扫描目录建倒排索引。`--ext .go .py .java` 过滤文件类型，默认索引所有文本文件。索引存储用简单的文本格式：每行一个关键词，后面跟文件路径和行号列表。

查询：`indexctl query --keyword "TransactionHandler" --store .index/` 查询，输出 `filepath:line_number: line_content`。多关键词空格分隔表示 AND 关系——结果必须包含所有关键词。增量更新：文件改了以后 `indexctl update --dir ./src/ --store .index/` 只重新索引 mtime 变化的文件。全量重建加 `--full`，删除的文件自动清理索引条目。

查询走内存加载索引文件，启动时读 `.index/` 下数据。索引文件不存在报 `index not found, run build first` 退出码 1。空目录建索引输出 `no files indexed` 退出码 0。`--keyword` 未指定报 `no keyword specified` 退出码 1。关键词为空字符串跳过不报错。索引文件损坏报 `corrupt index: ...` 退出码 2，需要重新 build。

构建流程：解析→编译→测试→打包，测试失败不打包。go build 能编译通过，不依赖第三方库。
