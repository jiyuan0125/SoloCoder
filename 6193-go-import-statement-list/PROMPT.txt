项目里混着 Go、Python、Java 三种语言的代码，老板问「我们到底依赖了哪些外部库」——找到天黑也找不完。Go CLI 做一个跨语言 import 语句扫描器，自动按文件后缀选择解析策略，依赖去重分组一次出结果。

1. 命令 `importscan scan --dir ./project/ --output deps.json`。Go 匹配 `import "xxx"` 和批量 `import ( ... )`。Python 匹配 `import xxx` 和 `from xxx import yyy`。Java 匹配 `import com.xxx.Yyy`。按文件后缀自动选择：`.go` `.py` `.java`，其他后缀跳过。

2. 依赖去重分组输出 `{"go": {"stdlib": ["fmt","os"], "external": ["github.com/gin-gonic/gin"]}, "python": {"stdlib": ["os","json"], "external": ["requests","flask"]}, "java": {"external": ["org.springframework.boot"]}}`。Go 标准库列表内置（go stdlib 包名硬编码），Python 按常见标准库列表判断，Java 按包名前缀 `java.` `javax.` 区分。识别不了的归入 `unknown` 不报错。

3. `--lang go,python` 只扫描指定语言。`--external-only` 只输出第三方依赖。`--graph` 输出文本树形依赖图，每层缩进两空格。`--count` 额外输出每种语言的外部依赖总数到 stderr。

4. 空项目零依赖输出空 JSON `{}` 退出码 0。`--dir` 不存在报 `directory not found: ...` 退出码 1。文件编码非 UTF-8 跳过并 stderr 记 `encoding error: filename`。import 语句语法不标准（比如跨行的 Java import）尽力解析，解析失败的归 `unknown`。

go build 能编译通过，不依赖第三方库。代码分几个文件组织，别全写 main.go 里。
代码分文件组织，解析器、处理器、输出器分开，main.go 只做参数解析和流程串联。
