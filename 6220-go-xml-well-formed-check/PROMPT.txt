先跑一遍格式检查拿到错误列表，再根据错误类型分级处理——这是 XML 报文校验该有的流程。上游推过来的 XML 格式经常不合法，标签没闭合、属性缺引号、实体引用写错，Go 重写一个 XML 格式检查器，逐条报错并标明行号。

命令格式：`xml-check validate <file.xml> [--output text|json]`。文本输出每条错误一行：`[行号:列号] <错误类型>: <描述>`，错误类型分为 `unclosed-tag`（标签未闭合）、`attr-quote`（属性引号缺失）、`entity-ref`（实体引用错误）、`malformed`（其他格式错误）。JSON 输出结构 `{"file": "<路径>", "errors": [{"line": N, "col": N, "type": "<类型>", "message": "<描述>"}], "valid": bool}`。退出码：0 合法 / 1 存在错误 / 2 文件不存在或读取失败。空文件报 `empty file` 退出码 2。支持的实体引用至少检查 `&amp;`、`&lt;`、`&gt;`、`&quot;`、`&apos;` 这五个。

内部扫描流程分阶段：初始化→扫描中→分析中→报告生成，分析中发现问题就把该条标记为异常。另外依赖关系变更后，下游的依赖图要触发重新计算。go build 能编译通过，不依赖第三方库。
代码按模块拆分，不要把所有逻辑写在一个文件里。解析、转换、输出分开组织。
