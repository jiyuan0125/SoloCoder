你能想象吗？上个月数据同步丢了一整天的量，查到最后发现是 JSON 配置文件少了个逗号——解析器直接静默失败，没有任何报错。这种事不能再发生了。Go 写一个 JSON 语法验证工具，错误位置和原因都输出清楚，支持批量验证整个目录。

CLI 设计：`json-validate <文件或目录> [--recursive] [--output text|json]`。文本输出格式 `[<文件名>:行号:列号] <错误描述>`，常见错误类型要能识别：缺少逗号、多余逗号（trailing comma）、未闭合的字符串、未闭合的数组/对象、非法值（如裸露的 undefined）。JSON 输出数组，每项含 file、line、column、error_type、message。加 `--stop-on-error` 参数时遇到第一个错误就停止该文件的检查，继续下一个文件。退出码：0 全部合法 / 1 存在语法错误 / 2 输入路径不存在。空文件报错 `empty file is not valid JSON`，只含空白字符的文件同样报错。目录模式下最后输出汇总：`总计: N 文件, 合法: M, 错误: K`。

跑完验证自动更新统计信息（累计验证文件数、错误数），第一次跑没有历史数据可更新，要处理好——新建统计文件而不是报错。纯标准库实现，`go run .` 能跑。
不要写单文件，核心逻辑、CLI 入口、辅助工具各放一个文件。
