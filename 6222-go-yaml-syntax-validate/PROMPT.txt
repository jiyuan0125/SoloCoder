YAML 缩进差一个空格解析就挂，上周 CI 连续失败了三次，每次都是缩进问题。于是决定自己用 Go 写一个 YAML 语法验证工具，缩进错误、类型不匹配、重复键名这些常见问题全部检出，错误信息必须带行号。

验证命令：`yaml-validate <file.yaml> [--output text|json]`。逐字符解析时维护缩进栈，发现缩进不一致（混用空格和 tab、同级缩进深度不同）立即报错并指出期望深度。文本输出 `[行号] <错误类型>: <描述>`，错误类型覆盖：`indent-error`（缩进错误，指定期望深度和实际深度）、`type-mismatch`（值类型与上下文不匹配）、`duplicate-key`（重复键名）、`invalid-anchor`（未定义的 anchor 引用）。JSON 输出含 errors 数组，每项有 line、type、message、context（前后各一行内容）字段。退出码：0 合法 / 1 有错误 / 2 文件不存在。空 YAML 文件（0 字节或只有注释）视为合法，退出码 0。多文档 YAML（`---` 分隔）每个文档独立校验，错误行号为全局行号。

内部同步流程走这几个阶段：准备→扫描→传输→验证→完成，验证失败要重试传输。不用第三方包，go build 通过就行。
项目结构要分模块：主入口、核心处理逻辑、工具函数分文件组织，方便测试和维护。
