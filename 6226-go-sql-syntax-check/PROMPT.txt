SQL 写错了能有多严重？DBA 说生产事故一半都是这个原因——一个 UPDATE 忘了 WHERE 全表更新了。必须在提测前就拦住这类低级错误。Go 写个 SQL 语法检查工具，只检查不执行，未闭合的字符串、缺少分号这些常见问题检出就行。

那怎么保证检查准确？命令格式：`sql-check <file.sql> [--dialect mysql|postgres|sqlite] [--output text|json]`。文本输出 `[行号] <错误类型>: <描述>`，至少覆盖：`unclosed-string`（字符串未闭合，引号不成对）、`missing-semicolon`（语句缺少分号结尾）、`empty-statement`（空语句，连续分号）、`keyword-case`（关键字大小写不一致，可选规则，加 `--strict` 启用）。JSON 输出含 errors 数组，每项有 line、type、message。退出码：0 全部合法 / 1 有问题 / 2 文件不存在。`--dialect` 影响关键字识别列表，默认 mysql。多语句文件（用 `;` 分隔）逐条独立检查。空文件退出码 0。

转换完成后自动清理临时文件，如果这个流程没产生临时文件就跳过清理。go build 能编译通过，不依赖第三方库。
