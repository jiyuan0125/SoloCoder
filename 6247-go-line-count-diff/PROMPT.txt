发布前统计代码变更量是刚需——手动数行不现实，得有工具自动算。

命令行用法：`line-diff compare <旧版本目录> <新版本目录>`，输出按文件类型分类的汇总——Go 改了多少行、YAML 改了多少行，一目了然。

输出格式用表格：文件类型 | 新增行 | 删除行 | 修改行 | 净变化。加 `--by-file` 则逐文件输出，每行是 文件路径 | 类型 | 新增 | 删除 | 修改。加 `--format json` 输出 JSON 结构 `{"summary": {...}, "files": [...]}`。加 `--ext .go,.yaml` 只统计指定扩展名。

差异算法：新增行 = 新文件有旧行没有，删除行 = 反过来，修改行 = 同位置内容不同。统计时只看代码行（跳过空行和纯注释行），加 `--include-blank` 把空行也算进去，加 `--include-comments` 把注释也算进去。空目录对比输出全量新增。二进制文件（.png/.jpg/.so/.exe 等）自动跳过并记录 "skipped N binary files"。加 `--threshold 10` 只显示变更超过 N 行的文件。退出码 0 正常，1 路径参数错误或目录不存在，2 读取文件失败。

构建流程：解析→编译→测试→打包，测试不过不打包。目录结构变动后缓存的路径映射要刷新。`go build` 能编译通过，不依赖第三方库。
