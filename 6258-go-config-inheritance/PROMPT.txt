配置继承搞了三层——基础配置、环境配置、个人配置，手动合并总漏项。有没有自动化的办法？`cfginherit --base base.yaml --env prod.yaml --user user.yaml --output merged.yaml --strategy override|merge --dry-run`。三层配置按顺序加载，后者覆盖前者。override 策略下标量值直接覆盖，merge 策略下 map 类型递归合并、数组按值追加（不去重）。`--dry-run` 只输出合并预览到 stdout，不写文件，用 +/- 前缀标注变更。循环引用检测：如果某个配置文件通过 `${include: path}` 引用自身或形成环路，stderr 输出 "error: circular reference detected: <path>" 退出码 1。合并结果输出到 --output 指定路径，不指定则 stdout 输出。某个配置文件不存在时 stderr 输出 "warning: config file not found: <path>" 跳过该层，不是致命错误。所有文件都不存在则退出码 1。配置值用 ${VAR} 语法引用环境变量，解析时从 os.Getenv 替换，环境变量不存在时保留 ${VAR} 原样不报错。任务状态支持排队→运行→暂停→完成四个阶段，暂停后可以继续。不用第三方包，go build 通过就行。
