上周排查一个连接超时问题，查了两个小时才发现环境变量 APP_DB_PORT=3307 覆盖了配置文件里的 3306，而默认值 5432 根本没人记得——到底哪个值在生效，四个人有四种说法。

Go 写配置覆盖链工具。优先级：默认值 < 配置文件 < 环境变量 < 命令行参数，高优先级覆盖低优先级。用法：`cfg-chain resolve --defaults defaults.yaml --file config.yaml --env-prefix APP_ --cli-flags "db.port=3307"`。

输出合并后的完整配置到 stdout，加 `--show-chain` 在每个字段旁标注来源，格式 `db.port = 3307 (来源: cli-flag)`，来源标签：`default`、`file:<文件名>`、`env:<变量名>`、`cli-flag`。加 `--format json` 输出结构化结果 `{"resolved": {...}, "chain": {"db.port": {"value": 3307, "source": "cli-flag", "overrides": [...]}}}`。

文件不存在报 "config file not found: <路径>" 退出码 1。环境变量格式 `${PREFIX}_${KEY}` 自动映射，`APP_DB_PORT` 映射到 `db.port`。冲突链中某个值类型不一致（比如默认值是数字环境变量是字符串）打警告 "type conflict at <路径>: expected <类型> got <类型>"。文件处理分阶段：待处理→处理中→校验中→已完成，校验失败回到处理中。`go build` 能编译通过，不依赖第三方库。
不要写成一个 main.go 搞定所有事情。按职责拆文件：入口、解析、处理、输出分开。
