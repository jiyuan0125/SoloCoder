配置文件被程序一改，注释全没了——辛辛苦苦写的参数说明、使用注意事项，每次更新配置都白写。这事儿忍了好几个版本了，必须搞个注释保留机制。

子命令 set 修改配置值，--key 指定配置路径（点号分隔），--value 指定新值。新增的配置项用 --insert-at 指定插入位置（行号或 after:KEY_NAME），不指定就追加到所属 section 末尾。修改已有 key 时，紧邻上方的注释块（连续 # 开头的行）保持不动。子命令 delete 删除配置项，关联的注释——紧邻的上方注释块——一起删掉，不留悬空的 "# 这里的XXX" 之类的东西。删除后如果留下连续空行超过两行，压缩为一行。子命令 diff 对比两个配置文件的差异，忽略注释和空行差异，只比较有效配置项，输出 "KEY: OLD_VALUE -> NEW_VALUE"。子命令 sync 做配置同步，流程五步走：准备（校验源和目标文件格式）→扫描（对比差异）→传输（写入变更）→验证（回读确认一致）→完成。验证失败自动重试传输，最多 3 次，都失败输出 "error: sync verification failed after 3 retries: KEY"。配置文件不存在时自动创建，空文件也正常处理。不支持的格式输出 "error: unsupported format: EXT" 并 exit 1。

不用第三方包，go build 通过就行。纯标准库解析，主逻辑和辅助函数分文件。
