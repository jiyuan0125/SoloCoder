两台机器的文件目录要完全同步，源端删了什么目标端也删，加了什么也加——这不就是目录镜像吗？rsync 的 --delete 能干但太重了，我们要一个纯 Go 实现直接嵌入调用，不装额外依赖，也不依赖 SSH 通道。

用法：mirror -source /data/src -target /data/backup。扫描源端和目标端目录，比较文件列表后执行同步操作：源端有但目标端没有的文件拷贝过去，目标端有但源端没有的文件删除，两端都有但内容不同的以源端为准覆盖。比较方式默认用文件大小加修改时间快速判断，加 -checksum 参数开启 MD5 全量校验模式，适合对数据一致性要求高的场景。子目录递归处理，遇到符号链接时跳过并记录。

操作前先输出变更计划表，三列：操作类型（ADD/COPY/DELETE）、源路径、目标路径。加 -dry-run 只输出计划不实际执行，方便人工确认。文件排除：-exclude "*.log" -exclude "*.tmp" 排除匹配 glob 模式的文件，支持多个。并发拷贝 -workers 4 控制并发数，默认 4。执行完输出统计汇总：新增 N 个、更新 N 个、删除 N 个、跳过 N 个、失败 N 个。源或目标目录不存在时输出 "directory not found" 退出码 1。单个文件操作失败不中断整体流程，记录到失败列表最后汇总输出。

go build 能编译通过，不依赖第三方库。主逻辑和辅助函数分文件写。
