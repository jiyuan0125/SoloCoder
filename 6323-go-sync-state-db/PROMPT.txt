先 10 万个文件每次全量比一遍太蠢，建个状态数据库增量同步。`syncdb --root <dir> --db .syncstate.db --action init|update|check|rebuild`。init 扫描目录建初始状态库，每个文件记录 relative_path、mtime（Unix 纳秒）、size（字节），数据存本地 JSON 文件，格式 {"version": 1, "files": [{"path": "...", "mtime_ns": N, "size": N}]}。update 扫描目录更新变化的条目，mtime 或 size 变了的标记为 dirty，同时输出变更列表到 stdout。check 对比两个状态库（用 `--db-other` 指定第二个库），输出差异列表：added（新文件）、deleted（已删除）、modified（mtime 或 size 变化），JSON 数组格式，每个元素包含 status、path、old_mtime、new_mtime、old_size、new_size。rebuild 删除旧库从源端完全重建。状态库文件损坏或格式不对时 stderr 输出 "error: corrupt state db, use rebuild" 退出码 2。`--db` 不指定默认 `.syncstate.db`。root 目录不存在退出码 1。记录有四种状态：draft→pending→approved→archived，通过后可撤回重新编辑。标准库写的，go run . 直接跑。
