上次事故根因是同一个文件备份了 47 份，磁盘直接满了。做个备份去重存储——相同内容只存一份物理文件，用引用计数跟踪谁在用。

命令行用法：`dedup-store add <文件路径>` 添加备份，`dedup-store list` 列出所有条目，`dedup-store remove <文件路径>` 删除引用。remove 时先检查引用计数，大于 1 就只减计数不删物理文件，等于 1 才真正删文件。输出格式：每行一个条目，字段用 tab 分隔——文件名、SHA256、引用数、首次备份时间。`dedup-store stats` 输出总条目数、去重节省空间、物理文件数。

内部用 SHA256 做内容指纹，映射表存 JSON 文件（默认 `~/.dedup-store/index.json`）。启动时读取映射表，退出时写回。文件不存在就自动创建空映射和目录。add 时如果 SHA256 已存在，引用计数加 1，不复制文件。相同路径重复 add 不增加计数，直接提示 "already tracked" 并退出码 0。

同步流程五步走：准备阶段锁定映射表 → 扫描源目录建立文件列表 → 传输阶段逐个 add → 验证阶段对每个新文件重算 SHA256 和存储的值比对 → 验证失败回退并重试传输一次。全部完成后输出统计：新增 N 个、去重 N 个、失败 N 个。

go run . 就能跑起来，纯标准库，主逻辑和辅助函数分文件写。
