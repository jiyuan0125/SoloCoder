问题出在传输中断上——文件传了一半网络断了，对面拿到个半截文件还以为数据完整。金融审计那边盯着这事，要求传输过程不能出现任何半成品文件，半成品文件一律视为安全事故。

写一个 Go 工具 `atomiccp`，实现原子性文件传输。流程是先写到目标目录的临时文件（`.tmp` 后缀），写完后 `os.Rename` 替换为目标文件名。rename 失败则删除临时文件并退出码 1，打印 `error: rename failed: <path>: <系统错误>`。支持参数 `--source src/ --dest dst/`，`--checksum` 开启传输后 SHA256 校验，校验失败打印 `checksum mismatch: <file>` 并退出码 2。源目录不存在退出码 1 输出 `error: source directory not found: <path>`。空文件也要正确传输（生成 0 字节目标文件）。传输完主文件后自动在同目录生成 `.summary` 摘要文件，内容是文件名+大小+时间戳的 JSON 数组：`[{"name":"a.txt","size":1024,"copied_at":"2024-01-15T14:30:00Z"}]`。如果源目录里没有文件，摘要文件输出空数组 `[]`。全标准库，`go run . --source ./data --dest ./backup` 能跑。
