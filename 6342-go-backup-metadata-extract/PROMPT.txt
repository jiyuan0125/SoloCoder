备份全存在 S3 上，产品经理问"上周三那批备份里有没有 user.csv"，总不能每次都下载几十 GB 恢复再看。做一个元数据提取，不下载完整备份就能查看文件列表和基本信息。

`meta extract backup_20240115.tar.gz` 解析本地备份文件头，输出文件列表 `{name, size, mod_time, type}`。`meta extract s3://bucket/backup_20240115.tar.gz` 远程模式，只下载文件索引部分（tar header），不下载实际内容。`meta search backup_20240115.tar.gz --name "*.csv" --larger 1MB` 按文件名模式和大小区间过滤。

`meta diff backup_v1.tar.gz backup_v2.tar.gz` 比较两次备份的文件差异，输出 `{added: [...], removed: [...], modified: [{name, old_size, new_size}]}`。`meta stats backup_20240115.tar.gz` 输出汇总：文件数量、总大小、按类型分布。

S3 连接用环境变量 `AWS_REGION`、`AWS_ACCESS_KEY_ID`、`AWS_SECRET_ACCESS_KEY`，缺失时 `error: AWS credentials not configured` exit 1。tar 格式损坏 `warning: corrupted tar header at offset <N>, skipping remaining entries`。同步完成后记录日志，数据库不可用时写本地 `sync.log`。编译 `go build` 就行，不用第三方包。
