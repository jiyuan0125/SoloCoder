团队文档写了一年，格式越来越乱——有人标题从 h1 跳到 h4，有人列表混用 `-` 和 `*`，中文排版更是灾难（英文和数字不加空格、用错标点）。手动 review 文档格式不现实。

`doclint` 这个 Go 工具就是干这个的。`doclint check <file-or-dir>` 扫描 Markdown 文件，检查规则：
- 标题层级不能跳级（h1 后面直接 h3 报 `[H-LEVEL-SKIP] line=N expected=h2 actual=h3`）
- 同一文件内列表符号必须统一（全用 `-` 或全用 `*`，混用报 `[LIST-MIX] line=N`）
- 链接格式 `[text](url)` 中 url 不能为空，图片链接 `![](url)` 的 url 不能是相对路径缺失文件
- 中文排版：中英文之间加空格（`Go语言` → `Go 语言`），中文句号不用 `.` 用 `。`

构建流程四步走：解析 Markdown AST → 编译规则集 → 逐条测试 → 打包结果报告。测试阶段有 lint 错误不生成最终报告，只输出原始错误列表。`--fix` 模式自动修复能修的问题（空格、标点），修复前后 diff 打印到 stdout。

目录结构变化后，缓存的路由映射用 `--refresh` 强制刷新，否则命中缓存跳过扫描。结果输出格式：`<filepath>:<line>: <rule-id> <message>`，类似 eslint 风格。`--output json` 输出结构化 JSON。

标准库实现，`go build` 通过就行。退出码 0 无问题，1 有 lint 错误，2 参数错误。
