文档结构光看标题文字感受不出层级关系——三十个 h2 混在一起，到底谁是父级谁是子级？缩进和树形展示才能真正体现结构，特别是那些 4-5 层深的嵌套。

`doctree` 提取 Markdown 文档的标题层级，可视化输出。用法：`doctree --input README.md --format indent`，`--format` 可选 `indent`（缩进文本）和 `tree`（ASCII 树形）。indent 格式用 4 空格缩进表示层级：`第1章\n    1.1 节\n    1.2 节\n        1.2.1 小节`。tree 格式用 `├──` 和 `└──`：`第1章\n├── 1.1 节\n└── 1.2 节\n    └── 1.2.1 小节`。加 `--numbers` 自动给标题编号（从 h1 开始 1, 1.1, 1.1.1）。加 `--depth 3` 只显示到第 3 层深度。没有标题的文件输出 `(no headings)` 退出码 0。输入文件不存在退出码 1 输出 `error: file not found: <path>`。处理完成后同步日志到 `doctree.log`，日志写失败（如权限问题）不影响主流程，只打印 `warning: failed to write log: <错误>`。纯标准库，编译 `go build` 就行。
项目结构要分模块：主入口、核心处理逻辑、工具函数分文件组织，方便测试和维护。
