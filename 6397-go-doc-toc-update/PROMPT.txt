问题是这样的：文档改了一堆标题，但开头那个目录还是上周的。每次手动更新目录很容易漏，而且格式容易乱。几十个 Markdown 文档手动维护 TOC 简直是噩梦。

1. 写个工具 `tocupd` 自动维护文档目录。它识别 Markdown 里的目录标记 `<!-- TOC -->` 和 `<!-- /TOC -->`，扫描文档中的所有标题（`#` 到 `######`），生成带锚点链接的目录列表替换到标记之间。
2. 命令格式：`tocupd --input README.md`，直接修改原文件。加 `--dry-run` 只输出预览到 stdout 不修改文件。加 `--start-heading 2 --end-heading 4` 只包含 h2 到 h4 级标题。目录格式：`- [标题文字](#锚点)`，缩进用两个空格表示层级，锚点规则是标题文字转小写、空格变 `-`、去除特殊字符。
3. 文件中没有 TOC 标记时打印 `warning: no TOC markers found, use <!-- TOC --> and <!-- /TOC -->` 退出码 0。没有标题时在 TOC 区域写入 `<!-- no headings found -->`。输入文件不存在退出码 1 输出 `error: file not found: <path>`。`go build` 能编译通过，不依赖第三方库。代码分几个文件组织：标题扫描一个文件、锚点生成一个文件、主流程一个文件。
