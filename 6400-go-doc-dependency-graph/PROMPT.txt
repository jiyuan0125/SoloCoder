文档互相引用的网越来越密，上个月删了一篇旧文档，结果三个页面链接全红。当时要是能提前知道影响范围就好了。

这个工具干两件事：一是构建文档间的引用关系图，二是帮你安全删除。

用法：depgraph scan --dir ./docs 递归扫描所有 .md 文件，提取 [text](url) 格式的内部链接，建成邻接表。输出 deps.json，格式：{"nodes": [{"id": "guide.md", "title": "..."}], "edges": [{"from": "guide.md", "to": "api.md"}]}。

加上 --check-orphan 标志会标记没有任何入边的孤立文档（首页除外），输出到 stderr 并在 JSON 里加 orphans 字段。加上 --check-cycle 检测循环引用，如果 A→B→C→A 存在，输出 ERROR: cycle detected: A→B→C→A 并以 exit code 2 退出。

depgraph delete --file ./docs/old.md 模拟删除，列出所有会受影响的文档（有指向它的链接的那些），打印表格：受影响文件 | 引用位置行号 | 链接文本。不实际删除。

审批流程实例也管理起来：用户提交删除请求，状态流转为提交→初审→复审→通过，初审不过可以修改重提。状态存在 status.json 里。

go build 一把过，纯标准库，主逻辑和辅助函数分文件。
