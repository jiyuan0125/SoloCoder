你有没有遇到过这种情况？一个函数写了 800 行，圈复杂度飙到 45，参数 11 个，谁都不敢改。不如写个工具把这些问题全部量化出来。

`fnmetric` 是一个 Go 函数质量分析工具。命令格式：`fnmetric analyze --dir ./pkg --threshold complexity=20,params=5,returns=3`。它扫描指定目录下所有 `.go` 文件，解析 AST 提取每个函数的圈复杂度（统计 if/for/switch/case 分支数+1）、参数数量、返回值数量，超过阈值的函数标红输出。输出是表格格式，列为文件名、函数名、圈复杂度、参数数、返回值数、状态（OK/WARN）。状态判定：全部低于阈值为 OK，任一项超过为 WARN。还支持 `fnmetric report --dir ./pkg --format json` 输出 JSON 格式报告，结构是 `{"files":[{"name":"xxx","functions":[{"name":"yyy","complexity":15,"params":3,"returns":2,"status":"OK"}]}]}`。目录不存在退出码 1 输出 `error: directory not found: <path>`。没有 Go 文件打印 `no Go files found` 退出码 0。只依赖标准库，编译完直接跑。
代码分文件组织，解析器、处理器、输出器分开，main.go 只做参数解析和流程串联。
