准备开源了，翻了一遍代码发现导出函数一大半没写注释，godoc 渲染出来全是空描述。得赶紧摸个底，按包分组统计注释覆盖率，看哪些包最需要补，不能带着一堆空注释发布出去被人笑话。

工具扫描指定目录下所有 .go 文件，解析 AST 找出所有导出函数（func 首字母大写）和导出类型（type 首字母大写），检查紧邻其上方是否存在以函数名或类型名开头的标准注释，比如 // FuncName 开头的才算有效注释。按包汇总，输出每个包的导出符号总数、有注释数、覆盖率百分比，最后给一个总体覆盖率。覆盖率低于阈值的包用 ⚠ 标记高亮。遇到 build tag 排除的文件自动跳过，测试文件（_test.go）默认不纳入统计。

命令行用法：comment-coverage -dir ./pkg -threshold 80。-dir 指定扫描根目录，默认当前目录；-threshold 设置覆盖率告警阈值百分比，低于此值退出码返回 1，否则退出码 0。输出格式支持终端表格和 JSON 两种，加 -format json 切换。JSON 输出包含 packages 数组，每项有 name、exported、commented、coverage 四个字段，以及顶层 total_coverage 字段。扫描空目录时输出 "no Go files found" 退出码 0。纯标准库实现，go run . 就行。
