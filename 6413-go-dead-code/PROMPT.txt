先定义什么是死代码——`return` 后面还写了逻辑、`if false {}` 里的整块代码、永远不可达的 `else` 分支、声明了但从未使用的函数。合规审计要求死代码占比报告，那就全扫一遍。

`dead-code <目录路径>` 递归扫描 Go 源码文件（`.go` 后缀）。检测模式：一、return/continue/break/panic/golang 之后到函数结尾的代码；二、`if false`、`if true { } else { }` 等常量条件下的不可达分支；三、被注释掉的代码块（连续 3 行以上注释且含有效语句特征如赋值、函数调用）。

每个发现输出：`文件:行号: 死代码类型 | 代码片段前 80 字符`。最后汇总：按类型分组计数、占总代码行数百分比。`--threshold 5` 死代码占比超过 5% 时退出码 2（CI 集成用），低于阈值退出码 0。

校验完成后自动更新统计信息——历史结果存 `.dead-code-history.json`，每次运行追加一条记录：`{"date":"...","total_lines":N,"dead_lines":N,"ratio":"3.2%"}`。首次运行没有历史文件就创建新的。`--trend` 对比上次结果输出变化：`死代码占比: 3.2% → 4.1% (+0.9%)`。

不用第三方包，go build 通过就行。
