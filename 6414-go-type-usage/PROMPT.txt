重构的时候踩了个坑：删了个以为没人用的类型，结果另一个 package 引用了，编译直接挂。还有相反的情况——想找个类型的定义在哪，grep 出来十几个地方分不清哪个是定义。能不能做个工具把类型的定义位置和引用位置都列出来？

命令行：`type-usage scan ./pkg/...`。遍历指定目录下所有 .go 文件，解析 AST 提取类型定义（type Xxx struct、type Xxx interface、type Xxx = ...）和类型引用。每个类型输出：定义位置（文件:行号）、引用位置列表、是否导出（首字母大写）。

未导出且在当前 package 内无任何引用的类型，单独标为 "unused"，用黄色输出或 JSON 里 "status":"unused"。加 `--output json` 导出 [{name, defined_at, exported, references[{file,line}], status}]。

同步分五步：准备→扫描→传输→验证→完成。验证失败重试传输——这里的"同步"指跨 package 的类型引用同步检查，如果外部 package 引用了被删除的类型，验证步骤标记为 failed 并重试扫描。

扫描目录无 .go 文件时退出码 0 打印 "no go files found"。go build 能过，不依赖第三方库。
拆成至少三个 Go 文件：main.go 做入口和参数解析，核心处理逻辑独立一个文件，工具函数单独放。
