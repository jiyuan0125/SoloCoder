上周一个 bug 查了半天，原因是内层作用域遮蔽了外层同名变量，`err` 被重新声明了。这个工具扫描 Go 源码，找出内层和外层同名的变量声明，标出可能导致 bug 的遮蔽。

用法：`shadowcheck <目录或文件> [--ignore <变量名列表>] [--format text|json]`。

默认忽略 `err` 和 `_`（太多误报），可以通过 `--ignore err,_` 调整。检测范围包括：花括号内 `:=` 重新声明外层已有变量、for 循环变量遮蔽外层变量、if/init 语句中的遮蔽。

text 格式每行 `文件:行号  外层变量  内层变量  遮蔽类型`。遮蔽类型分 `SHADOW`（危险，内外层类型不同）和 `WARN`（可能有意，类型相同）。

json 格式 `[{"file":"...","line":15,"outer":"var x int","inner":"x := \"str\"","type":"SHADOW"}]`。

退出码：0 无遮蔽，1 有 SHADOW 级遮蔽，2 输入文件不存在。

结果写入 `.shadow-results.json` 索引，格式 `{"file":"...","shadows":[...]}`。删除已有结果后索引也要同步更新，遍历剩余结果重建索引。

标准库搞定，go build 通过就行。
代码按模块拆分，不要把所有逻辑写在一个文件里。解析、转换、输出分开组织。
