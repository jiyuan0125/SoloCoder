上周 code review 一个 PR 改了 200 行，其中 60 行是冗余的 if-else 嵌套和不必要的类型转换，reviewer 逐条指出花了半小时。我想做个静态扫描工具，自动找出 Go 代码里可以简化的模式，输出 diff 格式直接贴到评论里。

命令行用法：`simplify scan <目录或文件> [--depth N] [--format diff|json] [--output 文件路径]`。扫描 .go 文件时递归深度由 --depth 控制，默认 3。输出格式选 diff 直接贴 review，选 json 则每条建议包含 file、line、rule、suggestion 四个字段。比如 `simplify scan ./pkg --depth 5 --format json --output result.json`。

检查规则覆盖这些场景——连续 if-return 可以合并为 switch、冗余 else 分支（if 内 return 后的 else）、不必要的类型转换（string([]byte(s)) 再转回来）、if 嵌套可提前 return 减少层级、双否定布尔表达式（!!b）。每条规则有唯一标识符如 S001、S002，json 输出里 rule 字段就是标识符。

`--output` 不指定则输出到 stdout。扫描目录不存在时打印 "directory not found: <path>" 并退出码 1。空文件或无 .go 文件的目录提示 "no Go files found" 退出码 0。首次运行没有历史统计，统计信息写入当前目录下 .simplify-stats.json，记录扫描文件数、发现问题数、按规则分类计数。再次运行时对比上次结果，打印新增和已修复的数量。

编译只用 `go build`，纯标准库不依赖任何第三方包。
不要写单文件，核心逻辑、CLI 入口、辅助工具各放一个文件。
