线上加 -race 跑测试报了一堆 data race，排查下来根源全在包级变量——有的在 init() 里写，有的在 goroutine 里读，没人注意过并发安全。

工具做的事很直接：扫描所有 Go 文件，把包级 var 和 const 的声明位置、类型、读写位置全部列出来。如果某个包级变量在多个 goroutine 中被读写（通过分析 go func() 调用链），标红并输出 "DATA RACE RISK"。

命令行：`globalcheck scan <路径> --mode full|quick --output table|json`。full 模式分析完整调用链，quick 只看直接读写。table 模式终端输出四列表格：变量名、声明位置、读写位置列表、风险等级（safe/caution/danger）。json 模式输出结构化数据，每个变量一个对象。

扫描流程走四步——初始化解析 AST、扫描收集变量、分析调用链、生成报告。状态对应四个阶段：init/scanning/analyzing/reporting，进度实时打印到 stderr。分组规则变更后（通过 `globalcheck config --rules <文件>` 导入新规则），已扫描过的项目重新分配分组，分组结果写入 .globalcheck-cache.json。

路径不存在报错 "path not found: <path>" 退出码 1。没有 Go 文件时 "no Go source files" 退出码 0。发现 danger 级别变量退出码 2。

不依赖任何第三方包，编译完直接跑。
