服务死锁了——一个 goroutine 拿了锁之后 panic 没释放，另一个 goroutine 就永久卡死了。还有 defer unlock 写漏的、同一 goroutine 重复加锁的。靠人审查锁的配对太容易遗漏了，得用工具把 sync.Mutex 和 sync.RWMutex 的使用全扫一遍。

扫描 AST 找到所有 sync.Mutex 和 sync.RWMutex 的使用，逐函数检查。检查项包括：调用 Lock 后在同一个函数内是否有对应的 Unlock（包括 defer Unlock）；RWMutex 的 RLock 是否有配对的 RUnlock；是否存在 Lock 之后又在 Unlock 之前再次 Lock 的重复加锁；是否有 Unlock 但往前找不到对应的 Lock 调用。输出格式：[ERROR] file.go:42: Lock without matching Unlock，[WARN] file.go:55: Unlock without Lock。

命令：mutex-check -dir ./pkg 递归扫描目录下所有 .go 文件。加 -severity error 只输出 ERROR 级别忽略 WARN。加 -format json 输出结构化结果，每项包含 file、line、type（MISSING_UNLOCK/DUPLICATE_LOCK/UNLOCK_WITHOUT_LOCK）、message 四个字段。无问题时输出 "no mutex issues found" 退出码 0。有 ERROR 时退出码 1，只有 WARN 时退出码 0。
