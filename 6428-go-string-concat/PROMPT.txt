日志模块里循环拼字符串用的 `+`，请求量上来以后 GC 压力暴增，P99 从 50ms 涨到 500ms。得把代码里所有低效拼接找出来，标出位置给出建议。

`concat-check <目录或文件>` 扫描 Go 源码，检测两类问题：一、循环体内用 `+` 拼接字符串（`result += part`），这是最严重的性能杀手；二、多次 `+` 拼接超过 5 段（`a + b + c + d + e + f`），即使在循环外也不理想。每处问题输出：`文件:行号: 问题类型 | 代码片段`，并附建议如 `循环拼接建议改用 strings.Builder` 或 `多段拼接可考虑 fmt.Sprintf 或 strings.Join`。

汇总输出：按文件分组计数，以及所有文件的总计和占比（如 "循环拼接: 12 处, 多段拼接: 8 处, 总计: 20 处"）。`--severity high` 只输出循环内拼接（高严重度），`--severity all` 输出全部（默认）。`--fix` 参数生成修改建议的 diff 输出（不自动修改源文件），把 `result += part` 改成 Builder 模式的代码框架。`--threshold 3` 自定义多段拼接阈值，默认 5。

报告完成后的通知——`--notify` 配了就发邮件，没配就输出 `报告已生成: N 处问题 (通知已跳过: 未配置邮件)`。纯标准库，go run . 就行。
至少拆成两个包或三个文件以上，不要单文件一把梭。
