我们有个接口签名改了一个参数类型，实现方有二十几个 struct，漏改了一个上线后直接 nil panic，全组被叫起来修 hotfix。这事之后就想做个工具，把接口和实现的方法签名对一遍，任何一个不匹配都别放过去。

工具扫描 Go 源码，找出所有接口定义及其方法签名，然后检查每个声明实现该接口的类型，逐个方法对比——参数类型、返回值类型、参数数量必须完全一致。缺少的方法逐个列出来，多余的方法（接口没有但实现有的）只做提示不报错。

命令行是 `iface check <包路径或目录>`，加上 `--interface <名称>` 只检查指定接口，不加则检查所有。还有 `--verbose` 打印每个类型的检查过程。`iface report [--format json|table]` 输出检查结果。json 格式每条记录包含 interface、implementer、missing_methods、mismatched_methods 字段。table 格式终端显示四列：接口名、实现者、缺失方法、签名不匹配。

额外支持 `iface list <包路径>` 列出所有接口及其实现者，方便浏览。

路径无效时报 "package not found: <path>" 退出码 1。没有找到接口定义时 "no interfaces found" 退出码 0。发现不匹配退出码 2，打印 "MISMATCH: <类型> missing method <方法名>" 或 "MISMATCH: <类型>.<方法> signature differs"。

不用第三方包，`go build` 通过就行。
项目结构要分模块：主入口、核心处理逻辑、工具函数分文件组织，方便测试和维护。
