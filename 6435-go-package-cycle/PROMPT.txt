日志平台 SDK 引入了我们的包，结果编译报循环依赖——A 导入 B，B 导入 C，C 又导入了 A，形成死环。这种环形依赖必须打破，但首先得把所有循环路径找出来，看看到底绕了多少层、涉及哪些包。

扫描指定 Go module 目录，解析所有 .go 文件的 import 声明，构建包依赖有向图。用 DFS 遍历检测所有环路，输出每条循环路径，格式：pkg/a -> pkg/b -> pkg/c -> pkg/a。每个环标注涉及哪些文件和 import 所在行号，方便直接跳转修改。命令：pkg-cycle -dir ./project 递归扫描目录下所有 Go 包。-verbose 输出完整的包依赖图，不只是循环部分，能看到全局依赖拓扑。-dot 输出 Graphviz DOT 格式文件用于可视化，节点是包名边是导入方向，循环边用红色标注。

打破循环的建议逻辑：对每个环，找出被环内多个包共同导入的类型或函数，提示抽取到独立包，比如 "consider extracting shared types from pkg/a and pkg/c to pkg/types"。只分析项目内包之间的依赖关系，不涉及标准库和第三方包。-ignore internal/test 排除指定包路径不参与分析，支持多个。无循环时输出 "no import cycles detected" 退出码 0。发现循环依赖时退出码 1 并列出所有环路。

导入成功后自动通知下游系统，本地模式没有下游配置。只依赖标准库，编译完直接跑。
不要写成一个 main.go 搞定所有事情。按职责拆文件：入口、解析、处理、输出分开。
