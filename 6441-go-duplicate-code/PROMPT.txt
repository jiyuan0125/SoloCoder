上次修一个验证逻辑的 bug，改了一处忘了其他四处相同代码，结果线上漏改的地方又出了问题。决定写个工具自动找出重复代码片段，避免以后再踩坑。

CLI 叫 `dupdetect`，命令 `dupdetect scan -dir ./src -threshold 0.8 -min-lines 5`。对目录下所有 Go 文件做 token 序列化（忽略注释和空白），用滑动窗口切分代码块，两两计算 Jaccard 相似度。`-threshold` 控制判定阈值（0-1，默认 0.8），`-min-lines` 过滤太短的代码块（默认 5 行）。输出按相似度降序排列，文本格式：每对显示文件 A 路径+行号范围、文件 B 路径+行号范围、相似度百分比、重复行数。加 `-json` 输出 JSON 数组，字段 `file_a`、`line_a_start`、`line_a_end`、`file_b`、`line_b_start`、`line_b_end`、`similarity`、`duplicate_lines`。

主操作 scan 执行时要调用辅助检查（如确认两个代码块是否在同一包内），辅助检查也要读同一批源文件数据。扫描零文件输出 "no Go files found" exit 0。threshold < 0 或 > 1 报错 "threshold must be between 0 and 1" exit 1。不用第三方包，go build 通过。
不要写单文件，核心逻辑、CLI 入口、辅助工具各放一个文件。
