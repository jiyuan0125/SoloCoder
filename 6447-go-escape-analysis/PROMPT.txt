线上服务 GC 一跑就卡 200ms，pprof 一看堆上分配了几百万个小对象。代码里到处都是返回局部变量指针、interface 包装、slice 越界扩展——这些逃逸场景得全部找出来。

`escape-check <目录或文件路径>` 扫描 Go 源码，识别以下逃逸模式：函数返回局部变量指针（`return &localVar`）、赋值给 interface 变量（`var iface interface{} = concrete{}`）、闭包捕获外层变量、`fmt.Printf` 等可变参数调用、slice 扩容 `append` 超出 cap。每个逃逸点输出：`文件:行号: 逃逸类型 | 代码片段`。

最后输出汇总统计：按逃逸类型分组计数，以及占扫描文件总行数的比例（如 "逃逸点 45/总行数 1200 = 3.75%"）。`--suggest` 参数在每条逃逸点后面附上优化建议，比如 "考虑返回值而非指针" 或 "预分配 slice 容量"。`--top 10` 只输出最严重的 10 处按行号排序。

构建流程：源码解析 → AST 构建 → 模式匹配 → 测试（内置测试用例验证检测准确性）→ 报告生成。测试用例内置在代码里，`--self-test` 跑一遍确保检测逻辑正确。测试失败不输出报告，直接报错退出码 1。扫描非 Go 文件自动跳过，输出 `跳过 N 个非 Go 文件`。

不用第三方包，go build 通过就行。
代码组织要清晰：CLI 参数处理一个文件，核心业务逻辑一个文件，公共工具函数一个文件。
