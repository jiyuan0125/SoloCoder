测试覆盖率 80% 但线上还是出 bug——你翻开测试文件一看，一半的测试函数里压根没 assert，有些测试还互相依赖执行顺序，有些导出函数根本没有对应测试。写个工具自动找出这些测试坏味道，别让覆盖率数字骗了人。

扫描 _test.go 文件，检测三类问题。第一类：无断言测试——函数体里找不到 assert、require、Error、Fatal、t.Error、t.Fatal 等任何断言调用，说明这个测试就算逻辑全错也能通过。第二类：顺序依赖——TestMain 里修改了全局状态但没有恢复，或者测试函数通过共享文件和全局变量传递数据，导致执行顺序不同结果不同。第三类：覆盖率盲区——对比 go test -coverprofile 生成的 profile 文件，列出项目内没有被任何测试函数覆盖到的导出函数。

用法：test-smell -dir ./... -cover profile.cov。-dir 指定包路径支持 ./... 递归，-cover 可选，传入覆盖率 profile 文件路径开启盲区检测。输出每类问题汇总，格式：[SMELL] func TestXxx in file_test.go:12 - no assertions。-format json 输出结构化结果，包含 no_assert、dependencies、coverage_gaps 三个数组。无问题输出 "no test smells detected" 退出码 0。标准库搞定，go run . 跑起来。
代码要模块化：主流程、具体功能实现、辅助函数分开存放，主文件只做调度。
