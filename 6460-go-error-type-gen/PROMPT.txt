后端五个模块的错误码格式五花八门，有的用纯数字有的用字符串，前端根本没法做统一拦截。能不能定义一套规范，然后自动生成错误码映射和包装函数？

命令 `errgen -config errors.yaml -output ./errors`。配置文件格式：`modules` 数组，每个模块含 `name`（模块名）、`prefix`（错误码前缀如 "USR"）、`errors` 数组，每条有 `code`（数字如 1001）、`message`（中文描述）、`http_status`（对应 HTTP 状态码如 400）。生成两个文件：`error_codes.go` 导出常量 `Err<Prefix><Code>` 和字符串描述；`error_wrap.go` 导出 `WrapError(module, code int, detail string) error` 函数，返回包含模块名、错误码、HTTP 状态码、详情的结构化 error。

生成完自动更新 `error-index.json` 索引文件，记录所有已生成的错误码、对应模块、生成时间。索引构建时也要读取已有的 error 文件，合并新旧条目，重复 code 报 "duplicate error code: <module>:<code>" exit 1。

配置文件不存在 exit 1。yaml 格式错误打印具体字段和原因。http_status 不在有效范围（100-599）报 "invalid http_status" exit 1。零外部依赖，编译完直接跑。
代码按模块拆分，不要把所有逻辑写在一个文件里。解析、转换、输出分开组织。
