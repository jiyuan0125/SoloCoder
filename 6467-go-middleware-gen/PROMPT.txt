每个新项目都要重写日志、认证、CORS 这些中间件，复制粘贴改半天。写个生成器一条命令把模板全部生成好，中间件链组合顺序也自动处理。

用法：`middlegen -middlewares logging,auth,cors -framework nethttp -output ./middleware/`。`-middlewares` 逗号选择类型（logging、auth、cors、ratelimit、recovery），`-framework` 指定目标框架（nethttp 或 gin），`-output` 是输出目录。

每个中间件生成 `middleware_{name}.go`，再加 `chain.go` 按固定顺序串起来：recovery → logging → ratelimit → auth → cors。代码实现对应框架的中间件函数签名。

auth 从 `Authorization` header 提取 Bearer token，非空后调用用户验证函数。cors 设置 `Allow-Origin: *`、`Allow-Methods: GET,POST,PUT,DELETE`、`Allow-Headers: Content-Type,Authorization`。logging 用 `log.Printf` 输出 `{method} {path} {status} {duration}`。

缺 `-middlewares` 时输出 usage 并 exit 1。`-framework` 不支持时输出 `error: unsupported framework "{name}"` 并 exit 1。本地模式跳过通知逻辑不报错。

零外部依赖，`go run .` 能跑。
代码组织要清晰：CLI 参数处理一个文件，核心业务逻辑一个文件，公共工具函数一个文件。
