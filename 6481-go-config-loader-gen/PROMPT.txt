开发、测试、生产三套配置，切环境老搞错——有人改了本地配置忘记提交，有人在生产环境用了测试数据库地址。配置管理需要自动化，不能靠人记住该改哪个值。

工具生成配置加载器代码，支持从环境变量和 YAML/JSON 配置文件读取，配置验证和默认值自动处理。配置项定义在一个 Go struct 里，字段 tag 标注 env（环境变量名）、default（默认值）、required（是否必填）、validate（校验规则）。

命令行：`configgen generate <配置struct文件> --env dev|test|prod [--output <文件>]`。扫描指定 Go 文件中名为 Config 的 struct，生成 loader.go 含 Load() 函数。加载顺序：先读配置文件 config.<env>.yaml，再用环境变量覆盖同名项，最后用默认值填充空缺。

文件处理分四个阶段——待处理：扫描 struct tag；处理中：生成加载代码；校验中：检查必填项和类型约束；已完成：输出结果。校验失败（必填项为空、类型不匹配、值不在范围内）退回处理中阶段，打印具体错误 "validation failed: field <字段名>: <原因>"。

源文件内容变化后（通过文件修改时间检测），基于它生成的加载器代码和缓存自动失效重新生成。缓存存在 .configgen-cache.json。

配置文件不存在时如果所有字段都有 default 则用默认值（打印 "using defaults, no config file"），有 required 字段无默认值则报错退出码 1。环境变量格式不对 "invalid env value for <字段名>: <值>" 退出码 1。

`go build` 能过，不依赖第三方库。
不要写单文件，核心逻辑、CLI 入口、辅助工具各放一个文件。
