前阵子排查一个线上问题，发现 crontab 里散落着二十多个定时任务，有的重复执行有的从没跑过，根本没人知道全貌。需要一个工具把任务管理起来——解析 Cron 表达式、注册任务、按时触发执行，让调度逻辑有迹可循。

CLI 命令 `schedgen init` 生成配置文件 `scheduler.yaml`，结构：`tasks` 数组，每条含 `name`、`cron`（标准五段式表达式）、`command`（要执行的命令行）、`timeout`（如 "30m"，超时杀进程）。`schedgen validate scheduler.yaml` 校验所有 Cron 表达式是否合法，command 对应的程序是否存在。`schedgen run -config scheduler.yaml` 启动调度器，按 Cron 时间触发任务，每次执行记录到 `sched-log.json`，每条含 `task_name`、`start_time`、`end_time`、`exit_code`、`output`（最后 10 行）。

任务执行超时发 SIGTERM，5 秒后还没退出发 SIGKILL。Cron 表达式非法报 "invalid cron expression: <expr> in task <name>" exit 1。配置文件不存在 exit 1。同一个 name 出现两次报 "duplicate task name: <name>" exit 1。

代码分几个文件组织：config.go（配置解析）、scheduler.go（调度核心）、task.go（任务执行）、main.go，别全写 main.go 里。go build 能过，不依赖第三方库。
代码组织要清晰：CLI 参数处理一个文件，核心业务逻辑一个文件，公共工具函数一个文件。
