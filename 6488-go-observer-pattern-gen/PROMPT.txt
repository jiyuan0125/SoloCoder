先说现状：状态变更后要通知五六个模块——邮件、短信、日志、审计、缓存刷新、搜索引擎更新。每个模块都直接调用其他模块的方法，改一个牵一发动全身。需要生成观察者模式的模板代码——主题接口、观察者接口、事件分发机制，让各模块解耦。

命令：observer-gen -subject Order -events Created,Updated,Deleted -observers EmailNotifier,SMSNotifier,Logger -output observer.go。生成 Subject 接口（Register、Unregister、Notify）、Observer 接口（OnEvent）、具体 Subject 实现类（观察者切片 + sync.Mutex 保护线程安全）。每个事件一个 struct（如 OrderCreatedEvent），含 Type、Timestamp、Payload。

单个观察者 panic 时 recover 捕获后记录错误继续通知下一个，不因一个崩溃影响其他人。生成的代码包含完整 import 和 package 声明，-package observers 指定包名（默认 main）。参数不完整输出 usage 退出码 1。

审批流程：提交→初审→复审→通过，初审不过可以修改重提。

纯标准库，go run . 就行。
