谁没被 coverage profile 折腾过？十几个 CI 节点各跑一部分包，profile 文件散得到处都是，手动 cat 再去重——行重复了结果就偏了。能不能一个命令把所有 profile 合了，顺便告诉我哪些包覆盖率不到 80%？

`covmerge merge --files a.out,b.out,c.out --output merged.out`，读取多个 Go coverage profile 文件，相同文件+相同行范围的去重只保留一条，输出合并后的 profile。`--filter "github.com/myproject/pkg/..."` 按包路径前缀过滤，只保留匹配的包，支持 `...` 通配。`--threshold 80` 设覆盖率阈值，合并完输出汇总表：每一行是 PACKAGE | COVERAGE% | STATUS（达标显示 OK，不达标显示 BELOW），末尾输出 TOTAL 行。任何输入文件格式非法时输出 "invalid profile format in <filename>: line <N>" 并 exit 1。文件不存在输出 "file not found: <path>" exit 2。`--json` 改为 JSON 格式输出，结构为 `{"packages":[{"name":"...","coverage":85.3,"status":"OK"}],"total":82.1}`。`covmerge report --file merged.out` 单独查看某个 profile 的汇总，不合并只统计。空 profile（0 行有效覆盖数据）输出 "empty profile: no coverage data" exit 3。纯 Go 标准库，`go build` 出来不依赖 go tool。
代码分文件组织，解析器、处理器、输出器分开，main.go 只做参数解析和流程串联。
