每次新加一个 gRPC 接口，mock 服务就得手写一遍，protobuf 定义文件明明就在那里。写个工具读 proto 文件，自动生成 mock 服务代码——根据请求字段值返回预设响应，还能模拟延迟和错误率，CI 里直接用。

主命令 `grpcmockgen`——`grpcmockgen generate --proto api.proto --output mock_server.go --package mock`。解析 .proto 文件中的 `service` 和 `rpc` 定义（只需要 service/rpc/method/message 这几级结构，不需要完整 protobuf 解析器）。生成的 Go 代码实现一个 HTTP 服务器（因为纯标准库不支持 gRPC 框架，所以生成 REST-style 的 mock），每个 rpc 对应一个 HTTP handler。响应规则通过 `--rules rules.json` 指定，格式：`{"UserService/GetUser":{"match":{"id":"123"},"response":{"name":"test user"},"delay":"100ms","error_rate":0.1}}`——匹配请求字段值返回对应响应，`delay` 模拟延迟，`error_rate` 按概率返回 HTTP 500。不匹配时返回默认零值 JSON 和 200。`--port 50051` 指定 mock 服务监听端口。proto 文件不存在输出 "proto file not found: <path>" exit 1。proto 解析失败输出 "parse error at line <N>: <detail>" exit 2。生成的 .go 文件必须能 `go build` 通过。Go 实现，只用标准库，交叉编译友好。
不要写单文件，核心逻辑、CLI 入口、辅助工具各放一个文件。
