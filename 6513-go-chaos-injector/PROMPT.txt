你注意到没有？线上故障 80% 都是测试里根本没模拟过的错误路径——超时没人测、连接失败没人测、数据被篡改更没人测。能不能在 CI 里自动给 error 返回路径注入故障，按概率随机触发，不改源码，输出 patch 文件让开发者自己决定用不用。

`chaosinject scan --dir ./pkg --output chaos.patch`，扫描目录下所有 .go 文件，找到返回 error 的语句（`if err != nil { return ..., err }` 和 `return &SomeError{...}` 这两种模式），按 `--probability 0.2`（默认 20%）概率选择注入点。注入类型通过 `--faults timeout,connfail,corrupt` 指定：timeout 注入 `time.Sleep(30 * time.Second)` 再返回 error；connfail 注入 `return errors.New("connection refused")` 替换原 error；corrupt 在返回前把 response body 的随机字节置零。输出 unified diff 格式的 patch 文件到 `--output`。`--dry-run` 只输出将被注入的函数名和文件位置，不生成 patch。指定目录下没有 .go 文件输出 "no Go source files found in <dir>" exit 1。patch 文件写失败 exit 2。`--max-injections 50` 限制最大注入点数防止过度注入。patch 内容只包含修改部分，不改原文件，开发者 `git apply chaos.patch` 手动应用。纯 Go 标准库，编译后单二进制直接跑。
