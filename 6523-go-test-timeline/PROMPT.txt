上次 CI 跑了 47 分钟，想知道时间花在哪了，`go test -json` 的输出倒了半小时没看出个所以然——几百行 JSON 堆在终端上，哪个包的哪个测试跑了多久完全不清楚。把 `go test -json` 的输出按包和函数分组，整理出开始时间、结束时间、耗时、状态的结构化时间线，最慢的测试排前面，JSON 格式输出给下游可视化工具用。

`testtimeline parse --input test2json.out --output timeline.json`。输入是 `go test -json ./...` 的原始输出，每行一个 JSON。`Action:start` 记录开始时间，`Action:pass/fail/skip` 记录结束和状态，`Action:output` 收集日志。输出结构：`{"packages":[{"name":"github.com/my/pkg","tests":[{"name":"TestFoo","start":"...","end":"...","duration":"2s","status":"pass","output":["line1"]}],"total_duration":"15s"}]}`。`testtimeline summary --input timeline.json` 输出 PACKAGE | TESTS | PASSED | FAILED | DURATION 表格，按 duration 降序。`testtimeline slow --input timeline.json --top 10` 列出最慢的 10 个测试。空输入输出 "no test events found" exit 1。非法 JSON 跳过该行输出 "[WARN] invalid event at line <N>"。代码拆成至少 3 个 Go 源文件：main.go、parser.go、timeline.go。

Go 标准库，`go build` 能编译通过。
