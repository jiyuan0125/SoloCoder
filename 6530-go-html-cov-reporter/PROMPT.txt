终端里看覆盖率数字不直观，哪些行覆盖了哪些没覆盖，纯数字看不出个所以然。上个 sprint 差点带着 60% 覆盖率上线。

把 Go coverage profile 转成 HTML 报告。`report -profile coverage.out -source ./src -out report.html` 读取 `go test -coverprofile` 生成的 profile 文件，解析每个文件的覆盖率数据，生成一个独立 HTML 文件。

HTML 结构：顶部汇总区域显示总覆盖率百分比、文件数量、总行数、覆盖行数，用绿色进度条可视化。下方是每个源码文件的可折叠区块——覆盖的行绿色背景 `#e6ffec`，未覆盖红色背景 `#ffebe6`，文件路径旁标注该文件覆盖率百分比。行号在左侧显示。

`merge -profiles cov1.out,cov2.out -out merged.out` 合并多个 profile 文件，同一文件同一行的覆盖状态取并集（任一 profile 覆盖即为覆盖）。合并后输出 `merged {count} profiles: {files} files, {total_lines} total lines, {pct}% coverage`。

profile 文件不存在时输出 `error: file not found: {path}` 退出码 1。profile 格式非法时输出解析错误到 stderr 退出码 2。`-source` 目录不存在时退出码 1。HTML 中不内嵌外部资源，纯内联 CSS，浏览器直接打开即可。

用 Go 标准库写，go run . 或 go build 都行。
代码按模块拆分，不要把所有逻辑写在一个文件里。解析、转换、输出分开组织。
