50 个 commit 的范围内出了 regression，`git bisect` 手动跑要试六七轮，每轮 checkout、编译、跑测试、标记 good/bad——光编译就要两分钟，整个过程得盯在电脑前一个多小时。交给工具自动完成，二分查找缩小范围，直接告诉你哪个 commit 引入了问题、谁写的、commit message 是什么。

`hunt -good v1.0.0 -bad HEAD -test "go test ./..." -dir ./project` 二分查找。算法：`git rev-list --ancestry-path` 获取列表，取中点 checkout 运行 test，退出码 0 标 good 否则 bad，缩小到剩一个 commit。

过程输出到 stderr：`[1/6] testing abc1234... FAIL`。结果到 stdout：`INTRODUCED_BY: abc1234 | Author: Zhang San | Date: 2024-01-15 | Message: refactor config`。

`-max-steps 20` 防无限循环。`-build "go build ./..."` 编译失败标记 skip。`-timeout 5m` 超时标 bad。无提交输出 `error: no commits between {good} and {bad}` 退出码 1。全 bad 输出 `all commits fail, cannot bisect` 退出码 2。

至少 3 个 Go 源文件：main.go、bisect.go、types.go。Go 标准库，flag 包解析。
不要写成一个 main.go 搞定所有事情。按职责拆文件：入口、解析、处理、输出分开。
