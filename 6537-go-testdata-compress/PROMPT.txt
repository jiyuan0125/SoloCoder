测试数据目录膨胀到 2GB 了——其中大部分是 JSON fixture 和二进制采样文件。每次 git clone 都要拉这些，新人入职第一件事就是等 15 分钟拉仓库。CI 也一样，每个 job 都要重新下载。按子目录分组打包成 tar.gz，支持增量打包只压缩变化的文件，解压时校验 SHA-256 确保没损坏。

`pack -dir ./testdata -group-by project -out ./testdata.tar.gz` 按顶层子目录分组，每个生成一个 tar.gz。`-incremental -checkpoint .checkpoint` 只打包 SHA-256 变化的文件，首次全量。输出 `packed: {new} new, {modified} modified, {unchanged} unchanged`。

`unpack -archive ./testdata.tar.gz -dir ./testdata -verify` 解压并校验。比对 manifest.json（嵌入 tar.gz 内）中 SHA-256，不匹配输出 `CHECKSUM MISMATCH: {file} expected {hash} got {hash}` 退出码 2。

`manifest -dir ./testdata` 生成 manifest.json：`{"files":[{"path":"","size":0,"sha256":"","modified":""}]}`。流式计算哈希不全部加载到内存。大文件输出 `packing large file: {name} ({size}MB)...`。

Go 标准库实现。go build 编译通过。退出码 0 成功、1 参数错误、2 校验失败。
代码组织要清晰：CLI 参数处理一个文件，核心业务逻辑一个文件，公共工具函数一个文件。
