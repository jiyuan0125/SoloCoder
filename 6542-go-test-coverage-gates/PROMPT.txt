覆盖率从 85% 悄悄降到 72%，整整两个 sprint 没人注意到，直到线上出了两个本该被测试拦住的低级 bug。事后查 git history 才发现是某次重构删了一批测试用例。配一个阈值门禁，每次跑完覆盖率自动检查——全局不低于 80%，核心包不低于 90%，未达标的阻止合并。

`init -out gates.json` 生成配置模板：`{"global_threshold":80.0,"packages":{"pkg/handler":90.0},"allowlist":["pkg/generated"]}`。

`check -profile coverage.out -config gates.json` 逐包检查。输出：`pkg/handler: 92.3% ✓ (threshold: 90%)` 或 `pkg/models: 68.1% ✗ (threshold: 80%, gap: -11.9%)`。汇总：`RESULT: 14/16 packages passed | Overall: 78.5% (threshold: 80%) | STATUS: FAIL`。全局阈值按行数加权平均。allowlist 跳过输出 `SKIPPED (allowlist)`。

`-diff baseline.json` 对比上次：`pkg/handler: 92.3% → 88.1% ↓4.2%`。`-json` 输出结构化报告。退出码：0 达标、1 参数错误、2 不达标。profile 为空输出 `error: empty coverage profile` 退出码 1。
