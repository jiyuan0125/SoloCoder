那个支付模块有 12 个 struct，手写 property-based test 的随机值生成器和 round-trip 检查，每个 struct 都要编一套，写到第四个就不想写了。从 Go struct 定义文件里直接提取字段类型，自动生成随机值构造器、序列化 round-trip、零值安全检查这些 property test，省下大量重复劳动。

`generate -file models.go -out property_test.go` 解析 struct 定义自动生成。每个导出 struct 生成：
- `random{StructName}(rng *rand.Rand)` 随机值生成器——int 用 `rng.Intn()`，string 随机字母，bool 随机，float64 `rng.Float64()`，slice 随机长度
- `Test{StructName}_SerializationRoundTrip` JSON marshal→unmarshal→DeepEqual
- `Test{StructName}_ZeroValueSafety` 零值不 panic
- `Test{StructName}_DeterministicHash` 相同内容相同哈希

`-count 100` 随机迭代次数，默认 100。`-strategy simple|exhaustive` exhaustive 包含边界值（int 最大最小、空字符串、nil slice）。生成文件要 `go test` 直接运行。无 struct 输出 `no struct definitions found` 退出码 0。文件不存在 `error: file not found` 退出码 1。

Go 标准库实现。go build 能编译通过。
代码分文件组织，解析器、处理器、输出器分开，main.go 只做参数解析和流程串联。
