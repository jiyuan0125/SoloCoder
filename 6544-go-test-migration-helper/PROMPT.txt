接手了一个三年老项目，150 个测试文件全用裸 `testing.T` 写的——setup/teardown 逻辑每个文件各写一遍，公共 fixture 全局变量满天飞，想加个 beforeAll 都不知道该改哪里。迁移到 testify/suite 统一结构，解析 AST 自动识别 TestMain 中的初始化逻辑、共享变量、子测试，转成 suite 模式。

`migrate -dir ./project -out ./migrated` 扫描 `_test.go` 解析 AST 识别模式：`TestMain` 中 setup/teardown → `SetupSuite`/`TearDownSuite`；公共初始化 → `SetupTest`/`TearDownTest`；共享 var → suite struct 字段；`t.Run("subtest",...)` → 独立 Test 方法。输出 suite 文件：`type {Name}Suite struct { suite.Suite }`，原函数转方法，保留注释。

`-dry-run` 输出摘要：`{file}: 3 tests migrated, 2 setup blocks extracted, 1 shared var promoted`。`-diff` 输出 unified diff。`-keep-original` 保留原文件新文件加 `.suite.go` 后缀。无可迁移模式跳过。无 `_test.go` 输出 `no test files found` 退出码 0。迁移后代码要 `go vet` 通过，不通过输出 `warning: vet issues in {file}`。

Go 标准库实现。go build 能编译通过。
拆成至少三个 Go 文件：main.go 做入口和参数解析，核心处理逻辑独立一个文件，工具函数单独放。
