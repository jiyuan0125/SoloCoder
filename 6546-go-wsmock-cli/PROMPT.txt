前端联调 WebSocket 接口的时候，后端还没开发完，前端只能对着协议文档猜消息格式。上次联调会上双方各执一词吵了半小时——最后发现是文档没写清楚推送消息的时序。搞个 WebSocket mock 服务，用 JSON 配置文件定义收到什么消息就回什么消息，前端不用等后端，自己先把交互逻辑调通。

`serve -config mock.json -port 8080` 启动 mock 服务。配置：`{"responses":[{"match":{"type":"subscribe","pattern":"order.*"},"reply":{"type":"snapshot","data":"..."},"delay_ms":200}],"default_reply":{"type":"error","data":"unknown"}}`。收到消息解析 JSON，按 `match.type`（支持 glob）匹配，延迟 `delay_ms` 后发送 reply。`match` 为空则连接后立即发送。

`-record -out recording.jsonl` 记录收发消息，每行 `{"direction":"in|out","timestamp":"","message":""}`。`-max-clients 10` 超出关最旧连接。

配置格式错误输出 `error: invalid config at line {n}: {msg}` 退出码 1。端口占用输出 `error: port {n} already in use` 退出码 2。

Go 实现，只用标准库，交叉编译友好。
项目要用多文件结构，入口文件、业务逻辑、数据模型分开放，别揉在一个文件里。
