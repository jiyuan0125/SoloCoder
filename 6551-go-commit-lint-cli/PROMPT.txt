上次发版 commit message 写成了 "update stuff"，线上回滚的时候翻半天 git log 找不到对应改动。团队约定了 Conventional Commits 规范，但每次都有人忘，CI 也没拦住。得有个工具在提交那一刻就检查格式，不合规矩直接打回去。

用法分两种：从 stdin 管道读 `echo "fix: resolve null pointer" | commit-lint`，或者从文件读 `commit-lint -file msg.txt`。检查规则默认开启 Conventional Commits 格式（正则 `^(feat|fix|docs|style|refactor|perf|test|build|ci|chore|revert)(\(.+\))?: .{1,100}`），subject 行不超过 100 字符，body 每行不超过 200 字符，空行分隔 subject 和 body。支持自定义规则文件 `-rules custom.json`，里面可以覆盖正则、行长度上限、允许的 type 列表。

输出格式：通过时 stdout 输出 `OK` 退出码 0；不通过时逐行列出违规项，每项格式 `LINE {n}: {rule} — {具体原因}`（如 `LINE 1: format — must match type(scope): subject`），退出码 1。空输入（空文件或空 stdin）输出 `error: empty commit message` 退出码 2。输入有但只有空白字符同理。

用 Go 标准库写，`go run .` 或 `go build` 都行，退出码 0 通过 1 违规 2 输入错误。
