LFS 缓存悄悄吃了 50GB 磁盘空间，清理的时候完全不知道哪些对象还在用、哪些可以删。`.git/lfs/objects` 下面按哈希前两位分目录存了成千上万个文件，手动看根本看不过来。

两件事要做：一是搞清楚 LFS 的现状（跟踪了什么、占了多少空间），二是安全清理旧对象。

`lfs-helper status` 读取 `.gitattributes` 中 `filter=lfs` 的规则，列出所有 LFS 跟踪模式（如 `*.psd` `*.zip`）。扫描 `.git/lfs/objects` 目录统计本地缓存大小和文件数量。`lfs-helper list` 列出仓库中所有 LFS 文件，表格输出：文件路径、实际大小、OID、是否在本地缓存中。`lfs-helper clean -older-than 90d` 删除超过 90 天未访问的本地 LFS 缓存对象（通过文件 atime 判断）。`lfs-helper clean -larger-than 100MB` 只清理超过指定大小的对象。`-dry-run` 显示将要删除的对象和释放空间但不实际删除。

清理时先验证对象在远程存在（`git lfs ls-files` 检查），不存在的对象不删并在 stderr 输出 `warning: {oid} not on remote, skipping`。没有 LFS 对象时输出 `No LFS objects found`。不在 git 仓库或未启用 LFS 时报错退出码 1。

Go 标准库实现，`go build` 编译通过。
