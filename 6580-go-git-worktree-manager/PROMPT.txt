难道没人觉得 git worktree 的命令太难记了吗？每次 add 都要翻 man page，list 输出一坨没人想看的东西。

三个子命令，用 os.Args[1] 区分：
- `wt add <branch-name>` → 在项目同级目录创建 `repo-<branch-name>` 目录，自动执行 `git worktree add ../repo-<branch-name> <branch-name>`。分支不存在时先从 HEAD 创建。输出 "created worktree at %s"
- `wt list` → 列出所有 worktree，表格格式输出：`PATH | BRANCH | IS_DIRTY`，dirty 判断通过 `git status --porcelain` 是否有输出
- `wt remove <branch-name>` → 删除对应 worktree 并打印 "removed worktree: %s"。有未提交修改时提示 "worktree has uncommitted changes, use -force to override"，不加 `-force` 退出码 1

全局标志：`-json` 将 list 输出切换为 JSON 数组 `[{"path": "...", "branch": "...", "dirty": true/false}]`。

不是 git 仓库时退出码 1 打印 "fatal: not a git repository"。worktree 目录不存在时退出码 1 打印 "worktree not found: %s"。成功退出码 0。

Go 纯标准库，交叉编译友好。`go build -o wt .`。
代码按模块拆分，不要把所有逻辑写在一个文件里。解析、转换、输出分开组织。
