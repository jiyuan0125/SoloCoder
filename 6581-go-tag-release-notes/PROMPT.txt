release notes 每次手动整理太浪费时间——对比前一个 tag 差异，按 feat/fix/breaking 归类。

命令行：`tag-release-notes -tag v2.1.0` 自动找上一个 tag 对比。`-prev v2.0.0` 手动指定。`-output release.md` 指定输出文件默认 stdout。`-format markdown`（默认）或 `-format json`。

从 `git log v2.0.0..v2.1.0` 解析 commit message 按前缀分类：`feat:` → Features 段，`fix:` → Bug Fixes 段，`break:` 或 `BREAKING CHANGE:` → Breaking Changes 段，无前缀归 Other 段。

Markdown 输出：`## v2.1.0 (2024-06-01)` 下按段列 bullet。json 输出：`{"tag":"v2.1.0","date":"2024-06-01","features":[...],"fixes":[...],"breaking":[...],"other":[...]}`。

tag 不存在退出码 1 打印 "tag not found: %s"。无上一个 tag 时以第一个 commit 为起点。纯 Go 标准库，`go build -o tag-release-notes .`。
不要写单文件，核心逻辑、CLI 入口、辅助工具各放一个文件。
