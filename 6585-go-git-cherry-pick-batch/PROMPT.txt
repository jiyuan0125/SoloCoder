cherry-pick 到第三个 commit 冲突了，后面两个也被堵住，整个过程白费。批量操作得能处理这种级联失败。

命令行：`cherry-pick-batch -commits abc123,def456,ghi789 -branch feature/target` 将指定 commit 应用到目标分支。`-from feature/source` 配合 `-count 5` 自动取最近 N 个 commit 而不需要手动列 hash。`-continue` 在冲突解决后继续剩余的 pick。

处理逻辑逐个执行：
- 每个 commit 先 `git cherry-pick <hash>`
- 已在目标分支的 commit（patch-id 相同）跳过，打印 "SKIP: %s already applied"
- 冲突时：简单冲突（单侧修改）自动解决，打印 "AUTO-RESOLVED: %s"；复杂冲突暂停，打印 "CONFLICT: %s, resolve and run with -continue"，同时写入 `.cherry-pick-batch.state` 文件保存剩余 commit 列表
- `-continue` 读取状态文件，从上次中断处继续

全部完成输出 "cherry-picked: %d, skipped: %d, conflicts: %d"。退出码：0 = 全部完成，1 = 有冲突需手动处理，2 = 参数错误。

state 文件格式（JSON）：`{"pending": ["hash1", "hash2"], "branch": "feature/target"}`。

纯 Go 标准库，编译后单二进制。`go build -o cherry-pick-batch .`。
不要写成一个 main.go 搞定所有事情。按职责拆文件：入口、解析、处理、输出分开。
