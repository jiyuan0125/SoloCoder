六个子项目各写各的 release notes，合并成主项目公告时手动复制粘贴漏了两个重大修复——一个是安全补丁，客户都看到了。自动收集、按规则组织，这种重复活不该让人做。

1. 命令 `rncombiner merge -dir ./releases -output RELEASE.md`。扫描目录下所有子项目的 release note 文件（格式 `<project-name>-v<version>.md`），每个文件按 Markdown 标题分节。合并策略：按子项目分组，每组内按版本号降序排列，组间按 `-sort` 参数指定顺序（`alpha` 字母序、`time` 按文件修改时间）。输出一份合并后的 Markdown，顶部是总览：`## v2.0.0 Release Notes`，然后按子项目列出变更。

2. 合并时去重：同一个变更描述出现在多个子项目文件中只保留一条，记录 `duplicates-removed.json` 供人工复核。加 `-format json` 输出 JSON 版本：`{"version": "2.0.0", "sections": [{"project": "auth", "version": "1.3.0", "changes": ["..."]}]}`。

3. 自定义排序规则通过 `sort-rules.yaml` 配置：`order` 数组指定子项目排列顺序，未列出的排后面。目录为空输出 "no release files found" exit 0。文件名不符合命名规范跳过并打印 warning。用 Go 标准库写，`go run .` 或 `go build` 都行。
