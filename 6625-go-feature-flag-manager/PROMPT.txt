功能开关散落在六七个配置文件里，上周有人关了生产环境的开关但忘了开 staging 的，测试说功能没了折腾了一下午。需要一个统一的命令行工具管理所有环境的功能开关。

子命令设计：`flagctl create --name dark-mode --envs dev,staging,prod --default false` 创建开关，`flagctl enable --name dark-mode --env staging` 启用指定环境，`flagctl disable --name dark-mode --env prod` 禁用，`flagctl list [--env staging]` 列出所有或指定环境的开关状态，`flagctl delete --name dark-mode` 删除。配置持久化到一个 JSON 文件，路径通过 `--config flags.json` 指定，默认 `./feature-flags.json`。JSON 结构：`{"flags":[{"name":"dark-mode","environments":{"dev":true,"staging":true,"prod":false},"created_at":"2024-01-01T00:00:00Z","updated_at":"2024-01-02T00:00:00Z"}]}`。`create` 时开关名重复返回错误 `flag already exists: <name>` 退出码 2。`enable/disable` 时开关不存在报错退出码 3。`list` 输出表格：名称、环境列、创建时间。`delete` 需要二次确认，`--force` 跳过确认。项目拆成至少 3 个 Go 源文件：主入口、核心逻辑、数据模型分开。纯 Go 标准库，编译后单二进制可以直接跑。
