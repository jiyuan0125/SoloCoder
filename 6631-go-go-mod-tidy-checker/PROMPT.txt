上周 CI 又因为 go.mod 没 tidy 编译失败了，排查发现是有人加了 import 但忘了跑 `go mod tidy`。写个工具专门检测这种情况，集成到 CI 的 pre-commit 阶段。

工具的流程是：拷贝原始 go.mod 和 go.sum 作为基准，然后执行 `go mod tidy`（通过 `os/exec` 调用），对比 tidy 前后两个文件的 diff。命令行 `tidycheck --path ./myproject --report plain`，`--report` 可选 `plain`（文本）或 `json`。plain 模式输出：如果有差异，逐行列出 `UNUSED: github.com/x/y@v1.0.0` 和 `MISSING: github.com/z/w@v2.0.0`，最后输出 `go.mod is NOT tidy. N unused, M missing.`。无差异则输出 `go.mod is tidy.`。JSON 模式输出 `{"tidy":false,"unused":["github.com/x/y@v1.0.0"],"missing":["github.com/z/w@v2.0.0"]}`。go.mod 已经 tidy 时退出码 0，需要 tidy 时退出码 1。指定路径下没有 go.mod 文件输出 `no go.mod found` 退出码 2。`go mod tidy` 本身执行失败（比如网络问题）退出码 3 并输出原始错误。项目拆成至少 3 个 Go 源文件：主入口、核心逻辑、数据模型分开。纯 Go 标准库，`go run .` 或 `go build` 都行。
