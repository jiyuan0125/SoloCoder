几十个容器的重启策略乱七八糟，有的该用 always 的用了 no，该用 on-failure 的用了 always，出过一次容器挂了没人拉起来的事故。逐个 `docker update` 太折磨，得批量搞定。

子命令：`rpolicy list [--filter "web-*"]` 列出容器当前重启策略，输出表格 `容器名 | 当前策略`，filter 支持 glob 匹配。`rpolicy set --policy always --filter "web-*"` 批量设置，`--policy` 只接受 `no`、`always`、`on-failure`、`unless-stopped` 四个值，其他值报错 `invalid policy: <value>` 退出码 2。`rpolicy set --policy on-failure --filter "job-*" --max-retry 5` 为 on-failure 策略设置最大重试次数。set 执行时逐个调用 `docker update --restart=<policy>` 命令，成功输出 `[OK] container_name`，失败输出 `[FAIL] container_name: <error>`。`--dry-run` 模式只显示将要执行的 docker update 命令不实际执行。`--format json` 切换 list 输出为 `[{"name":"web-1","policy":"always","max_retry":0}]`。Docker daemon 不可达时输出 `cannot connect to docker daemon` 退出码 1。项目拆成至少 3 个 Go 源文件：主入口、核心逻辑、数据模型分开。Go 标准库，命令行参数用 flag 包解析。
