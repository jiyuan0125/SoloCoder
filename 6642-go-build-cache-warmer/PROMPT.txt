CI 冷启动编译太慢了，每次都要重新拉依赖。特别是换了 runner 或者缓存过期之后，首轮构建动辄五六分钟。写个工具预热 Go 编译缓存，拉取依赖并预编译常用包。

1. 命令 `cache-warmer warm --config warmer.json`，读取项目根目录下的配置文件。配置文件格式是 JSON，包含 `packages` 数组（如 ["net/http", "encoding/json", "github.com/gin-gonic/gin"]）和 `timeout_seconds` 整数字段。配置缺失时使用默认超时 300 秒。

2. 对每个包执行 `go mod download` 和 `go build -v`，逐个处理。单个包失败不影响其他包，失败的包名和错误信息记录到 stderr，格式是 "FAIL: {package}: {error}"。全部处理完输出摘要到 stdout：成功数、失败数、总耗时，格式是 "warmed: {ok}/{total}, failed: {fail}, elapsed: {duration}"。

3. 加一个 `cache-warmer check` 子命令，检测当前 GOPATH 缓存命中率，输出已缓存的包数量和缺失的包列表。

4. 超时用 context.WithTimeout，超时后取消当前包的编译。退出码 0 表示全部成功，2 表示有部分失败，1 表示配置错误。

Go 标准库写，go run . 或 go build 都行。
项目结构要分模块：主入口、核心处理逻辑、工具函数分文件组织，方便测试和维护。
