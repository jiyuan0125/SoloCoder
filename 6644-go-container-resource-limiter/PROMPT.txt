一个未限容的容器吃满 32G 内存把整台节点拖垮，影响上面跑的 12 个服务。SaaS 限制工具按容器收费太贵，Go 自己写一个批量管理资源限制的工具。

`reslimit set --container my-api --cpu 2 --memory 4g` 设置单个容器限制。`reslimit batch config.yaml` 从配置文件批量设置，格式 `{containers: [{name, cpu, memory}]}`。`reslimit list --filter "web-*"` 按容器名前缀过滤，输出表格 `CONTAINER | CPU | MEMORY | STATUS`。`reslimit check --alert 90%` 检查资源使用率，超过阈值输出 `alert: my-api CPU usage 95% exceeds threshold 90%`。

配置文件可能很大——一个节点上几百个容器的情况，解析时用流式读取不全量加载。`--dry-run` 预览变更不实际执行。`reslimit export -o current.yaml` 导出当前所有容器的限制为配置文件。

容器不存在 `error: container not found: <name>` exit 1。限制值非法 `error: invalid memory limit: <value>, expected format: <number><k|m|g>` exit 2。Go 标准库实现，不依赖第三方包，`go build` 能编译通过。
