API 文档总是过时的，代码改了文档没跟着更新，新同事入职对着文档调试半天发现接口早就变了。同事希望能有个工具直接从 Go 源码里提取路由和 handler 信息自动生成文档。

工具扫描 Go 源码目录，提取路由注册和 handler 函数签名，输出文档。命令行 `docgen scan --path ./src --format markdown --output api-docs.md`。扫描逻辑：匹配 `http.HandleFunc("/path", handler)`、`r.GET("/path", handler)`、`mux.HandleFunc("/path", handler)` 三种常见路由注册模式。提取信息包含：HTTP 方法（GET/POST/PUT/DELETE）、路径、handler 函数名、源码位置（文件名:行号）。如果 handler 函数上方有 `//` 注释，将注释作为接口描述。输出 Markdown 格式：按路径排序，每个接口一段 `### GET /api/users` 加描述加 `Handler: userHandler` 加 `Source: handlers.go:42`。`--format openapi` 模式输出 OpenAPI 3.0 YAML 格式，每个路由生成对应的 path 和 operation。扫描到零个路由时输出 `no routes found` 到 stderr，退出码 0 仍生成空文档。目录不存在退出码 1。项目拆成至少 3 个 Go 源文件：主入口、核心逻辑、数据模型分开。纯 Go 标准库，`go run .` 或 `go build` 都行。
