OpenAPI spec 提交了引用失效的 schema，到运行时才报错，这种事出过三次了。提交前得有个卡口工具挡一下。

直接说怎么用：`openapi-validator check --file api.yaml`，读取 OpenAPI 3.0 的 YAML 文件，逐项检查后输出问题清单。检查项包括——引用完整性（所有 `$ref` 指向的定义都存在，不存在就报 "unresolved ref: {path}"）、路径参数一致性（paths 里声明了 path parameter 但 parameters 里没定义，或者反过来）、schema 完整性（required 里列的字段在 properties 里必须有定义）、response 定义完整性（每个 path+method 至少有一个 response）。

`--format` 参数控制输出格式，可选 json 或 text。text 模式输出行格式：`{severity} {rule_id} {location}: {message}`，severity 是 error/warning，rule_id 比如 REF001（引用缺失）、PARAM001（参数未定义）、SCHEMA001（schema 不完整）、RESP001（缺少 response 定义）。json 模式输出结构化数组：`[{ "severity": "error", "rule": "REF001", "location": "paths./users.get.responses.200.schema.$ref", "message": "...", "suggestion": "..." }]`。

检查通过（零 error）退出码 0，有 error 退出码 1，只有 warning 退出码 0 但 stderr 打 "passed with N warnings"。spec 文件不存在或 YAML 解析失败退出码 2，stderr 打 "fatal: {具体原因}"。

多个 worker 并发处理输入数据——`--dir` 模式可以批量扫描目录下所有 YAML/JSON 文件，用 `--workers` 控制并发数（默认 4），每个文件一个 goroutine。Go 实现，只用标准库，交叉编译友好。
