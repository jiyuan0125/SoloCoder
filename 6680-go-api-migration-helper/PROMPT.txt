上次 API 从 v2 迁 v3，几十个字段映射关系全记在脑子里，迁移完漏了三个字段，排查了一整天。这回得把映射关系记下来，工具自动生成转换代码。

第一步 apimig define --old v2-schema.json --new v3-schema.json，两个 schema 文件格式：{"name": "User", "fields": [{"name": "user_name", "type": "string", "required": true}, ...]}。工具对比两个 schema，自动匹配同名字段，输出 mapping.json：{"mapped": [{"old": "user_name", "new": "user_name", "action": "direct"}, ...], "removed": [...], "added": [...], "type_changed": [...]}。

第二步 apimig generate --mapping mapping.json --lang go 输出转换函数：func ConvertV2ToV3(input V2User) V3User。直接映射的字段赋值拷贝，removed 的字段忽略，added 的字段用零值，type_changed 的加 TODO 注释。

第三步 apimig check --old v2-schema.json --new v3-schema.json --mapping mapping.json 验证映射完整性——如果 new schema 里有字段没被映射覆盖，打印 WARNING: unmapped field 'email' in new schema。

--output 指定输出文件，默认 stdout。Go 实现，只用标准库，交叉编译友好。
代码按模块拆分，不要把所有逻辑写在一个文件里。解析、转换、输出分开组织。
