protobuf 二进制和 JSON 互转这事，SaaS 到量了收费太贵。自己写一个，而且要能直接读 .proto 文件解析消息定义，不是硬编码 schema。

`proto-json convert --proto message.proto --type User --input user.bin --direction proto2json` 读取二进制 protobuf 文件，根据 .proto 文件中定义的 User 消息类型，解析并转换为 JSON 输出到 stdout。反过来 `--direction json2proto` 把 JSON 转成二进制 protobuf 写入 `--output` 指定文件。

.proto 文件解析要支持：message 定义（嵌套 message 也要能递归解析）、enum 类型（输出为字符串名称，不是数字）、repeated 字段（JSON 里输出为数组）、map 字段（JSON 里输出为对象）、oneof 字段（JSON 里只包含设置了的那一个）。基本类型映射：string↔JSON string、int32/int64/uint32/uint64↔JSON number、bool↔JSON boolean、bytes↔JSON base64 string。

`proto-json inspect --proto message.proto` 列出文件中定义的所有 message 和 enum，输出每个 message 的字段列表（字段名、类型、是否 repeated）。`--format json` 或 `--format table` 控制输出格式。

proto 文件有语法错误时 stderr 打 "parse error at line {N}: {detail}"，退出码 1。输入二进制文件无法按指定 message 解码时 stderr 打 "decode error: {reason}"，退出码 1。JSON 输出默认 pretty print（缩进 2 空格），`--compact` 关闭格式化。项目拆成至少 3 个 Go 源文件：主入口、核心逻辑、数据模型分开。纯 Go 标准库，编译后单二进制可以直接跑。
