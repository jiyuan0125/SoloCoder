安全审计发现线上好几个接口根本没做认证，spec 里写没写没人知道。每次人工翻 spec 效率太低，得有个扫描工具自动查一遍。

直接扫描 OpenAPI 3.0 spec 文件（JSON/YAML），检查三类安全问题。第一，未认证接口：path 缺少 `security` 字段且全局也没有定义 `security` 的操作。第二，弱密码算法：`securitySchemes` 中 type 为 http 且 scheme 为 basic/digest 的标记为弱认证。第三，敏感数据暴露：response schema 中包含名为 password、secret、token、credit_card 的字段标记为敏感。输出报告到 stdout，格式 `SEVERITY | CATEGORY | PATH | METHOD | DETAIL`，如 `HIGH | NO_AUTH | /api/users | GET | missing security definition`。加 `-json` 输出 JSON 数组格式，加 `-o report.txt` 写文件。

全局有 security 定义但单个 path 用 `security: []` 覆盖掉的也算未认证。空 spec 文件报错 `error: empty spec file` 并退出码 1。未发现问题的退出码 0，有问题退出码 1。纯标准库 Go 实现，go build 直接编译。
