内网到某个客户的专线最近老丢包，运维那边只给了一个 ping 的平均值，看不出问题在哪。这就好比你去看医生，医生只告诉你"体温还行"——细节呢？

1. 命令行：`ping-stat --host 10.0.0.1 --count 100 --interval 500ms --timeout 2s --json`。`--count` 指定 ping 次数（默认 20），`--interval` 发包间隔（默认 1s），`--timeout` 单次超时（默认 3s），`--json` 开关控制输出格式。不传 `--json` 则实时输出每次结果，格式 `{seq} from {host}: time={rtt}ms`，超时的打 `request timeout: seq={seq}`。

2. 结束后输出统计摘要。JSON 模式输出完整结构：`{ "host": "10.0.0.1", "sent": 100, "received": 95, "lost": 5, "loss_rate": 5.0, "rtt": { "min_ms": 1.2, "max_ms": 45.3, "avg_ms": 3.5, "p50_ms": 2.8, "p95_ms": 12.1, "p99_ms": 38.7, "jitter_ms": 2.1 }, "timestamps": [{ "seq": 1, "sent_at": "...", "rtt_ms": 3.2, "status": "ok" }, ...] }`。抖动 (jitter) 计算方式是相邻成功 RTT 差值的平均数。

3. 百分位计算要对成功 RTT 排序后取对应位置，不要用估算法。丢包率保留一位小数，百分比形式（如 5.0 表示 5%）。host 参数不传或格式错误退出码 1，stderr 打 "usage: ping-stat --host <ip-or-hostname> [options]"。

注意：用 ICMP 需要考虑跨平台问题，Linux 上用 raw socket，Windows 上如果权限不够要退化为 TCP ping 模式（连目标 host 的某个端口）。纯 Go 标准库，编译后单二进制可以直接跑。
代码分文件组织，解析器、处理器、输出器分开，main.go 只做参数解析和流程串联。
