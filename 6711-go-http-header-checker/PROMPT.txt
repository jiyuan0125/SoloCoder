V2 要上线了，安全扫描那边说站点缺好几个安全 header。到底缺了哪些、配得对不对，得有个工具一次查清。

`header-check --url https://example.com --format json`。发送 GET 请求拿到响应 header，逐项检查安全 header。检查清单——Content-Security-Policy（存在即可）、Strict-Transport-Security（必须含 max-age≥31536000秒）、X-Frame-Options（值必须是 DENY 或 SAMEORIGIN）、X-Content-Type-Options（值必须是 nosniff）、X-XSS-Protection（值应该是 0 或 "1; mode=block"）、Referrer-Policy（no-referrer 等合规值）、Permissions-Policy（存在即可）。

输出 JSON：`{ "url": "...", "checks": [{ "header": "Strict-Transport-Security", "present": false, "value": "", "status": "missing" }, { "header": "X-Frame-Options", "present": true, "value": "ALLOWALL", "status": "invalid", "detail": "expected DENY or SAMEORIGIN" }] }`。status 三种：pass、missing、invalid。

`--output headers.json` 导出完整响应 header。URL 连不上退出码 1。所有 pass 退出码 0，有 missing 或 invalid 退出码 1。需要用到 bytes.Buffer 等标准库功能。Go 标准库实现，不依赖第三方包。go build 能编译通过。
不要写单文件，核心逻辑、CLI 入口、辅助工具各放一个文件。
