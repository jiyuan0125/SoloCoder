连接池参数到底设多大合适？生产环境 max_conns=100 但实际 QPS 上去之后等待超时频发。先在测试环境模拟一遍——

先创建连接池，参数用 flag 传入：`--max-conns 50 --max-idle 10 --idle-timeout 30s --wait-timeout 5s`。然后模拟工作负载：`--workers 200 --requests 10000 --hold-time 100ms`，200 个 worker 同时获取连接，每个连接持有 100ms 后归还。跑完输出统计报告。

报告字段包括：总请求数、成功获取数、等待超时数（exit code 1 的请求）、平均等待时间、P50/P95/P99 等待时间、最大并发使用数、空闲回收次数。格式化成表格输出，`--json` 参数切换为 JSON 格式。连接创建和销毁也记录时间点，输出创建速率和销毁速率。

边界场景：workers 大于 max-conns 时必然出现等待超时，工具要正确统计。idle-timeout 到期后自动回收空闲连接并计入统计。wait-timeout 内未获取到连接的请求标记为 timeout 而不是 error。空的连接池（max-conns=0）直接报错 "invalid config: max-conns must be > 0" 退出码 1。负数参数也报错退出码 1。

Go 实现，只用标准库，交叉编译友好。
