几十个接口，每次上线前手工测一遍？新人两天就受不了了。

测试用例写 YAML 文件，结构示例：
```yaml
name: "用户接口测试"
base_url: "http://localhost:8080"
tests:
  - name: "获取用户列表"
    method: GET
    path: "/api/users"
    expect:
      status: 200
      body_contains: "users"
  - name: "创建用户"
    method: POST
    path: "/api/users"
    body: '{"name":"test"}'
    headers: {"Content-Type":"application/json"}
    expect:
      status: 201
```

运行 `./tester -file tests.yaml`，逐个执行请求。断言支持：status（精确匹配）、body_contains（包含字符串）、json_path（`$.data.id` 等于某个值）、response_time_lt（响应时间小于 X ms）。变量替换用 `{{base_url}}` 和 `{{env.API_KEY}}`。

输出报告到 stdout：✓ GET /api/users - 200 (45ms)，✗ POST /api/users - 500 expected 201 (120ms)。最后汇总：Passed: 5/7, Failed: 2。退出码：0=全通过，1=有失败。用 `-o report.json` 输出 JSON 报告，含每个用例的请求/响应详情。

路径参数安全处理，`../` 这种不跟随。Go 标准库，`go build` 编译通过。
代码分文件组织，解析器、处理器、输出器分开，main.go 只做参数解析和流程串联。
