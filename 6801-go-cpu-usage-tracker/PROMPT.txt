top 看一眼就过去了，数据没法回溯？生产环境出了 CPU 飙高的故障，事后想分析是哪个进程搞的，但当时没有记录。有没有一个轻量工具能持续采集 CPU 数据存下来？

`cputrack` 启动后默认每 5 秒采集一次。`--interval 1s` 改采集间隔。采集内容包括：总体 CPU 使用率（user/system/idle/iowait 百分比）、每个逻辑核心的使用率、CPU 占用前 10 的进程（PID、名称、CPU%）。

输出方式三种——stdout 实时表格显示；`--log cpu.csv` 写 CSV 文件，每行带时间戳；`--json` 输出 JSON Lines 格式方便后续用 jq 分析。CSV 列：timestamp,cpu_user,cpu_system,cpu_idle,top_pid,top_name,top_cpu_pct。

`--top N` 改变显示的 Top 进程数量。`--duration 10m` 跑指定时长后自动退出，不设就持续跑直到 Ctrl+C。`--threshold 80` 超过 80% 使用率时 stderr 输出告警 "CPU usage exceeded threshold: XX%"。主流程修改全局状态后内部触发的事件处理函数也读取同一份状态。扫描完成后自动生成摘要文件。某些配置下可能没有输出内容。

用 Go 标准库写，go run . 或 go build 都行。
