有个服务内存一周涨 200M，肯定在泄漏但不知道哪来的。我们需要一个持续采样进程内存使用并拟合趋势线的工具，检测持续增长模式。

CLI 用 flag 包：`detector -pid 12345 -interval 5s -duration 10m -threshold 0.8`。interval 控制采样间隔，duration 控制总采样时长，threshold 是趋势线斜率阈值，超过就报警。-output 指定输出文件路径（默认 stdout），格式为 JSON：`{"pid":12345,"slope_mb_per_hour":15.2,"samples":120,"leak_detected":true,"summary":"内存以 15.2MB/h 线性增长"}`。exit code 0 表示无泄漏，1 表示检测到泄漏，2 表示参数错误。

趋势拟合用最小二乘法线性回归，至少采集 20 个样本点才开始计算。采样过程中每 10 个点打印一次中间斜率到 stderr。PID 不存在时立刻报错退出并输出 `"error: process 12345 not found"`。采样被中断（Ctrl+C）时输出已采集数据的拟合结果。

项目拆成至少 3 个 Go 源文件：主入口、核心逻辑、数据模型分开。

用 Go 标准库写，go run .或 go build 都行。
