昨晚网卡中断全打到 CPU 0 上了，单核跑到 100% 其他核闲着。调 IRQ 亲和性得先知道中断分布，不然就是瞎调。统计 /proc/interrupts 里的数据，按核和类型分类，支持持续监控和变化率。

步骤：1）读取 /proc/interrupts 解析成 `map[irq_type][]count_per_cpu`；2）支持单次快照 `intcount snapshot` 和持续监控 `intcount watch -interval 2s`；3）变化率模式 `intcount delta -interval 5s`，输出两次采样差值。

输出表格格式对齐到终端宽度：`IRQ_TYPE  CPU0  CPU1  CPU2  ...  TOTAL`，最后一列合计。JSON 模式加 `-json` flag：`{"interrupts":[{"type":"RES","counts":[1200,3400,...],"total":46000,"delta":null}]}`。watch 模式按 Ctrl+C 停止时打印汇总。/proc/interrupts 不存在报 `"error: /proc/interrupts not found, Linux only"` exit 1。

项目拆成至少 3 个 Go 源文件：主入口、核心逻辑、数据模型分开。数据导入后自动更新关联的索引文件。新导入的数据可能还没建立关联。工具管理配置模板和配置实例。实例基于模板生成。

用 Go 标准库写，go run .或 go build 都行。
