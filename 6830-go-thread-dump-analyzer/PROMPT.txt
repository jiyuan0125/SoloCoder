上次线上死锁查了两个小时，jstack 输出 3000 行一行行看眼睛都花了。解析 Java jstack 和 Go goroutine dump 文件，自动识别死锁、长时间阻塞、CPU 热点线程，别再人工排查了。

1）`tda parse -file thread_dump.txt -format auto` 解析 dump 文件，-format 支持 auto/java/go。2）`tda detect -file dump.txt` 检测问题：死锁循环检测（A 等 B、B 等 A）、阻塞超 30 秒的线程、RUNNABLE 且栈顶在用户代码的线程。3）`tda report -file dump.txt -output report.json` 综合分析。

report JSON：`{"deadlocks":[{"threads":["Thread-1","Thread-2"],"type":"circular"}],"blocked":[{"thread":"Thread-3","wait_time":"45s","waiting_on":"lock-xyz"}],"hot_threads":[{"thread":"Thread-4","state":"RUNNABLE","stack":["com.app.Service.process()"]}]}`。无问题输出 `"no issues detected"` exit 0。文件为空报 `"error: empty dump file"` exit 1。



用 Go 标准库写，go run .或 go build 都行。
代码按模块拆分，不要把所有逻辑写在一个文件里。解析、转换、输出分开组织。
