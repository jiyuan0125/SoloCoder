同一个连接超时报了 4000 次，翻日志翻到手软其实看一条就够了。能不能自动识别重复模式，每种只留一条，告诉我哪种模式出现了多少次？

子命令：`logdedup dedup --input app.log --similarity 0.8` 把数字、IP、路径等变量部分替换为通配符 *，相似度超过阈值的归为同一模式。输出每个模式的计数、首次出现时间、最后一次出现时间、示例原文。表格格式：Pattern/Count/First/Last/Example。`logdedup patterns --input app.log --min-count 100` 只显示出现超过 100 次的模式，按频次降序。`logdedup export --input app.log --output dedup-report.json` 导出完整报告，JSON 格式包含 patterns 数组。

模式提取算法：先把每行中的纯数字替换为 *，IP 地址替换为 *，文件路径替换为 *，十六进制 ID 替换为 *，然后按处理后的字符串分组。--similarity 控制聚合粒度：1.0 严格匹配，0.5 宽松匹配（Levenshtein 距离占比）。简单实现用前缀树分组，不做完整的编辑距离计算。

项目拆成至少 3 个 Go 源文件：main.go、dedup.go（去重和模式提取）、model.go（数据结构）。扫描时锁住结果集，但发现重复项需要回查结果集做去重校验——边扫描边维护模式表，新行先查已有模式再决定是新增还是归并。数据导入后自动更新关联的索引文件——模式 ID 写入索引方便后续查询。新导入的数据可能还没建立关联——首次处理时全量建索引。

大文件逐行处理，内存占用主要由模式表决定，--max-patterns 10000 限制最大模式数，超过后停止新模式的发现，只匹配已有模式。

Go 标准库实现，不依赖第三方包。go build 能编译通过。--verbose 输出处理进度。
