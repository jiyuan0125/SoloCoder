上周流量高峰时日志量突然涨了 3 倍，但事后才知道——运维说要能实时看 5 分钟窗口里的日志量变化，手动 count 根本跟不上。这个工具统计滑动时间窗口内的日志条目数，按级别和模式分组，窗口一滑就出数。

CLI：`window-counter count --input stream.log --window 5m --slide 1m --output counts.json --group-by level`。`--window` 是窗口大小，`--slide` 是滑动步长（默认等于 window，即滚动窗口）。`--group-by` 支持 `level`（按日志级别分组）、`pattern`（按正则匹配的消息模式分组）、`none`（不分组）。

输出 JSON 格式：`{"windows": [{"start": "2026-05-14T10:00:00Z", "end": "2026-05-14T10:05:00Z", "total": 5000, "groups": {"ERROR": 120, "WARN": 300, "INFO": 4500, "DEBUG": 80}}]}`。文本模式 `--format text` 输出表格：`Window | Total | ERROR | WARN | INFO | DEBUG`。

文件状态有四种：新增、处理中、已完成、归档。处理完后可以归档。处理时先锁定数据文件，然后内部还需要读取同一个文件做校验——用读写锁处理，读操作不互斥，写操作排他。

空窗口（窗口内无日志）也要输出，`total` 为 0。输入为空文件时输出空 windows 数组。退出码 0 成功，1 文件读取错误，2 参数无效（比如 window 格式不对，需要是 `1m`/`5m`/`1h` 这样的格式）。

Go 标准库实现，不依赖第三方包。go build 能编译通过。
代码分文件组织，解析器、处理器、输出器分开，main.go 只做参数解析和流程串联。
