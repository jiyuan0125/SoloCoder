上周排查线上问题，在几十个堆栈信息里手动找行号找了半天。这种苦力活不该人干——从日志里把结构化错误信息提出来，文件名、行号、函数名、错误消息各归各的，输出 JSON 直接交给下游分析。

CLI 用法：`tool extract --input app.log --output errors.json [--pattern goroutine] [--min-depth 2]`。`--pattern` 过滤只提取包含指定关键字的堆栈，`--min-depth` 设定堆栈最少层数，少于这个数的不输出。输入文件不存在时 stderr 打印 "input file not found" 并以 exit code 1 退出。

解析出来的每条错误是一个 JSON 对象，字段包括：timestamp（原始时间戳字符串）、message（错误消息）、frames 数组（每个元素含 file、line、function、package）。多行堆栈要完整归到同一条错误里，不能拆散。

处理流程分阶段走：读取 → 按空行切分堆栈 → 正则提取字段 → 过滤 → 输出。每个阶段独立，当前阶段出错不影响已处理的结果。匹配结果为零时输出空数组 `[]`，不报错。统计信息写入 summary.json，字段有 total_lines、matched_errors、skipped_malformed。

纯标准库 Go 实现，go build 交叉编译友好，不依赖第三方包。
