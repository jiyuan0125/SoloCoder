统计日志写入速率、平均条目大小、磁盘占用增长速率——三个指标直接说明日志系统健不健康。上周日志写入突然变慢，排查花了半天，要是有个报告工具早发现了。

CLI 设计：`report generate --input /var/log/app/ --format table`，`--format` 可选 table、json、csv 三种输出。`--window 5m` 指定统计时间窗口，默认 1 分钟。输出字段包括 window_start、window_end、lines_per_sec、avg_bytes、disk_growth_mb、p95_latency_ms。

输出格式说明——table 模式输出对齐的 ASCII 表格，表头用 `|` 分隔；json 模式输出 `{ "windows": [...] }` 数组；csv 带 header 行。磁盘增长速率通过比较窗口起止时的文件大小差值计算，无法获取文件大小时该字段填 -1 并 stderr 打印警告。

处理流水线：初始化 → 扫描文件列表 → 按时间窗口分桶 → 计算指标 → 输出报告。扫描阶段的文件排序按修改时间，源文件被外部修改不会影响已完成的窗口计算。后台用多个 goroutine 并行处理不同时间窗口的数据，最终合并写入同一个结果文件。

窗口内没有任何日志行时，该窗口的 lines_per_sec=0，其他指标标为 null。空目录直接报 "no log files found" 退出码 1。

Go 标准库实现，go run . 或 go build 都行。
