半夜 3 点支付网关挂了，Python 健康检查脚本因为 GIL 卡住没发现，损失了 2 小时交易。服务涨到 20+ 个之后 Python 脚本已经力不从心——用 Go 重写一个周期性健康检查工具。

配置 YAML checks 列表每项：name、type（http/tcp/dns/command）、target、interval（默认 30s）、timeout（默认 5s）、threshold（连续失败几次告警，默认 3）、on_failure（失败时执行的修复脚本）。`checker start --config health.yaml` 启动。

http 型发 GET 匹配 expected_status（默认 200）和可选 expected_body。tcp 型连 target:port。command 型执行命令 exit 0 为健康。连续失败达 threshold 时 stderr 输出 `ALERT: {name} unhealthy ({fail_count} failures)` 写入 alerts.log。恢复时输出 `RECOVERED: {name}`。on_failure 脚本达 threshold 执行一次，本身 30 秒超时。

`checker status` 输出 ASCII 表格（Check/Status/LastCheck/FailCount）。`checker history --name http-api --last 50` 查记录。`checker run --once` 跑一轮退出。timeout 未完成标 failed。配置 target 格式错报 "invalid target" 退出码 1。

纯 Go 标准库，编译后单二进制直接跑。
不要写成一个 main.go 搞定所有事情。按职责拆文件：入口、解析、处理、输出分开。
