之前用 shell 脚本做 CSV 格式转换，iconv 和 dos2unix 各种配合，遇到 Shift-JIS 编码的日文文件就傻了。Go 重写一个，支持编码转换（UTF-8、GBK、Shift-JIS）、分隔符转换（逗号变 Tab）、行尾符转换（CRLF 变 LF）。管道友好，可以接在其他命令后面用。

命令行用法：csvconv --input data.csv --output result.tsv --from-encoding utf-8 --to-encoding gbk --from-delimiter "," --to-delimiter "\t" --line-ending lf。所有 flag 都有合理默认值，--input 缺省时从 stdin 读，--output 缺省时写到 stdout。编码转换用 golang.org/x/text 包处理，分隔符支持逗号、Tab、分号、竖线四种。

输入文件不存在时打印 "error: input file not found: xxx" 并退出码 1。空文件直接输出空结果，退出码 0。编码转换失败时打印具体行号和报错信息，比如 "error: encoding conversion failed at line 42: invalid GBK sequence"。管道模式下（stdin 输入）要能实时流式处理，不要全部读进内存再吐。

--list-encodings 参数列出所有支持的编码名称。带 BOM 的 UTF-8 文件自动识别并去除 BOM，输出时不再加 BOM（除非用 --keep-bom）。大文件（百万行级别）内存占用控制在 50MB 以内，流式逐行处理。

Go 实现，go build 编译出单二进制。交叉编译友好，不依赖 CGO。
代码组织要清晰：CLI 参数处理一个文件，核心业务逻辑一个文件，公共工具函数一个文件。
