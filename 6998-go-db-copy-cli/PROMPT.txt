开发库改了表结构要同步到测试环境，直接拷 db 文件过去 schema 对不上——两个 SQLite 之间得做智能复制，列多了少了都能处理，数据量差别大也行。

`dbcopy copy --source dev.db --target test.db --table users,orders --filter "orders:created_at > datetime('now', '-30 days')" --create-missing`。`--source` 和 `--target` 指定源和目标 SQLite 文件路径。`--table` 逗号分隔要复制的表名，不指定则复制所有表。`--filter` 格式为 `表名:SQL WHERE 条件`，只复制满足条件的行。无 filter 则全表复制。

`--create-missing` 标志：目标库不存在的表，自动用源库的 CREATE TABLE 语句建表。不加此标志且目标缺表时，输出 `table XXX not found in target, use --create-missing` 并跳过该表。复制过程中遇到主键冲突：`--conflict skip`（默认）跳过重复行，`--conflict replace` 覆盖，`--conflict error` 中断并退出码 1。

输出汇总：`{table: "users", copied: 150, skipped: 3, errors: 0}`，每张表一行 JSON 到 stdout。源文件或目标文件不存在时输出具体错误并退出码 1。表为空时正常复制（零行）。Go 标准库实现，交叉编译友好。
至少拆成两个包或三个文件以上，不要单文件一把梭。
