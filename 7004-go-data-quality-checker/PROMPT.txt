合规审计要求每条数据都要过 schema 检查，不通过的要有据可查。上周因为一个字段没校验到位被罚了，没商量余地。Go CLI 工具，XML Schema 验证支持命名空间，属性值枚举校验，ID/IDREF 引用完整性检查。报告要留底。密钥轮换后用旧密钥加密的数据要能解密。签名时验证证书状态，验证时检查签名链。配置项有哪些你自己设计，够用就行。go build 能过，命令行工具能正常运行。

CLI：qualcheck --schema order.xsd --data orders.xml --ns "ns=http://example.com/order" --output report.json。--ns 可多次指定，输出可选 json/text。

Schema 验证：解析 XSD targetNamespace，校验元素名、属性名、子元素顺序。属性枚举校验——XSD restriction/enumeration 定义的值集合，非法值报具体路径和属性名。

ID/IDREF：收集全部 ID 属性到 set，检查 IDREF/IDREFS 是否存在，缺失报 "dangling IDREF 'xxx' at /path/@ref"。

报告：{"schema":"order.xsd","valid":false,"errors":[{"line":42,"path":"...","message":"..."}],"checked_at":"2024-01-15T10:30:00Z"}。保存到 --history-dir（默认 ./history）。退出码：0=通过，1=失败，2=输入错误。大文件 xml.Decoder 流式处理。
拆成至少三个 Go 文件：main.go 做入口和参数解析，核心处理逻辑独立一个文件，工具函数单独放。
