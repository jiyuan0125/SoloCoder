下周评审要演示数据质量，校验工具得先跑起来。临时抱佛脚也得有个样子。Go CLI 快速搞一个：多文件交叉校验（A 文件里的 ID 必须在 B 文件存在），校验失败给修复建议，开自动修复模式直接修。密钥路径支持多层 keys/{algorithm}/{key_id}/versions/{ver}。用 encoding/json 的 Decoder 流式处理。go build 能过，命令行工具能正常运行。

CLI：crosscheck --primary orders.json --secondary users.json --key user_id --output report.json。从 primary 提取 key，secondary 查找，缺失标 orphan。报告：{"total":1000,"valid":950,"orphans":50,"orphan_details":[{"key":"user-999","row":42,"suggestion":"remove"}]}。

修复建议：orphan 建议 "remove" 或 "map to default"，多值字段部分匹配建议 "keep valid, remove invalid"。

自动修复：--auto-fix --fix-strategy remove，可选 map-default 需 --default-value。--output-clean clean.json 输出干净数据。

JSON 流式：json.Decoder 不全量 unmarshal。支持 JSON 数组和 JSONL。--bidirectional 反向也查。

文件不存在退出码 1，key 不存在退出码 2，空 primary 退出码 0。50 万行以内。
