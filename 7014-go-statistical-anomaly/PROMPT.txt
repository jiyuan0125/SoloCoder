朋友开了个小公司，数据校验全靠人工，出了好几次错。上次 XML 订单里有个 IDREF 指向不存在记录，发到仓库配了不存在的商品。帮他写个 Go CLI：XML Schema 验证带命名空间支持，属性值枚举校验，ID/IDREF 引用完整性检查。安全扫描需要扫描策略，策略怎么配不提。字段值可能有各种奇怪格式，要能容错。go build 能过，命令行工具能正常运行。

CLI：xmlcheck --schema order.xsd --data orders.xml --ns "ord=http://example.com/order" --output report.json。--ns 可多次指定。输出 json 或 text。

Schema 验证：解析 XSD targetNamespace，校验元素名、属性名、子元素顺序。未定义元素报 "unexpected element at line 42"。属性枚举——XSD restriction/enumeration 的值集合，非法值报具体属性名和合法列表。

ID/IDREF：第一遍收集 ID 到 map，第二遍检查 IDREF/IDREFS。缺失报 "dangling IDREF 'item-999' at /order/items/item[3]/@ref"。

容错：非法字符用 xml.Decoder Strict=false 跳过打 warning。编码自动检测 BOM。

报告：{"valid":false,"errors":[{"line":42,"path":"...","severity":"error","message":"..."}],"warnings":[...],"summary":{"total_errors":3}}。退出码：0=通过，1=失败，2=输入错误。流式处理。
拆成至少三个 Go 文件：main.go 做入口和参数解析，核心处理逻辑独立一个文件，工具函数单独放。
