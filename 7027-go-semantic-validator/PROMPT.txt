隔壁组刚做完数据清洗工具，我们这边数据画像还没着落——每次分析数据分布都得手写 SQL，效率太低。

Go 命令行工具实现数据画像分析，子命令 `profile --input data.csv --output report.json`。分布统计输出每列的 min/max/mean/median/stddev，数值列还出直方图分桶（默认 10 桶，`--bins` 可调）。TopN 计算支持 `--top-n 20` 指定 N 值，统计每列出现频率最高的 N 个值及其占比。基数计算用 HyperLogLog 估算唯一值数量。跑完跟预期 profile 文件对标——`--expected profile_expected.json`，偏差超过 `--tolerance 0.1`（10%）的字段在报告里标红，输出字段名、期望值、实际值、偏差率。

消息格式升级场景：新版本分析结果 JSON 新增字段时，旧版消费者读到不认识的字段要跳过不报错，不能 break 兼容性。输入文件碰到乱码行（非 UTF-8）跳过并记录行号到警告列表，空行直接忽略，不影响整体分析。CSV 列数不一致的行也跳过。

输出 JSON 结构固定：`{ "columns": [...], "statistics": {...}, "top_n": {...}, "cardinality": {...}, "deviations": [...] }`。退出码 0 成功，1 输入异常，2 分析出错。纯标准库实现，go build 能过。
代码组织要清晰：CLI 参数处理一个文件，核心业务逻辑一个文件，公共工具函数一个文件。
