数字化改造第一步，老板点名要先搞校验，月底前得出活。但规则改了又怕影响全量数据，能不能先拿一小部分试试？

Go 命令行工具 `rule-chainer` 实现校验规则版本管理。`rule-chainer init --rules-dir ./rules` 初始化规则仓库，每个规则存为 YAML 文件，包含 name、version、expression、priority 字段。`rule-chainer apply --rules-dir ./rules --data input.csv --range 0-100` 灰度校验只取前 100 行试水。变更前自动评估影响范围——对比新旧规则对同一样本数据的校验结果差异，输出 affected_count 和 detail。`rule-chainer rollback --rules-dir ./rules --version v3` 回滚到指定版本，从 `.rule-history/` 目录恢复。CSV 列类型自动推断：采样前 100 行判断每列是 int/float/string/date，推断结果输出到 stdout 供确认。

数据库操作通过 REST 风格路径访问：`tables/{table}/rows/{id}/columns/{col}`。字段值遇到格式异常不中断，记录到 `parsing_errors` 数组，包含行号、列名、原始值、错误原因。

CLI 输出统一 JSON 格式，退出码 0 成功 1 规则冲突 2 输入异常。纯标准库实现，go build 能过。
代码要模块化：主流程、具体功能实现、辅助函数分开存放，主文件只做调度。
