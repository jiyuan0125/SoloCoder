映射逻辑散落在业务代码各处，改一个字段要改五个文件，上个月出了一次字段对不上的事故，从那以后就决定要把映射抽成独立模块。

Go CLI 工具叫 `enrichtool`，专门做字段映射和数据丰富。子命令 `remap` 做字段映射：`--mapping map.json` 指定映射配置，里面每条规则有 source、target、transform 三个字段。transform 支持 `to_int`、`to_float`、`to_date`、`to_bool`、`to_string` 五种类型转换，转换失败用 `--default` 指定的默认值填充，没有 default 就留空字符串。子命令 `condmap` 做条件映射：`--rule 'if status>100 then "error" else "ok"'` 这种简单条件表达式，走 A 分支或 B 分支，支持嵌套条件用 `elif`。子命令 `enrich` 用外部查找表丰富数据：`--lookup ref.csv --key product_id --add category,price_range`，查找表里找不到的 key 字段留空不报错。校验分三阶段走：格式校验→规则校验→关联校验，前一步通过才能做下一步，哪步失败 stderr 输出具体哪条记录哪个字段不通过。输入输出 stdin/stdout，`--format` 选 json/csv。go build 能过，命令行工具能正常运行。
不要写单文件，核心逻辑、CLI 入口、辅助工具各放一个文件。
