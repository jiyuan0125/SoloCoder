需求评审完确认了：扁平化和嵌套构建是两个独立功能，要能互相转换，缺一个都不行。

Go CLI 工具 `normalizer`，把 JSON 结构标准化这件事搞清楚。`flatten` 子命令：`--input nested.json` 读嵌套 JSON，点号路径展开，`{"user":{"name":"张三","addr":{"city":"北京"}}}` 变成 `{"user.name":"张三","user.addr.city":"北京"}`。`--separator` 可选分隔符，默认点号，数组索引用 `[0]` 格式。

`nest` 子命令反过来，`--input flat.json` 把点号路径重建回嵌套结构，碰到同一个前缀下既有标量又有对象的冲突，标量优先。`expand` 子命令处理数组展开聚合：同前缀 `items.0`、`items.1` 合并成 `items` 数组。

三个子命令 `--output` 指定输出文件，不指定就 stdout。空 JSON 输入 `{}` 或 `[]` 输出空结果不报错。深层嵌套超过 20 层给警告但继续处理，不截断。代码组织成多个文件——核心逻辑、IO 处理、命令行入口分开，别全塞 main.go 里，每个文件不超过 200 行。纯标准库，go build 能过，命令行工具能正常运行。退出码 0 成功，1 参数错，2 处理错。
代码分文件组织，解析器、处理器、输出器分开，main.go 只做参数解析和流程串联。
