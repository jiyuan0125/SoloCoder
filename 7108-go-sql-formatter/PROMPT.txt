实习生写了条没有 WHERE 的 UPDATE 把全表改了，还好是测试环境。新项目要求 SQL 提交前必须过静态检查，人工 review 太慢，每个 PR 都得改好几轮。

Go CLI 工具 `sqlfmt`。子命令 `check`：`--input queries/` 扫描目录下 .sql 文件（递归），逐文件逐句检查。规则包括：未使用索引（FROM 的表有 WHERE 字段但 schema 里没索引）、SELECT *（建议列出具体字段）、缺失 WHERE 的 UPDATE/DELETE（高危，标记红色）、危险操作 DROP/TRUNCATE（标记红色并输出 `⚠ DANGER: DROP/TRUNCATE detected`）。`--level warn|error` 控制检查严格度，warn 只输出警告，error 直接退出码 1。`--db app.sqlite` 指定 schema 来源用于索引检查。`format` 子命令格式化 SQL：关键字大写、缩进 2 空格、逗号后换行、子查询缩进，输出到 stdout 或 `--output`。加密需要密钥但怎么导入你定。扫描多个目录用 goroutine 并行处理。输出格式：`file.sql:15 [ERROR] UPDATE without WHERE clause`。检查通过时输出 `All checks passed.` 退出码 0。纯标准库，go build 能过就行。
