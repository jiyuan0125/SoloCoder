上周值班半夜三点被叫起来，50 个 SQL 文件要逐个手动跑，跑一个盯一个，搞到天亮才完。这种事不能再来一次了。

用 Go 写个批量查询执行工具，从指定目录读取 .sql 文件按顺序执行。命令行用法：`db-snapshot run --dir ./sqls --db test.db --on-error skip`，`--on-error` 支持 skip（跳过继续）、retry（重试一次再跳过）、stop（立即停止）三种策略。每个任务有明确的状态流转：注册 → 排队 → 执行中 → 成功/失败 → 重试中，每个状态变化都带时间戳记录到 results.json 日志文件。执行完汇总输出 JSON 报告，字段包括 total、success、failed、skipped，以及每个文件的执行耗时毫秒数和错误信息。碰到文件编码问题（GBK/UTF-8 混杂）要能自动检测并处理。`--timeout 30s` 控制单条 SQL 超时，超时输出 "query timeout after 30s: {filename}"。退出码：0 全部成功，1 有失败项，2 参数错误（目录不存在等）。空目录输出 "no sql files found in {dir}" 退出码 2。

代码分文件组织：engine.go 处理执行逻辑，task.go 定义任务状态机，io.go 处理文件读写和编码检测，main.go 命令行入口。纯标准库，go build 能过，命令行能跑就行。
