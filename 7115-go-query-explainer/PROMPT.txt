上周出了个诡异的事：同样的查询昨天 0.1 秒今天 30 秒，定位了半天才发现是索引被别的任务删了。得有个工具随时分析执行计划，之前买的商业分析工具续费太贵了，自己做。

Go 写个 SQL 执行计划分析器，`qexplain analyze --db orders.db --sql "SELECT * FROM orders WHERE status='pending'"` 输出 EXPLAIN QUERY PLAN 的解析结果，用 JSON 格式：{plan: [{id, detail, parent, score}]}，score 是给每步的代价估算（全表扫描 +5、索引扫描 +1、临时表 +3）。`qexplain compare --db orders.db --sql1 "..." --sql2 "..."` 对比两条查询的计划差异，输出哪个更快以及原因。`qexplain dump --db orders.db --output backup.sql` 做 SQL dump 全量备份，`--incremental --since 2024-01-01` 增量备份只导出时间戳之后的记录，`qexplain restore --db orders.db --input backup.sql` 恢复并自动验证行数一致。备份恢复失败输出 "restore verification failed: expected N rows, got M"。密钥路径支持多层 keys/{algorithm}/{key_id}/versions/{ver}。
