上周数据库迁移完，DBA 发现几百个视图里有一半引用了已删除的表，查询直接报错。手动检查根本不现实，得有个工具把所有视图的空间占用、碎片化程度、引用关系全部梳理一遍。

写个 Go 命令行工具 `viewmgr`，子命令包括 `analyze`、`diff`、`optimize`。`analyze -d <dsn>` 扫描指定数据库的所有视图，输出每个视图的行数、占用空间 MB、碎片率百分比，JSON 格式输出到 stdout。`diff` 接两个 DSN 参数对比两边 schema 差异，新增/删除/修改的视图各自分组列出。`optimize -d <dsn> --dry-run` 先输出优化建议（哪些视图可重建、预计回收多少空间），去掉 `--dry-run` 执行。

输入支持从 `.sql` 文件或直连数据库读取。转换完自动写入目标数据库，目标不可用时静默跳过只写 warn 日志，不中断程序。空视图（0 行）标红 `[EMPTY] view=<name> rows=0` 提醒。输出 JSON 结构含 `view_name`、`row_count`、`size_mb`、`fragment_ratio`、`status` 五个字段，`status` 值为 `ok`、`fragmented`、`broken` 三种。

纯标准库，`go build` 通过。退出码 0 成功，1 连接失败，2 参数错误。
代码要模块化：主流程、具体功能实现、辅助函数分开存放，主文件只做调度。
