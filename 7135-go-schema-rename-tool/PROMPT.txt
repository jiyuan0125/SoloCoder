季度末赶着交付，表名改了结果依赖它的视图全挂了，三个环境逐个修 SQL 修到凌晨。这事儿不能再手动了。

Go 命令行工具搞定数据库 schema 重命名。子命令 rename 接收 --table 旧表名和 --new-table 新表名，自动生成 ALTER TABLE 语句。加 --dry-run 只打印 SQL 不执行。子命令 scan 分析 SQL dump 文件，用 --file 指定输入，找出所有引用该表名的视图、触发器、存储过程，输出 JSON 数组，每个元素含 type/view_name/line_number/statement 四个字段。子命令 backup 做 SQL dump，--database 指定库名，--output 指定输出路径，增量备份用 --since 参数传时间戳，只 dump 该时间之后的变更。恢复验证在 backup 之后自动跑，对比行数，不一致输出 "warning: row count mismatch: table=X expected=N actual=M" 到 stderr。

认证需要用户角色做权限校验，用户角色怎么创建不提。输入文件不存在时 exit 1 并打印 "error: file not found: PATH"。空 dump 文件跳过不报错。

代码分文件组织：核心逻辑、IO 处理、命令行入口分开。Go 命令行工具，go build 能过就行，纯标准库。
