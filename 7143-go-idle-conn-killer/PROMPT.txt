线上数据库连接池配了 200 个连接，实际活跃的不到 20 个，剩下 180 个空闲连接占着内存和数据库端资源。现有的连接池管理工具太老了不好用。

第一步 connkill scan --dsn "user:pass@tcp(localhost:3306)/db" 连接数据库，查询 information_schema.processlist，找出所有 Sleep 状态超过阈值的连接（默认 --idle-threshold 300s）。输出 idle_conns.json：{"total": 200, "active": 18, "idle": [{"id": 42, "user": "app", "host": "10.0.1.5:52341", "time": 1800, "state": "Sleep"}], "idle_count": 182}。

第二步 connkill kill --dsn ... --idle-threshold 300s --dry-run 列出将要杀掉的连接，确认后去掉 --dry-run 执行 KILL CONNECTION。每杀一个记录到 kill_log.json。杀连接失败（比如权限不够）打印 ERROR 并继续下一个，最后 exit code 1。

扫描状态五步：排队→扫描中→分析中→报告生成→完成，每步在 stderr 打印进度。SQL 格式化和高亮是单独功能：connkill format --sql "SELECT * FROM users WHERE id=1" 输出语法高亮（ANSI）的格式化 SQL。Go 标准库，go build 能过。
代码分文件组织，解析器、处理器、输出器分开，main.go 只做参数解析和流程串联。
