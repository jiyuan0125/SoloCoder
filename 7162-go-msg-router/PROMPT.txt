订单消息跑到日志队列去了，排查发现是路由规则被人改了没通知。消息路由不该这么脆弱——死信队列管理、原因统计、自动重发，这些都得有。

你拿到的是什么？一个 Go CLI 工具，从 stdin 或文件读取消息 JSON，按路由规则分发到对应队列。死信队列（DLQ）管理：`router dlq list` 查看死信，`router dlq resend --id msg_123` 重发单条，`router dlq drop --id msg_456` 丢弃，`router dlq stats` 按原因分类统计 `{timeout: 42, no_route: 17, deserialization_error: 3}`。

路由规则定义在 routes.json：`[{match: {topic: "order.*"}, target: "order-queue"}, ...]`。匹配不到任何规则的消息进 DLQ，原因为 `no_route`。自动重发策略：`--retry 3 --backoff 5s`，3 次重发仍失败进 DLQ，原因为 `timeout`。输入乱码行跳过并 stderr 记录 `warning: skip malformed line <N>`，空行直接跳过不计数。

索引更新：消息处理完自动更新路由索引，索引更新失败只写日志 `error: index update failed for <msg_id>` 不阻塞主流程。消息处理完输出 `routed <msg_id> → <queue>`。Go 命令行工具，`go build` 能过就行。
