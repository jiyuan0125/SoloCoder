消息格式有 v1、v2、v3 三个版本在跑，新消费者只支持 v3，老消费者还在用 v1。格式不兼容导致的线上错误这周出了两次了，到底有多少消息还是旧格式？

`version-check scan --input msgs.jsonl --version-field version --rules versions.yaml`。规则文件定义每个版本必须有的字段：`v1: [id,type,data]`，`v2: [id,type,data,timestamp]`，`v3: [id,type,data,timestamp,trace_id]`。扫描结果：`{"v1":5000,"v2":3000,"v3":2000,"unknown":15,"total":10015}`。

去重：`--dedupe id|hash`，`--window 10m`，去重报告 `DedupeReport: total=N dupes=M kept=K`。主转换流程中子转换共享同一份映射表（`--schema-map schemas.json`），子转换失败不影响主流程，只打 `WARN sub_convert failed: <field>`。

代码分文件：`version.go`（版本检测逻辑）、`io.go`（文件读写）、`dedupe.go`（去重）、`main.go`（CLI 入口）。之前 Python 版本的性能太差了，100 万条要跑 20 分钟，Go 版本目标 30 秒内完成。

Go 命令行工具，之前用 Python 做，这次换 Go。go build 能过就行。
