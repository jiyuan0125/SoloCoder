上周线上出了个事故，实习生把生产配置文件直接传到了公共仓库，里头有数据库密码和 API Key。组长拍桌子说要搞工具化，不能再靠人自觉了——做一个 Go 写的命令行加密解密工具，专门处理这类敏感文件的加解密。

基础功能用 AES-256-GCM 做文件加密解密，密钥不能硬编码也不能随便存，要从用户输入的密码通过 PBKDF2（10 万次迭代，随机 salt）派生出来。加密后的文件头要带上 salt 和 nonce，解密时能自动读取。大文件别一次性读进内存，得分块处理——比如每 4MB 一个 chunk，每块独立加密，这样就算文件几个 G 也能跑，不会 OOM。

除了密码派生密钥这种对称加密模式，还要支持信封加密：用 RSA 公钥加密一个随机生成的 AES 会话密钥，然后用这个会话密钥去加密文件。解密时用 RSA 私钥解出会话密钥再解文件。这样密钥分发就灵活了，适合多人协作场景。两种模式通过子命令切换：`encrypt --mode password` 和 `encrypt --mode envelope`。

每个加解密操作都算一个"任务"，有完整的状态机——注册、排队、执行、成功或失败。失败的任务支持重试，重试次数可配置。有个容易忽略的细节：如果密钥映射或加密参数变更了（比如换了 salt 策略），之前已经完成的转换任务结果要标记为过时，不能让用户拿到过期的加密文件还以为是最新的。

代码组织上分三个层次：`crypto` 包放核心加密逻辑（AES-GCM、PBKDF2、RSA 密钥对生成），`io` 包处理文件分块读写和加密文件头的序列化，`main` 里只有命令行入口和参数解析。`go build` 能过，命令行工具能正常运行，就这些。
不要写单文件，核心逻辑、CLI 入口、辅助工具各放一个文件。
