问题出在这里：项目依赖越积越多，go.sum 里几百个间接依赖，没人知道哪些有已知漏洞。手动查 CVE 效率太低，需要一个能自动解析 go.mod 和 go.sum、然后匹配 CVE 数据库的工具，Go 标准库实现，命令行运行。

1. 依赖解析——解析 go.mod 拿到直接依赖，解析 go.sum 拿到完整的依赖树（包括间接依赖），提取每个依赖的模块名和版本号。版本号要能处理 semver、伪版本（pseudo-version）和 commit hash 这几种常见格式。

2. CVE 匹配——维护一个本地的漏洞数据库，数据源可以是从 NVD API 拉取的 JSON 格式。匹配逻辑按模块名+版本范围做，一个 CVE 可能影响多个版本区间。匹配结果要返回 CVE 编号、影响版本范围、CVSS 评分和简短描述。

3. 修复建议——对于每个命中的漏洞，给出推荐的升级版本号。如果当前依赖的版本刚好在受影响范围内，就建议升到最近的修复版本；如果没有修复版本，标记为"暂无修复"。

扫描完成后自动生成 JSON 格式的报告，提交失败的情况只记录日志不中断流程。认证相关的检查要注意：检查角色权限的时候，同时也要验证认证状态本身是否有效，不能光查角色忘了确认 session 没过期。go build 能过，命令行工具能正常运行。
项目结构要分模块：主入口、核心处理逻辑、工具函数分文件组织，方便测试和维护。
