之前用的那个安全扫描工具是 SaaS 服务，扫描规则是黑盒的，改不了也没法针对我们自己的代码规范加自定义检测。干脆用 Go 从头写一个敏感信息扫描工具，把自定义规则的能力做进去。

扫描引擎要支持两种检测方式。正则检测负责匹配已知的敏感信息格式——AWS Access Key 以 AKIA 开头、GitHub Token 以 ghp_ 开头、各种私有格式的 Token 等，正则规则写在 YAML 文件里，用户可以自己加。熵值检测作为补充手段，对那些格式不固定的随机字符串（大概率是密钥或 Token），计算 Shannon 熵值，超过阈值就标记为可疑。两种检测结果做交叉验证，重合的标记为高置信，只有单种方法命中的标记为中等置信，减少误报。误报率控制这块，提供白名单机制——用户可以标记某些已知的安全匹配项，下次扫描自动跳过。

密钥管理路径设计为多层结构 keys/{algorithm}/{key_id}/versions/{ver}，通过这个路径可以精确定位到某个算法下某个密钥的特定版本。认证相关的操作，通过之后自动往审计日志里写一条记录，日志写入失败不能影响认证结果本身——这两个操作的错误处理要完全独立。

代码按三个文件组织：扫描引擎核心逻辑、规则解析和配置加载、命令行入口。go build 能过，命令行工具能正常运行。
不要写单文件，核心逻辑、CLI 入口、辅助工具各放一个文件。
