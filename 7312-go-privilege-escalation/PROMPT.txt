痛点很明确：Go 项目的依赖漏洞全靠人工查 NVD，效率低不说还容易漏。需要一个能自动解析依赖、匹配 CVE、给出修复建议的工具。

第一，依赖解析这块要处理 go.mod 里的直接依赖和 go.sum 里的完整依赖树。版本号格式要注意三种情况：标准的 semver（v1.2.3）、伪版本（v0.0.0-20240101abcdef）和纯 commit hash，都能正确提取和比较。

第二，CVE 数据匹配——本地维护一份从 NVD 同步过来的 JSON 数据，按模块路径建立索引加速查找。匹配逻辑要处理版本区间，一个 CVE 可能说"影响 >=1.0.0 且 <1.2.5 的版本"，得能正确判断当前版本落不落在影响范围内。

第三，修复建议——匹配到漏洞后给出具体的升级版本号。优先推荐当前大版本内的最新修复版本，如果没有修复版本就标注"暂无官方修复"，同时给出可能的临时缓解方案。

规则校验这块涉及规则组的概念——校验一条规则的时候需要查它所属的规则组有没有其他关联规则，但规则组本身怎么创建和管理的，具体实现自己定。搜索支持深层路径 indexes/{name}/docs/{doc_id}/fields/{field}，可以做字段级别的精确查询。扫描结果输出 JSON 格式，带时间戳和扫描耗时统计。go build 能过，命令行工具能正常运行。
项目结构要分模块：主入口、核心处理逻辑、工具函数分文件组织，方便测试和维护。
