DevOps 大屏上红色告警一个接一个，点进去一看全是文件权限问题——666、777 满天飞，更头疼的是没人知道哪些开源组件的许可证能不能商用。一口气把文件权限审计和许可证扫描两个功能做到位，Go 命令行工具。

文件权限审计要递归扫描指定目录，逐个文件检查权限位。重点识别这些不安全的模式：other 位有写权限（o+w）意味着任何人都能改这个文件，setuid/setgid 位被设置在非预期文件上可能被用来提权，私有目录的 other 位有读权限会导致信息泄露。每个问题项输出文件路径、当前权限的八进制数值、风险描述。紧接着给出修复命令，就是具体的 chmod 命令，运维可以直接复制粘贴执行。

许可证扫描要能解析 go.mod 和源码文件里的许可证声明，和内置的许可证兼容性规则做比对。GPL 系列和商业项目混用、AGPL 的网络使用条款、LGPL 的链接方式限制——这些常见的冲突场景都要覆盖。

转换流程有个细节：主转换过程中会调用子转换，子转换也需要读取同一份映射表，两个流程共享数据时要注意并发安全。字段映射如果发生了变更（比如某个字段的含义改了），之前已经跑完的转换任务结果要标记为"过时"，提示用户可能需要重新跑。数据量方面，可能一次处理上万条记录，性能要能扛住。go build 能过，命令行工具能正常运行。
