上周 review 代码发现生产配置里 debug: true 开着，吓得我赶紧把所有项目的配置文件翻了一遍，结果触目惊心——admin/admin、空密码、明文 Token 到处都是。Go CLI 做一个配置审计工具，把扫描、基线检查和报告输出串起来。

配置审计扫描 .yaml、.json、.toml、.env、.ini 这些格式。检测项：密码明文（password、secret、token 键名对应的值直接写死的）、不安全默认值（admin/admin、root/root、localhost:3306 配合空密码）、调试开关在生产配置中打开（debug: true、log_level: trace）。每个检测项输出文件路径、行号、键名和具体值。

合规基线内置参考 OWASP 和 CIS 的规则集，规则指定键路径、期望值或禁止值模式、严重等级。用户通过 YAML 文件扩展基线，检查结果按严重等级分组。报告支持 JSON 和终端表格，JSON 里每条记录包含检查项 ID、严重等级、当前值、期望值和建议操作。

索引管理有五个状态：初始化→构建中→可用→重建→下线。状态之间有合法的转换路径，不能从"下线"直接跳到"可用"，必须先回到"初始化"。正则匹配这块用 regexp 的命名捕获组来提取结构化数据，比如从日志行里同时提取时间戳、级别和消息体。go build 能过，命令行工具能正常运行。
拆成至少三个 Go 文件：main.go 做入口和参数解析，核心处理逻辑独立一个文件，工具函数单独放。
