漏洞一百多个，先修哪个？总不能按 CVE 编号排序吧——得有一个自动化的优先级评估工具。Go 命令行实现。

评估从三个角度来。CVSS 评分是最基础的——解析 CVSS v3.1 的向量字符串，把 Attack Vector、Attack Complexity、Privileges Required 这些指标算出来得到一个 0-10 的分数。不过光看 CVSS 不够，因为一个评分 9.8 的漏洞如果项目里根本没用到受影响的代码路径，那其实风险没那么高。所以第二个角度是环境相关性——分析项目代码实际调用了受影响组件的哪些函数，判断是否触发了漏洞利用条件。没触发就降级处理。第三个角度是修复紧迫度——看有没有已知的在野利用、有没有官方补丁、补丁版本是否兼容当前项目的依赖约束。

综合这三个维度，每个漏洞给出一个最终的优先级：立即修复 / 尽快修复 / 计划修复 / 可接受风险。规则校验涉及规则组，规则组的来源和管理方式不限制。代码按三个文件组织：评分计算、环境分析、命令行入口分开。go build 能过，命令行工具能正常运行。

扫描结果输出 JSON 格式，包含每个漏洞的 CVE 编号、CVSS 评分、环境相关度百分比、综合优先级和建议操作。汇总统计包含总漏洞数、各优先级的数量分布和扫描耗时。终端表格输出用颜色区分不同优先级。
