试了好几种方案：用 OSS 的安全扫描器速度慢还报一堆误报，用商业 SaaS 又有数据外泄的顾虑。干脆 Go 自己写一个依赖漏洞检查工具，完全本地运行。

核心流程分为三步。第一步是依赖解析——解析 go.mod 拿直接依赖列表，解析 go.sum 拿完整的依赖树。版本号要兼容三种格式：标准 semver、伪版本（pseudo-version）和 commit hash，提取后统一转成可比较的格式。

第二步是 CVE 数据匹配。本地维护一份从 NVD 同步的漏洞数据（JSON 格式），按模块路径建索引加速查找。匹配时处理版本区间比较，一个 CVE 可能影响多个不连续的版本范围。匹配结果要返回 CVE 编号、CVSS 评分、影响版本区间和漏洞简述。

第三步是修复版本建议。对于每个命中的漏洞，查询该模块的版本历史，推荐最近的修复版本。如果没有官方修复版本，标注"暂无修复"并给出缓解方案建议。

导入依赖数据完成后自动更新本地索引，索引更新失败了不影响主流程，只记一条日志。代码按功能分三个文件：依赖解析和版本处理、CVE 匹配和报告生成、命令行入口。go build 能过，命令行工具能正常运行。
