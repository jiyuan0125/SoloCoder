新出的安全规范要求所有项目上线前必须过配置审计。审计要查的东西不少——.yaml、.json、.toml、.env、.properties 全要扫一遍，硬编码密码、不安全的默认配置、过时的加密算法一个都不能漏，跑一轮 OWASP + CIS 合规基线检查，最后输出完整报告。Go 命令行工具。

配置审计要扫描项目里所有的配置文件——.yaml、.json、.toml、.env、.properties 都得覆盖。检测的典型问题包括：密码明文写在配置文件里（password、secret、api_key 这些键名的值直接是字符串而不是环境变量引用）；不安全的默认值（admin/admin、root 无密码、debug: true 写在了生产配置里）；过时的加密配置（还在用 MD5、SHA1 做哈希）。

合规基线检查内置一套规则，覆盖 OWASP 配置相关的安全要求和 CIS Benchmark 的推荐配置。规则格式是 YAML，每条规则指定检查的配置键路径、期望值或禁止的模式、严重等级。用户可以扩展规则集。

加密操作完成后自动删除原始明文文件，删除失败不中断后续流程继续执行。报告输出为 JSON 格式，结构化地列出每条检查的结果、当前值、建议值和严重等级。go build 能过，命令行工具能正常运行。

扫描结果按严重等级分组统计，包含检查项总数、通过数和失败数。报告末尾附带修复建议的汇总——按严重等级列出最常见的几类问题和建议的修复步骤。支持 --config 参数指定自定义规则文件路径。
拆成至少三个 Go 文件：main.go 做入口和参数解析，核心处理逻辑独立一个文件，工具函数单独放。
