单纯想用 Go 写个有意思的东西练手，那就做一个供应链安全检查工具吧——检查依赖包的完整性和来源，挺实用的。

工具的核心分三个检查维度。完整性验证：逐个计算依赖包的校验和（SHA256），和 go.sum 或者官方注册表里的记录做比对，不匹配的标记为潜在篡改。计算过程要处理各种打包格式，go module 的 zip 包、npm 的 tarball 都要能算。来源追溯：对每个依赖记录源码仓库 URL、维护者信息、最近发布时间，识别出那些没有明确来源、维护者已弃坑、或者从非官方渠道拉取的包。供应链攻击检测：比对已知供应链攻击事件（如 xz utils 后门事件），看项目有没有命中。

索引管理有五个状态——初始化、构建中、可用、重建、下线——状态之间有合法的转换路径。校验过程分三个阶段：语法检查确认数据格式正确，语义检查验证逻辑合理性，引用检查确保所有外部引用都有效，前一个阶段通过才进入下一个。规则校验涉及规则组，规则组的来源不做限制。扫描结果输出 JSON 格式，带时间戳、扫描耗时和命中统计。go build 能过，命令行工具能正常运行。

工具不依赖第三方包，纯 Go 标准库实现。扫描大型项目时显示进度百分比。支持 --exclude-dir 排除指定目录、--timeout 设置单个依赖检查的超时时间。输出 JSON 格式，包含扫描摘要和详细问题列表。
至少拆成两个包或三个文件以上，不要单文件一把梭。
