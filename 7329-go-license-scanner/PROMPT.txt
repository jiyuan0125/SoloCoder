老板催着交安全审计报告，安全基线和依赖漏洞两块都还是空的。Go CLI 工具把这两件事一并搞定——对照 CIS Benchmark 检查系统配置，解析 go.sum/go.mod 匹配已知漏洞，输出差距分析报告。

安全基线检查涵盖系统账户、SSH 配置、文件系统、网络和防火墙这些方面。系统账户要查空密码用户、UID 0 的非 root 账户、过期的服务账户。SSH 配置检查 PermitRootLogin、PasswordAuthentication、MaxAuthTries、允许的认证方式。文件系统看关键目录权限（/etc/shadow、/root）、tmp 目录是否设置了 noexec。每个检查项对应一个 CIS 规则编号。

依赖漏洞检查解析 go.mod 提取直接依赖，解析 go.sum 提取完整依赖树。版本号和本地 CVE 数据库做匹配，匹配逻辑要处理版本区间。发现的漏洞按 CVSS 评分排序。

转换主流程中调用子转换的时候，子转换也需要读取同一份映射表，两边共享数据要注意并发安全。审计日志里不能打印密钥和密码这类敏感信息，遇到这类字段要做脱敏处理——只显示前几位加星号。输出格式支持 JSON 和终端表格，JSON 里包含每条检查的规则编号、当前值、推荐值和建议操作。go build 能过，命令行工具能正常运行。
代码要模块化：主流程、具体功能实现、辅助函数分开存放，主文件只做调度。
