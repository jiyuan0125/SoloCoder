硬编码密码和不安全默认值这种低级错误在代码 review 里最容易被忽略——因为配置文件太多，手动查一遍至少半小时。Go CLI 写个配置审计工具自动扫描所有配置文件（.yaml、.json、.toml、.env），再跑一轮合规基线检查，输出审计报告。

配置审计要覆盖 .yaml、.json、.toml、.env 等常见格式。检测项包括：密码明文（password、secret、api_key 这类键名的值直接是字符串而非环境变量引用）、不安全的默认配置（admin/admin、debug: true 在生产配置中打开、空密码）、过时的加密算法配置（MD5、SHA1、DES）。每个检测项输出文件路径、行号、键名和具体的不安全值。

合规基线内置一套规则，覆盖 OWASP 配置安全要求和 CIS Benchmark 的推荐配置。规则按严重等级分级：CRITICAL（硬编码密码、私钥泄露）、HIGH（不安全默认值、弱加密配置）、MEDIUM（缺少安全头配置）、LOW（日志级别过高）。用户可以通过 YAML 文件扩展规则集。

权限管理支持多层路径 resources/{type}/{id}/actions/{action}，可以精确到某个资源类型的某个实例的某个操作的权限控制。报告输出为 JSON 格式，包含每条检查的规则编号、当前配置值、推荐配置值和建议操作，带扫描时间戳和统计汇总。go build 能过，命令行工具能正常运行。
