那个 Python 脚本跑了三年了，没人维护，现在要加 SBOM 生成和漏洞评估的功能，改不动了。用 Go 重写一个覆盖面更广的安全审计工具。

第一个层面是 SBOM 生成——解析项目的依赖树，输出 SPDX 和 JSON 两种格式的软件物料清单。SPDX 输出包含包名、版本、许可证、下载地址、SHA256 校验和，缺失字段要在报告中标注。JSON 格式额外包含依赖层级关系和传递路径。依赖树可视化用缩进文本格式，一眼看清谁依赖了谁。

第二个层面是漏洞优先级评估——对发现的每个漏洞综合打分。CVSS 评分从向量字符串计算，环境相关性分析看项目是否实际调用了受影响的代码路径，修复紧迫度结合在野利用情况和补丁可用性。三者综合给出优先级。

数据转换需要映射模板来定义字段对应关系，模板格式不做具体限制。输入数据的格式要兼容常见的配置文件格式——JSON、YAML、TOML 都得能解析。go build 能过，命令行工具能正常运行。

扫描结果输出两种格式：JSON（供其他工具消费和集成）和终端表格（带颜色区分不同严重等级）。汇总统计包含依赖总数、发现漏洞数、各优先级的分布。依赖树可视化输出按层级缩进，直接依赖和间接依赖用不同符号标记。
代码组织要清晰：CLI 参数处理一个文件，核心业务逻辑一个文件，公共工具函数一个文件。
