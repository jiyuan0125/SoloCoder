新规要求上线前必须过 RBAC 权限审查。角色继承关系乱成一锅粥了——admin 到底继承了哪些权限、editor 和 viewer 之间有没有冲突，没人说得清。Go CLI 做一个 RBAC 权限检查工具，构建角色继承关系、检查权限冲突、输出检测报告。

角色定义支持继承——admin 继承 editor 的所有权限再加自己的，editor 继承 viewer 的权限。权限检查的时候要沿着继承链往上查找，直到找到匹配的权限或者到达链的顶端。循环继承要检测出来并报错。

权限冲突检测场景包括：同一个用户通过不同角色获得了对同一资源的矛盾权限（一个角色给了读权限，另一个给了拒绝权限）；角色的继承链上出现了重复授权；权限规则里有通配符（*）和具体权限混用导致意图不清晰。

导入角色和权限配置后自动构建索引加速后续的查询，索引更新失败只记录日志不影响主流程。令牌生命周期管理有五个状态：创建→活跃→刷新→过期→吊销，每个状态转换都有审计记录。权限检查结果输出 JSON 格式，每条包含角色名、资源路径、操作类型、授权结果和判断依据。go build 能过，命令行工具能正常运行。

角色定义支持通配符权限——比如 resources.documents.* 表示所有文档操作。继承链上的重复授权要识别并合并显示。冲突报告按严重程度排序，最严重的（显式拒绝 vs 允许）排最前面。输出终端表格和 JSON 两种格式。
