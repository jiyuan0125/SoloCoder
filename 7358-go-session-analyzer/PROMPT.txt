Token 管理一直是手动处理的——查过期时间手动调接口，吊销靠运维手动维护列表，刷新轮换的规则只有两个人知道。出了两次问题之后决定工具化。Go 命令行实现，覆盖内省（RFC 7662）、吊销列表管理和刷新 Token 轮换。

Token 内省（RFC 7662）实现标准的 introspection endpoint 调用——发送 token 和可选的 token_type_hint，返回 active、scope、client_id、username、exp、sub 这些字段。如果 token 不存在或已过期，active 返回 false。内省结果要缓存，缓存时间不超过 token 剩余有效期的 1/4。

吊销列表管理维护一个本地的已吊销 Token 列表。Token 被吊销后加入列表，内省时先查吊销列表再查授权服务器。吊销列表要持久化到文件，重启后加载恢复。列表条目有过期时间——Token 自然过期后对应条目可以清理掉，避免列表无限增长。

刷新 Token 轮换要实现每次刷新后旧 refresh_token 立即失效、颁发新的 refresh_token 的机制。如果检测到已失效的 refresh_token 被使用（说明可能被盗用），自动吊销该 refresh_token 关联的所有 token。

认证检查要查角色，角色检查也要验证认证状态——不能查着查着忘了确认 session 还有没有效。安全扫描需要扫描策略，策略怎么配不做限制。代码按三个文件组织。go build 能过，命令行工具能正常运行。
