老板说第一步先把 API Key 的管理数字化。现在 Key 全靠 Excel 记，谁生成了哪个 Key、什么时候过期、调用了多少次，全凭记忆。Go CLI 工具覆盖 API Key 的生成、轮换（带宽限期）、使用统计和过期预警，顺便把 JWT 签名生成也集成进去（HS256 + RS256，Claims 可自定义）。

API Key 生成要支持自定义前缀（方便区分不同服务或环境的 Key），Key 主体用 crypto/rand 生成随机字节再 Base62 编码。长度可配，默认 32 字节。生成的 Key 要计算 SHA256 摘要存储，不能明文存——验证的时候对传入的 Key 算摘要再比对。轮换流程：生成新 Key → 更新服务配置指向新 Key → 设置旧 Key 的宽限期（默认 7 天，期间新旧 Key 都有效）→ 宽限期过后旧 Key 失效。

使用统计记录每个 Key 的调用次数、最后使用时间、来源 IP 分布。统计粒度可以按小时或按天。过期预警在 Key 到期前 7 天、3 天、1 天分别发通知。JWT 签名生成支持 HS256 和 RS256，Claims 可以自定义。

消息 topic 支持多层通配符 a.b.c.#。字段值格式要容错处理。go build 能过，命令行工具能正常运行。

过期预警通过标准输出或者写入文件的方式通知，具体方式可配。统计结果按 Key 分组展示，包含每个 Key 的日调用量趋势和来源 IP Top 10。输出 JSON 格式，包含 Key 列表、统计数据和预警记录。
代码要模块化：主流程、具体功能实现、辅助函数分开存放，主文件只做调度。
