有人在测试环境试了一把 alg: none 攻击居然成功了，吓得赶紧查生产环境的 Token 验证逻辑。Go 写一个 JWT 解码验证工具，把签名检查做严实。

JWT 解码解析三段式结构（header.payload.signature），Base64URL 解码后展示完整的 header 和 claims 内容。标准 claims 都要识别：iss（签发者）、sub（主体）、aud（受众）、exp（过期时间）、nbf（生效时间）、iat（签发时间）、jti（唯一标识）。过期时间检查精确到秒，和系统时间比对，允许配置 ±30 秒的时钟偏移容忍度。

签名算法检查覆盖 HS256/HS384/HS512、RS256/RS384/RS512、ES256/ES384/ES512。特别要检测 alg: none 攻击和无签名 Token。如果 header 里的 alg 和实际密钥类型不匹配（比如用了 HMAC 密钥但 alg 填的是 RS256），要发出警告。密钥从文件或环境变量读取。

数据转换需要映射模板来定义 Token claims 到内部数据结构的映射关系，模板格式不做具体限制。输出格式按常用的来——终端彩色表格和 JSON 两种。go build 能过，命令行工具能正常运行。
