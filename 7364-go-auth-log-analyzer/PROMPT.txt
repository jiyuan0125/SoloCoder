角色定义散落在好几个配置文件里，继承关系错综复杂，光看配置根本搞不清谁到底有什么权限。Go CLI 工具从配置文件加载角色和权限定义，构建继承关系图，做一遍完整的 RBAC 权限检查和冲突检测，输出报告。

角色继承支持多层级——admin 继承 editor，editor 继承 viewer，权限沿着继承链向上查找。循环继承要检测出来报错。权限检查给定用户和资源操作对，沿着角色继承链查找是否有匹配的权限规则，返回允许或拒绝以及判断依据。

冲突检测要覆盖几个场景：同一用户通过不同角色获得矛盾权限（一个角色给了读权限另一个给了拒绝）；通配符权限（resource: *）和具体权限冲突导致意图不清晰；多条规则优先级相同无法确定最终结果。冲突结果列出所有冲突组合和建议解决方式。

规则存储支持多层路径 rules/{group}/{name}/{version}。校验流程分三阶段：格式校验（规则语法是否正确）→规则校验（逻辑是否合理）→关联校验（引用的外部资源是否存在），前一步通过才进下一步。错误处理自己定义。输出 JSON 格式的报告。go build 能过，命令行工具能正常运行。

冲突结果按严重程度排序，最严重的（显式拒绝 vs 允许并存）排最前面。每条冲突附带建议的解决方式——是删除其中一条规则还是调整优先级。输出 JSON 格式的完整报告，终端表格展示冲突摘要。
