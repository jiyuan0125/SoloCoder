审计发现有人拿着过期的 JWT 在调接口——服务端没做 Token 过期检查。趁修这个 bug，把 RBAC 权限验证也一起做了。Go 写一个 JWT 解码验证工具，RBAC 集成进去。

JWT 解码解析三段式结构，Base64URL 解码展示完整 header 和 claims。标准 claims 都识别：iss、sub、aud、exp、nbf、iat、jti。过期检查精确到秒，允许 ±30 秒时钟偏移容忍。签名算法检查覆盖 HS/RS/ES 三个系列，检测 alg: none 攻击。密钥从文件或环境变量读取。

RBAC 权限检查基于 JWT claims 里的 roles 字段，验证用户是否拥有指定角色。角色支持继承——admin 隐含 editor 的全部权限。验证时沿着继承链查找。

处理消息时触发关联操作，关联操作也访问同一个队列状态，共享数据要做并发保护。代码按三个文件组织：JWT 解码和签名验证逻辑、RBAC 权限检查逻辑、命令行入口和参数解析。输出支持终端表格和 JSON 格式，JSON 里包含 Token 解码结果、签名验证状态和权限检查结论。go build 能过，命令行工具能正常运行。

角色继承支持多层级——admin 自动包含 editor 的全部权限，editor 包含 viewer 的权限。循环继承检测出来立即报错。JSON 输出包含 Token 完整解码结果、签名验证状态和权限检查的最终结论。
