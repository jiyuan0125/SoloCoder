移动端团队那边要求 Token 必须用 RS256 签名，说 HS256 的共享密钥在客户端不安全。后端原来只支持 HS256，改起来牵一发动全身。干脆 Go 从头写一个独立的签名工具，三种算法族全覆盖，Claims 完全自定义。

HMAC 系列（HS256/HS384/HS512）用共享密钥，生成时检查密钥长度是否满足安全要求。RSA 系列（RS256/RS384/RS512）支持 PEM 编码的 PKCS1 和 PKCS8 私钥格式。ECDSA 系列（ES256/ES384/ES512）分别对应 P-256、P-384、P-521 曲线。算法选择通过 --algorithm 参数指定，密钥通过 --key-file 或环境变量传入。

Claims 通过 JSON 文件或命令行 --claim key=value 传入，工具自动添加 iat 和 jti。exp 和 nbf 可配置。Token 输出到标准输出或指定文件。

证书有完整状态流转：申请→签发→生效→过期→续签。每个状态转换都有记录，状态之间有合法转换路径。正则匹配用 regexp 的命名捕获组提取结构化数据。输出 JSON 格式。go build 能过，命令行工具能正常运行。

证书状态转换有合法路径约束——不能从"过期"直接跳到"签发"，必须走"续签"流程。正则命名捕获组用在日志解析中提取结构化字段。输出 JSON 格式，包含生成的 Token、header 和 claims 的完整内容。
项目结构要分模块：主入口、核心处理逻辑、工具函数分文件组织，方便测试和维护。
