合规审计要求对所有角色定义做一遍权限冲突检测。角色继承层级有四层深，手动查根本查不过来——admin 继承 editor，editor 继承 viewer，viewer 可能还继承了什么别的角色，循环引用和矛盾权限藏在深处很难发现。Go CLI 工具加载角色和权限定义，构建继承关系图，检查冲突输出报告。

角色继承支持多层级——admin 继承 editor，editor 继承 viewer。权限沿继承链查找，循环继承检测报错。权限检查给定用户和资源操作，返回允许或拒绝及判断依据。

冲突检测场景：同一用户通过不同角色获得矛盾权限（一个允许一个拒绝）；通配符和精确规则冲突；优先级相同无法确定。冲突结果列出所有组合和建议。校验完成后自动生成报告，报告模板不存在就跳过生成步骤不报错。规则修改后引用该规则的所有校验结果要重新计算。输出 JSON 格式。go build 能过，命令行工具能正常运行。

角色定义支持通配符权限——resources.documents.* 表示所有文档类操作。继承链上的重复授权识别并合并。冲突报告按严重程度排序，最严重的排前面并附带建议解决方式。校验完成后自动生成报告，报告模板不存在就跳过。规则修改后所有引用该规则的校验结果自动重新计算。输出 JSON 格式。

校验流程分三阶段：格式校验确认规则语法正确→规则校验验证逻辑合理性→关联校验确保外部引用存在，前一步通过才进下一步。冲突结果附带建议解决方式。输出 JSON 格式的完整报告。
拆成至少三个 Go 文件：main.go 做入口和参数解析，核心处理逻辑独立一个文件，工具函数单独放。
