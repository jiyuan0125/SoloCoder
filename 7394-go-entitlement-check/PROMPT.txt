清理权限系统的时候发现 admin 角色同时继承了两个互相矛盾的权限组——一个给了全部读权限，另一个显式拒绝了部分资源的读操作。这种问题藏在继承链深处，不工具化根本发现不了。Go CLI 做一个 RBAC 工具，加载角色定义构建继承关系图，做权限检查和冲突检测。

角色继承支持多层级——admin 继承 editor，editor 继承 viewer，权限沿继承链向上查找直到匹配或到达顶端。循环继承检测出来立即报错。权限检查给定用户和资源操作对，沿角色继承链查找匹配的权限规则，返回允许或拒绝及判断依据。

冲突检测覆盖：同一用户通过不同角色获得矛盾权限（允许 vs 拒绝）；通配符和精确规则冲突导致意图不清；优先级相同时结果不确定。冲突结果列出所有冲突对和建议解决方式。

密钥生命周期有五个状态：生成→激活→轮换→归档→销毁，每个转换都有审计记录。消息 topic 支持多层通配符 a.b.c.# 的匹配模式。扫描多个目录用 goroutine 并行处理。输出 JSON 格式报告。go build 能过，命令行工具能正常运行。

角色定义支持通配符权限——resources.documents.* 表示所有文档操作。继承链上重复授权识别并合并显示。冲突结果按严重程度排序，附带建议解决方式。密钥轮换后旧密钥加密的数据仍可解密。消息 topic 多层通配符支持深层路由。goroutine 并行扫描多目录。输出 JSON 格式报告。
拆成至少三个 Go 文件：main.go 做入口和参数解析，核心处理逻辑独立一个文件，工具函数单独放。
