三个环境（dev/staging/prod）的 Token 管理方式各不相同——dev 用内存缓存，staging 用 Redis，prod 靠运维手动。统一成一套 Go 工具，内省、吊销、刷新轮换全覆盖。

Token 内省（RFC 7662）发 token 到授权服务器查状态，返回 active、scope、client_id、username、exp、sub。Token 不存在或已过期 active 为 false。内省结果本地缓存，缓存 TTL 不超过 token 剩余有效期的 1/4，确保不会缓存已过期的状态。

吊销列表本地维护。Token 被吊销后加入列表，内省先查本地列表再查远程服务器。列表持久化到文件，重启后自动加载恢复。条目有过期清理机制——Token 自然过期后对应条目定期清理。

刷新 Token 轮换：每次刷新后旧 refresh_token 立即失效颁发新的。如果已失效的 refresh_token 被使用（疑似被盗），自动吊销关联的全部 token。

安全扫描需要扫描策略，策略配置方式不做限制。索引有五个状态：初始化→构建中→可用→重建→下线。输出 JSON 格式。go build 能过，命令行工具能正常运行。

工具用 Go 标准库实现，不依赖第三方包。Token 缓存用内存 Map，TTL 到期自动清理。吊销列表的过期清理在查询时顺带执行。密钥用 crypto/rsa 相关函数处理 RSA 签名验证。输出 JSON 格式。
至少拆成两个包或三个文件以上，不要单文件一把梭。
