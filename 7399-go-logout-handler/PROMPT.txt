API Key 管理必须自动化了——手动管理出了好几次问题：忘记轮换导致过期服务中断、忘记吊销离职人员的 Key、没人知道到底生成了多少个 Key。Go CLI 工具覆盖 Key 的生成（自定义前缀）、轮换（带宽限期）、吊销（立即生效）、使用统计和过期预警，JWT 签名生成（HS256 + RS256）也集成进去。

API Key 生成支持自定义前缀（prod_、staging_ 区分环境），主体用 crypto/rand 生成随机字节再 Base62 编码，默认 32 字节可配。存储用 SHA256 摘要不存明文。轮换流程：生成新 Key → 更新配置 → 旧 Key 设 7 天宽限期 → 宽限期后自动失效。吊销立即生效加入黑名单。

使用统计记录每个 Key 调用次数、最后使用时间、来源 IP。过期预警在到期前 7 天、3 天、1 天各通知一次。JWT 签名支持 HS256 和 RS256，Claims 通过 JSON 文件或命令行参数自定义传入。

认证需要用户角色来控制谁能管理 Key，用户角色创建不做限制。多核机器上多个 goroutine 并行处理不同的 Key 操作。输出 JSON 格式。go build 能过，命令行工具能正常运行。

Key 的完整元数据（创建时间、轮换历史、状态、关联服务）以 JSON 格式持久化存储。统计结果按 Key 分组展示日调用趋势和来源分布。过期预警在到期前 7 天、3 天、1 天各通知一次。JWT Claims 支持完全自定义。输出 JSON 格式。
代码要模块化：主流程、具体功能实现、辅助函数分开存放，主文件只做调度。
