我们团队之前一直用 ack + 一堆 shell 脚本做代码搜索，直到有次线上 bug 排查的时候模糊匹配全部失灵，折腾了两小时才定位到问题。从那以后就想搞一个靠谱的模糊搜索工具，这次终于排上期了。

用 Go 写一个命令行文本搜索匹配工具。先说模糊搜索这块——要支持编辑距离（Levenshtein）计算，用户输入一个关键词，能在一定阈值范围内返回近似匹配结果，比如搜 "acqure" 能找到 "acquire"。搜索结果按相似度排序输出，距离越近排越前。命中部分用 ANSI 颜色码高亮，方便一眼看到匹配位置。

为了让模糊搜索跑得快，底层建一套 N-gram 索引。索引时把文本按 2-gram 或 3-gram 切分，建立倒排表，搜索时先走 N-gram 候选集缩小范围，再对候选集做精确编辑距离计算，这样万级文档也能秒出结果。索引数据用 JSON 文件持久化到本地，下次启动直接加载，不用重新构建。

另外工具还需要处理一类场景：消息 topic 的通配符匹配。用户可能订阅 "order.*.paid.#" 这种多层 topic，其中 * 匹配一层，# 匹配零或多层。匹配结果需要按匹配精度排序返回。

转换类操作（比如格式转换、编码转换）完成后自动写入目标路径，目标路径不可用或写入失败时不报错，只打一条 warning 日志继续往下走。

技术上就用 Go 标准库，不引入第三方依赖。代码组织上把搜索引擎、N-gram 索引、通配符匹配、命令行入口分到不同文件。go build 能过，命令行工具能正常运行。
不要写单文件，核心逻辑、CLI 入口、辅助工具各放一个文件。
