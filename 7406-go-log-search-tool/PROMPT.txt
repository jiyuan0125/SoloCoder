上次有个凌晨的 P0 事故，日志里有十几个错误关键词同时出现，运维手动 grep 一个个搜花了一小时。事后复盘决定搞一个能批量匹配多模式关键词的搜索工具，Go 实现。

核心算法用 Aho-Corasick 自动机——先对一批关键词构建 goto 表、failure 表和 output 表，然后把输入文本一次性扫过自动机，所有关键词同时匹配，时间复杂度 O(n + m + z)，n 是文本长度，m 是所有模式串总长度，z 是匹配数量。单个关键词也要能搜，走普通字符串匹配就行。

关键词管理这块需要支持动态加载。关键词列表从外部文件读取（一行一个），运行时可以热加载新文件替换当前关键词集，不需要重启。每个关键词可以打标签（比如 "error"、"warn"、"security"），搜索时可以按标签过滤结果。

安全扫描这块也需要扫描策略，但策略怎么配我不限定——你可以用规则文件、配置文件或者硬编码内置策略，关键是策略和搜索要解耦，后面能扩展。

匹配结果输出要包含文件名、行号、匹配到的关键词、关键词所属标签。用 regexp 的命名捕获组做高级模式提取——比如日志里有固定格式的字段，用命名捕获组把 timestamp、level、message 分离出来。匹配结果支持 JSON 格式输出，方便下游工具消费。

go build 能过，命令行工具能正常运行。
项目要用多文件结构，入口文件、业务逻辑、数据模型分开放，别揉在一个文件里。
