之前用 shell 脚本写搜索报告，每次输出格式都不一样——有时是 CSV，有时是纯文本，有时是 JSON。代码审查的时候根本没法对比。这回用 Go 重写一个正经的代码搜索工具，带聚合统计能力。

搜索结果聚合统计是重点。用户在一个代码仓库里搜关键词，工具不光返回匹配行，还要给出聚合视图：按文件类型分布（.go 有多少命中、.java 有多少命中）、按目录深度分布、按修改时间区间分布。这些统计数据按 JSON 结构输出到文件，结构大概是 { "total_matches": N, "by_ext": {".go": N, ...}, "by_dir": {...}, "by_time": {...} }。

分面统计——用户可以指定分面维度，比如按文件大小分桶（<1KB / 1-10KB / 10-100KB / >100KB），或者按最后修改时间分桶（最近7天 / 30天 / 更早）。每个分面桶内统计匹配数量，方便快速定位问题集中区域。

结果排序支持相关度排序（TF-IDF 打分）和时间排序（按文件修改时间）。默认用相关度排序，用户通过 -sort time 切换。

权限这块有个细节——权限变更后（比如某个用户从 admin 降级为 viewer），用户会话里缓存的权限信息要同步更新。搜索请求进来时先检查会话权限是否过期，过期了重新从权限服务拉取。

输出格式支持 JSON、CSV 和表格三种，用户通过 -format 参数选择。默认表格格式，带颜色高亮。

go build 能过，命令行工具能正常运行。
代码组织要清晰：CLI 参数处理一个文件，核心业务逻辑一个文件，公共工具函数一个文件。
