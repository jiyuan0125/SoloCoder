隔壁组刚做完一个配置管理工具，正好我们这边搜索能力也缺，顺手一起补了。Go 实现。

搜索结果聚合统计——不光返回匹配行，还要按维度聚合：按文件聚合（每个文件多少命中）、按模式串聚合（哪个关键词命中最多）、按时间段聚合（按文件修改时间分桶）。聚合结果以 JSON 格式输出，结构清晰方便下游消费。

分面搜索——用户可以指定分面维度。比如搜索 "error" 关键词的同时，按日志级别分面（ERROR/WARN/INFO 各多少），或者按服务名分面。分面统计结果是 { "facets": { "level": {"ERROR": 120, "WARN": 45}, "service": {"order": 80, "pay": 30} } } 这种格式。

搜索索引持久化——Aho-Corasick 自动机构建完之后序列化到 JSON 文件，下次启动直接反序列化加载，省去构建时间。索引文件记录版本号和构建时间，版本不匹配时自动重建。

令牌状态管理——令牌有创建→活跃→刷新→过期→吊销五种状态。状态流转单向不可逆。字段映射变更后，已有的转换任务结果要标记为 "过时"，提醒用户重新执行。

日志里绝对不能打印密钥、密码、token 这类敏感信息——打印前做脱敏处理（比如只显示前 4 位后 4 位，中间用 * 替换）。

go build 能过，命令行工具能正常运行。
代码组织要清晰：CLI 参数处理一个文件，核心业务逻辑一个文件，公共工具函数一个文件。
