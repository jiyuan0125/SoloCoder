公司内部知识库有 8000 多篇文档，之前靠目录树和文件名猜内容，效率低得离谱。上周老板让加搜索功能，要求能按关键词组合查询——"分布式 AND（限流 NOT 令牌桶）" 这种。Go 命令行工具。

倒排索引构建——输入一批文档，对每个文档做文本分析（分词、去停用词、归一化），然后把每个词项映射到包含它的文档列表。索引存内存，同时持久化到 JSON 文件。启动时检查 JSON 文件，存在就加载，不存在就提示用户先构建索引。

增量更新——用户可以追加新文档到现有索引，不需要全量重建。追加时解析新文档，把词项和文档 ID 合并到倒排表里。如果文档 ID 已存在，先删旧的再插新的。

布尔查询——支持 AND、OR、NOT 操作符，可以括号嵌套。解析查询字符串，构建查询树，对每个节点执行对应的集合操作（交集/并集/差集）。查询结果返回匹配的文档列表，按相关度排序（简单用词频 TF 做排序就行）。

认证这块需要用户角色——不同角色有不同的搜索权限。角色怎么创建不在这里限定，你可以用配置文件或内存数据结构，关键是搜索请求进来时先校验角色权限。管理员可以搜所有索引，普通用户只能搜自己有权限的索引分区。

go build 能过，命令行工具能正常运行。
代码分文件组织，解析器、处理器、输出器分开，main.go 只做参数解析和流程串联。
