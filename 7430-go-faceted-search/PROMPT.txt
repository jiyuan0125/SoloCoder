下周要做演示，搜索功能得先有个能跑的版本。Go CLI，支持索引持久化和分面搜索。

索引持久化——搜索索引数据（倒排表、文档元数据）序列化到 JSON 文件。JSON 文件里包含版本号和构建时间戳。启动时检查索引文件版本，版本不匹配自动触发全量重建。索引文件路径通过 -index-dir 参数指定，默认 .index/。

索引重建——全量扫描文档，重新建倒排表，写 JSON。重建过程中旧索引可用于查询。重建完成后原子替换——先写临时文件，写完后 rename 覆盖旧文件。

索引合并——两个索引文件可以合并，合并时按文档 ID 去重，保留最新版本。合并操作可以指定 -merge 命令触发。

密钥路径支持多层结构 keys/{algorithm}/{key_id}/versions/{ver}，比如 keys/aes/master-key/versions/1。每个版本对应一个密钥实例，查找时默认返回最新激活版本。

扫描规则更新后，历史扫描结果的严重级别要重新评估——因为新规则可能把之前标记为 "中" 的问题升级为 "高"。重新评估在后台异步执行，不阻塞正常搜索。

代码组织：搜索引擎核心、索引 IO、命令行入口分不同文件。

go build 能过，命令行工具能正常运行。
代码按模块拆分，不要把所有逻辑写在一个文件里。解析、转换、输出分开组织。
