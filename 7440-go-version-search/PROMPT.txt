文档系统上线三年了，索引全靠每次全量重建，文档数到了 5 万以后重建一次要 40 分钟。上周磁盘故障导致索引文件损坏，重建期间搜索完全不可用，被客户投诉了。Go 写一个带增量能力的索引管理工具。

索引持久化——搜索索引数据（倒排表、文档列表、统计信息）全部序列化到 JSON 文件持久化存储。文件包含版本号和构建时间戳。启动时校验版本号，版本不匹配自动触发全量重建。索引文件路径通过 -index-dir 参数指定，默认当前目录 .index/。

索引重建——全量扫描文档集，重新建倒排表，写入新 JSON 文件。重建过程用临时文件，写完后 rename 原子替换旧文件，保证重建期间旧索引仍可用于查询。用户通过 -rebuild 命令手动触发重建。

索引合并——两个索引文件可以合并，适用于多批次文档场景。合并时按文档 ID 去重，相同 ID 保留最新版本。合并完成后生成新的索引文件。

校验关联逻辑——校验时需要查关联表的规则，查关联表时也要校验触发方状态（触发方已禁用的规则不参与校验）。用版本号加缓存避免循环查询：首次查询后缓存结果，同一请求内复用缓存。

搜索结果输出支持 JSON 和纯文本两种格式。JSON 包含文件名、行号、匹配内容、相关度分数。

go build 能过，命令行工具能正常运行。
代码按模块拆分，不要把所有逻辑写在一个文件里。解析、转换、输出分开组织。
