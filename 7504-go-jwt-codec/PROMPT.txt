做JWT调试的时候老得手动去 jwt.io 粘贴解码，碰到大批量token更痛苦——一个一个粘效率太低了。写个命令行工具把 JWT 的三个部分拆开，header 和 payload 解码成可读 JSON，签名部分做格式化展示。

工具叫 `jwt-tool`，两个子命令：`decode` 和 `encode`。`jwt-tool decode` 接收一个或多个 JWT 字符串（通过 `-s` 参数或从文件 `--input` 读取），逐个解析。每个 token 的 header、payload 用 `encoding/json` 的 Indented 输出格式化，签名部分转成 hex 字符串展示。输出格式用颜色区分——header 蓝色、payload 绿色、签名黄色，管道或重定向时自动关闭颜色。

`jwt-tool encode` 接收一个 JSON 文件作为 payload，另一个可选的 JSON 文件作为 header，加上 `--secret` 指定密钥，生成 HS256 签名的 JWT。暂不支持 RS256，保持简单。

支持 `--batch` 批量模式——指定一个目录，遍历所有 `.jwt` 后缀的文件逐个解码。每个文件独立处理，某个文件解析失败（格式不对、base64 解码出错、不是三段结构）不影响其他文件，最后汇总报告：成功几个、失败几个、失败列表。

关联数据这块：decode 结果里的 `exp`、`iat`、`nbf` 这些时间戳字段，如果存在的话额外输出人类可读的时间格式，方便一眼看出是不是过期了。输出保持一致的缩进和换行，空文件给提示跳过，二进制文件检测到前几个字节不是 base64 字符就跳过。

Go 标准库，`go build` 通过就行。
拆成至少三个 Go 文件：main.go 做入口和参数解析，核心处理逻辑独立一个文件，工具函数单独放。
