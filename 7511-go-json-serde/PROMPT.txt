API 网关那边的日志都是大 JSON 文件，几十 MB 甚至上百 MB 一个。之前用 jq 处理，碰到特别大的文件直接 OOM。核心问题是不能把整个文件加载到内存里——得流式处理。

写个 `json-tool`，支持管道模式和重定向。工具分三个子命令：`json-tool format`（格式化美化）、`json-tool minify`（压缩去空白）、`json-tool query`（用简单路径表达式提取字段，比如 `.users[0].name`）。

大文件分块处理是关键。用 `encoding/json` 的 `json.Decoder`，带 `Token()` 方法流式读取，内存峰值控制在 100MB 以内。碰到大数组就逐元素处理，碰到大对象逐键值对处理。终端连着的时候显示进度条——已处理字节数/总字节数，百分比和预估剩余时间。管道模式下进度信息输出到 stderr，不影响 stdout 的正常数据流。

处理中断后可以从断点继续——如果输入是文件（不是管道），记录已处理的位置到临时文件，下次 `--resume` 时跳过已处理部分。如果是管道输入就没法 resume 了，给个提示。

输出保持合法 JSON 格式，`format` 默认两空格缩进，`--indent` 可调。`minify` 去掉所有多余空白但保持 UTF-8 编码正确。

Go 标准库，`encoding/json` 和 `os`。纯 CLI，`go build`。
不要写单文件，核心逻辑、CLI 入口、辅助工具各放一个文件。
