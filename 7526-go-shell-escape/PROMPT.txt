Shell 转义看着简单——不就是加个反斜杠嘛，但实际场景比想象中复杂得多。单引号里不能有单引号，双引号里的 `$` 和反引号要转义，ANSI-C quoting 的 `$'...'` 又是另一套规则。脚本里拼命令的时候，一个转义没处理好就命令注入了。

上个月出了个安全事故——运维脚本里变量没转义，用户输入里带了 `;rm -rf` 直接执行了。痛定思痛，写个 `shell-escape` 工具，保证输出的字符串在 shell 里是安全的。

工具两个子命令：`shell-escape escape` 把输入字符串转义成 shell 安全的格式，`shell-escape unescape` 反过来。支持三种转义风格通过 `--style` 参数选择：`single-quote`（用单引号包裹，内部的引号用 `'\''` 转义）、`double-quote`（双引号包裹，内部的特殊字符加反斜杠）、`dollar-single`（`$'...'` 格式，支持 `\n`、`\t` 等 C 转义）。

并发处理多个文件——`--batch` 指定目录，goroutine 并发处理，每个文件的转义结果写入对应输出文件。处理一个记录时自动更新关联统计：已处理文件数、成功数、失败数、跳过数。

校验模式 `--verify`：转义后的字符串用 `bash -c echo ...` 实际执行一下，验证输出和原始输入一致。错误信息包含文件名、行号、具体哪个字符的转义出了问题。

Go 标准库，命令行工具。`go build`。
项目要用多文件结构，入口文件、业务逻辑、数据模型分开放，别揉在一个文件里。
