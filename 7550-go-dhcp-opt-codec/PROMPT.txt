网络排查 DHCP 分配问题，`tcpdump` 抓到的报文里 Option 字段一堆十六进制，肉眼根本看不出哪个是租期、哪个是 DNS 服务器、哪个是子网掩码。每种 Option 的编解码格式还不一样——单字节、IP 列表、字符串、嵌套 TLV，不翻 RFC 根本解不出来。

写个 `dhcp-tool`，子命令 `decode` 和 `encode`。`dhcp-tool decode` 读 DHCP 报文的原始字节（从文件或 stdin），解析 Message Type、Transaction ID、各个 Option 字段。每个 Option 输出编号、名称（人类可读的）、长度和解析后的值。常见的 Option 直接解码展示（比如 Option 53 是 DHCP 消息类型、Option 51 是租期秒数、Option 54 是服务器 IP），不认识的 Option 输出原始十六进制。

`dhcp-tool encode` 反过来——从 JSON 描述生成 DHCP 报文。管道模式下大文件分块处理：按报文边界分割（DHCP 报文有固定头部），每次只保留一个报文的解析状态，内存占用不超过 100MB。

进度显示：终端连着时输出已解析的报文数量。达到某个阈值（比如连续 10 个报文的 Magic Cookie 不对）自动触发告警——stderr 输出醒目警告，可能是抓包格式不对。

中断恢复：文件输入时记录偏移，`--resume` 从断点继续。

Go 标准库实现。`go build`。
