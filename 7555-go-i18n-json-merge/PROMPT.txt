多语言项目里的 JSON 翻译文件散落在各个子项目目录里——`en.json`、`zh-CN.json`、`ja.json`，合并的时候头都大了。键名层级不统一，有的用点分隔 `user.profile.name`，有的用嵌套对象。而且翻译条目是有生命周期的——新增的还没翻译、修改过的需要重新审校、废弃的应该清理掉。

`i18n-merge-tool`，子命令 `merge`、`diff`、`export`。`i18n-merge-tool merge` 合并多个 JSON 翻译文件：`--sources` 指定多个文件路径或目录，`--output` 指定输出文件。合并策略：新增的键加 `+` 标记，修改的（值和上次不同）加 `~` 标记，只在部分语言中存在的键列出缺失的语言。`i18n-merge-tool diff` 比较两组翻译文件的差异——哪些键新增了、哪些删了、哪些值变了。`i18n-merge-tool export` 导出为标准格式——CSV 表格（列：键名、各语言翻译值、状态标记），方便导入 Excel 或翻译管理平台。

键名结构统一化：`--flatten` 把嵌套对象展平成点分隔的键，`--nest` 反过来。空字符串的翻译值标记为"未翻译"。

Go 标准库，`go build` 通过。
