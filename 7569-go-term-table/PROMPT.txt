日志分析面板里的表格，中文一列和英文一列混在一起，宽度全乱了——因为按字符数算宽度，中文字符实际占两列。终端表格渲染看着简单，Unicode 相关的处理才是深坑。组合字符占零列，emoji 更是各种宽度都有，不把这些搞清楚表格永远对不齐。更新配置——比如改了列宽限制——后缓存要刷新。

`term-table`，子命令 `render`、`align`、`export`。`term-table render` 读 TSV/CSV 数据，渲染成终端对齐的表格。每列宽度自适应：遍历所有行的该列内容，计算最大显示宽度（不是字节宽度，是终端显示宽度），加适当的 padding。表头用粗体或下划线区分。`term-table align` 只做对齐检查——读已有表格文本，验证列对齐是否正确。`term-table export` 把表格数据导出为 Markdown 或 HTML 格式。

Unicode 规范化：表格内容中的文本可能用 NFC 或 NFD 编码，`café` 和 `café`（组合字符版本）宽度不同。工具先统一规范化再计算宽度。NFC/NFD/NFKC/NFKD 四种形式都支持。两个视觉上一样的字符如果宽度计算结果不同，要警告。

Go 标准库实现，`unicode/norm` 和 `unicode/utf8`。`go build`。
代码要模块化：主流程、具体功能实现、辅助函数分开存放，主文件只做调度。
