上个月项目经理对着一张混乱的 Excel 表发火——五十多个任务挤在一起，谁阻塞谁都看不清，拖了整个迭代。我们决定做一个轻量的 CLI 看板工具，直接在终端里管任务，不用再打开表格软件。

这是个命令行程序，所有数据保存在当前目录的 JSON 文件里。任务有三种状态：todo、doing、done。移动到 done 之后自动归档，归档就是把任务从活跃列表移到单独的 archive.json，主列表里不再显示。

每个任务创建时需要指定标题，可选填优先级（high/medium/low，默认 medium）和负责人。任务 ID 用自增整数。列出任务时默认只显示未归档的，加 --all 才包含归档数据。

重点来了——任务之间有依赖关系。创建任务时用 --depends-on 3,7 指定前置任务，多个前置用逗号分隔。当某个任务的前置任务全部处于 done 状态时，这个任务才可以被移动到 doing。如果前置任务还有 todo 或 doing 的，尝试 move 的时候要报错，提示哪些前置还没完成。删除任务前也要检查有没有其他任务依赖它，有的话拒绝删除并给出提示。

CSV 导入这块，支持 `import <file.csv>` 命令。CSV 格式是 title,priority,assignee,depends_on。depends_on 列填前置任务的 ID，用分号分隔。导入时如果引用的依赖 ID 不存在，跳过这条并打印警告，不要整个导入失败。导入完成后显示成功几条、跳过几条。

命令列表大概这些：add、list、move <id> <status>、archive（归档所有 done 任务）、import <file>、delete <id>、show <id>（显示详情和依赖链）。list 支持 --status 过滤和 --assignee 过滤。

还有一个细节——任务标题不能重复，创建时检查一下。数据持久化方面，每次操作完立刻写文件，不搞缓存，这样就算程序崩了数据也不会丢。Go 标准库实现，不引入第三方框架。go build 能编译就行。
