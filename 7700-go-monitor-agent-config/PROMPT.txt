生产环境的 Prometheus agent 采集间隔从 15s 改成了 5s，改完 YAML 推上去——结果格式写错了一个缩进，agent 起不来，监控断了二十分钟。五个环境五套 agent 配置，全靠手动编辑 YAML，改错无法回滚。

MonitorEnv 实体有名称（小写字母+数字+连字符，2-32 字符）、创建时间、agent 配置列表。`env create <name>` 初始化独立目录，同名已存在则报错。`env delete <name>` 删除前确认目录存在。`env list` 显示所有环境名称和创建时间。

AgentConfig 实体有名称、采集间隔（秒，1-3600）、日志级别（debug/info/warn/error）、目标地址（host:port）、超时时间（毫秒，100-30000）。`agent add <env> <agent-name>` 添加 agent 配置，所有配置项有合理默认值。`agent set <env> <agent-name> <key>=<value>` 修改配置，key 不在允许范围或 value 格式不对则报错。`agent show <env> <agent-name>` 查看完整配置。

环境完全隔离——每个环境的配置和 agent 列表存在各自目录下，操作必须指定环境名。`env export <name>` 打包为 .tar.gz，`env import <file>` 导入（冲突时自动加后缀 _1）。每次修改立刻写盘，JSON 格式存储。

- `env create <name>` / `env delete <name>` / `env list`
- `agent add <env> <name>` / `agent set <env> <name> <key>=<value>`
- `agent show <env> <name>` / `agent list <env>` / `agent remove <env> <name>`
- `env export <name>` / `env import <file>`

Go 标准库实现，go build 通过。
代码按模块拆分，不要把所有逻辑写在一个文件里。解析、转换、输出分开组织。
