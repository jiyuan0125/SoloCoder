笔记库存了 300 多篇 Markdown，每次找东西只能 grep 文件名。明明记得写过一篇 goroutine 泄漏排查的文章，搜 "goroutine" 搜不到——因为标题写的是"内存问题定位"，正文里只提了一次 goroutine。靠文件名搜索根本不够用，得有内容级别的全文检索。

ft-index 纯 Go 标准库，`go build -o ft-index ./cmd/ft-index` 直接编译。

索引构建流程：扫描指定目录下所有 `.md` 文件，分词后建立倒排索引。分词策略是对中文按字符切分，英文按空格和标点。索引数据结构是 `map[string][]Posting`，Posting 包含文件路径、位置偏移、上下文片段。索引序列化成 JSON 存到 `.ft-index/` 目录下，文件修改时间作为增量更新的依据——只重新索引有变化的文件。

搜索支持两种模式：简单模式输入关键词空格分隔，全部匹配才算命中；高级模式支持引号精确匹配和 `-` 排除。搜索结果按 TF-IDF 排序，每条结果高亮匹配词并用 `...` 截取上下文。属性变更影响计算——比如笔记标题改了，索引自动更新，相关搜索结果的排序也跟着变。

笔记模型：每条有标题、正文、标签数组、分类、创建和修改时间。数据存本地 JSON 文件，目录结构 `~/.ft-index/notes/<id>.json`。子命令包括 `index` 建索引、`search` 搜索、`tags` 按标签筛选、`rebuild` 全量重建。索引过程并发但搜索串行，保证结果一致性。`go test ./...` 跑单测。
拆成至少三个 Go 文件：main.go 做入口和参数解析，核心处理逻辑独立一个文件，工具函数单独放。
