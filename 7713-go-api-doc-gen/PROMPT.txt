API 文档和代码不同步是老问题了——接口改了文档没更新，下游同事对着旧文档调半天调不通。与其手动维护文档，不如从代码注释直接生成，保证源码即文档。

api-doc-gen 是个 CLI 工具，Go 标准库实现，`go build -o api-doc-gen ./cmd/api-doc-gen` 编译。

解析策略：扫描 Go 源码文件，提取 handler 函数上方的结构化注释。支持多种注释格式——`// @API GET /users` 风格、`// API: POST /users` 风格、以及标准 godoc 格式。每个 API 条目解析出 HTTP 方法、路径、请求参数描述、响应格式、状态码说明。解析失败不影响其他条目，错误信息记录到 stderr。

写入数据后自动触发校验——校验也需要访问同一批 API 数据。校验内容：路径格式规范性（是否以 `/` 开头、有无双斜杠）、参数名是否重复、HTTP 方法是否合法。校验结果分 error 和 warning 两级。

输出为 Markdown 格式，按路径前缀分组。每个 API 一个小节，包含方法、路径、参数表格、响应示例。代码变更时，工具对比新旧解析结果，标记需要更新的文档段落用 `<!-- UPDATE NEEDED -->` 注释包裹。子命令：`gen ./src` 生成文档，`diff` 对比变更，`validate` 只跑校验不生成。处理 Markdown 文件输出到 stdout 或 `--output` 指定路径。`go test ./...` 跑测试。
