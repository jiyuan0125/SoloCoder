团队有写作风格指南，但没人真的逐条对照——文档写完就提交了，风格一致性全靠自觉。需要个工具把风格规则自动化，写完文档跑一下就知道哪里不合规。

style-guide-check 用 Go 标准库实现，`go build -o style-guide-check ./cmd/style-guide-check` 编译。

操作前需要先有基础数据——即风格指南规则文件 `.style-guide.json`。没有这个文件就生成默认模板让用户修改。规则分几大类：命名规范（文件名用 kebab-case 还是 snake_case）、标题风格（每个首字母大写还是只有第一个）、代码块要求（必须有语言标注、注释用中文还是英文）、段落限制（最大长度、最小长度）、术语统一（"服务器"还是"Server"，全局只能选一种）。

处理 Markdown 文件时逐段落逐行检查。每个违规项记录规则 ID、位置、实际值、期望值。链接检查也同步执行——外部链接发 HEAD 请求验证，内部链接检查文件存在性。两种检查并行跑，结果合并输出。

输出格式终端表格，按文件分组。`--strict` 模式下 warning 也视为错误返回非零退出码。`fix <file>` 自动修复能修的问题——统一术语、修复文件名、补代码块语言。不能自动修的只报告。配置支持层级——全局 `.style-guide.json` + 项目级 `.style-guide.local.json`，后者覆盖前者。`go test ./...` 跑测试。
至少拆成两个包或三个文件以上，不要单文件一把梭。
