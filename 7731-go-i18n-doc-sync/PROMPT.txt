多语言文档同步这活谁做过谁知道——英文改了，中文、日文还没更新，过了两周才发现翻译过期了。为什么不搞个工具自动检测哪些翻译需要更新？

i18n-doc-sync 用 Go 标准库实现，`go build -o i18n-doc-sync ./cmd/i18n-doc-sync` 编译。

工具管理文档的多语言版本，每种语言一个目录（`en/`、`zh/`、`ja/`）。基准语言默认英文，其他语言和它对比。同步检测方式：每个文档文件计算内容哈希，记录在 `.i18n-hashes.json` 中。英文文件变更后哈希改变，对应的其他语言文件标记为"需要更新"。

标签体系：每个文档有多个标签，按标签聚合显示同步状态。标签支持父子层级——`docs > api > users` 这样的路径。`list --tag api` 只看 API 相关文档的同步状态。

引用关系：文档间有交叉引用。翻译更新时，如果引用的文档本身也需要更新，一起标记。引用其他术语表的数据——术语翻译不统一也作为同步问题报出。

子命令：`sync <dir>` 扫描并输出同步状态报告；`stale` 只列出需要更新的文件；`hash <file>` 查看指定文件的哈希值；`mark-updated <file> <lang>` 手动标记某语言已更新。报告格式终端表格，过期文件用红色标注，最近更新的用绿色。数据存本地 JSON。`go test ./...` 跑测试。
不要写单文件，核心逻辑、CLI 入口、辅助工具各放一个文件。
