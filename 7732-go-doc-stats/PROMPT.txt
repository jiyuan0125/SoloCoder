最近老板问团队文档产出情况，一问三不知——多少篇文档、总字数多少、谁写的最多、更新频率如何。与其拍脑袋回答，不如写个工具把文档统计拉出来。

doc-stats 用 Go 标准库实现，`go build -o doc-stats ./cmd/doc-stats` 编译。

它扫描指定目录下所有 Markdown 文件，提取统计数据。每篇文档记录：标题、字数（中文字符数 + 英文单词数）、段落数量、代码行数、链接数量、图片数量、创建时间和最后修改时间。数据存本地 JSON 文件 `~/.doc-stats/reports/` 目录下，每次运行生成一份带时间戳的报告。

统计维度分几层。文件级：单篇文档的各项指标。目录级：某目录下文档总数、平均字数、总字数、代码占比。作者级：从 git blame 提取每篇文档的作者，统计每人贡献的文档数和字数。时间级：按周/月统计文档新增和修改趋势。

任务有多个审批步骤——生成统计报告后需要指定审批流程才能发布给团队。审批状态存在报告元数据里：草稿→待审批→已通过→已发布。

笔记支持标签和分类，搜索支持全文检索和按标签筛选。统计结果也可以按标签分组——比如只看"API"分类下的文档统计。子命令：`stats <dir>` 扫描并统计；`trend` 输出时间趋势；`authors` 按作者统计；`export` 输出 JSON 格式报告。`go test ./...` 跑测试，`go build` 通过。
项目结构要分模块：主入口、核心处理逻辑、工具函数分文件组织，方便测试和维护。
