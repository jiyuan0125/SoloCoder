同事转发了一篇内部技术文档，问我"这篇大概要看多久"——我只能靠字数粗估说"大概半小时吧"，实际他看了 50 分钟。纯 Markdown 文件没有任何阅读时间信息，每次都要手动猜。做个工具自动算阅读时间，中文英文代码块分别统计，比瞎猜靠谱多了。

read-time 用 Go 标准库实现，`go build -o read-time ./cmd/read-time` 编译。

计算逻辑：中文按每分钟 400 字，英文按每分钟 200 词，代码块按每分钟 100 行。先分段统计——标题段、正文段、代码段、引用段各自计算阅读时间，再加权求和。图片按每张 10 秒额外计入。最终时间向上取整到分钟。

从代码注释提取文档内容——扫描 Go 源码中 `//` 和 `/* */` 格式的 doc comment，识别出函数文档和包文档。代码变更时自动标记需要更新阅读时间的文档。输出为 Markdown 格式，每篇文档开头插入一行 `> 预计阅读时间：X 分钟`。

引用了其他表的数据——如果文档有结构化元数据（frontmatter 里的 `reading_time` 字段），工具会校验元数据值和实际计算值是否一致，不一致发出 warning。

子命令：`calc <file>` 计算单篇；`batch <dir>` 批量计算并输出报告；`inject <file>` 把阅读时间插入文档 frontmatter；`diff <old> <new>` 对比修改前后的阅读时间变化。支持多种注释格式。`go test ./...` 跑测试。
代码分文件组织，解析器、处理器、输出器分开，main.go 只做参数解析和流程串联。
