代码写了不少，但文档覆盖率多少？哪些模块有文档哪些没有？先扫描代码和文档目录建立映射，再算出覆盖率报告，一眼看出哪些地方缺文档。

doc-coverage 用 Go 标准库实现，`go build -o doc-coverage ./cmd/doc-coverage` 编译。

先扫描代码。遍历指定源码目录，提取所有导出函数、类型、常量。Go 代码通过解析 `go doc` 格式的注释判断是否有文档覆盖。命令和子命令多级结构：`cover src/` 统计源码文档覆盖率，`cover docs/` 统计文档目录覆盖。

再扫描文档。读取 `docs/` 目录下所有 Markdown 文件，提取标题和正文中提到的模块名、函数名。建立"代码实体→文档引用"的映射表。

最后生成报告。覆盖率 = 有文档的导出实体数 / 总导出实体数。按模块（包/目录）分组展示覆盖率百分比。扫描结果缓存到 `.doc-coverage/cache.json`，增量更新只重新扫描变更文件。

报告包含：总覆盖率、各模块覆盖率、未覆盖实体列表（标红）、覆盖率趋势图（纯文本柱状图）。输出格式终端表格，`--format json` 切换。每个未覆盖的实体给出一行建议，比如"函数 `ParseConfig` 没有文档注释"。

子命令：`scan <src-dir>` 扫描；`report` 输出覆盖率报告；`diff` 对比两次扫描的覆盖率变化。配置文件 `.doccoveragerc.json` 设置文档路径映射。`go test ./...` 跑测试。
不要写成一个 main.go 搞定所有事情。按职责拆文件：入口、解析、处理、输出分开。
