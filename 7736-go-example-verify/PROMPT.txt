文档里的示例代码到底能不能跑？这个问题不验证的话，读者照着抄过去编译都过不了，文档可信度直接崩盘。写个工具自动验证文档中的代码示例。

example-verify 用 Go 标准库实现，`go build -o example-verify ./cmd/example-verify` 编译。

工作方式：解析 Markdown 文件中的代码块，提取标注了语言为 `go` 的代码片段。每个片段写到一个临时文件，尝试用 `go build` 或 `go run` 编译执行。编译成功标记为通过，编译失败记录错误信息。非 Go 代码块跳过，只验证 Go 示例。

从代码注释提取文档——扫描 `// Example` 开头的注释块识别示例函数，和 Markdown 中的代码块做关联。代码变更时自动标记需要重新验证的示例。变更通知下游——验证结果变化时更新缓存的验证状态。

验证环境：每个代码片段在独立的临时目录中执行，不影响主项目。超时 30 秒强制终止。有副作用的代码（网络请求、文件写入）跳过执行只做语法检查。代码块头部支持 `// verify:skip` 注释跳过验证。

子命令：`verify <file>` 验证单文件；`verify-dir <dir>` 批量验证；`report` 输出验证结果汇总——通过数、失败数、跳过数。输出格式终端彩色文本，`--format json` 切换。验证结果缓存到 `.example-verify/results.json`。支持多种注释格式。`go test ./...` 跑测试。
项目要用多文件结构，入口文件、业务逻辑、数据模型分开放，别揉在一个文件里。
