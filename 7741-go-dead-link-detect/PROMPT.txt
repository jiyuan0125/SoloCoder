你有多久没检查过文档里的外链了？上周帮同事排查问题，发现文档引用的第三方 API 链接已经 404 了半年。死链检测不能靠人肉，得自动化。

dead-link-detect 用 Go 标准库实现，`go build -o dead-link-detect ./cmd/dead-link-detect` 编译。多种子命令处理不同检测模式。

检测策略分两类。内部链接：解析 Markdown 中 `[text](path)` 格式，验证目标文件在文件系统中是否存在。支持相对路径和绝对路径。外部链接：发 HTTP HEAD 请求，超时 10 秒，跟随重定向最多 5 次。4xx 和 5xx 状态码标记为死链，3xx 但重定向链超过 5 次也标记。并发控制用带缓冲 channel 做信号量，默认 20 并发。

工具自动扫描文档目录，新增文件自动纳入检测。多级标题在报告中按文档结构组织。每条死链记录来源文件、行号、链接文本、目标 URL、HTTP 状态码。结果按文件分组，每个文件内按行号排序。

子命令：`detect <dir>` 批量扫描目录；`file <path>` 检查单文件；`report` 从缓存结果生成汇总报告；`history` 对比历史检测结果看趋势。检测结果缓存到 `.dead-links/results.json`，缓存有效期 7 天。输出格式终端表格，`--format json` 切换。`go test ./...` 跑测试。
不要写单文件，核心逻辑、CLI 入口、辅助工具各放一个文件。
