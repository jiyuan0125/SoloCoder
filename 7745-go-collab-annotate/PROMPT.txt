多人协作写文档，批注散落在各个渠道——有的在代码评审里，有的在即时通讯里，有的口头说了就忘了。先把批注集中管理起来，再做评分和质量追踪。

collab-annotate 用 Go 标准库实现，`go build -o collab-annotate ./cmd/collab-annotate` 编译。`annotate <file> --line 42 --text "这段描述不准确"` 在指定文件的指定行添加批注。批注模型包含文件路径、行号范围、批注内容、作者（从 git config 读取）、时间戳、状态（待处理/已解决/已忽略）。批注也可以不关联行号，直接针对整个文件。

批注状态可流转：待处理→已解决或已忽略。`resolve <id>` 标记为已解决，`ignore <id>` 标记为忽略。处理完成后自动归档到 `.annotations/archive.json`。同时，工具对文档质量打分——完整性、可读性、示例覆盖率三个维度独立评分，批注密度也作为质量指标（批注多的文档可能质量差需要重写），每个维度给出行级改进建议。

子命令：`annotate` 新增批注；`list <file>` 列出文件的所有批注；`resolve <id>` 解决批注；`stats` 统计各作者批注数和解决率。数据存 `~/.collab-annotate/annotations.json`，文件写入用原子操作。输出 Markdown 格式。`go test ./...` 跑测试。
不要写成一个 main.go 搞定所有事情。按职责拆文件：入口、解析、处理、输出分开。
