文档审阅流程能不能别再靠邮件来回转发附件了？需要一个工具把审阅状态管起来——谁在审、审到哪了、有没有卡住。

review-workflow 用 Go 标准库实现，`go build -o review-workflow ./cmd/review-workflow` 编译。

审阅模型：每条审阅记录包含文档路径、提交者、审阅者列表、当前状态（待分配/审阅中/已通过/已拒绝）、每个审阅者的独立结论、时间线。状态按顺序流转，不能跳步。更新配置时自动刷新缓存，刷新也要重新读取配置数据——比如审阅者列表变更，待分配的审阅任务自动重新分配。

笔记支持标签和分类，搜索支持全文检索和按标签筛选。审阅任务也可以按标签过滤——`--tag api` 只看 API 相关文档的审阅。

权限控制：提交者不能同时是审阅者。文档作者只能提交审阅请求，不能批准自己的文档。至少一个审阅者通过才能标记为已通过。所有审阅者拒绝则标记为已拒绝。

子命令：`submit <file> --reviewer alice,bob` 提交审阅请求；`approve <id>` 通过；`reject <id> --reason "缺少安全说明"` 拒绝；`status` 查看所有进行中的审阅；`history <file>` 查看某文档的完整审阅历史。数据存本地 JSON 文件 `~/.review-wf/reviews.json`。`go test ./...` 跑测试，`go build` 通过。
项目要用多文件结构，入口文件、业务逻辑、数据模型分开放，别揉在一个文件里。
