大文档不想一次性全发布——先发概述和核心章节，后面的补充材料等写完再上。分片发布需要精确控制哪些章节可见哪些隐藏，手动维护很容易出错。

doc-partial-publish 用 Go 标准库实现，`go build -o doc-partial-publish ./cmd/doc-partial-publish` 编译。在 Markdown 文件中用 `<!-- publish: on -->` 和 `<!-- publish: off -->` 控制发布范围，没有标记的段落默认发布。标题层级也参与控制——如果某个 H2 标记为 off，其下属的 H3-H6 全部排除。

`publish <file>` 读取源文件，过滤掉标记为 off 的章节，调整标题编号（避免跳号），重新生成目录，输出到 `published/` 目录或 `--output` 指定路径。每次发布变更需要审批——提交者发起、审批者确认，审批通过后才更新发布目录。发布历史记录在 `.publish-history.json` 中，包含版本号、发布时间、包含的章节列表。`status <file>` 查看哪些章节已发布，`history <file>` 查看发布历史。

评分维度包括完整性（已发布章节是否自成一体）、可读性（章节衔接是否通顺）、示例覆盖率（已发布部分代码块够不够）。每个维度独立评分附改进建议。`go test ./...` 跑测试。
代码按模块拆分，不要把所有逻辑写在一个文件里。解析、转换、输出分开组织。
