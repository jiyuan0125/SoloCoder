最近在写一个多功能 CLI 工具，子命令越来越多，if-else 链都快写不下去了。得有个子命令路由器，把不同子命令分发给对应的处理函数，主流程保持简洁。

subcmd-router 用 Go 标准库实现，`go build -o subcmd-router-demo ./cmd/subcmd-router` 编译。它是个并发任务处理框架的子命令路由组件。

路由模型：每个子命令有名称、短描述、处理函数、参数定义。路由器注册所有子命令，运行时根据 os.Args[1] 分发到对应处理函数。未注册的子命令返回错误并建议最接近的命令名（Levenshtein 距离最小的）。

任务队列支持最大并发数限制。子命令处理函数如果涉及并发任务，通过路由器内置的 worker pool 调度，默认并发数 CPU 核心数。任务失败自动重试，重试次数可配置（默认 3 次），指数退避。所有任务完成后输出汇总报告——成功数、失败数、总耗时。

主流程完成后自动生成关联记录——每个子命令的执行结果存入 `~/.subcmd-router/history.json`，包含命令名、参数、执行时间、结果状态。下次执行时可以快速查看历史。

子命令定义方式：`router.Register("deploy", deployHandler)`。支持别名——`router.Alias("d", "deploy")`。帮助信息按子命令分组展示，`--help` 输出全局帮助，`<cmd> --help` 输出子命令帮助。嵌套子命令也支持——`app service restart`。`go test ./...` 跑测试。
项目结构要分模块：主入口、核心处理逻辑、工具函数分文件组织，方便测试和维护。
