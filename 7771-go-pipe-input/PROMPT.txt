管道输入——Unix 哲学的精华就是管道，但 CLI 工具处理 stdin 输入总有些零碎的问题：阻塞等待、大文件内存溢出、编码不对乱码。为什么不把这些处理好做个通用组件？

pipe-input 用 Go 标准库实现，`go build -o pipe-input-demo ./cmd/pipe-input` 编译。它处理 CLI 工具从 stdin 读取管道输入的场景。

自动检测输入源：如果 stdin 有数据（通过 `os.Stdin.Stat()` 检测），从管道读取；否则从命令行参数获取文件路径。两者都没有时报错退出。流程分多个阶段：检测→读取→解析→处理→输出。

流式读取：不一次性加载全部内容到内存，用 `bufio.Scanner` 逐行处理。行长度上限可配（默认 1MB），超长行截断并发出 warning。大文件处理时内存恒定。

组件支持动态更新——读取过程中可以暂停/恢复，通过信号或回调控制。长时间操作显示已用时间和预估剩余时间（根据已读取行数和文件大小估算）。输出不破坏终端当前行——进度信息用 `\r` 覆盖。

编码处理：默认 UTF-8，遇到非 UTF-8 字节尝试 Latin-1 转换，转换失败跳过该行并报 warning。行尾符自动统一（CRLF/LF/CR 都支持）。

API：`p := pipe.New()`、`p.Process(func(line string) error { ... })`、`p.Run()`。支持上下文取消。`go test ./...` 跑测试。
不要写单文件，核心逻辑、CLI 入口、辅助工具各放一个文件。
