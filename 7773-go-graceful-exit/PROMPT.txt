优雅退出——程序被 kill 的时候，数据写到一半、连接没关闭、临时文件满天飞。这种不干净的退出在生产环境是定时炸弹。

graceful-exit 用 Go 标准库实现，`go build -o graceful-exit-demo ./cmd/graceful-exit` 编译。它管理 CLI 工具的生命周期退出。

注册机制：各模块注册自己的清理函数。`graceful.OnExit("db", func() { db.Close() })`。多个关联的实体按依赖关系排序——数据库关闭在日志 flush 之后、文件句柄关闭在数据库之后。依赖关系通过 `Before("db")` 声明。

组件支持动态更新——运行时可以注册新的清理函数。长时间操作显示已用时间。输出不破坏终端当前行。

退出流程三阶段：第一阶段发送通知（`context.Cancel`），各 goroutine 收到后开始清理；第二阶段等待所有注册的清理函数完成（带超时）；第三阶段强制退出未完成的。每个阶段的进度实时输出。

状态记录：退出时把当前状态快照写入 `.graceful-state.json`——哪些任务完成、哪些未完成、正在处理的文件路径。下次启动时读取状态文件，可以选择恢复未完成的任务。

API：`g := graceful.New()`、`g.Register("name", cleanupFn)`、`g.DependsOn("name", "other")`、`g.Wait()`。也支持无依赖的并行清理。`go test ./...` 跑测试。
