直接 go func() 启任务太野了，没有并发控制、没有重试、没有结果收集，出了问题连哪个任务失败都不知道。得有个正经的异步队列：先定义任务结构，再入队执行，最后统一收集结果。

task-queue 用 Go 标准库实现，`go build -o taskq-demo ./cmd/taskq` 编译。`Task` 接口包含 `Execute() error` 和 `Name() string`。任务可以有依赖——`task B depends on task A`，A 完成后 B 才开始执行，依赖的任务状态变化自动触发等待中的任务。

任务队列支持最大并发数限制（默认 CPU 核心数）。入队后立即返回 task ID，不阻塞调用方。任务失败自动重试，重试次数可配（默认 3 次），指数退避（1s、2s、4s），超过次数标记为失败。`Results()` 返回所有任务的结果列表——成功/失败、执行时间、错误信息。所有任务完成后输出汇总报告：成功数、失败数、总耗时。也可以注册回调 `OnComplete(func(result))` 异步处理。

文件操作相关：任务结果持久化到本地 JSON 文件，用原子操作写入。支持文件变更监听，外部程序可以监控任务进度。

API：`q := taskq.New(taskq.WithWorkers(5))`、`id := q.Submit(task)`、`q.Wait()`、`results := q.Results()`。支持上下文取消。`go test ./...` 跑测试。
不要写成一个 main.go 搞定所有事情。按职责拆文件：入口、解析、处理、输出分开。
