上次部署脚本卡在某个远程命令上，等了半小时才发现是网络不通。如果加个超时控制，30 秒没响应直接跳过或报错，问题早发现了。超时控制不是可选项，是生产环境的基本功。

timeout-control 用 Go 标准库实现，`go build -o timeout-demo ./cmd/timeout` 编译。它管理配置化的超时策略。

超时模型：每个操作有独立的超时时间。分为总超时（整个任务从开始到结束）、阶段超时（任务分多个阶段，每个阶段独立计时）。流程分多个阶段——初始化→执行→超时检查→清理。

配置层叠合并：全局配置（默认 30 秒）+ 项目配置（`timeout.json`）+ 用户配置（环境变量 `TIMEOUT=60`）。支持数组追加和深度合并。配置变更触发回调。

超时处理策略：可配置超时后的行为——直接返回错误（默认）、执行回调函数后返回、尝试取消操作（通过 context）。取消后等待清理完成，清理也有独立超时。

嵌套超时：父超时覆盖子超时。如果父任务总共 60 秒，子任务设了 120 秒，实际以 60 秒为准。超时传播——子超时触发后，如果父任务还有其他子任务在跑，可以选择取消全部还是只取消超时的那个。

API：`t := timeout.New(30*time.Second)`、`err := t.Run(func(ctx context.Context) error { ... })`、`t.WithCleanup(func() { ... })`。也支持 `timeout.WithContext(parentCtx, 30*time.Second)`。`go test ./...` 跑测试，`go build` 编译通过。
