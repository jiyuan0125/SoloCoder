配置合并这活谁喜欢干？全局配置、项目配置、用户配置三层叠加，数组要追加、对象要深度合并、冲突了谁优先？每次手写合并逻辑都是重复劳动。

config-merge 用 Go 标准库实现，`go build -o cfgmerge-demo ./cmd/cfgmerge` 编译。它给自己其他项目用的配置层叠合并库。

合并策略：基础配置 + 项目配置 + 用户配置，后者覆盖前者。标量值直接覆盖。对象深度递归合并——用户配置的 `db.host` 只覆盖 `host`，不影响 `db.port`。数组默认追加（用户配置的数组追加在基础配置后面），也支持替换模式。

更新配置时自动刷新缓存，刷新也要读配置——缓存失效后重新合并。合并结果缓存在内存中，下次获取直接返回缓存值。配置变更触发回调——注册 `OnChange(key, func(old, new))` 监听特定配置项的变化。

冲突检测：合并后检查是否有类型冲突（基础是 string 用户配了 int）、范围冲突（值超出允许范围）、依赖冲突（某个配置依赖另一个但另一个没设）。冲突按严重程度分级处理。

库支持嵌套子命令——每个子命令有独立的帮助信息和配置命名空间。未知子命令给出建议。

API：`m := merge.New(base)`、`m.Layer(project)`、`m.Layer(user)`、`result := m.Merge()`。也支持增量合并 `m.Set("db.host", "localhost")`。`go test ./...` 跑测试，`go build` 编译通过。
