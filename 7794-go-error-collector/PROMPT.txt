迁移 1000 条数据，第 3 条失败了就中断，剩下 997 条全跳过。用户只看到一条错误，不知道其他数据什么情况。应该全部跑完再汇总报告，错误收集起来统一输出，一次看完所有问题。

error-collector 用 Go 标准库实现，`go build -o errcol-demo ./cmd/errcol` 编译。它给命令行工具加错误收集的日志能力。

收集模型：每个错误记录操作名称、错误类型、错误消息、时间戳、上下文信息（key-value 对）。错误分三级：warning（不中断继续）、error（标记失败但继续）、fatal（立即停止收集并返回）。调整后相关的汇总也要更新——新增错误后，按错误类型统计的计数和按操作分组的汇总自动刷新。

日志分级输出到 stderr。支持结构化字段——每条错误日志带完整上下文。文件输出支持轮转（按大小和按天）。不依赖第三方库。

错误去重：相同操作+相同错误类型+相同消息的错误在 N 秒内只记录一次（默认 60 秒），计数器递增。最终报告显示 "same error occurred 15 times"。

报告格式：终端表格输出，按严重程度排序（fatal→error→warning）。每条错误一行：序号、操作、错误类型、消息。汇总行：总错误数、fatal 数、error 数、warning 数。JSON 格式输出给后续处理。

API：`ec := errcol.New()`、`ec.Add(op, err)`、`ec.Warn(op, msg)`、`ec.Report()`。也支持 `ec.Try(func() error { ... })` 自动收集。`go test ./...` 跑测试。
拆成至少三个 Go 文件：main.go 做入口和参数解析，核心处理逻辑独立一个文件，工具函数单独放。
