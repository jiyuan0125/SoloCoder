每次改完配置文件都要手动重启服务才能生效，改了十几遍之后终于烦了。为什么不能监听文件变更自动重载？先注册监听目标，再定义回调函数，文件一变就触发。代码修改自动跑测试、文档修改自动生成，都靠这个。

file-watcher 用 Go 标准库实现，`go build -o fwatch-demo ./cmd/fwatch` 编译。它给自己其他项目用的文件变更监听库。

先注册目标。`w.Add("./src", watcher.OnChange(handler))` 监听目录下所有文件变更。支持过滤模式——`w.Add("./src", watcher.WithPattern("*.go"))` 只监听 `.go` 文件。递归监听子目录（默认开启）。数据有生命周期——监听注册可以设 TTL，超时自动停止。

再定义回调。回调函数签名 `func(event Event)`，Event 包含文件路径、变更类型（Create/Modify/Delete/Rename）、文件信息。回调在独立 goroutine 中执行，不阻塞监听循环。多个回调串行执行，避免竞争。

最后管理生命周期。启动 `w.Start()`，停止 `w.Stop()`。库支持嵌套子命令——每个子命令有独立的帮助信息。未知子命令给出建议。

防抖机制：短时间内同一文件多次变更只触发一次回调（默认 100ms 防抖窗口）。大文件写入完成才触发（检测文件大小是否还在变化）。工作目录临时文件自动忽略。

API：`w := watcher.New()`、`w.Add("./src", handler)`、`w.Start()`、`w.Wait()`。用 `fsnotify` 不行就回退到轮询模式。`go test ./...` 跑测试，`go build` 编译通过。
