文件锁——多个进程或 goroutine 同时写一个文件，不锁的话数据必乱。但 `flock` 这种系统调用用起来有不少坑：锁没释放进程就挂了、不同操作系统行为不一致。为什么不封装一下？

file-lock-mgr 用 Go 标准库实现，`go build -o flock-demo ./cmd/flock` 编译。它管理 CLI 工具的文件锁。

锁模型：支持排他锁（写锁）和共享锁（读锁）。锁粒度：文件级锁（整个文件一把锁）和记录级锁（文件内某个范围）。任务有多个审批步骤——获取锁前检查是否已有其他进程持有，有的话排队等待或立即返回错误。

组件支持动态更新——锁超时时间可以在运行时调整。长时间等待时显示已等待时间和预估剩余时间（基于历史获取时间的平均值）。输出不破坏终端当前行。

锁文件格式：`.lock` 后缀，内容包含持有者 PID、获取时间、锁类型、备注。进程异常退出后残留的锁文件通过检查 PID 是否存活来判断是否为过期锁——PID 不存在就自动清理。

并发安全：内部状态用 mutex 保护。死锁检测——等待图检测循环依赖，发现死锁输出诊断信息。

子命令：`lock <file>` 获取排他锁；`unlock <file>` 释放锁；`status <file>` 查看锁状态；`list` 列出所有活跃锁；`clean` 清理过期锁。API：`l := flock.New("file.lock")`、`l.Lock()`、`l.Unlock()`。`go test ./...` 跑测试。
