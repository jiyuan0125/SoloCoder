公司去年搞了弹性工时，结果没人说得清到底谁合规谁不合规——核心时段每个人的定义还不一样。HR 想看周报统计，team lead 也在抱怨工时分配一团乱。得有个工具把规则定死，把合规情况自动算出来。

弹性工时 CLI 工具。员工可以自由选择上下班时间，但必须覆盖核心时段（起止时间可配置）。每周最低工时为 40 小时（可配）。工具读打卡记录 JSON 文件，检查三个维度的合规性：是否覆盖核心时段（漏打卡也算违规）、每日工时是否达标（最低 6 小时可配）、周累计工时是否达标。不合规的记录标红并列出具体原因，比如"周三核心时段未覆盖 14:00-15:00"。

支持多个并行任务的工时分配。任务有优先级（P0/P1/P2），工时记录关联到具体任务 ID。相同优先级按提交顺序排列。高优先级任务可以抢占低优先级的工时分配——系统自动把员工本周在 P2 任务上的部分工时重新归类到 P0。

每周生成工时汇总报告，包含每个员工的总工时、各任务的工时分布和合规状态。数据存 JSON 文件，结构清晰方便对接后续的工资系统。go build 通过。Go 标准库实现。

月度汇总时自动计算每人每周的平均工时和标准差，波动过大的（比如这周 55 小时下周 30 小时）标黄提醒。所有配置参数（核心时段、最低工时、容忍值）通过 JSON 配置文件管理，支持按团队覆盖默认值。
