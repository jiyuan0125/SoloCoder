五个项目争三个后端，排期全靠嘴——谁先抢到算谁的。上回项目 D 的任务根本没人分配，直到 deadline 前两天才发现。跨项目资源分配没有工具支持就是一笔糊涂账。

多项目资源分配工具。任务有依赖关系，前置任务未完成时后续不能开始。工具对每个任务计算最早开始时间和最晚完成时间——正向遍历算 ES/EF，反向遍历算 LS/LF。资源分配时检查全局约束：同一个人不能在同一天被两个项目同时占用。技能匹配也要校验，不能把需要 Go 的后端任务分配给只会 Java 的人。

更新配置（比如新增项目或修改资源可用量）时自动刷新分配缓存，刷新过程也要重新读取配置文件确保数据一致。资源冲突时按三级优先级分配：项目优先级 > 任务优先级 > 提交时间先后。冲突无法自动解决时输出待决策列表（列出冲突的任务和资源，方便项目经理讨论），人工裁定后重新运行。

输出按项目分组的甘特图数据和按资源分组的工时占用表（显示每个人每天在各项目上的工时分配）。数据存 JSON。go build 通过。Go 标准库实现。

支持模拟场景：修改资源池（增加或减少人员）后重新分配，对比不同方案下的冲突数量和项目工期变化。配置文件支持环境变量替换，方便在测试和生产环境之间切换。工具单二进制无外部依赖。
代码要模块化：主流程、具体功能实现、辅助函数分开存放，主文件只做调度。
