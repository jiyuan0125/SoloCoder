项目经理问"最晚什么时候必须完成"，没人能立刻回答。这个时间决定了任务有多少浮动空间，浮动为零的就是关键路径上绝对不能延误的环节。

最晚完成时间计算工具。输入任务网络图（JSON 格式）和项目截止日期。工具先正向遍历算出所有任务的 ES/EF，再从项目截止日期反向遍历计算每个任务的最晚开始时间（LS）和最晚完成时间（LF）。有多个后继任务的，取所有后继任务 LS 的最小值减去当前任务工期作为 LF。更新配置（比如改了截止日期或某任务的工期）时自动刷新缓存，刷新过程也要重新读取配置确保数据一致。

支持多级任务分解：项目→阶段→任务→子任务，四层。每层有独立状态和进度，向上汇总。浮动时间 Float = LS - ES，为零说明没有缓冲余量。关键路径上的任务自动高亮。工期为 0 的任务作为里程碑节点处理。

输出所有任务的 ES/EF/LS/LF/Float 完整表格，附带关键路径清单和浮动不足 2 天的警告列表。支持 --format json 输出供脚本调用。数据文件损坏时给出具体错误行号和描述，而不是笼统的 parse error。支持从 CSV 导入任务列表（自动转换为 JSON 格式存储）。工具不依赖外部服务，所有计算在本地完成。Go 标准库实现。
