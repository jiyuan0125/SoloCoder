产品经理坚信用户是从"首页→搜索→商品详情→购物车→下单"这条路径走的，打算优化搜索页。但数据分析师说不对，很多用户是从推荐位直接跳到商品详情的。两个人吵了一下午，谁也说服不了谁，因为没人真的跑过路径数据。

路径分析工具。输入用户行为日志（JSON：用户 ID、页面/事件名称、时间戳），提取每个用户的行为序列，统计最频繁的路径模式。输出 Top N 路径（起点到终点的完整事件链），含每个路径的用户数和占比。比如发现"首页→推荐位→商品详情→下单"这条路径的用户数是搜索路径的 3 倍，产品方向就该调整了。

路径可视化输出桑基图所需的 JSON 格式（源节点、目标节点、流量值），直接丢给前端就能渲染。

路径长度过滤（3-8 步），按时间范围和用户分群过滤。路径归一化去除重复事件——用户在商品详情页来回刷 10 次，路径里只记一次。会话切分：30 分钟无操作算新会话，避免把昨天的浏览和今天的下单串在一起。

Go 标准库实现，不引第三方包，单二进制分发。数据存 JSON 文件，操作带审计日志。
不要写成一个 main.go 搞定所有事情。按职责拆文件：入口、解析、处理、输出分开。
