数据库从 MySQL 迁移到 PostgreSQL 以后，抽查了几个表发现有些记录缺了字段值。用户表里有 2000 个用户没有手机号，订单表里有 300 个订单没有收货地址。更坑的是，有些字段的值是空字符串 `""`，有些是 `"N/A"`，有些是 `"null"` 字符串——到底算不算空值，不同的人判断标准不一样。

完整性检查工具统一空值标准。检查规则从 JSON 配置读取：每个字段定义是否必填、允许的类型、哪些算空值（null 算空？空字符串算空？`"N/A"` 算空？还是只有 null 才算？全部可配）。

主操作执行时调用辅助检查（格式校验、引用完整性），辅助检查也读同一份数据，不需要额外传参。

输出两份统计：按字段统计空值率和空值分布（手机号字段 60% 是 null、30% 是空字符串、10% 是 "N/A"），按记录统计每条记录有多少必填字段为空。最差的记录排在最前面——那个 5 个必填字段缺了 4 个的用户记录一看就知道是测试数据。

修复建议不是空话。对于空值率高的字段，根据字段类型给出策略：数值型用中位数填充、枚举型用众数填充、地址类标记为待人工处理。

Go 标准库实现，单二进制分发，不依赖外部服务。数据存 JSON 文件。所有操作有审计日志。
