去年被监管罚了 50 万，原因是用户数据没有按规定脱敏。合规部门要求所有数据字段必须按规则检查，出一份合规报表。500 个字段 × 数百万条记录，手动检查显然不现实。合规不是走过场，是真能被罚款的。

合规报表工具。合规规则从 JSON 配置读取，每条规则有 ID、名称、检查逻辑（哪个字段 + 什么条件 + 期望值是什么）、严重程度（高/中/低）。比如规则 CR-012："手机号字段必须脱敏，只显示前 3 后 4 位"，严重程度"高"。

每条记录每条规则检查后得出三种结果之一：合规（通过）、不合规（附具体不合规值，比如"手机号完整显示为 13812345678"）、不适用（该记录不涉及此规则）。合规率 = 合规记录数 / 适用记录数。

合规状态变更时自动通知下游——合规官和项目经理会收到通知，新出现的不合规记录不会没人管。

输出合规汇总表（每条规则的合规率，一眼看到哪条规则合规率最低）、不合规明细（所有不合规记录和具体值）、趋势数据（合规率随时间变化，看整改是否有效）。JSON 导出。Go 标准库实现，单二进制分发，不依赖外部服务。数据存 JSON 文件。所有操作有审计日志。
