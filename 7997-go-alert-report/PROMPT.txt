上个月库存低于安全线了才发现，紧急补货花了两周，期间断货损失了 30 万销售额。用户流失率连续三周上升也没人注意到，等月度报表出来已经流失了 500 个用户。数据出问题才反应过来太晚了，得有预警机制在问题刚冒头的时候就报警。

预警报表工具。流程分四步走：数据加载 → 阈值检测 → 趋势分析 → 预警生成。对比两个时间段的数据，变化超过阈值（可配）的标红。终端输出彩色表格一眼看到红的。

预警规则从 JSON 配置读取：每条规则有名称、检测字段、条件（大于阈值、小于阈值、偏离均值 N 倍标准差、环比下降超 X%）、严重程度（高/中/低）、通知方式。库存量低于安全线是"高"严重程度，日活跃环比下降 5% 是"中"。

预警不是触发一次就完事。状态分三种：新增（首次触发，需要关注）、持续（连续多期触发，显示持续了多久——"库存不足已持续 7 天"）、已恢复（不再触发了但最近触发过，可以松口气）。持续预警按持续时间排序，持续最久的排最前面。

输出预警清单（按严重程度排序），趋势数据（预警数量随时间变化）。支持 webhook 通知推到飞书或钉钉。Go 标准库实现，不引第三方包，单二进制分发。数据存 JSON 文件，操作带审计日志。
