测试覆盖率大家都关心代码层面，但 SQL 查询的覆盖率呢？一张表有 50 列，查询只用了 10 列，剩下的 40 列真的需要吗？删掉不用的列能节省存储和 IO。

帮我做个 SQL 测试覆盖率工具，用 Go 写。给定一组 SQL 查询文件（指定目录扫描所有 .sql 文件）和对应的 schema 定义（JSON 格式，包含表名、列名、列类型），分析每个查询用了哪些表、哪些列、什么类型的操作。

统计维度要全面：表覆盖率——schema 里定义了 N 张表，查询里引用了 M 张，覆盖率 = M/N。列覆盖率——某张表有 K 列，查询中引用了 L 列，覆盖率 = L/K。未覆盖的列名要明确列出来。操作类型分布——SELECT 列表引用、WHERE 过滤条件、JOIN 关联条件、GROUP BY 分组、HAVING 过滤、ORDER BY 排序各有多少次引用。

输出格式化的覆盖率报告：按表维度汇总，每张表显示列覆盖率百分比和未覆盖的列名列表。最后显示整体覆盖率汇总和低覆盖率（< 50%）的表列表，方便定位问题。

额外提供 JSON 格式输出（--json 参数）方便集成到 CI 流水线。
