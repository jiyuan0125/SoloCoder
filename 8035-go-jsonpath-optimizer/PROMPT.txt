一个 50MB 的 JSON 文件，用 JSONPath 查一个小字段，等了 3 秒。瓶颈在哪？很多时候是查询路径太暴力，全量遍历了一遍。能不能先分析路径，跳过不需要的分支？

写个 JSONPath 查询优化器，Go 实现。输入一个 JSONPath 表达式，做静态分析识别性能问题，然后重写为更高效的查询路径。

优化策略：识别全扫描路径——如果 .. 后面紧跟着明确的键名（如 ..name），可以记录路径线索，只递归包含目标键的子树。检测冗余递归——连续两个 .. 合并为一个，避免重复遍历。合并过滤器——[?(@.a > 1)][?(@.b < 10)] 合并为单次遍历的 [?(@.a > 1 && @.b < 10)]。索引利用——如果 JSON 数据源是数组且切片范围明确（[0:10]），在递归前先截断数组长度。

优化后输出三样东西：原始查询路径的分析（标注每一步的开销等级 high/medium/low）、优化后的等价查询表达式、预估的节点访问数对比（原始 N 个节点 vs 优化后 M 个节点）。

支持对比模式——对同一个 JSON 文件分别跑优化前后的查询，打印实际耗时差异。

go build 能编译，纯标准库。
