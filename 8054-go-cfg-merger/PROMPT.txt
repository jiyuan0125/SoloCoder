先加载默认配置，再加载环境特定配置覆盖，最后加载本地覆盖配置——三层配置合并是微服务里的标准做法。但手写合并逻辑容易出 bug，特别是嵌套对象的处理：到底该覆盖还是该合并？数组该怎么处理？

Go 实现一个配置合并工具。输入多个 JSON 配置文件，按优先级从低到高依次合并，后面的覆盖前面的。命令行传入多个文件路径（优先级从左到右递增），输出合并后的 JSON。

合并规则要精细：基本类型（字符串、数字、布尔）直接覆盖——后面的值替换前面的值。对象类型递归合并——只覆盖存在的 key，新增不存在的 key，不删除前面有但后面没有的 key。数组有两种策略可选——替换（后面整个数组替换前面的，默认行为）或追加（两个数组连接），通过 --array-strategy=replace|append 参数选择。null 值的特殊含义：如果后面的文件里某个 key 的值是 null，表示删除前面文件里的这个 key（用于"取消"某个默认配置的场景）。

合并结果保持 JSON 格式输出，可以选择美化打印或压缩输出。支持 JSON 和 YAML 两种输入格式（自动检测后缀名），输出统一为 JSON。
