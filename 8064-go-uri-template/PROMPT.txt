先定义好 URI 模板，再用实际参数展开成具体 URL——REST API 文档里到处都是这种模式。RFC 6570 定义了标准语法，值得好好实现一下。

Go 实现 URI 模板处理器，支持 RFC 6570 里最常用的几种操作。模板语法和对应展开规则：

简单变量替换 {var} ——变量值直接拼入。路径风格 {/var} ——前面加 / 然后拼入变量值（做 path encoding）。查询参数 {?var1,var2} ——前面加 ? 然后 key=value 格式，多参数用 & 连接。矩阵风格 {;var} ——前面加 ; 然后 var=value。片段 {#var} ——前面加 #。带默认值 {var:-default} ——变量不存在时用默认值。

能做模板展开：传入变量 map（如 {"userId":"123","postId":"456"}）和模板字符串（如 "/users/{userId}/posts/{postId}"），生成实际 URI。也能做反向匹配：给定模板和实际 URI，提取变量值（正则匹配实现）。反向匹配要报告匹配是否成功、提取到的变量值 map。

支持变量修饰符（explode with *）——{?list*} 把数组展开为 ?a=1&a=2&a=3 格式。
