GraphQL 的好处是强类型，但如果不在服务端校验查询就浪费了这个优势。用户可能查询不存在的字段、传错参数类型、使用未定义的片段——这些都得提前拦住。

Go 实现 GraphQL 查询验证器。输入一个 GraphQL Schema 定义和一段查询字符串，验证查询是否合法。检查项包括：

字段存在性——查询的字段在对应类型上是否存在（包括 __typename 内省字段）。参数校验——参数名是否存在、参数类型是否匹配、必填参数是否提供（参数后加 !）、枚举参数值是否在定义范围内。Fragment 校验——片段是否在有效类型上使用（fragment on User 不能用在 Query 类型上）、片段是否被引用、循环引用检测。变量校验——变量类型是否匹配使用位置的类型、变量是否在操作中声明。

验证不通过要列出所有错误（不要遇到第一个就停），每个错误标注位置信息——"Query.users: field 'email' does not exist on type 'User', did you mean 'emails'?"。支持 --max-errors N 参数限制输出数量。
