先跑一段字节码程序，结果不对——是编译器生成错了还是虚拟机执行错了？没有调试器只能到处加 print 语句，效率太低了。得加一个类似 GDB 的调试器。

Go 实现，给字节码 VM 加上完整的调试功能。调试命令：

断点管理：break addr 在指定指令地址设断点、delete addr 删除断点、info break 列出所有断点。执行控制：step 单步执行一条指令、next 执行到下一条源码行（跳过函数调用内部）、continue 继续运行到下一个断点或结束、finish 执行到当前函数返回。状态查看：print reg 查看指定寄存器值、print stack 查看操作数栈全部内容、print mem start len 查看内存区域、registers 显示所有寄存器快照。修改状态：set reg = value 修改寄存器值、set mem addr = value 修改内存值。反汇编：disasm 反汇编当前指令及前后各 5 条、list 显示源码和当前行。调用栈：backtrace 显示完整调用栈（函数名、地址、参数）。

交互式命令行——程序暂停时显示当前指令，等待输入命令。编译时生成行号映射表，调试时能显示源码行号和指令的对应关系。

go build 通过。
