解释执行字节码太慢了——每条指令都要解码操作码、分派到对应处理函数、执行操作，这个分派开销是直接执行机器码的 5-10 倍。能不能给热点代码加上 JIT 编译加速？JVM 的 HotSpot 就是这么干的——先解释执行，发现热路径后编译成机器码，性能直接起飞。

Go 实现一个简易 JIT 编译器。工作流程分三个阶段：

解释阶段：正常用解释器执行字节码，同时维护一个调用计数器表——记录每个函数被调用了多少次。热检测：当某个函数调用次数超过阈值（默认 100 次，可配置），标记为热函数触发 JIT 编译。JIT 编译：把热函数的字节码逐条翻译优化——合并常量加载（PUSH 1, PUSH 2, ADD 直接算出 PUSH 3）、消除冗余的栈操作（DUP 紧接着 POP 就删掉）、内联简单函数调用。

不需要生成真正的机器码——用 Go 代码生成然后 plugin 动态加载的方式模拟 JIT 效果。JIT 编译后的函数和解释执行的函数通过函数表统一调度，外部调用无感知。

提供 --jit 和 --interpret 两种模式对比性能——同一个程序跑两遍，输出执行时间和性能提升百分比。
