做代码重构工具需要对 AST 做结构化变换——批量重命名变量、提取公共子表达式、简化条件判断、替换废弃 API 调用。正则替换做不到语义级别的精确匹配，AST 变换才是正确的方式。

Go 实现 AST 变换框架。核心概念是变换规则——每条规则定义一个匹配条件和替换动作。两种规则定义方式：

Go 代码定义——实现 TransformRule 接口：Match(node) bool 判断节点是否匹配、Apply(node) Node 返回替换后的节点树。DSL 定义——用 "pattern -> replacement" 格式描述规则，比如 "a * 1 -> a"（去掉乘 1）、"if (true) { s } -> s"（去掉恒真条件）、"!!a -> a"（去掉双重否定）。DSL 中的 ?x 通配符匹配任意子树并捕获，替换时引用 ?x 还原捕获内容。

变换后要验证 AST 仍然合法——检查节点类型一致性、不会有悬空的引用、控制流完整。附带几个常用变换示例：常量折叠（1+2->3）、死代码删除（if(false){} 删除）、布尔表达式化简（true && x -> x）、变量重命名（指定旧名新名做全局替换）。

变换前后输出 AST 的 diff 对比。go build 能编过。
