团队里的代码规范要靠工具来强制执行——光靠人肉 code review 效率太低，命名不规范、函数太长、嵌套太深这些重复性问题应该机器自动检查出来。

Go 实现一个可扩展的 lint 引擎框架。核心设计：定义 Rule 接口，包含 Check(file *ast.File) []Issue 方法、Name() string、Severity() Level（Error/Warning/Info）。LintEngine 负责扫描指定目录的 Go 源文件、构建 AST、把每个文件的 AST 传给所有注册的 Rule 检查。

实现 5 个示例规则验证框架实用性：未使用的变量（函数内定义了但从未被引用的局部变量，排除 _ 开头的变量）、函数参数命名不规范（应该用驼峰命名，不能有下划线或全大写）、过长的函数（函数体超过 50 行给出警告，阈值可配置）、嵌套过深（if/for/switch 嵌套超过 3 层建议提取子函数）、魔法数字（代码里直接出现的硬编码数字常量值，如 if (status == 3) 应该定义成命名常量）。

输出结果按文件分组排序，每个问题包含文件名、行号、列号、规则名、严重级别、描述。支持 --format text/json。支持 .lintignore 排除文件。go build 通过。
