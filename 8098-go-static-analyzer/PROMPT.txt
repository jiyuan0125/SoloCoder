需要量化分析 Go 代码库的健康程度——不是找具体 bug，而是回答"哪些函数太复杂了需要拆分""哪些包耦合太紧""注释覆盖率怎么样"这类宏观问题。

Go 实现一个静态分析工具，扫描 Go 源码统计以下质量指标：

圈复杂度（Cyclomatic Complexity）——解析每个函数体，统计 if/for/case/&&/|| 等分支节点的数量加 1。超过 15 的函数标红警告，建议拆分。代码行数与注释行数比例——统计每个文件的总行数、代码行（非空非注释）、注释行（// 和 /* */）、空行，计算注释覆盖率百分比。平均函数长度——每个文件的平均函数体行数，超过 30 行的函数单独列出来。最深嵌套层级——每个函数最深的 if/for/switch 嵌套层数，超过 4 层标警告。包依赖关系——提取所有 import 语句构建依赖图，找出循环依赖（报错）和被依赖最多的包（可能是过度耦合的信号）。

支持按包和按文件两种统计粒度。输出文本报告（终端友好的表格），也支持 JSON 格式方便 Jenkins 等工具集成。用 Go 标准库的 go/parser 和 go/ast 包。go build 通过。
