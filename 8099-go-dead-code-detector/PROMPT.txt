代码库里有很多历史遗留的废弃函数——当年加的功能后来不用了，但没人敢删怕影响其他地方。这些死代码增加维护成本、拖慢编译速度、干扰代码搜索。应该找出来安全地清理掉。

Go 实现一个死代码检测工具。分析策略分三步：第一步扫描——找出所有定义的函数和方法（包括文件名、行号、函数名、接收者类型、是否导出）。第二步引用收集——扫描整个包（或整个模块），记录每个函数调用、方法调用、函数变量赋值、接口实现关系。第三步判定——定义集中存在但引用集中不存在的函数就是死代码。

特殊情况的正确处理：递归调用不算外部引用（递归函数如果只有自己调用自己还是死代码）、接口方法实现（实现了接口的方法通过接口类型间接调用时算被引用）、测试文件中的调用（*_test.go 里的引用默认要算，用 --ignore-tests 排除）、main 函数和 init 函数不算死代码（入口函数）、通过反射调用的函数用 //nolint:deadcode 注释标记忽略。

输出未使用函数列表——按文件分组，每个函数显示文件名、行号、签名。最后输出统计：总函数数、死代码数、占比。用 Go 标准库的 ast/parser 包。go build 能编。
