上周 code review 发现一个 800 行的函数嵌套了 7 层 if，这种代码放线上就是定时炸弹。团队决定引入复杂度门禁——每个函数的复杂度评分必须低于 C 级才能合入。现有工具只算圈复杂度，不够全面，需要把函数长度、参数爆炸、嵌套深度这些维度都综合起来。

Go 写一个代码复杂度分析器。遍历指定目录下的 .go 文件，对每个函数计算五项指标：有效代码行数（去掉空行和注释后的净行数）、参数个数（含可变参数）、返回值个数、最大嵌套深度（if/for/switch/select 嵌套层数）、分支总数（if/for/case/&&/|| 的数量）。然后加权求和得到综合评分——行数权重 0.3、参数权重 0.2、嵌套权重 0.3、分支权重 0.2。

评分映射到五个等级：A（0-30 分，低风险）、B（30-50 分，可接受）、C（50-70 分，需关注）、D（70-85 分，应优化）、E（85+ 分，高风险）。超过指定等级阈值的函数用红色高亮。输出支持表格模式（按评分降序排列）和 JSON 模式（--json 输出完整结构化数据）。

命令行用法：complexity-analyzer -dir ./src -threshold C。表格要包含函数名、文件位置、行数、嵌套深度、评分、等级这些列。纯 Go 标准库实现，go build 通过。
