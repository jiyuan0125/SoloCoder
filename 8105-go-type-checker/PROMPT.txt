新人提交了一段代码，string 赋给了 int 变量，编译器当然能拦住。但如果是隐式的类型不匹配——比如自定义类型的 struct 赋值、接口类型的断言——编译器的报错信息有时候不够直观。

帮我写一个简易的 Go 类型检查器。不需要做到完整编译器前端的程度——不做接口满足检查、不做泛型推导——但常见的类型错误得能检查出来。

给定一段 Go 代码（或者 .go 文件），检查这些类型错误：未定义变量（使用了没有在作用域内声明的变量名）、类型不匹配的赋值（int 赋给 string 变量、不同结构体类型互赋）、函数参数类型不对（调用函数时实参类型和形参类型不一致）、返回值数量不一致（函数声明返回两个值但 return 语句只返回了一个）、nil 指针解引用（对可能为 nil 的指针做 .field 访问）。

类型检查过程：先构建符号表（记录每个变量的类型），然后遍历表达式和语句做类型推导和一致性检查。支持基本类型（int/float64/string/bool）、数组类型、slice 类型、map 类型、指针类型、结构体类型。
用法：typechecker foo.go。输出错误列表，每个错误标注行号和原因。Go 标准库，go build 通过。
