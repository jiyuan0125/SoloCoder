接手了一个老项目，打开代码一看——导出函数没注释、注释跟函数名对不上、有的注释就一个词 handler——godoc 生成的文档根本没法看。

帮我做一个 Go 注释检查器。好的注释能帮理解代码意图，差的注释反而误导人——要么太短说了等于没说，要么太长把代码逻辑复制了一遍。

检查导出函数/类型/变量有没有注释（godoc 要求导出的标识符必须有注释）。注释格式对不对——应该以被注释的名字开头，如 // User represents a user in the system，而不是 // this is a user。注释内容是否太短（少于 10 个字符的注释基本没信息量）或太长（超过 200 字符的注释可能过度描述）。TODO/FIXME/HACK/XXX 标记的统计和报告——列出所有待办事项和临时方案的位置。

命令：comment-linter -min-len 10 -max-len 200 ./src。参数可配置最小和最大注释长度。输出每个问题的文件名、行号、问题类型、具体内容。支持 --format json 输出方便 CI 集成。
Go 标准库，go build 通过。
