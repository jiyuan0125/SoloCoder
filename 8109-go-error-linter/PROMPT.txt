Go 的错误处理经常被吐槽啰嗦，但更大的问题是错误处理写错了——忽略返回值、丢失上下文、嵌套太深。需要一个专门的工具来检查这些常见问题。

扫描 Go 代码找常见的错误处理问题：

忽略返回值——函数返回 error 但调用方用 _ = someFunc() 丢弃了。这是最常见的 bug 来源之一。错误未检查直接用——err 赋值后没有检查就继续使用了可能受影响的变量。error 嵌套丢失上下文——只 return err 没有用 fmt.Errorf("doing X: %w", err) 添加上下文信息。panic 在库代码里——库包里不应该 panic，应该在 _test.go 之外检查 panic 调用。重复的错误处理模式——连续多个 if err != nil { return err } 可以用辅助函数简化。
用法：error-linter ./pkg/...。按严重程度分类输出：error（必须修复）、warning（建议修复）、info（可以优化）。每个问题带文件路径、行号和修复建议。
