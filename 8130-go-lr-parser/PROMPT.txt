LL 解析器搞不定的左递归文法，LR 可以轻松处理——从输入符号逐步归约到起始符号，自底向上的方式表达能力更强。Yacc 用的就是 LR 系算法。

帮我实现一个 LR(0)/SLR(1) 解析器。LR 解析是自底向上的——从输入符号逐步归约成非终结符，最终归约到起始符号。比 LL 解析能力更强，能处理更多类型的文法。

从文法自动生成 LR 项目集（item sets）——每个项目是在产生式右端某个位置加了点的产生式（如 E -> E . + T）。构建 LR 状态机——从初始项目集开始，对每个可能的下一个符号做 GOTO 得到新项目集，直到没有新状态。构造 ACTION 表和 GOTO 表——ACTION[current_state, terminal] 决定 shift（移进）还是 reduce（归约），GOTO[current_state, nonterminal] 决定转移到哪个状态。

对输入 token 序列做移进-归约解析——维护状态栈和符号栈，每一步查 ACTION 表决定动作。输出每一步的栈状态和动作（"Stack: [0, E, 1, +, 4], Action: shift 5"）。

命令：lr-parser grammar.txt "id + id * id"。遇到冲突要报告出来——"shift/reduce conflict at state 5 on token '*'"。纯 Go 标准库，go build 编译通过。
