IDE 的跳转到定义功能靠的就是类型推导——光知道变量名不够，还得知道它的类型才能找到对应的类型定义和方法集。

帮我写个 Go 工具，做 Go 源码的类型推导和解析——给定一段 Go 代码，告诉我每个表达式是什么类型。这是静态分析的基础能力。

场景是这样的：我们团队在做静态分析，需要知道代码里每个表达式的类型。程序读入 .go 文件，解析后对每个表达式做类型推导——包括基本类型（int、float64、string、bool）、复合类型（slice 如 []int、map 如 map[string]int、chan 如 chan int、指针如 *int）、接口类型（interface{}和自定义接口）、自定义类型（type MyInt int 定义的新类型）。

要能处理类型断言（v.(int) 的结果类型）、类型转换（int(x) 的结果类型）和隐式接口满足的情况——如果一个 struct 的方法集包含了某个接口的所有方法，那这个 struct 的变量在赋值给接口类型时的类型推导。

遇到类型不匹配的地方要报错，给出位置和期望类型 vs 实际类型——"file.go:42: cannot use x (type string) as type int in assignment"。

纯 Go 标准库实现，go build 能编译通过。
