搞一个 Go 的 import 解析器，帮我们做依赖分析。Go 项目的 import 结构直接影响编译速度和模块化质量——import 太多说明耦合度高，循环 import 说明设计有问题。

程序接收一个 Go 项目目录，递归扫描所有 .go 文件，解析 import 语句，构建完整的导入依赖图。要能处理四种 import 形式：普通导入（import "fmt"）、别名导入（import f "fmt"，记录别名 f）、点导入（import . "math"，记录为点导入）、空白导入（import _ "driver"，记录为空白导入）。

区分三种来源：标准库（Go 自带的包，如 fmt、os、strings）、第三方（GOPATH/pkg/mod 或 vendor 目录下的包）、项目内部（同一模块内的包，用模块路径前缀判断）。

输出每个包的导入列表（标注来源类型）和整个项目的依赖拓扑排序结果。如果发现循环导入要明确报错并指出循环链——"cycle detected: pkg/a -> pkg/b -> pkg/c -> pkg/a"。

Go 标准库实现，go build 通过。
