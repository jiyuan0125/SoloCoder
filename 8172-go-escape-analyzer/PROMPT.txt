帮我写一个 Go 逃逸分析工具。Go 编译器会自动决定变量分配在栈上还是堆上——栈分配几乎零成本，堆分配要 GC 回收。理解哪些变量会逃逸到堆上是优化 Go 程序性能的关键。

分析 Go 源码中哪些变量会逃逸到堆上。检测这些逃逸模式：返回局部变量指针——func newFoo() *Foo { f := Foo{}; return &f }（f 逃逸到堆因为指针逃出了函数作用域）。闭包捕获局部变量——匿名函数引用了外层的变量，变量的生命周期可能超出原函数。interface{} 类型转换——把具体类型的值赋给 interface{}，编译器需要在堆上分配内存来存储动态类型信息。slice/map 超出栈大小——编译期无法确定大小的分配会逃逸。发送到 channel 的指针——指针传给了另一个 goroutine。

这个工具在日常开发中能省不少重复劳动。
对每个逃逸点标注原因和优化建议。重点分析函数调用链中的指针传递。输出逃逸报告。Go 标准库，go build 编译过。
