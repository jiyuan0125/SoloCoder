我团队的测试覆盖率一直不太理想，但光看 go test -cover 输出的一个百分比数字没法定位问题——到底是哪个包拖了后腿？哪个函数完全没覆盖？需要一个更细致的覆盖率分析工具。

帮我实现一个 Go 覆盖率分析器，读取 go test -coverprofile=cover.out 的输出文件。coverprofile 格式是 Go 标准的覆盖率数据格式，每行记录一个源码块的执行次数。

解析后生成详细报告——不只是整体覆盖率百分比，还要按包、按文件、按函数分别统计。标记出完全没有测试覆盖的函数（执行次数为 0 的函数）、覆盖低于阈值的文件（比如低于 50% 的文件标黄、低于 30% 标红）。

支持设置阈值参数（--threshold 60），低于阈值就返回非零退出码——方便 CI 集成（覆盖率不达标就阻止合并）。输出格式支持终端表格和 JSON 两种。
命令行工具：coverage-analyzer cover.out --threshold 60 --by func。Go 标准库，go build 通过。
统计信息以表格或结构化形式输出，一眼就能看出关键指标。
加几个断言检查不变量，出问题时能早点暴露。
