JSON 解析库上线一个月，突然有个用户上传了一个畸形 JSON 导致服务 panic。手动构造测试用例根本覆盖不完——模糊测试让机器自动生成各种边界输入才是正解。

帮我写一个 Go 的模糊测试引擎。模糊测试（fuzzing）就是给程序喂大量随机输入，看它会不会崩溃。Go 1.18 内置了 fuzzing，但自己实现一个能学到更多。

实现一个通用的 fuzz 测试框架。核心思路：用户定义一个测试目标函数（接收某种类型的输入，返回 error 或 nil），框架自动生成随机输入调用目标函数。如果目标函数返回 error 或 panic，记录触发问题的输入。

支持的输入类型自动生成：整数（随机生成 int8 到 int64 的各种范围）、字符串（随机 ASCII、Unicode、特殊字符组合）、字节序列（随机长度和内容）、结构体（通过反射读取字段类型，递归生成随机值）。提供 API 让用户注册自定义的 mutator——基于已知好的输入做变异（翻转某个字节、插入随机字符、截断等策略）。

发现问题时自动保存触发输入到文件（testdata/fuzz/ 目录），方便回归测试。
