微服务 B 改了一个接口的字段名，服务 A 不知道还在用旧字段——联调的时候才发现。契约测试能在编译阶段就拦截这种不兼容变更。

写一个 Go 的契约测试工具。微服务架构下，每个服务有自己的 API——服务 A 调用服务 B 的接口，怎么确保 B 没有偷偷改了接口？契约测试不直接调 B 服务，而是验证接口契约是否被满足。

工具读入一个契约定义文件（JSON 格式），描述 HTTP 请求和期望响应的结构。契约格式示例：
{ "request": { "method": "GET", "path": "/api/users/1" }, "response": { "status": 200, "headers": { "Content-Type": "application/json" }, "body": { "id": 1, "name": "string", "email": "string", "created_at": "string" } } }

验证项：HTTP 状态码匹配、响应头匹配、JSON body 结构匹配（字段名存在、类型匹配 int/string/bool/array/object）、必填字段检查、值范围检查（用 min/max 约束）、嵌套结构递归验证。

对 HTTP API 发实际请求验证返回值是否符合契约。如果服务端改了接口没更新契约，测试就会失败。

支持从 Go 测试代码中运行（testing.T）。Go 标准库 + net/http，go build 通过。
