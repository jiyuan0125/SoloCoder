CI 偶尔失败但本地跑不过——排查了半天发现是两个测试共享了一个全局 map，A 测试往里面写了数据 B 测试读到了。这种测试间污染问题比 bug 还难定位。

写个工具确保 Go 测试之间完全隔离。测试不隔离的话，A 测试修改了全局状态导致 B 测试失败——这种间歇性 bug 最难排查。问题是很多测试间的依赖是隐式的，不容易看出来。

分析 Go 测试代码，检测测试间的隐式依赖：修改全局变量——测试函数里直接修改了包级变量，后续测试看到的是被修改后的值。写入共享临时目录——多个测试向同一个目录写文件，文件名可能冲突。依赖执行顺序——TestA 必须在 TestB 前跑（比如 TestA 创建数据 TestB 查询），这种顺序依赖不稳定。共享 HTTP server 或数据库连接——多个测试用同一个连接，事务可能互相影响。

对于检测到的问题，自动建议修复方案：用 t.Parallel() 标记独立性（如果通过了并行测试说明是隔离的）、用 t.Cleanup() 清理状态（注册清理函数在测试结束后恢复）、使用 t.TempDir() 创建独立临时目录（每个测试一个独立目录）。
