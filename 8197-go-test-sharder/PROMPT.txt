CI 从 12 分钟缩到 3 分钟全靠分片——把 2000 个测试均匀分配到 4 台机器上并行跑，瓶颈从总耗时变成了最慢那个分片的耗时。手动分片太糙了，慢测试全堆在一台机器上反而更慢，需要智能分配。

Go 写一个测试分片工具。先通过 go test -list ./... 收集所有测试函数名，然后按指定策略分成 N 个分片。三种策略可选：按数量平均分，每个分片约 total/N 个测试最简单。按历史耗时加权分，读上次运行的耗时记录 JSON 格式，把慢的测试打散到不同分片让每片总耗时大致相等。按包维度分，同一个包的测试放同一片，因为 go test 按包编译减少重复编译开销。

命令行用法：--total-shards 4 --shard-index 0 表示总共 4 片执行第 0 片，--strategy weighted 启用耗时加权。输出每个分片的测试列表 JSON 文件，或者加 --run 参数直接执行当前分片的测试并输出结果。

增量更新很重要：缓存上次的分片结果到本地文件，只有新增或删除的测试需要重新分配，已分配的测试保持不动避免 flaky。Go 标准库实现，go build 通过。
