只改了用户模块却要等全量测试跑完——500 个测试里 400 个跟用户模块无关。按模块和依赖关系过滤测试能节省大量等待时间。

写一个 Go 测试过滤器，按规则选择要运行的测试。有时候不需要跑全量测试——只改了用户模块就只想跑用户相关的测试，改了 API 层不想跑数据库层。

工具支持这些过滤维度（可以组合 AND/OR）：按测试名模式——正则匹配，如 "TestUser.*" 匹配所有 TestUser 开头的。按文件路径——只跑指定目录下的测试。按测试标签——通过注释标记（// +build integration），选择跑或不跑某类标签。按上次结果——只跑失败的（--failed）、只跑新增的（--new，对比 git 发现新增的测试）。按代码变更范围——分析 git diff 找出改动的文件，只跑受影响模块的测试（需要分析 import 依赖链确定影响范围）。

多种条件可以组合——"只跑 failed AND 在 user 包里" 或者 "跑 new OR 在变更影响范围内"。

输出过滤后的测试列表（可以预览不实际运行），或直接运行过滤后的测试。
