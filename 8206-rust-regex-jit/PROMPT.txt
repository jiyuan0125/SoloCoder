线上日志处理对正则匹配性能要求很高——每秒要处理几十万行日志，每行都要跑正则。解释执行 NFA 太慢了，想做一个带 JIT 编译的正则引擎，把模式编译成本地机器码加速匹配。
Rust 的性能优势在这里很明显。 Rust 生态的工具链越来越成熟了。

用 Rust 实现一个正则 JIT 编译器。工作流程：先把正则表达式编译成 NFA（用 Thompson 构造法）。NFA 转换为字节码（每个状态转移对应一条或几条字节码指令）。字节码 JIT 编译为本地机器码——利用 Rust 的 memmap 和 mmap 分配可执行内存，手工编码 x86-64 指令。

支持的语法同标准正则：. * + ? | () [] {n,m} ^ $ \d \w \s。

提供两种执行模式：interpret 模式（字节码解释执行，用于调试和基准对比）和 jit 模式（机器码直接执行）。CLI 参数 --mode jit|interpret 选择模式，输出匹配结果和执行耗时。
匹配大型文本时不能栈溢出——NFA 匹配用循环不用递归。cargo build 通过。

Rust 的所有权模型让实现更安全。
字符串处理注意 UTF-8 编码，不要按字节截断导致乱码。
