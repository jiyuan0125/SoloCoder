微服务架构下团队用 Protobuf 做服务间通信，.proto 文件越写越多，字段定义改来改去。手动检查 proto 文件的正确性效率太低了——字段编号有没有重复、引用的消息类型存不存在、oneof 里有没有冲突，这些问题靠人眼排查迟早漏掉。需要一个自动化工具来解析 .proto 文件，输出结构化的消息定义描述，同时做基本的正确性校验。用 Rust 写一个 Protobuf 文件解析器，集成到 CI 流水线里，每次提交 proto 文件变更时自动检查。

用 Rust 写一个 Protobuf 解析器：
- 解析 .proto 文件中的 syntax、package、message、enum 定义
- 支持 repeated、optional、map 字段修饰符
- 支持嵌套 message 和 oneof 类型
- 解析后输出消息的结构化描述（字段名、类型、编号）
- 能检测出字段编号重复、类型引用不存在等常见错误

这个工具在日常开发中能省不少重复劳动。
CLI：protobuf-parser api.proto，输出所有 message 和 enum 的结构。cargo build 编译通过。
