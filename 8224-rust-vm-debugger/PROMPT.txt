虚拟机跑起来遇到 bug 的时候，只有最终的输出结果能看，中间执行过程完全是黑盒——指令序列执行到哪一步出了问题？某个寄存器的值在什么时候被意外改写了？函数调用栈的深度是否符合预期？这些问题没有调试器根本没法排查。需要做一个类似 GDB 的交互式调试器：先加载字节码程序，然后在关键位置设断点，程序运行到断点处暂停，这时可以单步跟踪后续指令、打印寄存器和内存的当前值、甚至在线修改某个寄存器再继续执行。整个调试流程和 GDB 类似，只是操作对象从 x86 机器码变成了自定义字节码。
Rust 社区对这类工具有很大需求。

用 Rust 给虚拟机写一个调试器：
- 支持在指定指令地址设断点（break 0x10）
- 支持单步执行（step）和继续运行（continue）
- 支持查看和修改寄存器值（print R0、set R0 = 42）
- 支持查看栈内容和内存区域
- 支持 inspect 查看当前指令的反汇编
- 交互式命令行界面，输入命令控制执行
CLI：vm-debugger program.bc，进入交互调试模式。cargo build 编译通过。
