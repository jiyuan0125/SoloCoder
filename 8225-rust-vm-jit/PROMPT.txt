纯解释执行字节码，一条一条解码再分发执行，性能瓶颈很明显——热循环跑几百万次的时候，解释器的分支判断开销比实际计算还大。能不能像 JVM 的 HotSpot 那样给虚拟机加上 JIT 能力？思路其实不复杂：先用解释模式跑，同时统计每个函数被调用了多少次；一旦某个热函数的调用次数超过阈值，就把它编译成原生机器码缓存起来，下次再调用时直接跳到机器码执行，跳过解释开销。完全从零生成优化的机器码当然很难，但先用简单的 1:1 映射把字节码逐条翻译成机器码并不复杂，重点是理解 JIT 的触发条件和解释-编译混合执行的工作模式。

用 Rust 实现带 JIT 的虚拟机：
- 先用解释模式执行字节码，统计每个函数的调用次数
- 调用超过阈值的热函数触发 JIT 编译
- 把字节码翻译成机器码（先用简单的 1:1 映射）
- JIT 编译后的代码可以和解释执行混合运行
- 提供 --jit 和 --interpret 两种模式对比性能
CLI：vm-jit --jit run program.bc，输出执行结果和耗时统计。cargo build 通过。
