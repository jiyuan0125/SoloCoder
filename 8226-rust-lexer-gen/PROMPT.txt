做编译器的第一步永远是词法分析——把源码文本切成一个个 token。每个语言的 token 规则都不一样，手写词法分析器虽然不难但很枯燥，重复劳动多。如果有一个工具能根据 token 规则定义自动生成对应的 Lexer 代码就好了。思路是设计一套简单的 DSL 让用户描述 token 规则——标识符长什么样、数字怎么匹配、字符串怎么解析、注释怎么跳过——然后自动生成一份完整的 Rust Lexer 实现，包含 next_token() 接口，生成的代码能独立编译运行。这样以后做新语言只需要写规则文件，不用每次手写词法分析器。

用 Rust 写一个 Lexer 生成器：
- 用户用 DSL 定义 token 规则（如 NUMBER: [0-9]+、IDENT: [a-zA-Z_][a-zA-Z0-9_]*）
- 支持关键字、字符串字面量、注释的规则
- 处理规则的优先级（如关键字优先于标识符）
- 生成 Rust 源码的 Lexer，包含 next_token() 接口
- 生成的代码能独立编译运行

CLI：lexer-gen tokens.ldef --output lexer.rs，生成 Lexer 代码文件。cargo build 通过。
