Rust 生态里最有名的解析库之一就是 Pest，它用 PEG（解析表达式文法）而非 CFG 来定义语法规则，写起来比 BNF 简洁得多。但 Pest 内部是怎么把 .pest 文件编译成高效解析器的？选择操作 / 和顺序组合是怎么处理的？正向断言 & 和负向断言 ! 的回溯机制是怎样的？这些内部细节靠读源码很难理清。自己实现一个简化版 Pest 解析器，走一遍 PEG 规则的解析、状态机的构建、到最终递归下降代码生成的全流程。附一个 JSON 解析器作为端到端的验证示例。

用 Rust 实现一个 PEG 解析器（类似 Pest）：
- 支持 PEG 语法规则：sequence、choice（/）、optional（?）、repeat（* +）
- 支持 &expr（正向断言）和 !expr（负向断言）
- 支持 ..range 和 ASCII/Unicode 字符类
- 输入 .pest 风格的语法定义文件
- 自动从 PEG 规则生成 Rust 解析器
- 附带一个 JSON 解析器作为示例

CLI：pest-parser grammar.pest input.txt，解析输出 AST。cargo build 通过。
