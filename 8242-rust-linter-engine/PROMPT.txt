代码审查的时候，很多问题其实是重复出现的——未使用的变量、多余的 clone、不必要的 mut 声明、空 match arm 里漏掉了处理分支。这类机械性的问题每次都要人工 review，效率太低了，而且容易遗漏。Clippy 虽然能检查不少，但项目特有的规范它管不了——比如禁止使用某些 API、要求特定的错误处理模式、强制 import 分组方式。需要一个可配置的静态分析引擎：内置常见的代码质量规则，同时支持自定义规则扩展，让团队把代码规范沉淀到配置文件里，CI 跑一遍就能自动拦截大部分问题。

用 Rust 写一个 Linter 引擎：
- 解析源码，遍历 AST 执行检查规则
- 内置规则：未使用的变量/导入、冗余 clone、不必要的 mut、dead code
- 支持自定义规则（用 DSL 或 Rust 插件）
- 每条警告输出文件名、行号、规则名、说明
- 支持严重级别：error、warning、info
- 支持 .lintconfig.toml 配置开关规则

CLI：linter-engine src/ --config .lintconfig.toml，输出所有警告。cargo build 编译通过。
