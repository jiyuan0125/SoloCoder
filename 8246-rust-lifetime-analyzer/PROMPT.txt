Rust 生命周期标注有时候很难理解——'a: 'b 到底表示谁比谁长？为什么这里加个 'a 就编译过了？为什么编译器推断出来的生命周期和我想的不一样？想做一个工具来可视化分析生命周期关系：解析带生命周期标注的 Rust 函数签名，构建一个生命周期约束图（'a: 'b 表示 'a 不比 'b 短），然后计算最小化的生命周期集合，检测不可满足的约束。最后把生命周期的包含关系用可视化的方式展示出来，让开发者一眼就能看出哪个生命周期最短、哪些是等价的。对省略了生命周期标注的函数也做自动推断，和 rustc 的推断结果对比。
这类工具在 Rust 项目里非常实用。

用 Rust 实现生命周期分析器：
- 解析带生命周期标注的 Rust 函数签名
- 构建生命周期约束图（'a: 'b 表示 'a 比 'b 长）
- 计算最小化生命周期集合
- 检测不可满足的生命周期约束
- 可视化输出生命周期的包含关系图
- 对省略的生命周期做自动推断

这个工具在日常开发中能省不少重复劳动。
CLI：lifetime-analyzer function.rs，输出生命周期关系分析。cargo build 编译通过。
