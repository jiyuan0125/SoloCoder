普通 DCE 只删没人用的值，但很多"有定义"的指令其实也是废的——比如一个纯计算的结果没被任何人读，或者一个 if 分支的条件永远是 true 导致 else 块永远不会执行。这个 pass 要做得更彻底。Rust 实现。

激进 DCE（ADCE）的核心思路是反过来想：不是找"死代码"然后删，而是找"活代码"然后保留，剩下的全删。活代码的定义——有副作用的指令（Call、Store、Jump/Branch/Return）以及它们传递依赖的所有指令。传递依赖通过 def-use 链反向追踪：一条有副作用的指令的操作数是活的，产生这些操作数的指令也是活的，递归下去。

不可达代码消除：从入口块做 BFS，访问不到的块全部标记为不可达，直接删除。常量折叠后的空分支：如果 Branch 的条件是已折叠的常量，把不可达的那个分支块标记删除。

整个 pass 的执行顺序——先做不可达代码消除，再做常量折叠，最后做 ADCE，循环执行直到不再有变化。每轮统计删掉了多少条指令和多少个基本块，方便调试。

cargo test 用复杂的 IR 验证：嵌套分支含不可达块、循环体内的冗余计算、函数调用后的无用计算。cargo build 通过。
