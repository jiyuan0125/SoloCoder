之前做的编译器后端一直用无限虚拟寄存器，但真机就那么几个物理寄存器，分配不过来就得 spill 到内存。用 Rust 实现一个基于图着色的寄存器分配器，这是编译器后端最经典也最复杂的优化之一。

第一步构建活跃性分析（liveness analysis）：对每个 SSA 值，计算它在程序的哪些点"活跃"（从定义点到最后一个使用点之间的区间）。因为 SSA 每个值只定义一次，活跃区间就是一条简单的线段。遍历所有指令，记录每个虚拟寄存器的 def 点和最后一个 use 点。

第二步构建干扰图（interference graph）：两个虚拟寄存器如果在同一个程序点都活跃，它们之间就有一条边。干扰意味着不能分配到同一个物理寄存器。图用邻接表表示。

第三步图着色：用简化版的 Chaitin 算法。先做 simplify——反复从图中移除度数小于 K（可用寄存器数）的节点，压入栈。然后 select——从栈中弹出节点，给它分配一个和邻居不冲突的颜色。如果 simplify 阶段找不到可移除的节点，选一个 spill 候选（比如活跃区间最长的或使用频率最低的），标记为需要 spill，然后继续。

spill 处理：在 spill 的虚拟寄存器的 def 后插入 store 到栈槽，在每个 use 前插入 load 从栈槽加载。然后重新做活跃性分析和着色。

支持配置物理寄存器数量（默认 8）。cargo test 验证着色正确性和 spill 场景。cargo build 通过。
