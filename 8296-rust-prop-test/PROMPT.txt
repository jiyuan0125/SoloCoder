单元测试只能测你想得到的情况，但 bug 往往藏在边界条件里——空字符串、溢出、NaN、超长输入。Property-based testing 让你定义性质（property），框架自动生成海量随机输入来找反例。用 Rust 实现一个类似 QuickCheck 的框架。

先定义核心 trait Generator：每个实现该 trait 的类型能生成随机值。内置生成器：bool（均匀随机）、整数类型（均匀分布在范围内）、字符串（随机长度 + 随机 ASCII 字符）、Vec<T: Generator>（随机长度 + 逐个生成元素）、Option<T: Generator>（随机 Some/None）。随机源用简单的 xorshift 或 fastrand 算法。

Property 定义为闭包：Fn(&T) -> bool，输入随机生成的值返回是否满足性质。测试运行时反复生成输入调用 property，默认跑 1000 次。发现反例后启动 shrinking——把输入值逐步缩小（整数减小、字符串缩短、Vec 删元素），找到仍然触发失败的最小输入。

提供一个宏来简化定义：
```rust
property!(vec_reverse, |v: Vec<i32>| {
    let reversed: Vec<i32> = v.iter().cloned().rev().collect();
    let double: Vec<i32> = reversed.iter().cloned().rev().collect();
    v == double
});
```

cargo test 跑几个示例 property 验证框架。不依赖 proptest 或 quickcheck crate。cargo build 通过。
