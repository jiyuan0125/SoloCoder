Git 合并冲突有时候其实没那么严重——一边改了格式另一边改了内容，或者两边在不同的位置加了代码。手动打开冲突标记文件一个一个看太慢了。写一个冲突自动解决器，对能自动处理的冲突直接解决，不能的保留标记。Python 实现。

输入是包含 <<<<<<< HEAD / ======= / >>>>>>> branch-name 冲突标记的文本文件。工具逐个解析冲突块，对每个块应用策略：

策略选项：
- ours：始终采用我们的版本
- theirs：始终采用他们的版本
- union：合并两边（如果修改的是不同行且不重叠，把两边的改动都保留）
- smart：智能选择——如果一边只改了空白/格式而另一边改了内容，采用内容改动一边；如果两边改动完全相同，任意采用一边；如果两边改了不同行，合并两边改动

配置文件指定默认策略（JSON 或命令行参数），也可以对特定文件或路径模式指定不同策略。无法自动解决的冲突保留原始标记并在报告中列出。

统计输出：总冲突数、自动解决数、保留冲突数、每个冲突的策略决策日志。

CLI：python3 conflict_resolver.py --strategy smart merged_with_conflicts.txt -o resolved.txt。返回 0 全部解决，1 有残留冲突。纯 Python 3 标准库。
