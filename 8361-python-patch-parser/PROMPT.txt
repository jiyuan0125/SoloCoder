CI 管道里需要分析 PR 的 diff 来决定跑哪些测试——如果只改了文档就不跑全量测试，如果改了核心模块就触发完整回归。第一步得解析 patch 文件。Python 实现。

支持解析的格式：unified diff（标准 diff -u 输出）和 git diff 输出（包含 a/ 和 b/ 前缀，支持更多元数据）。

解析产出结构：
- Patch 对象：包含多个 FileDiff
- FileDiff：旧文件路径、新文件路径、是否新建/删除/重命名、文件模式变更（如 chmod +x）、二进制标记
- Hunk（差异块）：旧文件起始行号和范围、新文件起始行号和范围、行列表
- Line：类型（added/removed/context/No-newline-at-end）、内容

解析流程：逐行读取 patch 文件。遇到 --- a/path 和 +++ b/path 就开始一个新的 FileDiff。遇到 @@ -l,s +l,s @@ 就开始一个新的 Hunk。后续的 + - 空格 前缀行归类到当前 Hunk。

额外提取的信息：修改了哪些函数（如果 diff 中有 @@ 标注了函数名）、总共增删改了多少行、哪些文件是纯格式修改（只有空白变化）。

输出结构化 JSON，方便其他工具消费。CLI：python3 patch_parser.py changes.patch。纯 Python 3 标准库。
