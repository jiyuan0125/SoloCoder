文档覆盖率是代码质量的一个重要维度——注释太少后面维护的人看不懂，注释太多又说明代码本身不够自描述。写一个注释率分析工具来量化文档覆盖程度。Python 实现。

统计指标：
- 注释率 = 注释行数 / (代码行数 + 注释行数) × 100%
- Docstring 覆盖率 = 有 docstring 的函数/类数 / 总函数/类数 × 100%
- TODO/FIXME/HACK 数量

注释类型分类：
- 行内注释：代码行末尾的 # 注释
- 独立注释行：整行都是 # 注释
- Docstring：函数/类/模块的三引号字符串
- 块注释：连续多行的 # 注释（和上方代码之间有空行分隔）

分析粒度：
- 文件级别：每个文件的注释率和 docstring 覆盖率
- 函数级别：每个函数是否有 docstring、注释行数、代码行数
- 模块级别：按目录聚合统计

评级标准：注释率 15-25% 是健康范围（参考多种研究的建议）。<10% 文档不足，>40% 可能过度注释。Docstring 覆盖率目标 80%+。

输出终端表格，按注释率从低到高排列，文档不足的文件标红。python3 comment_ratio.py src/。纯 Python 3 用 ast 和 tokenize 模块。
