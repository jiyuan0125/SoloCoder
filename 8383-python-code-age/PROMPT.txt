代码库有些文件半年没人碰了，有些是上周刚写的。老代码通常更稳定（经过充分测试），新代码 bug 率更高。写一个代码年龄分析工具来量化代码的新旧程度。Python 实现。

数据来源：git log 获取每个文件每一行最后被修改的时间。用 git blame（或 git log -L）按行查询最后修改的 commit 日期。

聚合指标（按文件）：
- 平均年龄：文件所有行的最后修改时间的平均值
- 最大年龄：文件中最久没改的行的年龄
- 年龄中位数：比平均更抗极端值干扰
- 新代码比例：30 天内修改过的行占总行数的百分比
- 腐烂指数：(当前日期 - 平均最后修改日期) / 365，单位是"年"。超过 2 年的代码被认为是"腐烂"代码

按目录聚合：每个目录下所有文件的平均年龄。按年龄从老到新排列——最老的模块可能需要重新审视。

年龄分布可视化：把文件的行按年龄分组（<30天, 30-90天, 90天-1年, 1-3年, 3年+），显示每个年龄组的行数占比。

输出终端表格 + 年龄热力图（颜色越老越深）。python3 code_age.py /path/to/repo。纯 Python 3 + git 命令行。
