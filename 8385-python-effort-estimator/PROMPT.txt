项目排期总是不准——开发者估 2 天的活经常变成 5 天。想用代码度量来辅助估算，虽然不可能精确但至少比拍脑袋靠谱。Python 实现基于代码度量的工作量估算工具。

输入：一个功能需求的描述（文本）或者代码变更的范围（git diff 统计）。输出：预估的开发小时数和置信区间。

估算模型（简化的 COCOMO 式）：
- 基础工作量 = a × (KSLOC)^b，a 和 b 是校准参数（根据历史数据调整，默认 a=2.4, b=1.05）
- 复杂度调整因子 = 圈复杂度权重 × 平均复杂度 + 嵌套深度权重 × 平均嵌套
- 技术债调整 = 如果修改的文件技术债分数高（经常出 bug），增加 20-50% 的工作量
- 风险调整 = 如果修改涉及核心模块（高扇入），增加 30% 的工作量

多个维度可以手动调整权重。支持历史校准——输入过去 N 个任务的实际工时和代码度量，用最小二乘法拟合参数 a 和 b。

输出格式：预估工时（乐观/最可能/悲观三个值）、各调整因子的明细、置信区间。python3 effort.py estimate --diff changes.patch。python3 effort.py calibrate --history past_tasks.json。纯 Python 3。
