项目要求兼容 Python 3.8+，但开发者不小心用了 3.10 才有的语法（match-case）或标准库功能。CI 上跑低版本 Python 才发现就晚了。写一个静态版本兼容性检查器。Python 实现。

检查维度：
- 语法兼容性：用 ast 模块尝试解析源文件。如果解析失败，检查错误是否因为高版本语法——match/case（3.10+）、ExceptionGroup/except*（3.11+）、类型参数语法（3.12+）
- 标准库 API 兼容性：检查 import 和属性访问是否使用了目标版本没有的模块或函数。比如 tomllib 是 3.11 新增的，zoneinfo 是 3.9 新增的
- 内置函数兼容性：dict.merge（3.9+）、str.removeprefix/removesuffix（3.9+）、int.bit_count（3.10+）、ExceptionGroup（3.11+）
- 类型注解兼容性：内置泛型 list[int]（3.9+，之前需要 from typing import List）、ParamSpec（3.10+）、TypeVarTuple（3.11+）

版本特性数据库：一个 JSON 文件记录每个 Python 版本新增的语法、标准库模块、内置函数和类型。检查时对比目标版本过滤。

输出每个不兼容用法的文件:行号、使用的特性、引入的 Python 版本、目标版本不支持。按严重程度排序。

python3 version_checker.py src/ --target 3.8。纯 Python 3 用 ast 模块。
