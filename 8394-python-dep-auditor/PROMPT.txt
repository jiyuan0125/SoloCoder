npm 的 left-pad 事件告诉我们依赖管理的重要性——一个不起眼的包可能整个供应链都有问题。Python 实现一个依赖审计工具，检查项目依赖的健康状态。

审计维度：
- 过时检查：对比当前安装版本和 PyPI 最新版本。major 版本落后标红，minor/patch 落后标黄
- 已知漏洞：查 PyPI 的安全公告或者简单的本地数据库（已知有安全问题的包版本列表）
- 维护状态：包最后一次发布时间（超过 2 年没更新可能已废弃）、是否有活跃的 issue/pr、是否有弃用公告
- 传递依赖爆炸：显示每个直接依赖的传递依赖树。传递依赖总数 >50 的包标记为风险
- 重复依赖：同一个包的不同版本出现在传递依赖中（版本冲突）
- 许可证检查：每个依赖的许可证是否在白名单内

输出格式：
- 直接依赖列表（当前版本 → 最新版本，是否过时）
- 风险报告（有漏洞的包、废弃的包、许可证问题的包）
- 传递依赖树（可视化依赖关系）
- 审计评分：A（无问题）到 F（严重问题）

python3 dep_auditor.py requirements.txt。纯 Python 3 + requests（查 PyPI API）。
