Splay Tree 的思路很特别——不做显式的平衡操作，而是每次访问一个节点就把它旋转到根。这样最近访问的节点总是靠近根，对局部性好的访问模式（比如缓存）性能很好。Go 实现。

Splay 操作（把节点 x 旋转到根）分六种情况：
- x 的父节点是根：单旋转（Zig）
- x 和父节点都是左子/都是右子（同侧）：先旋转父节点再旋转 x（Zig-Zig）
- x 和父节点不在同侧：先旋转 x 再旋转 x（Zig-Zag）

每一步都保持 BST 性质不变。经过 O(log n) 步旋转后 x 到达根节点。

操作：Search 时先做普通 BST 查找，找到后对该节点做 Splay。Insert 时先做普通 BST 插入，然后对新节点做 Splay。Delete 时先 Splay 目标节点到根，然后删除根并把左右子树合并（右子树的最小节点成为新根）。

摊还分析下所有操作 O(log n)，但最坏情况单次操作可能 O(n)。写个 main 演示局部性优势：先访问 1-100，然后重复访问 50-60 这 10 个 key，统计 Splay Tree 和普通 BST 的查找深度对比。go build 通过。
