分布式缓存集群有 5 个节点，新加一个节点时不能让所有 key 重新映射——一致性哈希就是解决这个问题。当节点数从 N 变成 N+1，只有 1/(N+1) 的 key 需要迁移。Go 实现。

算法：把整个哈希值空间 [0, 2^32) 首尾相连形成一个环。每个节点通过哈希函数映射到环上的一个或多个位置（虚拟节点）。每个 key 也哈希到环上，顺时针找到第一个节点就是它的归属节点。

虚拟节点（VNode）：每个物理节点在环上放多个虚拟节点（比如 150 个），用不同的哈希种子或编号：hash("node1#0")、hash("node1#1")...虚拟节点让 key 的分布更均匀，避免数据倾斜。

节点变更：加入新节点时，新节点的虚拟节点插入环中，只影响相邻虚拟节点之间的 key（即 1/(N+1) 的比例）。删除节点同理，受影响的 key 迁移到下一个节点。

操作：AddNode(node)、RemoveNode(node)、GetNode(key) → node。虚拟节点数量可配置。

写个 main 做 benchmark：100 万个 key 分配到 100 个桶，统计均匀性。然后桶数从 100 变到 101，验证迁移比例。go build 通过。
