Maglev Hashing 是 Google 的负载均衡器用的哈希算法，用在 VIP 到后端的映射表上。和一致性哈希不同，它生成一个查找表实现 O(1) 查询，同时保持后端故障时的最小迁移。Go 实现。

算法分两步：
1. 生成每个后端的偏好列表（permutation）：对每个后端 j，用两个不同的哈希函数计算 offset 和 skip，然后生成偏好序列：(offset + i×skip) mod M，i = 0,1,2,...。这个序列是后端 j 希望占据的槽位列表
2. 填表：N 个后端各自拿出偏好列表的下一个槽位，如果该槽位还没被占就填上后端名。如果被占了就看下一个偏好。Round-robin 方式轮流让每个后端尝试填表，直到所有槽位都被填满

后端故障时只需重新计算查找表——故障后端的槽位会被其他后端的偏好列表填补，大部分映射不变。

参数：查找表大小 M 选质数（如 65537），后端数量 N 通常几十到几百。M >> N 保证均匀。

操作：Build(backends)、Lookup(key) → backend、AddBackend(b)、RemoveBackend(b)（后两个触发重建）。

写个 main：7 个后端构建 65537 大小的查找表，统计每个后端分配到的槽位数。然后下线一个后端，看多少映射变了。go build 通过。
