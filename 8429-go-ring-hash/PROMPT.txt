实现一个 Ring Hash（也叫 Ketama Hash），用于分布式缓存场景的 key 分配。Go 语言。

Ring Hash 是一致性哈希的经典实现——一个物理节点对应多个虚拟节点，每个虚拟节点占环上的一个位置，key 顺时针找最近节点。通过调整虚拟节点数量实现权重分配。

结构设计：环用排序数组存储所有虚拟节点的 (hash, nodeID) 对。Get(key) 时先算 key 的哈希，然后二分查找找到第一个大于等于该哈希的虚拟节点，返回对应的物理节点。

关键参数：
- 虚拟节点倍数：默认每个物理节点 100 个虚拟节点。权重为 2 的节点放 200 个虚拟节点
- 哈希函数：用 xxhash 或 fnv（比标准库的 crc32 分布更好）
- 查找表大小：就是虚拟节点总数 = Σ(每个节点的权重 × 倍数)

节点变更处理：AddNode 时在排序数组中插入新的虚拟节点（用 sort.Search 找位置）。RemoveNode 时删除对应的虚拟节点。每次变更后受影响的 key 只是新/删节点附近的 key。

均衡性验证：统计每个物理节点实际分到的 key 数量 / 期望数量的比值。理想情况所有比值接近 1.0，偏差在 ±10% 以内。

写个 main：5 个节点（权重 1:1:2:3:3），100 万个 key，统计分配比例是否符合权重。然后下线一个节点重新分配。go build 通过。
