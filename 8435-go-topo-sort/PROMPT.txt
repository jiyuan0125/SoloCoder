编译器要根据模块依赖确定构建顺序，有循环依赖就得报错。拓扑排序是经典解法，但只输出"检测到环"远远不够——开发者需要知道环在哪，A→B→C→A 这条环路径必须完整输出才能快速定位问题。

Go 实现两种拓扑排序算法。Kahn 算法 BFS 方式：先计算所有节点的入度，入度为 0 的节点进队列。依次弹出节点并将其所有邻居的入度减一，邻居入度归零就入队。弹出的顺序就是拓扑排序结果。如果最终弹出的节点数小于总节点数就说明存在环，报告哪些节点未能被处理。DFS 方式用三色标记法：白色未访问、灰色正在访问、黑色已完成。回溯时把节点加入结果列表最后反转得到拓扑序。DFS 过程中遇到灰色节点就说明有环，从当前递归栈里提取出完整的环路径。

图用邻接表表示，支持从文本文件读取依赖关系，每行格式 A B 表示 A 依赖 B 即 B 是 A 的前置。也提供 API 支持代码直接调用传入边列表构建图。

命令行工具读依赖文件后输出编译顺序列表，有环时输出环路径和涉及的所有节点。准备两组测试数据：5 个模块的无环依赖验证排序正确，以及 A→B→C→A 循环依赖验证环检测。Go 标准库实现，go build 通过。
