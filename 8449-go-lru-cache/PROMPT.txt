做一个线程安全的 LRU 缓存，Go 实现。用在 HTTP 代理服务器里缓存响应。

LRU（Least Recently Used）的淘汰策略——容量满了后删除最久没被访问的条目。O(1) 的 Get 和 Put 靠哈希表 + 双向链表实现。

数据结构：map[key]*Node 提供O(1)查找，双向链表维护访问顺序——最近访问的移到头部，尾部的是最久没用的。Node 包含 key、value、prev、next 指针。

操作实现：
- Get(key)：查 map，命中则把节点移到链表头部并返回 value。未命中返回 -1（或零值 + false）
- Put(key, value)：查 map，已存在则更新 value 并移到头部。不存在则创建节点插入头部，加入 map。如果超过容量，删除链表尾部的节点（同时从 map 中删除）
- Delete(key)：从 map 和链表中移除
- Len()：返回当前缓存条目数
- Clear()：清空所有条目

并发安全：用 sync.RWMutex 保护——Get 用读锁，Put/Delete 用写锁。或者用分片锁（多个独立的 LRU 分片，每个有自己的锁）减少锁竞争。

写个 main 测试：容量设为 1000，并发插入和读取 10 万次（多个 goroutine），验证容量限制和淘汰正确性。go build 编译通过。
