数据库 crash 后重启，第一件事就是读 WAL 重建内存状态。Writer 往里写了什么格式，Reader 就得按什么格式读出来——包括跨 block 的大记录拼接和 CRC32 校验。上个项目写了 Writer，这个写配套的 Reader。

按 32KB 的 block 读取日志文件，解析每条记录的 header（checksum 4B + length 2B + type 1B）。四种 record type 的拼接逻辑：full 表示完整记录一口读完，first 是大记录的开头，middle 是中间段，last 是尾巴——遇到 first 开始攒，middle/last 追加，攒满就是一条完整记录。每条完整记录都要校验 CRC32，校验失败由调用方决定跳过还是中止。

提供迭代器接口 Next() (key, value, opType, error)，遇到 EOF 或全零 header（截断 block）正常结束。block 尾部的 zero padding 不算有效记录。

bufio.Reader 做缓冲。go build 通过。能正确读取前一个 WAL Writer 写出的文件。
