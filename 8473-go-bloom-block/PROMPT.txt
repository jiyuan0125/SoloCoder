一个 4KB 的 data block 里有几千个 key，磁盘读一次要 0.1ms。如果 99% 的查询都 miss，那 99% 的磁盘读取全是浪费。Bloom filter 块就是干这个的——用几 KB 的位图快速判断 key 大概率不在 block 里，直接跳过读取。可能误报但不漏报。Go 实现。

每个 data block 对应独立的一段 bitset。构建 SSTable 时收集每个 block 的 key 集合，按 1% 误报率配置位数组大小（m = -n×ln(p)/(ln2)^2），哈希函数个数 k = m/n × ln2。查询时先定位到对应 block 的 bloom 段，检查所有哈希位——全命中才去读磁盘，任何一个 miss 直接跳过。

哈希函数用 double hashing 模拟：hashes[i] = h1 + i×h2。序列化格式是段数 + 每段偏移 + bitset 数据，反序列化后常驻内存。
