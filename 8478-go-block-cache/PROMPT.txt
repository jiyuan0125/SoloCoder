LSM-Tree 的读路径有个致命弱点——同一个热点 key 可能触发几十次磁盘读取（每层 SSTable 都要查一遍）。Block Cache 把读过的 data block 缓存在内存里，下次命中直接返回，不用再走磁盘。RocksDB 靠这个把读延迟从 10ms 降到 0.1ms。Go 实现。

LRU 策略，key 是 fileID + blockOffset 组合的 128-bit hash。限制最大内存占用（按字节数不是条目数），超限驱逐最久未访问的条目。高并发场景下用分片锁——16 到 64 个 shard 各自一把锁，分片函数 key % shardCount，每个 shard 内部双向链表 + map 做标准 LRU。

统计命中率（hit/miss/eviction），提供 Stats() 接口。条目放入时记录字节大小，维护总占用近似值。
