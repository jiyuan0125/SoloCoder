磁盘上散落着几百个 SSTable 文件，崩溃后重启怎么知道哪些文件属于哪层、哪些已经被 compaction 清理了？Manifest 就是"数据库的数据库"——记录所有状态变更历史：哪个文件被创建、哪个被删除、哪次 compaction 完成。Go 实现。

记录格式参考 LevelDB 的 log format：record type（ADD/DELETE/NEW_CURRENT）+ level + file metadata（id, size, smallest/largest key）。每次 flush 完成、compaction 完成、文件删除都追加一条记录到 manifest 文件，每条带 CRC32 校验。

定期做 checkpoint：把当前完整状态快照写入新 manifest 文件，恢复时读最新 checkpoint 再重放之后的增量记录就行，不用从头回放几万条历史。manifest 文件太大时滚动创建新的，旧的保留备份。损坏的记录跳过并报警。

go build 通过。
遇到异常情况输出清晰的错误信息到 stderr，带上上下文方便定位问题。
