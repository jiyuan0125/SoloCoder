读操作正在进行的时候，后台 compaction 把文件重组了——如果读操作直接引用文件列表，可能读到一半文件被删了。Version 机制解决这个问题：每次 compaction/flush 生成一个不可变的新 version，读操作引用旧 version 不受影响，这就是 LSM-Tree 里的 MVCC。Go 实现 Version Set。

Version 结构是每层 SSTable 文件列表的不可变快照，带引用计数。VersionSet 管理当前 version（current）和历史版本链。读操作 Ref 当前 version，用完 Unref——引用计数归零才能回收文件资源。

新 compaction/flush 完成后创建新 version（应用增量变更：哪些文件加了、哪些删了），通过 manifest 持久化（LogAndApply）。current 指针切换要原子化，用 atomic pointer 或 mutex 保护。
