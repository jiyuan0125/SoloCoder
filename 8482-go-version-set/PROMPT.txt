读操作正在进行的时候，后台 compaction 把文件重组了——如果读操作直接引用文件列表，可能读到一半文件就被删了。Version 机制解决的就是这个问题：每次 compaction 或 flush 生成一个不可变的新 version，读操作引用旧 version 完全不受影响，这就是 LSM-Tree 里的 MVCC。Go 实现 Version Set。

Version 结构是每层 SSTable 文件列表的不可变快照，带引用计数。VersionSet 管理当前活跃 version 即 current 和历史版本链表。读操作开始时 Ref 当前 version，用完 Unref——引用计数归零才能回收该 version 引用的文件资源。新 compaction 或 flush 完成后创建新 version：应用增量变更记录哪些文件新增了哪些删除了，通过 manifest 持久化 LogAndApply。current 指针的切换要原子化，用 sync.RWMutex 或 atomic pointer 保护。

支持回滚：如果新 version 创建过程中出错可以丢弃，current 指针不变。go build 通过。
