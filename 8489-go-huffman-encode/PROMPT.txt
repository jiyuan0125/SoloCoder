deflate、JPEG、PNG 这几个压缩格式有什么共同点？底层都用 Huffman 编码。原理很直觉：出现频率高的字符用短码（比如 'e' 只需 3 bit），频率低的用长码（'z' 可能要 10 bit），平均编码长度逼近信息熵下界。Go 写一个编码器。

先统计输入数据的字节频率（256 个桶），用最小堆（container/heap）构建 Huffman 树——每次取两个最小频率节点合并，直到只剩一棵树。从根到叶子的路径（左 0 右 1）就是编码表。

编码时按编码表把字节流转成 bit 流（byte 数组模拟），最后一个字节记录有效 padding 位数。输出要自包含：频率表（256 个 uint32）+ 原始 bit 长度（uint64）+ 压缩 bit 流，解码端不需要额外信息。支持 canonical Huffman code（按符号值排序分配编码，存储更紧凑）。

边界情况：只有一个唯一字符（编码为单个 0 bit）、空输入直接返回空。go build 通过。
