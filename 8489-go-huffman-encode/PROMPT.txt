deflate、JPEG、PNG 这几个压缩格式有什么共同点？底层都用 Huffman 编码。原理很直觉：出现频率高的字符用短码比如 'e' 只需 3 bit，频率低的用长码 'z' 可能要 10 bit，平均编码长度逼近信息熵下界。Go 写一个编码器。

先统计输入数据的字节频率分布 256 个桶，用 container/heap 构建最小堆驱动的 Huffman 树——每次弹出两个最小频率节点合并为新节点，重复合并直到只剩一棵树。从根到叶子的路径左 0 右 1 就是每个符号的编码表。

编码时按编码表把字节流转换成 bit 流用 byte 数组模拟，最后一个字节可能有 padding 需要记录有效 bit 位数。输出格式要自包含：频率表 256 个 uint32 加上原始 bit 长度 uint64 再加压缩后的 bit 流，解码端不需要任何额外信息。支持 canonical Huffman code 按符号值排序分配编码，存储更紧凑只需要记录每个位宽有几个符号。

边界情况：只有一个唯一字符编码为单个 0 bit、空输入直接返回空结果。Go 标准库，go build 通过。
