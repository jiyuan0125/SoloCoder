编码器把一段文本压成了几十个字节，怎么还原？从压缩数据头部读出频率表重建 Huffman 树，然后逐 bit 遍历——从根节点出发 0 走左子树 1 走右子树，走到叶子节点就输出一个解码字符。Go 写 Huffman 解码器。

头部格式支持两种方式：频率表重建树 256 个 uint32 加原始 bit 长度 uint64 简单直观容易实现，或者 canonical code 加符号列表只存位宽分布更紧凑节省空间。最后一个字节可能有不完整的 padding bit，头部记录了有效 bit 数，解码时尾部必须忽略多余的无效 bit 防止解码出错误数据。

性能优化很关键：预建 8-bit 查找表总共 256 项，一次查表能解码 1 个或多个符号，不用每个 bit 都走一遍树结构速度提升几十倍。退化情况也要处理——只有 1 到 2 种字符时 Huffman 树退化成单条链，查表优化失效但基本的逐 bit 遍历逻辑必须仍然正确输出。

canonical code 按位宽从小到大排序分配编码，解码时用位宽信息还原出完整编码表。支持流式解码大文件不一次性加载。Go 标准库，go build 通过。
