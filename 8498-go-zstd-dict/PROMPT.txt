500 字节的 RPC payload 用 LZ77 压缩——窗口才 500 字节，里面几乎找不到重复串，压缩率不到 5%。但如果给一个预训练字典（从历史消息中提取的高频子串），压缩时字典作为"之前已经见过的数据"初始化滑动窗口，同样的 500 字节能压到 40%。Facebook 的 Zstandard 就是这么干的。Go 实现字典构建和序列化。

字典构建：从一组训练样本（建议 ≥ 100 条）中提取高频子串，用 N-gram 统计或 suffix array 找重复模式，选出最有区分度的 32KB 内容。字典格式：magic number (0x37A4ED11) + dictionary ID (uint32) + histogram 数据 + 词表内容。

压缩端用字典初始化滑动窗口虚拟前缀，解压端也要加载对应字典（通过 ID 匹配），否则解不出来。支持字典的序列化和加载，多字典 ID 管理。

不要做完整的 zstd 压缩格式，重点做字典的构建和序列化。go build 通过。
字典 ID 冲突或者格式不对时要报错，别静默用错字典导致解压出来一堆乱码。
训练样本太少（少于 10 条）时给出警告，字典质量会严重下降。
