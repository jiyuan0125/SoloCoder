之前在做一个 ID 追踪系统，用户 ID 从注册开始自增，有些业务场景下 ID 是连续的或大段连续的——比如批量导入的 10000 个用户，ID 从 500001 到 510000。这种数据用普通位图存太浪费了，一万位才 1.2KB，但存一亿个稀疏 ID 就要 12MB。RLE 位图用 [start, length] 对来表示连续段，压缩效果取决于连续性。

用 Go 实现一个 RLE 压缩位图。内部存储是一组有序的 run（区间段），每个 run 表示 [start, end) 的连续位。空位图没有任何 run。

Add 操作：插入一个位，找到它应该落在哪个 run 旁边，如果和已有的 run 相邻或重叠就合并。比如已有 [10,20)，插入 9 变成 [9,20)，插入 21 变成 [10,21)。Remove 操作：删除一个位，可能把一个 run 拆成两个——比如 [10,20) 删除 15 变成 [10,15) 和 [16,20)。Contains 操作：二分查找对应的 run。

集合运算：AND 返回两个位图的交集（找重叠区间段），OR 返回并集（合并所有区间段），XOR 返回对称差。这些操作都可以用双指针归并的方式高效完成，时间复杂度 O(n+m)。

序列化：把 run 数组编码成字节流（每个 run 用 varint 编码 start 和 length），反序列化恢复。Go 标准库，go build 通过。空位图和包含超大值（超过 uint32 范围）的情况都要正确处理。
