Python 和 Java 默认排序都用 Tim Sort，不是没道理的——真实世界的数据经常是"大部分有序、局部有乱序"的，普通快排对这种数据没有任何特殊优化，但 Tim Sort 能自动检测已有的有序段（run），直接拿来做归并，几乎白赚。

1. run 检测和扩展。从左到右扫描输入数组，识别连续递增或严格递减的子序列作为一个 run。如果 run 长度小于一个阈值 minRun（通常取 16-32），就用插入排序往右扩展到 minRun 长度。递减的 run 反转成递增。

2. 归并栈。把检测到的 run 压入一个栈，栈里的 run 需要满足两个不变量（保持归并效率和稳定性）：栈顶往下第 3 个 run 的长度 > 第 2 个 + 第 1 个，以及第 2 个 > 第 1 个。不满足就和较短的邻居归并。归并用标准的双缓冲区归并。

3. 稳定性。整个排序过程必须是稳定的——相同值的元素保持原始相对顺序。插入排序是稳定的，归并也是稳定的（相等时取左边 run 的元素优先）。

4. 性能。最坏 O(n log n)，最好（已排序数组）接近 O(n)，因为每个元素本身就是 run 不需要额外操作。对部分有序数据比标准库的 sort.Slice 快。

minRun 的选取：取使得 n/minRun 恰好是 2 的幂或略小的值。Go 标准库实现，go build 通过。
