C++ 的 std::sort 为什么快？因为它底层用的 Intro Sort 是个混血——正常情况下跑快速排序，发现递归太深（说明 pivot 选得不好、快排要退化）就切换到堆排序保底，小范围切换到插入排序省常数开销。三种算法各取所长。

用 Go 实现完整的 Intro Sort——

快排阶段：选 pivot 用三数取中法（首、中、尾三个元素的中位数），partition 用 Hoare 或 Lomuto 方案都行。每进入一层递归，深度计数器加一。

深度检测：初始深度限制设为 2×⌊log₂(n)⌋。如果递归深度超过这个限制，说明快排在这个数据上可能要退化到 O(n²) 了，立即切换到堆排序处理当前子数组。堆排序最坏 O(n log n)，保证整体不会爆炸。

插入排序阶段：当子数组长度小于 16（阈值可以微调），切换到插入排序。小数组上插入排序没有递归开销，常数因子更小。插入排序从左到右，每个元素往前面已排序的部分找位置插入。

泛型支持：用 Go 泛型约束 cmp.Ordered，或者接受自定义的比较函数。API 对外暴露一个函数 Introsort(data []T)。

三种排序的切换逻辑要正确——不能漏掉某个分支导致快排一直跑到底。写个测试：对已排序数组、逆序数组、全相同值、锯齿形数据（1,3,5,7,2,4,6,8...）分别排序，验证都能在合理时间内完成。

Go 标准库，go build 通过。
