线上日志系统要同时检测几十个关键词——error、warning、panic、timeout 等等。一个一个 grep 太慢了，O(k×n) 的时间完全不可接受。Aho-Corasick 算法建好自动机之后一次扫描就能找到所有模式串，O(n + m + z)，z 是匹配数。

实现步骤——

第一步，构建 Trie 树。把所有模式串插入 Trie，每个节点有转移 map 和 fail 指针。模式串末尾的节点标记为输出节点，记录是哪个模式串。

第二步，计算 fail 指针。用 BFS 层序遍历 Trie。根节点的 fail 指向自己。对于节点 u 的每个字符 c 的子节点 v：从 u.fail 开始沿 fail 链找到有 c 转移的节点 w，v.fail = w 通过 c 转移到的节点。如果一直找不到（回溯到根节点），v.fail = root。同时把 fail 节点的输出合并到当前节点的输出列表（输出链接）。

第三步，匹配扫描。从根节点出发，逐字符扫描输入文本。当前节点有 c 的转移就走下去，没有就沿 fail 链跳转直到找到有 c 转移的节点或回到根节点。每次走到一个节点，检查它和它的 fail 链上的输出节点，记录所有匹配。输出每个模式串在文本中的所有出现位置（起始和结束索引）。

关键词列表从文件按行读取。支持 UTF-8 字节流。空关键词跳过。重复的匹配结果去重。Go 标准库，go build 能编译通过。
