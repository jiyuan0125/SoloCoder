为什么字符串搜索要用 KMP 而不是暴力匹配？暴力方法在匹配失败时把模式串往右移一位从头开始，最坏 O(n×m)。KMP 的精妙之处在于它利用了之前已经匹配过的信息——匹配失败时不是回到开头重来，而是跳到模式串中间某个已知可以继续的位置，主串指针永远不回退。

用 Go 实现 KMP 字符串搜索。

next 数组（前缀函数/部分匹配表）的计算——next[i] 表示 pattern[:i+1] 这个前缀中，既是前缀又是后缀的最长子串的长度（不包括自身）。计算方法：用一个循环从 i=1 开始，维护一个 j 表示当前最长相等前后缀长度。如果 pattern[i] == pattern[j]，j++ 然后 next[i]=j；如果不等且 j>0，j = next[j-1] 然后重试；如果 j==0，next[i]=0。

搜索过程——两个指针 i（主串）和 j（模式串）。如果 text[i] == pattern[j]，双双前进。如果不等：如果 j>0，j = next[j-1]（利用已知信息跳转，不回退 i）；如果 j==0，i++。当 j == len(pattern) 时找到一个匹配，记录起始位置 i-j，然后 j = next[j-1] 继续找下一个匹配。

退化情况测试——模式串 "aaaaa" 在主串 "aaaaaaaaaa" 中搜索。暴力方法每次只移动一位（最坏 O(n×m)），KMP 能高效处理这种情况（O(n+m)）。

命令行接收模式串和文件路径，输出所有匹配的起始位置（0-based）。Go 标准库，go build 编译通过。
