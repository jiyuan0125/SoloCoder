在英文长文本里搜一个关键词，理论上最快的算法是 Boyer-Moore——它从模式串的末尾开始比较，不匹配时根据 bad character 和 good suffix 两张表跳过一大段文本，实际比较次数经常远小于文本长度。在某些场景下能达到 sublinear 的效果。

1. Bad Character 表。对模式串中每个出现的字符 c，记录它最后一次出现的位置（从右往左数）。匹配失败时，如果失配位置的文本字符 c 在模式串中出现过，就把模式串右移到 c 对齐上次出现的位置；如果没出现过，直接把模式串跳过这个字符。右移量 = max(1, j - bc[text[i+j]])。

2. Good Suffix 表。匹配失败时，已经匹配成功的后缀可能在模式串的其他位置也出现过。good suffix 表记录：当模式串位置 j 失配且后缀已匹配长度为 k 时，模式串至少要右移多少才能让相同的后缀对齐。构造 GS 表比较复杂——需要计算 suffix 数组然后推导偏移量。

3. 匹配过程。从右往左比较模式串和文本。失配时取 bad character 和 good suggestion 两张表中较大的跳转量（保证不错过可能的匹配）。重复直到模式串滑过整个文本。

4. 输出。找到所有匹配位置，返回 0-based 起始索引。

对短模式串 bad character 规则的表现测试——模式串只有 2-3 个字符时跳转量很小，但仍然是正确的。Go 标准库，go build 编译通过。
