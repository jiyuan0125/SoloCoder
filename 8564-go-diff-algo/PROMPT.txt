文本比较工具有很多种 diff 算法，不同的算法对同一组输入可能产生不同的差异结果。想做一个通用的 diff 库，支持切换不同的底层算法，方便比较哪种算法的结果更合理。

实现步骤——

第一步，统一接口。定义 DiffResult 类型：一组 Operation（INSERT/DELETE/EQUAL），每个 Operation 包含类型、内容（一行或多行文本）。定义 DiffAlgorithm 接口：Diff(a, b []string) []Operation。所有算法实现这个接口。

第二步，基于 LCS 的 diff。用 LCS 找出两个行数组的公共行，不在 LCS 中的行按位置关系标记为 INSERT 或 DELETE。这个方法产生的差异通常比较稳定可预测。

第三步，基于编辑距离的 diff。用动态规划找把 a 变成 b 的最小编辑序列。每个操作是 INSERT（加一行）、DELETE（删一行）或 REPLACE（改一行）。这种方法可能产生不同的差异结果——比如把一行删除再插入可能被解释为替换。

第四步，CLI 工具。接收两个文件路径，输出 diff 结果。默认用 LCS 方式，可以通过 -algo 参数切换算法（lcs 或 edit-distance）。输出格式统一，不管底层用什么算法。

Go 标准库，go build 通过。两种算法的结果都用相同的 DiffResult 格式，上层代码不需要关心底层实现。
