Git 的 patience diff 模式据说对代码变更的展示效果更好——它不会因为两段代码有相同的空行或大括号就错误地把不相关的代码关联起来。原理是先找出两端唯一的公共行作为锚点，然后对每对锚点之间的部分递归做比较。结果更符合程序员的直觉。

用 Go 实现 patience diff 算法。

第一步，找唯一公共行。遍历两个文件的行数组，找出在两边都只出现一次的行（唯一行）。这些唯一行就是锚点候选。

第二步，在唯一公共行上求 LCS。把这些唯一公共行按在两个文件中的位置排序，求它们的最长递增子序列（LIS）。LIS 中的行就是最终的锚点——它们在两个文件中都有唯一的对应关系。

第三步，递归比较。在相邻锚点之间的文本段递归应用 patience diff 或者普通 LCS diff。如果段很短就直接用 LCS 比较。锚点行本身标记为 EQUAL。

第四步，输出结果。用标准 diff 格式输出：+ 表示新增，- 表示删除，空格表示不变。对差异部分加上上下文行方便阅读。

测试——用包含大量重复行的代码文件（比如很多 } 和空行）做对比，看看 patience diff 是不是真的比普通 LCS diff 的结果更好理解。边界情况：两个文件完全相同、完全不同。

Go 标准库，go build 编译通过。
