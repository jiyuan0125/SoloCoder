很多 diff 工具的核心都是 Myers 算法——Git 的 diff 引擎、diffutils 的实现都用了它或者它的变体。它的特点是时间复杂度 O((M+N)D)，D 是最小编辑距离。对于代码变更这种编辑距离通常很小（改了几行）的场景，Myers 比 O(MN) 的 DP 快得多。

用 Go 实现 Myers diff 算法。

算法核心是在 edit graph 上找最短路径。把两个序列画成二维网格——横轴是序列 a 的位置，纵轴是序列 b 的位置。沿对角线移动是"相等"（免费），向下移动是"删除"，向右移动是"插入"。找从 (0,0) 到 (M,N) 的最短路径，就是找最少的非对角线移动。

算法用 BFS 逐层扩展——d 从 0 到 max(M,N)，每层记录可以到达的最远对角线位置。用一维数组 V 记录每条对角线 k 上能到达的最远 x 坐标。每一步尝试向前移动，然后沿对角线尽可能走远。

输出最短编辑脚本（SES）——记录每一步做了什么操作（保持/删除/插入），然后生成类似 unified diff 格式的输出。+ 表示新增行，- 表示删除行。

和朴素 DP 的性能对比——对编辑距离很小（只改了几行）的两个文件，Myers 应该明显更快。对编辑距离很大（完全不同的两个文件），退化和 DP 差不多。

输入两个字符串数组或文件路径，输出差异。Go 标准库，go build 通过。
