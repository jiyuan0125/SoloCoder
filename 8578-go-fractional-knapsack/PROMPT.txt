背包问题有个特殊版本——物品可以分割。比如往油箱里加不同标号的燃油，每种有总量和单位价格，油箱容量有限。想加价值最高的油但装不下的那一种可以只加一部分。这种情况下贪心策略就是最优的，不像 0-1 背包那样需要 DP。

用 Go 实现分数背包问题求解。

贪心策略——计算每种物品的单位价值（value/weight）。按单位价值从高到低排序。然后依次取物品：如果当前物品能完整放入（剩余容量 >= 物品重量），全部放入。否则只放一部分（取剩余容量对应的量），背包就满了。这一步之后停止。

输出最大价值和每种物品的选取比例——比如物品 A 选了 100%（全取）、物品 B 选了 50%（取一半）、物品 C 选了 0%（没取到）。

和 0-1 背包的对比——用同一组数据分别跑分数背包和 0-1 背包，展示分数背包的结果一定 >= 0-1 背包（因为分数背包允许分割，解空间更大）。对比输出两个结果，让贪心在分数背包上的最优性一目了然。

边界处理——物品数量为 0 返回 0。容量为 0 返回 0。物品重量为 0 但价值为正的应该全取（不占容量）。排序用 sort.Slice 按单位价值降序排列。

Go 标准库，go build 通过。时间复杂度 O(n log n)（排序的复杂度），贪心选取是 O(n)。
