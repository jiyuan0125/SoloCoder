分布式任务调度里最基本的问题——把 n 个任务分给 m 个工人，怎么分才能让总完成时间最短？比如有 6 个任务耗时 [5, 2, 4, 3, 1, 6]，3 个工人。贪心做法是每次把当前任务分配给负载最轻的工人，近似比是 2 倍最优解。

用 Go 实现两种任务分配算法。

贪心分配（List Scheduling）——按任意顺序遍历任务，每次把当前任务分配给当前总负载最轻的工人。用一个最小堆维护工人的当前负载。每次分配 O(log m)。总时间 O(n log m)。输出每个工人的任务列表和总负载。

LPT 启发式（Longest Processing Time First）——先把任务按执行时间从大到小排序，然后用贪心分配。先分配长任务可以避免最后只剩长任务被迫分配给某个工人导致严重不均衡。近似比提升到 4/3 倍最优解。

匈牙利算法（如果任务数 = 工人数）——如果每个工人只做一个任务且每个任务恰好分配给一个工人，代价矩阵 cost[worker][task] 已知，用匈牙利算法求最小总代价的完美匹配。实现经典的 O(n³) 版本。

输入——任务列表（每个任务有 ID 和执行时间）和工人数量。也支持代价矩阵模式（二维数组）。从文件或命令行读取。

输出每个工人的任务列表、总负载、以及全局最大负载（makespan）。三种策略的结果对比。Go 标准库，go build 通过。
