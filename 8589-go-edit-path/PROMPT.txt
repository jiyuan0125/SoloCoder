光知道编辑距离是 3 不够用——用户要知道具体哪 3 步、每步在什么位置做了什么。比如把 "kitten" 变成 "sitting" 需要把 k→s、e→i、插入 g 三步。编辑路径回溯就是在 DP 表的基础上逆向追踪出完整的操作序列。

实现步骤——

第一步，构建完整的 DP 表。和标准编辑距离一样，建 (m+1)×(n+1) 的表。每个格子 dp[i][j] 还需要记录是从哪个方向来的（用于回溯）。方向有三种：上方（删除）、左方（插入）、左上角（匹配或替换）。

第二步，回溯操作序列。从 dp[m][n] 出发，检查当前格子是从哪来的。如果来自左上角且 s[i-1]==t[j-1]，这是匹配（无需操作）。如果来自左上角且 s[i-1]!=t[j-1]，这是替换操作。如果来自上方，这是删除操作。如果来自左方，这是插入操作。操作按从后往前的顺序记录，最后反转为从左到右。

第三步，输出格式。每步操作格式："位置 X: 将 'a' 替换为 'b'"、"位置 X: 插入 'c'"、"位置 X: 删除 'd'"。操作按位置从左到右排列。也输出一个对齐视图：上面一行是源字符串，下面一行是目标字符串，用 - 表示删除、+ 表示插入、| 表示匹配、^ 表示替换。

两个空串结果是 0 步。Go 标准库，go build 编译通过。
