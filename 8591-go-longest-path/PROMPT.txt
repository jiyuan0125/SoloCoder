项目管理里有个问题：一个任务依赖图（DAG）中，从开始到结束的最长路径决定了项目的最短完成时间。这不就是关键路径法吗？在有向无环图上找最长路径，一般图上最长路径是 NP-hard 的，但 DAG 上用拓扑排序加 DP 就能做。

用 Go 实现 DAG 上的最长路径求解。

拓扑排序——先用 Kahn 算法（BFS 入度法）对 DAG 做拓扑排序。如果排序结果数量 < 节点总数，说明图中有环，报错退出。

DP 求最长路径——按照拓扑排序的顺序处理节点。对每个节点 u，松弛所有出边 (u, v, weight)：如果 dist[v] < dist[u] + weight，更新 dist[v] = dist[u] + weight，同时记录 predecessor[v] = u。初始化：源点 dist = 0，其他 dist = -∞。

路径回溯——从终点沿 predecessor 数组反向追踪到源点，得到最长路径的具体节点序列。也可以输出从源点到每个节点的最长距离。

负权边处理——DAG 上的最长路径算法本身就能处理负权边（不像 Dijkstra 那样受限）。如果需要找最短路径，把权值取负找最长路径再取负回来就行。

从文件读图数据——邻接表格式：每行 "起点 终点 权重"。源点通过参数指定。输出最长路径长度、路径节点列表、以及到每个可达节点的最长距离。

Go 标准库，go build 编译通过。检测到环要报错。
