资源分配里经常遇到这样的问题：手头有一组资源，每个有不同的大小，需要选出恰好等于目标值的组合。比如有磁盘空间 [100, 200, 300, 400]，用户申请 500GB，可以选 100+400 或者 200+300。

1. DP 可行性判断。dp[i] = true 表示存在子集的和为 i。dp[0] = true（空集和为 0）。对每个元素 x，从大到小遍历 dp：如果 dp[j-x] 为 true，则 dp[j] = true。时间 O(n×target)。空间 O(target)。

2. 具体方案回溯。用一个二维数组或者额外的 choice 数组记录 dp[j] 是通过添加哪个元素变成 true 的。从 dp[target] 开始反向追踪：取 choice[target] 对应的元素 x，然后 target -= x，继续追踪直到 target=0。输出选中的元素列表。

3. Bitset 优化。如果 target 比较大但元素都是整数，用一个 uint64 数组做 bitset 代替 bool 数组。每次处理一个元素 x 就把 bitset 左移 x 位然后 OR 上原来的 bitset。操作是位运算所以非常快。

4. 最接近的子集。如果找不到精确和等于 target 的子集，输出和最接近 target 的子集。遍历所有 dp[i] 为 true 的 i，找 |i - target| 最小的。

从命令行读入数字列表和目标值。空集的和为 0。Go 标准库，go build 通过。
