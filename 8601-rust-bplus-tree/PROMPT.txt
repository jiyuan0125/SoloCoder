之前在做一个小型数据库的索引引擎，需要一个内存中的 B+ 树来存有序键值对。B+ 树和普通 B 树的区别在于：只有叶子节点存 value，内部节点只存 key 做路由；叶子节点之间用链表串起来，支持高效的范围查询。

用 Rust 实现一棵 B+ 树。

插入操作——找到应该插入的叶子节点。如果叶子节点满了（超过阶数限制），分裂成两个叶子节点，把中间的 key 复制一份提升到父节点（注意是复制不是移动，因为叶子还保留着）。如果父节点也满了就递归分裂，一直到根节点。根节点分裂时树增高一层。

删除操作——从叶子节点删除 key-value。如果节点太空（低于最小填充），从兄弟节点借一个 key，或者和兄弟合并。合并时要把父节点中对应的 key 也删掉，可能触发父节点的合并。

范围查询——B+ 树的杀手锏。给定范围 [lo, hi]，先找到 lo 所在的叶子节点，然后沿着叶子链表顺序扫描到 hi。时间 O(log n + range_size)。这是 B+ 树比普通 B 树更适合数据库索引的核心原因。

按 key 查找——从根开始，每个内部节点二分查找确定走哪个子节点。到叶子节点后做精确查找。

节点大小固定比如 4 阶（方便测试），或者用一个常量配置。叶子链表用 unsafe 的裸指针或者 Rc<RefCell<>> 实现。

cargo build 能编译，cargo run 跑一个 demo 插入数据后做范围查询。
