Linux 内核用红黑树做进程调度和内存管理，为什么不用 AVL？因为红黑树的插入删除需要的旋转次数更少（最多 2-3 次 vs AVL 的 O(log n) 次），适合频繁修改的场景。红黑树的平衡条件比 AVL 宽松——不保证严格平衡，但保证最长路径不超过最短路径的 2 倍。

用 Rust 实现一棵红黑树，做一个简单的有序 Map。

节点结构——key + value + left/right/parent 指针 + color（Red 或 Black）。用 Option<Box<Node<K,V>>> 表示子节点，用 Option<NonNull<Node>> 表示 parent（避免循环引用）。

红黑树五条性质——根节点是黑色、叶节点（NIL）是黑色、红色节点的两个孩子必须是黑色、从任一节点到其后代叶节点的所有路径包含相同数量的黑色节点、新插入的节点是红色。

插入——先按 BST 插入红色节点，然后修复。修复要看叔节点的颜色：叔节点是红色就变色（父和叔变黑、祖父变红，然后跳到祖父继续）。叔节点是黑色就看方向（LL/RR/LR/RL）做对应的旋转+变色。

删除——最复杂的操作。先按 BST 删除，如果删掉的是黑色节点需要修复。修复分各种情况（兄弟的颜色、兄弟孩子的颜色），根据情况做旋转和变色。

支持前驱/后继查询，按顺序遍历所有键值对。main 里演示插入 20 个随机数据然后中序打印，验证有序性和树的高度大致是 O(log n)。cargo run 能跑就行。
