为什么 Redis 用跳表而不是红黑树实现有序集合？因为跳表实现简单、范围查询方便、还支持 O(log n) 的查找。原理也不复杂——在有序链表上随机建多层索引，每层是下一层的子集，查找时从最高层开始逐层下降，类似于二分搜索。

用 Rust 写一个跳表，拿它当有序集合用。

层数决定——每个节点用抛硬币的方式决定层数：第 i 层出现的概率是 1/2^i。最大层数设个上限比如 16。节点结构：key、value、forward 数组（forward[i] 指向同一层下一个节点）。

查找——从最高层的头节点开始，当前层的下一个节点的 key < 目标 key 就往前走。走不动了就降一层继续。最后一层走完就找到了目标位置（或者确认不存在）。时间期望 O(log n)。

插入——先查找确定插入位置，记录每一层的前驱节点。然后生成随机层数，创建新节点，更新每层的前驱节点 forward 指针。类似链表插入，只是多层同时做。

删除——查找目标节点，记录每层的前驱。然后在各层中移除目标节点（更新前驱的 forward）。被删节点层数以上的层不需要处理。

范围查询——找 >= 某个 key 的前 N 个元素。先定位到 >= key 的节点（最低层），然后沿链表往后遍历 N 个。

main 里做个简单 benchmark：插入 10 万个整数，然后随机查 1000 个，打印耗时。cargo build 通过，cargo run 能看到结果。
