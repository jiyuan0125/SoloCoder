团队在做一个搜索补全系统，底层需要一个高效的前缀匹配数据结构。Trie（字典树/前缀树）天生适合这个场景——每个节点代表一个字符，从根到某个节点的路径就是一个前缀。前缀搜索只需要沿路径走几步再 DFS 收集结果，比暴力扫描快几个数量级。

用 Rust 实现一棵 Trie。

节点设计——每个节点存子节点 map（HashMap<char, Box<TrieNode>> 或者固定 26 数组）、一个 is_end 标记（表示从根到这个节点是一个完整词）、以及一个可选的 count（统计以该节点结尾的词被搜索了多少次）。

插入——逐字符遍历单词，每走一步检查子节点是否存在，不存在就创建新节点。走完整单词后标记 is_end=true，count 加一。

精确查找——沿字符路径走到底，检查最后节点 is_end 是否为 true。走不通就返回 false。

前缀查询——先沿前缀字符走到对应子树，然后 DFS 收集所有 is_end=true 的节点，拼接出完整单词。可以限制返回数量（Top-K）。

词数统计——查某个前缀有多少个匹配词：DFS 到前缀子树后统计所有 is_end=true 的节点数。

删除——删除一个单词后，如果路径上的节点不再属于任何单词就回收。递归从叶子往根检查，is_end=false 且子节点为空的节点可以删除。

从文件读入词表（每行一个词），然后支持交互式输入前缀实时返回补全建议。cargo run 能用就行。纯 Rust 标准库。
