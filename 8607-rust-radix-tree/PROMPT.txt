Web 框架做路由匹配的时候，把每个 URL path 注册到一个树结构里，请求来了沿着树走就能找到对应的 handler。Radix Tree（基数树/压缩前缀树）比普通 Trie 省空间——只有一个子节点的路径会合并成一条边，减少中间节点数量。

1. 插入路径。注册一条路由比如 "/api/v1/users"，把路径按 "/" 分隔成段 ["api", "v1", "users"]。沿着树按段往下走，如果某段匹配就走子节点。如果路径分叉（比如已有 "/api/v1/posts" 再插入 "/api/v1/users"），在分叉点拆分节点——公共前缀 "v1" 共享，"users" 和 "posts" 各占一个子节点。

2. 精确匹配。给定一个 URL path，分段后沿树走，完全走通且到达一个有 handler 的节点就是匹配成功。返回对应的 handler。

3. 最长前缀匹配。用于通配符场景——比如 "/api/*" 匹配所有以 "/api/" 开头的路径。当精确匹配失败时，回退到最近的通配符节点。

4. Demo。模拟注册几条路由规则："/"、"/api/v1/users"、"/api/v1/posts"、"/api/v2/status"。然后测试各种 URL 能匹配到正确的路由。输出匹配结果。

插入已有前缀时要正确拆分节点——比如先插 "abc" 再插 "abd"，公共前缀 "ab" 是共享的，第三个字符分叉。cargo build 编译通过，cargo run 打印匹配结果。
