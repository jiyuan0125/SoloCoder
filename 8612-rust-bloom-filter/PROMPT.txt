爬虫去重有个痛点——URL 数量太大，存数据库查重太慢，全放内存又太占空间。布隆过滤器用很少的内存就能判断一个 URL 是"一定没抓过"还是"可能抓过"，允许少量误判（把没抓过的误判为抓过，也就是漏抓少量页面）但不会漏掉没抓过的判断为没抓过。

1. 参数自动计算。用户指定预期元素数量 n 和可接受的误判率 p。根据公式自动算出最优的 bit 数组大小 m = -(n × ln p) / (ln 2)² 和哈希函数个数 k = (m/n) × ln 2。比如 n=100 万、p=0.01，m ≈ 958 万 bit（约 1.14 MB），k ≈ 7 个哈希函数。

2. 插入元素。对元素做 k 次哈希（用双重哈希技巧：hash_i(x) = hash1(x) + i × hash2(x)），得到 k 个位置，把 bit 数组中这些位置设为 1。

3. 查询元素。同样做 k 次哈希，检查 k 个位置是否都是 1。全都是 1 → "可能存在"（可能是真的也可能误判）。有任何一个是 0 → "一定不存在"（确定性判断）。

4. 哈希函数。用两个基础哈希函数（比如 SipHash 和 FNV），然后通过 h_i = h1 + i*h2 生成 k 个哈希值。不需要真的实现 k 个不同的哈希函数。

5. 序列化。支持把 bit 数组序列化到文件和从文件加载。参数（m、k、n）也要一起存。

写个 demo 插入 1 万个 URL，然后查询 1000 个不在集合中的 URL，统计误判率。cargo run 跑通。
