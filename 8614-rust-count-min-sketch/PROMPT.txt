API 网关需要统计每个 endpoint 的请求次数来发现热点接口。但 endpoint 有几万个，精确计数太占内存。Count-Min Sketch 用很少的内存就能估计频次——不精确但够用，误差可控。

用 Rust 实现 Count-Min Sketch。

实现步骤——

第一步，数据结构。一个 d×w 的二维计数器数组（d 行 w 列），d 是哈希函数个数（深度），w 是每行的宽度。所有计数器初始化为 0。d 和 w 可以由用户指定，也可以根据期望误差 ε 和置信度 δ 自动算：w = ⌈e/ε⌉，d = ⌈ln(1/δ)⌉。

第二步，add 操作。给某个 key 的计数加一。对 key 应用 d 个不同的哈希函数，得到 d 个位置 (1, h1(key)), (2, h2(key)), ..., (d, hd(key))。每个位置对应的计数器加一。

第三步，estimate 操作。查询某个 key 的估计频次。同样用 d 个哈希函数得到 d 个位置，读取这 d 个位置的计数值，取最小值作为估计结果。为什么取最小值？因为哈希冲突只会让计数偏大，不会偏小，所以最小值最接近真实值。

第四步，top-K 查询。维护一个大小为 K 的最小堆，遍历所有可能的热点 key（或者接受外部输入的候选列表），对每个 key 做 estimate，保留估计频次最高的 K 个。

main 里模拟一批请求流（随机生成 10 万个 endpoint 调用），打印 top-10 热点 key 和估计频次。cargo run 能跑起来。
