分布式缓存集群有 10 个节点，100 万个 key 按某种规则分布在这些节点上。这时候要加一个节点——如果用简单的 hash(key) % 10 取模分配，几乎所有的 key 都要迁移到新位置，缓存命中率直接归零。一致性哈希解决了这个问题：加节点时只有少量 key 需要迁移。

用 Rust 实现一致性哈希。

哈希环——想象一个 0 到 2^32-1 的环形空间。每个缓存节点通过哈希映射到环上的一个或多个位置。每个 key 也哈希到环上，顺时针方向遇到的第一个节点就是它所属的节点。

虚拟节点——如果只有 10 个真实节点，每个节点只占环上一个位置，数据分布会很不均匀。解决方案：每个真实节点映射到多个虚拟节点（比如 100-200 个），用 node_id + "#1"、node_id + "#2" 这样的字符串做哈希。虚拟节点越多分布越均匀。

查找——给定一个 key，哈希后在环上找到第一个 >= 哈希值的虚拟节点（用排序数组 + 二分查找）。如果超过了最大值就回绕到第一个节点。

添加节点——把新节点的虚拟节点插入到环上。受影响的 key 只是新节点和它前一个虚拟节点之间的 key，大约 1/N 的 key 需要迁移。

删除节点——把被删节点的虚拟节点从环上移除。它负责的 key 会迁移到下一个节点。

Demo：模拟 10 个节点、100 万个 key 的分布，打印每个节点的负载比例（应该接近 10%）。然后删掉一个节点，统计有多少 key 被迁移（应该接近 10%）。cargo run 能跑。
