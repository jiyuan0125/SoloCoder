一致性哈希通常需要一个环结构加虚拟节点，Jump Consistent Hash 是 Google 提出的一种零内存替代方案——不需要环、不需要虚拟节点，一个纯函数就能做一致性哈希分配。

1. 核心算法。就一个函数 jump_consistent_hash(key: u64, num_buckets: i32) -> i32。思路是：当桶数从 1 增长到 n 时，每次增加一个新桶，以 1/(new_bucket_number) 的概率把 key 重新分配到新桶。实现用一个循环：b = -1, j = 0; while j < num_buckets { b = j; key = key * 2862933555777941757 + 1; j = (b+1) * ((1<<31) / ((key>>33)+1)) }。返回 b。

2. 特性。输出在 [0, num_buckets) 范围内。桶数变化时只有 1/old_num_buckets 的 key 会迁移到新桶。完全均匀分布（如果哈希函数是均匀的）。零内存——不需要预计算环或表。确定性——同一个 key 和桶数永远返回同一个桶。

3. Benchmark 测试均匀性。生成 100 万个随机 key，分配到 10 个桶，统计每个桶的 key 数量。计算标准差和变异系数（CV），CV 应该接近 0。桶数从 10 变到 11 时统计迁移率，应该接近 1/10。

4. 局限性。只能增加桶不能减少（减少桶时跳过的桶编号会导致不均匀）。不支持删除特定桶。

cargo run 能看到统计结果。纯 Rust 标准库。
