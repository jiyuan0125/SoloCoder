Google 的 Maglev 负载均衡器用了一种特殊的一致性哈希——不是环结构，而是一个查找表。对任意 key 做 O(1) 的查表就能得到后端节点。查找表的大小是固定的（比如 65537），后端节点变动时做最小化重映射。

用 Rust 实现 Maglev 一致性哈希。

偏好列表生成——对每个后端节点，用两个不同的哈希函数生成一个长度等于查找表大小的排列（permutation），这就是该节点的偏好列表。偏好列表表示该节点"想"占据查找表中的哪些位置。

查找表填充——所有节点的偏好列表同时开始填充。每一轮，每个节点按偏好列表顺序找一个还没被占用的位置并占据。重复直到查找表的所有位置都被填满。填充完成后，查找表 lookup[index] = node_id。查找时对 key 做一次哈希取模就得到节点。

O(1) 查找——lookup[hash(key) % table_size] 直接得到目标节点。比环结构的一致性哈希快。

节点变动处理——增加或删除节点时重新运行填充算法。由于偏好列表的特性，大部分 key 的映射不会变，只有被影响的节点相关的 key 会重映射。

写个 demo 生成 3 个后端节点的查找表，测试一些 key 的分配。然后删除一个节点，重新生成查找表，统计有多少 key 的映射变了。cargo build 通过，cargo run 有输出。
