游戏里 NPC 要在地图上找路，Dijkstra 会往所有方向均匀扩展，太浪费了。A* 算法用一个启发函数引导搜索方向——大概知道目标在东边就优先往东搜，不是漫无目的地全扫。

1. 算法核心。维护一个开放列表（优先队列，按 f 值排序）和一个关闭列表（已处理的节点）。f(n) = g(n) + h(n)，g(n) 是从起点到 n 的实际代价，h(n) 是 n 到终点的启发估计。每次从开放列表取 f 值最小的节点扩展。如果取到终点就找到了最短路径。

2. 启发函数。支持两种：曼哈顿距离（|x1-x2| + |y1-y2|，适合四方向移动）和欧几里得距离（√((x1-x2)² + (y1-y2)²)，适合八方向移动）。启发函数必须不高估实际代价才能保证最短路径。

3. 网格地图。用二维数组表示，0 是可通行、1 是障碍。支持四方向（上下左右）和八方向（加上对角线）移动。对角线移动的代价是 √2。

4. 路径输出。如果没有路径，提示不可达。如果找到了，用字符画打印地图——# 表示障碍，* 表示路径，S 表示起点，E 表示终点。路径步数也打印。

定义一个 20×20 的网格地图，放几个障碍，演示从左上角走到右下角。cargo run 能看到地图和路径。
