编译系统的依赖分析——模块 A 依赖 B 和 C，B 依赖 D，C 也依赖 D。编译顺序必须是 D → B → C → A（被依赖的先编译）。这就是拓扑排序——给 DAG 的节点排个线性顺序，使得所有边的方向都从前指向后。

用 Rust 实现拓扑排序。

Kahn 算法（BFS 入度法）——计算每个节点的入度（有多少条边指向它）。把所有入度为 0 的节点放入队列。循环：从队列取出一个节点 u，加入结果序列。对 u 的每个邻居 v，把 v 的入度减一。如果 v 的入度变为 0，加入队列。队列为空时结束。

环检测——如果结果序列的长度 < 节点总数，说明还有节点没处理（它们的入度始终不为 0，因为它们在一个环里互相依赖）。检测到环就报错"图中存在环，无法排序"。

图的输入——格式自己定，比如 "A B" 表示 A 依赖 B（B → A 有条边）。用 HashMap<String, Vec<String>> 存邻接表。

也实现 DFS 拓扑排序——按 DFS 的完成时间（后序）反序就是拓扑序列。DFS 过程中如果发现后向边（指向已经在当前 DFS 路径上的节点），说明有环。

写个 demo 读几组依赖关系，打印拓扑排序结果。也测试一个有环的图，验证环检测。cargo run 能看到输出。
