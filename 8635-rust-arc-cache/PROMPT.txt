LRU 和 LFU 各有优缺点——LRU 对突发扫描没抵抗力，LFU 对新的热点数据反应迟钝。ARC（Adaptive Replacement Cache）是 IBM 提出的自适应算法，同时维护"最近"和"频繁"两个 LRU 列表，根据工作负载自动调整两者比例。

用 Rust 实现 ARC 缓存算法。

四个列表——T1（最近使用的条目，LRU）、T2（经常使用的条目，LFU）、B1（被 T1 淘汰的幽灵条目）、B2（被 T2 淘汰的幽灵条目）。T1 和 T2 存实际数据，B1 和 B2 只存 key（用于学习访问模式）。

自适应策略——p 参数控制 T1 的目标大小（0 到 capacity）。访问命中 T1 或 T2，移到 T2 的 MRU 端。访问命中 B1（幽灵列表），说明 T1 太小了，p++，然后从 T2 淘汰一条到 B2（如果 T2 满了），新条目加入 T2。访问命中 B2，说明 T2 太小了，p--，然后从 T1 淘汰一条到 B1，新条目加入 T2。全新数据加入 T1。

ARC 的优势在于它能从幽灵列表学习——B1 命中多说明工作集偏"频繁"（加大 T2），B2 命中多说明偏"最近"（加大 T1）。

写个 demo 展示它比普通 LRU 在扫描负载下的命中率优势。cargo run 能看到对比数据。
