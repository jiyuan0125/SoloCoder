缓存准入策略有个巧妙的设计——TinyLFU。它用 Count-Min Sketch 记录历史访问频率，新元素只有在频率高于即将被淘汰的元素时才允许进入缓存。这样能抗住扫描 workload：一次性访问的数据不会把有价值的热数据挤出去。

用 Rust 实现 TinyLFU 缓存准入策略。

Count-Min Sketch 部分——维护一个小的 CMS（深度 4，宽度 64 或 128）来记录历史频率。每次访问（无论命中还是未命中）都更新 CMS。add(key)：对 key 做 4 次哈希，对应 4 个计数器加一。estimate(key)：取 4 个计数器的最小值。每隔一段时间（比如 64 次操作）对所有计数器右移一位（halving），实现窗口衰减——很久以前的访问频率逐渐降低。

Window 策略——给新元素一个短暂的窗口期。新元素先进入一个小的 Window Cache（容量占总容量的 1%）。如果新元素在窗口期内被再次访问，说明它有价值，才有资格和主缓存中的元素竞争。竞争规则：新元素的 CMS 频率 > 主缓存中即将被淘汰的元素的频率，才允许进入主缓存。

写个简单的缓存结构，支持 put 和 get。demo 里跑两组访问序列——一组是稳定热点数据，一组是大规模扫描——对比 TinyLFU 和普通 LRU 的命中率。cargo run 能看到结果。
