游戏引擎里每一帧都要创建大量临时对象（粒子、碰撞检测结果等），帧结束时全部销毁。如果用通用分配器，频繁的 malloc/free 是性能瓶颈。Bump 分配器（也叫线性分配器）超级快——维护一个指针，每次分配就往后移动指针，释放只能整体 reset 回到开头。

用 Rust 实现 Bump 分配器。

核心操作——new(size)：分配一块 size 字节的内存区域，维护 offset 指针（初始为 0）。alloc(nbytes)：检查 offset + nbytes <= capacity。如果够，记录当前位置，offset += nbytes（考虑对齐），返回引用。如果不够，返回错误或者触发扩容。reset()：offset 设回 0，"释放"所有已分配的对象。下次 alloc 从头开始复用内存。

内存对齐——分配时要考虑对齐要求。如果对象需要 8 字节对齐，offset 要向上取整到 8 的倍数再分配。用 (offset + align - 1) & !(align - 1) 计算。

用 unsafe 操作原始内存或者用 Vec<u8> 模拟都行。Vec 模拟更安全但不那么"真实"。

写个 demo 展示分配速度——连续分配 10000 个小对象，对比 Bump 分配器和系统分配器的耗时。reset 后再分配验证不会出错。cargo run 能看到分配和 reset 的过程。
