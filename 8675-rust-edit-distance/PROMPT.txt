你用过拼写检查吧？输入 "recive" 自动提示 "receive"——背后就是编辑距离在算两个字符串差了几步。但光知道距离是 2 还不够，拼写纠正、diff 工具都需要知道具体改了什么：第 3 个位置插入了 'e'，第 5 个位置把 'v' 替换成了 'c'。

用 Rust 实现编辑距离计算，不光返回距离值，还得回溯出完整的编辑操作序列。

DP 表怎么建？(m+1)×(n+1) 的二维表。dp[i][j] 取三个来源的最小值——上方加 1（删除）、左方加 1（插入）、左上角加 cost（相等则 cost=0，否则 1 表示替换）。

回溯怎么走？从 dp[m][n] 往回追——来自上方就是删除了 s[i-1]，来自左方就是插入了 t[j-1]，来自左上角看 cost：0 是匹配，1 是替换。操作按从左到右的顺序排列输出。

空间能优化到 O(min(m,n)) 吗？用两行交替就行。空串的边界别遗漏。CLI：edit-distance "kitten" "sitting"，同时输出距离和操作序列。cargo build 通过。
性能对比：跑两组测试——"kitten" vs "sitting"（经典用例），以及两个 1000 字符的随机字符串。输出 DP 表大小、计算耗时。如果两个字符串完全相同（距离为 0）直接短路返回，跳过整个 DP 计算，O(1) 退出。
