CDN 缓存节点要淘汰冷门内容——LRU 只看最近访问时间，但一个被爬虫反复拉取的资源频率很高不该淘汰。LFU（Least Frequently Used）按访问频率淘汰，频率最低的先走，同频率按 LRU 淘汰最久没访问的。

问题 1：怎么做到 get/put 都是 O(1)？HashMap 存 key 到节点的映射。另外维护一个 freq 到双向链表的映射——每个频率一条链表，链表按访问时间排序。get 时把节点从旧频率链表移到新频率链表。put 时如果满了，从 min_freq 链表的尾部（最久没访问的）淘汰。

问题 2：怎么维护 min_freq？新插入的节点频率为 1，min_freq 设为 1。淘汰只在 min_freq 链表里找。频率增加时，如果旧频率链表空了且旧频率 == min_freq，min_freq 加 1。

用 Rust 实现泛型 LFU 缓存，key 和 value 都是泛型（key 需要 Hash + Eq）。容量由构造函数指定。cargo build 通过。
跑一遍这个操作序列：put(1,10), put(2,20), put(3,30)，然后 get(1), get(2)，put(4,40) 应该淘汰 3（频率最低且最久没访问）。get 不存在的 key 返回 None，put 更新已存在的 key 也要验证。
