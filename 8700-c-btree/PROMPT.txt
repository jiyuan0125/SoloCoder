自己动手写一个数据库索引引擎——B 树几乎是一切数据库和文件系统的基石。为什么不用二叉搜索树？因为磁盘按块读写，一个 4KB 的页能装上百个 key，B 树的扇出大、树高低，3-4 层就能存上亿条记录，磁盘 IO 次数极少。

用 C 语言实现 B 树。

节点怎么组织？每个节点存一组有序的 key 和对应的子节点指针。阶数（最大 key 数）可配置，比如 t=3 就是最多 5 个 key、6 个子节点。叶子节点没有子节点。

插入时节点满了怎么办？分裂——中间 key 提到父节点，左右各成一个新节点。一路向上递归分裂，根节点满了就新建一个根，树高加 1。

删除时空节点怎么处理？和兄弟合并或者从兄弟借一个 key。三种情况：叶子直接删、内部节点用前驱/后继替换再递归删、节点太空时合并。要保持所有叶子在同一层。

CLI 交互：btree insert 42、btree search 42、btree delete 42、btree print（可视化树结构层次）。gcc 编译通过。
测试——插入 100 个随机 key 后中序遍历验证有序。删除几个 key 后再搜索，确认删了的不在。print 输出树结构层次，可视化验证分裂和合并正确。
