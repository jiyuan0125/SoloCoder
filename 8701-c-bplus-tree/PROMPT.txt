小型数据库的索引引擎——用户执行 SELECT * FROM orders WHERE id BETWEEN 100 AND 500，引擎需要快速定位这个范围里的所有记录。B+ 树比 B 树更适合这种场景：数据全部存在叶子节点，叶子用链表串起来，范围查询顺着链表扫一遍就搞定，不用在树里反复上下跳。

用 C 语言实现 B+ 树。

树的结构——内部节点只存 key 做路由，不存数据。所有数据都在叶子节点里。叶子之间用双向链表连接，方便前向和后向遍历。度数（fanout）通过宏定义，调大度数可以降低树高。

插入流程——找到目标叶子节点，插入 key-value。叶子满了就分裂，中间 key 复制一份到父节点（注意是复制不是移动，叶子要保留这个 key）。分裂可能一路向上传播。

范围查询——从根定位到起始 key 的叶子，然后顺着链表往后遍历，直到超过结束 key。时间复杂度 O(log n + m)，m 是结果数。

查找不到返回明确错误码，删除不存在的 key 要处理边界。gcc 编译，命令行演示插入数据后范围查询。
测试——插入 200 个随机 key-value 对，范围查询验证结果正确。删除几个 key 后再查范围，确认已删的不出现。对比 B 树和 B+ 树在范围查询上的性能差异。
