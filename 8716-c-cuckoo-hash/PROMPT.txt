DNS 服务器收到一个查询请求，必须在微秒级响应——每个域名查两次哈希函数就能确定在不在，O(1) 最坏情况保证。Cuckoo Hashing 用两个独立的哈希函数和两个表，每个 key 在两个表里各有一个候选位置。查找最多查两个位置，不可能更慢。这种确定性延迟在高性能系统里非常关键。

用 C 语言实现 Cuckoo Hashing。

两个表两个哈希函数——h1(key) 和 h2(key) 分别映射到 table1 和 table2。查找时两个位置都看，找到就返回。插入时先看 h1 位置空不空，空就放。不空就看 h2 位置，空就放。

两个都满了怎么办？踢——随机选一个位置，把那里的旧元素踢出去，旧元素去自己的另一个位置。如果那个位置也满了就继续踢。形成一条踢的链条。

链条太长怎么办？说明表太满了。设一个最大踢次数（比如 500），超过就触发扩容——两个表都翻倍，所有元素重新插入。

支持 insert、lookup、delete。gcc 编译。测试随机插入大量 key 后验证每个 key 都能 O(1) 查到。
测试——插入 10000 个随机 key 后验证全部可查到。测量两个表的负载均衡度——大小应接近 1:1。踢链最大长度记录，验证不超过阈值。
