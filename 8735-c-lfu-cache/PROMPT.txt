CDN 缓存节点和 LRU 的问题——一个被爬虫反复拉取的资源频率很高但可能最近没访问，LRU 会把它淘汰掉，不合适。LFU（Least Frequently Used）按频率淘汰——频率最低的先走，同频率按 LRU 淘汰。热点内容不会被误杀。

用 C 语言实现 LFU Cache。

怎么组织数据？两层映射——第一层 key → (value, freq)，第二层 freq → 双向链表（同频率的节点按时间排序）。另外维护一个 min_freq 变量，淘汰时直接从 min_freq 链表的尾部取。

get 操作——key 不存在返回 -1。存在就频率 +1：从旧频率链表摘下来，挂到新频率链表头部。更新 min_freq（如果旧频率链表空了且旧频率 == min_freq，min_freq++）。

put 操作——key 存在就更新 value 并做一次 get 的逻辑。key 不存在就创建，频率初始化为 1，min_freq 设为 1。超过容量就从 min_freq 链表尾部淘汰。

gcc 编译。测试一组操作序列，验证淘汰策略正确。
测试——容量 2，put(1,10), put(2,20), get(1), get(1), put(3,30)（淘汰 2 频率最低）。get(2) 返回 -1，get(1) 返回 10。验证频率优先淘汰。
