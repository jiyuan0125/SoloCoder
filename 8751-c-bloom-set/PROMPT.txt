上周做日志去重的时候碰到了一个很典型的场景——每天几十亿条访问日志，需要快速判断某条日志是不是重复的，直接用哈希表存所有 ID 内存根本吃不消。布隆过滤器正好适合这种"可能存在"的判断，用很少的内存换一个可接受的误判率。

帮我用纯 C 写一个基于布隆过滤器的集合数据结构。底层用位数组 + 多个哈希函数来实现，哈希函数用 MurmurHash3 或者简单点用 FNV-1a 配合不同种子也行。误判率通过参数 m（位数组大小）和 k（哈希函数个数）可调，最方便的是用户直接指定期望的误判率（比如 0.01），内部自动算出最优的 m 和 k。

支持四个核心操作：add(element) 往集合里加元素、contains(element) 判断元素是否可能存在、union(other_bloom) 两个布隆过滤器做并集（要求参数一致才能合并）、intersect(other_bloom) 做交集估算。add 和 contains 的时间复杂度都是 O(k)，跟集合大小无关。

写个命令行程序从 stdin 逐行读取指令——+keyword 添加元素、?keyword 查询是否存在、& keyword1 keyword2 对两个布隆过滤器求交集、| keyword1 keyword2 求并集。再写一段测试代码：往里面插入 100 万个随机字符串，然后查询另外 100 万个不在集合里的字符串，统计实际误判率是不是接近理论值。

gcc 编译，只依赖标准库，不要引第三方代码。
