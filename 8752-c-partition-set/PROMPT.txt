做社交平台的时候有个需求一直困扰我们——用户的好友关系、群组归属这些东西本质上是等价类问题，几百万用户频繁地合并圈子、查询"这俩人在不在同一个圈子里"。最开始用哈希表存，发现合并操作太慢了，后来才意识到并查集（Union-Find）才是正解。

用 C 实现一个等价类（Partition Set / 并查集）数据结构，底层用数组存每个元素的父指针。find 操作必须用路径压缩——递归往上找到根节点的同时把路径上的节点直接挂到根上，这样后续查询就快了。union 操作用按秩合并：矮树挂到高树下面，保证树的高度始终在 O(α(n)) 级别（α 是反阿克曼函数，实际中不超过 4）。

对外提供这些接口：make_set(x) 创建只含 x 的集合、find(x) 返回 x 所在集合的代表元素、union(x, y) 合并 x 和 y 所在的集合、count_sets() 返回当前有多少个独立集合。初始化时指定元素总数上限，内部预分配好数组。

命令行程序从文件读取 "a b" 格式的边关系（每行一条边，表示 a 和 b 属于同一集合），每处理完一条边就实时输出当前的连通分量数。最后支持查询模式，交互式输入两个元素判断是否连通。

处理 100 万个元素、200 万条边的场景也要在 1 秒内跑完。gcc 编译，纯标准库。
