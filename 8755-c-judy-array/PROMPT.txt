Judy Array 这东西你可能没听过，但它在处理稀疏整数键的时候确实有一手——内存占用比哈希表低很多，查询速度还能接近 O(1)。原理是根据节点的密度自动在不同表示方式之间切换：稀疏的时候用线性搜索的数组，密集的时候用位图，中间状态用别的压缩结构。

帮我用 C 实现一个 Judy Array，至少实现 J1 版本（整数键集合，不带值）。支持四个操作：insert(key) 插入一个整数键、delete(key) 删除、lookup(key) 查询是否存在、iter() 按顺序遍历所有键。

内部结构可以简化——不用完全照搬 Doug Baskins 的原始实现，但核心思路要保留：把 32 位键分成几段（比如 4 段，每段 8 位），用 trie 结构逐层索引。每一层根据子节点的数量选择不同的存储方式——子节点少于 N 个用线性数组（省指针），多于 N 个用 256 路的指针数组或位图（加速查找）。这个 N 的阈值可以自己调。

带个 benchmark 程序做两组对比测试。第一组：插入 100 万个随机 32 位整数键，对比 Judy Array 和普通链地址法哈希表在内存占用上的差异。第二组：同样的数据集做 1000 万次随机查找，对比查询速度。输出两组数据的具体数值（内存用 KB，查询用毫秒）。
