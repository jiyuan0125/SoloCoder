之前有个需求是做 IP 黑名单的快速匹配，几万条 CIDR 规则，每条请求都要判断是否命中。Trie 树能做但太浪费空间——大量公共前缀被重复存储。后来发现 crit-bit tree（也叫 patricia trie）正好解决这个问题，它只在关键分叉位上创建节点，中间路径全部压缩掉了。

用纯 C 实现一个 crit-bit tree，用来存字符串集合。树的内部节点只存一个"关键位"的位置和两个子指针，叶子节点存实际的字符串。查找的时候从根节点开始，在每个内部节点处检查关键位是 0 还是 1 来决定走左子树还是右子树——本质上就是在对字符串做逐 bit 的二分。

支持四个操作：insert(key) 插入字符串，先找到应该插入的位置，和最近的叶子节点比较确定第一个不同的 bit 位，在这个位上创建新的内部节点；delete(key) 删除，删完之后如果某个内部节点只剩一个子节点就把它的父节点直接连到那个子节点上（压缩）；lookup(key) 精确查找；prefix_search(prefix) 前缀搜索，找到所有以 prefix 开头的字符串，这个对 IP 路由表场景特别有用。

写个命令行工具，输入一批单词建树，然后交互式查询单词是否存在或者搜某个前缀下的所有词。最后跑个测试：插入 10 万个随机 URL，验证所有 lookup 结果正确，再测试前缀搜索的覆盖率。

gcc 能编就行，只依赖标准库。
