拼写检查、搜索纠错这类功能的核心就是"找和这个词最相似的那些词"。暴力做法是对词典里每个词算一遍编辑距离，但词典几万条的时候太慢了。BK-Tree 巧妙地利用了三角不等式来剪枝——只有当某个词到树根的编辑距离 d 和目标词到树根的距离 r 满足 |d-r| ≤ max_dist 时，它的子树里才可能有匹配。

用 C 写一棵 BK-Tree，专门做模糊字符串匹配。建树：根节点放第一个词，后续每个词从根开始找位置——计算它到当前节点的编辑距离 d，如果当前节点的第 d 个子节点为空就直接挂上去，否则递归进入那个子节点继续找。这样相同距离的词会聚在一起。

query(word, max_dist) 查询所有和 word 的编辑距离不超过 max_dist 的词。搜索时对每个节点算当前词和节点词的编辑距离 d：如果 d ≤ max_dist 说明当前节点就是一个匹配；然后只需要递归搜索距离在 [d-max_dist, d+max_dist] 范围内的那些子节点，其他子节点全部剪掉。

add_word(word) 往树里插入新词。建树前不需要调 insert 的顺序，任何顺序都能工作。

加载一个词典文件（每行一个词，几万条英文单词），然后交互式输入单词和容忍距离，输出所有相似建议和对应的编辑距离。编辑距离用标准 DP 实现，O(mn)。

另外做个简单 benchmark：10 万条词的词典，100 次模糊查询，统计每次搜索访问了多少个节点（剪枝效果）。gcc 编译。
