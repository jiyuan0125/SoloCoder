LZ77 的思路其实很直觉——一段文本里如果某个片段之前出现过，就不用再存一遍了，记一个"往前看多远、多长"的引用就行。gzip、PNG 压缩底层都在用它。不过从理论到工程还有些坑：滑动窗口的查找效率、输出格式的编码、边界的处理。

用 C 实现 LZ77 压缩算法。核心参数：滑动窗口大小 32KB（往前看的最远距离）、lookahead buffer 256 字节（最长匹配长度）。压缩输出不用原版 LZ77 的三元组格式，改用一种更紧凑的自定义 bit 流格式——区分"字面量"和"匹配引用"两种 token：字面量是 1 bit 标志 + 8 bit 原始字节；匹配引用是 1 bit 标志 + 15 bit distance + 8 bit length。

查找最长匹配的策略：对滑动窗口建一个简单的哈希表（key 是 3 字节前缀，value 是位置链表），每次遇到新位置时先在哈希表里找候选匹配位置，逐个比较找到最长的。匹配长度至少 3 才输出引用，否则就当字面量。

解压时顺序读取 bit 流，遇到字面量直接输出，遇到引用就从已解压的输出缓冲区里往前 distance 个位置拷贝 length 个字节。注意引用可能重叠——比如 distance=1、length=10 就是重复最后一个字符 10 次。

命令行：lz77 compress file.txt file.lz77、lz77 decompress file.lz77 out.txt。压缩后解压必须和原文完全一致。gcc 编译。
