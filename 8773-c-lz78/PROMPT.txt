LZ78 和 LZ77 的思路不太一样——LZ77 是回头找之前出现过的内容做引用，LZ78 则是边压缩边显式维护一个字典，每遇到一个"之前没见过的新组合"就往字典里加一条。输出的是 (字典索引, 新字符) 对，解压时同步重建字典就行。

用 C 写个 LZ78 压缩实现。压缩过程：初始化字典为空（或者预置 256 个单字节条目）。维护一个当前匹配 w（初始为空），逐个读取输入字符 c。如果 w+c 在字典里，就把 c 追加到 w 继续读下一个字符。如果 w+c 不在字典里，输出 (w 的索引, c)，然后把 w+c 作为新条目加入字典，w 重置为空。文件结束时如果 w 非空，输出 (w 的索引, 空)。

字典用 trie 或者哈希表实现都行。用 trie 的话每个节点存字典索引，查找就是顺着字符路径往下走。哈希表的话 key 是 (父索引, 字符)，value 是子节点索引。

字典大小设上限（比如 4096 条或 65536 条），满了之后的处理策略有两种：清空重建（简单粗暴）或者冻结字典不再添加新条目（后续全靠已有的条目做匹配）。先实现清空重建的版本。

输出格式：每条 token 是 (index, char)，index 用 12 bit 或 16 bit（取决于字典大小），char 用 8 bit。紧凑地打包成 bit 流。解压过程就是逆向操作——读 (index, char)，输出 index 对应的字符串 + char，然后把新的字符串加入字典。
