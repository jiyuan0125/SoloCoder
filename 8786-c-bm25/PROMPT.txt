搜索排序最常用的算法不是什么深度学习，而是 BM25——一个诞生于上世纪 90 年代的概率检索模型。Google 早期也用过它的变体。核心思想很简单：一个词在一篇文档里出现越多（TF 高），且在所有文档里出现越少（IDF 高），那这个词对这篇文档的区分度就越大，相关性分数越高。但 TF 的贡献不是线性的，文档越长 TF 天然越高，所以要归一化。

用 C 写一个 BM25 相关性打分的完整实现。公式：对查询里每个 term t，score += IDF(t) * (TF(t,d) * (k1 + 1)) / (TF(t,d) + k1 * (1 - b + b * DL(d) / AVGDL))。IDF(t) = log((N - DF(t) + 0.5) / (DF(t) + 0.5) + 1)。N 是总文档数，DF(t) 是包含 t 的文档数。k1 控制词频饱和速度（默认 1.2~2.0），b 控制文档长度归一化（默认 0.75），DL(d) 是文档 d 的长度，AVGDL 是所有文档的平均长度。

输入：一组文档（从文件读取，每行一篇，空格分词），一个查询字符串。输出：所有文档按 BM25 分数降序排列，显示每篇文档的分数、TF、IDF 等中间值。

TF 直接统计 term 在文档中出现的次数。DF 需要先建一个倒排索引（或简单的哈希表）统计每个 term 出现在多少篇文档里。AVGDL 是所有文档 token 数的平均值。

命令行：bm25 --docs docs.txt --query "search terms" --k1 1.5 --b 0.75。也支持从文件读取多条查询批量打分。gcc 编译。
