前阵子公司内部做代码审计，发现好几个服务还在用字符串拼接构造 SQL，fmt.Sprintf("SELECT * FROM users WHERE id = " + id) 这种写法到处都是。安全团队让整个研发部门自查，但纯靠人看代码效率太低，几百万行 Go 代码根本看不完。

用 Go 写一个 SQL 注入静态检测工具。核心逻辑是递归扫描指定目录下所有 .go 文件，对源码做文本模式匹配找出危险写法。

检测规则分三类：第一类是 fmt.Sprintf 构造 SQL——匹配 fmt.Sprintf 调用的第一个参数（格式化字符串）里包含 SELECT/INSERT/UPDATE/DELETE/EXEC 等关键词，并且格式化字符串里有 %v/%s/%d 等占位符。第二类是字符串拼接构造 SQL——匹配 + 运算符连接的字符串中一侧包含 SQL 关键词。第三类是 database/sql 的 Query/Exec 直接拼接变量——匹配 db.Query("..." + var) 或 db.Query(fmt.Sprintf(...)) 模式。

输出格式：每条检测结果标注文件名、行号、检测到的危险代码片段、风险等级（高/中/低）和具体触发了哪条规则。高等级是直接拼接用户输入，中等级是 fmt.Sprintf 带占位符，低等级是疑似但不确定的情况。

命令行参数：sqli-detector scan ./src 递归扫描目录，sqli-detector scan -f single_file.go 扫描单个文件。支持 -format=text|json 输出格式。

只用 Go 标准库（不需要 go/ast 那些复杂的，用正则匹配就行），go build 能编译通过。
