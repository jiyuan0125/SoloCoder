你见过最离谱的安全漏洞是什么？我见过一个——线上服务把用户输入的文件名直接拼到 shell 命令里执行，input_file + " | rm -rf /" 这种。这种命令注入漏洞危害极大，但现实中还真不少见，特别是内部工具和脚本。

用 Go 实现一个命令注入防护工具。分三个层面：

检测层：扫描用户输入中的危险字符和模式。shell 元字符：;、|、||、&&、$()、反引号、\n（换行符）。重定向符号：>、>>、<。变量替换：${}、$var。路径穿越：../。检测函数 DetectInjection(input string) []Warning 返回所有匹配到的危险模式及其位置。

转义层：对输入做安全转义。最可靠的方式是直接用 Go 的 exec.Command(name, args...) 接口，传参数列表而不是拼字符串。如果必须拼字符串的场景（比如传给外部脚本），用单引号包裹输入并转义内部的引号。EscapeShellArg(input string) string。

安全封装层：提供 SafeExec(name string, args []string) 函数封装 os/exec，内部强制规则——绝不使用 bash -c 模式、绝不从用户输入构造命令行、只接受预定义的命令名和参数列表形式调用。如果命令名不在白名单里直接拒绝。

包含几个测试用例展示常见攻击手法被拦截的过程：分号注入、管道注入、反引号替换、换行注入。

Go 标准库，go build 编译通过。
