公司内网有个基于 LDAP 的登录系统，用户名输入框直接拼进了 LDAP 查询字符串。测试环境试了一下输入 *)（|(uid=*)(userPassword=*)）就绕过了认证，还把所有用户信息都查出来了。LDAP 注入不像 SQL 注入那么常见，但危害一点不小。

用 Go 实现一个 LDAP 注入防护工具。三道防线：

输入检测：检测 LDAP 查询中的特殊字符——*（通配符，可能扩大查询范围）、( 和 )（LDAP 过滤器语法的关键字符）、\（转义字符）、/、NUL(\x00)。还有 LDAP 控制符 &（AND）、|（OR）、!（NOT），这些如果出现在用户输入中被拼进查询就会改变过滤逻辑。

输入转义函数 EscapeLDAP(input string) string：把危险字符转义成 LDAP 安全格式——反斜杠后跟两位十六进制编码。比如 * 转成 \2a，( 转成 \28，) 转成 \29，\ 转成 \5c，NUL 转成 \00。这是 RFC 4515 推荐的转义方式。

参数化查询构建器：不直接拼字符串，而是提供 SafeFilter() 函数。调用方式类似 fmt.Sprintf 但内部对占位符位置的输入自动转义——Filter("(&(uid=%s)(objectClass=user))", username) 自动把 username 里的特殊字符转义后再拼进去。

包含几个典型攻击场景测试：* 绕过认证、*)(|(uid=* 查询所有用户、)(cn=*)) 信息泄露。

Go 标准库，go build 能编译。
