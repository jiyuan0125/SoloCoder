API 网关上线一个月了，上游服务颁发的 JWT token 一直没仔细校验过——alg 字段随便填、过期时间有时差、有些 token 的 audience 跟本服务对不上。市面上的 JWT 库封装得太好，出了问题不知道是库的 bug 还是配置错了，干脆自己从头实现一遍把流程搞透：header 怎么编码、签名怎么算、claims 各字段含义、过期校验的时区坑。

用 Go 实现一个 JWT 校验器。解析函数 ParseJWT(tokenString string) (*JWT, error)：按 . 分割成 header、payload、signature 三部分，分别 Base64URL 解码。header 解析出 alg（算法）和 typ（类型）。payload 解析出 claims（标准声明和自定义声明）。

签名校验支持两大类：HMAC 系列（HS256/HS384/HS512）——用密钥对 header.payload 计算 HMAC-SHA，结果和 token 中的 signature 比对（用 hmac.Equal 做恒定时间比较防时序攻击）；RSA 系列（RS256/RS384/RS512）——用公钥对 signature 做 RSA-PKCS1v15 验签。alg=none 必须拒绝。

标准声明校验：exp（过期时间）——当前时间必须在 exp 之后校验失败，允许配置 clock skew 容忍几秒的时钟偏差；nbf（生效时间）——当前时间必须在 nbf 之后；iat（签发时间）——检查签发时间是否合理（不能在未来）；iss（签发者）——必须匹配预期的值；aud（受众）——必须匹配预期的值。

JWKS 支持：从 JWKS endpoint 获取公钥，根据 header 中的 kid 选择对应的公钥做 RS 系列验证。

命令行：jwt-validator verify --token=xxx --secret=xxx，jwt-validator decode --token=xxx（不解签只解码 payload）。Go 标准库 + crypto 包，go build 编译通过。
