对接第三方 SSO 的时候踩了个坑——他们的 JWKS endpoint 返回的公钥死活解析不了，最后发现是 n 和 e 的 Base64URL 编码有 padding。与其每次查 RFC 猜字段含义，不如自己写一遍 JWK 解析器，把 RSA 模数、EC 曲线坐标、对称密钥的解码全搞明白。

用 Go 实现一个 JWK 解析器。支持三种密钥类型：

RSA（kty=RSA）：n（模数）和 e（指数）是 Base64URL 编码的大整数，解码后用 big.Int 构建 rsa.PublicKey。还要处理可选参数 d（私钥指数）、p、q（素数因子）等私钥参数。

EC（kty=EC）：crv（曲线名称 P-256/P-384/P-521）、x 和 y 是 Base64URL 编码的曲线坐标点。解码后构建 ecdsa.PublicKey。

Oct（kty=oct，对称密钥）：k 是 Base64URL 编码的密钥字节。

JWKS（Key Set）解析：一个 JSON 数组包含多个 JWK。提供按 kid（Key ID）查找对应密钥的功能——JWKSet.Lookup(kid string) (*JWK, error)。

从远程 JWKS endpoint 获取密钥集：用 HTTP GET 请求 .well-known/jwks.json，解析返回的 JSON。带缓存和自动刷新——缓存 TTL 可配置（比如 1 小时），过期后后台异步刷新不影响请求。

命令行：jwk-parser parse key.json 解析单个 JWK 文件，jwk-parser fetch https://example.com/.well-known/jwks.json 获取远程 JWKS。

Go 标准库，go build 通过。
