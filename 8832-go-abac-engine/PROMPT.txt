RBAC 太粗了。有些场景需要根据用户属性（部门、职级）、资源属性（密级、所有者）、环境条件（时间、IP）做细粒度控制。比如"只有工作时间内、同部门、职级 P7 以上才能查看机密文档"——这个用 RBAC 没法表达，得用 ABAC。

用 Go 实现 ABAC（基于属性的访问控制）引擎。策略定义用 JSON 格式，每条策略包含：

条件表达式：基于主体属性（subject.department、subject.level）、资源属性（resource.classification、resource.owner_id）、环境属性（env.time、env.source_ip）的逻辑组合。支持比较操作符（==、!=、>、<、>=、<=、in）、字符串操作（contains、startsWith、endsWith）、时间范围判断。

策略评估 Evaluate(ctx Context) Decision：输入一组属性（JSON），根据所有策略计算结果。多条策略之间的组合逻辑支持 AND、OR、NOT。评估结果三种：Allow、Deny、Unknown（没有策略匹配时）。

冲突解决：支持两种模式——Deny 优先（只要有任何 Deny 策略匹配就拒绝）和按优先级（策略有 priority 字段，高优先级覆盖低优先级）。

评估日志：每次判断都记录输入属性、匹配了哪些策略、最终结果和耗时。方便审计和调试。

策略热加载：从 JSON 文件加载，文件变化时自动刷新。也支持通过 API 动态添加和删除策略。

Go 标准库，go build 通过。
