登录接口总被人暴力尝试密码。不是简单的限流问题——正常用户也可能输错几次密码，不能误伤。需要区分"正常用户偶尔输错"和"暴力破解大量尝试"。

用 Go 写一个暴力破解防护模块。跟踪维度：按 IP 跟踪——同一 IP 连续登录失败次数。按账号跟踪——同一账号被不同 IP 尝试的次数。两种维度独立计数。

防护策略配置：max_attempts（最大失败次数，默认 5）、lockout_duration（锁定时长，默认 30 分钟）、auto_unlock（是否自动解锁，默认 true）、decay_time（失败计数衰减时间，比如 15 分钟内的失败才计数）。

防护动作：临时封禁 IP——达到阈值后该 IP 的所有登录请求直接返回 429，不查数据库不做密码验证（节省资源）。记录告警日志——包含 IP、尝试的账号、时间窗口、失败次数。可选通知——调用 webhook 通知安全团队。

提供一个演示 HTTP 服务：模拟登录接口（POST /login，body: {username, password}）。正确的用户名密码是 admin/secret123。错误密码时计数，触发防护后返回拒绝响应。Go 标准库，go build 编译通过。
