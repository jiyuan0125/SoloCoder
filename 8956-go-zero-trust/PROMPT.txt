公司最近在推零信任架构改造，安全团队先把方案定好了——所有内部服务的访问请求都要过一遍策略引擎，根据用户身份、设备状态、来源网络、时间段等因素综合判断是否放行。现在需要一个决策引擎的原型来验证这个思路。

用 Go 写一个零信任访问控制器。核心逻辑是读取一份策略配置文件（JSON 或 YAML 格式），然后接收请求上下文参数，逐条匹配策略规则，输出最终的允许/拒绝决定。

策略规则要支持这些维度的匹配：用户身份验证状态（是否已登录、MFA 是否通过）、设备信任等级（公司设备、BYOD、未知设备三种）、请求来源 IP 段（属于内网网段、VPN 网段还是公网地址）、时间段限制（比如只允许工作日 9:00-18:00 访问）、请求频率限制（一分钟内超过 N 次自动拒绝）。规则之间支持 AND 和 OR 逻辑组合，多条策略按优先级从高到低排序，命中第一条即返回结果，所有规则都没命中时走默认策略——默认拒绝。

配置文件支持热加载。程序启动后监控配置文件的修改时间戳，检测到变更就自动重新解析加载，不需要重启进程。CLI 工具形式，eval 子命令接受一组请求参数（比如 --user=authenticated --device=corporate --ip=10.0.1.5 --time=14:30），输出匹配结果、命中的策略名称和规则详情。也支持批量模式，从 JSON 文件读取一组请求场景统一评估。纯 Go 标准库实现，go build 能编译通过就行。
