上周数据库被拖库了，从发现到处置花了四个小时，期间全靠微信群沟通——安全工程师发现异常后在群里喊了一声，DBA 半小时后才看到消息，确认问题后又花了二十分钟找到对应负责人批准断网操作，整个过程中关键取证信息散落在聊天记录里，事后复盘几乎没法还原完整的时间线。

用 Go 写一个安全事件响应编排工具，把混乱的应急流程变成可追踪、可执行的 playbook。

每个 playbook 是一组预定义的响应步骤，比如数据库泄露事件的 playbook 包含：确认告警真实性、隔离受影响数据库、导出访问日志作为取证、修改所有相关凭证、确认修复后恢复服务、写复盘报告。每个步骤有状态（pending、in_progress、done、skipped）、负责人、开始时间和结束时间、以及可添加的注释。

触发方式支持两种：手动用 CLI 命令创建事件实例并选择对应 playbook，或者通过 JSON 输入自动触发（可以对接上游告警系统）。事件的状态持久化到本地 JSON 文件，中断后可以继续推进。CLI 操作——创建事件、列出事件、推进步骤、查看详情、关闭事件。Go 标准库实现，go build 通过。
