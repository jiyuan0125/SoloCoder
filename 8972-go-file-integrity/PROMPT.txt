关键配置文件被偷偷改了但没人知道，这种事发生过不止一次了——有人调试的时候顺手改了 nginx 配置忘记改回来，有人把数据库密码在配置文件里换了个测试环境的值然后忘了还原，等到出了故障排查了半天才发现配置被改了。

用 Go 做一个文件完整性监控工具，类似 Tripwire 的简化版。工作原理是建立基准、定期比对、报告变化。

第一次运行时执行 init 命令，扫描指定目录下的所有文件，记录每个文件的 SHA256 哈希值、文件大小、权限位、属主和属组、最后修改时间，把这些信息存入基准数据库（本地 JSON 文件）。后续运行 check 命令时，重新扫描同样的目录，逐文件对比当前状态和基准记录，发现差异就报告。

检测的变化类型包括：新增文件（基准里没有的）、删除文件（基准里有但现在找不到了）、内容变化（哈希值不同）、权限变化（权限位改变）、属主变化（owner 或 group 改变）。支持排除规则，用 glob 模式排除不需要监控的路径（如 *.log、.git/、tmp/ 这些频繁变化的目录或文件）。

CLI 工具，子命令包括 init（建立基准）、check（检查变化）、update（把当前状态更新为新的基准）。Go 标准库实现，go build 通过。
