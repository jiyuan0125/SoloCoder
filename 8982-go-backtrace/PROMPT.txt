C 程序崩溃了，core dump 文件里只有寄存器快照和栈内存，要把这些原始数据还原成可读的调用栈信息——如果没有合适的工具，光看寄存器值和十六进制内存内容完全不知道程序崩溃时在做什么。

Go 写一个调用栈还原工具。输入是一组栈帧地址（通常从 RBP 寄存器链式回溯得到，或者从 core dump 的栈内存区域提取），结合对应 ELF 文件的符号表和 DWARF 调试信息，逐帧还原出函数调用链。

栈帧展开的原理：x86-64 架构下，函数序言通常会把上一个 RBP 压栈然后设置新的 RBP。所以从当前 RBP 开始，每次读 [RBP] 得到上一个 RBP，读 [RBP+8] 得到返回地址（RIP），一直追溯到 RBP 为 0 或者无效地址为止。这个过程叫 frame pointer chasing。

对每一帧的返回地址，用符号表查找函数名，用 DWARF 行号表查找源文件和行号。最终输出类似 gdb backtrace 的格式：#0 0x4005a0 in main.foo at main.go:42，#1 0x400620 in main.bar at main.go:38，依此类推。

也支持从文件读取一组 RIP/RBP 值对（不需要做 frame pointer chasing，直接解析地址）。Go 标准库实现，go build 通过。
