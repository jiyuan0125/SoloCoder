想写个 HTTP 头部注入检测工具。起因是公司的 WAF 规则里没有覆盖 CRLF 注入，而有些内部接口直接把用户输入塞进 HTTP 响应头里，这种组合就是个定时炸弹。

Python 实现检测流程：先对输入字符串做编码归一化（%0d%0a → \r\n、URL 解码到稳定状态），然后逐字符扫描，查找 CR（\r，0x0D）和 LF（\n，0x0A）及其各种编码形式。识别出 CRLF 注入后，进一步分析注入的内容——是在伪造新的响应头（比如注入 Set-Cookie）、还是在做响应拆分（注入完整的第二个 HTTP 响应）。

检测这些场景：
1. 响应头注入：在现有头部值中插入换行后接新的头部字段（如 Set-Cookie、Location）
2. 响应拆分：注入完整 HTTP 响应头 + 空行 + HTML 响应体
3. 头部字段名伪造：注入 Host、X-Forwarded-For、X-Real-IP 等可能影响后端路由的敏感头部
4. 编码绕过：\r 和 \n 的各种变体（%0d、%0a、\0x0d、\\r、\\n、Unicode 换行符）

每条检测结果输出：注入位置（字节偏移）、注入类型分类、伪造的头部字段名（如果有）、风险等级（高/中/低）。python3 命令行工具，支持单条检测和批量文件扫描。
