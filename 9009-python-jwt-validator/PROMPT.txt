JWT 调试的时候你遇到过这种纠结吗？token 签名验证不通过，但肉眼看 payload 内容又没问题，到底是密钥错了还是算法不匹配？写个工具把这些检查自动化。

Python 命令行工具，输入一个 JWT token，先拆分三段（header、payload、signature），Base64URL 解码后以格式化 JSON 输出各段内容。然后做一系列安全检查：

签名验证支持 HS256 和 RS256——HS256 需要提供对称密钥字符串，RS256 需要提供公钥 PEM 文件。验证过程要检查 Base64URL padding 是否正确、header 里的 alg 和 typ 字段是否合法。安全检查项包括：alg:none 攻击（header 声称无签名但 token 带了第三段）、算法混淆攻击（用 HS256 验证 RS256 签名、用公钥当 HMAC 密钥）、jku/x5u 头部注入风险提示。

时间相关的检查：exp 过期时间、nbf 生效时间、iat 签发时间，跟当前时间比较后给出"有效"/"未生效"/"已过期"状态，时间偏差容忍度可配置（默认 30 秒）。python3 实现，依赖尽量少，cryptography 库处理 RS256 验签即可。
