想搭一个 OpenID Connect Provider。几个内部应用各自维护一套登录逻辑，用户改个密码要登五个地方改，统一认证迫在眉睫。

在 OAuth2 授权码流程基础上扩展成完整的 OIDC Provider。流程是这样的：用户从应用跳转到 /authorize 端点，带上 scope=openid——服务端先认证用户身份（用户名密码校验），用户确认授权后生成 authorization code，应用用 code 换回 access_token 和 id_token。

id_token 用 JWT 格式，包含 sub（用户唯一标识）、name、email、aud（客户端 ID）、iss（签发者 URL）、nonce（防重放）。签名用 RS256，启动时自动生成 RSA 密钥对。提供 /.well-known/openid-configuration 发现端点，列出所有支持的端点 URL、支持的 scope 和 claim、签名算法。userinfo 端点用 access_token 调用，返回用户基本信息。

token 的有效期和刷新策略可配置，默认 access_token 一小时，支持 refresh_token 续期。命令行启动 HTTP 服务，python3 运行，尽量用标准库。
