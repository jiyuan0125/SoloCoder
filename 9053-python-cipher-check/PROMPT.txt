线上服务的加密套件配置一直没有审计过，可能还开着 RC4 或者 3DES 这些老古董。想知道具体哪些该关、哪些没问题，得实际连上去看服务端到底支持什么。

写个 Python 工具，连接指定主机和端口，枚举服务端支持的所有 TLS 密码套件。方法是用 ssl 模块逐个设置客户端的密码套件列表（只包含一个套件），尝试握手——成功说明服务端支持这个套件，失败说明不支持。

安全评级规则：安全套件使用 AES-GCM 或 ChaCha20-Poly1305 加密、ECDHE 或 DHE 密钥交换（提供前向保密能力）、SHA-256 及以上哈希算法。弱套件使用 AES-CBC 模式（存在 padding oracle 风险）、密钥交换不提供前向保密。不安全套件包含已废弃算法——RC4（受 Bias 攻击影响）、DES/3DES（Sweet32 攻击可破解）、NULL（无加密纯明文）、EXPORT（出口级弱加密，FREAK 攻击目标）、MD5 哈希（碰撞攻击）。

最后按安全程度排序输出——不安全的排最前面引起注意，每行显示套件完整名称、适用的 TLS 版本范围、安全等级、具体问题描述。python3 实现，用标准库 ssl 模块，能直接运行。
