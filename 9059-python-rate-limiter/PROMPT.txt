给 API 服务做一个限流器。之前接口被人用脚本疯狂调用，数据库连接池被打满，正常用户全部超时。后来临时加了个固定窗口限流，结果窗口边界处流量能瞬间打到两倍限流值。这次好好实现几种算法，在不同场景下选用最合适的。

Python 实现四种限流算法。固定窗口计数器：按时间窗口（如每 60 秒）统计请求次数，简单直观但窗口边界有突刺问题。滑动窗口计数器：把大窗口分成多个小格子（如每秒一个），统计最近 N 个小格子的总量，边界过渡更平滑。令牌桶：以固定速率往桶里放令牌，请求消耗令牌，桶满则丢弃，允许短时突发但长期平均速率受控。漏桶：请求排队以固定速率处理，输出完全平滑。

限流维度：按 IP 地址、按用户 ID、按 API 路径分别设置限流阈值，每个维度独立计数，取最严格的限流结果。配置示例：IP 每分钟 100 次、用户每分钟 30 次、热点路径每秒 500 次。

检查接口：输入请求标识（包含 IP、用户 ID、路径），返回 allow/deny 决定、当前已用量、剩余配额、重试等待秒数。用内存字典存储计数器，不需要外部 Redis 或数据库。写个简单的命令行演示，模拟并发请求场景测试各种算法的效果差异。python3。
