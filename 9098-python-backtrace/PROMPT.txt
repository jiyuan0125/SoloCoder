程序崩溃后留下的 backtrace 日志有时候格式不太规范，不好快速定位崩溃点。写个工具解析和格式化 backtrace，自动查找对应的源码位置。

Python 实现一个 backtrace 解析器。输入来源：标准崩溃日志（包含 #00 pc 地址 格式）、GDB 的 bt 输出、LLDB 的 thread backtrace、或者 addr2line 的输出。解析每帧信息——栈帧序号、程序计数器地址（PC）、共享库名称、函数名（如果有符号的话）、偏移量。

地址解析：如果有对应的带符号的二进制文件和 debug 信息，调用 addr2line 工具将 PC 地址转换为源文件名和行号。如果没有符号，至少展示库名+偏移量。支持批量解析——一次传入多个地址。

去抖动和去重：递归调用导致的重复帧自动折叠（如 #15-#20 都是同一个函数的递归调用，折叠为一行并标注递归深度）。异常帧检测：地址为 0x00000000 的空指针调用、栈帧地址不连续可能表示栈溢出。

输出格式化的调用栈，每帧显示序号、地址、函数名（加粗高亮）、源文件:行号、库名。也支持输出 JSON 格式方便自动化分析。python3 命令行工具。
