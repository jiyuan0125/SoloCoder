微服务架构里每个服务各自做权限检查太乱了，有些服务直接跳过了权限验证。想做一个集中的访问代理，所有请求先过这一层，通过后才转发到后端服务。

Python 实现一个访问控制代理（Access Broker）。请求流程：客户端发送请求到代理，代理提取请求中的身份信息（JWT token 或 API Key）和目标资源信息（HTTP 方法和路径），查询权限策略判断是否允许，允许则转发请求到后端服务，拒绝则直接返回 403。

身份验证：从请求头的 Authorization 字段提取 JWT token，验证签名和过期时间，提取用户 ID 和角色。API Key 模式则从 X-API-Key 头提取密钥，查询密钥对应的身份。策略引擎：从 YAML 配置文件加载策略规则，每条规则包含路径模式（支持通配符 /api/v1/*）、允许的 HTTP 方法、允许的角色或用户列表。

请求转发：用 requests 库将鉴权通过的请求转发到配置的后端地址，保留原始请求头（去掉鉴权相关的头部），返回后端响应。审计日志记录每次访问的决策结果。python3 命令行 HTTP 服务。


错误处理：后端服务不可用时返回 502，请求超时（默认 10 秒）返回 504。所有鉴权失败和转发请求都记录审计日志（JSON 格式输出到 stdout 和文件），包含时间戳、客户端 IP、用户 ID、请求路径、决策结果（allow/deny）、响应状态码。python3 命令行启动 HTTP 代理服务。
