安全事件响应的流程一直靠人肉协调——发现问题的人在群里喊一嗓子，然后大家各自去看日志，谁在做什么、进展到哪了全靠嘴说，复盘的时候翻聊天记录。写个工具把事件记录和任务分派标准化，让响应过程可追溯。

Python 实现一个事件响应管理工具。事件创建：记录基本信息——发现时间（自动填充当前时间）、报告人、事件类型（入侵、数据泄露、恶意软件、钓鱼、DDoS、权限滥用、配置错误）、严重等级（P1 紧急-半小时内必须响应/P2 高-4小时/P3 中-24小时/P4 低-72小时）、受影响的系统和服务列表、初始描述、已知的攻击指标（恶意 IP 地址、可疑域名、文件 SHA-256 哈希值）。

事件状态机：新建 → 确认（排除误报或确认真实威胁）→ 调查（收集证据、分析攻击路径和影响范围）→ 遏制（隔离受感染系统、封禁恶意 IP、撤销被盗凭证）→ 根除（清除后门、修复被利用的漏洞）→ 恢复（逐步恢复服务并监控）→ 关闭（撰写复盘报告、更新防御措施）。每个状态转换记录操作人、时间戳和操作备注。

任务管理：创建子任务指定负责人和截止时间。时间线自动汇总所有操作。数据存 SQLite，事件 ID 格式 INC-20260515-0001。python3 命令行工具。
