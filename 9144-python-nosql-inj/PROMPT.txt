NoSQL 注入不如 SQL 注入出名但同样危险。MongoDB 如果直接把用户输入作为查询条件，攻击者传一个 {"$gt": ""} 就能匹配所有记录绕过认证。写个工具检测和防御这类注入。

Python 实现两层防护。第一层输入检测：递归分析传入的查询参数（字典或 JSON 对象），检测典型的 NoSQL 注入模式——$where 操作符中的 JavaScript 代码（可以执行任意 JS）、$gt/$gte/$lt/$lte/$ne/$nin 等操作符在认证场景中的滥用（如 {"password": {"$ne": ""}} 匹配所有非空密码）、$regex 操作符用于正则注入、嵌套对象注入（多层嵌套的 $where 和 $or 组合）。

第二层输入清洗：sanitize() 函数递归遍历输入数据，将所有以 $ 开头的键名转义（在键名前加转义字符），防止被 MongoDB 解释为操作符。支持白名单模式——指定哪些操作符是允许的（比如查询接口允许 $in 但不允许 $where）。

也提供 WAF 中间件拦截 HTTP 请求中的疑似注入 payload。不依赖特定数据库驱动，纯输入分析。python3 命令行工具和库形式。
