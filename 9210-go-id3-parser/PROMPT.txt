MP3 文件的 ID3 标签版本太多太乱，v2.3 和 v2.4 的帧格式还不一样——帧大小计算方式不同、时间帧的名字也变了（v2.3 叫 TYER，v2.4 叫 TDRC）——想写个统一的解析器把这事搞清楚。

解析 ID3v2 标签，能处理 v2.3 和 v2.4 两个版本。先读 tag header（10 字节）：版本号（2 字节，主版本+修订号）、flag（unsynchronisation / extended header / experimental / footer 各占 1 bit），标签总大小用同步安全整数解码（4 字节，每个字节只用低 7 bit）。然后逐帧解析：帧 ID（4 字节 ASCII，比如 TIT2）、帧大小（v2.3 普通整数，v2.4 同步安全整数，这个区别一定要处理好）、帧 flag（2 字节），再根据帧 ID 解析内容——TIT2 标题、TPE1 艺术家、TALB 专辑、TRCK 曲目号、TDRC/TYER 年份、TCON 流派（带括号的数字编号要转换成文字）、APIC 封面图（报告 MIME 类型、描述和图片尺寸）、COMM 注释（前面有 3 字节语言代码 + 编码字节 + 描述前缀，要正确跳过）。遇到未知帧类型跳过并报告帧 ID 和大小，不要因为碰到不认识的帧就报错。遇到 unsynchronisation flag 置位的标签，要做反同步处理（把 0xFF 0x00 替换回 0xFF）。

Go 实现，纯标准库，同步安全整数的编解码自己写。go build 编译通过。
