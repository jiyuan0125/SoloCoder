GIF 这个格式说简单也简单——1987 年就定了规范，比 JPEG 和 PNG 都早。说复杂也挺麻烦，多帧动画、LZW 压缩、透明色、disposal method 这些概念搅在一起。写一个完整的 GIF 解析器等于把这些全过了一遍。

解析的起点是文件头——GIF87a 或 GIF89a，紧跟的是逻辑屏幕描述符：7 个字节包含了画布宽高、全局颜色表标志位和大小、背景色索引、像素宽高比。如果全局颜色表标志为 1，后面就是 2^(N+1) 个 RGB 三元组，每个颜色 3 字节。

接下来就是反复读数据块了——图像描述符（0x2C）里面有自己的坐标偏移、宽高和可选的局部颜色表。图像数据用 LZW 压缩，需要先读一个最小码长字节，然后按子块（sub-block）方式读取变长数据。LZW 解码要维护一个字符串表，初始大小由最小码长决定，遇到 clear code 重置表，遇到 info code 输出对应字符串并往表里加新条目。

扩展块（0x21）也不能忽略——图形控制扩展（0xF9）控制每帧的延时（单位是 10ms）、透明色索引和 disposal method（决定下一帧绘制前要不要清空画布）。注释扩展和应用扩展（比如 NETSCAPE2.0 的循环次数）也要能识别。

最后输出整张 GIF 的完整画像：帧数、每帧的偏移坐标和尺寸、延时、是否有透明色、disposal 方式、全局和局部颜色表大小、循环次数。命令行 gif-parse animation.gif。Go 标准库实现，go build 编译通过。
