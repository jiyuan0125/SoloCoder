线上视频转码服务最近加了一批新编码格式——VP9、AV1、HEVC——质量控制团队发现有些文件声称是 H.264 实际编码参数不合规。需要深入到视频流内部看编码器的配置记录，确认 profile、level、像素格式这些参数是否在平台允许范围内。

容器内的编码信息在哪里？MP4 的 stsd box 里——视频轨的 sample entry 类型名就是编码标识（avc1=H.264, hev1=H.265, vp09=VP9, av01=AV1）。H.264 和 H.265 各有一个配置记录（AVCDecoderConfigurationRecord / HEVCDecoderConfigurationRecord），里面包含 SPS/PPS/VPS。从 SPS 里可以解析出 profile（Baseline/Main/High）、level（3.0/3.1/4.0/4.1 等）、像素格式、色彩空间、实际编码尺寸。

MKV 的 CodecID 字段直接告诉你编码类型（V_MPEG4/ISO/AVC=H.264, V_MPEGH/ISO/HEVC=H.265, V_VP9=VP9, V_AV1=AV1），CodecPrivate 里是编码器私有数据，结构和 MP4 的配置记录类似。FLV 从视频 Tag 的编码 ID 字段判断（7=AVC/H.264, 12=HEVC）。

裸码流检测——没有容器的情况下，通过扫描 NAL 单元头判断：H.264 的 NAL 类型 7 是 SPS，类型 8 是 PPS，类型 5 是 IDR；H.265 的 NAL 类型 32 是 VPS，33 是 SPS，34 是 PPS。输出编码名称、profile、level、bit depth、chroma subsampling。用法 codec-detect video.mp4。Go 标准库，go build 通过。
