WebM 本质上就是 MKV 的子集——限制只能用 VP8/VP9 视频 + Opus/Vorbis 音频，EBML 结构完全一样但 DocType 是 "webm"。但 WebM 有些自己的扩展元素比如 VPCodecPrivate、DiscardPadding 需要专门处理。Rust 来写。

先验证 EBML Header 的 DocType 为 "webm"。然后解析 Segment 结构——跟 MKV 一样用变长整数编码。Info 元素里的 Duration 可能是浮点数（FLOAT 类型的 EBML 元素占 4 或 8 字节），需要正确解析。TimecodeScale 默认 100000000（纳秒级别的 100ms）。

Tracks 元素是重点——视频 Track 的 CodecID 是 "V_VP8" 或 "V_VP9"，CodecPrivate 里是 VP8/VP9 的编解码器私有数据。音频 Track 的 CodecID 是 "A_VORBIS" 或 "A_OPUS"，Opus 的 CodecPrivate 前面 8 字节是 OpusHead（版本、声道数、预跳过、采样率、输出增益、声道映射），后面可能有 OpusTags。

Cues 元素提供关键帧索引——解析 CuePoint 下的 CueTime 和 CueTrackPositions，获取每个关键帧在哪个 Cluster 的什么位置。有了这个索引就可以做随机 seek，不需要从头扫描到尾。用法 webm-parser info clip.webm。Rust 实现，cargo build 通过。
