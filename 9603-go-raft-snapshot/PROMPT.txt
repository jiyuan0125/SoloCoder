用 Go 实现 Raft 的快照机制。背景是日志不能无限增长，当日志积累到一定程度时，需要把当前状态机状态拍一个快照，然后截断之前的日志。

具体要求：状态机快照的生成和恢复、日志截断后 lastIncludedIndex 和 lastIncludedTerm 的维护、快照数据的序列化（用 JSON 或 gob 都行）。InstallSnapshot RPC 要能正常工作，让落后太多的 follower 通过快照赶上而不是逐条复制日志。

写个 demo 展示日志增长到阈值后自动触发快照，快照后日志被正确截断。go build 能通过。

补充几个关键点：对于批量处理场景支持目录扫描和通配符匹配。参数可以保存为配置文件方便复用。处理出错时给出具体原因和修复建议而不是一个笼统的 error。输出结果要清晰易读方便人工确认或者被其他程序调用。性能方面也要考虑——单次处理不能太慢，如果需要可以加个 --fast 模式牺牲精度换速度。

错误恢复机制也要考虑——如果程序崩溃了，重启后能从断点继续而不是从头开始。配置参数可以保存到文件下次直接 --config file.json 加载。支持管道输入输出方便和其他命令行工具组合使用。
