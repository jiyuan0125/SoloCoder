想基于 Raft 做一个最简单的分布式 KV 存储——支持 get、put、delete 三个操作的键值数据库，底层用 Raft 共识保证多节点数据一致。先别搞太复杂，能跑起来验证概念就行。

状态机就用一个 Go map 实现，put 操作往 map 里写键值对，get 操作从 map 里读，delete 操作删除对应的 key。所有写操作（put 和 delete）必须通过 Raft 日志提交后才能应用到状态机，读操作则要看一致性级别——最简单的方式是读也走 Raft 日志保证线性一致性，但性能差一些；也可以直接读 leader 的本地状态机，快但可能读到稍微旧的数据。先实现线性一致性版本：所有操作都作为 Raft 日志提交。

客户端通过命令行交互，输入 get key、put key value、delete key 这些命令。多节点间要保证数据一致：往节点 A 写了 key=val，从节点 B 读同一个 key 也能拿到 val。节点间用 HTTP 或 TCP 做简单的 RPC 通信。

跑起来能看到完整流程：启动 3 个节点，选举出 leader，客户端发写请求，日志复制到多数节点后提交，状态机应用，读请求返回最新值。go build 能编译。
