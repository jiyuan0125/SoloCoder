帮我用 Go 实现一个支持多 Raft 组的框架。单个 Raft 组只能串行处理请求，多组可以并行，比如 TiKV 那样的 multi-raft 架构。

每个 Raft 组管理自己独立的日志和状态机，组之间互不干扰。需要一个 RegionRouter 来根据 key 的范围把请求路由到对应的 Raft 组。支持动态分裂（split）：当一个组的负载太大时可以一分为二。

写个 demo：启动 3 个 Raft 组，分别管理 key range [a-f)、[f-m)、[m-z)，客户端发请求能看到被正确路由，触发一次 split 能看到组重新划分。go build 编译通过。

对了，还有个细节——对于批量处理场景支持目录扫描和通配符匹配。参数可以保存为配置文件方便复用。处理出错时给出具体原因和修复建议而不是一个笼统的 error。输出结果要清晰易读方便人工确认或者被其他程序调用。如果处理过程中出现什么问题，错误信息要具体到是哪个步骤哪条数据出的问题。

代码结构要清晰——核心逻辑和 CLI 入口分离，核心功能可以被其他脚本 import 使用。依赖尽量少只用标准库或者一两个常用第三方库。README 写清楚安装依赖和基本用法。
