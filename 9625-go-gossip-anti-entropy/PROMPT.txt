集群跑久了，不同节点的数据会慢慢产生差异——有的节点漏收了某些更新，有的节点重启后丢了内存数据。不需要立即修复，但最终得让所有节点数据一致，这就是反熵（anti-entropy）要做的事。

反熵的核心思路：节点定期随机挑一个伙伴，互相比较数据版本，找出差异部分并补齐。逐个 key 比较太慢了，用 Merkle Tree 来高效定位差异。每个节点维护本地数据集的 Merkle 哈希树——把所有 key 按哈希值分到不同的叶子节点，每个叶子节点存一段 key range 的数据哈希，父节点是子节点哈希的组合。比较时两棵树从根节点开始：根哈希相同说明数据一致，直接结束；根哈希不同就递归比子树，直到定位到具体的差异 key range，只传输有差异的部分。这比全量同步高效太多了，尤其是数据量大但差异小的时候。

模拟场景：5 个节点各自独立写入一些 key-value 数据（有重叠有不重叠），启动反熵后能看到每轮同步的数据交换过程。打印每轮反熵后各节点之间的一致性比例（相同的 key 占比），最终趋于 100%。中途有新数据写入的话一致性会先下降再恢复。
