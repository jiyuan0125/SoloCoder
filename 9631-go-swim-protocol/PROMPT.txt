用 Go 实现 SWIM 故障检测协议。SWIM 是一种可扩展的弱一致性成员管理协议，比传统的心跳方式更优雅。

SWIM 分为两个层次：故障检测层和传播层。故障检测用间接探测：节点 A 探测 B 不通，就请 C 代为探测 B。如果 C 也探不通 B，就认为 B 可能挂了。传播层用感染式传播（infection-style）把成员变更消息 piggyback 在探测消息上，不需要额外的传播通道。

实现一个完整的 SWIM：3 个节点以上的集群，能看到故障检测和消息传播的过程。模拟一个节点故障，其他节点在有限轮次内检测到。go build 编译通过。

另外要注意，对于批量处理场景支持目录扫描和通配符匹配。参数可以保存为配置文件方便复用。处理出错时给出具体原因和修复建议而不是一个笼统的 error。输出结果要清晰易读方便人工确认或者被其他程序调用。最终输出要包含处理摘要：成功多少个、失败多少个、跳过多少个。

接口设计要考虑易用性——新手看一眼 help 就能跑起来，高级用户有足够的参数可以调。输出格式统一用 JSON 方便后续脚本处理。如果处理过程中被中断（Ctrl+C），要把已处理的结果保存下来不要全部丢掉。
