集群加减节点的时候，有些数据得从一个节点搬到另一个节点。迁移过程要稳——不能丢数据，不能中断服务太久，中断了还得能恢复继续。

实现一个完整的数据迁移流程。第一步是确定迁移范围：哪些 key 需要从源节点搬到目标节点，通常是一个 key range（比如 [m-s)）。第二步是源节点扫描这个范围内的所有 key-value 数据并打包——可以用一批一批地读，每批 100 条，避免一次性读太多撑爆内存。第三步通过网络把打包的数据传输到目标节点——可以用 HTTP POST 或者直接 TCP 连接。第四步是目标节点接收数据并写入本地存储，写入时做基本的校验（key 的范围是否在预期之内）。第五步是迁移完成后更新路由表，把这段 key range 的归属指向新节点。整个过程中源节点继续服务读写请求（一致性可以放宽到最终一致——迁移期间读到旧数据可以接受）。断点续传：用一个进度文件记录"已经迁移到哪个 key 了"，中断后从上次的位置继续。

写个 demo：两个节点各存了一些 key-value 数据（模拟分布式 KV），触发一次迁移把 node1 上 key range [m-s) 的数据搬到 node2。迁移过程中打印进度（已迁移 N/total 条）。中途模拟一次中断，恢复后从断点继续。最终验证迁移后 node2 上有完整的目标数据，node1 上对应数据已清理。
