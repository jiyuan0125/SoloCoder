按 key 的范围来划分数据是最直观的分片方式——key 在 [a-m) 的去节点 1，[m-z) 的去节点 2。简单好理解，范围扫描也方便，但问题是容易热点：如果 key 分布不均匀（比如大部分 key 都以 s 开头），某个范围就会特别大。

主要做这几块。分片规则定义：每个分片是一个 [start, end) 的半开区间，分片之间不重叠，合起来覆盖整个 key 空间。路由查找：给定一个 key，二分查找确定它属于哪个分片（分片按 start 排序），然后返回对应的节点。分片分裂：监控每个分片的数据量或请求量，当某个分片超过阈值时一分为二——找到中间点把 [a-m) 拆成 [a-g) 和 [g-m)。分裂后创建新分片、数据迁移到新节点、更新路由表。分片合并：相邻分片数据量都很少时合并成一个，减少管理开销。分片元信息（分片范围、归属节点、数据量）要能持久化保存，节点启动时加载。

跑个 demo：初始 2 个分片覆盖 [a-z)，写入 10000 条随机 key 的数据。触发自动分裂——某个分片数据量超过 5000 条就一分为二。能看到分片如何越分越细：[a-z) → [a-m) + [m-z) → [a-g) + [g-m) + [m-z) → ...。打印每步分裂后的分片列表和数据量分布。
