用 Go 实现一个目录分片（Directory Sharding）方案。有些数据天然按目录或前缀组织（比如文件路径、用户 ID 前缀），按目录来分片比按单个 key 更高效。

做法：维护一个分片映射表（目录前缀 → 节点），查找时先匹配最长前缀，然后路由到对应节点。支持动态调整：某个目录数据量暴增时自动拆分为子目录分片。分片映射表变更时通知所有节点更新本地缓存。

模拟场景：文件系统按路径前缀分片，/usr/ 分到节点 1，/home/ 分到节点 2，/var/ 暴增后拆分为 /var/log/ 和 /var/data/。go build 编译通过。

还有一个实际问题：对于批量处理场景支持目录扫描和通配符匹配。参数可以保存为配置文件方便复用。处理出错时给出具体原因和修复建议而不是一个笼统的 error。输出结果要清晰易读方便人工确认或者被其他程序调用。命令行参数要设计合理——有默认值让最少参数就能跑，也有高级选项给需要调优的用户。

性能方面要注意——单个文件处理不能太慢（别超过 10 秒），批量处理时可以并行加速。内存占用也要控制，处理大文件时别超过 500MB。日志输出要分级：正常模式只打印摘要，verbose 模式打印每一步的细节。
