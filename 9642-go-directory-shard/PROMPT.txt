有些数据天然按目录或者前缀组织——文件系统按路径、用户数据按 user_id 前缀、日志按日期目录。按目录来分片比按单个 key 更高效，因为相关的数据聚在一起，范围查询和批量操作都快得多。

做法是维护一个分片映射表：目录前缀到节点的映射。比如 /usr/ → node1、/home/ → node2、/var/ → node3。查找时做最长前缀匹配——给定 /var/log/syslog，依次尝试 /var/log/syslog、/var/log/、/var/、/，取匹配到的最长前缀对应的节点。前缀匹配可以用 Trie（前缀树）实现，查找效率 O(L)（L 是路径长度）。支持动态调整：监控每个目录的数据量，某个目录暴增时自动拆分为子目录分片——比如 /var/ 增长太快就拆成 /var/log/ → node3、/var/data/ → node4。拆分后映射表更新并通知所有节点刷新本地路由缓存。合并则是反向操作——子目录数据量都变小了就合并回父目录。

模拟场景：一个文件系统按路径前缀分片。初始 / → node1 全包。写入一批数据后 /usr/ 暴增触发拆分 → /usr/ 分到 node2。继续写入 /var/ 也暴增 → 拆分为 /var/log/ → node3、/var/data/ → node4。最终打印映射表和各节点数据量。查询几个具体路径验证路由正确。
