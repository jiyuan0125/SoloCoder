分布式系统里客户端不知道数据在哪个节点，也不应该关心。路由器就是那个中间层——客户端把请求发给路由器，路由器根据 key 找到正确的后端节点转发过去，对客户端完全透明。

功能拆解成几块。路由映射表：维护分片到节点的映射，支持从 JSON 配置文件加载初始路由，也支持运行时动态更新（比如再平衡后路由变了）。路由表带版本号，更新时创建新版本替换旧版本，做到热切换——正在处理中的请求用旧版本，新请求用新版本，不存在读写竞争。请求路由：根据请求的 key 查路由表找到目标节点，然后把请求转发过去。连接池管理：对每个后端节点维护一个连接池（Go 的 net/http client 默认就有连接池，可以配置 MaxIdleConnsPerHost），避免每次请求都新建 TCP 连接。失败重试：目标节点不可用时（连接超时或返回错误），尝试该分片的副本节点（如果有的话），都失败才返回错误给客户端。

写个测试：启动 3 个模拟后端节点（简单的 HTTP server），分别负责 key range [a-m)、[m-s)、[s-z)。路由器加载配置后监听客户端请求。客户端发 get apple（路由到 node1）、get python（路由到 node3），能看到请求被正确转发。然后动态修改路由表（把 [a-m) 的节点从 node1 改成 node4），新请求立即路由到新节点。打印每次路由的决策过程。

Go 标准库 net/http，go build 编译通过。
