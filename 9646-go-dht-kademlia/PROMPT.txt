Kademlia 是 BitTorrent、IPFS 等系统都在用的分布式哈希表，用 XOR 距离来组织节点和数据的拓扑关系。和 Chord 的环形结构不同，Kademlia 是一个扁平的 160-bit ID 空间，距离定义为两个 ID 的异或值。

实现要点拆解如下。节点 ID 和 key ID 都是 160-bit 的值（SHA-1 哈希生成）。路由表用 k-bucket 结构：按与本地节点的 XOR 距离分桶，第 i 个桶覆盖距离范围 [2^i, 2^(i+1))，每个桶最多存 k 个节点（通常 k=20）。两种 RPC：FIND_NODE（找离目标最近的节点）和 FIND_VALUE（找目标 key 对应的值，如果中间节点有缓存就直接返回）。α 并发查找：每次向离目标最近的 α 个节点（通常 α=3）并发发送查询请求，不等上一个回复就发下一批，加速收敛。查找过程是迭代的——每轮选择当前已知的离目标最近的 α 个节点并发查询，收到回复后把新发现的更近的节点加入候选列表，再向这些更近的节点查询。重复直到找不到更近的节点为止。

模拟一个 50 节点的 Kademlia 网络：先让所有节点填充自己的 k-bucket 路由表，然后执行一次 FIND_VALUE 操作。打印每一轮查询了哪些节点、收到了哪些响应、当前已知最近节点距离的变化，最终几轮收敛找到存储目标 key 的节点。
