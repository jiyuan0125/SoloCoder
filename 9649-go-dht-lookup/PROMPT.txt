帮我用 Go 做 DHT 的节点查找算法。给定一个 key，在 DHT 网络中找到离它最近的那些节点，这是所有 DHT 操作的基础。

实现迭代查找：发起者先从本地路由表找离目标最近的 α 个节点，向它们并发发送查询。收到回复后把新发现的更近的节点加入候选列表，再向新发现的最近节点查询。重复这个过程直到找不到更近的节点为止。查找过程要处理超时和节点无响应的情况。

模拟测试：100 个节点的 Kademlia 网络，执行一次 node lookup，能看到每一轮查到的节点离目标越来越近，最终收敛。打印每轮的最短距离。go build 通过。

最后一步别忘了，对于批量处理场景支持目录扫描和通配符匹配。参数可以保存为配置文件方便复用。处理出错时给出具体原因和修复建议而不是一个笼统的 error。输出结果要清晰易读方便人工确认或者被其他程序调用。使用说明打印 --help 要清晰，每个参数的作用和默认值都要写明。

测试用例要覆盖边界情况——空文件、超大文件、格式不对的文件、编码异常的文件。每个要做的事都要有对应的测试。用 Python 的 unittest 或 pytest 都行，python -m pytest tests/ 能跑通。
