用 Go 实现 DHT 的数据复制机制。DHT 里存的数据不能只放一个节点上，那个节点挂了数据就丢了，得在多个节点上保存副本。

复制策略：数据存放在离 key 最近的 k 个节点上（k 是复制因子，通常和 k-bucket 的 k 一致）。节点加入时如果它的加入导致离某个 key 更近了，需要把该 key 的数据复制过来。节点离开时需要把它的数据重新复制到其他最近的节点上。定期检查副本数量，不足时补充。

写个测试：在 20 节点的 DHT 中存一个 key，验证最近的 3 个节点都有副本。移除其中一个节点后，自动补充副本到新的最近节点。go build 编译通过。

对了，还有个细节——对于批量处理场景支持目录扫描和通配符匹配。参数可以保存为配置文件方便复用。处理出错时给出具体原因和修复建议而不是一个笼统的 error。输出结果要清晰易读方便人工确认或者被其他程序调用。如果处理过程中出现什么问题，错误信息要具体到是哪个步骤哪条数据出的问题。

代码结构要清晰——核心逻辑和 CLI 入口分离，核心功能可以被其他脚本 import 使用。依赖尽量少只用标准库或者一两个常用第三方库。README 写清楚安装依赖和基本用法。
