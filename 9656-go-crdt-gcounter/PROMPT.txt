多节点场景下需要统计某个指标的总数（比如总请求数、总销售额），但每个节点只能增加自己的计数器，不能直接改别人的。G-Counter（Grow-only Counter）就是解决这个问题的 CRDT——每个节点维护自己的计数，合并时取各节点计数的最大值，结果一定收敛。

实现思路：每个节点有一个唯一 ID（比如 node-1、node-2）。G-Counter 内部用一个 map[string]int64 存储——key 是节点 ID，value 是该节点的本地计数。Increment() 操作只增加自己节点对应的计数器值（自增 1 或者增加指定量）。Value() 操作求和所有节点的计数值作为全局计数。Merge(other) 操作接收另一个 G-Counter 的状态，对每个节点 ID 取 max(本地值, 远程值)。因为只取最大值所以合并是幂等的，顺序无关的——不管以什么顺序合并，最终结果都一样。序列化和反序列化也要实现——把内部的 map 编码成 JSON 字节数组，方便通过网络传输或者持久化到磁盘。反序列化时还原成 map。

模拟测试：3 个节点各自创建 G-Counter。节点 A 增 3 次（值=3），节点 B 增 5 次（值=5），节点 C 增 2 次（值=2）。然后两两合并——A merge B 得到 {A:3, B:5}，再 merge C 得到 {A:3, B:5, C:2}，总值为 10。不管合并顺序如何结果都一样。

Go 标准库实现，go build 通过。
