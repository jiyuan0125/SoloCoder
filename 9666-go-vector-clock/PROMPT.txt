分布式系统里经常需要判断两个事件谁先谁后、或者是不是并发的。物理时钟不靠谱（各机器时钟有偏差），向量时钟（Vector Clock）用纯逻辑的方式来追踪因果关系。

实现方式：每个节点维护一个向量（实际上是 map[nodeID]counter），初始全零。事件发生时（本地操作或发送消息），自增自己节点的计数器：vc[nodeID]++。发送消息时把整个向量时钟附在消息上。接收消息时，对向量中每个节点 ID 取 max(本地值, 消息携带值)，然后自增自己的计数器。比较两个向量时钟的关系：如果 A 的每个分量都 ≤ B，则 A happened-before B（A 是 B 的因果前驱）；如果 A 和 B 有交叉（有的分量 A 大有的 B 大），则 A 和 B 是并发的；如果 A 的每个分量都等于 B，则 A 和 B 是同一个事件的等价视图。

写一个模拟来验证：3 个节点 A、B、C。A 发送消息给 B（携带 vc_A），B 收到后更新 vc_B 再发给 C，C 收到后更新 vc_C。打印每次事件后的向量时钟状态，验证 B 的事件确实 happened-after A 的事件。然后让 A 和 C 各自独立发一个事件（并发），验证两个向量时钟是 concurrent 关系。
