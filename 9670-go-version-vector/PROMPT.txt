版本向量（Version Vector）和向量时钟长得很像，但用途不同。向量时钟追踪事件的因果顺序，版本向量追踪数据副本的版本——某个 key 的值在各个副本上被更新了几次。读写的时候能看到数据来自哪些副本、各更新了几次，用于检测冲突和决定是否需要合并。

实现方式：每个数据副本有一个唯一 ID（比如 node-1、node-2）。版本向量是一个 map[replicaID]counter，记录每个副本对该数据的更新次数。Increment(replicaID)：对应副本写入数据时自增自己的 counter。Merge(otherVV)：对每个副本 ID 取 max(本地值, 远程值)，得到合并后的版本向量。Compare(vv1, vv2) 判断两个版本向量的关系——如果 vv1 的每个分量都 ≤ vv2，则 vv1 是 vv2 的祖先（vv1 descends from vv2）；如果 vv1 和 vv2 有交叉，则它们是并发的（concurrent），说明有冲突需要解决；如果所有分量都相等，则两个版本相同。

写个测试模拟典型的读写场景：3 个副本 A、B、C 写入同一个 key。A 写入 2 次（vv={A:2}），B 写入 3 次（vv={B:3}），C 只读。然后 A 和 B 交换版本信息，A 收到 B 的 vv 后 merge 成 {A:2, B:3}，B 同理。验证 A 和 B 的 merge 结果一致。再测一个并发冲突：A 写入（vv={A:1}）的同时 B 也写入（vv={B:1}），两边的 vv 互相 compare 显示 concurrent，标记为冲突需要解决。
