反熵和读修复都是自动机制，但有时候运维需要手动介入——发现某些 key 的副本不一致了，想主动扫描出来修复掉，而不是等后台慢慢跑。需要一个手动触发的数据修复 CLI 工具。

工具设计成两个子命令。scan 子命令：扫描指定范围的 key，从所有副本读取值和版本，比对找出不一致的。可以指定 key 范围（--start key1 --end key2）或者全量扫描（--all）。输出不一致的 key 列表，包括每个副本上的值和版本信息，以及建议的修复方案（取最新版本）。repair 子命令：执行实际修复。可以指定 key 范围或全量修复。修复逻辑：对每个不一致的 key，从所有副本读取，选出最新版本，写回到所有落后副本。修复前先打印修复计划（哪些 key 要修、怎么修），用户确认后执行。加个 --dry-run 参数可以只看不修。进度显示：扫描/修复了多少 key、剩余多少、发现不一致多少条、已修复多少条。

模拟测试：5 个节点的副本集群，故意制造 20 个 key 的不一致（各副本值不同）。运行 scan 命令，输出不一致的 key 列表。运行 repair --dry-run，输出修复计划但不执行。运行 repair，执行修复并打印进度。最终再 scan 一次验证全部一致。
