分布式 KV 的 Put 操作比 Get 复杂——写入要保证持久性（不能因为一个节点挂了就丢了），要处理并发写入同一个 key 的冲突，还要支持不同的一致性级别。

客户端发 put key value 请求到协调节点。协调节点找到 key 对应的所有副本，根据写一致性级别写入：one（写一个副本就返回成功）、quorum（写多数副本才返回成功）、all（写全部副本）。每个副本写入后返回确认（附带版本号）。协调节点收集到足够确认后返回成功。并发写入冲突的处理：如果两个客户端同时写同一个 key，各副本可能收到不同顺序的写入。冲突解决可以用 Last-Write-Wins（比较时间戳，新的覆盖旧的）或者版本向量（检测并发冲突，保留多版本让客户端解决）。这里先用 LWW 简单实现。写入失败处理：如果目标副本不可达且一致性级别允许，可以跳过该副本（降低一致性）或者用 hinted handoff 暂存。

模拟 3 节点集群：客户端 A 写 key=foo（version=1），客户端 B 同时写 key=bar（version=1）。Quorum 级别下，至少 2 个副本确认写入成功才返回。打印写入过程中各副本的响应和最终状态。然后模拟并发写同一个 key——A 和 B 同时写 key=valA 和 key=valB，LWW 策略下时间戳大的胜出。
