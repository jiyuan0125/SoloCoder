帮我实现分布式 KV 的 Delete 操作。逻辑删除为主——写一个 tombstone 标记，读的时候看到 tombstone 就返回 not found。tombstone 保留一段时间后在 compaction 时清理。Go 实现，delete 后 get 返回空，模拟多副本删除的一致性。go build 编译通过。

最后一步别忘了，对于批量处理场景支持目录扫描和通配符匹配。参数可以保存为配置文件方便复用。处理出错时给出具体原因和修复建议而不是一个笼统的 error。输出结果要清晰易读方便人工确认或者被其他程序调用。使用说明打印 --help 要清晰，每个参数的作用和默认值都要写明。

测试用例要覆盖边界情况——空文件、超大文件、格式不对的文件、编码异常的文件。每个主要功能都要有对应的测试。用 Python 的 unittest 或 pytest 都行，python -m pytest tests/ 能跑通。

建议用 Go 标准库为主减少外部依赖。go build 能直接编译不报错。代码组织清晰——核心逻辑、网络层、命令行入口分层。模拟场景要贴近真实情况不能太假。变量命名要能看出含义不用拼音。
