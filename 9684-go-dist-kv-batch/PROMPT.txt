数据迁移的时候一条一条写太慢了——10 万条配置数据导进去跑了快两个小时。后来加了个批量写入接口，攒一批后统一提交，30 秒就搞定了。这次用 Go 把批量写入模块好好实现一下。

做一个 batch 接口，客户端可以一次提交多个 put 和 delete 操作。batch 里的操作要么全部成功要么全部失败，中间有任何一个 key 写入失败（比如磁盘空间不够），整个 batch 回滚。底层复用已有的单条 put/delete 接口，但在内存中先把所有操作攒起来，攒满后统一执行——减少系统调用次数和网络往返开销。

batch 接口需要支持几种模式：同步模式调用后阻塞等所有操作完成返回结果；异步模式提交后立即返回一个 batch ID，后续可以查询执行状态。batch 大小有上限（比如最多 1000 条操作或者 4MB 总大小），超出就拒绝。每个 batch 操作有一个顺序保证——batch 内的操作按提交顺序执行，同一个 key 被多次写入时取最后一次的值。batch 执行完成后返回一个汇总结果：成功数、失败数、失败的 key 列表和对应的错误原因。

并发安全方面，多个客户端同时提交 batch 时不能互相干扰——每个 batch 是一个独立的事务单元。如果两个 batch 操作了相同的 key，按提交时间先后执行，后到的覆盖先到的。

go build 能过就行，带个 demo 演示批量写入 500 条数据并验证原子性。
