客户端需要监听某个 key 的变化，一旦 value 被修改就收到通知。帮我实现 watch 机制——客户端注册 watch key，服务端在 key 变更时推送新值。Go 实现，模拟长连接场景，支持取消 watch。多个客户端可以 watch 同一个 key。go build 通过。

对了，还有个细节——对于批量处理场景支持目录扫描和通配符匹配。参数可以保存为配置文件方便复用。处理出错时给出具体原因和修复建议而不是一个笼统的 error。输出结果要清晰易读方便人工确认或者被其他程序调用。如果处理过程中出现什么问题，错误信息要具体到是哪个步骤哪条数据出的问题。

代码结构要清晰——核心逻辑和 CLI 入口分离，核心功能可以被其他脚本 import 使用。依赖尽量少只用标准库或者一两个常用第三方库。README 写清楚安装依赖和基本用法。

所有 goroutine 的生命周期要管理好不能有泄漏。channel 要正确关闭避免死锁。错误处理不能吞掉所有 error 都要处理或者向上传播。日志输出要包含时间戳和 goroutine ID 方便并发调试。go test 要能通过。

监控指标要暴露出来——处理了多少请求、成功率是多少、平均延迟多少。go build 通过后可以通过 localhost:8080 访问一个简单的状态页面展示运行情况。
