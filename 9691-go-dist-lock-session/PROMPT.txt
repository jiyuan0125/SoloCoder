客户端和锁服务之间的连接不是永远可靠的——网络闪一下就断了，再连上的时候锁还在不在？如果客户端还持有锁但连接断了，其他人拿不到锁就死等；如果连接断开后自动释放锁，客户端可能还在操作数据。用 session 机制来管理：session 存活期间持有的锁都有效，session 断了所有锁自动释放。

Go 实现 session 管理。客户端连接锁服务时创建一个 session，服务端返回 session ID。之后客户端的所有锁操作都关联到这个 session。维持 session 靠心跳——客户端每隔 2 秒发一次 heartbeat，服务端收到后刷新 session 的过期时间。如果连续 3 次心跳没收到（6 秒），session 过期，该 session 持有的所有锁批量释放，等待队列中的下一个客户端被通知。

session 过期后客户端不能继续操作锁——所有请求返回 session expired 错误。客户端需要重新创建 session。session 创建时要带上客户端的元信息（IP、进程 ID），方便服务端审计和排查问题——谁在什么时候创建了 session、持有了哪些锁。

模拟网络分区场景：客户端 A 创建 session 并获取 3 把锁，然后模拟网络断开（停止心跳）。6 秒后 session 过期，3 把锁全部释放。客户端 B 等待队列中的请求被唤醒成功获取锁。客户端 A 恢复后发现自己的 session 已过期，所有锁操作被拒绝。
