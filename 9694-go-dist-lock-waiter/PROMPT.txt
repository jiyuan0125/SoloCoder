锁竞争时如果没有排队机制，所有等待者都在那盲等——不停轮询锁是否释放，CPU 和网络都浪费了。公平锁让等待者排个队，先来先得，释放锁时按 FIFO 顺序通知下一个等待者。

Go 实现一个公平锁等待队列。Lock(key) 时如果锁已被持有，不返回失败也不忙等，而是把当前请求加入该 key 的等待队列并阻塞。等待队列是 FIFO 的——最早排队的最先被唤醒。锁释放时，从等待队列头部取出一个等待者发送通知（通过 channel），被通知的等待者自动获得锁。如果同时有多个 key 在等锁，各自的队列独立运作。

等待者不能无限期等下去——Lock 时可以传一个 timeout 参数，超时还没拿到锁就从队列中移除并返回超时错误。等待者超时离开时不能阻塞队列——下一个等待者不受影响继续等。还要处理等待者主动取消的场景：调用 CancelLock(requestID) 从队列中移除，锁释放时不会通知已取消的等待者。

等待队列的状态要可查询：QueueLength(key) 返回等待者数量，QueueList(key) 返回所有等待者的 ID 和等待时间。这可以帮助监控哪些 key 的锁竞争特别激烈。

go build 编译通过，模拟 5 个客户端竞争同一把锁，验证它们按提交顺序依次获取锁。
