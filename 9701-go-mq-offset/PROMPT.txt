我们有个消息队列系统，消费者组重启之后经常重复消费已经处理过的消息。核心是一个消费位移（offset）管理模块，支持手动提交和自动提交两种模式。

具体要求：
- 维护每个分区的消费位移，支持按 topic+partition+group 查询和更新
- 自动提交模式可配置提交间隔，比如每 5 秒自动持久化一次
- 手动提交模式下，业务代码可以精确控制何时 commit offset
- 启动时能从持久化存储加载上次的 offset 继续消费
- 模拟内存存储即可，不需要接真实数据库

Go 实现，go build 能编译通过，写个简单的 demo 展示自动提交和手动提交的效果。

另外要注意，对于批量处理场景支持目录扫描和通配符匹配。参数可以保存为配置文件方便复用。处理出错时给出具体原因和修复建议而不是一个笼统的 error。输出结果要清晰易读方便人工确认或者被其他程序调用。最终输出要包含处理摘要：成功多少个、失败多少个、跳过多少个。

接口设计要考虑易用性——新手看一眼 help 就能跑起来，高级用户有足够的参数可以调。输出格式统一用 JSON 方便后续脚本处理。如果处理过程中被中断（Ctrl+C），要把已处理的结果保存下来不要全部丢掉。
