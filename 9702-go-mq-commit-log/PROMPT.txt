自研消息队列需要持久化存储，Kafka 的 commit log 方案很值得借鉴——消息顺序追加写入日志，通过 offset 快速定位，简单高效。核心在于分段（segment）和索引（index）的设计。

Go 实现 commit log 机制。日志按段（segment）存储，每个段是一个独立文件，配置最大大小（默认 1MB）。当前段写满后自动创建新段，文件名用 base offset 命名（比如 000000000.log、000001024.log）。每条消息追加写入当前活跃段，写入成功返回该消息的全局 offset（单调递增的 int64）。

读取时按 offset 查找：先用二分查找定位到目标 segment（比较 offset 和每个 segment 的 base offset），再在 segment 内通过索引定位。索引可以简单用 map 存储 offset → 文件内偏移量的映射，或者用稀疏索引（每 1000 条消息建一个索引项）加顺序扫描。按 offset 范围读取返回一组消息，支持 limit 参数限制返回数量。

日志目录可配置（默认 ./data/commit-log），启动时扫描目录下所有 .log 文件重建索引。消息格式包含：magic byte、消息长度、CRC32 校验、时间戳、key 长度、key、value 长度、value。CRC 校验失败的消息标记为损坏并跳过，返回警告。

go build 通过，演示写入 2000 条消息（触发多次段滚动），然后按 offset 范围读回来验证数据完整性。
