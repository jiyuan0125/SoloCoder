调用外部 API 经常超时或返回 503——这种瞬态错误重试几次就好了，但重试不能太暴力。固定间隔重试会加重下游负担，指数退避加抖动（jitter）才是正确姿势——等待时间越来越长但每次加一点随机性，避免所有失败请求同时重试形成惊群效应。

Go 实现任务自动重试模块。配置参数：maxRetries 最大重试次数（默认 3）、baseInterval 退避基数（默认 1 秒）、maxInterval 最大退避时间（默认 60 秒）。退避策略支持三种：固定间隔（每次等 baseInterval）、指数退避（delay = base × 2^retryCount，加上 0-1 秒的随机 jitter）、自定义函数（传入 retryCount 返回等待时间）。可以指定哪些错误才重试——用 ShouldRetry(err) bool 函数过滤，比如只对网络超时和 5xx 重试，4xx 不重试（客户端错误重试没意义）。

重试耗尽后的处理方式可配置：返回最后的错误（默认）、调用降级函数返回兜底值（比如从缓存取旧数据）、或者把任务转入死信队列等人工处理。每次重试都记录详细信息——重试次数、等待时间、错误消息。这些记录可以通过 GetRetryLog(taskID) 查询，方便排查"这个任务怎么跑了 30 秒"。

重试等待期间不能阻塞 goroutine——用 time.After 或者 timer 实现，等待期间 goroutine 可以处理其他任务。
