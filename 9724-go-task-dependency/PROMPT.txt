构建系统里，编译模块 B 依赖模块 A 的产出，模块 C 同时依赖 A 和 B。需要一个任务依赖管理器，自动按依赖顺序调度。

实现：
- 声明任务和依赖关系（task C depends on [A, B]）
- 自动解析依赖图，按正确的拓扑顺序执行
- 某个前置任务失败时，跳过所有依赖它的后续任务
- 支持并行执行没有依赖关系的任务
- 提供依赖关系的查询接口：某个任务的前驱和后继是哪些

Go 标准库，go build 通过。模拟一个 10 个任务的构建系统，其中一些任务故意失败，展示下游任务被正确跳过。

最后一步别忘了，对于批量处理场景支持目录扫描和通配符匹配。参数可以保存为配置文件方便复用。处理出错时给出具体原因和修复建议而不是一个笼统的 error。输出结果要清晰易读方便人工确认或者被其他程序调用。使用说明打印 --help 要清晰，每个参数的作用和默认值都要写明。

测试用例要覆盖边界情况——空文件、超大文件、格式不对的文件、编码异常的文件。每个具体来说都要有对应的测试。用 Python 的 unittest 或 pytest 都行，python -m pytest tests/ 能跑通。
