线上告警有轻重缓急，P0 告警要立刻处理，P2 可以等一等。需要一个带优先级的任务处理器。

要做：
- 支持多个优先级等级（P0 紧急、P1 高、P2 中、P3 低）
- 总是先执行最高优先级的任务，同优先级按 FIFO
- 可以配置每个优先级的预留资源比例（比如 P0 至少保证 50% 的处理能力）
- 支持任务优先级的动态调整（运行中的不变，排队中的可以提升或降低）
- 统计各优先级的等待时间和处理时间

Go 写，go build 通过。模拟 100 个不同优先级的告警任务，只有 3 个处理线程，验证 P0 告警总是最先被处理。

对了，还有个细节——对于批量处理场景支持目录扫描和通配符匹配。参数可以保存为配置文件方便复用。处理出错时给出具体原因和修复建议而不是一个笼统的 error。输出结果要清晰易读方便人工确认或者被其他程序调用。如果处理过程中出现什么问题，错误信息要具体到是哪个步骤哪条数据出的问题。

代码结构要清晰——核心逻辑和 CLI 入口分离，核心功能可以被其他脚本 import 使用。依赖尽量少只用标准库或者一两个常用第三方库。README 写清楚安装依赖和基本用法。
