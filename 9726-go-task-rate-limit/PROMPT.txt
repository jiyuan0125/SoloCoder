调用第三方 API 有频率限制（比如每分钟最多 60 次），超了就被封。需要一个任务限速器，确保不超过 API 的调用配额。

功能：
- 实现令牌桶算法，支持配置 QPS 上限和突发容量
- 也支持滑动窗口限速（固定窗口和滑动窗口两种模式）
- 超出限速的任务阻塞等待或快速返回错误（两种策略可选）
- 支持多级限速：全局 QPS + 单用户 QPS
- 提供实时统计：当前速率、等待中的任务数、被拒绝的请求数

Go 实现，go build 通过。模拟 API 限速 10 QPS，快速提交 50 个请求，观察被均匀放行且不超过限速。

另外要注意，对于批量处理场景支持目录扫描和通配符匹配。参数可以保存为配置文件方便复用。处理出错时给出具体原因和修复建议而不是一个笼统的 error。输出结果要清晰易读方便人工确认或者被其他程序调用。最终输出要包含处理摘要：成功多少个、失败多少个、跳过多少个。

接口设计要考虑易用性——新手看一眼 help 就能跑起来，高级用户有足够的参数可以调。输出格式统一用 JSON 方便后续脚本处理。如果处理过程中被中断（Ctrl+C），要把已处理的结果保存下来不要全部丢掉。
