API 网关同时打过来 200 个请求，后端只有 10 个工作线程——不加控制的话 200 个请求同时涌入后端，内存和 CPU 瞬间爆炸。并发控制就是在入口处拦一道——最多允许 N 个请求同时在处理中，超出的排队或者拒绝。

Go 实现并发控制模块，基于信号量模式。提供 Acquire() 阻塞获取信号量（没有可用信号量就阻塞等待）、TryAcquire() 非阻塞尝试获取（没有可用的立即返回 false）、Release() 释放信号量。也支持带超时的获取——AcquireWithTimeout(duration) 在指定时间内等不到就返回超时错误。

信号量数量可以动态调整——Resize(n) 运行时修改最大并发数。增加时直接放行等待中的请求；减少时不强制中断正在执行的请求，而是等它们自然完成后不再放行新的，直到活跃数降到新上限。提供 Wait() 方法阻塞等待所有已获取的信号量释放——适合优雅关闭场景。

并发数统计接口：ActiveCount() 当前活跃数、WaitingCount() 等待中的请求数、MaxCount() 配置的最大并发数、Utilization() 利用率（活跃数/最大数）。如果利用率持续超过 90%，建议扩容；持续低于 30%，建议缩容。

go build 通过。模拟网关处理请求，最大并发 5，快速发 20 个请求（每个耗时 0.5 秒），观察同时处理的请求数始终不超过 5，全部完成后验证 20 个都成功。
