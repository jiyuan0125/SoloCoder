用户在界面上提交了一个耗时任务，想看到进度条，知道还要等多久。需要给任务加上进度追踪。

实现：
- 任务可以上报进度百分比（0-100%）或已处理/总数（如 45/100）
- 进度信息实时可查，支持注册进度变更回调
- 长时间没进度更新时自动标记为"可能卡住"并告警
- 基于 Historical 进度估算剩余时间（ETC），考虑速度波动
- 进度信息可以序列化，方便通过 API 返回给前端

Go 标准库实现，go build 通过。模拟一个文件处理任务，处理 100 个文件，每处理完一个更新进度，展示实时进度和预计剩余时间。

对了，还有个细节——对于批量处理场景支持目录扫描和通配符匹配。参数可以保存为配置文件方便复用。处理出错时给出具体原因和修复建议而不是一个笼统的 error。输出结果要清晰易读方便人工确认或者被其他程序调用。如果处理过程中出现什么问题，错误信息要具体到是哪个步骤哪条数据出的问题。

代码结构要清晰——核心逻辑和 CLI 入口分离，核心功能可以被其他脚本 import 使用。依赖尽量少只用标准库或者一两个常用第三方库。README 写清楚安装依赖和基本用法。
