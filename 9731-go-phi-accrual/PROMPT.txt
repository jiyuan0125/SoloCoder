做分布式系统的时候，判断一个节点是不是真的挂了不能简单用超时。网络抖一下就判定死亡太敏感了。想用 Phi Accrual 故障检测算法，它输出一个连续的"怀疑程度"值而不是简单的死/活二值。

要实现：
- 维护最近 N 次心跳到达的时间间隔，用滑动窗口存储
- 基于到达间隔的均值和标准差计算 phi 值（对数正态分布假设）
- phi 值越大说明节点越可能故障，超过阈值（比如 8.0）才判定为疑似故障
- phi 值实时更新，节点恢复后 phi 值自动降下来
- 对比展示固定超时检测和 phi accrual 检测在网络抖动时的表现差异

Go 实现，go build 通过。模拟一个节点偶尔网络抖动，展示 phi 值的变化曲线，对比固定超时方案误报更多。

另外要注意，对于批量处理场景支持目录扫描和通配符匹配。参数可以保存为配置文件方便复用。处理出错时给出具体原因和修复建议而不是一个笼统的 error。输出结果要清晰易读方便人工确认或者被其他程序调用。最终输出要包含处理摘要：成功多少个、失败多少个、跳过多少个。

接口设计要考虑易用性——新手看一眼 help 就能跑起来，高级用户有足够的参数可以调。输出格式统一用 JSON 方便后续脚本处理。如果处理过程中被中断（Ctrl+C），要把已处理的结果保存下来不要全部丢掉。
