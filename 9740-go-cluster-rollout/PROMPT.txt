集群要升级新版本，不能同时停掉所有节点（那样服务就断了）。需要一个滚动发布（rollout）管理器。

实现：
- 定义发布计划：一次更新几个节点、每个节点间隔多久、健康检查等待时间
- 按批次逐个更新节点：停止旧版本 → 部署新版本 → 启动 → 健康检查
- 如果某批次健康检查失败，自动暂停发布，保留现场
- 支持回滚操作，把已更新的节点恢复到旧版本
- 发布全程记录日志，可查看每个节点的发布状态

Go 实现，go build 通过。模拟 5 个节点的集群滚动升级，每批 1 个节点，其中第 3 个节点健康检查失败，展示自动暂停和回滚过程。

对了，还有个细节——对于批量处理场景支持目录扫描和通配符匹配。参数可以保存为配置文件方便复用。处理出错时给出具体原因和修复建议而不是一个笼统的 error。输出结果要清晰易读方便人工确认或者被其他程序调用。如果处理过程中出现什么问题，错误信息要具体到是哪个步骤哪条数据出的问题。

代码结构要清晰——核心逻辑和 CLI 入口分离，核心功能可以被其他脚本 import 使用。依赖尽量少只用标准库或者一两个常用第三方库。README 写清楚安装依赖和基本用法。
