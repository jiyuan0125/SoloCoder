一台机器上跟 10 个对端通信，开 10 条 TCP 连接太浪费——每个连接都要握手、占用文件描述符、维护内核缓冲区。HTTP/2 的做法是一条连接上跑多个逻辑流，数据帧交织传输，接收方按流 ID 重组。理论上一条连接就够了，效率高得多。

Go 实现多路复用连接。在一条模拟的传输通道（byte channel 或 pipe）上承载多个独立的逻辑流（stream）。每个 stream 有唯一的 32 位 stream ID（奇数客户端发起，偶数服务端发起）。发送方把不同 stream 的数据切割成帧（frame），帧头包含 stream ID、帧类型（DATA/HEADERS/FIN/RST）、payload 长度，帧之间可以交织发送。接收方按 stream ID 分发到对应的 stream buffer。

流的完整生命周期：客户端发起 OpenStream() 分配新 stream ID 并发送 HEADERS 帧，双方都可以发 DATA 帧传输数据，任一方发 FIN 帧表示自己这边写完了（半关闭），双方都发 FIN 后 stream 完全关闭。RST 帧用于异常终止——立即关闭 stream 不等数据传完。

流量控制——每个 stream 有独立的滑动窗口（默认 64KB），发送方记录已发未确认的字节数，超过窗口大小就暂停发送。接收方处理完数据后发 WINDOW_UPDATE 帧通知发送方可以继续。某个 stream 窗口满了不影响其他 stream——各自独立控制。

物理连接断开后所有 stream 都收到错误通知。演示中用一个 byte channel 模拟物理连接。

go build 通过。一条连接上同时跑 3 个 stream 传输不同内容（文本、数字序列、随机字节），展示帧的交织传输和接收方按 stream ID 正确重组。
