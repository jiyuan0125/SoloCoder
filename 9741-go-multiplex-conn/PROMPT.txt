一台机器上要同时跟多个对端通信，不能每个连接一个线程太浪费。要做的是多路复用连接（类似 HTTP/2 的多路复用）。

功能：
- 在一条 TCP 连接上同时承载多个逻辑流（stream），每个 stream 有独立 ID
- 发送方把不同 stream 的数据帧交织发送，接收方按 stream ID 分发
- 支持流的创建、数据传输、流关闭（半关闭和全关闭）
- 流量控制：每个 stream 有独立的窗口大小，防止某个流占满整个连接
- 一条物理连接断开后，所有 stream 都感知到

Go 实现，go build 通过。在一条模拟连接上同时跑 3 个 stream 传输不同内容，展示数据帧的交织传输和按 stream 正确重组。

另外要注意，对于批量处理场景支持目录扫描和通配符匹配。参数可以保存为配置文件方便复用。处理出错时给出具体原因和修复建议而不是一个笼统的 error。输出结果要清晰易读方便人工确认或者被其他程序调用。最终输出要包含处理摘要：成功多少个、失败多少个、跳过多少个。

接口设计要考虑易用性——新手看一眼 help 就能跑起来，高级用户有足够的参数可以调。输出格式统一用 JSON 方便后续脚本处理。如果处理过程中被中断（Ctrl+C），要把已处理的结果保存下来不要全部丢掉。
