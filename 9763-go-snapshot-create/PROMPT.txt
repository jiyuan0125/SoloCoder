日志不可能无限增长，磁盘放不下，重启回放也慢得要命。定期给状态机拍个快照，把当前状态序列化保存，然后就能放心地截断旧日志了——这是分布式存储系统的标准操作。用 Go 来实现快照创建的完整流程。

状态机就用一个简单的 KV 存储来演示。程序维护两个核心数据结构：一个 map[string]string 作为状态机，一个 []LogEntry 作为操作日志（每条日志包含 index、term、command）。当写入操作（Put/Delete）到达时，同时追加日志和更新状态机。

快照触发条件可以简单点——日志条目数量超过 100 条时自动触发，或者通过命令行手动触发。触发后做的事情：把状态机的整个 map 序列化为 JSON（或者 gob），记录当前 lastApplied 的索引值作为 lastIncludedIndex，保存为快照文件或内存结构。

快照保存成功后的清理工作：删除 lastIncludedIndex 及之前的所有日志条目，释放内存。打印创建报告——"snapshot created: 100 log entries compacted, snapshot size 2.3KB, state has 47 keys, 53 log entries remaining"。

还要支持连续创建多次快照：第二次快照在第一次的基础上继续，只保存增量部分的状态变化。重启后从最新快照恢复，再回放剩余日志，验证结果正确。

Go 标准库实现，go build 能编译。
