多个客户端同时做加减法，最终结果还得跟串行执行一模一样——这就是分布式计数器状态机要解决的问题。用 Go 实现它，重点在于操作日志驱动和顺序保证。

状态机本身很简单：维护一个 int64 的计数器值，支持 Increment(n) 和 Decrement(n) 两种操作。但关键在于这些操作必须通过日志驱动——每条日志记录一个操作指令，状态机严格按 index 顺序 apply 每条日志。不能直接调用 Increment 跳过日志，否则重启后就无法恢复了。

操作的序列化格式：每条日志记录 {"op":"incr","value":5} 或 {"op":"decr","value":3}，外加 index 和 term 字段。Apply 时解析操作类型和参数，更新计数器。

并发场景的模拟：启动 10 个 goroutine，每个并发往日志里追加 100 个随机操作（Incr 或 Decr 随机值）。追加可以并发，但 apply 必须按 index 顺序串行执行。最终验证并发追加+串行 apply 的结果，和预先算好的预期值完全一致。

另外还得支持快照——把当前计数器值和 lastApplied 保存下来。模拟"重启"：清空内存状态，从快照恢复，然后回放快照之后的日志，验证最终值正确。

Go 标准库，go build 编译通过。
