系统崩溃重启后第一件事就是 WAL 回放——从头到尾读一遍日志，把每条记录重新应用到状态机上，恢复到崩溃前的状态。这个过程需要正确处理各种异常情况，用 Go 把它实现得健壮一点。

回放的基本流程：从 WAL 目录读取所有 segment 文件，按编号排序。依次打开每个文件，逐条读取记录（格式仍然是 [length][crc][data]）。对每条记录验证 CRC32——校验通过则解析操作内容，调用状态机的 Apply 方法执行；校验失败则打印警告并停止回放（说明这是崩溃时没写完的最后一条）。

状态机用 KV 存储来演示。操作格式：{"op":"put","key":"x","value":"42"} 或 {"op":"delete","key":"y"}。回放时按序执行这些操作，最终状态就是崩溃前的最新状态。

需要处理的几种情况：空 WAL 目录（首次启动，状态机保持初始状态）、部分写入的记录（CRC 校验失败，忽略这条及之后的记录）、多个 segment 之间跳跃（前一个 segment 正常读完，继续读下一个）。回放完成后打印统计："replayed 847 records from 3 segments, last valid index=847, state machine has 156 keys"。

还要支持一个 dry-run 模式：只读取和校验但不 apply，用于检查 WAL 的完整性。

Go 标准库实现，go build 能编译。
