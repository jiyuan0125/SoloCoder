因果一致性是分布式系统里一个很精妙的模型——比强一致弱一点（无关的操作可以乱序执行），比最终一致强一点（有因果关系的操作必须按序执行）。比如"用户 A 发帖"先于"用户 B 评论这条帖子"，这两个操作有因果关系，所有节点必须先看到帖子再看到评论。但用户 A 的帖子和用户 C 的帖子无关，谁先看到都行。

用 Go 实现因果一致性需要几个关键组件。首先是向量时钟（vector clock）：每个节点维护一个 map[nodeID]counter，本地事件时自增自己的 counter，发送消息时带上整个 vector clock。接收方合并两个 vector clock（逐节点取 max）再自增自己的 counter。

因果依赖的检查：节点收到一个操作时，先检查这个操作携带的 vector clock 是否" happened-before" 本地的 vector clock。具体来说，对于 vector clock 中的每个节点，操作携带的 counter 都要 <= 本地的 counter。全部满足才能执行，否则缓存等待。

等待和执行：不满足依赖的操作先放到一个等待队列里。每次本地有新操作执行后，扫描等待队列检查是否有操作可以释放了。有则执行，无则继续等。

模拟场景：3 个节点，操作之间有因果链 A→B→C（A 是 B 的前提，B 是 C 的前提）。消息可能乱序到达（B 比 A 先到），验证节点能正确缓存 B 等到 A 到达后再按序执行。

Go 标准库实现，go build 编译通过。
