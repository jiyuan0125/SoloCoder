之前遇到过一个线上 bug：用户反馈说"我刚看到的订单状态是已发货，刷新一下怎么变成待发货了？"调查发现是负载均衡把他导到了不同的副本，两个副本的数据版本不一样。这就是单调读被违反的场景——同一个客户端连续读同一个 key，不应该看到时间倒退。用 Go 来实现这个保证。

实现思路：客户端侧维护一个 per-key 的 maxVersionMap，记录每个 key 曾经看到过的最高版本号。每次从服务端读取数据后，如果返回的 version > maxVersionMap[key]，更新这个记录。如果返回的 version < maxVersionMap[key]，说明发生了时间倒退（过期读），拒绝这次结果并重试。

重试逻辑：被拒绝的读取会换一个副本重新发起请求，最多重试 3 次。如果 3 次都返回过期数据（说明所有可达副本都还没同步到），退而求其次返回最新拿到的数据，但打印一个警告。

模拟场景：3 个副本，版本分别是 v5、v3、v4。客户端第一次读到 v5（更新 maxVersion=5），第二次被导到落后的副本拿到 v3——检测到 v3 < maxVersion=5，拒绝并重试。第三次拿到 v5，正常返回。

运行 1000 次连续读取，统计被拒绝的过期读次数、平均重试次数。和不做单调读保护的情况做对比。

Go 标准库，go build 编译通过。
