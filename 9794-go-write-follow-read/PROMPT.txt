先读一个值，然后基于这个值做写入——这个顺序很重要。比如客户端读到商品库存是 5，然后下单减 1，库存应该变成 4。但如果在客户端读和写之间，另一个客户端已经把库存改成 3 了，这时候再做"减 1"操作结果就不对了。写跟随读（writes-follow-reads）要保证的是：写操作必须基于不比之前读到的更旧的版本。

用 Go 实现这个机制的方式：客户端读取数据时，服务端返回 (value, version)。客户端做写操作时，把之前读到的 version 作为前提条件一起发送：("SET stock=4 IF version=5")。服务端执行写之前检查当前数据的 version 是否等于客户端的 readVersion。等于则执行写，version+1。不等于（被别人抢先改了）则拒绝，返回冲突错误让客户端重新读取最新值再试。

这就是乐观并发控制（OCC）的基本思路。在高并发场景下冲突率会上升，但大多数场景读多写少，冲突不频繁。

模拟场景：3 个客户端同时读取 stock=5，各自尝试把库存减 1。只有第一个客户端的写会成功（version 匹配），后两个会收到版本冲突错误，需要重新读取（此时 version 已经变了）再重试。最终 stock 应该变成 2，且每一步的冲突和重试都要打印清楚。
