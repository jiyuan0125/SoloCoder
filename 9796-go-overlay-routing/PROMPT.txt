前段时间研究 P2P 网络的时候在想，那些覆盖网络（overlay network）到底是怎么在底层 IP 网络之上又建一层路由的？每个节点有一个虚拟地址，消息不是直接发给目标，而是一跳一跳经过中间节点转发过去。这个路由过程到底怎么实现的？用 Go 来做一个实际的覆盖网络路由器看看。

每个节点有一个 Virtual ID（VID），比如 8 位的十六进制字符串。节点维护一张路由表，记录"如果要到达某个 VID 区间，下一跳应该发给谁"。路由策略用贪心转发——每次选距离目标最近的邻居作为下一跳。距离度量用 XOR distance（和 Kademlia 一样），即两个 VID 的异或值，值越小越近。

消息转发的流程：节点收到一条目标不是自己的消息后，查找路由表中距离目标最近且比自己更近的下一跳节点，把消息转发过去。如果找不到比自己更近的节点（说明自己就是最接近目标的），消息到达终点。每跳记录经过的节点，最终打印完整的路由路径。

构建一个小型覆盖网络：12 个节点，VID 从 000 到 bbb。随机连接邻居（每个节点连 3-4 个），构建路由表。测试几个端到端的消息传递——比如从节点 000 发消息到节点 bbb，打印路径 "000 → 0a3 → 8f2 → bbb (3 hops)"。

Go 标准库，go build 通过。
