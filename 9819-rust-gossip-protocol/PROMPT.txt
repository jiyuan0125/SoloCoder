先明确 Gossip 协议要解决的核心问题——在一个没有中心协调者的集群里，怎么高效地把一条消息扩散到所有节点。每个节点只知道少数几个邻居，但通过多轮交换，消息最终能传遍全网。用 Rust 实现完整的 Gossip 协议，包括 push、pull 和 push-pull 三种模式。

消息传播的基本模型：每个节点维护两个集合——received（已经收到过的消息 ID 集合）和 pending（还没传播出去的消息集合）。每次 Gossip 交互时，节点从 pending 集合中选一些消息发给对端，然后把这条消息从 pending 移到 received（表示已经传播过了）。

三种模式的对比。Push 模式：节点主动把消息发给随机邻居，邻居收到后继续 push。Pull 模式：节点定期问随机邻居"你有什么新消息？"，邻居返回差集。Push-Pull 模式：双向交换，每次交互双方都告诉对方自己有什么新的。

收敛效率的测量：从节点 0 发出一条消息，每轮统计已收到消息的节点数。记录完全收敛需要的轮数。理论上 push 模式在节点数多时收敛慢（后期很难把消息送到最后几个节点），pull 模式前期慢但后期快，push-pull 是最优的。

模拟 50 个节点，分别用三种模式传播同一条消息，对比收敛轮数和每轮的已覆盖节点数。
