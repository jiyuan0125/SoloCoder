Anti-entropy（反熵）是 Gossip 协议中用来修复数据不一致的机制。普通的 rumor mongering 可能会遗漏一些消息（节点临时不可达时），anti-entropy 通过定期全量对比来补齐缺失的部分。Cassandra 就是用 Merkle Tree 来做 anti-entropy 的。用 Rust 实现一个基于版本向量的 anti-entropy 同步。

数据模型：每个节点存储一组 key-value 对，每个 value 带一个版本号（单调递增）或向量时钟。节点间定期做 anti-entropy 同步——选一个随机对端，比较双方的版本信息，找出差异，互相补齐。

同步流程的三个步骤。第一步是版本交换：节点 A 把自己的 (key, version) 列表发给节点 B。第二步是差异计算：B 对比两个列表，找出 A 有但 B 没有的（或者 B 的版本更新的）key 列表，以及 B 有但 A 没有的。第三步是数据传输：双方各自把缺失的数据发给对方。

优化——Merkle Tree 索引：如果 key 很多，交换全量版本列表太慢。用 Merkle Tree 把 key 按范围分成桶，每个桶一个哈希值。对比时先比较树根，如果相同说明整棵子树一致，不用继续比。不同则递归比较子树，直到找到差异的叶子节点。

模拟 5 个节点，每个节点有 100 个 key。故意让节点 3 漏掉 10 个更新，然后触发 anti-entropy，观察修复过程。
