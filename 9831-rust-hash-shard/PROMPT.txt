有次面试被问到哈希分片和一致性哈希有什么区别，没答好。后来自己想明白了——哈希分片是 key % N 直接映射到固定数量的分片，加节点得重新分配所有 key。一致性哈希是映射到环上，加节点只影响相邻区间。这个程序用 Rust 实现最朴素的哈希分片，方便和一致性哈希对比。

分片的规则：给定 N 个分片（编号 0 到 N-1），key 的分片号 = hash(key) % N。hash 函数用简单的 fnv1a 或 murmurhash。每个分片是一个独立的 HashMap<String, Vec<u8>>，存储属于它的所有 key-value 对。

查询操作：hash_get(key) 计算分片号，从对应分片的 HashMap 查找。写入操作：hash_put(key, value) 计算分片号，写入对应分片。范围查询不支持（因为哈希打散了 key 的自然顺序）。

节点变更的问题演示：N=3 时写入 1000 个 key，然后 N 改成 4。打印需要迁移的 key 比例——理论上是 75% 的 key 需要重新分配（只有 hash(key) % 3 == hash(key) % 4 的 key 不用动）。这个比例说明朴素哈希分片在扩容时代价很大。

和一致性哈希的对比：同样从 3 节点扩到 4 节点，一致性哈希只需要迁移约 25% 的 key。用代码验证这个理论值。
