先搭好 Chord DHT 的环结构，再实现查找、插入、节点加入这几个核心操作。Chord 把节点和 key 都映射到一个哈希环上，通过 finger table 做 O(log N) 跳查找。用 Rust 实现一个可以在单进程内模拟的完整 Chord DHT。

哈希空间的设计：用 64 位哈希空间（u64），key 和 nodeId 都通过 SHA-256 取前 8 字节映射到 u64。环是 [0, 2^64) 的区间，节点按顺时针排列。每个节点负责从 predecessor 到自己的区间。

Finger Table 的构建：节点 i 的第 k 个 finger 指向 successor(i + 2^k mod 2^64)。m=64 所以理论上最多 64 个表项，但实际只需要 log(N) 个有效的（很多指向同一个节点）。查找时从最高位开始，如果 finger[k] 比自己离 target 更近就跳过去。

关键操作的实现：find_successor(id) 查找 id 的负责节点（O(log N) 跳）、put(key, value) 把数据存到负责节点、get(key) 查找数据、join(existing_node) 新节点加入环并通知其他节点更新 finger table。

模拟 16 个节点的 Chord 环，插入 100 个 key，打印几次查找的路由路径。展示 finger table 如何加速查找——从 16 个节点的环中，一次查找通常只需要 4 跳左右。
