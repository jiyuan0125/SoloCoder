之前看 Kademlia 论文时对路由表的组织方式一直半懂不懂——什么是 k-bucket？为什么按前缀位数分层？直到自己实现了一遍才理解，原来每一层对应的就是距离的不同数量级。用 Rust 把 DHT 的路由表管理单独拿出来做清楚。

路由表的数据结构：RoutingTable 是一个数组，长度等于 ID 位数（比如 64）。第 i 个元素是一个桶（bucket），存储所有满足"和自身 ID 的 XOR 距离在 [2^i, 2^(i+1)) 范围内"的节点。直观理解：第 0 层是距离最近的节点（XOR 差值 < 2），第 63 层是距离最远的。

k-bucket 的管理：每个桶有容量上限 k（默认 20）。新节点加入时，如果对应桶没满就直接插入（按最后活跃时间排序，最新的在尾部）。如果桶满了，先 ping 最老的节点——还活着就保留老的，丢弃新的；死了就替换。

路由查找：给定 target ID，从距离最近的桶开始搜索（最高位对应的桶），找到桶中距离 target 最近的 α 个节点返回。如果没有节点，往相邻桶扩展搜索。

模拟：创建 100 个节点，给节点 0 构建完整的路由表。打印每层桶的节点数量——应该是最远层最多（因为范围最大），最近层最少。然后执行几次查找，展示从路由表中选出的 α 个最近节点。
