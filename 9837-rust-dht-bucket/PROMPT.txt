k-bucket 是 Kademlia DHT 的路由基础结构。和 Chord 的 finger table 不同，k-bucket 不是精确指向一个节点，而是一个"候选池"——每个桶存最多 k 个节点，查找时从候选池里选最近的。这种设计更容错——单个节点下线不会导致路由失败。用 Rust 单独实现 k-bucket 的管理逻辑。

k-bucket 的数据结构：KBucket 包含一个节点列表（Vec<NodeInfo>，按最近活跃时间排序）、容量上限 k。NodeInfo 包含 node_id、address、last_seen 时间戳。

核心操作的实现。Insert：新节点到来时，如果桶没满，插入到尾部（最新的）。如果桶满了，检查头部的最老节点是否还存活（通过 ping 模拟）。存活则丢弃新节点；不存活则移除头部，新节点插入尾部。Update：收到已有节点的消息时，把它移到尾部（更新活跃时间）。Remove：节点下线时直接从列表中删除。

桶的分裂：有些 DHT 实现（比如 BitTorrent）支持桶分裂——当一个桶满了且该桶覆盖了自身 ID 的区间时，把桶一分为二。这样自身 ID 附近的桶更密集，路由更精确。这个程序也实现这个优化。

模拟：创建 1000 个节点 ID，向一个 k=8 的路由表逐个插入。观察哪些桶被填满了、分裂后桶的分布。打印路由表概览——每层桶的节点数和覆盖的 ID 范围。
