先定义 DHT 的存储接口，再实现数据的 put/get 和副本管理。在 Kademlia 里，数据 (key, value) 被存放在距离 key 最近的 k 个节点上。查找时也是找最近的 k 个节点然后取值。用 Rust 实现 DHT 的存储层。

数据记录的格式：Record { key: Vec<u8>, value: Vec<u8>, timestamp: u64, ttl: u64 }。key 和 value 都是字节序列，timestamp 记录存储时间，ttl 是过期时间。记录存储在距离 hash(key) 最近的 k 个节点上。

Put 操作：计算 key_hash = hash(key)。通过 DHT 查找找到距离 key_hash 最近的 k 个节点。向这 k 个节点并行发送 STORE 请求，每个节点把记录存到本地存储中。不需要所有 k 个都成功——只要多数（比如 k/2+1）成功就认为 put 完成。返回实际存储成功的节点数。

Get 操作：计算 key_hash，查找最近的 k 个节点，向它们发 FIND_VALUE 请求。任何一个节点有数据就返回（最快的那个）。如果多个节点都返回了，取 timestamp 最新的。如果都没有，返回 NotFound。

副本一致性：没有强一致保证——put 是往多个节点写，但可能有部分失败。get 取最新的那个。定期通过 republish 机制刷新副本——原始发布者每隔 ttl/2 时间重新发布一次，确保副本不会过期丢失。

模拟 20 个节点的 DHT，put 50 个 key，观察每个 key 的副本分布。然后故意关掉 2 个节点，验证 get 仍能成功。
