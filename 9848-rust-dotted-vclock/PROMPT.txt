向量时钟有一个已知问题——客户端不断更新同一个 key 时，向量时钟会越来越大（因为每个更新者的 counter 都要记录）。Dotted Version Vector（点版本向量）通过把"当前更新者"和"已观察到的版本"分开来解决这个膨胀问题。用 Rust 实现这个优化。

Dotted VV 的数据结构：DotVersionVector { dot: (node_id, counter), context: VectorClock }。dot 是当前这个版本的"点"（谁写的、第几次写），context 是写这个版本时看到的所有其他版本（一个标准的向量时钟）。这样就把"谁更新了"和"更新时看到了什么"分开了。

更新的流程：节点写新版本时，dot 变成 (self_id, context[self_id] + 1)，context 更新为 merge(context, old_dot)。这样 dot 只有一个节点的 counter，不会膨胀。

版本比较的规则：版本 A 的 dot 被 B 的 context 覆盖（A.dot.node 在 B.context 中且 B.context[A.dot.node] >= A.dot.counter），则 A 是 B 的祖先（A before B）。如果 A 和 B 互不覆盖，它们是并发的（冲突）。

服务器端的处理：服务器为每个 key 维护一个 Dotted VV。多个客户端的并发写会产生多个 sibling（兄弟版本），需要冲突解决。解决后合并为一个新版本，dot 指向服务器自己。
