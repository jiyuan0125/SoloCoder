在做一个离线优先的应用时遇到了经典的冲突问题——两个用户离线期间各自修改了同一条记录，上线同步时两份数据冲突了。怎么自动解决而不是弹窗让用户选？用 Rust 实现几种常见的自动冲突解决策略。

冲突检测的方法：给每条记录附带向量时钟或版本号。同步时比较版本——如果一方是另一方的祖先（所有 counter 都 <=），直接用较新的。如果双方互不包含（concurrent），就是冲突，需要解决。

三种自动解决策略的实现。策略一是 LWW（Last Writer Wins）：比较两边的物理时间戳，取较新的。实现简单但有数据丢失风险。策略二是 Merge（合并）：如果两个字段不完全冲突（比如 A 改了 name，B 改了 age），按字段合并。实现 JSON 级别的合并，每个字段独立比较版本。策略三是 CRDT 合并：如果字段类型是 CRDT（计数器、集合），用 CRDT 的 merge 操作。

对于无法自动解决的冲突（比如两人都改了同一个字段为不同值），提供手动回调接口——用户注册一个 resolver 函数，输入两个冲突值，输出解决后的值。

模拟场景：两个客户端并发编辑同一条用户记录，字段分别是 name 和 age。用三种策略分别解决，对比结果。打印每次冲突的详情和解决过程。
