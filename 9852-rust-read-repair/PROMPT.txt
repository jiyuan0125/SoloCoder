读修复是 Dynamo 风格数据库里最常用的数据修复机制——在读操作过程中顺便检测副本间的不一致，发现差异后自动修复。这比专门的 anti-entropy 修复更及时，而且零额外开销（读操作本来就要做）。用 Rust 实现读修复的完整流程。

数据模型：3 个副本存储相同的 key-value 数据，每个 value 带版本号。读操作向 R 个副本发起查询（R=majority），收齐后比较版本号。如果有副本的版本落后了，在读请求返回之前，异步地把最新版本写回落后的副本。

具体的修复流程：客户端向 3 个副本发起 Read(key)。假设副本 A 返回 v5，副本 B 返回 v5，副本 C 返回 v3。读操作返回 v5（最新版本），同时异步向副本 C 写入 v5 的数据。副本 C 收到后更新本地数据。

需要处理的边界情况：如果只有 2 个副本响应（1 个超时），用已收到的 2 个响应中的最新版本来修复超时的副本。如果 3 个响应版本都不一样（说明有多个并发写入还没合并），选择版本最高的，但把其他版本也保留为 sibling（供后续冲突解决）。

模拟 100 次读操作，其中 20% 的副本故意返回旧版本。统计读修复的触发次数和修复延迟。打印几个典型的修复过程。
