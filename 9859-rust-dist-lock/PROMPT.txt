先明确分布式锁要解决什么问题——多个进程/机器需要对同一个资源做互斥访问。单机用 mutex 就行，但跨机器就得通过网络协调。最简单的方式是用一个共享的 KV 存储：set-if-not-exists（SETNX）成功就获得锁，删除就释放。但这里有很多坑。用 Rust 实现一个健壮的分布式锁。

基本的锁获取流程：客户端向 KV 存储发送 TryLock(key, client_id, ttl) 请求。如果 key 不存在（或已过期），写入 (key, client_id, expires_at)，返回成功。如果 key 存在且未过期，返回失败。锁释放：只有持有者才能释放——删除前检查 value 是否等于自己的 client_id，不等则拒绝。

需要处理的经典问题。问题一：客户端获取锁后崩溃，锁永远不释放。解决：设置 TTL，过期自动释放。问题二：锁过期后客户端还在用（以为自己还有锁）。解决：Fencing Token——每次获取锁时递增一个 token，所有使用锁资源的操作必须带 token，服务端拒绝过期的 token。

锁的可重入：同一个 client_id 可以多次获取同一把锁（计数器 +1），释放时计数器 -1，到 0 才真正删除。

锁的公平性：不保证 FIFO——多个等待者竞争时随机获取。如果需要公平锁，需要维护一个等待队列。
