用 Rust 实现分布式锁的 Fencing Token 机制。

问题是这样的：分布式锁不是绝对可靠的，客户端 A 拿到锁后可能因为 GC 暂停或网络问题"假死"，锁超时被释放，客户端 B 获取了锁。这时候 A 醒过来还在写入，就会和 B 的写入冲突。Fencing Token 就是用来解决这个问题的。

要做的事：
- 每次获取锁时返回一个单调递增的 fencing token
- 存储层在执行写入时检查 token，只有 token 比之前的大才允许写入
- 模拟上面的场景：A 拿到 token=1，A 假死后 B 拿到 token=2，A 恢复后用 token=1 写入被拒绝
- 输出每次写入操作及其 token 的判定结果

cargo build 通过，内存模拟。
