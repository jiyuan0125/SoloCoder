消息顺序是分布式消息队列里一个让人头疼的问题。理想情况是消息按发送顺序被消费，但多 partition、多消费者、网络延迟都会打乱顺序。用 Rust 实现几种消息顺序保证策略，对比它们的效果和代价。

顺序的三个级别。全局有序：所有消息严格按发送顺序被消费，但吞吐量极低（只能单 partition + 单消费者）。分区有序：同一个 key 的消息在同一个 partition 内有序（Kafka 的默认保证）。无序：不保证任何顺序，吞吐量最高。

分区有序的实现：消息路由到 partition 时，相同 key 的消息总是去同一个 partition（hash(key) % partition_count）。partition 内的消息严格按 offset 顺序投递给消费者。消费者按顺序处理——即使处理 message-2 比 message-1 快，也要等 message-1 处理完才能处理 message-2。

乱序的检测和报告：消费者维护每个 key 的 expected_sequence。如果收到的消息 sequence > expected（跳过了中间的），或者 sequence < expected（重复或乱序），打印警告。统计乱序消息的比例。

模拟场景：10 个 key，每个 key 发 20 条消息到 4 个 partition。多消费者并行消费。打印每个 key 的消息是否按序到达。故意模拟一次网络重传导致的消息重复，观察消费者的处理方式。
