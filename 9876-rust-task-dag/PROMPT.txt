有次处理一个数据处理流水线的需求——先下载数据、再解析、再清洗、再聚合、最后输出报告。每个步骤是一个任务，步骤之间有依赖关系（必须等前面的完成才能开始）。而且有些步骤可以并行（比如同时清洗多个数据源）。用 DAG 来表示这种依赖关系，用 Rust 实现一个 DAG 任务执行器。

DAG 的数据结构：每个任务是一个节点，节点之间的有向边表示依赖关系（A→B 表示 B 依赖 A）。用 HashMap<TaskId, Task> 存任务，HashMap<TaskId, Vec<TaskId>> 存依赖关系（前驱列表）。

拓扑排序和执行：计算每个任务的入度（有多少前置依赖）。入度为 0 的任务可以立即执行。任务完成后，减少所有后继任务的入度。新的入度为 0 的任务进入就绪队列。这个过程就是 Kahn 算法的并行版本。

并行执行策略：同时就绪的任务并行执行（每个任务一个 tokio task）。最大并行度可配置——限制同时执行的任务数不超过 N（防止资源耗尽）。并行度 = 1 时退化为串行执行。

环形依赖检测：构建 DAG 时检查是否有环（DFS 或拓扑排序检测）。有环则拒绝整个 DAG 并报错。
