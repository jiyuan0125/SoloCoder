在一个连接上跑多个请求——这就是多路复用。HTTP/2、gRPC 都用这个技术。和每个请求一个连接相比，多路复用省了连接建立的开销，但也带来了流量控制和请求隔离的问题。用 Rust 实现一个简单的多路复用连接框架。

帧的设计：所有数据被切分成 Frame。帧头包含 stream_id（标识属于哪个请求/响应）、flags（FIN 表示结束）、length（载荷长度）。帧体是实际的二进制数据。每个 stream 代表一个独立的请求-响应会话。

发送端：应用层调用 send(stream_id, data)，数据被切成固定大小的帧（比如 4KB），加上帧头后写入底层连接。同一个连接上多个 stream 的帧交错发送。接收端根据 stream_id 把帧分发给对应的 stream handler。

流量控制的实现：每个 stream 有一个发送窗口（类似 TCP 的滑动窗口）。接收方通过 WINDOW_UPDATE 帧告诉发送方"我还能接收多少字节"。发送方窗口耗尽时暂停发送，等 WINDOW_UPDATE 后继续。

并发 stream 的管理：限制同时活跃的 stream 数量（比如最多 256 个）。stream ID 用递增的奇偶数分配——客户端用奇数，服务端用偶数。stream 关闭后 ID 不复用。

模拟：在一条连接上同时跑 10 个 stream，每个 stream 发送 1MB 数据。打印帧交错发送的过程和每个 stream 的传输进度。
