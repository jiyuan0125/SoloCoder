背压（backpressure）是流量控制的更深层概念——不仅控制发送速率，还要把压力传导到上游。举个例子：数据库处理慢了，API 层就该少接受请求，而不是自己堆积请求。用 Rust 实现一个端到端的背压传导机制。

三层架构的模拟：客户端 → API 服务 → 数据库。数据库有处理能力上限（每秒 50 个请求）。当数据库队列积压时，API 服务感知到并开始拒绝部分客户端请求（返回 503）。客户端收到 503 后降低发送速率。

背压信号的传递：数据库维护一个 queue_depth 计数器。每次处理完请求后，如果 queue_depth > high_watermark（比如 80），向 API 层发送"减速"信号。API 层收到减速信号后，将接受请求的概率从 100% 降到 50%。queue_depth 降到 low_watermark 后恢复正常。

背压策略的选择：丢弃策略（超出负载直接拒绝请求）、缓冲策略（用有界队列暂存，队列满再拒绝）、降级策略（返回缓存数据或简化结果，减轻下游压力）。程序支持配置这三种策略。

级联背压：如果 API 层自己也积压了（客户端请求太多），API 层向客户端发送背压信号。客户端降低发送速率。这样压力从数据库一路传到客户端。

模拟 3 个客户端、1 个 API 层、1 个数据库。数据库处理能力突然下降，观察背压如何逐层传导。打印各层的队列深度和吞吐量变化。
