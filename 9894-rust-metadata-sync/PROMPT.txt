元数据同步在集群中无处不在——节点的配置信息、服务发现数据、路由表等都需要在节点之间保持一致。用 Rust 实现一个基于 Gossip 的元数据同步工具，确保集群中所有节点的元数据最终一致。

元数据的格式：Metadata { version: u64, node_id: String, entries: HashMap<String, String> }。每个节点维护自己的元数据和从其他节点收到的元数据（完整视图）。版本号每次本地修改时递增。

同步协议：每秒每个节点随机选一个邻居，交换双方的元数据版本号摘要。比较后，只传输对方缺失或过期的部分（增量同步）。收到更新后合并到本地视图——对每个 key，取版本号更高的值。

冲突解决：如果两个节点对同一个 key 写了不同的值，用时间戳或节点 ID 作为 tie-breaker。LWW（最后写入者胜出）是默认策略。

一致性验证：定期（每 10 秒）计算所有节点的元数据一致性比例。如果所有节点的所有 key-value 都相同，一致性 = 100%。打印一致性指标——"consistency: 95% (238/250 entries synced)"。

模拟 5 个节点，运行期间随机修改各节点的元数据。观察同步延迟——一次修改需要几轮 Gossip 才能传播到所有节点。
