用 Rust 实现一致性级别选择器。分布式系统有不同的读一致性级别，客户端可以按需选择在性能和正确性之间权衡——想快就选最终一致（随便读副本），想准就选强一致（必须读主）。

三种级别的实现。强一致读：直接从主副本读取，保证返回最新的已提交数据。延迟等于一次到主副本的 RPC。写后读：先查主副本拿最新版本号，然后从副本读——副本版本够新就直接返回，不够新就等最多 500ms。最终一致读：随机选一个副本读，最快但可能拿到过期数据。

数据模型：一个 key-value 存储，3 个副本，数据带版本号。写入总是走主副本，然后异步同步到从副本（100-500ms 随机延迟）。

模拟写入 key="counter" 值从 1 递增到 100 后，用三种级别各发 1000 次读请求，统计过期读比例和平均延迟。打印对比报告——"Strong: stale=0/1000 avg=5ms; RYW: stale=0/1000 avg=12ms; Eventual: stale=312/1000 avg=1ms"。

cargo build 通过。

这个工具的意义在于帮助开发者理解一致性级别的实际效果。在真实系统中，不同业务可能选择不同级别——用户 Profile 读用最终一致就行（允许短暂旧数据），金融交易必须用强一致。

Rust 标准库实现，cargo build 通过。
