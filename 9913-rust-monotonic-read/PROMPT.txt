用户群里有人反馈"我刚看到的订单状态是已发货，刷新一下变回待发货了"。查了一下，负载均衡把他导到了不同从节点，两个节点数据版本不一样。单调读保证的就是这件事：同一个客户端连续读同一个 key，不应该看到时间倒退。

用 Rust 实现单调读模块。客户端侧维护一个 session token（记录已观察到的最新版本号），每次读取时把 session token 传给存储层，存储层保证返回的数据版本不低于 session token。如果当前副本没有足够新的数据，等待同步完成或者从更快的副本读取。实现上用 LSN（log sequence number）作为版本号——每个写入递增 LSN，读操作携带客户端已知的最高 LSN。

模拟多副本存储——3 个节点，主节点写入后异步同步到从节点（有延迟）。多客户端各自维护独立的 session。客户端 A 从从节点-1 读到版本 5（更新 session），下次请求可能被路由到从节点-2（还在版本 3），存储层检测到 session LSN=5 > 当前版本 3，等待同步追上再返回。整个过程对客户端透明。

单调读的成本主要在客户端——服务端不用改什么，客户端记住之前看到过的最高版本号就够了，实现简单但效果很直接。等待同步时要有超时（比如 5 秒），超时后返回错误而不是旧数据。

Rust 标准库，cargo build 通过。演示 2 个客户端、3 个副本（主+2 从，从节点同步延迟 1-3 秒），客户端多次读取同一个 key 验证版本号只升不降。
