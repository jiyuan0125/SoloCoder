客户端先发了'余额加 100'再发了'余额加 50'，如果网络把后发的先送到服务器了，结果可能就不对。单调写保证同一个客户端的写操作按发送顺序到达服务器，用序列号来实现。

问题：如果客户端的写请求被分配到不同节点，可能出现顺序颠倒——比如先 set x=2 再 set x=1，但由于网络延迟节点先收到 x=1 再收到 x=2，最终 x=2 而不是期望的 x=1。单调写保证写入顺序与客户端发起顺序一致。

要做的：
- 客户端维护一个单调递增的写入序列号
- 每次写入带序列号发送到存储节点
- 存储节点检查序列号：只接受比上次已应用序列号大 1 的写入
- 序列号不对的写入排队等待或拒绝
- 支持多客户端，每个客户端独立维护自己的序列号
- 提供验证接口：可以检查最终数据是否反映了正确的写入顺序

Rust 标准库，cargo build 通过。

单调写在移动网络环境下特别重要——网络切换可能导致 TCP 重连和包重传，没有序列号保证的话写操作可能乱序到达服务端。
