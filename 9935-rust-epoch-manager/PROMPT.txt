帮我实现一个 Epoch 管理器，用 Rust。

在分布式系统里，epoch 是一种逻辑时钟，用来标记配置变更的代次。每次集群配置变化（加节点、减节点、副本迁移）都会递增 epoch。所有节点必须知道当前 epoch，用旧 epoch 发出的操作都会被拒绝。

要实现：
- 全局维护一个递增的 epoch 号
- 配置变更（加/减节点）触发 epoch 递增
- 每次变更生成一份新的配置快照，绑定到对应的 epoch
- 节点操作时必须携带 epoch，存储层校验 epoch 匹配才执行
- 用旧 epoch 的操作被拒绝并返回当前最新 epoch（让客户端更新）
- 支持查询历史：每个 epoch 对应的配置是什么
- 节点启动时拉取最新 epoch 和配置

Rust 标准库，cargo build 通过。

这个工具的核心价值在于把epoch manager的关键细节都暴露出来——不是藏在框架的抽象层后面，而是让你能直接看到每个操作的效果。用Rust实现，利用类型系统在编译期捕获状态转换的错误。cargo build 通过。

Epoch 标记全局配置变更——每次变更 epoch +1，旧 epoch 的操作在新 epoch 下无效。这是防止旧配置干扰新配置的核心机制。
