线上改了一个分片配置，结果有两个节点还在用旧配置发请求，数据全乱了。根本原因是配置变更没有版本化。每次变更绑定一个递增的版本号，所有节点必须确认收到了新版本才能用新配置。用 Rust 把配置版本管理实现出来。

问题：分布式系统的配置不是一成不变的——节点上下线、分片迁移、权重调整。每次配置变更都需要版本化，确保所有节点最终能看到一致的配置，而且不会回退到旧配置。

功能：
- 配置用一个递增的版本号标识（config_version）
- 支持增量变更：基于当前版本提交变更（加节点、删节点、调权重），生成新版本
- 变更传播：模拟 gossip 或 leader 推送，把新配置扩散到所有节点
- 冲突处理：如果两个节点基于不同版本提交了冲突变更，后提交的自动 rebase 到最新版本
- 节点查询配置时返回其已知最新版本的内容
- 配置回滚：支持回退到指定版本（本质上是创建一个新版本，内容是旧版本的配置）

Rust 标准库，cargo build 通过。

配置版本化让回滚变得容易——发现新配置有问题时回退到上一个稳定版本。配置历史也用于审计，记录谁在什么时间改了什么。
字符串处理注意 UTF-8 编码，不要按字节截断导致乱码。
