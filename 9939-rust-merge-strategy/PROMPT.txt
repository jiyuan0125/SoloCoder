帮我用 Rust 实现一个数据合并策略引擎。

问题：分布式数据库做多主复制或分片合并时，不同节点对同一份数据有不同的修改，合并时需要一套策略来决定最终值。不同场景用不同策略——CRDT 自动合并、last-write-wins、或者标记冲突等人工介入。

功能：
- 定义多种合并策略：LWW（最新时间戳胜）、CRDT-Counter（计数器直接加）、CRDT-Set（OR-Set 并集合并）、Manual（标记冲突不自动合并）
- 每个 key 可以配置不同的合并策略
- 执行合并时，根据策略自动处理：LWW 比较时间戳；Counter 累加值；Set 取并集保留 add/remove 语义
- Manual 模式下，合并结果标记为 CONFLICTED，等待外部 resolve
- resolve 接口：手动指定一个 key 的最终值，生成合并后的新版本
- 合并日志：记录每次合并的输入版本、策略、输出结果

Rust 标准库，cargo build 通过。

这个工具的核心价值在于把merge strategy的关键细节都暴露出来——不是藏在框架的抽象层后面，而是让你能直接看到每个操作的效果。用Rust实现，利用类型系统在编译期捕获状态转换的错误。cargo build 通过。
