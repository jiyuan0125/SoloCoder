WAL 日志要清理、墓碑要回收、旧版本要修剪、临时文件要删除——每个组件各自做 GC 太乱了。用 Rust 实现一个统一的 GC 管理器，把所有清理任务统一起来调度：定期触发、手动触发、或空间压力触发。

很多分布式存储组件都需要垃圾回收——WAL 日志清理、tombstone 回收、旧版本修剪、临时文件删除。这个 GC 管理器统一管理这些 GC 任务。

需要做：
- 定义 GC 任务接口：每个任务实现 check() 和 run() 方法
- 预置几种 GC 任务：日志截断、tombstone 清理、过期数据删除、孤儿文件清理
- GC 调度器：按配置的策略运行任务——定期触发、手动触发、或空间压力触发（剩余空间低于阈值时加速 GC）
- 每次运行记录统计：回收了多少空间、花了多长时间
- 并发控制：同一时间只运行一个 GC 任务，避免资源竞争
- 可视化：显示各 GC 任务的历史运行记录和效果

Rust 标准库，cargo build 通过。

分布式 GC 比单机复杂——不仅要确认没有本地活跃引用，还要确认没有远程节点在使用。通常需要分布式引用计数或 lease 机制。
