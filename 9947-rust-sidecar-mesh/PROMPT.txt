帮我用 Rust 实现一个 Sidecar 服务网格代理。

场景：在服务网格（Service Mesh）里，每个服务实例旁边部署一个 sidecar 代理，拦截所有入站和出站流量。sidecar 负责 mTLS、服务发现、负载均衡、重试、可观测性等。这个工具模拟 sidecar 的核心逻辑。

要做：
- 出站拦截：服务发出的请求先经过 sidecar，sidecar 做服务发现找到目标实例，做负载均衡选择一个，然后转发
- 入站拦截：到达服务的请求先经过 sidecar，做认证和限流检查
- 连接池：对每个目标服务维护连接池，复用连接
- 重试策略：配置每个服务的重试次数和超时
- 断路器：如果某个服务连续失败 N 次，自动打开断路器，一段时间后半开探测
- 指标上报：记录每个服务的请求量、延迟、错误率

Rust 标准库，cargo build 通过。

这个工具的核心价值在于把sidecar mesh的关键细节都暴露出来——不是藏在框架的抽象层后面，而是让你能直接看到每个操作的效果。用Rust实现，利用类型系统在编译期捕获状态转换的错误。cargo build 通过。

Sidecar 模式的核心是不修改应用代码就能增加基础设施功能——服务发现、负载均衡、加密、可观测性都由 sidecar 代理处理。
