帮我用 Rust 写一个分布式日志收集器的核心模块。

场景是这样的：我们有几十台机器在跑服务，每台都会产生日志，需要一个工具把日志按时间顺序收集并合并输出。实现一个能从多个模拟的日志源（可以是文件或 stdin）读取日志行的收集器，日志行格式是 "YYYY-MM-DD HH:MM:SS [LEVEL] message"。按时间戳排序合并输出，支持按 LEVEL 过滤，能处理日志源断开重连的情况。

用纯 Rust 标准库实现，cargo build 能编译通过，cargo run 可以演示合并效果。

这个工具的核心价值在于把log collect的关键细节都暴露出来——不是藏在框架的抽象层后面，而是让你能直接看到每个操作的效果。用Rust实现，利用类型系统在编译期捕获状态转换的错误。cargo build 通过。

日志收集器统一格式化各服务日志，建立索引，提供查询。通过 trace_id 关联分散在各服务的日志是核心功能。

程序要打印关键操作的详细信息，让使用者清楚看到每一步的效果。Rust 标准库实现，cargo build 通过。

日志格式的统一化是关键——不同服务可能用不同的日志格式，收集器需要做归一化处理。每条日志至少提取：timestamp、level、service_name、trace_id、message。归一化后建立倒排索引，支持按任意字段搜索。
