生产环境每秒几万请求，不可能每个都记录完整 trace——太贵了。采样是必须的妥协：只采 10% 的请求做完整追踪，剩下的放过。用 Rust 实现几种采样策略：概率采样、速率限制采样、基于 trace_id 的确定性采样。

问题是这样的：生产环境流量太大，不可能每个请求都记录完整 trace，需要采样。实现几种采样策略：固定比例采样（比如只采 10%）、基于 trace_id 尾数的确定性采样（相同 trace_id 永远做相同决定）、速率限制采样（每秒最多采 N 条）。提供一个统一的接口，可以组合多种策略，比如先过速率限制再按比例采样。

用 Rust 写，不依赖外部 crate，cargo build 编译通过，能演示几种采样策略的效果。

采样是追踪的必要妥协——记录每次请求的完整链路太贵了。采样策略在足够的数据和合理的开销之间取得平衡。

采样策略的一个重要分类是头部采样 vs 尾部采样。头部采样在请求入口就决定是否记录（简单但可能错过异常请求）。尾部采样等请求完成后根据结果决定（能捕获异常请求但需要暂存所有 span）。这个程序实现头部采样（概率采样和自适应采样两种模式）。
