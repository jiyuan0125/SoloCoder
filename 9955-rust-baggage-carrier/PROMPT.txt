分布式追踪里除了 trace_id 和 span_id，还想把用户 ID、实验分组、租户 ID 这些业务信息一路传下去。W3C 定义了 baggage 规范——随请求传播的自定义键值对，沿途所有服务都能看到。用法简单但细节不少：特殊字符转义、大小限制、嵌套传播。

用 Rust 实现 BaggageCarrier。核心功能：添加 baggage 项 set(key, value)、获取 get(key)、删除 remove(key)、获取全部 items()。序列化成 HTTP header 字符串——遵循 W3C baggage 格式，逗号分隔的 key=value 对（比如 "user_id=123,tenant=acme,exp_group=A"）。反序列化从 header 字符串解析回 baggage——处理空格、引号、转义字符。

特殊字符处理：value 里的逗号、等号、反斜杠用百分号编码。空 key 或空 value 跳过不报错。最大条目数 64 个、最大总字节 8KB，超出拒绝添加。多来源合并时相同 key 取最后出现的值。

纯 Rust，cargo build 通过。写个 demo：创建 baggage 设置 5 个键值对（含特殊字符），序列化再反序列化验证值一致。
