P99 延迟 500ms 意味着每 100 个请求里有一个要等半秒——平均值看不出这个问题，因为 99% 的请求 10ms 内就完成了。直方图能暴露这种尾部延迟。用 Rust 实现一个 Histogram 指标类型，支持自定义桶边界、百分位计算和多实例合并。

实现一个 Histogram 结构体。桶的边界可配置——传入一组上界值（比如 [1, 5, 10, 50, 100, 500, 1000] 表示毫秒），每个桶统计落在该范围内的观测值数量。最后一个桶是"上不封顶"的。record(value) 把值放入对应的桶中（二分查找定位桶）。查询百分位数 percentile(p)——比如 percentile(0.99) 返回 P99 值：从最低桶开始累加计数，累加到总量的 99% 时返回该桶的上界值。

输出基本统计：count（总观测数）、sum（总和）、min、max、avg。merge(other_histogram) 合并两个直方图——对应桶的计数相加。分布式场景下每个节点各自统计，然后聚合到中心节点做全局百分位计算。桶的计数用 u64 不用浮点，避免精度损失。

如果桶边界配置不合理（比如所有值都落在一个桶里），百分位计算精度很差。提供 bucket_suggestion(sample_data) 根据样本数据自动推荐桶边界——用分位数确定合适的边界点。

Rust 实现，cargo build 通过。生成 10000 个模拟 API 延迟数据（正态分布均值 50ms，加 1% 的 spike 到 500ms），写入 histogram，查询 P50/P90/P99/P999，打印各桶的分布。
