帮我实现一个 Rust 的存活探针（liveness probe）服务。

存活探针的作用是检测进程是不是卡死了——如果探针失败，Kubernetes 会直接杀掉重启。和健康检查的区别是：存活探针不关心依赖服务是否正常，只关心自己是不是死锁了或者陷入无限循环了。实现一个 /livez 端点，内置一个心跳机制——主循环定期更新心跳时间戳，探针检查心跳是否在超时范围内（比如最近 10 秒内有更新）。支持配置超时阈值和探针端口。心跳停滞超过阈值就返回 503，否则返回 200。

Rust 标准库，cargo build 通过，能演示正常和心跳超时两种情况。

这个工具的核心价值在于把live probe的关键细节都暴露出来——不是藏在框架的抽象层后面，而是让你能直接看到每个操作的效果。用Rust实现，利用类型系统在编译期捕获状态转换的错误。cargo build 通过。

存活探针检测进程最基本的健康——主循环是否卡死、是否有死锁。超时后编排系统会杀掉进程重启。

程序要打印关键操作的详细信息，让使用者清楚看到每一步的效果。Rust 标准库实现，cargo build 通过。

存活探针的实现通常很轻量——不需要做完整的业务逻辑检查，只需要验证进程主循环是否在运行。常见的做法是暴露一个 /healthz 端点返回 200，或者检查一个原子变量的最后更新时间。这个程序用 HTTP 端点实现探针，支持配置检查间隔和超时时间。
