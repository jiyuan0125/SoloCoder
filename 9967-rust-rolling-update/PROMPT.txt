写一个 Rust 模拟的滚动更新（rolling update）策略执行器。

我们在做部署系统，需要模拟 K8s 的滚动更新过程。模拟一个有 N 个实例的服务集群（比如 10 个），实现滚动更新策略：按配置的 maxUnavailable 和 maxSurge 参数逐步替换旧版本实例为新版本。更新过程中保证可用实例数不低于 minAvailable，同时总实例数不超过 maxTotal。支持回滚——如果新版本健康检查失败，自动把已更新的实例回滚到旧版本。每一步都打印当前集群状态（每个实例的版本和健康状态）。

Rust 标准库实现，cargo build 通过，演示一次滚动更新和一次回滚。

这个工具的核心价值在于把rolling update的关键细节都暴露出来——不是藏在框架的抽象层后面，而是让你能直接看到每个操作的效果。用Rust实现，利用类型系统在编译期捕获状态转换的错误。cargo build 通过。

滚动发布的速度取决于 batch_size 和观察时间。太激进可能错过故障信号，太保守发布太慢。

程序要打印关键操作的详细信息，让使用者清楚看到每一步的效果。Rust 标准库实现，cargo build 通过。
