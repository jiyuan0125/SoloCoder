用 Rust 做一个金丝雀发布（canary deployment）的模拟器。

金丝雀发布就是先让一小部分流量打到新版本，没问题了再逐步扩大范围。模拟一个集群，有旧版本和新版本两组实例。实现流量按百分比分配到不同版本（比如 95% 到 v1，5% 到 v2）。监控新版本的成功率和延迟指标，如果指标恶化超过阈值就自动回滚（流量全部切回旧版本），如果指标正常就逐步增加新版本的流量比例直到 100%。整个过程按时间步模拟，每步输出流量分配和指标数据。

Rust 实现，cargo build 编译通过，演示一次成功的金丝雀发布全流程。

这个工具的核心价值在于把canary deploy的关键细节都暴露出来——不是藏在框架的抽象层后面，而是让你能直接看到每个操作的效果。用Rust实现，利用类型系统在编译期捕获状态转换的错误。cargo build 通过。

金丝雀发布用少量实例先验证新版本。关键是定义清晰的回滚指标（比如错误率超过阈值就回滚）和足够的观察时间。

程序要打印关键操作的详细信息，让使用者清楚看到每一步的效果。Rust 标准库实现，cargo build 通过。

金丝雀发布的自动化需要明确的指标定义——什么算成功、什么算失败。常见的指标包括错误率、P99 延迟、CPU 使用率。程序用一个简单的规则引擎：如果 canary 实例的错误率 > baseline 的 2 倍，自动回滚。
