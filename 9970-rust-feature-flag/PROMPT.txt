写一个 Rust 的特性开关（feature flag）服务。

做产品经常需要灰度发布功能，希望可以按用户比例、用户标签、地理位置等条件决定某个功能是否开启。实现一个 FeatureFlag 引擎：支持布尔型开关（开/关）、百分比灰度（比如 20% 用户看到新功能）、基于用户属性的规则（比如 "age > 18 AND region = cn"）。规则用简单的 DSL 或 JSON 配置描述。提供 is_enabled(flag_name, user_context) 接口来判断某个用户是否命中某个开关。支持动态加载配置（从文件读取），配置变更不需要重启。

Rust 标准库，cargo build 通过，演示几种不同类型的开关判断。

这个工具的核心价值在于把feature flag的关键细节都暴露出来——不是藏在框架的抽象层后面，而是让你能直接看到每个操作的效果。用Rust实现，利用类型系统在编译期捕获状态转换的错误。cargo build 通过。

功能开关让代码部署和功能发布解耦——代码先上线但功能默认关闭，需要时通过配置打开。回滚很快，也方便做灰度发布。

程序要打印关键操作的详细信息，让使用者清楚看到每一步的效果。Rust 标准库实现，cargo build 通过。
